# Rivet roadmap

Living plan, updated 2026-10-12. Status: **done** · **in progress** · **planned** · **idea**. Dates = when decided. Internal design records: [`docs/CLAUDE.md`](docs/CLAUDE.md) (index of specs, plans, research, benchmarks).

## 0. North star

- **Beat every peer ≥ 1.3×**: Razor, Solid, Svelte, React, Qwik on SSR (CPU/page, p50, TTFB, peak memory), DOM (mount, update, heap) and resume (click / navigate to interactive). Measured, same harness, published with losses ([`perf-scoreboard`](docs/benchmarks/perf-scoreboard.md), [`2026-10-09 fair comparison`](docs/benchmarks/2026-10-09-fair-comparison.md)).
- **Dynamic at static cost**: a dynamic page should cost what a static file costs. Today: 0.294 vs 0.092 ms CPU/req, 6.6× fewer rps ([`editorial`](docs/benchmarks/2026-10-11-editorial.md)) → not yet.
- **Static sites at zero JS**: pages with nothing interactive ship no JS (Astro parity); today 65 KB JS per static article.
- **Adoption**: a framework + ui kit people pick for apps, admin tools, AI apps, content sites (mobile apps later); docs, homepage, `npm create rivet@latest`, AI tooling (MCP, skills, llms.txt).
- **Resume model under review (2026-10-18)**: serialized resume is at its measured ceiling on SSR CPU (6.6× static, 1.75× Solid hydratable), memory (1.9× static), HTML bytes and chunk count. Proposed replacement: the [derived client](docs/design/research/2026-10-18-beyond-resume-hydration.md) — four compiler-chosen layers per interaction site (native HTML / derived slices with no runtime / adopted boundaries = [structural resume](docs/design/specs/2026-10-18-structural-resume-design.md) / rendered), values only on the wire, no author-placed seams; MPA-first navigation + optimistic server actions as stances. Rulings R1′–R4′ pending; spike S2 (hand-derived resume-bench client) decides before any compiler work; serialized resume's machinery is not deleted before S2 reports. Round 3 ([floor-first](docs/design/research/2026-10-18-floor-first.md)): ~57 % of Node's CPU/page is transport and compression is unmeasured but larger than the render → op-stream rendering + spliced precompressed blocks + dictionary transport (wire ≈ data deltas, 0 external JS on app pages) now; native host (3× CPU, 20× memory, measured by the 2026-10-06 spike) gated on X2; measure encoded, not identity (R-A).
- Where we stand (claims on the homepage spec): static SSR 3.6× less CPU than Razor (5.6× at 5k rows); post-resume navigation 2.1× faster than Qwik; DOM updates 1.9× faster than Solid. Losses: small resumable pages vs Solid 2 (1.9× CPU, +28 % HTML), static editorial vs Astro / Eleventy / Hugo, krausest bytes vs Solid.

## 5. How we decide

- **Perf first**: every runtime / compiler change is measured (ssr-bench, dom-bench, resume-bench, size-report); no semantic trades (dev guards, guarantees) for bytes; speed over size.
- **Land measured non-regressions**: no percentage threshold (2026-10-11); big bets need ≥ 1.3× to become defaults.
- **Docs follow code**: every API / behaviour change updates docs, llms.txt outputs, AGENTS / CLAUDE.md, skills, MCP data in the same change (CI `--check`).
- **Zero-cost**: an unused feature costs 0 bytes; every `@rivetjs/*` subpath tree-shakes; `scripts/zero-cost` gates it.
- **Live props by default**: every prop live unless justified and documented as read-once.
- **cdk headless, ui = HeroUI look tweaked, API similar-improved**; upstream behaviour + ported tests are the floor.
- **Clean-room Pro**: HeroUI Pro-inspired components from public docs only (names, anatomy); own code, CSS, content; lucide icons.
- **Breaking changes allowed** until real users; every in-repo consumer migrates in the same change.
