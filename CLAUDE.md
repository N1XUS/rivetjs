# Rivet monorepo

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Rivet = compiled, resumable JSX framework: SSR-first streaming server output, fine-grained signals, compiled DOM templates, resumable pages (no hydration re-render), file routing, compile-time i18n/styles/slots. Rust/oxc compiler → WebAssembly. Goal: beat Solid, Svelte, React and ASP.NET Razor on SSR (CPU/page, complete p50, TTFB, peak memory) and DOM (mount, update, heap) benchmarks. Requires untampered JS built-ins (no prototype-poisoning guards; same stance as React/Solid).

## Rules

- Every lib/sublib has a CLAUDE.md; ALWAYS update the nearest CLAUDE.md(s) in the same change as the code — stale CLAUDE.md = incomplete change.
- Docs follow code (user rule 2026-10-08): any change to an API, behaviour, default, command, error code or file layout updates EVERY place that describes it, in the same change. Covers user docs (`apps/*/content/**`, examples), `llms.txt` / `llms-full.txt` / per-page `.md` outputs (regenerate, never hand-edit), AGENTS.md / CLAUDE.md in templates + create-rivet output, skills / editor rules, READMEs, guides (`docs/guides/**`), specs that state current behaviour, JSDoc, compiler diagnostic texts + quick fixes, the MCP server's data. Before finishing: grep docs + md files for the old name / behaviour; an out-of-date description = incomplete change. Generated AI outputs are checked in CI (`--check`), so stale ones fail the build.
- **HIGH PRIORITY — icons:** never invent SVG paths and never use UTF glyphs (✓ × ▾ → ★ …) as icons. Use an icon library (lucide; in Rivet UI: `import { Icon } from "@rivetjs/kit/icon"`). Applies to apps, docs, cdk, examples, templates.
- Perf first: every runtime/compiler change is justified by measurement (ssr-bench, dom-bench, size-report). No semantic trades (dev guards, guarantees) for bundle size. Measured hot path idioms: `docs/guides/performance.md`.
- Zero-cost: an untouched feature costs 0 bytes — every `@rivetjs/*` subpath is independently tree-shakeable; nothing in a runtime entry imports test/dev/devtools code. `scripts/zero-cost` enforces it.
- cdk = faithful 1:1 ports of react-aria / react-stately / react-aria-components / Angular CDK: same behaviour, options, events, edge cases; port the upstream test suites too; keep license headers + `libs/cdk/NOTICE`. Overlapping names ship ONE `@rivetjs/cdk/<name>` module covering both upstreams. No simplified reinterpretations.
- cdk styling is headless: default `rv-*` class names + `data-*` state; behaviour-critical styles (visually-hidden, overlay underlay, stacking) set inline from JS, never keyed on classes. Overlays use the shared div overlay layer, never native `<dialog>`/`popover`.
- Resumability (one model since M6-CUT 2026-10-22: derived): the server records interactive component instances (boundaries) and their signal values only; the browser runs a boundary's ordinary compiled DOM function over the server nodes on its first event / wake / trigger. No capture rules: handlers, functions, class instances and JSX props need not serialize (a component given non-data props adopts with its parent). Render must be the same on both sides (RV2103 non-deterministic value, RV2104 signal in a loop; a mismatch renders that boundary in the browser). Signal values and route data must be resume-format data (RV2107; classes via `registerClass`). `.ts` modules are not server-rewritten (import `@rivetjs/runtime/dom` only from `.tsx`). Not yet on derived (plan M6): bridges, forms progressive enhancement, some `Suspense` cases. Native automata (ZERO STATESPACE): a `// @rivet-native` family (ui switch / checkbox / accordion / Button / CloseButton) at a call site the build proves closed (`libs/compiler/facts-native.ts`, prop `$native: 1`) renders native `input` / `<details>` / `<button>` markup with CSS state and ships 0 JS; the inline loader neither holds press events nor replays clicks under `[data-nc]`. See `docs/guides/resumability.md`.
- Compiler Rust (user rule 2026-10-06): only the root/orchestrator agent edits `libs/compiler/rust/**` (incl. `compile.rs`) and runs `rust/build.sh`. Subagents never edit `.rs` files or start Docker builds: they write a patch file (unified diff + what/why + verify steps) to the orchestrator's patch queue; the root batches queued patches, builds the wasm once, runs compiler tests + oracle + zero-cost + `typescript-plugin:build`, then hands results back. Reason: parallel lanes each editing Rust and running their own Docker build. Prefer new code in `rust/src/compile/*` modules over growing `compile.rs`.
- Experimental framework (user rule 2026-10-06): breaking API / behaviour changes are allowed — no deprecation aliases, compat shims or transition releases — until there are real users of the libraries. Still update every in-repo consumer (apps, docs, templates, tests) in the same change.
- Git: work on the main checkout (`perf/ssr-beat-razor`), no worktrees. `git add` specific paths only (never `-A`/`.`). Never touch user WIP (`apps/playground/src/routes/_layout.tsx`, `apps/playground/tsconfig.json`, `apps/docs/examples/todo-list/src/routes/index.tsx`, `*-tmp.ts`). Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

- Publishing: `NX_DAEMON=false npx nx run-many -t package` builds every lib into `dist/libs/<lib>` (`scripts/package/build.ts`: `.js`/`.jsx` + `.d.ts`, LICENSE, generated manifest); publish only from there (`libs/*/package.json` stay private source manifests the workspace resolves). ## Gotchas

- CI ≠ this host (CI-RED-2 2026-10-21, `docs/guides/testing.md` "CI parity"): CI runs Node 24 (local default here is 26: no global `ErrorEvent`, NNBSP in `Intl` times, slower wasm — reproduce with `/Users/denisseverin/.nvm/versions/node/v24.18.1/bin`), Linux headless Chromium with a virtual cursor at (0, 0) (`@rivetjs/testing` headless cursor guard, installed by `node-env.ts` / `browser-env.ts`), Linux fonts, 2-vCPU runners (absolute perf budgets enforced off CI only: `vitest.config.ts` `PERF_BUDGETS`, `RIVET_PERF_BUDGETS=1`), and `nx run … --skip-nx-cache` hands tasks `NX_SKIP_NX_CACHE` / `NX_WORKSPACE_ROOT` / `NX_TASK_*` (strip them for nested Nx).
- `npm run typecheck` ≈ 80 s sequential with tsgo (peak tree RSS ~2.7 GB: `apps/ui-docs`); scope with `NX_DAEMON=false npx nx run <project>:typecheck --output-style=static --skip-nx-cache`. nx `--parallel` > 1 exceeds 3 GB (tsgo already uses 4 checker threads per project).
- Zero-cost check builds `apps/ssr-bench` (rolldown); a bundler "debugName" warning is expected noise.
- Resumed pages adopt server nodes (`dom-adopt.ts` / `dom-adopt-run.ts`): a boundary runs once over its nodes, `For` rows adopt lazily, a markup mismatch renders the boundary in the browser (dev warning); a `CTXFREE` record (ZERO CALLSITE: the build proved no context provider above its call site, `libs/compiler/facts-callsite.ts`; docs-kit frames today) adopts without its ancestors — see `docs/guides/resumability.md`.
- DOM v2 is the only DOM lowering (spec `docs/design/specs/2026-10-06-dom-v2-only-design.md`; v1 deleted 2026-10-07): components return DOM values (Node | array | accessor) and own nothing; `{...spread}` (incl. cdk `globalDOMProps` roots) → one `_spread(el, …)`; resumed (derived) + i18n modules lower the same ABI (`libs/runtime/dom-adopt.ts` adopts server nodes). Structural components needing disposal use `Output` (`libs/runtime/dom.ts` `_dom`). See `libs/compiler/CLAUDE.md`, `libs/runtime/CLAUDE.md`.
- Event handlers run batched through reactivity `_dispatch`; the first trusted mouse click per document flushes its DOM updates one task later (Chrome first-click frame stall) — Playwright tests reading the DOM right after a page's first `page.click` must wait. See `docs/guides/resumability.md` "First mouse click".
- `tsconfig.json` at root is an editor fallback only; packages have strict projects.
- Production browser builds differ from server / dev on two data paths (ZERO UI-JS2, `docs/guides/performance.md` "Shipped bytes"): `@rivetjs/ui`'s resolver merges with tailwind-merge only in modules `libs/compiler/class-merge.ts` flags (they import `@rivetjs/ui/tv-merge`), and cdk locale tables (`// @rivet-locale-table`) keep only the declared locales' languages when the app declares them (`libs/compiler/locale-tables.ts`, `rivet({ locales })` / `rivetRouter({ locales })` / `i18n()` `locales`; undeclared = whole tables; docs sites + starter-ui declare theirs). A browser-only class / locale difference: check those first.
- Docs builds: keep extra output copies out of an app dir (`apps/<app>/dist-*`): the client build reads them (Tailwind source detection, most likely; measured 2026-10-26: ui-docs client build +0.8 GB RSS with four copies, over the 3 GB docs-kit budget).
