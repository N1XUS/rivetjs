The date widgets and announcements need a locale. `@rivetjs/cdk/i18n` resolves it (React Aria `useLocale`), caches date formatters and matches localized string tables; `@rivetjs/cdk/i18n-provider` gives a subtree its own locale (React Aria `I18nProvider`).

::example{id=i18n-provider}

## Import

```ts
import { useLocale, getDefaultLocale, resolveLocale, isRTL, getDateFormatter, getStringsForLocale, formatString, LocaleContext, type Locale } from "@rivetjs/cdk/i18n";
import { I18nProvider } from "@rivetjs/cdk/i18n-provider";
```

## Where the locale comes from

1. The nearest `<I18nProvider locale="…">`.
2. Else `<html lang>` in the browser (what `@rivetjs/i18n` writes for the page's locale), then `navigator.language`.
3. On the server without a provider: `"en-US"`. A locale `Intl` rejects also falls back to `"en-US"`.

On a resumed page components do not run in the browser: the locale is resolved while the server renders and stored, as a string, in widget state. Wrap the app (or the route) in `I18nProvider` with the request's locale so the server renders the right language.

## I18nProvider

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `locale` | `string` | environment | BCP 47 tag, such as the `[[lang]]` route parameter of `@rivetjs/i18n`. Its direction is derived with `isRTL`. |
| `children` | content or `() => content` | none | Rendered inside the provider (plain JSX children are lazy); a render function works too. |

```tsx title="src/components/Booking.tsx"
import { I18nProvider } from "@rivetjs/cdk/i18n-provider";
import { BookingForm } from "./BookingForm.tsx";

export function Booking(props: { locale: string }) {
  // Children render inside the provider: date fields below use `props.locale`.
  return <I18nProvider locale={props.locale}>{() => <BookingForm />}</I18nProvider>;
}
```

The runtime's `<Provider token={LocaleContext} value={…}>` works too: it defers its children.

## API

| Export | Does |
| --- | --- |
| `useLocale()` | `{ locale, direction }` of the nearest provider, else `getDefaultLocale()`. Call in a component body. |
| `getDefaultLocale()` | The environment's locale (see above) and its direction. |
| `resolveLocale(locale?)` | `locale` when given, else `useLocale().locale`. |
| `isRTL(locale)` | Right-to-left by `Intl.Locale` text info, else the maximized script (`Arab`, `Hebr`, …), else the language. |
| `getDateFormatter(locale, options?)` | A cached [`DateFormatter`](dates.md) per locale and options (React Aria `useDateFormatter`). The cache clears beyond 256 entries. |
| `getStringsForLocale(strings, locale, defaultLocale = "en-US")` | The table for `locale`: exact match, then language-script, then language, then any region of the language, else `defaultLocale`. |
| `formatString(template, variables?)` | Replaces `{name}` placeholders; unknown names stay as written. |
| `LocaleContext` | The context the provider sets (`null`: environment default). |

Types: `Locale` (`{ locale: string; direction: "ltr" | "rtl" }`), `LocalizedStrings<K>` (locale → key → template).

### Cached Intl formatters

Building an `Intl.NumberFormat`, `PluralRules`, `DisplayNames`, `ListFormat` or `DateTimeFormat` takes 7 to 60 µs. Calling `format` on an existing one takes about 0.2 µs. `n.toLocaleString(locale, options)` builds a new formatter on every call. In render code and bindings, use `cachedIntl` from `@rivetjs/cdk/i18n/intl-cache`, or a module-level formatter when the locale is fixed:

```tsx
import { cachedIntl } from "@rivetjs/cdk/i18n/intl-cache";

const price = (n: number, locale: string) => cachedIntl(Intl.NumberFormat, locale, { style: "currency", currency: "EUR" }).format(n);
```

The cache key is the constructor, the locale and the option entries (sorted), so two option objects with the same entries share one instance. Each constructor's cache clears beyond 256 entries. `cachedIntl` is a plain module function, so resumed bindings and handlers can call it. `@rivetjs/cdk/i18n/list-formatter` (`listFormatter`, React Aria `useListFormatter`) and `@rivetjs/cdk/i18n/filter` (`getCollator`, `createFilter`) are cached the same way.

## Resumability

- `useLocale()` and `getDateFormatter()` run during render. Keep the locale string, not the formatter, if a handler needs it later.
- To switch locale on a resumed page, render one provider per branch (as the first example does), or navigate to the localized route.

## Upstream

React Aria `@react-aria/i18n` (`I18nProvider`, `useLocale`, `isRTL`, the `useDateFormatter` cache) and `@internationalized/string` (`LocalizedStringDictionary` locale matching, `{name}` interpolation). Deviations: the default locale reads `<html lang>` first; strings are plain templates (React Aria compiles its JSON into functions). Not ported: `useNumberFormatter` (use `cachedIntl(Intl.NumberFormat, …)` or `NumberFormatter` from `@rivetjs/cdk/number`), plural and select message formats. `useCollator`, `useFilter` and `useListFormatter` are plain functions in `@rivetjs/cdk/i18n/filter` and `@rivetjs/cdk/i18n/list-formatter`.

## Common mistakes

- **Plain children in `I18nProvider`.** `<I18nProvider locale="de"><Calendar /></I18nProvider>` renders `Calendar` in the default locale. Use `{() => <Calendar />}`.
- **A locale only in the browser.** Without a provider the server renders `en-US`, and resumed widgets keep it.
- **Formatting with the server's time zone.** Pass `timeZone` to the formatter options when the value is not a local date.
