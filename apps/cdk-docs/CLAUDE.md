# apps/cdk-docs
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Docs site of `@rivetjs/cdk` (headless components + foundations), second site on `@rivetjs/docs-kit` (same engine as `apps/docs`). Engine internals: [libs/docs-kit/CLAUDE.md](../../libs/docs-kit/CLAUDE.md).

## Layout
- Published alpha docs: version labels and StackBlitz package specs use `0.1.0-alpha.0`; installation guides use public npm packages. Production hosting is enabled at `cdk.rivetjs.severyn.pro`. One example check is quarantined (`data-list`, see below).
- Quarantine: `examples/_quarantine.json` holds `data-list` (2026-10-20, CDK-EX; needs user approval): resumed ListBox rows keep their server text after `createListData.update` (`../../libs/cdk/collections/CLAUDE.md` OPEN resume gap). The 2026-10-16 deployment entries (`merge-props`, `radio-group-events`, `toggle-button-group-options`) pass since the cold-interaction fixes and were removed 2026-10-20 (CDK-EX); a new entry needs user approval and stays explicit in build output.
- Modal example checks (`dialog-nested`, `dialog-trigger`, `modal-basic`) accept inert on the target or an ancestor: `ariaHideOutside` marks the outermost page/portal wrapper, not necessarily the trigger/dialog itself.
- `wrangler.jsonc`: production static assets from `dist/client`, Worker `rivetjs-cdk`, custom domain `cdk.rivetjs.severyn.pro`. Cloudflare repo-root build: `npm run docs:build:cloudflare -- apps/cdk-docs`; deploy with `--config apps/cdk-docs/wrangler.jsonc`. Production origins and sibling links are set by that script; source links use `N1XUS/rivetjs`.
- `site.config.ts`: name, origin (docs `:4323`; env `CDK_DOCS_ORIGIN`; examples are pages of this app, `/examples/<id>/frame/`), `sites` (`docs` → `DOCS_ORIGIN`, `ui` → `UI_DOCS_ORIGIN`, for `[x](site:docs/…)` / `site:ui/…` links), repo, version.
- `api.config.ts`: TypeDoc entry points of the API reference (`src/generated/api.json`, committed).
- `vite.config.ts`: `docsSite()` before `rivetRouter({ prefetch: "document", resume: { preload: { rules: [...DOCS_PRELOAD_RULES] } } })` (document prefetch for nav + content links; docs-kit marks prev/next `prerender`, same as `apps/docs`; cdk chunks of the frame load on intent, not when visible), Tailwind; dev server `:4325` (search works there: in-memory Pagefind index of the dev pages, built on the first search ≈ 16 s cold, see docs-kit `tools/dev-search.ts`).
- `content/<section>/<page>.md`: pages. Sections `start/`, `components/`, `foundations/`. URL = path without `.md` (`content/components/menu.md` → `/components/menu/`).
- `content/_nav.ts`: assembles nav from `content/_nav/<area>.ts` (`start`, `forms`, `collections`, `overlays`, `pickers`, `interactions`, `utilities`); each area exports `components` + `foundations` groups (`start.ts`: `groups`). Order = reading order (prev/next). `areas` (top bar: Start, Components, Foundations) + `nav` sections each with `area`; groups render as collapsible side-nav groups.
- `examples/<id>/`: one small app per example (see Examples). ~410 examples (`carousel-*`: every embla 8.6.0 predefined example, headless; `drag-drop-*`: the 19 Angular CDK docs examples (`adev/src/content/examples/drag-drop`) + Material table-drag-drop on a plain table, upstream markup / data / `app.css` as plain CSS with `--example-*` colour variables redefined under `:root[data-theme="dark"]`; deviations: lucide `Move` handle icon, poster card preview instead of Wikimedia images, cdk Modal instead of the Overlay pane).
- Resizable (2026-10-08): `content/components/resizable.md` (nav Utilities > Content after ScrollArea; react-resizable-panels 4.14.3 port, no upstream docs mirror: horizontal, vertical, nested, collapsible, persisted layout (`cookieStorage` snippet), conditional panels, imperative API, keyboard table, styling, API) + 7 Rivet-authored examples `resizable-{horizontal,vertical,nested,collapsible,persistence,conditional,imperative}` (plain CSS `.Group` / `.Panel` / `.Handle`; steps press keys on separators and assert `aria-valuenow`). `::api` symbols use full keys (`"@rivetjs/cdk/resizable#Group"`).
- Lightbox (2026-10-08): `content/components/lightbox.md` (nav Media after Carousel; YARL section list: anatomy, slides, controlled, settings, events, each plugin, video, embeds, PDF, inline, custom slides, styling, a11y, resumability, upstream) + 7 examples `lightbox-{basic,plugins,video,embeds,pdf,inline,custom-slides}` (Tailwind, lucide icons; steps select parts by `data-action` / `data-lightbox-*`: lightbox parts take no `id`). Shared media `examples/_assets/` (README lists them): image copies from ui-docs + generated `lightbox-clip.mp4` / `-poster.jpg` / `lightbox-sample.pdf`, imported with `?url` (no `?image` pipeline here). `lightbox-embeds` never opens the YouTube slide in its check (the player keeps the network busy: `networkidle` times out in strict mode; the default quiet detector ignores cross-origin requests); keyboard steps respect the 250 ms arrow throttle (click `[data-action=prev]` for a quick second move).

Steps assert the server `clip-path` only: the browser re-serializes a changed inline `clip-path` (`inset(26% 0px 0px)`). `api.config.ts` entry `@rivetjs/cdk/compare` (no `::api` until `api.json` is regenerated).

- FLIP (2026-10-12, lane MOTION): `content/foundations/flip.md` (nav Interactions foundations after Motion; Rivet-authored `@rivetjs/cdk/flip`: API table, capture / play, drivers incl. `@rivetjs/motion/layout` `layoutDriver`, measured note; no live example yet). `foundations/motion.md` Notes name the split (cdk physics vs `@rivetjs/motion`); `components/masonry.md` documents the `FlipDriver` `motion` value.

## Pages (content/*.md)
- Frontmatter: `title`, `description` (≤160 chars, hard limit), `template: guide`, `status: experimental`, `related: [section/page, …]` (pages of THIS site only).
- Every page appears exactly once in the nav (build fails on orphans/duplicates). New page → add it to the area file that owns it.
- Links: relative `.md` (`../foundations/overlays.md`, `menu.md#events`). Main Rivet docs: absolute `http://127.0.0.1:4321/<path>/`.
- Directives: `::example{id=<id>}`, `::api{symbol="@rivetjs/cdk/<entry>#name"}`, `:kbd[Escape]`, `:term[…]`; callouts `:::note|tip|warning|gotcha`. No raw HTML.
- Component page template (mirror the upstream React Aria Components page):
  1. Intro + hero example. 2. Anatomy (rendered HTML block, parts table: element, default `rv-*` class, data attributes, ids). 3. Import snippet.
  4. Props table (EVERY prop from the source types in `libs/cdk/<module>`: type, default, notes) + Events table.
  5. Feature sections, each ≥1 live example: content/slots, value & selection (controlled/uncontrolled), disabled, validation, component options, events.
  6. "DOM events and attributes": which element each `*Props` part object lands on, which events the component owns (its behaviour runs first). `on*Capture` handlers do not resume yet.
  7. Styling: class/data-attribute table, Tailwind example, plain-CSS example, `@rivetjs/cdk/theme.css` note, transitions (overlays).
  8. Accessibility: roles/ARIA, keyboard table (`:kbd[…]`). 9. Resumability: what ships before interaction, slot/callback rules, limitations.
  10. Testing (`@rivetjs/testing` helpers, if any). 11. Upstream: ported APIs, deviations, "Not yet supported".
- Foundations/utility pages: API table for every export + examples per function/option.
- Document only what the code does (read source + tests in `libs/cdk`); never invent props.

## Examples (examples/<id>/)
- Files: `example.ts` (`export default defineExample({...})` from `@rivetjs/docs-kit/define.ts`), `src/routes/index.tsx`, `src/styles.css`, optional `src/components/*.tsx`. Merged over `templates/starter-static` (static mode default); built as a real production app.
- `defineExample`: `title`, `summary`, `tags`, `status`, `frame: { height: "xs"|"sm"|"md"|"lg"|"xl"|px, auto?: true }` (`auto`: frame follows its content height; docs-kit CLAUDE.md "Frame height"), `show: [files]` (code tabs), `test: Step[]`. `Step` schema: [libs/docs-kit/CLAUDE.md](../../libs/docs-kit/CLAUDE.md#example-step-schema-definets-runner-toolsexamplests-run).
- `test` steps run in Chromium during the build; any failing step or console error FAILS the build. Tests must verify the behaviour shown.
- Mark the shown region in `index.tsx` with `// #region demo` / `// #endregion`.
- Naming: `<component>-<facet>` (`select-events`, `select-tailwind`, `select-css`, `select-slots`, `select-controlled`). Ids unique within the example and stable (tests use them).
- Resumability in example code: callbacks as inline arrows or local consts; closed-overlay content / slots containing components as render functions `{() => …}`.
- Tailwind examples: `styles.css` = `@layer theme, base, rivet, components, utilities; @import "tailwindcss"; @import "@rivetjs/cdk/tailwind.css"; @source "./**/*.{ts,tsx}";`. Plain-CSS examples: no Tailwind import, rules on `rv-*` classes and `[data-*]` / `[aria-*]`.
- `src/generated/examples.json` is what `<Example>` reads (server only, from disk); `examples/_quarantine.json` = known check failures (id → step + reason), reported as quarantined by the build.
- Native-select checks (`calendar-pickers`, `range-calendar-pickers`) use Home/End/ArrowDown on Linux and letter type-ahead on other platforms: Cloudflare's Chromium 153 headless-shell ignores select type-ahead, while local macOS Chromium ignores the navigation-key selection path. Both paths assert the same calendar updates; this changes check inputs only, not components or their shown source.

## Icons (HIGH PRIORITY)
- Never hand-write SVG paths; never use UTF symbols or emoji (✓ × ▾ ▸ → ★ 🗑 …) as icons. Use lucide (`lucide` package, icon data).
- In an example: copy `examples/menu-slots/src/components/Icon.tsx` to `src/components/Icon.tsx`, then `import { Check } from "lucide"; <Icon icon={Check} class="…" />` (`size`, `strokeWidth`). Examples are standalone apps, so each keeps its own copy.
- In the site / docs-kit UI: `import { Icon } from "@rivetjs/kit/icon"` (same API, default size 24; server + client).
- Tests assert icons by element (`{ matches: "#id svg.check" }`), not by glyph text.
- Overlay arrows: `<OverlayArrow>` child holding a CSS-shaped `<span class="tip" />` (`clip-path` triangle), not an SVG path; rotate per `data-placement` (`placement-*:` Tailwind variants).
- lucide has no brand icons: the GitHub links (footer) are text.

## Gotchas
- Generated routes in `src/routes/(docs)/` are overwritten on every prepare/build: edit the `.md`.
- `src/styles.css` has `@source not "./generated/**"`: Tailwind otherwise scans the 21 MB examples manifest + `api.json` (Vite phase 16.7 s → 7.5 s); classes only present as text in that data are intentionally not generated.
- Calendar / DatePicker presets (no children) render their buttons without an icon (headless): date examples compose the parts and pass lucide icons (`<Button slot="previous"><Icon icon={ChevronLeft} /></Button>`).
- Date examples wrap the route in `<I18nProvider locale="en-US">` (no `locale` / `timeZone` props) and compose the parts (pickers: a local `src/components/RangePickerParts.tsx` in date-range-picker examples). Calendar / RangeCalendar resumed-page focus bugs are fixed (K4): keyboard-first and first-click steps work, no warm-up. DateField / TimeField tests start with `{ press: [segment, key] }`.
- The `drag` step (Playwright `dragAndDrop`: one pointer move) never starts an Angular CDK drag (the first move past the threshold only starts the sequence) and races the visible-preload of resumed frames: `drag-drop-*` tests check structure / non-drag interactions; their drags were verified with stepped CDP mouse events against the built frames (2026-10-08).
- Ports 4320–4326 are shared by both sites; don't start extra servers on them.
- A full `examples` run (no ids) stops at the first failing check and writes NO manifest (it replaces it); fix failures with per-id runs (they merge), then rerun the full set. Steps must not race overlay exit transitions (reopen after `{ absent: "#menu" }`).
