# apps/ui-docs/src/home

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Home page (`/`) of the ui docs, mounted by `../routes/index.tsx` (HOME-UI 2026-10-27). Layout and feel: centered hero, a dense live component collage on a soft panel, then Themes / Dark mode / Accessibility / Customization / component directory / final call. Rivet brand (logo gradient); upstreams may be credited (React Aria, HeroUI; ruling 2026-10-27); icons lucide via `@rivetjs/kit/icon`; images reused from `../../examples/_assets/` (`?image`).

## Files
- `data.ts`: `ACCENTS` (10 colour presets for the swatches: id, label, hex from the preset's OKLCH accent via `oklchToHex`), `accentOf(color)`, `LOOKS` (look presets + theme builder links, as the `theme-swap` example), `SCREENS` (showcase views → `/examples/showcase-<id>/frame/` + page), `CATEGORIES` / `COMPONENT_COUNT` (Components nav minus overview: a new component page appears in the directory and the counts by itself).
- `Hero.tsx`: static. CTAs = `<a>` with `buttonVariants`; starter command in a docs `.code-panel` + docs-kit `CopyButton` (page script copies; `.code-block` is taken by the ui chat-message / code-block CSS on this page).
- `Showcase.tsx` `ShowcaseBar`: Segment view switch (`selectedKey` signal) + `ColorSwatchPicker`. The collage is its SIBLING (`#home-collage` in the route), not a child: a press wakes this toolbar only, never the tiles. So the swatch `onChange` writes `#home-collage`'s `data-ui-preset` itself (`applyPreset`, `presets.ts`), and CSS hides the collage while a screen is open (`.uih-showcase-head:not([data-view="components"]) + .uih-collage`). A picked screen = an example-frame iframe rendered only while picked.
- `Bento.tsx` `Bento`: the collage, one component per tile (`data-tile=<name>`; separate boundaries). Static tiles have no handler / signal (0 JS). Avatars are markup with `avatarVariants` slot classes + `Picture` (the Avatar component probes its image / fallback timer in a `clientEffect`, which would boot the runtime at load); the verify code likewise = `inputOTPVariants` slots (InputOTP mirrors / caret / ResizeObserver are load-time effects). DatePicker uses a fixed `parseDate` (no today-dependent markup). Overlays portal into `#home-overlays` inside the collage (`PortalProvider` in the route) so they keep the preset. Column 3 spans two columns as a 2-column grid between `md` and `xl`; `max-md:hidden` / `max-xl:hidden` wrappers drop secondary tiles on narrow screens.
- `Themes.tsx`: `LookBar` (Segment over `LOOKS`; `onSelectionChange` writes `#home-looks` `data-ui-preset` via `applyPreset`, the builder link follows the signal) + `LookPreview` (`#home-looks`: plan / settings / assistant cards + blobs shown for Glass).
- `Sections.tsx`: `DarkModeSection` (static; light panel = `[data-theme="light"]` (rivet.css declares the light tokens on it), dark panel = `[data-theme="dark"] > [data-ui-theme="rivet"]` (scoped.css; docs-kit's unlayered dark tokens would win on the `[data-theme]` element itself). A `[data-ui-preset]` light island is impossible under a dark `<html>`: presets.css matches `[data-theme=dark] [data-ui-preset]` with higher specificity), `AccessibilitySection` (RadioButtonGroup = native radios: arrow keys work before any script), `CustomizeSection` (hand-tokenized code spans + default vs customized Button), `ComponentsSection` (directory), `CtaSection`.
- `presets.ts`: `applyPreset(id, preset)` links `@rivetjs/ui/styles/themes/presets.css` (`?url`, ~170 KB raw) on the first call, then sets `data-ui-preset`. Not in route CSS: lightningcss duplicates it to ~576 KB and docs-kit would inline it as critical CSS.
- `home.css`: route CSS (`/` only). Layout classes `uih-*` on ui tokens; resets of docs-kit rules that share class names with ui ones (`.uih .card`, `.card p`, zero-specificity base headings), as `../theme-builder/theme-builder.css`.

## Rules / gotchas
- Everything renders inside `.uih[data-ui-theme="rivet"]` (scoped.css in the site stylesheet): ui tokens there, docs tokens (`--fg`, `--line`, …) still from `:root`.
- New ui component on the page: its CSS comes with its import (no stylesheet edit); check class-name collisions with docs-kit (`../../CLAUDE.md` `src/styles.css` entry) and reset in `home.css`.
- No load-time work: a component with a load / idle / visible effect (`clientEffect` without `when`) puts `data-boot` on the boundary tail and starts the runtime + the page's whole boundary chain before input (measured: InputOTP → 262 JS files / 325 KB before input). `../../tests/home.test.ts` fails on `data-boot`; render such parts as static markup with the component's variants.
- `/` is NOT a `leanPages` entry (user ruling 2026-10-27): docs fetch-ahead prefetches the collage handler modules (~260 files / ~320 KB) at idle, low priority, never executed before input; first press ≈ 0.45 s at 4× CPU (lean: 1.1–1.4 s). Nothing boots at load (`data-boot` guard in `tests/home.test.ts`).
- Interactive parts must work on a cold page (first input): `../../tests/home.test.ts` (built site) covers swatches, view switch, Follow, Save, Rating, look switch, keyboard radios.
