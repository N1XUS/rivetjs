# apps/ui-docs/src/theme-builder
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

`/themes` theme builder (heroui.com/themes counterpart). Route: `../routes/themes.tsx` (renders `<ThemeBuilder/>`). Derivation: `@rivetjs/ui/theme` (libs/ui, port of HeroUI's builder algorithm).

## Files
- `ThemeBuilder.tsx`: signals per value (lightness / chroma / hue / base / radius / formRadius / vibrant / mode); `computed` params → `resolveParams` (preset overrides) → `deriveTheme` → `themeVariables` (inline `style` of `.tb-stage`, all tokens + derived formulas + radius, so the preview ignores the docs `:root` tokens), `themeCss` (code panel, copy / download), `auditContrast` (WCAG AA + APCA summary; failing pairs list ratio + Lc with their thresholds). Controls: presets (`THEME_PRESETS`), cdk `Slider` ×4 (value = Signal; free drag + animated snap), segmented radius / mode buttons, vibrant checkbox, shuffle / reset / share link. URL sync: `url-sync.tsx` `syncUrl(…signals)` (the one load-time `clientEffect`: first run reads `location.search` + the site's `data-theme`, later runs `history.replaceState` the query — `state.ts` `toQuery`; empty query = Rivet defaults).
- `Preview.tsx`: the stage content. `@container` root (`.tb-preview`) + `#tb-overlays` + cdk `PortalProvider container="#tb-overlays"` around `Toast.Provider` and the tiles: every overlay (Select, ComboBox, DatePicker, Dropdown, Popover, Tooltip, Modal, toasts) portals inside `.tb-stage`, so it inherits the edited theme (inline vars) instead of the docs tokens on `<body>`. Masonry = CSS columns on the stage width (`columns-1 @2xl:columns-2 @5xl:columns-3`, tiles `break-inside-avoid`). Own tiles: Team members (Avatar, Chip, Button), Uploads (ProgressBar, Meter, ProgressCircle, Spinner), Buttons (every variant / size, Badge), Status (Alert ×4 + toast buttons success / warning / danger), Chips and badges (AvatarGroup, Badge), Calendar view (ToggleButtonGroup, Kbd, Separator, Skeleton, Link), token swatches (Surface).
- `preview-forms.tsx`: AccountCard (TextField + Input, InputGroup prefix icon + password toggle, Description, Select, ComboBox, Checkbox, Button full-width / outline, Link), SettingsCard (Switch list with Description, Segment, Slider, Switch with icon thumb, NumberStepper disabled by the switch), PlanCard (RadioButtonGroup plan cards, Tooltip with arrow, Popover reading the plan signal, Dropdown with icons / Kbd / danger item, Modal danger confirm). Fields on cards use `variant="secondary"` (HeroUI on-surface).
- `preview-data.tsx`: InvoicesCard (Table multiple selection over a `Selection` signal + selection count, status Chips, Pagination; `Table.ScrollContainer` scrolls inside the card on phones), BookingCard (RangeCalendar + DatePicker with popover Calendar; fixed `parseDate` values: no today-dependent markup), ProjectCard (Breadcrumbs, Tabs with render-function panels holding TagGroup / activity / Accordion), AssistantCard (ChatMessage user / assistant + ChatMessageActions Copy, PromptInput appending the sent text as a user turn).
- `url-sync.tsx`: the load-time effect, in a leaf module on purpose. It reads the signals itself (no `values` capture): a resumed effect fetches its symbol's chunk + the chunks of what it captures, and each chunk evaluates the module its symbol comes from — inside `ThemeBuilder.tsx` (or capturing its `values` computed) it pulled `Preview.tsx` and every ui component (+258 chunks / 320 KB br at load).
- `content.ts`: the tiles' invented data (`COLORS`, `PEOPLE`, `TOKENS`, `VIEWS`, `INVOICES`, `STATUS_COLOR`, `TOPICS`, `FAQ`, `ANSWER`, `ROLES`, `TIMEZONES`, `CHANNELS`, `PLANS`). A `.ts` leaf: a resumed symbol reading a module-scope const of a tile module evaluated that module and all its ui imports.
- `state.ts`: URL query names = HeroUI's (`lightness`, `chroma`, `hue`, `base`, `radius`, `formRadius`, `vibrantPalette`), ranges, track gradients.
- `theme-builder.css`: route CSS (linked on /themes only): `@reference "../styles.css"` + component CSS of the preview components (the site stylesheet has none since HOME-UI 2026-10-27; each component module also imports its own; incl. the docs class-name collisions `card` / `menu` / `menu-item` / `tag`; same order as `@rivetjs/ui/styles/components/index.css`), builder styles on docs-kit tokens, `.tb-stage .card` reset of docs-kit's `.card` (+ `.card__description` colour: docs `.card p` beats it), zero-specificity `h1`–`h4` reset of docs-kit's base headings (display font, docs colour), `.tb-stage .menu-item` reset (colour, focused background) of docs-kit's theme-menu `.menu-item`; `.tag` needs none (`.tag--<variant>` wins).
- Guide page: `../../content/start/themes.md` (describes the builder + preview; update it with the preview).

## Gotchas
- Handlers: inline arrows over signals only (resumable). No mode in the URL (follows the site theme on load).
- cdk Slider dev a11y: the dangling thumb `aria-labelledby` (`<id>-0-label`) is fixed in cdk (2026-10-08). Remaining: runtime dev a11y `label-control` warns that the slider `<Label>` "is not associated with a control" — RA drops the label's `for` on purpose (VoiceOver iOS bug) and labels the group via `aria-labelledby`; the dev check (libs/runtime/dev/a11y.ts) should skip labels referenced by an `aria-labelledby`.
- Preview perf (2026-10-09, `--no-checks --no-search` builds, Chromium cold, load + quiet, brotli; lane PRELOAD-VISIBLE harness): scripts / KB before the first input at 1280×720: old preview 174 / 194 → whole-library preview 381 / 474 → PRELOAD-VISIBLE (effect leaf + `content.ts` + docs-kit `code-watch.tsx` + loader visible-area fix) 214 / 255; 1440×1000 402 / 486 → 329 / 380. With the planner's background budget (`preload.background`, 2026-10-11) below-fold widgets also prefetch at idle: 1280×720 HEAD 386 / 474 → 359 / 441 with these leaves; numbers in `docs/benchmarks/2026-10-11-preload-background.md`. Remaining: load-time cdk effects (Tabs ScrollShadow, Table, Checkbox) capture props recipes of their parent tiles, so the tiles' render chunks load with them (one chunk per component; `libs/compiler/vite.ts`), and `visible` directives (Select parts, ListBox, …) of tiles near the viewport. A load-time effect must not live in (or capture computeds / functions of) a module that imports heavy components.
- New overlay component in the preview: it must portal through cdk `Portal` / `Overlay` (PortalProvider-aware); one that appends to `document.body` itself would lose the theme.
