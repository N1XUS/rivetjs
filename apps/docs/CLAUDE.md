> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

## Pages (content/*.md)
- Frontmatter: `title`, `description` (≤160 chars), `template` (`guide`, `concept`, `recipe`, `best-practice`, `gotcha`, `reference`, `tutorial`, `page`, `home`, `stub`), `status`, `since`, `tags`, `related: [section/page, …]`.
- Every page appears exactly once in `_nav.ts` (build fails on orphans/duplicates).
- Links: relative `.md` links between pages. Directives: `::example{id=…}`, `::chart{id=…}` (`content/_charts.ts`), `::api{symbol="@rivetjs/pkg/entry#name"}`, `::starter{…}`, `:term[…]`, `:kbd[…]`; callouts `:::note|tip|warning|gotcha`; fence meta `compiled` (tsx/jsx: real dom + server compiler output behind a switch, e.g. `learn/signals.md` Cart). No raw HTML. Full list: [libs/docs-kit/tools/content/CLAUDE.md](../../libs/docs-kit/tools/content/CLAUDE.md).
- `TODO-CONTENT` marks placeholder pages (`check-content --strict` fails on them).
- Plain language: say what the reader can do after the page; document only what the code does. Behaviour claims (resume, live props, serializability) are verified by a compile / render probe before they land; known runtime gaps go in a `:::gotcha`, not silently omitted.

- Files: `example.ts` (`export default defineExample({...})` from `@rivetjs/docs-kit/define.ts`), `src/routes/**.tsx`, `src/styles.css`, optional `src/components/*.tsx` (auto-listed as resume modules), optional server files. - `test` steps run in Chromium on a production build; a failing step or console error FAILS the build.
- `// #region demo` / `// #endregion` marks the focused code. Callbacks: inline arrows or local consts (resumable).
- `src/generated/examples.json` is what `<Example>` reads (server only, from disk); `docs-kit examples apps/docs` regenerates it and lists the code-only examples (server mode, i18n, own document, dynamic pages, absolute links) with the reason.
- `examples/motion-*` (`@rivetjs/motion` guide pages `content/guides/motion/*`, dep `@rivetjs/motion` + `motion`): example frames render after the head is sent, so Motion entrances take the custom-property form — examples with entrances import `@rivetjs/motion/entrance.css` (test steps assert `data-mvv`, not `data-mve`).

## Icons (HIGH PRIORITY)
- Never hand-write SVG paths; never use UTF symbols or emoji (✓ × ▾ → ★ + − …) as icons. Use lucide (`lucide` package, icon data).
- In an example: `src/components/Icon.tsx` (copy from `examples/computed-total/src/components/Icon.tsx`), then `import { Plus } from "lucide"; <Icon icon={Plus} />`. Examples are standalone apps: each keeps its own copy.
- In the site / docs-kit UI: `import { Icon } from "@rivetjs/kit/icon"` (same API, default size 24; server + client). lucide has no brand icons: the GitHub links (footer) are text.

- Code fences: `node libs/docs-kit/cli.ts check-snippets apps/docs` (syntax + `@rivetjs/*` import drift; fence meta `nocheck` skips pseudo-code, `check` = full typecheck).

## Gotchas

- `content/guides/tooling/ai.md` documents portable `rivet-ui-design` installation for Codex/Claude Code/Cursor, local-clone and post-push remote commands, complete-bundle copying, automatic/explicit invocation, and optional MCP. The public bundles and starter copies are generated from `libs/mcp/ai`; keep this guide aligned with that source.
- `content/_charts.ts` imports `docs/benchmarks/*.json`: `serve` does not watch `docs/`, so a regenerated report needs a content touch or rebuild.
- Generated routes in `src/routes/(docs)/` are overwritten on every prepare/build: edit the `.md`.
- `src/styles.css` has `@source not "./generated/**"`: Tailwind otherwise scans the 21 MB examples manifest + `api.json` (Vite phase 16.7 s → 7.5 s); classes only present as text in that data are intentionally not generated.
- `tests/content.test.ts` / `site.test.ts` import docs-kit files by path: renaming docs-kit tools breaks them.
- Ports 4320–4326 are shared by both sites; don't start extra servers on them.
