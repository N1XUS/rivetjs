This page walks through the static starter (`templates/starter-static`). After reading it, you know where pages, components and styles go, which files you edit, and which files are made by the build.

## The files at a glance

```txt
my-app/
├── package.json        scripts (dev, build, preview, check), dependencies, engines
├── vite.config.ts      Vite with the Rivet router plugin
├── tsconfig.json       TypeScript and JSX settings
├── prerender.js        writes every page to an HTML file (static sites)
├── serve.js            serves the built site on your machine
├── src/
│   ├── document.ts     the HTML around every page
│   ├── styles.css      global styles (Tailwind)
│   ├── components/
│   │   └── Counter.tsx a component used by a page
│   └── routes/
│       ├── _layout.tsx wraps every page
│       ├── index.tsx   the page at /
│       └── about.tsx   the page at /about
├── .rivet/             generated by the build; do not edit
└── dist/               build output
```

## Pages: `src/routes`

Each `.tsx` file in `src/routes` is a page. The file path is the URL:

| File | URL |
| --- | --- |
| `src/routes/index.tsx` | `/` |
| `src/routes/about.tsx` | `/about` |
| `src/routes/books/index.tsx` | `/books` |
| `src/routes/books/[id].tsx` | `/books/1`, `/books/2`, … |

A page file has a default export: the page component. It can also export `head` for the page title:

```tsx title="src/routes/about.tsx"
export const head = { title: "About" };

export default function About() {
  return <h1 class="text-2xl font-bold">About</h1>;
}
```

Files that start with `_` are special. `_layout.tsx` wraps every page in its folder and in the folders below. `_404.tsx` and `_error.tsx` show "not found" and error pages. [File routes](../guides/routing/file-routes.md) lists all the rules.

A page file can also hold code that runs only on the server: exports wrapped in a call from `@rivetjs/router`, such as `load(…)` (loading data), `guard(…)` (checking access) and `actions(…)` (handling forms). The compiler removes them from the browser build. The static starter has none; the server starter (`templates/starter-server`) has a `load(…)` and `actions(…)` in `src/routes/index.tsx`. See [loading data](../guides/routing/loading-data.md) and [server code in route files](../guides/routing/server-code-in-routes.md).

## Components: `src/components`

Put components that pages share in `src/components`, or anywhere outside `src/routes`. Import them with the file extension:

```tsx
import { Counter } from "../components/Counter.tsx";
```

:::note
Components resume in the browser without being listed anywhere: `rivetRouter` compiles every `.tsx`/`.jsx` file of your project that a route imports (not `node_modules`, not files outside the project root). Set `resume: { appModules: false }` to list files yourself in `resume.modules`.
:::

## `vite.config.ts`

Rivet runs as a Vite plugin. `rivetRouter()` from `@rivetjs/router/vite` reads `src/routes`, configures the compiler and builds both the server and the browser code:

```ts title="vite.config.ts"
import { defineConfig } from "vite";
import tailwindcss from "@tailwindcss/vite";
import { rivetRouter } from "@rivetjs/router/vite";

export default defineConfig({
  plugins: [
    rivetRouter({
      mode: "static",
      styles: ["src/styles.css"],
    }),
    tailwindcss(),
  ],
});
```

- `mode`: `"static"` makes HTML files at build time. `"server"` (the default) renders pages on each request. See [rendering modes](../learn/rendering-modes.md).
- `styles`: stylesheets that every page links.
- `resume.appModules` (default `true`): resume every app component file a route imports. With `false`, list the files in `resume.modules`.
- Not set in the starter, often useful: `devtools: false` (turn off the [DevTools](../guides/tooling/devtools.md) panel on the dev server), `dev: { resume: false }` (dev pages render in the browser from the first load), `transitions` (view transitions on client navigation, see [transitions](../guides/routing/transitions.md)).

[Vite](../guides/tooling/vite.md) and [config reference](../reference/config.md) list all options.

## `src/document.ts`

The HTML around every page: `<html>`, `<head>`, `<body>`. Rivet puts the page between `start` and `end`. The page's `head` export (title, meta tags, links) and the stylesheets are passed in:

```ts title="src/document.ts"
import { headTags, type DocumentShell } from "@rivetjs/router/server";

const document: DocumentShell = ({ head, styles }) => ({
  start:
    '<!doctype html><html lang="en"><head><meta charset="utf-8">' +
    headTags({ title: head?.title ?? "Rivet app" }) +
    styles.map((href) => `<link rel="stylesheet" href="${href}">`).join("") +
    "</head><body>",
  end: "</body></html>",
});
export default document;
```

The starter's version also passes `meta` and `links` from `head` and sets the viewport.

## `src/styles.css`

Global styles. The starter uses Tailwind CSS v4 through its Vite plugin. Tailwind is your choice, not a Rivet requirement. See [CSS and Tailwind](../guides/styling/css-and-tailwind.md).

## `tsconfig.json`

TypeScript settings. The two that matter for JSX:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "jsx": "preserve",
    "jsxImportSource": "@rivetjs/runtime",
    "noUncheckedSideEffectImports": false
  },
  "include": ["src", "*.ts", ".rivet/routes.d.ts"]
}
```

`jsx: "preserve"` leaves JSX to the Rivet compiler. `jsxImportSource` gives your editor the JSX types. `noUncheckedSideEffectImports: false` keeps TypeScript 6 and later from reporting `import "./styles.css"` (TS2882). `.rivet/routes.d.ts` adds the types of your routes. The starter also lists `plugins: [{ "name": "@rivetjs/typescript-plugin" }]`, which shows Rivet compiler errors in your editor; see [editor setup](editor-setup.md).

## Generated: `.rivet/`

The router plugin writes this folder each time you run `vite` or `vite build`: the route table, the app that connects routes, the server entry and route types. Do not edit these files; they are rewritten. The starter's `.gitignore` lists `.rivet/`, `dist/` and `node_modules/`.

## Build output: `dist/`

After `npm run build`:

- `dist/client`: what the browser gets. HTML files (one folder per page), `_data.json` files for client navigation (only when some page resumes), `404.html`, and `assets/` with scripts and styles. Deploy this folder to any static host.
- `dist/server`: the server build. The static starter uses it only to render the HTML files.

The script files in `dist/client/assets` hold the browser code: the resume runtime (`derived-runtime-….js`, with the code every component shares in `dom-derived-abi-….js`; `dom-lite-….js` and small lite chunks for pages whose interactive components are all simple enough, see [Chunks](../guides/performance/chunks.md)), one chunk per component file that can wake up (for example `index-….js` for `src/routes/index.tsx`, `app-….js` for the generated app and its layouts) and the shared chunks they import. After a page loads, the browser fetches the ones it may need at low priority; it runs them only when you use the page.

## `prerender.js` and `serve.js`

- `prerender.js` calls `prerenderBuild({ dist: "dist" })` from `@rivetjs/router/static` and writes every page into `dist/client`.
- `serve.js` serves `dist/client` on port 4173 for `npm run preview`.

The server starter has a different `serve.js`: it calls `start({ dist: "dist" })` from `@rivetjs/router/node` and renders pages for each request. See [deploying to Node.js](../guides/deploy/node.md).
