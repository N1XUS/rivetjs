# @rivetjs/ssr-bench

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Static SSR throughput/latency/memory benchmark in Docker: every frontend fetches the same deterministic fixture via one native unary gRPC call per page and streams the same HTML. Lanes: Rivet (hand emitter + compiled JSX + keyed `<For>` + `@rivetjs/router` file routes), Solid 2 / Solid 1, Qwik 2 / Qwik 1, ASP.NET Razor (.NET 10). North star: beat Razor (and every lane) on CPU/page, complete p50, TTFB, peak memory under identical 1 CPU / 512 MiB quotas.

## Entry points

- `build.ts` — builds every lane → `dist/<lane>.mjs` (`rivet`, `solid`, `qwik`, `solid-stable`, `qwik-stable`, `solid-stable-string`, `solid-stable-static` (Solid 1 `hydratable:false`), `solid-stable-interactive`, `rivet-compiled`, `rivet-for`, `rivet-router`, `rivet-derived`), Qwik client dirs `dist/client{,-stable}`, router app builds `dist/rivet-router/{client,server}` (Vite + `rivetRouter()`) and `dist/rivet-derived/{client,server}` (`router-app/vite.derived.config.ts`, `resume.model: "derived"`), `dist/server.mjs` (plain-JS HTTP server), `dist/builds.json`. Rejects stale `proto/generated.sha256`.
- `server.ts` — shared HTTP server (every lane except `rivet-router`/`rivet-resume`/`rivet-derived`); adapter contract `renderPage(page, { signal, articleHtml }, sink)`; `/page?rows=&token=&article=1&strings=1`, `/api/articles/performance`, `/health`, `/metrics`.
- `stable-build.ts` — stable Solid/Qwik compiler + resolver from `../bench-stable`.
- `benchmark.py` (via `run-python.ts`, needs Python 3.12+ / `RIVET_BENCH_PYTHON`) — builds images, runs Compose, drives load, writes reports. `--gc tuned|default` (GC profile for ALL Node lanes + Razor), `--strings` (escaping variant, `strings=1`), `--grid` (text-grid variant, `strings=2`: Razor-adversarial scenario, `docs/benchmarks/razor-adversarial.md`), `--prewarm S` (default 10), `PATHS` (rivet-resume / rivet-derived → `/resume`), `metadata.provenance` (generator sha, window, GC, container commands). `report.py`, `serve-report.py`, `load.py` (legacy generator).
- `cpu-breakdown.ts <file.cpuprofile> [--requests N] [--json]` — self time by owner: `rivet` (lane bundle / router build), `data` (shared gRPC client + decoder), `http` (Node core writes), `harness` (`dist/server.mjs` glue), `gc`.
- `fair-report.ts` — like-for-like report over finished runs (+ dom/resume/scoreboard JSON) → `docs/benchmarks/<name>.{md,json}` (`--title` heading); static vs resumable peer classes; verdicts via `../dom-bench/verdict.ts`; `--notes <file.md>` appends a hand-written section (audits, CPU profiles, caveats; edit the notes file, never the generated `.md`); `--store-competitors` rewrites `../dom-bench/competitors.json` with provenance.
- npm: `bench:ssr`, `bench:ssr:report`, `test:ssr`, `test:ssr:integration`.

## Zero-cost gate (`scripts/zero-cost/check.sh`)

- Runs `node apps/ssr-bench/build.ts`, then `lanes-hashes.mjs apps/ssr-bench/dist` → sha256 (12 chars) of **every** file in `dist/` vs `scripts/zero-cost/lanes.txt` (rendered lane bundles, Qwik client builds, `server.mjs`, `builds.json`).
- Any byte change in `adapters/`, `fixture/`, `services/`, `server.ts`, `build.ts`, `stable-build.ts`, `apps/bench-stable` versions, or the runtime/compiler shows up there. Doc-only / refactor changes must keep it identical; intended deltas: `sh scripts/zero-cost/check.sh --update`.
- `libs/compiler/oracle/corpus.jsonl` embeds the `rivet-compiled.jsx` source as a compile case; `scripts/size-report.mjs` also builds here and reads `dist/builds.json`.

## Rules / invariants

- Same DTO, ten fields per row, article HTML, per-request token, strict validation, quotas for every lane. No page or data caching.
- Same Node runtime (Node 26.11.1 image) and same data client (`services/content.server.ts`, lean `node:http2` unary gRPC, decode outside any call-state chain) for every Node lane — 2026-10-09 (PERF-TRANSPORT F0 / F2 / F3, orchestrator decision). Never a lane-owned data path or representation (F1 `Utf8Text`-style byte text for Rivet only was rejected). Pre-2026-10-09 numbers (Node 24.14 + grpc-js) are a different provenance.
- Same GC profile for every Node lane (compose `x-node` command; never a per-lane flag) — round-2 B2. Bun/Deno lanes take the profile from `benchmark.py` `GC_PROFILES` (Deno `--v8-flags`, Bun `BUN_JSC_useConcurrentGC=0`; JSC has no semi-space knob). Rank like-for-like only: rivet-compiled vs static peers (dotnet, solid-stable-static), rivet-resume vs hydratable/resumable peers (solid*, qwik*; `fair-report.ts` `RESUMABLE_PEERS` lists `solid-stable-interactive` first — the like-for-like peer).
- Never compare numbers with different `metadata.provenance` (generator sha, duration, warmup, GC profile, strings, rate) — round-2 B1.
- Bench scope allowed for the Rivet lane: Node tuning, generated decoder, byte-level emit, native hosting — same container limits as Razor.
- Stable lanes resolve only through `apps/bench-stable`; Solid 2 must not enter the Solid 1 bundle.
- Adapter safety: hostile token attribute preserved, exact field text, no injected script.
- Frontend quota 1 CPU for every comparison. `--cores N` (1–16, MULTICORE 2026-10-12) is a scaling probe only: compose `cpus: ${SSR_BENCH_CORES}` for every node lane + `RIVET_WORKERS` → `router-app/server.ts` `start({ workers })` (rivet-router lanes only; other lanes stay one process), recorded in `metadata.frontend_quota.cpus`. Never rank lanes from a `--cores` > 1 run.
- Run measurements with no other builds/tests running; `--skip-build` after a successful build (also passes Compose `--no-build`).

## Gotchas

- C# protobuf regen: Grpc.Tools' linux_arm64 protoc segfaults (exit 139) — use the SDK image under `--platform linux/amd64`, copy the project to a temp dir, `dotnet build -c Release -p:GenerateProto=true`, copy `Generated/*.cs` back, then update `proto/generated.sha256`.
- `rivet-compiled-baseline` requires the retained image ID; it cannot be rebuilt from current source.
- Docker Desktop inflates syscall cost; read generator headroom warnings per case.
- `__pycache__/` dirs are gitignored build noise.
- Peak memory (`usage - inactive_file` = container anon pages) is a V8 / malloc high-water, not a live set: idle lane RSS is rivet-resume 60 MB vs solid-stable-interactive 72 MB, and the module graph is small. Prewarm runs at the largest row count, so later small-row cases inherit its heap. Solid drops back (~95 MiB at 100 rows) because V8's memory reducer runs in the gaps between trials (`--trace-memory-reducer`: "low alloc" → shrinking GCs, V8 pages 107 → 11 MB); for rivet-resume it reports "high alloc" and never shrinks (~165–190 MiB flat). Root cause (2026-10-07, `--trace-mutator-utilization`) is a V8 13.6 quirk, not idle work: `Heap::HasLowAllocationRate` also needs `HasLowEmbedderAllocationRate`, and `ComputeMutatorUtilizationImpl` returns 0 when the smoothed embedder (cppgc) allocation rate is exactly 0 → "high alloc" forever, even after 40 s fully idle (young/old rates ~0). rivet-router never allocates a cppgc object; Solid's first request loads `node:vm` (via Node web-streams internals), whose cppgc allocation keeps the rate > 0 — until it decays to 0 (100 ms half-life: ~110 s), after which Solid stays "high alloc" too (measured: 130 s of load → no reduce). So Solid's small-row drop is timing (cases right after prewarm), not a framework difference; same in V8 14.6 (Node 26). Correction (2026-10-07, 240 s idle curves): "never" was wrong — `WatchdogGC` (100 s after the last mark-compact) shrinks an idle rivet-resume at t≈110 s (RssAnon ~165 → ~67 MiB); a server whose idle gaps are < 100 s never shrinks. Fixed in the router node adapter (`idleMemory`, default on — `libs/router/adapters/CLAUDE.md`): one `new vm.Script("")` 1 s after the last request → reducer "low alloc" at its 2nd tick → shrink at t≈15 s. rivet-compiled / Solid lanes use the shared `server.ts` and are unaffected. Bug report draft: `docs/design/research/2026-10-07-v8-memory-reducer-embedder-rate.md`. Measured with `benchmark.py` (c=1, 2 paired off/on runs × 3 repeats; control lanes unchanged code): rivet-resume peak 179 → 151 MiB (100 rows), 192 → 185 (1000), 203 → 179 (5000); controls ±3 MiB; CPU/page and p50 moved with the controls (noisy host, load 15–34), in-container paired CPU A/B 100 rows 0.92 vs 0.92 ms, 5000 rows 30.3 vs 29.0 ms. At 5000 rows both lanes hold ~80–110 MB V8 pages (incl. ~20–38 MB pooled), 15–25 MB brk malloc, 15–35 MB thread arenas (compiler zones). Identical-code reruns vary ±10 MiB: compare memory only over several paired runs. Analysis 2026-10-07 in `../../libs/runtime/CLAUDE.md` (per-render closures).
- .NET tiered JIT: the first trial after a container (re)start is up to 3× slower — keep `--prewarm` on for real runs (switching `--gc` recreates containers).
- Razor's default `HtmlEncoder` emits non-ASCII as `&#x…;` in the strings variant (more bytes); production default, kept.
- Text grid (`--grid`, `strings=2`, 2026-10-07): Razor beats rivet-compiled on rps / p50 / TTFB / CPU at 1000 rows (CPU 2.6 vs 6.0 ms/page `default` GC c1); Rivet keeps peak memory. Cause: `putText` per-char loop for strings ≤ 64 units (`TEXT_INLINE` / `RAW_TEXT`). `docs/benchmarks/razor-adversarial.md`. Flipped 2026-10-09 by the shared Node 26 + lean h2 harness change: rivet-compiled 2.00 vs Razor 2.31 ms CPU/page, 358 vs 334 rps, 66 vs 94 MiB (grid c1, `docs/benchmarks/2026-10-09-transport-node26.md`). WebAssembly row emitter (runtime `server-rows.ts`, 2026-10-09): Docker single-lane probes grid c1 CPU 2.04–2.19 → 1.64–1.80 ms/page, c10 2.41–2.63 → 2.14–2.36, ints 1000 c1 0.56–0.58 → 0.37, ints 100 c10 0.082 → 0.069, escaping c1 −2 to −8%; lane outputs unchanged (`docs/benchmarks/razor-adversarial.md` last section).
- Grid Docker split (2026-10-08, `docs/benchmarks/razor-adversarial.md` "Where the Docker time goes"): render + HTTP ≈ 0.87 ms/page; the rest is the shared data layer. That is grpc-js, JS string decode, and ~1 ms GC from old-gen nepotism: old per-call objects keep each decoded page alive through scavenges, so every page is promoted. Decoding outside grpc-js fixes it for Rivet but not Solid; not applied (shared harness) at the time. Superseded 2026-10-09: grpc-js replaced by the lean `node:http2` client and Node 24 → 26 for every Node lane (see Rules; numbers in `docs/benchmarks/razor-adversarial.md` "Transport + runtime update").
- Deno lanes need Compose `init: false` (image entrypoint already runs tini; double init warns).
- Shared harness code (`server.ts`, `services/`, `loadgen/`) is the same for every lane — never optimise it for Rivet only; Rivet-owned = adapters, runtime writer, router build/handler.
- `rivet-router`: `article=1` → 400 (Rivet JSX has no raw-HTML sink); `/metrics` = `process.memoryUsage()` only (no request counters). Route modules type data via `PageProps<typeof loader>` so `tsc` works before `.rivet/` exists.
- Docker build stage copies `libs/router` (router lane); its Vite build hashes land in `scripts/zero-cost/lanes.txt` like every other `dist/` file.
