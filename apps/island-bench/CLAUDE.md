# apps/island-bench

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Framework-islands benchmark (lane BRIDGES T7, spec `docs/design/specs/2026-10-11-framework-bridges-design.md` §6.2): the same page — header with a React counter (`load`) + static React badge, a 1000-row server-rendered list, a React picker (`idle`), a React SVG chart (`visible`, below the fold) — in `rivet-bridge-react` (`@rivetjs/bridge-react`, the subject), `astro-react` (Astro 7.3.8 + `@astrojs/react` 7.0.1), `next` (Next 16.4.0 App Router, per-request SSR, RSC for the static parts) and `rivet-native` (same page as Rivet components, resumed: the ceiling). Preact pair (T8): `rivet-bridge-preact-p10` (`@rivetjs/bridge-preact` on astro-preact's Preact 10.29.8: same version, the headline) + `rivet-bridge-preact` (Preact 11.0.1, cross-version) vs `astro-preact` (`@astrojs/preact` 6.0.6, Preact 10.29.8), same page with the Preact twins of the components. Write-up: `docs/benchmarks/2026-10-12-islands.md` (+ `.json`, generated by `report.ts`; hand-written findings in `.notes.md`). Methodology: [README.md](README.md).

## Layout

- `data.ts` — seeded rows (1000 × `{ id, label, value }`), chart series (12), picker month. `site.css` — shared CSS (each build copies it).
- `components/*.preact.tsx` — Preact twins of the four components (`/** @jsxImportSource preact */`, `preact/hooks`, same markup with `class`), imported by the Preact pair lanes only.
- `components/*.react.tsx` — the four React components, imported by every React lane (relative paths; `/** @jsxImportSource react */` pragma so the Rivet-JSX project typechecks them). Markup hooks the runner reads: `#inc` / `#count`, `.day[data-d]` / `#picked`, `rect.bar[data-i]` / `#bar-label`, `span.badge`. `components/tsconfig.json` = React JSX project for editors.
- `lanes/rivet-bridge-react/` + `lanes/rivet-bridge-preact/` + `lanes/rivet-native/` — `page.tsx` (the page), `server.tsx` (`render(manifest, write)` = `renderResumable` streamed between fixed head / tail strings), `build.ts` → `rivet-build.ts` `buildRivetLane(dir, outDir, bridge, preactFrom?)` (Vite resume client build + SSR build; `bridge` = `"react"` / `"preact"` → that adapter's `/vite` entry, `null` for rivet-native; `preactFrom` = a `node_modules` folder whose `preact` / `preact-render-to-string` are aliased in both builds and bundled into the SSR output). `lanes/rivet-bridge-preact-p10/build.ts` = the rivet-bridge-preact page with `preactFrom` = `lanes/astro-preact/node_modules` (needs that lane's install; fails unless that install is preact 10.29.8 and the output has no Preact 11 renderer (`moveBefore`) and a Preact 10 core (`defaultProps`)) → `dist/<lane>/{client,server}`. `build-lane.ts <lane>` = CLI.
- Rivet lanes resume on the derived model (the only one since M6-CUT 2026-10-22). M6-PARITY smoke 2026-10-22: all three lanes hydrate + interact; islands via the lean boot; `page.tsx#Page` is still a boundary (the `rows.map` site over imported data), so the derived runtime + page chunk are fetched ahead after load (not run).
- `rivet-bridge-react-full` (T7b baseline, `offerLean` stubbed) deleted with the serialized model (M6-CUT 2026-10-22): no full-driver counterpart on derived; older reports keep its rows as history.
- `serve-rivet.ts <dist> <port>` — production server of the Rivet lanes: static assets from memory + streaming SSR, writes batched per `setImmediate` (a per-chunk flush cost 20× CPU/page). No compression (`IB_GZIP=1` turns gzip on, not used by the bench).
- `lanes/astro-react/` — own install (`package.json` pins + `package-lock.json`, `node_modules` gitignored), `astro.config.mjs` (`output: "server"`, `@astrojs/node` 11.1.7 standalone), `src/pages/index.astro` (`client:load|idle|visible`, badge static), `build.sh` (exit 3 = not installed).
- `lanes/astro-preact/` — same shape as astro-react with `@astrojs/preact` (own install ≈ 151 MB) and `vite.resolve.dedupe: ["preact"]` (the shared components sit outside the lane; without it they would resolve the workspace's Preact 11).
- `lanes/next/` — NO own install: `node_modules` = untracked symlink to `../../../editorial-bench/lanes/next/node_modules`, created by `run.ts` / `build.sh` when that install exists (both fail loudly otherwise). `app/page.jsx` (`force-dynamic`, badge as a server component), `app/islands.jsx` (`"use client"` re-exports), `next.config.mjs` (`compress: false`, `experimental.cpus: 2`, turbopack / tracing root = repo root for the shared components).
- `run.ts` — phases `build,server,browser` → `results/<stamp>.json` (or `--out`, merged across invocations). `report.ts --in … --out docs/benchmarks/<name> [--notes …]` → `.md` + `.json`.

## Rules / invariants

- Same React component sources, same data, same element structure in every lane; `run.ts` validates every lane's first page (1000 `<li`, island markers) before timing.
- No lane compresses (Astro's standalone node server cannot): server CPU = render + write; browser bytes = as transferred (raw) + a gzip -6 estimate of the same response bodies (CDP `Network.getResponseBody`).
- Ports 4431 (rivet-bridge-react), 4432 (astro-react), 4433 (next), 4434 (rivet-native), 4436 (rivet-bridge-preact), 4437 (astro-preact), 4438 (rivet-bridge-preact-p10). Never 4320–4329.
- `NODE_ENV=production` for every lane's build and server (`run.ts` sets it; React / Astro / Next pick their production builds by it; recorded as `host.env`). Runs before the 2026-10-12 review fix inherited an unset NODE_ENV: React DEV SSR in the bridge + Astro lanes.
- "Before input" window (browser phase): after `load`, until NO request is in flight (requestWillBeSent adds, loadingFinished / loadingFailed remove) AND no network event for 1 s. A single long download emits no events: Fast 3G runs before the 2026-10-12 DEMO fix ended the window mid-download (T7b / T8 Fast 3G "before input" bytes superseded).
- Optional env hook `IB_BENCH_LOCK=<script>`: `run.ts` calls `<script> acquire BRIDGES "<purpose>" <maxLoad>` / `release BRIDGES` around timed phases (maxLoad 4; `--loaded` passes 99 and the report labels the run "loaded host"). Unset = no lock, a note is recorded and the report says "smoke run". On shared agent hosts wrap the command in the host's CPU gate.
- Verdicts (report.ts): Preact pair in its own section (`rivet-bridge-preact-p10` = same-version headline and `rivet-bridge-preact` = cross-version, each vs `astro-preact`, same rules, own tallies); subject `rivet-bridge-react` vs each lane, WIN / LOSE at ≥ 1.1× and above a per-metric noise floor, else TIE; losses vs astro-react / next carry a "what Rivet would need" line; vs rivet-native = island cost (listed, not a loss).

## Commands

```sh
export PATH=/Users/denisseverin/.nvm/versions/node/v26.5.1/bin:$PATH
(cd apps/island-bench/lanes/astro-react && npm ci --workspaces=false --ignore-scripts)
(cd apps/island-bench/lanes/astro-preact && npm ci --workspaces=false --ignore-scripts)
(cd apps/editorial-bench/lanes/next && npm ci --workspaces=false)   # the next lane links this install (run.ts / build.sh create the symlink)
node apps/island-bench/run.ts --phases build
node apps/island-bench/run.ts --phases server,browser --out results/run.json   # optional IB_BENCH_LOCK=<lock script>
node apps/island-bench/report.ts --in apps/island-bench/results/run.json --out docs/benchmarks/2026-10-12-islands --notes docs/benchmarks/2026-10-12-islands.notes.md
npx nx run island-bench:typecheck
```

## Gotchas

- The bridge lane's React components compile with React's JSX through `@rivetjs/bridge-react/vite` (`rivet:react:jsx-source`); the explicit pragma in `components/` is for TypeScript, not the build.
- Browser phase: one discarded warm-up visit per lane and condition; every selected lane's server runs during the whole phase. Server phase: medians over rounds, peak RSS = max over rounds.
- Next's chart `chartReadyMs` is negative (the chart chunk loads before the scroll); the report does not use it.
- Next build: process tree ≈ 0.94 GB (2 workers); `/usr/bin/time -l` alone reports the largest process, so `run.ts` also samples the `ps` tree.
