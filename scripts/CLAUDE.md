# scripts/ — repo gates and generators

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Plain Node scripts run from the repo root (`export PATH=/Users/denisseverin/.nvm/versions/node/v26.5.1/bin:$PATH`). No build step; `.mjs` = plain JS, `.ts` = run via Node type stripping.

## Layout

- `docs-cloudflare.ts`: production build wrapper for `apps/docs`, `apps/cdk-docs`, `apps/ui-docs`: uses bundled Chromium + libraries on Linux without root access (Playwright installation elsewhere), supplies the three production origins, runs the complete docs build with `--no-checks` unless `DOCS_CHECKS=1` (2026-10-23: known-red examples on the derived-only model must not block deploys; "What loaded" paragraphs stay empty); UI then stages a lossless page-vs-assets/search partition under `dist/cloudflare` and enforces 20,000 files per Free-tier Worker. `stageUIAssets(root)` is exported for `tests/docs-cloudflare.test.ts` (same URLs/bytes, source preserved, headers in both, stale output cleaned).

## Zero-cost gate internals

1. `runtime-hashes.mjs` bundles each `exports` entry of `libs/reactivity` + `libs/runtime` with rolldown (minify, `process.env.NODE_ENV="production"`, conditions `import,production,default`) and prints hash + size → `$tmp/runtime.now` (plain, `[resumed]`, `[domData]` lines; see the table above).
   `packages-hashes.mjs` does the same for router/forms/i18n/kit/ui/motion/bridge/bridge-react/bridge-preact + `CDK_ENTRIES` (cdk masonry, masonry/behaviour, flip, scheduler and scheduler/layout) → `$tmp/packages.now`.
2. `node apps/ssr-bench/build.ts` rebuilds the bench lanes; `lanes-hashes.mjs` hashes every emitted file → `$tmp/lanes.now`.
3. `diff` against `runtime.txt` / `packages.txt` / `lanes.txt`; any difference = status 1 (`--update` moves the `.now` files over the baselines instead).
4. `dev-leaks.mjs`: no dev façade / devtools literal in any production entry (status 1 on a leak, also with `--update`). New devtools event → add it to `DEV_STRINGS`; new `development` façade module → `DEV_FILES`; new `#dev`-gated warning → its text in `DEV_MESSAGES`.
5. `condition-parity.mjs`: a name the `types` file promises but the production/dev/browser file lacks typechecks and breaks at bundle time — add no-op stubs (prod) or keep dev façades' extra helpers unexported (status 1).
6. `node libs/compiler/oracle/check.ts` runs the compiler parity corpus (`libs/compiler/oracle/corpus.jsonl`, recorded from the former TypeScript implementation): diagnostics must match exactly, emitted code after esbuild minification. Prints `N/N corpus cases match`.
7. Success output: `runtime + lanes: identical`, `dev leaks: none (N entries)`, `condition parity: ok (N entries)`, then the corpus line. A rolldown `codeSplitting … debugName` warning is expected noise.

Rules: an untouched feature costs 0 bytes — if an entry's hash changes for an entry you did not intend to touch, the change leaks into it (fix, don't `--update`). Intended deltas: `--update` and name them in the commit. Sizes in `runtime.txt` are the minified byte counts used in perf reviews.

## Release (`scripts/release/`, `.github/workflows/release.yml`)

- One version for every publishable lib (`publishableLibs()`; docs-kit has no `publishConfig`, never published). Workspace placeholder `0.0.0-experimental`; no `v*` tags yet (first changelog = whole history).
- `release.ts <bump>` steps: 1 version (current → next, dist-tag default `next` for prereleases else `latest`; `npm create rivet@latest` needs create-rivet on `latest`), 2 changelog (printed; `--apply` prepends `CHANGELOG.md`), 3 bump (`--apply`: published lib versions, every workspace internal dependency spec, and corresponding `package-lock.json` entries; private workspace versions stay unchanged; dry run: source untouched), 4 `nx run-many -t package`, 5 dist manifests → next version, 6 `smoke.ts --no-build`, 7 `create-e2e.ts`, 8 `npm publish <dist> --dry-run --tag <t> --access public` per lib in `ORDER` (fails first when a dist manifest has no `repository`: provenance), 9 prints the tag it would create. Writes `version=` / `tag=` to `$GITHUB_OUTPUT` when set.
- `--registry <url>` (local end to end): step 8 = real `npm publish` without provenance, only when `assertLocalRegistry` accepts the host (localhost / 127.0.0.1 / [::1]); excludes `--publish` and `--apply`. Enforced, before anything runs: `storage/npmrc` must exist (`verdaccio.ts start` writes it); inherited `npm_config_*` + proxy env (`HTTP(S)_PROXY`, `http(s)_proxy`, `ALL_PROXY`, `npm_config_(https_)proxy`) dropped, `NPM_CONFIG_USERCONFIG` / `GLOBALCONFIG` (storage) set for every child (incl. `npx nx`); every publish gets `localNpmArgs` (`--userconfig`, `--registry`, `--@rivetjs:registry`, `--noproxy=localhost,127.0.0.1,::1`); `assertNpmTargets` at start and again before step 8 refuses a repo-root `.npmrc`, an existing global npmrc (`npm config get globalconfig`), proxy env, registries not local, another user config, non-local credentials; dist `publishConfig` `*registry*` keys stripped; each package's `release.ts` `dryRunArgs` probe (`--dry-run --offline`, same flags: no request to any host) must print `Publishing to <local>`. Why: a scoped `@rivetjs:registry` (npmrc or `publishConfig`) beats `--registry` (npm 11.17), so `--registry` alone could publish `@rivetjs/*` to npmjs with the user's `~/.npmrc` token. Tests `scripts/tests/release.test.ts` (refusals; scoped npmrc / `publishConfig` overridden, no network). Run through `local-e2e.ts`.
- `--publish` (real `npm publish`, provenance enabled unless `NPM_CONFIG_PROVENANCE=false`) refuses to run outside GitHub Actions (`GITHUB_ACTIONS=true` + `NODE_AUTH_TOKEN`) and without `--apply`. Locally: never pass it; never `npm publish` / `npm login` / `git tag` / push.
- Partial release recovery: workflow input `resume-from` (lib directory, e.g. `create-rivet`) passes `--resume-from` to the CI-only publish path. Before uploading any remaining packages, every earlier package must be available at the release version with exactly the same `dist.integrity` as the newly packed tarball; missing versions, pending scans, and content mismatches stop recovery.
- `.github/workflows/release.yml`: `workflow_dispatch` only (inputs `bump` / `version` / `preid` / `dist-tag` / `dry-run` default true), `permissions: contents: write, id-token: write`, `NPM` secret → `NODE_AUTH_TOKEN`, `NPM_CONFIG_PROVENANCE`; provenance is disabled for private repositories (npm limitation); non-dry-run commits `CHANGELOG.md` + workspace manifests + `package-lock.json` (`chore(release): v<x>`), tags `v<x>`, pushes.
- Root `package.json` `repository` (github.com/N1XUS/rivetjs) feeds every dist manifest's `repository` (+ `directory`) and, when absent, `homepage` (`<repo>/tree/main/<dir>#readme`) + `bugs` (`<repo>/issues`) (`build.ts` `githubWeb`). Libs without a `README.md` get a generated one (`# name`, `description`, install line, source / docs / issues links); a lib without `description` is a build notice.

## Size report internals

- Scheduler coverage: `CDK_EXAMPLES` includes `scheduler-views-binding`, measured as a standalone production app with real view-switch interactions from its example manifest. UI component reports discover the public Scheduler subpath and its generated stylesheet automatically. `ui-components.mjs --only=scheduler --update` merges only that measured component row, preserving unmeasured components, page fixtures and bundle metadata; without `--update`, a selected run only prints. The shared partial-update helper is covered by three baseline-preservation regressions.

- Apps are staged into `.artifacts/size-report/apps/<name>`; docs examples are staged as standalone apps by `stage()` itself (starter + example files + resume modules for `src/components`; `apps/docs/examples/<id>/example.ts` supplies `test` steps + `mode`); the docs render examples inside the docs app.
- Columns: HTML brotli, resume state (`<script type="rivet/boundaries">` text), inline JS, eager requests/JS before first interaction (`data-fo` fetch-ahead included), runtime closure, page closure (runtime + boundary chunks the tail names), first-interaction requests/JS.
- Builds are deterministic → `--check` is exact; `--tolerance=<bytes>` only for known noise. `--apps=… --update` merges only measured apps into the baseline and preserves every unmeasured app and lane (`size-report/baseline.mjs`, regression in `tests/size-report.test.ts`); full `--update` still replaces the complete baseline.

## Gotchas

- Packaging: the app's Vite plugin must compile framework `.jsx` under `node_modules` and bundle `@rivetjs/*` for SSR (see `libs/compiler` `vite.ts`); a lib must not hold `x.ts` + `x.tsx` (both emit `x.d.ts`); runtime file paths must be inline `new URL("./x.ts", import.meta.url)` (rewritten), not built through helpers (left as `.ts`: build warning).
- Both gates need `apps/ssr-bench` and docs examples to build: run after `npm ci`; Playwright Chromium must be installed for size-report (`npx playwright install chromium`).
- `gen-events.mjs` throws `add a word for "<rest>"` when a new DOM event name needs a word in its `words` list.
- `check-tsx-projects.ts` uses `git ls-files`, so untracked `.tsx` files are not checked; tracked files deleted in the worktree are skipped.
