## Layout

- `ai-tester/`: autonomous tester: `node scripts/ai-tester/cli.ts run --area reactivity|router|resume [--no-commit] [--model <slug>]`, `doctor [--model <slug>]`, `status [id]`. One 30-minute/3072-MiB campaign; snapshot-local workspace packages/bins; native independent RED/GREEN, affected gates, read-only review and named-path atomic temporary-index commit. Doctor proves actual provider readiness within 60s; model overrides stay per invocation. Private CLI inspection disables inherited integrations; no-finding requires actual passing assertions and unchanged source blob bytes. Evidence `.artifacts/ai-tester/`; tests `tests/ai-tester*.test.ts`. See its README/CLAUDE and approved design.
- Regression selection counts executed assertions: unrelated skip/todo records retained by native Vitest `-t` are allowed with exact matching counts; selected skips and multiple executed cases fail. The first live Astra campaign exposed this integration gap before intake; its failed record remains intact.
- AI tester proof integrity: original source blobs and declared overlays are checked after RED and throughout candidate verification, including index-hidden writes outside the candidate. Proposed raw binary patches are retained before tests/gates with a private index and canonical Git diff output; invalid proof never becomes accepted because a patch exists.
- AI tester compiler headroom: child `GOMEMLIMIT` derives from at most60% of the tree budget remaining after measured supervisor RSS (64MiB steps, at most1792MiB under the default cap). Per-command `.resources.json` records the starting envelope; exhausted budgets stop before spawn. Standalone `scripts/tsc.ts` keeps its existing default. This does not raise the3072MiB RSS limit, disable diagnostics or add retries.
- Consumer gates: changing `libs/router/server/handler.ts` schedules `vitest:forms` even under touched-only test selection, because forms tests import the handler directly. Client-only router edits retain normal scope; combined handler/forms edits schedule forms once.

- `docs-cloudflare.ts`: production build wrapper for `apps/docs`, `apps/cdk-docs`, `apps/ui-docs`: supplies the three production origins, runs the docs build without the Chromium example checks (`--no-checks`, user 2026-10-29: keep the deploy simple and fast; CI gates examples; "What loaded" paragraphs stay empty) and with the memory budget report-only (`DOCS_KIT_MAX_RSS_MB=0` unless set: Linux runner peaked at 5 GB with checks); `DOCS_CHECKS=1` runs the checks, with bundled Chromium + libraries on Linux without root access (Playwright installation elsewhere); UI then stages a lossless page-vs-assets/search partition under `dist/cloudflare` and enforces 20,000 files per Free-tier Worker. `stageUIAssets(root)` is exported for `tests/docs-cloudflare.test.ts` (same URLs/bytes, source preserved, headers in both, stale output cleaned).

## Gates runner (`scripts/gates/`)

- Plan: changed files = `git diff --name-only <base>` (default `HEAD`; working tree incl. deletions) + untracked, minus `apps/ui-docs/src/generated/api.json` (rewritten by `docs-kit api`), or `--files a,b`. Owner project = longest nx project root; affected = owners + transitive dependents (nx graph from `nx graph --file`, or `--graph <json>`); a root `sharedGlobals` file (`package.json`, `package-lock.json`, `nx.json`, `tsconfig.base.json`, `.nvmrc`) or `vitest.config.ts` affects every project. `--all` = every gate, every project.
- Gates (ids for `--only` / `--skip`: exact id, bare group `typecheck` = `typecheck:*`, globs `vitest:cdk*`; `--only` adds each selected gate's `requires`, and an exact id outside the affected plan comes from the `--all` catalog): `api:ui-docs` → `typecheck:<p>` (affected, sequential) → `tsx-projects` (.tsx / tsconfig changed) → `gen-events` / `gen-row-wasm` (their sources) / `test-shards` (nx targets, shards, ci.yml) / `errors` / `content:<app>` + `snippets:<app>` + `llms:<app>` (affected docs apps) / `mcp-data` (`build-data.ts` then `--check`: the data file is gitignored, a stale local copy fails `--check`) / `ai-files` / `parity` (compiler touched) → `vitest:<v>` (every `--project` of the nx `test` target; `--tests touched` (default) = projects owning a changed file + the docs / ui-docs suites when their site is affected, `--tests affected` = every affected project; `--maxWorkers=2`, `NODE_OPTIONS=--max-old-space-size=2048`), `vitest:scripts` (`scripts/` changed; `--maxWorkers=1`: 3.7 GB tree with two) → `build:<p>` then its dist-reading suites (nx `test` `dependsOn: build`: docs, ssr-bench + `python:ssr-bench`, dom-bench, playground, devtools) → `build:docs` / `build:cdk-docs` / `build:ui-docs` (affected) → `frames` → `zero-cost` (after the ssr-bench suites: check.sh wipes `apps/ssr-bench/dist`) → `size` → `format` (`--base <base>`).
- `--update-baselines`: `frames.mjs --update`, `check.sh --update`, then `lanes.txt` Qwik lines (`qwik*`, `client/`, `client-stable/`) restored to the `--base` version unless Qwik lane sources changed (`apps/ssr-bench/adapters/qwik*`, `stable-build.ts`, `apps/bench-stable/**`, a `build.ts` diff line naming qwik); `size:update` (`--update`) then `size` (`--check` = run-to-run variance); `home-perf` (`apps/docs/scripts/home-perf.ts` after `build:docs`, docs rebuilt when `_home-perf.json` changed) before `vitest:docs`. Baseline line deltas are listed in the report.
- Classification: `pass` / `fail` (new red) / `known-red` (every failure line matches a `known-reds.json` entry for that gate: `{ gate, match, reason, owner, since }`; vitest line = `<file> > <test>`, docs builds `example <id>`) / `noise` (size growth only, every value ≤ `--size-tolerance` B (default 20); zero-cost diff of Qwik lane lines only without Qwik source change) / `rss` (sampled process-tree RSS sum > `--rss-limit` MB, default 3072) / `blocked` (a required gate failed). Exit 1 on fail / rss / blocked.
- Resources: one gate at a time, each under `nice -n 10` and `/usr/bin/time -l` (`-v` on Linux; largest single process = `peakProcessRssBytes`); tree RSS sampled from `ps` every second (`peakRssBytes`); heavy gates (typecheck, vitest, builds, parity, frames, zero-cost, size) take a slot of a mkdir semaphore shared by concurrent runs (`$RIVET_HEAVY_SLOTS_DIR`, default `<tmpdir>/rivet-heavy-slots`; `--slots n` / `$RIVET_HEAVY_SLOTS`, default 3, 0 = off; slots of dead pids are reclaimed); `--timeout` minutes per gate (default 120, kills the process group). Commands get this Node first on PATH, `NX_DAEMON=false NX_ISOLATE_PLUGINS=false`, nested-nx `NX_TASK_*` / `NX_SKIP_NX_CACHE` / `NX_WORKSPACE_ROOT` dropped.
- Output: a progress line per gate, final table (gate, status, duration, peak RSS, detail), known reds (reason + owner), noise, baseline deltas, new reds with failure lines + log path; logs + `report.json` in `.artifacts/gates/<timestamp>/` (`--logs <dir>`), `--json <file>` copy. CI does not call the runner (its jobs run the same commands, split per job).

## Zero-cost gate internals

1. `runtime-hashes.mjs` bundles each `exports` entry of `libs/reactivity` + `libs/runtime` with rolldown (minify, `process.env.NODE_ENV="production"`, conditions `import,production,default`) and prints hash + size → `$tmp/runtime.now` (plain, `[resumed]`, `[domData]` lines; see the table above).
   `packages-hashes.mjs` does the same for router/forms/i18n/kit/ui/motion/bridge/bridge-react/bridge-preact + `CDK_ENTRIES` (cdk masonry, masonry/behaviour, flip, scheduler and scheduler/layout) → `$tmp/packages.now`.
2. `rm -rf apps/ssr-bench/dist`, then `node apps/ssr-bench/build.ts` rebuilds the bench lanes; `lanes-hashes.mjs` hashes every emitted file → `$tmp/lanes.now`. The fresh dist matters: until ZERO Z0 (2026-10-25) a long-lived checkout kept the `rivet-derived/*` files of the lane deleted at M6-CUT, `--update` recorded them, and every fresh checkout (CI) then failed with 26 missing lines. Snapshot copies whose `node_modules` symlink outside the tree drift on Qwik (`q-manifest.json` `origins` become `../../…` paths → `manifestHash` in the bundles): copy `apps/ssr-bench/node_modules/@qwik.dev/core` and `apps/bench-stable/node_modules/@builder.io/qwik` into the snapshot.
3. `diff` against `runtime.txt` / `packages.txt` / `lanes.txt`; any difference = status 1 (`--update` moves the `.now` files over the baselines instead).
4. `dev-leaks.mjs`: no dev façade / devtools literal in any production entry (status 1 on a leak, also with `--update`). New devtools event → add it to `DEV_STRINGS`; new `development` façade module → `DEV_FILES`; new `#dev`-gated warning → its text in `DEV_MESSAGES`.
5. `condition-parity.mjs`: a name the `types` file promises but the production/dev/browser file lacks typechecks and breaks at bundle time — add no-op stubs (prod) or keep dev façades' extra helpers unexported (status 1).
6. `node libs/compiler/oracle/check.ts` runs the compiler parity corpus (`libs/compiler/oracle/corpus.jsonl`, recorded from the former TypeScript implementation): diagnostics must match exactly, emitted code after esbuild minification. Prints `N/N corpus cases match`.
7. Success output: `runtime + lanes: identical`, `dev leaks: none (N entries)`, `condition parity: ok (N entries)`, then the corpus line. A rolldown `codeSplitting … debugName` warning is expected noise.

Rules: an untouched feature costs 0 bytes — if an entry's hash changes for an entry you did not intend to touch, the change leaks into it (fix, don't `--update`). Intended deltas: `--update` and name them in the commit. Sizes in `runtime.txt` are the minified byte counts used in perf reviews.

The 2026-10-29 form ownership fix (`name="id"` must not disable enhanced submission) regenerates only the `@rivetjs/forms` line in `zero-cost/packages.txt` from `packages-hashes.mjs#hash`; its minified size stays 4979 B. All runtime, sibling-package and SSR-lane hashes stay unchanged.

## Release (`scripts/release/`, `.github/workflows/release.yml`)

- One version for every publishable lib (`publishableLibs()`; docs-kit has no `publishConfig`, never published). Workspace placeholder `0.0.0-experimental`; no `v*` tags yet (first changelog = whole history).
- `release.ts <bump>` steps: 1 version (current → next, dist-tag default `next` for prereleases else `latest`; `npm create rivet@latest` needs create-rivet on `latest`), 2 changelog (printed; `--apply` prepends `CHANGELOG.md`), 3 bump (`--apply`: published lib versions, every workspace internal dependency spec, and corresponding `package-lock.json` entries; private workspace versions stay unchanged; dry run: source untouched), 4 `nx run-many -t package`, 5 dist manifests → next version, 6 `smoke.ts --no-build`, 7 `create-e2e.ts`, 8 `npm publish <dist> --dry-run --tag <t> --access public` per lib in `ORDER` (fails first when a dist manifest has no `repository`: provenance), 9 prints the tag it would create. Writes `version=` / `tag=` to `$GITHUB_OUTPUT` when set.
- `--registry <url>` (local end to end): step 8 = real `npm publish` without provenance, only when `assertLocalRegistry` accepts the host (localhost / 127.0.0.1 / [::1]); excludes `--publish` and `--apply`. Enforced, before anything runs: `storage/npmrc` must exist (`verdaccio.ts start` writes it); inherited `npm_config_*` + proxy env (`HTTP(S)_PROXY`, `http(s)_proxy`, `ALL_PROXY`, `npm_config_(https_)proxy`) dropped, `NPM_CONFIG_USERCONFIG` / `GLOBALCONFIG` (storage) set for every child (incl. `npx nx`); every publish gets `localNpmArgs` (`--userconfig`, `--registry`, `--@rivetjs:registry`, `--noproxy=localhost,127.0.0.1,::1`); `assertNpmTargets` at start and again before step 8 refuses a repo-root `.npmrc`, an existing global npmrc (`npm config get globalconfig`), proxy env, registries not local, another user config, non-local credentials; dist `publishConfig` `*registry*` keys stripped; each package's `release.ts` `dryRunArgs` probe (`--dry-run --offline`, same flags: no request to any host) must print `Publishing to <local>`. Why: a scoped `@rivetjs:registry` (npmrc or `publishConfig`) beats `--registry` (npm 11.17), so `--registry` alone could publish `@rivetjs/*` to npmjs with the user's `~/.npmrc` token. Tests `scripts/tests/release.test.ts` (refusals; scoped npmrc / `publishConfig` overridden, no network). Run through `local-e2e.ts`.
- `--publish` (real `npm publish`, provenance enabled unless `NPM_CONFIG_PROVENANCE=false`) refuses to run outside GitHub Actions (`GITHUB_ACTIONS=true` + `NODE_AUTH_TOKEN`) and without `--apply`. Locally: never pass it; never `npm publish` / `npm login` / `git tag` / push.
- Partial release recovery: workflow input `resume-from` (lib directory, e.g. `create-rivet`) passes `--resume-from` to the CI-only publish path. Before uploading any remaining packages, every earlier package must be available at the release version with exactly the same `dist.integrity` as the newly packed tarball; missing versions, pending scans, and content mismatches stop recovery.
- `.github/workflows/release.yml`: `workflow_dispatch` only (inputs `bump` / `version` / `preid` / `dist-tag` / `dry-run` default true), `permissions: contents: write, id-token: write`, `NPM` secret → `NODE_AUTH_TOKEN`, `NPM_CONFIG_PROVENANCE`; provenance is disabled for private repositories (npm limitation); non-dry-run commits `CHANGELOG.md` + workspace manifests + `package-lock.json` (`chore(release): v<x>`), tags `v<x>`, pushes.
- Root `package.json` `repository` (github.com/N1XUS/rivetjs) feeds every dist manifest's `repository` (+ `directory`) and, when absent, `homepage` (`<repo>/tree/main/<dir>#readme`) + `bugs` (`<repo>/issues`) (`build.ts` `githubWeb`). ## Size report internals

- Scheduler coverage: `CDK_EXAMPLES` includes `scheduler-views-binding`, measured as a standalone production app with real view-switch interactions from its example manifest. UI component reports discover the public Scheduler subpath and its generated stylesheet automatically. `ui-components.mjs --only=scheduler --update` merges only that measured component row, preserving unmeasured components, page fixtures and bundle metadata; without `--update`, a selected run only prints. The shared partial-update helper is covered by three baseline-preservation regressions.

- Apps are staged into `.artifacts/size-report/apps/<name>`; docs examples are staged as standalone apps by `stage()` itself (starter + example files + resume modules for `src/components`; `apps/docs/examples/<id>/example.ts` supplies `test` steps + `mode`); the docs render examples inside the docs app.
- Columns: HTML brotli, resume state (`<script type="rivet/boundaries">` text), inline JS, eager requests/JS before first interaction (`data-fo` fetch-ahead included), runtime closure, page closure (runtime + boundary chunks the tail names), first-interaction requests/JS.
- Builds are deterministic → `--check` is exact; `--tolerance=<bytes>` only for known noise. `--apps=… --update` merges only measured apps into the baseline and preserves every unmeasured app and lane (`size-report/baseline.mjs`, regression in `tests/size-report.test.ts`); full `--update` still replaces the complete baseline.

## Gotchas

- Packaging: the app's Vite plugin must compile framework `.jsx` under `node_modules` and bundle `@rivetjs/*` for SSR (see `libs/compiler` `vite.ts`); a lib must not hold `x.ts` + `x.tsx` (both emit `x.d.ts`); runtime file paths must be inline `new URL("./x.ts", import.meta.url)` (rewritten), not built through helpers (left as `.ts`: build warning).
- Both gates need `apps/ssr-bench` and docs examples to build: run after `npm ci`; Playwright Chromium must be installed for size-report (`npx playwright install chromium`).
- `gen-events.mjs` throws `add a word for "<rest>"` when a new DOM event name needs a word in its `words` list.
- `check-tsx-projects.ts` uses `git ls-files`, so untracked `.tsx` files are not checked; tracked files deleted in the worktree are skipped.
