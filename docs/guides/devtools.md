# DevTools

Rivet DevTools (`@rivetjs/devtools`, experimental): components, signals, DOM updates, hot updates and errors of a page on the Vite dev server. Design: [spec](../design/specs/2026-10-03-devtools-design.md); P0 + P1 [plan](../design/plans/2026-10-03-devtools.md).

## Use

- `vite` (serve) with `rivet()` or `rivetRouter()` and `@rivetjs/devtools` installed: on by default.
- Open: `Alt+Shift+R`, or the round **R** button bottom right. Close: same key, or **×**.
- **Pop out**: the panel moves to its own window (same session; survives page reloads). A duplicated tab (or a page opened by `window.open` without `noopener`) copies the session: agents claim their session on `BroadcastChannel("rivet-devtools")` and the newcomer regenerates it before its pop-out channel opens (100 ms after load), so one pop-out never talks to two tabs.
- Resumed router dev pages ([dev resume](routing.md#file-routes-dev-resume-vite-serve)) have no component instances in the browser. Measure first, inspect second:
  - until switched, the page stays resumed: Performance (CLS, interactions, chunk loads per interaction, first-interaction latency), Updates, HMR, Errors measure the real resumed page;
  - showing a tab that needs live components (Components, Signals, Contexts, Router, Forms) switches the page to client render through the dev entry's hot-update fallback (`dev-mount.tsx` renders over the resumed container): agent dispatches `rivet:devtools-inspect`; the entry announces `rivet:dev-client-render` `{ phase: "start" | "done" }` (DevTools only since M6-CUT: a code edit reloads a resumed page; after the switch edits hot-replace with state kept);
  - one-line notice under the tabs: resumed (which tabs switch), switching, "switched to client render for inspection (performance up to N s was measured on the resumed page)", or client-rendered after a hot update;
  - Performance: shifts and long frames during the switch (+ 500 ms) are dropped; `resume.switchedAt` marks the boundary (summary: "client render from N s");
  - the panel keeps its last tab for the browser tab session: reopened on Performance after a reload, the page stays resumed;
  - `rivetRouter({ dev: { resume: false } })` still client-renders from page load.
- Opt out: `rivet({ devtools: false })` / `rivetRouter({ devtools: false })`.
- Builds never include DevTools (production and development). Development-build opt-in (`RIVET_DEVTOOLS=1`) comes with P2.
- Panel UI is prebuilt: `npx nx run devtools:build` (also run by `devtools:test`). Unbuilt → `/__rivet/devtools/` answers 503 with that command. Stale (built from older `protocol.ts` / `ui/` sources, or another protocol `VERSION` than the page agent) → a "rebuild the panel" banner; on a version mismatch the panel stops there (the agent also warns in the page console).

## Panels

- **Components**: mount roots → components (owner tree; `For`, `ChunkGroup`, `Provider` and lazy/client-only wrappers hidden). Rows collapse / expand; **Filter components** keeps name matches and their ancestors; past 500 visible rows only the rows in view render. Hover → outline + name in the page; **Pick** → click an element to select its component (Esc cancels). Side pane: file (opens in editor), owner chain (click-through), **Why it last updated**, signals, computeds (runs, time; overridable), effect/binding count, **Context provided**, **Contexts read**, props (overridable), **Depends on** (signals / computeds its effects, bindings and computeds read outside itself; signals open in the Signals tab), **State used by** (components reading its signals / computeds), DOM update count.
- **Why it last updated**: the writes of the flush that last re-ran one of the component's effects, bindings or computeds (several in a batch): signal (click → Signals tab), write site (source-mapped stack, recorded while the panel is open), **DevTools edit** badge for panel writes. First runs have no cause.
- **Signals**: every live signal (filter by name, component, value, file, `#id`); select → owner chain, creation site, write count, **Last write** (site, DevTools flag), **Depends on** / **Used by** (3 levels; signal rows click through).
- **Contexts**: every provider instance under the mount roots: context name, providing component, value, consumers; jump to the provider (its row is focused in the owner pane) or any consumer. Filter by name / component / value.
- Names: from the source binding (`const count = signal(0)` → `count`; object property, class field, assignment target; `signal`, `computed`, `createContext`), scoped by component: `Layout › count`. Contexts: binding name (`ThemeContext`), else the token's `id`, else `context #12`; repeats numbered in creation order (`ThemeContext#2`). Router contexts: `Navigation`, `SearchParams`, `RouteParams`, `ServerData`. Repeats within a component numbered in creation order (`count`, `count#2`); unnamed → `Layout › signal #12`. Same format in every panel. Dev server only (see How it works).
- Values: expandable tree wherever a value shows (signals, computeds, graph, context, props). Children load on expand, 100 per page (**N more…**); expansion kept across writes. Arrays, typed arrays, plain objects, `Map`, `Set`, errors; class instances show class name, own fields, then prototype getters (italic, listed, never invoked); `[circular]` for a value already on the path; Date / RegExp / function / symbol / bigint / DOM nodes as one-line previews; strings over 120 chars truncated (**show all N chars**, up to 64 KiB).
- Whole-value edit: **edit** → JSON → **Set** (or Enter), JSON-safe signals only. Through the signal's own `.set` (normal flush); non-JSON input rejected in the panel.
- In-tree edit (any signal value; no dialog): double-click a leaf → typed editor (type picker: string, number, boolean, bigint, Date, null, undefined, JSON) → Enter (Escape cancels). Booleans toggle on double-click. Containers: **+ key** (plain object / class instance), **+ entry** (Map: typed key + value), **+ member** (Set), **+ item** (array, appended); **×** on a row removes the key / entry / member / item (array: spliced). Leaves inside Map entries (addressed by key identity), Set members (replaced in place of order), Date, bigint, undefined, class instance fields, typed array elements.
- Write semantics:
  - copyable containers on the path (plain objects, arrays, Map, Set, typed arrays) are copied: a fresh value through the signal's `.set` (equality sees a change; frozen objects re-frozen);
  - a class instance on the path is mutated in place (copying could drop private state / identity); below a plain root the root is still copied (normal `.set`); an instance root is mutated, then re-notified (`pins.notify`: the signal is set to a sentinel and back in one batch → observers run once with the mutated value). Custom `equals` may still skip it (the panel says so). Computeds returning the same instance stop propagation (in-place semantics);
  - accessors are never invoked or written; frozen / non-writable / non-configurable properties refuse with a reason.
- Debug overrides (dev only, temporary): editing a **computed** pins it (consumers see the pinned value until **Reset**; source writes do not unpin); editing a **prop** pins what the component reads (value props until **Reset**; accessor props — signal / computed getters — until **Reset** or the prop's next real change). Overridden rows: **overridden** badge, real value, **Reset**. Handlers / plain functions and getters are not overridable. Overrides never write signals.
- Context edit: a provider whose value is a signal (or holds signals) edits that signal in place → consumers that read it update. Plain values: read-only, with the reason (a provided value is a snapshot each consumer reads once at setup; an edit could not reach them — provide a signal). Not made reactive in dev: that would change what `useContext` returns.
- **Router** (shown when `@rivetjs/router` runs): route pattern, URL, params, load time, loader data per layout (`/`, `/shop`, …, `page`), layout chain, pending navigation (destination, type, trigger, state, elapsed), last navigations (to, from, type, trigger, start→commit time).
- **i18n** (shown with the `i18n()` plugin): page locale (dev `?rivet-locale=` module query, else `<html lang>`), `dir`, default and configured locales, catalogs (file, key count), missing message keys this session (dev prefixed `t()` lookups, with counts), fallbacks (keys a locale lacks).
- **Forms** (shown when `createForm` / `createAutosave` ran): per live form: id, definition, component (click-through), values (the form's `FormData`; password fields and `password` / `secret` names masked), touched, dirty, shown issues (field and form), submitting / submitted / validating / enhanced, submit count, autosave (status, confirmed version, unsaved field count, error, conflict). Autosave states without a form store listed on their own. Polled while the tab shows.
- **Performance**: page totals (CLS = largest session window vs 0.1 / 0.25; slowest interaction vs 200 / 500 ms; chunks loaded after inputs, first-interaction latency, resumed page flag), toggles, timeline (one lane per finding kind; click → finding), sortable per-component table (runs, self time, total run time, DOM updates, CLS, reflows, time in long frames, max re-runs per interaction, flags), interactions, findings (component links, source location + app stack, why / how to fix + docs link). Component tree rows get a **⚠** badge with the reasons (click → Performance, filtered by that component).
  - Layout shifts: `layout-shift` observer (buffered from navigation start); input-driven shifts skipped; score split over the components of the moved nodes by moved area; **Show layout shifts** flashes shifted rects (purple).
  - Forced reflows (**Detect forced reflows**, off by default, kept for the tab session so a reload covers page start): prototype patch of layout reads (`offset*`, `client*`, `scroll*`, `getBoundingClientRect`, `getClientRects`, `getComputedStyle`, `innerText`, …) and DOM writes (node insert / remove, attributes, `textContent` / `innerHTML`, `classList`, style setters, …). A read while layout is dirty (a write earlier in the task) inside a framework run (effect, binding, computed: `hook.current`) or an event handler (dispatch of a page event, until the task ends) → finding: component (the running node's, else the read element's / event target's), the read, app stack. Repeats at one site counted (×n).
  - Long frames: `long-animation-frame` (else `longtask`) ≥ 50 ms; component runs inside the frame (time, runs), top scripts (invoker → function, file).
  - Runs per component: `node.run` time and count (effects, bindings, computeds it owns). Self time = run time minus runs nested in it (a computed pulled by an effect: its run ends before the effect's, while `hook.current` is the effect again) — default sort, used for hot, long-frame and interaction sums; Total = inclusive (nested runs counted in each). Hot = self ≥ 50 ms and ≥ ¼ of all self time, or long-frame time ≥ 50 ms, or frequent re-runs.
  - Frequent re-runs: one effect / computed run ≥ 10× within 1 s after an input (or until the next) → finding naming it and its component.
  - Interactions: event timing (`interactionId`, longest event per interaction): input delay, processing, presentation; components whose runs fell in processing; target component; slow ≥ 200 ms → finding with the dominant phase.
  - Chunks: script resource loads ≤ 3 s after an input (until the next input), sizes (transfer, else encoded) and time; resumed page = `script[type="rivet/boundaries"]` present.
  - **Highlight updates by frequency**: update flashes colored by updates of that node in the last second (blue 1, green 2–3, amber 4–7, red 8+).
- **Updates**: **Highlight updates** flashes DOM nodes as bindings re-run; per-component DOM update counts (since the panel opened; **Reset counts**).
- **HMR**: Vite updates, per-component hot replacement (instances, state kept or reset: `shape` = signal count changed, `kind`, `refresh-reset`), invalidations, full reloads, Vite errors. Kept across reloads (session).
- **Errors**: uncaught errors and rejections, Vite errors, framework dev hints attached to their error, dev a11y warnings (`a11y` hook events, kind `a11y`: rule badge, element `<tag id class>`, component link when client-rendered; hover highlights the element in the page via `error.highlight`); frames; app location → opens in editor (Vite's `/__open-in-editor`).
- Dropped events: more than 500 events in one frame are not sent (`dropped` count); the tab bar shows a **N dropped** badge and the panel refetches the tree.
- Signal and computed locations: creation stacks, captured while the panel is connected and from page start after a reload with the panel open (source-mapped, app frames only).

## How it works

- Agent (`@rivetjs/devtools/agent`): first module script of every dev page (`transformIndexHtml`; router dev pages list it before `@vite/client`). Installs `globalThis[Symbol.for("rivet.devtools")]`, keeps the component model, draws the overlay in a shadow root, answers panel requests. Its failures are listed as `agent` errors, never thrown into the page.
- Instrumentation: `development` export condition selects façades (`@rivetjs/reactivity` → `dev.ts`, `@rivetjs/runtime/dom` → `dev/dom.ts`) on the dev server and under `node --conditions=development`. Without a hook they are inert. Level 1 (always, browser): structure (mounts, signal creation). Level 2 (panel connected and open): writes, runs, DOM updates.
- DOM (every module, resumed / i18n included, lowers the one DOM ABI): the façade wraps it — `_c` / `_cp` give each component its own owner in development only (production has none, spec Q5) and report `comp.mount { owner, fn, props, spanOf }`; `spanOf()` = the output's first / last connected node; the agent reads both span ends inclusively (picker `componentAt`, highlight `rectOf`). Writers (`_t`, `_tx`, `_insert`, `_attrWrite`, `_cls`, `_attrSet`, accessor `_attrValue` / `_setAttr` / `_className` / `_textValue`, `_rcdata` parts) report `dom.update` re-runs (`_insert` / `_t` / `_tx` with the parent element as node); `_show` / `_switch` / `_match` / `_for` are hidden like `Show` / `For`.
- Read-only internals: `@rivetjs/reactivity/debug` `_debug(x)` → frozen views (value, state, owner tree, sources/observers). Importing it with a hook already installed keeps inert DOM bindings in the graph (`_observeBindings`); without a hook (DevTools off) bindings are released as in production.
- Contexts: the reactivity façade reports `ctx.create { token }` and `ctx.read { token, owner, provider }` (provider owner found by the same parent walk as `useContext`; null → default value). Level 1 (always while the agent runs).
- Overrides (agent hooks set `hook.edit` before app code): the reactivity façade gives each computed an internal pin signal it reads itself (one extra source per computed, hidden in every panel; consumers unchanged); the DOM façade hands components a props proxy that answers pinned keys and reads the component's internal pin signal (bindings reading props subscribe to it). Registered on `hook.pins` (`computed`, `computedPin`, `notify`, `prop`, `props`). Without `edit` (tests' recording hooks) the façades stay transparent.
- Write causes: `sig.write` carries a write stack while recording (`hook.stacks`); a run (`node.run`; `dom.update` → the running binding, `hook.current`) is attributed to the task's pending writes to signals it reads, directly or through computeds (upstream `_debug` walk, ≤ 2,000 nodes; past that all pending writes are kept). Unrelated writes of the same task are not listed. `hook.stacks` stays on once a panel connected (not reset on close: open question).
- Performance: agent-side (`agent/perf.ts` bookkeeping, `agent/reflow.ts` patch); the only façade addition is `hook.current` (the running computed / effect, set by the reactivity façade while recording).
- Framework hooks (development export conditions; production resolution never reaches them): `@rivetjs/router/client` → `client/dev.ts` (wraps `routeData` / `_layouts`, `onNavigate`, names the contexts; `lib.register { lib: "router", describe }`, `lib.changed`), `@rivetjs/forms` → `dev.ts` (`createForm` → `lib.form { store, owner, describe }`), `@rivetjs/forms/autosave` → `autosave-dev.ts` (`lib.autosave`), `i18n()` → `GET <base>__rivet/i18n.json` on `vite serve` (locales, catalogs, fallbacks); missing keys from the dev `rivet i18n: missing message …` warnings (agent wraps `console.warn`, forwards everything).
- Plain app modules (`.ts` / `.js`, not compiled by `rivet()`): the same naming transform on `vite serve` client requests (TypeScript parsed before type stripping; same-line edits).
- Stores (debug hook only, no panel yet): `@rivetjs/reactivity/store` development façade emits `store.create { store, owner, tree }` (level 1); `tree()` / `_debugStore(store)` → read-path tree `{ path, value, signal, observers, children }`. Panel integration: DevTools rework branch.
- Panel: prebuilt Rivet app in its own realm (iframe at `<base>__rivet/devtools/`, or a pop-out window). Transport: `MessageChannel` (docked), `BroadcastChannel("rivet-devtools:<session>")` (pop-out); batches per animation frame, ≤ 500 events. Requests resolve by id; an `error.request` response (handler threw, or unknown request type) rejects; no response in 20 s (`REQUEST_TIMEOUT`) rejects. The hook retains no events (forwarded synchronously to the agent).
- Previews never call user code beyond plain property reads (getters reported, not invoked); proxies may run their traps (errors contained). Built-ins are recognised by internal-slot brand checks (intrinsic getters such as `Map.prototype.size`), not `instanceof`, so values from another realm (an app in an iframe) preview and edit as Map / Set / Date / plain object; JSON edits refuse sparse arrays (holes would turn into `null`).
- Source locations: inline source maps fetched from the dev server only (same origin; third-party / CDN frames keep their served position), cached per module across HMR `?t=` stamps (refetched on a newer stamp), at most 50 (LRU).
- Names: `rivet()` passes each compiled client module through `nameSignals` (`@rivetjs/devtools/server`) on `vite serve` when DevTools is on: `signal(…)` / `computed(…)` imported from `@rivetjs/*` and assigned to a binding become `__rivetName(signal(…), "count")`; an appended helper reports the name to the hook. Same-line edits, source map columns shifted. Builds and `compile()` output unchanged.
- Zero production cost: production bundles of `@rivetjs/reactivity`, `@rivetjs/runtime` entries and the SSR lanes are byte-identical with and without DevTools (hash gates); `if (DEV)` hot-path branches fold away. Router, forms and i18n runtime entries: unchanged (dev hooks are separate files behind `development` conditions; the i18n endpoint lives in the Vite plugin).

## Limits (P1)

- `vite serve` only; development builds, resumed production pages, an Async panel, Server-Timing: later phases.
- Tree is the owner tree: a page passed as `children` shows next to its layout, not inside it.
- Names need the dev transform (`vite serve` client modules, `.tsx` and app `.ts` / `.js`): signals in dependencies (`node_modules`, framework packages) show `#id`. Only direct bindings are named (not `useCounter()` results).
- Plain provided values are read-only (see Context edit). Value props destructured at setup (`({ label }) => …`) keep their real value under an override (the override reaches reads of `props.x`).
- Owner chain = owner tree: a page under a layout shows `App › Router › Page`.
- Router pane: route pattern (`/items/:id`), not the file route id; resumed pages: after the first client load.
- i18n locale is the page's module locale / `<html lang>`; missing keys only for dynamic (prefixed) `t()` lookups (static keys fail at compile time).
- Performance: runs, DOM updates, re-runs and effect reflows need recording (panel open); observers and handler reflows work from page start. Slowest interaction is the max, not the p98 INP. Long frames show script attribution only with `long-animation-frame` (Chromium). Layout-shift scores go to the moved nodes' components, not the cause (often a sibling inserted above). Reflow detection misses code that cached DOM prototype methods before the patch and reads outside framework runs / page event dispatch (timers, observers).
- Forms pane polls (700 ms) while shown; values come from the DOM (`FormData`), so a form not in the document shows none.
- No `bindModel` highlight; `For` row / `Async` state / event timing in P3.
