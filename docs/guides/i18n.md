# Internationalization

Compile-time i18n (`@rivetjs/i18n`): ICU catalogs inlined per locale. No catalog, ICU parser or message runtime in the browser for static messages; no resume state for messages. Design: [spec](../design/specs/2026-10-03-i18n-design.md).

## Setup

- `vite.config.ts`: `i18n()` before `rivetRouter()` / `rivet()`.
  ```ts
  import { i18n } from "@rivetjs/i18n/vite";
  import { rivetRouter } from "@rivetjs/router/vite";
  export default defineConfig({
    plugins: [
      i18n({ locales: ["en", "de"], defaultLocale: "en", catalogs: "locales/{locale}.json", routing: { prefix: "as-needed" } }),
      rivetRouter(),
    ],
  });
  ```
- Config: `locales` (order = compiler variant index), `defaultLocale`, `catalogs` (path with `{locale}` or loader fn), `fallback` (per-locale chain, ends at default), `missing` (`error` default, `warn`, `fallback`; dev defaults to `warn`), `timeZone`, `routing.prefix` (`always` / `as-needed` / `never` / locale → path map), `cookie` (`{ name?, maxAge? }`: name default `rivet_locale`, `maxAge` seconds, none = session cookie; `false` = off), `baseUrl`, `dts` (default `src/rivet-i18n.d.ts`).
- Plugin writes `dts`: `Messages` keys + param types, `Locales`. `t("unknown")` / wrong params are type errors and compile errors.
- Catalog edit in dev: table re-registered, `dts` rewritten, full reload.
- Dev server: pages render their locale's variant (`<html lang>`); a non-default locale's page loads `entry.dev.tsx?rivet-locale=<l>`. App modules (under the Vite root) imported from it keep the query and compile for that locale; framework/node_modules modules are shared. Builds unchanged.

## Messages

- Catalog JSON: nested objects flatten to dotted keys (`cart.title`). Values: ICU MessageFormat.
- `t("cart.title")`: static text. Server: one fragment set per locale in the template; zero per-request cost. DOM: inlined into the `_tpl` HTML (DOM v2; params / formatters inserted, effects only when a param reads state).
- Params: `t("greet", { name: user.name })`. Object literal only. Each param evaluated once, in source order; locales may reorder (slot write orders per variant).
- Plural/select/number/date: `{n, plural, one {# item} other {# items}}`, `{g, select, …}`, `{x, number, ::currency/EUR}`, `{d, date, short}`. Only these parts import `@rivetjs/i18n/runtime` (`Intl` instances cached per locale + options). `other` required; plural `offset` rejected.
- Rich text: `<link>terms</link>` needs param `link: (c) => <a href="/terms">{c}</a>` (static native JSX around `{c}`). `b i em strong code br small` need no param. Tags inside plural/select cases: each such case is its own template (server fragments, DOM spec); tagless cases stay strings.
  - Value positions (variable, prop, return value, `cond && t(…)`, resumed binding): a message with tags (top level or in cases) is its own template per variant (server `compiledTemplate` + hoisted fragments, DOM: own `_tpl` — several nodes returned as a node array, resumed modules too); JSX content like an element. Props are live (getters): a rich prop reading signals (`message={t(…)}`) re-evaluates where the receiving component reads it in a binding; a body read / destructure is read once.
  - Attributes / `t.in`: strings → diagnostic `RV4004` ("Message tags (<x> in "k") are not supported in an attribute / t.in()"); use a tagless message there.
  - JSX children: unchanged (static markup inlined into the parent template).
- Prefixed keys: `` t(`nav.${id}`) ``: per-locale object of keys under the prefix, hoisted once; no params; unknown key → `""` (dev: `console.warn`).
- `t.in(locale, "key", params)`: runtime pick between locales (emails, server code outside JSX).
- Types (generated `dts`): `Messages` key → params; tag params `(children: Content) => Content` (`Content` from `@rivetjs/runtime/jsx-runtime`, imported by the dts only when a message has tags), `b i em strong code br small` optional. `t()` returns `string` for tagless messages, `Content` for messages with tags (top level or in cases); `t.in` always `string`. Prefixed keys: an overload accepts a template pattern (`` `nav.${string}` ``) under any key's first segment (literal keys still checked exactly), returns `string`, takes no params.
- Server `t()` outside JSX is a per-locale value: rendering resolves it (children, attributes incl. `Picture alt` / `title`, route `head`, kit `<Title>` / `<Meta>`: router `translateHead`); `String()` throws (use `t.in`).
- Resume: static messages create no sites. A message reading signals is an ordinary text binding; its symbol is compiled per locale.

## Build

- One client build per locale: `RIVET_LOCALE=<locale> vite build` → `dist/client/<locale>/`, base `/<locale>/`. Without `RIVET_LOCALE` a client build fails.
- App base (`base: "/shop/"` / `rivetRouter({ base })`): assets under `/shop/<locale>/`; route patterns and router `BASE` stay `/shop` (router strips the locale suffix in locale client builds; its `shared/base.ts` gets the app base inlined, other apps' bundles unchanged).
- Static: `[[lang]]` page/layout exports `paths = entries(() => [{ lang: "uk" }, …])` (non-default locales; `/` is the default under `as-needed`); `prerenderBuild({ locales })`. Docs example `i18n-plurals`.
  - With more params, a set belongs to the form whose optional params it names (`adapters/static.ts` `optionalParams`): `{ slug }` → `/blog/:slug`, `{ lang: "uk", slug }` → `/:lang/blog/:slug`. Param-less forms build once (`[{}]`).
  - Images (`?image`): written once to `dist/client/assets/` (parent of the locale outDir), URLs without the locale (`libs/compiler/images/plugin.ts`).
- `locale()`: server = `ServerData.locale` (rendered locale; none settled → first locale; throws outside a render); client build = `i18n()` virtual module `\0rivet-i18n-client:<locale>` (`export const locale = () => "<l>"`, `t` re-exported); dev client = importer's `?rivet-locale`, else the default locale.
- One server build: `vite build --ssr` (all locales).
- Serve: `start({ dist, locales: ["en", "de"], resolveLocale: errorLocale(config) })` (node) / `loadBuild(dist, config, { locales, resolveLocale })` / `prerenderBuild({ locales })`. Pages get their locale's resume manifest; `/<locale>/assets/` immutable.
- `AppConfig.i18n = { locales, manifests, resolve? }`: variant + manifest from `locals.locale`; document gets `locale`, `dir`.
- Error pages (`_404`, `_error`): request `locals` (locale the guard settled); else `resolve(request)` (`errorLocale(config)`: URL prefix, cookie, Accept-Language); else a first path segment naming a locale; else first locale.

## Routing

- Routes under `src/routes/[[lang]]/`; guard in the page/layout file (e.g. `[[lang]]/_layout.tsx`): `export const access = guard(i18nGuard(config))`.
- Guard: `lang` param must name a locale (else 404); otherwise resolve.
  - Unprefixed URL (root or deep link) → 302 to the resolved locale's prefixed URL (path + query kept), when that locale has a prefix.
  - `as-needed`: default locale preferred/chosen (cookie naming it) → served unprefixed; same-site navigation (`Sec-Fetch-Site: same-origin`, a followed unprefixed link, e.g. switcher to the default locale) → never bounced. `Vary: cookie, accept-language, sec-fetch-site`.
  - `always` / prefix map: every unprefixed URL redirects. `Vary: cookie, accept-language`.
  - Prefixed URLs never redirect (no loops).
  - Sets `locals.locale`, `locals.dir`, `Content-Language`.
  - Locale cookie (explicit choice): same-site document navigation (`Sec-Fetch-Site: same-origin` + `Sec-Fetch-Mode: navigate`, no `Sec-Purpose` prefetch) to a URL naming a locale (prefix; under `as-needed` unprefixed = default) other than the one cookie/headers pick → `Set-Cookie: rivet_locale=<locale>; Path=/; [Max-Age]; [Secure on https]; SameSite=Lax` (not HttpOnly). Covers a switcher's plain links, both directions. That response: `Cache-Control: private` (router rule for any `event.cookies` write: `public`/`s-maxage` dropped, other directives kept); other responses keep their caching, no `Vary` on prefixed URLs.
  - No cookie: Accept-Language detection alone, redirects, cookie already naming it, typed URL / external link, client-router data requests, `cookie: false`, `strategy` without `cookie`.
  - Cookies blocked: same-site no-bounce rule still serves the default locale for that navigation; later direct visits detect again.
- Document shell: `<html lang="${input.locale}" dir="${input.dir}">`.
- `localizeHref(href, locale, config, base = BASE)`, `delocalizeHref(href, config, base = BASE)` (locale prefix after the app base; paths outside it as without one; `url` strategy also strips it), `alternates(url, config)` (hreflang per locale + `x-default` + canonical; needs `baseUrl`) for `head` links, `dirOf(locale)`.
- Switcher: plain links (`localizeHref`) with `data-rivet-reload` under a client router (locale switch = document load), or `setLocale(locale, config)` (browser: writes `document.cookie` with the server's attributes, `location.assign(localizeHref(current, locale))`). `localeCookie(locale, config, secure)` (`./resolve`): the cookie string.

## Resolution

- `@rivetjs/i18n/resolve`: `resolveServer(request, config, order?)`, `resolveClient(config, order?)` (CSR only; SSR/resume pages take `<html lang>`).
- Default order `url`, `cookie` (`rivet_locale`), `preferredLanguage` (q-sorted Accept-Language / `navigator.languages`; exact, base language, region), `baseLocale`. Custom strategies: `{ name, server?, client? }`. Results outside `locales` ignored.

## Limits

- No runtime catalogs; no in-place locale switch (switch = navigation).
- Modules importing `t`: server list-mount plans and direct regions off.
- Node without full ICU formats numbers/dates in English (plugin warns).

## Cost

- Untranslated apps: compiler output byte-identical (oracle 227/227; corpus test with unused `staticCalls`); SSR bench lanes unchanged.
- Runtime (rolldown, minified): `@rivetjs/runtime/server` 17585 → 18536 B (+951), `@rivetjs/runtime/server-resume` 35723 → 36251 B at i18n merge (+528); variant fragment sets, per-variant values.
- Untranslated renders: every variant check sits behind a module flag set only by `_variants` / `_variantValue` (translated modules). Bundles without translated modules constant-fold the checks away (server-resume entry alone: 36318 → 35905 B).
- Microbenchmark (ssr-bench `rivet-compiled`, 100 rows, with vs without the variant checks, before the flag): list-plan path −1.4 % / +2.8 % (two runs), per-row template path +4.0 %; run-to-run noise ±3 %. Flag added since the per-row path (resume apps: no list plans) hits the checks per row.
- SSR i18n lane vs Razor `IStringLocalizer` and per-locale resume bytes: not yet measured.
