# Resumability

Status: [resumability design](../design/specs/2026-10-03-resumability-design.md) SP1 (Core) implemented ([structural resume](../design/specs/2026-10-18-structural-resume-design.md) proposes replacing this serialized model; rulings pending, nothing below changes until its gates pass) ([plan](../design/plans/2026-10-03-resumability-core.md)); SP2/SP3 partial: structural regions, `For`, `clientOnly`, router, preload scheduler. Playground `/` and `/items/:id` resume; the former `/csr` demo redirects (308) to them.

## Use

- Router apps (`rivetRouter`): every app `.tsx` module a route imports resumes automatically (`resume.appModules`, default true); `resume.modules` is only needed for modules not statically reachable. Plain `rivet({ resume })` needs every app module listed (or `appModules: true`).
- Vite: `rivet({ resume: { modules: ["src/page.tsx"], entry: "src/resume-entry.ts", preload: { rules: [{ match, strategy }] } } })`.
  - client build: one symbol chunk per component + runtime entry chunk + `.vite/rivet-resume.json` (`{ hash, runtime, symbols: { id: url }, sizes: { url: bytes }, preload?: { id: strategy } }`).
  - SSR build: listed modules compile with recorder slots.
- Entry (optional): `export default createResume({ contexts: [[Token, value]] })` from `@rivetjs/runtime/dom-resume`.
- Server: `renderResumable(() => <Page/>, writer, { manifest, signal, nonce })` or `resumableToString(...)` from `@rivetjs/runtime/server-resume`.
- Playground (production build only): file routes in [src/routes](../../apps/playground/src/routes) on `@rivetjs/router` — `/`, `/items/:id`, `/resume` ([resume-demo.tsx](../../apps/playground/src/resume-demo.tsx)); the client build has no application entry (stylesheet input only).
- gtag-style page views ([page-views.tsx](../../apps/playground/src/page-views.tsx)): `clientEffect(async () => { const path = url().pathname; (await loadAnalytics()).pageView(path); }, { when: "idle" })` (`url`: the root layout's URL accessor); analytics chunk loaded at idle, absent from `data-preload`; reruns per client navigation.

- Component elements under a native element:

## Resumable functions (R2)

- A function value is resumable when the server created it through `_rFn` (symbol id + captures); captured anywhere (props, objects, signals) it serializes as `{f}`.
  - Late captures (Function Bridge T5, 2026-10-11): the captures argument may be a thunk (`_rFn(id, f, () => [a, b])`, hoisted registrations whose captures are still in their TDZ): called once, at the recipe's first encode (end of the render / segment), then interned, so a `let` reassigned after registration resumes with its value at that point; render-time sites (spread `onX` handlers, `_rChild` / spread `children` sites) keep the thunk in their record until then, so a hoisted function's captures may still be in their TDZ while the JSX renders; a throw fails the render as `Cannot resume <id>: captures …` (cause kept) — in a streamed segment (Async / Suspense content, incl. records a Suspense moved out of the shell) only that segment, like its other render errors. No recorder: never called.
  - `let` cells (Function Bridge T7, 2026-10-11, runtime; compiler C6 / T8 boxes the `let`): `_rCell(value)` → `{ v }`, reads / writes `x.v`; encoded once, at its first encode (`{k:"cell", a:[value]}`, interned: every symbol capturing it shares one browser cell, not reactive). Q2: a server write after that (an `Async` continuation, a later segment) does not reach the page — the browser keeps the encoded value; development warns once (the first server write after the cell was encoded). A function stored in a cell — directly, in an object, or behind other functions — may capture the cell: a cycle through a cell decodes from any end (the decoder fills a cell reached inside a decoding function / computed / custom entry once the outermost one is done; a cell whose value fails to decode — a chunk that does not load, an element that never streams — becomes an accessor: reading it retries the decode and throws that error until it succeeds, a write replaces it; only the cell's readers see the failure, never a silent `undefined`, and nothing else on the page is affected). Any failed decode is rolled back whole: no function, cell or signal decoded alongside it keeps the discarded half-built object (`const actions = { a: () => actions.b(), b }` with `b`'s chunk failing once — the retry rebuilds `actions` and `a` together).
  - Bound functions and function groups (Function Bridge T9 + fix 1 runtime, T10 compiler, 2026-10-12): `f.bind(t, ...args)` of a resumable function resumes as a bound function (`_rBound` → `{k:"bind"}`, the browser calls `bind` again; a function with its own `bind` is left to it). Mutually recursive local functions resume as one group per instance (`_rGroup(id, [even, odd], captures)` → one recipe entry, members `{i: [group, k]}`): the browser runs the group's factory once per instance and every member keeps its identity (`holder.even === even`); two instances never share members; a failed decode rolls the group back with its frame. Limit: a bound `this` / argument that reaches the bound function back (`o.h = f.bind(o)`) is a capture cycle and throws "Cyclic reference" unless a `let` cell breaks it. Compiler (T10, `rust/src/resume/groups.rs`): a strongly connected set (≥ 2) of local function declarations / `const` arrow or function-expression bindings in ONE statement list → one group symbol `(<union of the members' captures>) => { <members in source order> return [<members>]; }` (no member symbols, no per-member registration; captures = union of the members' T11-narrowed captures, a whole use in one member widens that base); the server registers it once per instance, `_rGroup(id, [even, odd], () => [caps])`, at the top of the list when every member is a declaration (T6 hoisting), else after the last `const` member's statement (keyed per group: several groups in one list, or ending in one multi-declarator statement, all register); an early exit (`return` / `throw` / `break` / `continue` leaving the list) between the first `const` member and that point is RV2011; a cycle through a `let` function or a holder is not grouped; a `const g = f.bind(t, ...args)` used by name anywhere a resumable value flows (captured, JSX prop, call argument, object / array store; bound-of-bound chains included; casts / parentheses on the callee unwrapped; a later spread argument kept) whose innermost callee is a local function (made an Fn site) or a module function / import (a `_rMod` reference) → server `const g = _rBound(f, t, [args])` (a value capture; never a recipe; DOM output unchanged). Inline `.bind` in a prop / handler resumes through the props / `_rOn` recipe; inside an object literal a resumable closure reaches (whole object captured or that key read) it is RV2014; a spread first argument RV2012; a callee that is not a local / module function or import (parameter, prop, call result) RV2013. T10 fix 2: RV2013 / RV2014 and RV2012 on a non-provable receiver are compile warnings (`compile` `warnings`, Vite `[rivet:compiler]` warning, editor warning; the code is still emitted: an object with its own `bind` is legal, the render-time "not serializable" error stays the ground truth); RV2012 / RV2013 are errors only when the callee is provably a function (local declaration / `const` function literal, module function, import); a `this`-dependent target stays RV2007 even with `.bind(ctx)`.
  - Boxed `let`s (Function Bridge C6 / T8 + fix round 1, 2026-10-11, compiler `rust/src/resume/cells.rs`): a statement-list `let x` (identifier binding; not a `for` head) that a site captures is a cell when it has any write anywhere — the declaring function, a nested function / method / arrow, a class field initializer — whatever its position relative to the capture (source order is not execution order: a hoisted function declaration or a class field can run before or after the write). Server: `const x = _rCell(init)`, every reference `x.v` (called `(0, x.v)(…)`, shorthand `{ x: x.v }`, destructuring `({ x: x.v } = o)`); symbols capturing it rewrite the same references (capture kind `cell`); the DOM main module keeps `let`. An Event / client-event / ref / model site whose expression is not a function literal (`onClick={h}`, `onClick={m ? a : b}`) captures the value at JSX evaluation (`[h.v]`, kind `value`), as the DOM build binds it: a later `h = …` does not rebind the listener. Exception (fix round 2): when a reference sits inside a function nested in that expression (`onClick={p.on ? () => { x++ } : undefined}`), the site keeps the shared cell (that function runs later); an eager reference next to it reads a JSX-time snapshot (`h$s`, T11 follow-up), so `onClick={(h || (() => h()))}`-style mixes bind the listener the DOM build would. Captured by value as before: `var`, destructured `let`s, `for` heads (also when the loop body writes the head binding after the capturing closure: the handler sees the value at capture, not the body's later write — per-iteration cells are a follow-up), a `let` in a function that calls a direct `eval`, one used as a JSX tag / inside `<slot>`, or captured by a spread / styled / props / element site. Fixes `let-after-jsx`, `let-shared-cell`, `holder-let-later`, `let-hoisted-after-write`, `let-class-field-write` (G-CORPUS).
  - Narrow member captures (Function Bridge C7 / T11 + fix round 1, 2026-10-12, compiler `rust/src/resume.rs` `narrow_decl`): a handler / binding / attribute / Fn / effect / client-event / computed site that only reads static members of a captured `const` object literal captures each first-level member it reads, not the object: `const store = { count: n, blob }` + `onClick={() => store.count.set(store.count() + 1)}` → server `[_rMember(store, "count")]`, symbol `(store$count) => { const store = { count: store$count }; … }` — `blob` never reaches the state. Handlers, client events, Fn symbols and effects narrow the props members they call the same way (`props.onPress()` → `props$onPress`, rebuilt with `_members`, live forward boxes kept; limit: a `function` prop called as `props.onPress()` sees the rebuilt props object as `this`, not the original); bindings / attributes / computeds keep the whole props (one shared recipe ref), and any non-called props read (`props.item`, `props.item.id`, `props.label`) keeps the whole props (its recipe, not the member's value; path narrowing is T12). Whole object when the module uses it otherwise anywhere: passed / returned / spread / written / `in` / `delete` / iterated, a computed key, a key the literal does not declare (inherited `hasOwnProperty`, a `__proto__` literal), a `let`, or a call through a key whose value is not provably `this`-free — only arrows, non-function literals, reactivity primitives (`signal`, `computed`) and `const` bindings of those are; a method, function expression, imported or borrowed function keeps `store.inc()` whole. Corpus `narrow-object` passes.
  - Narrowed stores (Function Bridge T12 runtime + fix 1, C11 / T13 compiler, 2026-10-12; `docs/guides/stores.md` "Resume"): a captured `const store = createStore(…)` whose every reference is `read` / `write` / `at` with a literal path is marked on the server, `const store = _rStorePaths(createStore(…), ["count", "user.name"])` (views `at(store, "p")` are followed: their literal reads add `p.q`, a whole / dynamic read adds `p`); the state then holds only the containers along (server-read ∪ literal) paths — `{k:"store", a:[root signal, nodes]}`, unread data never ships (corpus `narrow-store`, `store-paths-union`, `store-paths-browser-read`, `store-paths-view`). Whole store (as before) on any other use of the store or of a view of it — a dynamic root path (`store-paths-dynamic`), `read(store)`, passed / aliased / a JSX prop, `view.s` (`store-paths-view-escape`) — after a whole server read, and while streamed segments are pending. Dev: a browser read of an unshipped path warns once (`Rivet resume: store path "…" was not shipped`).
- Resume-compiled modules (application modules, source packages such as `@rivetjs/cdk`), inside a function, outside handlers, effects, computeds and attribute-binding expressions:
  - local functions: `function f() {}`, `const f = () => …` / `function () {}`, consts derived through functions (route tables) — when a site captures them, or when passed as a component prop / object literal value / `return` value (`onAction={onAction}`, `return { inc }`, `return inc`);
  - function expressions and method shorthands as object literal values (`{ onKeyDown: (e) => … }`, `{ onPress(e) {…} }` → `onPress: _rFn(id, function (e) {…}, captures)`, also in `{...{ … }}` spreads), `return` values (`return () => …`) — a component's returned parameterless accessor is a child site on the server (`_rChild(_rFn(…))`): its reads re-run it after resume, also inside For rows (RESUME-ACCESSOR-ROW + fixes 1–2, 2026-10-12; before, such a component never updated on a resumed page). Component = PascalCase module-level function; on the resumed server render a PascalCase function's returned parameterless accessor is rendered as a child where the call sits (`_rChild`), so a PascalCase factory returning a value accessor (`Sel()()`, selector / hook-like) gets the rendered value there, not the function — name such factories in camelCase. Covered: `return () => …`, `return c ? () => a : () => b` (also `&&` / `||` / `??`), `const view = () => …; return view`, a hoisted `function view() {…}` returned by name (parameterless, not async / generator), concise `(props) => () => …`. RV2015 warning (still frozen after resume): an anonymous default export, a function passed to a wrapper call (`const Card = memo((p) => () => …)`), a returned `let view = () => …` (declare it `const`). Not covered, no warning: class / method components, a returned parameter, an accessor built by a helper call — return an inline arrow from a named component, component props (`onChange={(v) => …}`), also in `c ? f : g`, `c && f`, `a ?? f`, `a || f` branches of props;
  - JSX-returning functions as component props / children (also in conditional branches) and conditional `r:slot` children: `slot` symbols;
  - functions stored into a captured holder (Function Bridge C4 / T4, 2026-10-11, `rust/src/resume/escape.rs`): holder = a local `const` / `let` some site captures (fixpoint: holders reached through other holders' functions too, and (T4b) through data: a local stored into a holder is searched as a holder too); stored = right side of an assignment to it or a member chain rooted at it (`api.inc = () => …`, `h = () => …`, `h.fns = [f]`), arguments of store calls on it (`push unshift splice fill set add`: `list.push(f)`, `map.set(k, f)`), object-literal values in its initializer, and in its initializer every call / `new` argument and array element, recursively (`signal(() => …)`, `track([() => …])`, `new Map([["k", () => …]])`); a `let` holder's own function initializer too → `_rFn(id, f, caps)` in place; (T4b) a local function stored by name (`api.open = open`, `list.push(open)`; `const open = () => …` or `function open() {}`) becomes a recipe at its declaration: `const open = _rFn(id, () => …, caps)` / `function open() {}` registered by `_rFn(id, open, () => caps);` at the top of its statement list (Function Bridge T6: hoisting kept, thunk captures read at the first encode — a declaration after `return` / `throw` resumes; every captured local function declaration registers this way), one id for every holder it lands in; consumed callbacks stay plain (nothing below them searched): member calls `map filter forEach reduce reduceRight some every find findIndex findLast findLastIndex flatMap sort toSorted replace replaceAll from then catch finally addEventListener removeEventListener setTimeout setInterval requestAnimationFrame requestIdleCallback queueMicrotask`, the same scheduling globals, `@rivetjs/reactivity` `untrack batch runWithOwner _regionState effect createRoot onCleanup`; assignment right sides do not search call arguments (`h.timer = setTimeout(f)` stores the handle); a function whose capture is still in its TDZ where it is created (the holder in its own initializer, a `let` / `const` declared later, any lexical capture from inside a hoisted function declaration nested in its scope, a binding of another `switch` case) stays plain (eager capture list; thunk captures T6).
- Components: every user component, non-`@rivetjs` package components, and components of `@rivetjs/*` source packages (compiler option `sourcePackages`; `rivet()` and the editor pass the `rivet.source` packages a module imports, linked ones included, e.g. `@rivetjs/cdk`); other `@rivetjs/*` components (`runtime`, `router`, `kit`, …) keep plain function props.
- Module references (Function Bridge T3, 2026-10-09; `libs/compiler/CLAUDE.md` "Module references"):
  - a module function / `const` function / import (named, default, `ns.member`, any package) used as a value inside a component (object / array element, argument, prop, `return`, …) → stamped once per module load: server epilogue `__rivetR_mod((() => x), "<unit>#<name>$<h5>$ref"[, 1])` (thunk: an import cycle may still hold `x` in its TDZ; runtime `_rMod` resolves it on the first encode, retries while uninitialised) → `{f: id}` wherever a render reaches the value (objects, arrays, Maps, signal values), browser symbol `() => (x)`;
  - ids canonical: unit = the resolved module id + its query (`vite.ts` `resolvedImports`; else the specifier / relative path) → one id per value in every importer; own values: name = their exported name (= the importers' id), not exported → salted `<local>$l` (never an export's id); `h5` keeps export names unique (RV2009 on a genuine clash; RV2008 for a used local `b` next to `export { a as b }`);
  - stamped: functions, classes, static data (plain objects / arrays of primitives, functions, nested plain data; lucide icon data); by value: primitives, signals / computeds, objects holding signals (module stores — the server values transfer);
  - not stamped: `use*Context*` arguments / `*Context` tokens, `@rivetjs/*` framework packages, callee-only uses (`inc(n)`), uses inside handlers;
  - chunks: own references in the chunk of the component using them, or their own chunk when used by components in ≥ 2 chunks / imported by another module; import references one chunk each, importing only that value;
  - known limits: two installed versions of one package share an id (dedupe the package); a module resolving to different files on server and browser (`browser` export condition) shares one id for two implementations; the client build fails when one import reference resolves to two real files (RV2010: `npm dedupe` / `pnpm dedupe` / Vite `resolve.dedupe`), and development warns (`resume module reference <id> is stamped with two different values, by <a> and <b>`) when a module that never stamped the current value stamps a different one (two importers sharing a value, or one re-evaluated after an edit, stay silent); a value exported under several names has one id (the smallest name).
- Not covered (render error `function is not serializable` when captured):
  - functions from non-resume modules reached only through other values (no use the compiler sees in a resume module), `.bind(…)` not held by a captured local `const` (inline in a prop / object / spread / JSX attribute, or of a function the analysis cannot make resumable: a parameter, a library result), `new Function`;
  - mutually recursive functions in different statement lists (`function a() { function b() { a(); } … }`): no group, the capture cycle still fails ("Cyclic reference");
  - module-level functions / imports used as values only outside components — module scope (`const table = { inc }`), hooks (`function useApi() { return { inc }; }`), helpers (gap, Function Bridge T20);
  - accessors (`{ get m() {} }`), class methods, function expressions / method shorthands using `this`;
  - local functions in arguments / array elements / assignments of values no site captures, consumed callbacks (`items.map((x) => …)`, `setTimeout(f)`), class fields (except arrow fields of a registered data class, T24);
  - functions created inside handlers / effects (browser-only: never serialized).
- Consts derived through functions (`_rFn` values, Q5 / Function Bridge T18, 2026-10-12): by value whenever the value encodes — signals (`const s = createSelectState({ onChange: (k) => … })`: handlers and bindings share its state), References (`[() => …]` of stamped functions, module refs), plain data (route tables, mapped data) — so the browser never re-runs the initializer (side effects once; corpus `recipe-side-effect`). Re-created from the recipe symbol only when the value does not encode (an unstamped function, a class instance, rendered content); a recipe id that failed once goes straight to its recipe for the rest of the process (`recipeOnly`, like `unportable`). Exceptions: `_rGroup` member arrays (members encode as `{i: [members, k]}`), getter objects (`hasAccessor`) and live props recipes keep their recipe. Snapshot: a by-value const is the value at its first encode (the shell flush, or the segment that first references it); later mutations do not reach later streamed segments, and the late captures of functions inside it (T5 thunks) are read at that flush too (`bridge-late.test.ts`: a streamed region capturing such a const finds the handler's late capture in the shell table). Sticky memo (accepted, T18 review): `recipeOnly` is process-wide and data-dependent — one failed `plain` attempt switches that symbol id to its recipe for the rest of the process (bounded by the symbol count; structural for `_rGroup`). Client registration: the browser decodes data instead of re-running the initializer, so a library factory that registered something in the browser by running there loses that registration — put browser-side work in `clientEffect` (or keep the value a function). Functions inside get opportunistic symbols either way. Measured (G-BYTES, ui showcases, br): dashboard 6261 → 6163, mail 7733 → 7601, chat 7625 → 7281, settings 6791 → 6216.
- Data class instances (Function Bridge T23 + fix 1 runtime, T24 compiler, 2026-10-12): every module-scope data class of a resume module registers (`_rClass(Cls, "<module>#<Class>$class")`, server epilogue; class-field arrows `_rFn("<module>#<Class>$<h>", arrow, [this])`, symbol `(__rivetSelf) => …`); a captured `new Cls()` of a class with a `#private` element, a base other than a module-local data class, or a resource read while constructing (`window` / `document` / `WebSocket` …) is RV2102 naming the field (`static [revive]` classes register as resource holders, T25: `[serialize]()` data `{cls, a: [data], rv: 1}`, rebuilt by `Cls[revive](data)` on first decode; package classes `registerClass(cls, { id, serialize?, revive })`, `cls` = the registered id; `[serialize]` without a reviver = `RV2102: <Class> has [serialize] but no static [revive]` at render); a registered class encodes its instances as `{cls, a: [own fields]}`; the browser (decoder in the on-demand `resume-builtins` chunk) restores the prototype (`Object.create`), defines the fields, never runs the constructor; decoded two-phase like `let` cells, so `this`-capturing class-field arrows cycle safely. Refused: true `#private` fields (D-priv, no private brand), built-in bases (Map, Date, Error, EventTarget, …), unregistered subclasses of a registered class, own `__proto__` fields; dev also refuses symbol / non-enumerable / accessor / read-only fields and frozen instances (production drops / flattens them). Mechanics: `libs/runtime/CLAUDE.md` "Data class instances".
- Diagnostics: R2 sites are opportunistic — no compile-time capture errors (`this`, class instances); a bad capture fails only when the function is actually serialized.
- Cost: only where the patterns occur; per created function one `_rFn` call (AsyncLocalStorage lookup + WeakMap set under a recorder; identity otherwise) and one `fn` symbol (DOM chunk export).

## Mechanics

- Compiler ([resume.rs](../../libs/compiler/rust/src/resume.rs)): sites → symbols `<module>#<Component>$<hash>` (Function Bridge C2, 2026-10-09: the shortest prefix, ≥ 3 base-36 digits, of an FNV-1a 64 digest over the symbol's kind, component, body text, parameters + capture kinds and imports that no other symbol of the component shares; identical twins in one component `$<hash>_<k>`, k in source order; same in both targets, deterministic across builds). An id changes only when that closure's code or captures change — adding a site elsewhere renumbers nothing. Captures = identifiers declared in an enclosing function outside the closure; module-scope names are imports of the symbol module.
- Server ([server-resume.ts](../../libs/runtime/server-resume.ts)): AsyncLocalStorage recorder (works across async rendering). `_trackReads` collects leaf signals (through computeds). Without a recorder every `_r*` call degrades to plain output.
- Format ([resume-format.ts](../../libs/runtime/resume-format.ts)): one interned table; sharing/cycles kept; JSON-exact primitives inline in objects/arrays (`{l}` all-literal arrays; `{p}` objects of literals, or with numbers / booleans / null inline and other values (strings: interned) as one-element `[ref]` arrays, key order kept; `{o}` only refs); a plain JSON tree (loader data: plain objects / arrays of JSON-exact literals, no holes, no digit-leading keys, no object reached twice or held by another entry) is ONE `{j: tree}` entry serialized natively, an object inside it that another entry references is `{i: [parent, key]}` (resolved when its `j` root decodes; `j` only in a render's last streamed segment, since a later patch could reference into an earlier tree after the client mutated it; getters on plain objects are read twice); Date/Map/Set/bigint/special numbers; built-ins (Function Bridge C1, 2026-10-09): URL `{h}`, RegExp `{t: [source, flags, lastIndex?]}`, URLSearchParams `{U}`, ArrayBuffer / DataView / typed arrays `{b: [kind, base64]}` (the view's bytes; buffer sharing not kept), errors `Error` … `AggregateError` `{E: [kind, message, data?]}` (own enumerable keys + `cause` / `errors`, no stack) — only the global constructors' own prototypes (subclasses refused); the compiler's captured `const x = new X(…)` check allows exactly these (`resume.rs` `SERIALIZABLE_BUILTINS`); `t` / `U` / `b` / `E` decode in `@rivetjs/runtime/resume-builtins`, a chunk loaded only by pages (`needs`), router data and form answers (`x`) that hold one (C1C2-SLIM); class instances, functions, symbols, Promise, WeakMap, SharedArrayBuffer refused with type name.
- Markers: end markers carry no id (`<!--/-->`, `<!--]-->`); the client pairs them by nesting.
- Adoption cost: adopted rows carry no item/index signals; rows dropped on the adoption run remove only their content (one `removeChild` per `<li>`) — their two row markers stay in the DOM as inert comments (`dom-adopt.ts` `left`, RESUME-DROP-MARKERS 2026-10-18: a comment removal costs about a third of an element's, and the markers were two thirds of the first keystroke's removals; 1,000 → 100 rows at 4× CPU: `removeChild` 45.7 → 29.7 ms, the same as Solid 1's 900 `remove()`s; kept rows keep their markers as anchors, rows dropped later take theirs along); runtime start pairs markers at idle (char-code scan, no regex), so the first activation skips the document walk; measured: first filter dispatch on the 1,000-row bench (4× CPU, dev build) 27.8 → 16.1 ms (2026-10-09).
- Loader ([resume-loader.ts](../../libs/runtime/resume-loader.ts)): shipped pre-minified ([resume-loader.min.ts](../../libs/runtime/resume-loader.min.ts), regenerate with `node libs/runtime/build-loader.ts`; test fails when stale); reads `data-events` only until first event; intent (60 ms pointer dwell, `focusin`, `touchstart`) → `modulepreload` (low priority); `pointerdown`/`keydown` → evaluate; loaded → handler runs synchronously (preventDefault works; delegated listeners are passive only for `touch*` / `wheel` / `scroll`, so mousedown / input / dragstart handlers can cancel). Cold keydown on an element inside `[data-rk="ArrowDown Space …"]`: the listed keys (`Space` = `" "`) are `preventDefault`ed while the chunk loads (no page scroll), then the handler runs; unlisted keys keep their default (composite widgets: `@rivetjs/cdk/keys` `navigationKeys(options)` builds the list). Pay-per-use: two loader builds from one source (`RIVET_KEYS` define) — `LOADER_KEYS` (+61 B brotli) only on pages whose recorder saw a `keydown` handler, else `LOADER` (1,796 B); keydown handlers only in later streamed segments get no hold. Cold `a[href]` click / `submit`: cancel, run, replay unless the handler prevented. Chunk failure: one retry under a cache-busted URL (`?r=<ms>`: browsers keep a failed module URL failed; a transiently failed shared chunk may then evaluate twice), then `rivet:resume-error`, reload unless prevented; at most one reload per page URL within 10 s (sessionStorage `rivet:reload:<href>`; storage unavailable → only when the page was not itself a reload), so a broken / CSP-blocked chunk cannot loop. Deploy skew: a page whose symbol is missing from the loaded chunk (a newer build without that closure — ids are content hashes, so a present id is the same code) never runs another function: `dom-resume` `symbol()` calls the loader's guarded `fail` with an error carrying `skew: <id>` (cancelable `rivet:resume-error`, then the reload), and the dispatch stops; old pages reaching still-deployed content-hashed chunks keep working. Tests: corpus `skew-renumbered` (inserted handler: old id still found) / `skew-changed` (handler code changed: reload path, no handler runs).
- Runtime ([dom-resume.ts](../../libs/runtime/dom-resume.ts)): lazy decode per reference; signals revived on first use; bindings activate on first change of a dep (sync when chunk loaded). Region tree: dead regions skip activation; each region owns what resumed inside it.

- Equality: `signal(v, { equals })` / `computed(fn, { equals })` — default `Object.is`; `false` always notifies; a comparator returns `true` for equal. Computeds cut off: consumers re-run only when the value changes.
  - resume: inline / local / module comparators in literal options compile to symbols; state entry carries `q` (symbol ref) or `q: false`; comparator chunk joins the chunks of anything capturing the signal; armed after the decoder's initial write;
  - opaque comparator (options object built at runtime) → server render error `equals comparator is not resumable`.
- State parse (bench page, 46 KB state, 4× CPU): `JSON.parse` 0.8 ms + template expansion 1.7 ms, at first intent or idle boot — not split per region.

## Preload

- Server plan ([server-resume.ts](../../libs/runtime/server-resume.ts) `planPreload`), per page:
  - dependency prefetch: handler/model entries list extra chunks = chunks of bindings reading signals reachable from their captures → intent prefetches them, pointerdown/keydown evaluates them → DOM update applies synchronously across chunks;
  - strategy per chunk, strongest use wins (`eager` > `idle` > `visible` > `intent` > `interaction`):
    - click/submit/input/change/key, pointerdown/mousedown/touchstart, focus/focusin/focusout/blur, invalid handlers → `intent` (the loader's own pointerover-dwell / focusin / touchstart prefetch announces them);
    - one handler symbol on ≥3 rows of one `For` list (in a region or not; `.map` rows and independent component instances count alone) or other events (scroll, wheel, pointerenter, …) → `visible` (observed elements = its `data-r` ids), but only for chunks ≤ 8,192 B (`VISIBLE_MAX`, minified own size from manifest `sizes`; static imports not counted) — larger stay `intent`;
    - `clientEvent` → `preload` option, else `idle` (window/document) / `visible` (element); `passive: false` → `eager`;
    - precedence: element `preload="…"` directive (literal; not on `<audio>`/`<video>`) > component level (module `export const preload = "…"`, or `<ChunkGroup preload>`) > app rules (vite `preload.rules`) > automatic; component level + rules land in manifest `preload` per symbol;
  - order: impact (click/submit 3, input/change 2, other 1, summed per element; +2 for handlers on `<a href>` / `<form action>`) desc, chunk size asc.
  - background budget (PRELOAD-VISIBLE 2026-10-11): a `visible` chunk whose new static closure (own size + manifest `deps` not already brought by the runtime / `e` / `i` chunks / earlier background ones; manifest `sizes`, minified, incl. shared chunks) fits the remaining `preload.background` bytes → `P` (visible + background at idle), else `v` (viewport only). Option: `renderResumable` / `createApp` / adapters `preload: { background }` (bytes; default 1 MiB `BACKGROUND_DEFAULT`; `0` off; router accepts `(url) => number | undefined`); unknown size (dev manifests) → `v`. docs-kit example frames pass `0` (`framePreload`: each frame plans its own document, so per-frame budgets add up: /components/select 241 → 1,078 KB with no budget). Matrix: `docs/benchmarks/2026-10-11-preload-background.md`; `preload: { lean }` (HOMEPAGE 2026-10-12; router: boolean or `(url) => boolean | undefined`) = empty schedule (no `e` / `i` / `v` / `P`, as the loader's Save-Data mode) + no fetch-ahead modulepreloads of a lazy router (`n` kept for navigation): nothing loads before an interaction, handlers on intent / the event (replayed); docs-kit `site.leanPages` (apps/docs home: 73 scripts / 186 KB gzip → 0 before input); framework-island pages (bridge D-lean, 2026-10-12; spec `docs/design/specs/2026-10-11-framework-bridges-design.md` §3.12): when a page's only Rivet resumables besides the islands are regions + `intent` client events (a file router), the islands boot lean (no runtime) and the rest ships as a deferred, non-booting state + loader (runtime on the first link intent / click, cold click held + replayed); `preload: { ahead }` (router default: document prefetch on) keeps its fetch-ahead — low-priority modulepreloads after `load`, never evaluated;
  - output: `data-preload='[runtimeUrl, [url, "e"|"i"|"v"|"P", ids?], …]'` on the state script (omitted when all `intent`); `interaction` chunks → `state.x` (intent skips them).
- Loader:
  - `e` after first paint, `i` at idle, `P` at idle too (background, plan order); `v` / `P` moved to the queue front by an IntersectionObserver (1 viewport margin) once an observed element shows a non-zero area (`intersectionRatio`, not `isIntersecting`: a clipped visually-hidden control — RA hidden select / date input in a `position: fixed; top: 0` wrapper — intersects with zero area wherever its widget is; before, every DatePicker / Select prefetched at load, PRELOAD-VISIBLE 2026-10-09). Background (`P`) because a below-the-fold widget's closure (Select ≈ 80 modules / 97 KB br) loaded only after scrolling takes seconds on a slow link: /themes below-fold Select first open, 4× CPU + Fast 3G, 0.6 s with background vs 4.4 s (h2) / 10.9 s (h1) viewport-only; runtime queued first;
  - ≤2 scheduled prefetches in flight (`fetchpriority=low`); intent bypasses the queue;
  - deps modules (STRUCT-PREFETCH 2026-10-11): the build writes `<chunk>.deps.js` (`export default [urls]` = manifest `deps`, the static import closure) next to every symbol chunk and the runtime (empty for one that imports nothing; manifest `depsModules`), flagged on the state script as `data-deps`. When the loader hints a chunk for an interaction (intent / pointerdown / keydown, urgent) or boots the runtime, it also imports that chunk's deps module and hints the whole closure (urgent), one round trip after the chunk's own request instead of the `import()` waterfall (modulepreload fetches one module). Only until the runtime has started — the cold window, an interaction before idle boot / scheduled preloads finished (after that the planner's preloads brought the shared closure; ungated, warm DatePicker h2 measured +18% with ~20 deps requests competing; a cap of two per page lost the cold win, +7%) and never over HTTP/1.1 (`nextHopProtocol`; six connections: cold DatePicker / Select +11–13%, chat +81%). Imports are never warmed alone (module evaluation order stays the importer's); scheduled (low-priority) hints and pages before intent request nothing extra. A site-wide graph module fetched at idle was tried first: 64 KB br on ui-docs (4,978 chunks), fetched by every example frame in parallel (/components/button 133 → 942 KB before first input) — rejected. Numbers: `docs/benchmarks/2026-10-11-preload-background.md`;
  - nothing starts, and no idle boot runs, within 150 ms of a scroll;
  - lazy imports reachable from a chunk (manifest `lazy`) prefetched on intent and on pointerdown/keydown; only `import()`s made by app modules (inside the Vite root, outside node_modules) are listed — a library's own `import()` (cdk carousel Autoplay / AutoScroll, the live announcer) loads on use (RT-PRELOAD 2026-10-08);
  - `saveData` / 2G: scheduled prefetches off, intent only;
  - every prefetched module is evaluated in a later idle slice (scroll-guarded), so the interaction finds it ready and runs synchronously; measured: first filter on the 1,000-row bench 43 → 8 ms;
  - scheduled chunks bring their lazy imports (manifest `lazy`) at idle, never earlier (eager/visible chunk → its `import()` targets at idle; spec: analytics never prefetched before idle); `resume.lazy: "intent"` (manifest `lazyIdle: false`, set by `@rivetjs/router`) keeps them intent-only;
  - sibling boost: manifest `groups` (chunks of one `ChunkGroup` / route) → state `g`; loading one chunk for an interaction schedules its siblings (`later`), unless Save-Data / 2G;
  - runtime boot warms declared `lazyComponent`s at idle (`_warmLazy`; `{ warm: false }` opts out — router pages load on intent or render); a loaded lazy component renders synchronously (`lazyFunction(...).peek()`), so client navigation needs no fallback frame.
- App guidance (chunk weight before first input, PRELOAD-VISIBLE 2026-10-09):
  - a symbol imports its module's module-scope names from the source module, so evaluating any symbol of a component evaluates that whole module and its static imports. Keep module-scope data (demo tables, option lists, icon sets) in `.ts` leaf modules, imported by what renders them;
  - a load-time effect (`clientEffect` with no `when`, `"load"` or `"idle"`) loads at boot every chunk it and its captures need. Inside a big component's module it pulls that component's render graph. Put it in a small leaf module whose imports are only what the effect uses, and pass it signals rather than computeds / props recipes built in the parent's render (a captured computed brings its component's chunk). Example: docs-kit `code-watch.tsx` (SiteFrame's idle code watcher: ~88 KB brotli → 0.5 KB on every docs page);
  - check with the browser network panel before the first input, or with docs-kit `check-examples` (`measure …: before N scripts / KB`).

## Streaming (`Async` pending state)

- Spec: [async streaming design](../design/specs/2026-10-03-async-streaming-design.md).
- Opt-in: `renderResumable(factory, writer, { manifest, stream: { deadline? } })`; `deadline` (ms from render start) has no default. `resumableToString` always awaits.
- Streams: an `Async` with `fallback` whose `load` returns a pending promise (`lazyComponent(…, …, { fallback })` too). It claims its enclosing region-site scope (the `<Async>` / component child site); row scopes, nested-in-the-same-scope or unscoped boundaries are awaited as before.
- Shell: `<!--rA[-->fallback<!--]-->`; state `a: [[marker, fallbackRegion, region, 0]…]`, `data-stream`, then the stream add-on script (708 B brotli; only on such pages).
- Segments, in completion order, each after its parent: `<template data-a>` + `<script type="rivet/state" data-patch>` + `<script>$rA(A)</script>`. `$rA` binds the patch and template by position before its own script (never a document query). Patch = incremental encoding on the shell's table (`t0` + new entries, chunks, symbols, entries, new event types, preload schedule, boot flag).
- Continuation (status 2): load failure without `error`, past `deadline`, or a cut stream (pending at `DOMContentLoaded`) → the browser re-creates the region; its DOM `Async` loads there. Request abort stops writing.
- Lifetime: a streamed boundary (`Async` / `Suspense` root) leaves its parent owner when it streams (reactivity `_detach`) — the render holding it (the shell, a segment) disposes its scopes when it ends: an awaited `Async`, a `Provider`, the `Async` content of an outer Suspense's segment. The stream disposes it once, after its segment and every nested one are out, or when its segment is dropped (its content discarded by an error boundary, the request aborted, the stream's end). A throwing `Suspense` fallback disposes it at once; a page that throws (no error boundary) ends the stream, which disposes every streamed boundary. A streaming `ErrorBoundary` that can write a fallback segment keeps a detached child of its owner until the stream ends; the fallback renders under it (it reads the boundary's context: locale, route data, head level). Before (2026-10-11 fix) such a boundary was disposed with its parent and always continued in the browser (`AbortError`). Tests `libs/runtime/tests/suspense-stream-nested.test.ts`.
- Inside an `ErrorBoundary`: a failed segment writes the boundary's fallback as a segment for the boundary region instead (status 1 for its content scope and every unwritten inner segment; link entries use status 3). Link entries `[site, content, site, 3]` are also written without streaming (CORE-GAPS (b), 2026-10-08) for every boundary whose content rendered (one id + one `a` entry per such boundary; failed content: none): the browser (`dom-resume` `catches` / `caught`) routes a failure of a resumed binding / effect under the content — first activation (`go`) or a later re-run (the content region's owner is created inside `catchError`) — to the boundary: it re-creates the site region (the DOM ErrorBoundary renders the content again, catches, shows the fallback; `reset` works as usual). Limit: streaming renders link only a boundary directly in its site (one inside a Show branch of the site reports to the console, as before). See [error boundaries](../design/compiled-runtime-milestone.md#error-boundaries).
- Browser: swap unless the region was re-created (segment dropped); merge into parsed state (queued before parse); started runtime registers the patch; bindings reading already-revived signals activate at once (server values may be stale).
- Row-template consts are refs ≤ -10 into `state.k` (no longer appended to `t`), so patches stay index-aligned.
- Limits: dependency prefetch of shell handlers does not include bindings streamed later (they activate after their chunk loads).

## Chunks

- vite `resume.chunks`:
  - `"component"`: one chunk per component;
  - `"group"`: one chunk per `<ChunkGroup>` subtree (`ChunkGroup` from `@rivetjs/runtime`, renders children only; renamed from `Island` 2026-10-12); components rendered in several groups, or none, keep their own chunk;
  - `"route"` (default since 2026-10-18): one chunk per lazy-import target's static module graph (`lazyComponent` / route imports), plus `main` (reached by no lazy root); modules several routes reach are placed by the bundler (one part module per file, imported by every route chunk reaching it, registered by module id — `_rSym`) into shared chunks merged under `resume.merge` / `cap`; `merge: false` leaves the bundler's split. Siblings per route prefetch together; manifest `fetchAhead`.
- Grouping ([facts.rs](../../libs/compiler/rust/src/facts.rs) + `groupComponents` in [index.ts](../../libs/compiler/index.ts)): static module facts (imports, `import()` edges, rendered component tags, chunk groups) + Vite resolution; changes chunks + manifest only, never server output.
- Runtime `symbol()` resolves an id in order: the registry a route-mode part filled at evaluation (`_rSym(moduleId, table)` from `@rivetjs/runtime/resume-symbols`; placed shared parts have no stable export names), then a multi-module chunk's `__rivet(id)` (chunk-group chunks: symbol names may repeat across modules), then the chunk's export by name.
- vite `resume.merge` (default 65536 source bytes since 2026-10-18, 2048 before; `false` = off): shared (non-entry) modules merge into fewer chunks when the extra bytes per request saved stay under the budget — amortised over entries per merge step, not a per-entry cap (ui-docs preload bytes p90 +7 %, max +27 %, full state max +64 %); entries (symbol chunks, runtime, app entry, dynamic-import targets) never change; the always-loaded entries take no page code, also through barrels; no merge closes a chunk import cycle; owner sets come from the static graph, so modules the bundler tree-shakes away still count as owned (the main source of the tails) (`libs/compiler/chunk-groups.ts`).
- Relative `import()` inside symbol bodies resolves against the source module.

## Security (injected markup)

- The loader reads its own state script (the element right before it) and the stream add-on its own patch / template (right before each `$rA` call): an HTML injection earlier in the body cannot name the runtime URL the nonce'd loader imports (`'strict-dynamic'` CSP stays meaningful).
- `data-r` ids are digits; anything else is skipped. Server output never repeats an id, but injected markup can copy one: sanitize user HTML to strip `data-r` / `data-rk` (DOMPurify keeps `data-*` by default). Dev warns on duplicates.
- Event types in `data-events` are letters, digits, `_ : . -` (a spread key that is not → render error). Trusted Types: the runtime's `rivet` policy is private (writes only into inert `<template>`s), shared across runtime copies through `Symbol.for("rivet.html")`.

## Limits (later sub-projects)

- Nested `For` directly as a row root, or two `For`s in one region: rows not adopted (re-created).
- Branch slots follow creation order, so a region read that reads a signal outside its Shows (`xs().map((x) => <Item/>)`, `flag() ? [<A/>, <B/>] : [<B/>]`, `For each={xs()}`) adopts none of its branches (rebuilt, values right): such a read could create different Shows on the browser. Pass lists to `For` as accessors (`each={xs}`) to keep both rows and branches. A component-root `Show` is created in a nested binding when it comes from a function child (`{() => <Show/>}`): never adopted.
- A `Show` / `Switch` at a component's root has no region of its own: the component is the content of its parent's region, so the first change of a signal it read on the server (a local `toasts` signal set by a `clientEvent` handler, say) re-creates the whole component — its locals start fresh (`signal([])`), so the re-created `Show` sees nothing and adopts the empty server branch. Two ways out: wrap the root in an empty `display: contents` anchor (`<span data-rv-toast-anchor="" style={{ display: "contents" }}><Show …/></span>`, cdk `ToastRegion`, `PreviewTrigger`) so the `Show` is a child element with its own region and only it re-creates; or create the state with `_regionState(() => signal([]))` so the re-created component continues from the server value. A compiler-side root region was tried and reverted (RESUME-BUGS 2026-10-09, 8c9caaf3): components rely on their body re-running on resume — client-only setup next to the root Show (cdk SharedElement's `client` flag + enter / exit effects, ScrollArea scrollbars' `_regionState` activation, TabPanel render-function panels) stopped working, and a root Show capturing an unserializable local (cdk FieldError under RadioGroup) failed the render. Open design gap: a root region needs an opt-in or a way to keep such body code. A JSX `fallback` of `Show` / `Switch` is lazy on the resume server target (compiled to a thunk the server calls only for the fallback branch): an unrendered fallback records no bindings (before 2026-10-09 its reads threw "Missing resumable text N" on the first change).
- Live pages (`export const live = true`, [routing](routing.md#file-routes-live-pages)): the page's `data` accessor is a signal in the resume state, so an in-place revalidation re-runs only the bindings that read `data()` (their symbol chunks load after the answer on a cold page) — the page component is never re-created, its local signals keep their values. A refetched list keeps adopted `For` rows whose fresh item equals the server item in data (new objects, same rows); a row with changed data is re-created; later updates are keyed. A kept row's resumed handlers still see the server item object (equal data, other identity). Without `live`, a revalidation re-renders the page (an open overlay is disposed with it: portal removed, `inert` / scroll lock released).
- Awaited (non-streamed) `Async` content renders after the read that constructed the boundary, but its records belong to that read's region (server-resume `_onAsyncContent`, a `held` logical scope): the Router's route content is a child of the Router region, so re-creating it (first navigation / revalidation of a resumed page) disposes the page's resumed state and what client code created inside (an open cdk overlay: portal, `inert`, scroll lock — fixed 2026-10-08, before the page content counted as the page root and leaked). Rows / branches / client-only mounts / streaming inside it still behave as at the page root (no output change). Streamed content attributes to its boundary region.
- Lazy component children (`_slot`) the traversal renders after the read of the site they were written in (an alias `const content = props.children`, a cdk / ui field's render-prop children inside a Provider) belong to that site's region too (server-resume `_onSlot`, same `held` scope): a server step removed by a ternary / `<Show>` / `<Show keyed>` takes its TextField label / input bindings with it — before, a later write of a shared signal (`value={email}`) resumed them and logged "Missing resumable element N" (fixed 2026-10-08). A slot called inside that site's read or a read nested in it keeps the current region.
- Contexts in the browser: re-created regions get the `resumableContext` providers around their site (entry `[12]`), captured computeds those around their creation (`v`); a resumed binding / clientEffect runs under its region's owner and a resumed handler under the resume root, which carry neither — a `useContext` call inside the binding / handler expression itself (directly or through a captured function) reads the default there. Read the context in the component body (a captured value) or inside a `computed` ([test](../../libs/runtime/tests/resume-owner-context-browser.test.ts) `known limit`). Recipe consts (`_rFn` values re-created from their symbol) run their initializer under the root too.
- Region re-creation during a focus change (2026-10-18): a region whose server content holds the target of a `change` / `blur` / `focus` event being dispatched (`window.event`, also for an event a taken-over spread's own listener handles) is re-created one task later (`dom-resume.ts` `activate`, `inFlight`), so the browser finishes delivering that sequence to the server element first — a blur commits `change`, then `blur` / `focusout` (with `activeElement` already cleared); a focus fires `focus`, then `focusin`. Other events (a click ends its sequence) re-create at once, as before. Replacing the element inside the first event sent the rest to a detached node: a form's delegated `focusout` (`@rivetjs/forms` `onBlur` under a ui `TextField`, whose cdk `change` handler re-creates the field on a resumed page) never saw the field the user left; route-chunk builds (every chunk of the region ready at the first change) made it deterministic, component builds hid it behind the region's chunk loads. A cold replay of such an event (its resumed handler runs from the replay chain, `current`) defers the same way, so the `blur` / `focusout` queued behind it replay first. Same fix: a revived signal holding a falsy value (`0`) is no longer taken for a region id by `arm` (a layout counter at `0` was reset to `undefined` when region 0 — the Router — re-created on the first navigation). Tests `libs/runtime/tests/resume-blur-region-browser.test.ts`, `resume-falsy-signal-browser.test.ts`.
- Capture errors (Function Bridge Q6 / T19, 2026-10-12, `server-resume.ts` `captureError`): `Cannot resume <id>: capture `<name>` <error>` on the dev server (dev manifest `captures`: symbol id → capture names as written — `o.a` for a member-narrowed capture, never the internal parameter `o$a` (compiler `ResumeSymbol.labels`, T19 fix 1) — `libs/compiler/vite.ts` `devResume.manifest()`; the router overlay adds the capture's source location), `capture #<i>` in a dev build without names (`NODE_ENV=development vite build`, `--conditions=development`), `Cannot resume <id>: <error>` in production (no index).
- Vite dev server serves pages resumed (state + loader, chunks per component from Vite; [dev resume](routing.md#file-routes-dev-resume-vite-serve)); the first component edit switches the page to client rendering for hot replacement. Not in dev: `ChunkGroup` / route chunk grouping, preload rules, lazy-page prefetch lists, minification.

## First mouse click: deferred flush

- Rule (reactivity `_dispatch`, every handler path: `_on` / `_listen` / `_spread`, `clientEvent`, resumed `dispatch`): the first `event.isTrusted && type === "click" && pointerType === "mouse"` per document (`event.view`, WeakSet) whose handlers queued effects, outside a batch → handler runs synchronously (preventDefault / stopPropagation / writes; signal + computed reads see new values), flush posted as a MessageChannel task. Handlers of the same event share it. Later clicks on that document, keyboard / touch / pen / untrusted events: synchronous flush as before.
- Why (Chrome 2026-10-07, Playwright, bare page + Rivet page): the first DOM-changing mouse click of a tab stalls the next frame (main thread idle in `WebFrameWidgetImpl::BeginMainFrame` until a hover update) — click→paint p50 sync headless 45–62 ms / headed 47 ms vs deferred 32 / 13 ms. Once one click's DOM change landed, later clicks paint faster synchronously (headless 16 vs 32, headed 6 vs 13): hence one-shot. Not re-armed by idle (3 s) or same-tab navigation (a new document defers its first click once: +1 frame when an earlier document already took the stall). Keyboard Enter sync 1 ms (deferred 7–17), touch tap sync 31–33 (deferred 48–49) → never deferred. A sync DOM write in `pointerdown` (cdk `data-pressed`) does not take the stall; the click's does.
- Ordering: a pending deferred flush runs first on the next `_dispatch` of another event, any `batch` / `batched` entry (effect creation, mounts) and any signal write outside a batch → no reordering, nothing sees a half-applied state across events. Errors: owner handlers in the flush as usual; else the dispatcher's `onError` (dom-resume: `report(symbol)`), else `reportError` — never thrown into the unrelated caller that released it. Disposal before the task: disposed effects skip.
- Navigations defer too (2026-10-08; the earlier `_flushInEvent()` opt-out is removed): Chrome also holds the frame ~50 ms after the hovered element is detached on a document's first mouse click (`ScheduleHoverStateUpdate` task), so dom-v2 `drop` / `swap` (`replace`, `reconcile`) hide the hovered old node (`display:none`, only while reactivity `_deferredFlush()`) and detach it in the next rAF, before that frame paints. Bare page: defer alone 70-85, defer + hide 33.8. resume-bench slow (Chrome 154, 4x CPU, 10 reps, host load ~6-9), paint p50 HEAD -> change: navigate 48.8 (46-72) -> 39.8 (39-56) vs Qwik 55.8; click 32.3 -> 33.2, keyClick 9.7 -> 9.5, tapClick 31.5 -> 32.1 (noise). Hidden stray stays in the DOM until the rAF; `@rivetjs/router` async swaps after a fetch are not covered.
- Tests: `@rivetjs/runtime/testing` `flush()` and `@rivetjs/testing/user` `act()` call reactivity `_settle()`. Playwright suites reading the DOM right after the page's first `page.click` must wait (`waitForFunction` / retrying `expect`). `libs/reactivity/tests/dispatch-defer.test.ts`, `libs/runtime/tests/click-defer-browser.test.ts`.

## Cold press: the mousedown focus move

- Rule (lane RESUME-PINS 2026-10-12, resume fuzz T31 pins cdk `/forms`, `/number-field`, `/radio-group`): a cold `mousedown`'s focus move runs natively at dispatch (the browser's mouse focus), before a handler that cancels it (RA useRadio's label `preventDefault`) or swallows it (`preventFocusOnPress` → RA `preventFocus`: catches the coming focus event and refocuses the active element) loaded. The loader records the element focused at dispatch with the cold event (`live[3]`). The runtime (`dom-resume` `cold`), once the chunks loaded: while the default's target (nearest focusable inclusive ancestor) still holds focus, focus goes back to the recorded element (`preventScroll`; the body: blur); the handlers replay; then, unless one canceled the mousedown, the default's focus follows (`focus({ preventScroll, focusVisible: false })`, or blur when nothing is focusable) — so every handler sees the focus state and the move it would see on a loaded page. Text entry, `select`, range inputs and `[draggable=true]` targets keep the native result (caret, picker). The default's target skips disabled controls and href-less links (`tabIndex` 0, not focusable); nothing focusable pressed = the body holds focus, so a canceling handler on a plain box (a `preventDefault` div, a radio label's text) keeps the element focused at dispatch.
- Once per press (2026-10-13, ui fuzz `/button-group`): `cold()` links each cold mousedown to the queued primary mouse / pen pointerdown with the same target when they are queued. For a linked press the focus-back runs before the pointerdown's replay, so a handler focusing the target (RA usePress, a menu trigger's press start) moves focus as on a loaded page, and the mousedown skips it (else it would put focus back on the previously focused element after the press start focused the trigger: the open menu's FocusScope restored to that element on Escape). The default's focus follows the press's last cold event unless its mousedown was canceled (an unpaired pointerdown focuses even when canceled, as natively: only a canceled mousedown keeps focus). A canceled press records its target as undone (the element focused at its dispatch, the undo time, its dispatch time): a later press dispatched before the undo puts focus back past it, walking strictly back in dispatch time (so A, B, A canceled cannot cycle), and two cold stepper presses never leave the first stepper focused.
- Why not hold the default (tried, reverted the same day): `preventDefault` on the mousedown + a script focus once the handlers ran makes Chrome's `:focus-visible` heuristic treat the focus as keyboard-like, and every later script focus on the page then matches too (dialogs, comboboxes, menus) — focus rings after plain mouse clicks on ui stories. A native mouse focus followed by script focus does not match; `focusVisible: false` covers the refocus after a focused text field (which always matches).
- Limits:
  - The pressed element sees a focus / blur pair before its handlers run (replayed in order); text-selection start is not undone.
  - Double `focus` event: a plain `onFocus` handler on the pressed element (or a `focusin` listener above it) runs for the native mouse focus at dispatch (if its chunk is loaded) and again for the replayed default focus; a loaded page fires one. RA `useFocus` / `useFocusWithin` state is idempotent; counting handlers are not (gap, LOW).
  - `focusVisible: false` is Chromium-only (Firefox / Safari ignore the option: their native heuristic decides whether the refocus after a focused text field matches `:focus-visible`).
  - Focusability is the `tabIndex` / `tabindex` walk + `:disabled` / href-less links; `inert`, hidden or `contenteditable` edge cases follow the walk, not the browser. SVG `<a xlink:href>` (no `href` attribute) is skipped as href-less (LOW gap).
  - Several presses queued cold: the first ones skip the focus-back (native focus already sits on the last pressed target), so their handlers see that target focused; the undone walk keeps the final focus right (LOW gap).
  - Touch: a touch pointerdown is not a press (the browser moves focus at the compatibility mousedown after the finger lifts); a touch press whose pointerdown handler focuses its target replays with the native focus already there when its mousedown came first (LOW gap).
  - Shadow DOM: a press inside a shadow root gets no focus restore (`event.target` is the host, `document.activeElement` the host too, so the walk's target never matches the inner focused element; pre-existing, LOW gap).
- Held click replay (2026-10-13, ui fuzz `/sidebar-extensions`): a held cold click (link, toggle, label, submit; C8) replays as a copy of the user's click (`new event.constructor(type, event)` dispatched on the activation target: same `detail`, `pointerType`, coordinates). `el.click()` gave `detail: 0`, `pointerType: ""`, which cdk focus-visible (`isVirtualClick`) and `usePress` count as a virtual click (keyboard / screen reader): a focus ring after a cold mouse click on a link. Untrusted either way.
- Split live / cold press (cdk fuzz `/number-field`, open pin, runtime): when the pointerdown handler's chunk is already evaluated (settle-time prefetch) but the mousedown one's is not, the live press start steps the value and focuses the field, then the browser's mousedown default (RA `preventFocus` is in the cold handler) moves focus to the stepper.
