# Resumability

Status: one model since M6-CUT (2026-10-22) — the derived model (plan [derived client](../design/plans/2026-10-18-derived-client.md), spec [structural resume](../design/specs/2026-10-18-structural-resume-design.md) §3.3–§3.5). The serialized model (state table, symbol chunks, `_rFn` / `_rMod` recipes, region re-creation, preload planner, lazy rows) is deleted. Framework bridges, `@rivetjs/forms` progressive enhancement, `Suspense` / `resource` state and app `Async` moved onto it in M6-PARITY (2026-10-22); open gaps are tracked in plan M6. User docs: `apps/docs/content/learn/resuming.md`.

## Use

- Router apps (`rivetRouter`): every app `.tsx` module a route imports resumes (`resume.appModules`, default true); `resume.modules` only for modules not statically reachable. Plain `rivet({ resume })` lists every app module (or `appModules: true`).
- Options (`RivetResumeOptions`): `modules`, `appModules`, `roots`, `dev` (dev server serves resumable pages), `domData` (default `false`). Removed in M6: `entry`, `chunks`, `merge`, `cap`, `lazy`, `lazyOwned`, `lazyRows`, `model`, `preload.rules`; router `createApp` `preload` = `{ lean? }`.
- Client build: one chunk per boundary module + the runtime entry (manifest `runtime` / `data-rt` = the `dom-derived-*.js` chunk holding the runtime, no re-export facade; boundary `symbols` likewise name the chunk holding the module's code, `vite.ts` `_foldFacade`); manifest `.vite/rivet-resume.json` `{ hash, runtime, symbols: boundary name → chunk, sizes, deps, builtins?, domData? }`.
- Server: `renderResumable(() => <Page/>, writer, { manifest, signal, nonce })` / `resumableToString(…)` from `@rivetjs/runtime/server-resume` (façade over `renderDerived` / `derivedToString`, `@rivetjs/runtime/server-derived`).
- Playground (production build): file routes `/`, `/items/:id`, `/resume` ([resume-demo.tsx](../../apps/playground/src/resume-demo.tsx)).

## Mechanics

- Server: records boundaries only (interactive component instances: a handler, a signal read in markup, an effect / trigger) and their keyed state values (`_rB` / `_rBOut` / `_rBEnd` / `_rBAttr`, `_rSig` / `_rSigStore`, `_rFor`, `_rHandler` / `_rHandlers`). Markup: `<!--bN-->…<!--/b-->` or `data-b="N"` on an element root. One tail `<script type="rivet/boundaries" data-rt data-fo data-events data-boot data-g>` (wire v2, ZERO S2: `v: 2`, `n` names table = each boundary name once with its chunk index into `u` (chunk URLs), `b` records by name index + runs of stateless sibling records — grows with distinct record shapes, not instances; `k` held keys per boundary, `w` wake lists) + inline loader `resume-loader-derived.ts` (~1.1 KB br, budget in `libs/runtime/tests/resume-loader.test.ts`).
- Loader: reads nothing until an event. Delegated `data-events` (default click input change submit keydown pointerdown pointerup mousedown mouseup focusin focusout). Intent (pointerdown, focusin, touchstart) starts the runtime + fetches the target boundary chunk. A cold event is held (click defaults: links, toggles, labels, summary, submit / reset; submit; invalid; keys in the boundary's `k` — a cold arrow / Space never scrolls the page) and replayed once the chunk ran. `data-fo` = chunks fetched (not run) after load, low priority; none under Save-Data / 2G. `data-boot` = a load / idle / visible trigger: start now. `data-g` = selector routed to the document click listener's boundary (router links).
- Browser (`@rivetjs/runtime/dom-derived`): a boundary's ordinary compiled DOM function runs once over its live server nodes (adopt run, `dom-adopt.ts`) on its first event / wake / trigger. Dependent children (functions, JSX with handlers, non-data props) adopt with the parent (a ROOT boundary has none: one whose record the server marks `BROWSER` — props that hand it behaviour its handlers call — renders in the browser on its first event, DEV warns; ZERO R-22 client half, the server mark is pending); independent ones (props = data) wait for their own. Keyed signals start from the server values; a key the tail leaves out starts from its own init (`LIT`, ZERO S1: the compiler flags a literal-tree init — `signal(0)`, `signal([])`, `createStore({ n: 1 })` — and the server ships no value for a key still holding it: 1000 unclicked counters = 0 keyed values). `For` rows adopt lazily (an event in the row, a write its rows read, a reconcile). Nodes are kept: focus, typed text, selection, scroll survive.
- Event path (`dom-derived.ts` `around`): an event materialises every not-yet-adopted boundary enclosing its target, outermost first (the page root down to the target's own; their handlers may see it bubble, records carry no per-boundary listener types); intent (`w`) loads the outermost one's chunk, and the loader holds a click default (checkbox, label, link) inside any boundary range until then. Router pages: `Root` spans the page, so the first event inside any boundary adopts Root → App → layouts → page and every dependent child; independent boundaries off the path wait. Measured: docs home first click (demo button) 117 files / ~1 MB raw (RED-DOCS 2026-10-23). Fix planned: STATIC-ZERO D5 (live-listener records; loader holds / runtime climbs only for those).
- Mismatch: markup that does not align renders that boundary in the browser (dev: one warning naming it).
- Router (R5): `app.tsx` default `Root` = the page's independent root boundary; props = route payload (JSON + resume-format values); adopt run rebuilds the router from `location`, `Root.ready()` loads page modules first. RV2107 = route data not encodable → page renders in the browser.
- Streamed `Async` with a fallback function resumes as a hole with the server's value (`$rD` add-on); `Suspense` is awaited in place; a unit whose probe run suspends renders in the browser on its first adopt (dev warning). Shell cache stores derived documents (`server-shell.ts` `derivedTail`).
- Render purity: RV2103 (non-deterministic value in render), RV2104 (keyed state in a loop; keys per site, occurrence suffixes pair by order). Boundary eligibility: a PascalCase module function is a component unless every return is an object literal / class.
- What makes a boundary live (STATIC-ZERO T1 / T3, 2026-10-23): a change source of its own (`source`: a handler that is always a function — arrow / function expression / a local function or const arrow —, keyed state, effect, resource, `Async`, module state) or live data in (`facts-fixpoint.ts`). Not state: a module const holding a literal tree (object / array / template / operators over such consts) or a member read of an asset import (`?url`, `.json`, images). A handler that may be absent (`onScroll={track ? sync : undefined}`, `onX={props.onX}`) makes the component `listens`, not `source`: it is conditional (`COND`) and the server keeps its record only for an instance whose handler is a function (`_rHandler(B, value[, type])`; its non-default event type joins `data-events` only then). A native spread in a conditional boundary's own body goes through `_rHandlers(B, attrs)`: an `on[A-Z]…` function in it keeps the instance. Listeners spread by a non-boundary component (a cdk hook inside a static `Link`) do not.
- Dev: dev server serves resumable pages; an edit of a resume module = full reload; a css``-only edit updates the sheet.

## DOM-backed loader data (`resume.domData`, default off)

- Spec `docs/design/specs/2026-10-20-dom-backed-loader-data-design.md`. Items of a `<For>` over a boundary's data props left out of the tail when every value the rows show is the item's (element whole text, plain attribute); read back from the rows on first use, rest in idle slices. 1,000 rows: resume data 8.5 → 0.3 KB br; first click a few ms more at 4× CPU. Server markup must not change before the runtime starts.
- Tests: `libs/runtime/tests/derived-dom-data.test.ts`, `derived-dom-data-browser.test.ts`.

## Security (injected markup)

- The loader reads its own tail (the element right before it): injected HTML earlier in the body cannot name the runtime URL the nonce'd loader imports (`'strict-dynamic'` CSP stays meaningful).
- Boundary ids (`data-b`, `<!--bN-->`) are digits; sanitize user HTML to strip `data-b`. Event types in `data-events`: letters, digits, `_ : . -`. Trusted Types: the runtime's `rivet` policy is private, shared across copies through `Symbol.for("rivet.html")`.

## App guidance (chunk weight before first input)

- A boundary's chunk evaluates its whole module and static imports: keep module-scope data (demo tables, option lists, icon sets) in `.ts` leaf modules imported by what renders them.
- A load-time effect (`clientEffect` with no `when`, `"load"` or `"idle"`) boots its boundary's chunk; inside a big component's module it pulls that module. Put it in a small leaf module — or, for page-wide behaviour with no component state, in a plain module script with no boundary at all (docs-kit `page-script.ts`: a `clientEvent` without `when` and every `clientEffect` set the IDLE trigger, so the page boots the runtime at idle).
- Check with the network panel before the first input, or docs-kit `check-examples` (`measure …: before N scripts / KB`).

## Cold press (`dom-derived.ts`)

- Ported from the serialized runtime (DERIVED-C 2026-10-21): a cold mousedown's native focus move is undone until the replay re-creates it (focus back to the element focused at dispatch, handlers replay, then the default's focus unless canceled, `focusVisible: false`); focus events of the press's native move never replay; a press queued while the runtime dispatches has its move hidden from every listener (window capture listeners). Held clicks replay as a copy of the user's click (same `detail`, `pointerType`). Listeners attached during a replay see later replayed events (`addEventListener` wrapped while a chain drains). Press up / click target re-hit-tested when the press start covered the target. Loader sets `window.__rvIM` (input modality) before any chunk runs; cdk focus-visible adopts it.
- Why not hold the mousedown default: `preventDefault` + script focus makes Chrome's `:focus-visible` heuristic match every later script focus (focus rings after mouse clicks).
- Limits (LOW): double `focus` for a plain `onFocus` on the pressed element; `focusVisible: false` Chromium-only; shadow DOM presses get no focus restore; touch pointerdown is not a press.
- Tests: `libs/runtime/tests/derived-cold-press-browser.test.ts`, `libs/ui/tests-components/cold-focus-ring.test.ts`.

## Listening records (tail names `n[i][2]`, D5)

- Tail v2 names table `n[i][2]` (server `FlushTail.e` before encoding): boundary name → event types its units listen to (`*` = any; union over the name's instances; absent = listens to nothing). An event adopts (and the loader holds / boots for) the records around its target once one of them listens to its type (outermost first: an ancestor unit may provide a context a descendant reads; not for a `CTXFREE` unit, which adopts alone — ZERO CALLSITE below); static text and native controls nothing listens to stay native — no runtime, no chunk. A record the loader cannot name (streamed) and a tail whose names list no types listen to everything.
- Intent (pointerdown / focusin / touchstart) warms only listening records, plus the document click listeners (tail `g`, the router's links) on a `data-g` match; any delegated event on a `g` match adopts its record (before D5 the enclosing record did: the router's link intent). Loader budget 1,344 B br (v2 lookup 1,305; native controls +39).
- What a unit listens to (compiler `_rB` events + server): its own JSX handlers (every type, default delegated ones too; unknown type `*`), `model:` bindings (`input change`), conditional handlers holding a function (`_rHandler` type), spread listener props rendered while it is current (`_trigger.ev`), a handler of a non-boundary helper it runs (cdk `Select` / `Group` / `Compare` internals: in place → compiler `_rListens("type")`, else `omitted` with a function → `*`), `*` for an `interaction` client trigger and for any `ref` / effect in its body (they may attach listeners imperatively at adopt). Focus alone no longer adopts a unit that does not listen to `focusin` (a `model:` input adopts on its first input / change).
- Server emission uses the compiler's full `_rB` events list (FE-COMPILE D5 events, landed with the runtime in ZERO batch 3); a module compiled by an older compiler passes no events and its names carry no types (every record listens, pre-D5 behaviour).

## Independent records: what ships (ZERO REGRESS 2026-10-26)

- Props read back (tail names `n[i][3]` = `"key=path …"`): the compiler (`compile/derived_read.rs`) names, in `_rB`'s sixth argument, each prop of an independent element-root boundary whose every use is the sole text of a native element on a static path from the root element (`<p>{title}</p>`, `props.title` or destructured; path `f` firstChild / `n` nextSibling; no spread / `innerHTML` / opaque / `pre` / `select` / foreign content, no other use). The server leaves a number or non-empty string without CR / NUL of those keys out of the record (`shipped`); the browser reads a missing key from that element's `textContent` before the boundary's standalone run (`dom-derived.ts` `propsOf`; DEV warns when the path finds no node). 500-card list: HTML 13.3 → 8.6 KB gz (one run record, no props), server time back to the pre-C3 cost.
- Below a record that listens to every event (`*`: the document click listeners' root, the router's `App`) an independent record without a trigger is flushed dependent and ships no props: any event there adopts every record around its target outermost first, so its standalone adopt never runs (a route page's `data` was sent twice). Test `tests/derived-cond-root.test.ts`.

## Per-call-site independence (ZERO CALLSITE 2026-10-26)

- Problem: an independent child still adopted with every enclosing record on its first event (intake 3: an ancestor unit may provide a context the child's unit reads through a hook the component facts cannot see), and a context-reading part (cdk `Button` → ui `ButtonRoot`) was dependent everywhere, so an example's demo component kept its record and adopted whole.
- Proof (build, `libs/compiler/facts-callsite.ts`, Rust `facts_refs.rs`): which context tokens a component's unit may read (`touch`: module reference graph across modules, hooks included) vs. what may be provided above a call site (`prov` of the caller's code, enclosing components, the caller's own sites, up to the page; frame pages: their `_layout`s + the docs-kit hosts). Reads (`useContext(X)`, cdk `contextProps` / `slottedContext`) are not provisions. Unfollowable code (`import(expr)`, `eval`, unresolved exports, unknown enclosing tags, roots, components used as values) = unprovable → today's behaviour.
- Proven site (data-only props, no overlap): a dependent callee becomes independent there (`resume.site` / `sites`: caller passes `_rS({…})`, `_rB` flag `SITE` → `INDEPENDENT | CTXFREE` + props shipped); an independent callee proven at every site gets `CTXFREE` (`resume.free`). A props-less `CTXFREE` boundary stays independent (nothing to ship).
- Scope today: shell pages (docs-kit example frames: hosts known, `_layout`s walked). A route root and everything above it is TOP (the router's `App` / layouts / generated `Root` are not walked as hosts; `App` listens to `*`, so intake 3 adopts the chain anyway), so router pages keep today's behaviour.
- Browser (`dom-derived.ts` `around`): a listening record whose unit root is `CTXFREE` adopts standalone (no ancestor unit); otherwise intake 3 as before.
- ui-docs (1,048 frames, base 49024275d): records 13,698 → 12,821, state 1,218,506 → 1,152,393 B, HTML median 11,453 → 11,374 B (gz 4,653 → 4,635); 892 frames smaller, 16 larger (literal props now shipped by `SITE` records: `button-custom-styles` +616 B, long class strings); ≥ 30 KB frames neutral (gz −45 B over 40). First click 4× CPU: alert-basic 122 → 92 ms, button-variants 88 → 83 ms (heap −0.4 MB); single-part examples, scheduler-views, showcase-kanban within noise. Server: zero-cards, routes-100 / 500 unchanged.
- Tests: `libs/compiler/tests/facts-callsite.test.ts`, `libs/runtime/tests/derived-callsite.test.ts`.

## Native automata (ZERO STATESPACE 2026-10-26)

- Idea: a finite-state component whose whole state space a native element realises renders native markup + CSS at a proven call site: 0 B JS before and after interaction, no record. ui families: switch (hidden `input type=checkbox role=switch` in the `<label>`), checkbox (hidden `input type=checkbox`), accordion (`<details>` per item, one shared `name` for single expansion, `<summary>` holding the heading). ARIA + keyboard = the browser's (switch: role switch + checked, Space; checkbox: checked, Space; accordion: summary = button-like disclosure with expanded, Tab between summaries, Enter / Space); the stylesheet derives every visual state from `:checked` / `[open]` / `:hover` / `:active` / `:focus-visible` (`[data-native]` rules).
- Declaration: `// @rivet-native Root(props…) Part(props…) …` line comment in the family module (root first; `data-*` / `aria-*` always allowed). Parsed by `vite.ts` `derivedWalk` (`facts-native.ts` `nativeFamilies`).
- Proof (build, `libs/compiler/facts-native.ts`, per call site, from Rust call facts `attrs`: names, `name*` = not a plain value, `...` spread, `()` function child): root + every call the caller's JSX encloses in it pass declared props with plain values only, no function / spread / render prop; other components inside = static instances (no source / listener / context, data inputs or a non-live caller, no boundary below: kit `Icon`); no part called outside a root in the same JSX (wrapper) and no part used as a value anywhere (else the family is off program-wide; calls between the family's own parts are its code); the caller module has no state selectors (`data-selected:` / `[aria-expanded=…]` / `group-data-[expanded]`, `stylesState`). Verdict `resume.native` (`"Caller:index"`) → Rust `Plan.native` → the element gets `$native: 1` on both targets.
- Run time: the root re-checks (`libs/ui/src/utils/native.ts` `nativeProps`: `$native === 1`, no getter, allowed keys, functions only as children slots; switch / checkbox also: no description, no cdk field / group-state / form-validation provider above) and renders the native branch; same answer on server and browser. An ancestor adopt runs the native branch over the server nodes and keeps the browser's state (`checked` / `open` are not rewritten).
- Loader: native controls carry `data-nc` (see Listening records): never held as presses, not replayed.
- Not native (today's path): controlled / live props (`isSelected`, `expandedKeys`, `onChange`), accordion default expansion (`defaultExpandedKeys` / `defaultExpanded`: an `open` binding would be rewritten by an ancestor's adopt run over the user's toggles; `checked` is safe, the attribute is only the default once the input is dirty), render props, `isIndeterminate`, a description, groups / forms with validation, tabs (radios expose a radio group, not tabs; no native Home / End / roving `aria-selected`: needs a micro handler), cdk disclosure demos (local `signal` + ui `Button` parts).
- Limits: app CSS outside the calling module keyed on a state attribute (`[data-selected]`) does not match native markup; callers style through the documented native selectors. Byte cost on pages that keep the live path: ui switch chunk +~0.6 KB gz, checkbox +~0.9 KB gz, accordion +~1.1 KB gz (the native branch ships with the component).
- Tests: `libs/compiler/tests/facts-native.test.ts`, `libs/runtime/tests/resume-loader.test.ts`, ui-docs example checks (state-neutral selectors: `:is([open], :has([aria-expanded=true]))`).

## Fetch-ahead gating (`server-derived-fo.ts`, ZERO R6a)

- `data-fo` lists only what can become live: records whose name listens (D5), `load` / `idle` / `visible` triggers, the document click listeners (`g`), plus their dependent parent chains, wake-list sources / readers and `MOD` records; nothing live → no `data-fo` (no runtime fetch). Pre-D5 tails (no types): every record.
- Per manifest the list is memoised by (kept names, islands) (`derivedTail` `fetchAhead`); a flush of ≤ 31 records runs the closure over a bit mask (`foNames`), no maps.
- Measured (size-report eager): route-transitions 5 → 4 requests (−0.5 KB br), scheduler-views-binding 60 → 59; ui frames unchanged (every cdk control listens: press / hover / focus handlers — R-13).

## Lite runtime (`@rivetjs/runtime/dom-lite`, ZERO R4 / R5)

- What: a second `DerivedRuntime` (same loader contract: `data-rt`, `start` / `on` / `cold` / `w` / `m`) for pages whose boundary chunks export residuals: `<Name>$a(node, rec)` adopts the server nodes directly (no template clone, no probe), `<Name>$c = () => import(ordinary module)`. Helpers: `_lw` (walk `f`/`n`/`h` steps), `_ls(rec, key, init)` (record value or init; wake-listed key → miss), `_lr(rec, key, at, codec, name?)` (ZERO X9: record value, else the initial value read from the page — codec 0 text, 1 number text, 2 attribute present, 3 attribute value; unreadable → miss; for keys the server elides as `DOMREAD`), `_le` (delegated handler), `_lt` (text after a sole child / content opener, scalars only), `_la` / `_lp` (attr / prop bindings). One reactivity instance, one delegated listener per event type (constant in N).
- Adopt: an event adopts the boundaries around its target (outermost first); a residual runs in `createRoot`. A throw (`LiteMiss`, missing node, wake key) = one-way fallback: dynamic import of `dom-derived` (through `dom-lite-full.ts`, its default only), handed `{ q: pending events, l: lite-owned ids, x: fallen ids }`; the full runtime re-adopts fallen ids through `$c` and leaves lite-owned ones live.
- Full runtime (R5): `dom-derived` runs `<Name>$a` too when the boundary is standalone; throw → ordinary component (one-way, dev warning).
- Leaves: `dom-events.ts` (delegation), `dom-attr.ts` (attribute writes), `dom-base.ts` (`_setProp`, construction doc) split out of `dom-v2.ts` / `dom.ts` so the lite chunk does not pull the whole DOM runtime (rolldown chunks per module).
- Numbers (shells count/N, gzip): JS before first input 22,655 → 7,534 B (N=1), 32,004 → 7,534 B (N=1000, constant in N); total 43,384 → 18,891 B at N=1000; first click 4× CPU at N=1000 112.7 → 43.7 ms. Floor = reactivity (~3.1–3.9 KB gz).
- Residuals: the compiler emits them (FE-COMPILE C1, compile result `lite`); hand-written ones in `libs/runtime/tests/dom-lite-browser.test.ts`.
- Production wiring (ZERO LITE-WIRE 2026-10-26): `rivet({ resume })` builds every module's lite entry + the lite runtime in a module graph of their own (`?rivet-lite` copies: no chunk shared with the ordinary graph, so pages that load the full runtime keep their exact bytes), manifest `lite: { runtime, symbols }`. Server (`server-derived.ts` `flush`, shell only): a page whose every record is `INDEPENDENT` with a name in `lite.symbols` and that holds nothing else for the browser (no island / lean island, `Async`, wake list `w`, counts `c`, DOM data `d`, document listeners `g`) gets `data-rt` = `lite.runtime` and tail `m` = the lite entries (fetch-ahead = their closure); any other page: `runtime` / `symbols` as before. Never both runtimes on one page: a fallback starts the lite graph's own full runtime copy. Tests `libs/compiler/tests/vite-lite.test.ts`.
- Measured (docs frames-only build, gzip -9, warm = after fetch-ahead): tutorial-03 2 files / 31,213 → 2 / 6,708 B before input; 500 / 1000 cards (measurement-only copies) 31,213 → 6,709 / 6,707 B (constant in N); first click 1× / 4× unchanged within noise (tutorial-03 15.6 / 23.4 → 15.2 / 21.1 ms; 1000 cards 45.9 / 51.5 → 45.1 / 49.8 ms). Non-lite pages: byte-identical (full docs build: every base file identical; only tutorial-03's pages differ). Only boundaries with residuals switch (docs: tutorial-03; ui-docs: none, ZERO UI-LITE census).

## Fuzz

- Resume fuzz (Function Bridge T31, `@rivetjs/testing/fuzz`, projects `cdk-resume-fuzz` / `ui-resume-fuzz`): every story-app route of `libs/cdk` / `libs/ui` `tests-components/app` (production build in its own `STORIES_DIST`, default `dist-fuzz`), on two Chromium pages of the same build:
  - resumed = the route as a document load;
  - CSR = `/`, then a client navigation to the route (the router renders the page component in the browser). The router's own traces are undone (h1 / `main` `tabindex="-1"` + its focus move — focus goes back to the element focused before it, e.g. an autofocused one, else nowhere — and the announcer).
- Driver: interactive elements of the resumed page (focusables, ARIA widget roles, `[data-rk]` descendants; no links leaving the page, no file inputs) in document order → per element click, type `"Rivet 7"` into text inputs, press its `[data-rk]` keys (else role keys), Escape. Both pages step in lock-step, then settle (no young request in flight + 2 frames, twice).
- Cold state is deterministic: the resumed page drops every `modulepreload` link added after parsing (preload queue, idle / `visible` preloads, hover-dwell prefetch; `page.ts` `dropPreloads`), so an element's first interaction finds its handler chunk unloaded — no race with background preloads. Idle boot and mount work run as on a real page. Removal after insertion is not proven to cancel a fetch Chrome already started; the determinism rests on the 3-run rule below.
- Oracle after every step:
  - `rivet:resume-error` (cancelled: no reload) and page errors (`ResizeObserver loop` ignored);
  - re-created server nodes: elements stamped at load, removed on the resumed page and kept on the CSR page;
  - normalised DOM: comments dropped, attributes sorted, generated ids (`rv…`) renumbered by first use, empty `class` / input `value` attributes / IDREFs to no element dropped, styles compared as parsed, live `:value` / `:checked` / `:focus`.
  - An attribute-only difference is reported once, then that exact (attribute, resumed value, CSR value) triple is tolerated on that element; any other value later (incl. `:focus` / `:value` / `:checked`, `aria-*`, `data-*` state) is compared again. A structural difference ends the DOM comparison; the rest of the route still runs, checking errors and reloads only (the suite logs where comparison ended).
- Findings → repro log (route, kind, step list, element descriptions; a stopping finding is replayed with the failing element's steps alone and gets that shorter repro when it reproduces). Known ones are pinned per app (`libs/<app>/tests-fuzz/pins.ts`: `match` against the finding's `diff` — the differing tokens / first differing lines only, never context — optional `step` (1-based, 0 = load), owner + note; `test.fails` until fixed, `design: true` for accepted resumed-vs-CSR differences such as mount-time effects, and for findings that do not reproduce on every run: a `test.fails` pin must fail every run). 3-run rule: before a finding becomes a `test.fails` pin (incl. every cold-state class), rerun its route 3 times (`RIVET_FUZZ_ROUTES='/^<route>$/'`, default plan, `dropPreloads` on): identical findings in all 3 = open pin with `step`; seen in 1 or 2 of 3 = timing → `design: true` pin, as narrow as the observed `diff` lines + `step` allow, note with the measured rate ("N of M runs"). Pure helpers (tolerance triples, `structuralDiff`, `rerunCommand`, pin matching, id normaliser): `libs/testing/tests/fuzz-helpers.test.ts` (node). Results + triage: spec `docs/design/specs/2026-10-09-function-bridge-design.md` §8.5.
- Knobs: `RIVET_FUZZ_ROUTES=` (substrings or `/regex/`), `RIVET_FUZZ_SHARD=i/n`, `RIVET_FUZZ_STEPS=` (per route, default 40, seeded sample of element groups above it), `RIVET_FUZZ_SEED=` (sample seed, default 1), `RIVET_FUZZ_LOG=1` (findings + totals), `RIVET_FUZZ_OUT=<file>` (one JSON line per route result). With `RIVET_FUZZ_STEPS` / `RIVET_FUZZ_SEED` set the pin tests are skipped (pins hold for the default plan only). - Route set: every route module of the app's `tests-components/app/src/routes/` (`storyRoutes` walk; `_` / `[` / `(` names skipped). The ui suite writes the gitignored visual matrix routes (`routes/visual/*`, `app/gen-visual.ts`) before listing them (COLD-FOCUS 2026-10-20), so a fresh checkout (CI shards) and a rerun after a local build cover the same routes — before, `storyRoutes` ran at collection, before `buildApp()` generated them: 85 tests on a clean tree, 149 once an earlier build had left `visual/` behind.

## First mouse click: deferred flush

- Rule (reactivity `_dispatch`, every handler path: `_on` / `_listen` / `_spread`, `clientEvent`, derived runtime `dispatch`): the first `event.isTrusted && type === "click" && pointerType === "mouse"` per document (`event.view`, WeakSet) whose handlers queued effects, outside a batch → handler runs synchronously (preventDefault / stopPropagation / writes; signal + computed reads see new values), flush posted as a MessageChannel task. Handlers of the same event share it. Later clicks on that document, keyboard / touch / pen / untrusted events: synchronous flush as before.
- Why (Chrome 2026-10-07, Playwright, bare page + Rivet page): the first DOM-changing mouse click of a tab stalls the next frame (main thread idle in `WebFrameWidgetImpl::BeginMainFrame` until a hover update) — click→paint p50 sync headless 45–62 ms / headed 47 ms vs deferred 32 / 13 ms. Once one click's DOM change landed, later clicks paint faster synchronously (headless 16 vs 32, headed 6 vs 13): hence one-shot. Not re-armed by idle (3 s) or same-tab navigation (a new document defers its first click once: +1 frame when an earlier document already took the stall). Keyboard Enter sync 1 ms (deferred 7–17), touch tap sync 31–33 (deferred 48–49) → never deferred. A sync DOM write in `pointerdown` (cdk `data-pressed`) does not take the stall; the click's does.
- Ordering: a pending deferred flush runs first on the next `_dispatch` of another event, any `batch` / `batched` entry (effect creation, mounts) and any signal write outside a batch → no reordering, nothing sees a half-applied state across events. Errors: owner handlers in the flush as usual; else the dispatcher's `onError` (derived runtime: its error report), else `reportError` — never thrown into the unrelated caller that released it. Disposal before the task: disposed effects skip.
- Navigations defer too (2026-10-08; the earlier `_flushInEvent()` opt-out is removed): Chrome also holds the frame ~50 ms after the hovered element is detached on a document's first mouse click (`ScheduleHoverStateUpdate` task), so dom-v2 `drop` / `swap` (`replace`, `reconcile`) hide the hovered old node (`display:none`, only while reactivity `_deferredFlush()`) and detach it in the next rAF, before that frame paints. Bare page: defer alone 70-85, defer + hide 33.8. resume-bench slow (Chrome 154, 4x CPU, 10 reps, host load ~6-9), paint p50 HEAD -> change: navigate 48.8 (46-72) -> 39.8 (39-56) vs Qwik 55.8; click 32.3 -> 33.2, keyClick 9.7 -> 9.5, tapClick 31.5 -> 32.1 (noise). Hidden stray stays in the DOM until the rAF; `@rivetjs/router` async swaps after a fetch are not covered.
- Linux headless Chromium (CI `ubuntu-latest`, CI-RED-2 2026-10-21) shows no first-click stall: click→paint p50 sync 10–17 ms vs deferred 25–28 ms in 6 of 6 runs, so the deferral costs about a frame there; macOS keeps the stall with a mouse move before the click (not a first-hover artifact). `click-defer-browser` "paints sooner" runs off Linux only. Open question (not measured): Linux / Windows desktop Chrome with a GPU.
- Tests: `@rivetjs/runtime/testing` `flush()` and `@rivetjs/testing/user` `act()` call reactivity `_settle()`. Playwright suites reading the DOM right after the page's first `page.click` must wait (`waitForFunction` / retrying `expect`); a read after a first click that detaches the hovered element waits two frames too (the hidden stray, `core-gaps-browser` (b)). `libs/reactivity/tests/dispatch-defer.test.ts`, `libs/runtime/tests/click-defer-browser.test.ts`.
