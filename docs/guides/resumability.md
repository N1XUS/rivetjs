# Resumability

Status: one model since M6-CUT (2026-10-22) — the derived model (plan [derived client](../design/plans/2026-10-18-derived-client.md), spec [structural resume](../design/specs/2026-10-18-structural-resume-design.md) §3.3–§3.5). The serialized model (state table, symbol chunks, `_rFn` / `_rMod` recipes, region re-creation, preload planner, lazy rows) is deleted. Framework bridges, `@rivetjs/forms` progressive enhancement, `Suspense` / `resource` state and app `Async` moved onto it in M6-PARITY (2026-10-22); open gaps are tracked in plan M6. User docs: `apps/docs/content/learn/resuming.md`.

## Use

- Router apps (`rivetRouter`): every app `.tsx` module a route imports resumes (`resume.appModules`, default true); `resume.modules` only for modules not statically reachable. Plain `rivet({ resume })` lists every app module (or `appModules: true`).
- Options (`RivetResumeOptions`): `modules`, `appModules`, `roots`, `dev` (dev server serves resumable pages), `domData` (default `true` since DOMDATA-DEFAULT 2026-10-27; `false` opts out). Removed in M6: `entry`, `chunks`, `merge`, `cap`, `lazy`, `lazyOwned`, `lazyRows`, `model`, `preload.rules`; router `createApp` `preload` = `{ lean? }`.
- Client build: one chunk per boundary module + the runtime entry (manifest `runtime` / `data-rt` = the `dom-derived-*.js` chunk holding the runtime, no re-export facade; boundary `symbols` likewise name the chunk holding the module's code, `vite.ts` `_foldFacade`); manifest `.vite/rivet-resume.json` `{ hash, runtime, symbols: boundary name → chunk, sizes, deps, builtins?, domData? }`.
- Server: `renderResumable(() => <Page/>, writer, { manifest, signal, nonce })` / `resumableToString(…)` from `@rivetjs/runtime/server-resume` (façade over `renderDerived` / `derivedToString`, `@rivetjs/runtime/server-derived`).
- Playground (production build): file routes `/`, `/items/:id`, `/resume` ([resume-demo.tsx](../../apps/playground/src/resume-demo.tsx)).

## Mechanics

- Server: records boundaries only (interactive component instances: a handler, a signal read in markup, an effect / trigger) and their keyed state values (`_rB` / `_rBOut` / `_rBEnd` / `_rBAttr`, `_rSig` / `_rSigStore`, `_rFor`, `_rHandler` / `_rHandlers`). Markup: `<!--bN-->…<!--/b-->` or `data-b="N"` on an element root. One tail `<script type="rivet/boundaries" data-rt data-fo data-events data-boot data-g>` (wire v2, ZERO S2: `v: 2`, `n` names table = each boundary name once with its chunk index into `u` (chunk URLs), `b` records by name index + runs of stateless sibling records — grows with distinct record shapes, not instances; `k` held keys per boundary (`_rB` `keys`; compiled code passes none — widgets list theirs in `data-rk`), `w` wake lists) + inline loader `resume-loader-derived.ts` (~1.6 KB br, budget in `libs/runtime/tests/resume-loader.test.ts`).
- Loader: reads nothing until an event. Delegated `data-events` (default click input change submit keydown pointerdown pointerup pointercancel mousedown mouseup focusin focusout). Intent (pointerdown, focusin, touchstart, keydown, a mouse / pen pointer resting 80 ms) starts the runtime + fetches the whole `data-fo` list at high priority (ZERO ONDEMAND). Hover events of a listening boundary boot (a pointer pass adopts before the press); on `intent` pages they are held without booting and dropped once the pointer left. A cold event is held (click defaults: links, toggles, labels, summary, submit / reset; submit; invalid; a `contextmenu` inside the nearest `data-cm` — cdk MenuTrigger `trigger="contextMenu"`, so the browser's own menu does not cover the replayed one (COLD-CTXMENU 2026-10-27); elsewhere the browser's menu shows; keys listed by the target's nearest `data-rk` — cdk thumbs, spin fields, composites; a text field without its own `data-rk` keeps its caret keys — or the boundary's `k` (the compiler emits none today): a cold arrow / PageUp never scrolls the page or steps a native range input) and replayed once the chunk ran; a value the replayed handler writes into the target stays (the dispatch-time value is put back only when the replay wrote it). `data-fo` = chunks fetched (not run) in the background, low priority, per `data-fw` (absent = first idle period after load, `load`, `intent` = never; see "Fetch-ahead timing"); no background fetch under Save-Data / 2G. `data-boot` = a load / idle / visible trigger: start now; `data-boot="<ids>"` (ZERO ABI-SPLIT) = the page's only triggers are `visible` ones: start when one of those boundaries' first element intersects the viewport (the loader variant `DERIVED_LOADER_VISIBLE` = the loader + `derivedVisibleBoot`, +184 B br, ships only on such pages). `data-fl` (IDLE-PREFETCH) = the page's lazy parts (see "Lazy parts at idle"), fetched after `data-fo`; only pages with one ship the lazy-part loader. `data-g` = selector routed to the document click listener's boundary (router links).
- Browser: compiled modules import the component ABI from `@rivetjs/runtime/dom-derived` (`dom-derived-abi.ts`, ZERO ABI-SPLIT 2026-10-27: client render until the adopt runtime `@rivetjs/runtime/dom-derived-runtime` = `dom-derived.ts`, the page's `data-rt`, is evaluated and installs itself — a client-rendered mount never fetches the runtime). A boundary's ordinary compiled DOM function runs once over its live server nodes (adopt run, `dom-adopt.ts`) on its first event / wake / trigger. Dependent children (functions, JSX with handlers, non-data props) adopt with the parent (a ROOT boundary has none: one whose record the server marks `BROWSER` — props that hand it behaviour its handlers call — renders in the browser on its first event, DEV warns; ZERO R-22 client half, the server mark is pending); independent ones (props = data) wait for their own. Keyed signals start from the server values; a key the tail leaves out starts from its own init (`LIT`, ZERO S1: the compiler flags a literal-tree init — `signal(0)`, `signal([])`, `createStore({ n: 1 })` — and the server ships no value for a key still holding it: 1000 unclicked counters = 0 keyed values). `For` rows adopt lazily (an event in the row, a write its rows read, a reconcile). Nodes are kept: focus, typed text, selection, scroll survive.
- Event path (`dom-derived.ts` `around`): an event materialises every not-yet-adopted boundary enclosing its target, outermost first (the page root down to the target's own; their handlers may see it bubble, records carry no per-boundary listener types); intent (`w`) loads the outermost one's chunk, and the loader holds a click default (checkbox, label, link) inside any boundary range until then. Router pages: `Root` spans the page, so the first event inside any boundary adopts Root → App → layouts → page and every dependent child; independent boundaries off the path wait. Measured: docs home first click (demo button) 117 files / ~1 MB raw (RED-DOCS 2026-10-23). Fix planned: STATIC-ZERO D5 (live-listener records; loader holds / runtime climbs only for those).
- Adopt runs write nothing the server node already holds (ADOPT-CONTENT 2026-10-26; `dom-v2.ts` `holds` during `_adoption.live`, `LAZY_ROWS` builds only): equal attribute values (an `<iframe src>` re-set reloads the frame), boolean attributes whose presence matches, `open` on `<details>` / `<dialog>` (user's toggle wins), sole text equal to the value. A picked radio, a closed disclosure and typed text survive adoption; a chrome click on a docs page still adopts the page content with its parent (dependent child) but writes none of its nodes (ui `/components/button`: 0 content nodes created, was +2,107; 0 frame reloads, was 10). Build decoration: an element carrying `data-rv-text` (docs-kit build-time highlighting puts it on coloured `<pre>`s) says the build wrapped markup around the rendered text below it; there, a server element whose children differ from the probe's but whose text is equal adopts as the server has it when the probe's subtree is static (no hole, comment marker or created node) — was a mismatch that rendered the whole DocPage in the browser. Deferring light closed subtrees until their own event was tried and dropped: deferred adoption of ui component internals broke them (double Segment indicator, Pagination off by one, ComboBox focus).
- Mismatch: markup that does not align renders that boundary in the browser (dev: one warning naming it).
- Router (R5): `app.tsx` default `Root` = the page's independent root boundary; props = route payload (JSON + resume-format values); adopt run rebuilds the router from `location`, `Root.ready()` loads page modules first. RV2107 = route data not encodable → page renders in the browser (checked, and warned, only when a record ships: a page with nothing live never walks its route data).
- Streamed `Async` with a fallback function resumes as a hole with the server's value (`$rD` add-on); `Suspense` is awaited in place; a unit whose probe run suspends renders in the browser on its first adopt (dev warning). Shell cache stores derived documents (`server-shell.ts` `derivedTail`).
- Render purity: RV2103 (non-deterministic value in render), RV2104 (keyed state in a loop; keys per site, occurrence suffixes pair by order). Ids: `createId()` is `rv…` on the server and `rvc…` in the browser, so an id root a unit creates in render differs in its adopt run; when parts that name it adopt at different times (lazy rows, child boundaries), IDREFs dangle. Hold such a root in a keyed signal (`const keyed = signal(createId())`: the record ships the server id; shared `@rivetjs/cdk/id` `resumedId`; date fields / pickers, ComboBox, Select, ListBox / GridList / Table / Tree collection roots, Tabs, Menu, labels / slots, dialogs / tooltips / overlays, radio / number / color fields, disclosure / stepper / resizable, scheduler, and ui navigation / morph / kanban roots; FACTS-GAP + ID-RESUME 2026-10-27). Boundary eligibility: a PascalCase module function is a component unless every return is an object literal / class.
- What makes a boundary live (STATIC-ZERO T1 / T3, 2026-10-23): a change source of its own (`source`: a handler that is always a function — arrow / function expression / a local function or const arrow —, keyed state, effect, resource, `Async`, module state) or live data in (`facts-fixpoint.ts`) where an instance may render outside every boundary (ORPHAN-B 2026-10-26: a live-data component every call site of which sits inside an interactive caller and passes it plain data only (no callback / signal) — SideNav `Item` — is no boundary: no `data-b`, no record, its caller's unit re-runs it; escaped components (`componentValues`) and route roots stay candidates). Not state: a module const holding a literal tree (object / array / template / operators over such consts) or a member read of an asset import (`?url`, `.json`, images). A handler that may be absent (`onScroll={track ? sync : undefined}`, `onX={props.onX}`) makes the component `listens`, not `source`: it is conditional (`COND`) and the server keeps its record only for an instance whose handler is a function (`_rHandler(B, value[, type])`; its non-default event type joins `data-events` only then). A native spread in a conditional boundary's own body goes through `_rHandlers(B, attrs)`: an `on[A-Z]…` function in it keeps the instance. A spread object the component body builds itself with an `on[A-Z]` key (object literal, `c ? {} : { onPointerMove }`, `c && { onKeyDown }`, a local `const` of one, spreads of those; FACTS-GAP 2026-10-27) makes it `listens` too; calls (`mergeProps(…)`), parameters and destructured `rest` are not seen through (forwarded props: their caller's handler decides). Listeners spread by a non-boundary component (a cdk hook inside a static `Link`, a lowercase helper such as `renderLink`) do not.
- Shell pages see through helpers (TABS-ROOT 2026-10-28): a props-less docs frame page is a boundary when a boundary renders anywhere below it, also behind the helper functions a component body hands its work to (cdk parts: `TabList` → `tabList()` → `<Collection>`; `libs/compiler/facts-fixpoint.ts` `shellRenders` over the binding graph). Before, such a page had no record and the `Collection` / select records shipped as dependent records with no parent: their standalone adopt ran with `{}` props (tab list emptied on the first key, focus to `body`). Other pages already have a record above (router `Root`, docs-kit `FrameRoot`).
- Dev: dev server serves resumable pages; an edit of a resume module = full reload; a css``-only edit updates the sheet.

## DOM-backed loader data (`resume.domData`, default on)

- Spec `docs/design/specs/2026-10-20-dom-backed-loader-data-design.md`. Items of a `<For>` over a boundary's data props left out of the tail when every value the rows show is the item's (element whole text, plain attribute); read back from the rows on first use, rest in idle slices. 1,000 rows: resume data 8.5 → 0.3 KB br; first click a few ms more at 4× CPU. Server markup must not change before the runtime starts.
- Server cost (ROWS-SSR 2026-10-27): a row 0 value shown in two slots (`{ id: 0, values: [0, …] }`) takes distinct slots (was: every later row a misfit, shipped whole); rows checked by a closure tree built once per list. ssr-bench `/resume` in-process: 100 rows CPU ≈ off, 1000 rows −10 %; HTML −8 % / −10 %. Default on since DOMDATA-DEFAULT 2026-10-27 (user ruling: server CPU + bytes over the client first-use cost; numbers `docs/guides/performance.md` "DOMDATA-DEFAULT"); a row is read whole before the runtime first writes into it (`readRow`), so a row text a non-data signal changes is never read back changed. The browser reader is a chunk of its own (`dom-data-reader.ts`, manifest `domData` = its URL): fetched (preloaded with the page's fetch-ahead) only by pages whose tail has `d` entries. Served only to builds with a keyed `<For>` whose rows show a value as whole text / plain attribute (compiler `domListIn`); other builds and `resume: { domData: false }` ship neither the reader nor the encoder (byte-identical).
- Tests: `libs/runtime/tests/derived-dom-data.test.ts`, `derived-dom-data-browser.test.ts`.

## Security (injected markup)

- The loader reads its own tail (the element right before it): injected HTML earlier in the body cannot name the runtime URL the nonce'd loader imports (`'strict-dynamic'` CSP stays meaningful).
- Boundary ids (`data-b`, `<!--bN-->`) are digits; sanitize user HTML to strip `data-b`. Event types in `data-events`: letters, digits, `_ : . -`. Trusted Types: the runtime's `rivet` policy is private, shared across copies through `Symbol.for("rivet.html")`.

## App guidance (chunk weight before first input)

- A boundary's chunk evaluates its whole module and static imports: keep module-scope data (demo tables, option lists, icon sets) in `.ts` leaf modules imported by what renders them.
- A load-time effect (`clientEffect` with no `when`, `"load"` or `"idle"`) boots its boundary's chunk; inside a big component's module it pulls that module. Put it in a small leaf module — or, for page-wide behaviour with no component state, in a plain module script with no boundary at all (docs-kit `page-script.ts`: a `clientEvent` without `when` and every `clientEffect` set the IDLE trigger, so the page boots the runtime at idle).
- Check with the network panel before the first input, or docs-kit `check-examples` (`measure …: before N scripts / KB`).
- Pick the trigger per effect (CEFF 2026-10-28, cdk / ui audit): an idle boot adopts every record of the page, so `when: "interaction"` for work nothing sees before the unit's first event (ref copies, focus resets, reporters, cleanups, mirrors handlers read) and for effects whose inputs are signals the render reads (a write wakes and adopts the unit, which runs them); `"visible"` for work only a visible element needs (wheel listeners, intersection observers) — a unit with no element (a part that renders nothing yet) starts at once; a conditional computed on the server (`untrack`) when only some instances need load-time work; default idle only for what the server cannot render (measured layout, mount focus, DOM properties, data loads, document listeners). Measured (frames-only builds): ui-docs frames that boot at idle 178 → 92 of 202, cdk-docs 97 → 48 of 123 (the rest: avatars with `src`, Tabs / ScrollShadow — its `data-*-scroll` attributes are public styling hooks, Tabs' overflow chevrons read them —, toasts, measured layout, open overlays, example code).

## Wakes create lists (TOGGLE-TABS-COLD 2026-10-27)

- A first write that wakes deferred records (wake list `w`) can create lazy lists whose rows read the written signal (cdk Tabs `items` + `panel`: the force-mounted panels' `Collection` under the deferred `TabPanels`). The write must reach them: keyed `before` (`dom-derived.ts`) runs the wake list first, then wakes `e.fors`; a plain signal's `_guard` (`dom-derived-abi.ts`) calls `s.set` again when the wake re-wrapped it (`wakeOnWrite`). Before: the first cold selection (arrow key, Enter, click) left the server's visible panel until the next change.
- A woken record whose chunk loads after the write creates its lists after it: keyed `before` marks the signal `written`, `sample` materialises a list whose rows read a written keyed signal at once (REDS-CDK 2026-10-28; resumed cdk Table body rows kept the server cells). Limit left: plain signals (no written flag). Tests `libs/cdk/tests-components/list-data.test.ts`, `libs/cdk/tests-components/tabs.test.ts` (automatic + manual activation), `libs/runtime/tests/derived-guard.test.ts`.

## Cold press (`dom-derived.ts`)

- Ported from the serialized runtime (DERIVED-C 2026-10-21): a cold mousedown's native focus move is undone until the replay re-creates it (focus back to the element focused at dispatch, handlers replay, then the default's focus unless canceled, `focusVisible: false`); focus events of the press's native move never replay; a press queued while the runtime dispatches has its move hidden from every listener (window capture listeners). Held clicks replay as a copy of the user's click (same `detail`, `pointerType`). Listeners attached during a replay see later replayed events (`addEventListener` wrapped while a chain drains). Press up / click target re-hit-tested when the press start covered the target. Loader sets `window.__rvIM` (input modality) before any chunk runs; cdk focus-visible adopts it. Held keys follow the focus their replays move (COLD-FIX-B 2026-10-27): keys typed before boot into a field that auto-advances (date / time segments, OTP-like inputs) replay on the element the previous key's replay focused, not all on the first one. A press's default focus replays only while focus still sits where the press left it (TOGGLE-TABS-COLD 2026-10-27): on its target (native move landed) or, for a press whose move was hidden, where it was at dispatch; focus moved on before the chunk loaded (a script `focus()`, Tab, Playwright `press`) stays — before, a cold click then focus + ArrowDown in another toolbar pulled focus back to the clicked button and the key moved nothing.
- Why not hold the mousedown default: `preventDefault` + script focus makes Chrome's `:focus-visible` heuristic match every later script focus (focus rings after mouse clicks).
- Limits (LOW): double `focus` for a plain `onFocus` on the pressed element; `focusVisible: false` Chromium-only; shadow DOM presses get no focus restore; touch pointerdown is not a press.
- Held defaults (RESUME-FIX A1 2026-10-27): a held submit / link click / submit-button click runs its handlers once (the replay), then its default once: the loader's `requestSubmit()` / re-dispatched link click reaches native listeners and the browser, never the delegated handlers again (`dom-events.ts` `_delegated`) nor the listeners `late` ran on the held event (compiled `onSubmit` = a direct `_listen` listener: off while that event propagates, `defaulted`). Lite runtime: same (`dom-lite-core.ts` `defaulted`). Limit: a listener `late` ran is re-added after the default (last on its target).
- Tests: `libs/runtime/tests/derived-cold-press-browser.test.ts`, `derived-cold-default-browser.test.ts` (Chromium + WebKit, full + lite), `libs/ui/tests-components/cold-focus-ring.test.ts`.

## Listening records (tail names `n[i][2]`, D5)

- Tail v2 names table `n[i][2]` (server `FlushTail.e` before encoding): boundary name → event types its units listen to (`*` = any; union over the name's instances; absent = listens to nothing). An event adopts (and the loader holds / boots for) the records around its target once one of them listens to its type (outermost first: an ancestor unit may provide a context a descendant reads; not for a `CTXFREE` unit, which adopts alone — ZERO CALLSITE below); static text and native controls nothing listens to stay native — no runtime, no chunk. A record the loader cannot name (streamed) and a tail whose names list no types listen to everything.
- Intent (pointerdown / focusin / touchstart / keydown / 80 ms rest) warms only listening records, plus the document click listeners (tail `g`, the router's links) on a `data-g` match; any delegated event on a `g` match adopts its record (before D5 the enclosing record did: the router's link intent). Loader budget 1,585 B br (1,583: v2 lookup 1,305; native controls +39; ZERO ONDEMAND timing / intent +239).
- What a unit listens to (compiler `_rB` events + server): its own JSX handlers (every type, default delegated ones too; unknown type `*`), `model:` bindings (`input change`), conditional handlers holding a function (`_rHandler` type), spread listener props rendered while it is current (`_trigger.ev`; a dropped static conditional record's types go to its nearest kept ancestor, e.g. a cdk Link's press listeners inside ui Breadcrumbs), a handler of a non-boundary helper it runs (in place → compiler `_rListens("type")`, else `omitted` with a function → `*`), `*` for an `interaction` client trigger and for any `ref` / effect in its body (they may attach listeners imperatively at adopt). Focus alone no longer adopts a unit that does not listen to `focusin` (a `model:` input adopts on its first input / change).
- Server emission uses the compiler's full `_rB` events list (FE-COMPILE D5 events, landed with the runtime in ZERO batch 3); a module compiled by an older compiler passes no events and its names carry no types (every record listens, pre-D5 behaviour).

## Independent records: what ships (ZERO REGRESS 2026-10-26)

- Props read back (tail names `n[i][3]` = `"key=path …"`): the compiler (`compile/derived_read.rs`) names, in `_rB`'s sixth argument, each prop of an independent element-root boundary whose every use is the sole text of a native element on a static path from the root element (`<p>{title}</p>`, `props.title` or destructured; path `f` firstChild / `n` nextSibling; no spread / `innerHTML` / opaque / `pre` / `select` / foreign content, no other use). The server leaves a number or non-empty string without CR / NUL of those keys out of the record (`shipped`); the browser reads a missing key from that element's `textContent` before the boundary's standalone run (`dom-derived.ts` `propsOf`; DEV warns when the path finds no node). 500-card list: HTML 13.3 → 8.6 KB gz (one run record, no props), server time back to the pre-C3 cost.
- Below a record that listens to every event (`*`) an independent record without a trigger and not `CTXFREE` is flushed dependent and ships no props: any event there adopts every record around its target outermost first, so its standalone adopt never runs (a route page's `data` was sent twice). Test `tests/derived-cond-root.test.ts`.
- Document click listeners' root (RT-DIET2 2026-10-26): the router's `Root` (`_rListen`, tail `g`) no longer listens to every event. A unit that reads what it provides is not `CTXFREE` and adopts with every record around it (intake-3 `around` rule); a `CTXFREE` unit adopts standalone; an event outside every listening record acts natively. Route modules' `above` = the route hosts' provisions (`resume.roots`, walked without the page modules they `import()`) + the page's `_layout` files, not TOP (`facts-callsite.ts` `routeHosts`): a context-free leaf under a route page (starter `Counter`) is `free`. A page whose only live records are the link listeners (no listening name, no trigger) fetches ahead on link intent (`data-fw="intent"`; test `derived-cond-root` "links-only").

## Per-call-site independence (ZERO CALLSITE 2026-10-26)

- Problem: an independent child still adopted with every enclosing record on its first event (intake 3: an ancestor unit may provide a context the child's unit reads through a hook the component facts cannot see), and a context-reading part (cdk `Button` → ui `ButtonRoot`) was dependent everywhere, so an example's demo component kept its record and adopted whole.
- Proof (build, `libs/compiler/facts-callsite.ts`, Rust `facts_refs.rs`): which context tokens a component's unit may read (`touch`: module reference graph across modules, hooks included) vs. what may be provided above a call site (`prov` of the caller's code, enclosing components, the caller's own sites, up to the page; frame pages: their `_layout`s + the docs-kit hosts). Reads (`useContext(X)`, cdk `contextProps` / `slottedContext`) are not provisions. Unfollowable code (`import(expr)`, `eval`, unresolved exports, unknown enclosing tags, roots, components used as values) = unprovable → today's behaviour.
- Proven site (data-only props, no overlap): a dependent callee becomes independent there (`resume.site` / `sites`: caller passes `_rS({…})`, `_rB` flag `SITE` → `INDEPENDENT | CTXFREE` + props shipped); an independent callee proven at every site gets `CTXFREE` (`resume.free`). A props-less `CTXFREE` boundary stays independent (nothing to ship).
- Scope today: shell pages (docs-kit example frames: hosts known, `_layout`s walked). A route root and everything above it is TOP (the router's `App` / layouts / generated `Root` are not walked as hosts; `App` listens to `*`, so intake 3 adopts the chain anyway), so router pages keep today's behaviour.
- Browser (`dom-derived.ts` `around`): a listening record whose unit root is `CTXFREE` adopts standalone (no ancestor unit); otherwise intake 3 as before.
- ui-docs (1,048 frames, base 49024275d): records 13,698 → 12,821, state 1,218,506 → 1,152,393 B, HTML median 11,453 → 11,374 B (gz 4,653 → 4,635); 892 frames smaller, 16 larger (literal props now shipped by `SITE` records: `button-custom-styles` +616 B, long class strings); ≥ 30 KB frames neutral (gz −45 B over 40). First click 4× CPU: alert-basic 122 → 92 ms, button-variants 88 → 83 ms (heap −0.4 MB); single-part examples, scheduler-views, showcase-kanban within noise. Server: zero-cards, routes-100 / 500 unchanged.
- Soundness (CTX-SOUND 2026-10-27): `around` is lexical. JSX in a nested function runs where the function is called (`const row = () => <X />; <P>{row()}</P>`, `<P>{row}</P>`, `<P render={row} />`, a local component, a callback passed to other code): such calls `escape` (`libs/compiler/facts-placement.ts`, above = TOP). In-place functions keep their proof: JSX children / render props written in a component element, IIFEs, eager array callbacks, reactivity `provide` / `untrack` / `batch` / `catchError` / `computed` / `effect`. Eager JSX (`const t = <X />` then `<P>{t}</P>`) is created before `P` runs and reads the default on both sides: proven. JSX outside every component (top-level helpers, factories) hides its callee's instances: above TOP, never `free`. An independent component that may read (through a hook) a token provided or unknown above a site is demoted to dependent there (`site` path or adopt with the parent). Cost: starter-ui +454 B br eager (`AvatarRoot`'s `const content = () => …` under its own `Provider`), docs-kit frames unchanged.
- Tests: `libs/compiler/tests/facts-callsite.test.ts`, `libs/compiler/tests/vite-callsite-sound.test.ts`, `libs/runtime/tests/derived-callsite.test.ts`.

## CSS-only Motion elements (MOTION-CSS 2026-10-27)

- Problem (external verify C10): a resumed boundary rendering `<Motion.h1 initial={…} animate={…}>` ran the Motion element inline in its adopt run, so its chunk graph carried element + tags + kit transition (≈ 33.9 KB raw / 11.7 KB br before input) for an element whose whole behaviour is CSS.
- Build pass (`libs/compiler/static-motion.ts`, Vite `derivedWalk`, after `boundaryFacts`): a call site written in place with constant `initial` / `animate` / `transition` / `reducedMotion`, no other Motion prop, and nothing Motion reads provided above it (`BoundaryFacts.aboveCall`: no TOP, no motion `element.tsx` / kit `transition.tsx` token, no unwalked package) becomes the plain `<tag style={…} data-mve="…">`; the rule (`@rivetjs/motion/static`, same code as the element) is the module's stylesheet import → route CSS (also for client renders; no head sink needed). Facts of rewritten modules are recomputed and the program closed again.
- Call sites in nested functions (CTX-SOUND 2026-10-27): see "Per-call-site independence" — only calls that run where they are written are proven; the Motion pass only rewrites elements written in place.

## Fetch-ahead gating (`server-derived-fo.ts`, ZERO R6a)

- `data-fo` lists only what can become live: records whose name listens (D5), `load` / `idle` / `visible` triggers, the document click listeners (`g`), plus their dependent parent chains, wake-list sources / readers and `MOD` records; nothing live → no `data-fo` (no runtime fetch). Pre-D5 tails (no types): every record.
- Per manifest the list is memoised by (kept names, islands) (`derivedTail` `fetchAhead`); a flush of ≤ 31 records runs the closure over a bit mask (`foNames`), no maps.
- Measured (size-report eager): route-transitions 5 → 4 requests (−0.5 KB br), scheduler-views-binding 60 → 59; ui frames unchanged (every cdk control listens: press / hover / focus handlers — R-13).

## Fetch-ahead timing (ZERO ONDEMAND 2026-10-26)

- Option: `PreloadOptions` (`renderResumable` / `derivedToString` `preload`, router `createApp` / adapters `preload: { ahead, lean }`): `ahead: "idle"` (default, no attribute) = low-priority modulepreloads in the first idle period after `load` (`requestIdleCallback`, else `setTimeout`); `"load"` = right after `load`; `"intent"` (= `lean: true`) = nothing in the background. `data-fo` ships in every mode; `data-fw` carries the mode.
- Intent fetches the whole `data-fo` list at once, high priority (one round trip of parallel requests, no import waterfall); before, lean pages fetched only the target's chunk and walked its imports. Trigger boots (`data-boot`) do not fetch the list.
- Hover: `pointerover` arms an 80 ms dwell (mouse / pen only); a pointer still `:hover` then = intent. Held `pointerover` / `pointerenter` / `mouseover` / `mouseenter` boot at once on `idle` / `load` pages (as before: the pass adopts, the press pays nothing; measured: a no-rest click otherwise paid the adopt, prompt-suggestion 11 → 38 ms); on `intent` pages they never boot, and `prune` drops the ones whose target is no longer `:hover` (at the dwell, before `rt.start`). `dom-derived.ts` `drain` folds a run of held enters into its innermost one, adopts around it and synthesises the enters over its path (no replay): one `onPointerEnter`, not two.
- Touch press cancel: `pointercancel` is a default held type, so a cold touch press that becomes a scroll replays its cancel (no stuck `data-pressed`; before: stuck until the next press).
- Cold visuals: ui hover / press / focus-visible styles pair every `data-*` state with its pseudo-class (`:hover` inside `@media (hover: hover)`, `:active`, `:focus-visible`), so a page whose code has not loaded looks the same (`libs/ui/styles/TWEAKS.md` TW-155; exception: pressed transform / scale / opacity rules keep `data-pressed` only, measured: an `:active` twin there made the first adopt at pointerdown ~20 ms slower; test `libs/ui/tests-components/cold-states.test.ts`).
- Tests: `libs/runtime/tests/derived-ahead-browser.test.ts`, `derived-cold-press-browser.test.ts`, `libs/ui/tests-components/cold-states.test.ts`. Numbers: lane report ZERO-ONDEMAND (bytes before input, first-click latency fast / Slow 4G 4x CPU per mode).

## Lazy parts at idle (IDLE-PREFETCH 2026-10-27)

- What: code behind `lazyComponent(() => import("…"))` (inline importer) leaves the before-input set (`data-fo`) and is fetched once that set has loaded, at idle, low priority (`data-fl`). A first open after idle evaluates a module already fetched: no round trip. User ruling 2026-10-27: idle prefetch OK; it unparked the BIG-UI lazy parts (scheduler context menu, month `+N more` panel, the open `PopoverInner`).
- Build: compiler `_lazyParts` finds the inline importers; `derivedManifest` writes `lazy` (chunk → its lazy-part chunks) and adds the parts to `deps`. Server: `laterUrls` = the parts the page's `data-fo` reaches, transitively, + closures, minus `data-fo`. Static: a part the page can never open (a scheduler without menu renderers) is still listed.
- Loader: pages with `data-fl` ship `DERIVED_LOADER_LATER` (`derivedFetchLater` spliced in place of the fetch-ahead link loop, +83 B br; other pages' loader byte-identical): it waits for every `data-fo` link's load / error, then appends `data-fl` in the next idle period. Runs wherever the fetch-ahead runs (background, or after an intent on `intent` pages); never under Save-Data / 2G. Never evaluated before use.
- Before idle (the part not fetched yet): the open waits for the part (one round trip + its bytes); the part's code is requested when its boundary runs (`lazyComponent.load()` at the first event), in parallel with the open.
- After idle: no round trip, but the import + module instantiate run after the boundary, one task before the mount (no-rest press +15…+60 ms at 4× CPU; hover-first equal).
- Tests: `libs/runtime/tests/derived-later-browser.test.ts`, `libs/compiler/tests/vite-derived.test.ts` "lazy parts". Numbers: `docs/guides/performance.md` "First interaction".

## Lite runtime (`@rivetjs/runtime/dom-lite`, ZERO R4 / R5)

- What: a second `DerivedRuntime` (same loader contract: `data-rt`, `start` / `on` / `cold` / `w` / `m`) for pages whose boundary chunks export residuals: `<Name>$a(node, rec)` adopts the server nodes directly (no template clone, no probe), `<Name>$c = () => import(ordinary module)`. Helpers: `_lw` (walk `f`/`n`/`h` steps), `_ls(rec, key, init)` (record value or init; wake-listed key → miss), `_lr(rec, key, at, codec, name?)` (ZERO X9: record value, else the initial value read from the page — codec 0 text, 1 number text, 2 attribute present, 3 attribute value; unreadable → miss; for keys the server elides as `DOMREAD`), `_le` (delegated handler), `_lt` (text after a sole child / content opener, scalars only), `_la` / `_lp` (attr / prop bindings). One reactivity instance, one delegated listener per event type (constant in N).
- Adopt: an event adopts the boundaries around its target (outermost first); a residual runs in an owner list of the nano core (`dom-lite-core.ts` `own`; released on throw). A throw (`LiteMiss`, missing node, wake key) = one-way fallback: dynamic import of `dom-derived` (through `dom-lite-full.ts`, its default only), handed `{ q: pending events, l: lite-owned ids, x: fallen ids }`; the full runtime re-adopts fallen ids through `$c` and leaves lite-owned ones live.
- Full runtime (R5): `dom-derived` runs `<Name>$a` too when the boundary is standalone; throw → ordinary component (one-way, dev warning).
- Leaves: `dom-events.ts` (delegation), `dom-attr.ts` (attribute writes), `dom-base.ts` (`_setProp`, construction doc) split out of `dom-v2.ts` / `dom.ts` so the lite chunk does not pull the whole DOM runtime (rolldown chunks per module).
- Numbers (shells count/N, gzip): JS before first input 22,655 → 7,534 B (N=1), 32,004 → 7,534 B (N=1000, constant in N); total 43,384 → 18,891 B at N=1000; first click 4× CPU at N=1000 112.7 → 43.7 ms. Floor then = reactivity (~3.1–3.9 KB gz); since RT-DIET the nano core replaces it (below).
- Nano core (RT-DIET 2026-10-26): residuals are closed world (keyed / never-written signals, copied data constants, globals; no props live, no context), so the lite runtime carries its own signal / effect / owner / delegation core (`dom-lite-core.ts`) instead of `@rivetjs/reactivity` + `dom-events.ts`; same `$$<type>` node fields, batched handlers, first-mouse-click deferred flush. Leaves re-exported from `dom-lite.ts`, one module each so the lite chunk carries only what its residuals import: `dom-lite-attr.ts` (`_lk` class, `_lq` plain attr, `_lb` boolean attr + property), `dom-lite-write.ts` (`_la` / `_lp`), `dom-lite-list.ts` (`_lf` keyed list), `dom-lite-model.ts` (`_lm` two-way `model:value` / `model:checked`; first run like the full runtime: a control changed before adoption keeps its state (text typed then stays), a pristine one takes the signal's value when it differs, keeping a focused selection). Replay restores value / checked only when they differ, and events dispatched while replaying are not held again.
- Lite v2 eligibility (`derived_lite.rs` header): `computed(arrow)` (`_lc`), local arrow / function declarations, live class / plain / boolean attributes, `model:*`, submit / change / reset handlers, `<For each by>` with a native row (`_lf`: server rows `<!--r[-->` adopt, new rows built from a data spec). Still ordinary: components / fragments in the body or rows, `style` bindings, spreads, refs, slots, `Show` / `Switch`, i18n.

## First mouse click: deferred flush

- Rule (reactivity `_dispatch`, every handler path: `_on` / `_listen` / `_spread`, `clientEvent`, derived runtime `dispatch`): the first `event.isTrusted && type === "click" && pointerType === "mouse"` per document (`event.view`, WeakSet) whose handlers queued effects, outside a batch → handler runs synchronously (preventDefault / stopPropagation / writes; signal + computed reads see new values), flush posted as a MessageChannel task. Handlers of the same event share it. Later clicks on that document, keyboard / touch / pen / untrusted events: synchronous flush as before.
- Why (Chrome 2026-10-07, Playwright, bare page + Rivet page): the first DOM-changing mouse click of a tab stalls the next frame (main thread idle in `WebFrameWidgetImpl::BeginMainFrame` until a hover update) — click→paint p50 sync headless 45–62 ms / headed 47 ms vs deferred 32 / 13 ms. Once one click's DOM change landed, later clicks paint faster synchronously (headless 16 vs 32, headed 6 vs 13): hence one-shot. Not re-armed by idle (3 s) or same-tab navigation (a new document defers its first click once: +1 frame when an earlier document already took the stall). Keyboard Enter sync 1 ms (deferred 7–17), touch tap sync 31–33 (deferred 48–49) → never deferred. A sync DOM write in `pointerdown` (cdk `data-pressed`) does not take the stall; the click's does.
- Ordering: a pending deferred flush runs first on the next `_dispatch` of another event, any `batch` / `batched` entry (effect creation, mounts) and any signal write outside a batch → no reordering, nothing sees a half-applied state across events. Errors: owner handlers in the flush as usual; else the dispatcher's `onError` (derived runtime: its error report), else `reportError` — never thrown into the unrelated caller that released it. Disposal before the task: disposed effects skip.
- Navigations defer too (2026-10-08; the earlier `_flushInEvent()` opt-out is removed): Chrome also holds the frame ~50 ms after the hovered element is detached on a document's first mouse click (`ScheduleHoverStateUpdate` task), so dom-v2 `drop` / `swap` (`replace`, `reconcile`) hide the hovered old node (`display:none`, only while reactivity `_deferredFlush()`) and detach it in the next rAF, before that frame paints.
