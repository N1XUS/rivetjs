# LITE-BOOT: first input dispatched in its own task (2026-10-29)

Base efa0a002a (A) vs the prime (B). Chrome 156.0.8078.48 headless, macOS, Apple M4 Pro, Node 26.5.1. Host shared with other lanes; load1 noted per row. Every cell: median (min–max), A and B interleaved in random order per repeat, fresh context, cache disabled.

## Change

- Loader (`libs/runtime/resume-loader-derived.ts` `prime`): with the background fetch-ahead (`idle` / `load`; not `intent`, Save-Data / 2G, `data-boot` pages) it also runs `boot(1)` and `rt.w(document)`.
- `rt.w(document)`: lite runtime (`dom-lite.ts`) loads every lite record's module; full runtime (`dom-derived.ts`) loads every listening record's chunk (no `ready` / `prepare`: the router's `Root.ready` would fetch page modules outside the fetch-ahead list). Errors swallowed until an event needs the record. Nothing adopts.
- First event after that: `rt.on` live → adopt + handler inside the input task. Before: held, replayed after `import()` resolved, which Chrome runs only after the next frame (CX-SCHED traces) → +1 frame.
- First-mouse-click deferred flush unchanged (click DOM write one task later; submit / key / touch writes in the task).
- Cost: +26 B br loader (1,738 → 1,764; visible 1,917 → 1,953; lazy parts 1,818 → 1,840 / 1,990 → 2,022); module evaluation at idle; chunk top-level code runs at idle instead of on the first event.
