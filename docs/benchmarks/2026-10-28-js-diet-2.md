# JS-DIET-2: JS before first input on the real resume-bench pages (2026-10-28)

Lane JS-DIET-2 (plan JS-DIET phase 1). Base 6c9d47ca7. Host: Apple M4 Pro, Chrome 156.0.8078.48, Node 26.5.1.
Load: run 1 load1 8.7–34 (another lane building), run 2 7–18.6; SSR Docker bench was off for run 1 and restarting
(image build) during the last minute of run 2. Interleaved rotating lane order, fresh context per sample.

## Variants

- `base`: HEAD build (full runtime: runtime + abi + root + page chunks).
- `s12`: slice 1 (pass-through `Root` drops out of the tail: `App` independent) + slice 2 (lite runtime: record props,
  `_lv`, `_lo`). Slice 2's compiler half is a Rust patch (not built in the lane): the pages' residuals were
  hand-written stand-ins of its output (bench only, never landed).
- `s123`: + slice 3 (lite runtime + the one lite entry in one chunk).
- `s1234`: + slice 4 (runtime module evaluated at idle) — measured, not landed.
- Solid 1.9.15 (`solid-stable`) for reference.

A default-exported lite boundary keeps the runtime's ~90 B facade (else the chunk's `default` would be the
runtime). Full-runtime pages: client runtime unchanged; server bundles +33 B min (`lite.props`). Big ui pages
(ui-docs frames incl. the ≥ 100-element ones, `scripts/size-report/frames.mjs --sites=ui`): JS unchanged (no lite
entries there). Rejected alternative: `dom-derived.ts` telling lite chunks by `<Name>$c` (−9 B min) cost
+80..+190 B br on every ui frame (Brotli).
