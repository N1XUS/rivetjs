## Lazy rows server cost (lane LAZY-COST, 2026-10-21)

- Finding: M2-R5's control (`2026-10-20-derived-r5.notes.md`) measured `rivet-resume` with lazy rows at 5.737 ms CPU/page vs 1.467 recorded at 1000 rows c1 (TTFB 3.34 vs 0.70 ms).
- Base `e80dd8dca`. Fix: `libs/runtime/server-resume.ts` `lazyPlanRows` — a lazy `<For>` whose row is a row plan (`$rows`) writes its rows from one list tape (region plan without ids, WebAssembly row emitter) instead of one `renderToString` per row. Details: `libs/runtime/CLAUDE.md` "Lazy rows from row plans"; spec `docs/design/specs/2026-10-19-lazy-collection-rows-design.md` §4 "LAZY-COST measured".
- Lanes (all `/resume`, lane name `rivet-resume`, one image each): `rivet-resume` = default build; `+lazy` = same app built with `RIVET_LAZY_ROWS=on RIVET_LAZY_ROWS_HARNESS=1` (manifest `lazyRows`) + `ENV RIVET_LAZY_ROWS=on`; `(base)` = `libs/runtime/server-resume.ts` at base, `(fix)` = with the fix.
- Host: macOS arm64, 14 cores, Docker VM; another agent lane (Chromium) and non-Rivet containers running. Tuned GC, node generator, 1 CPU / 512 MiB per lane, c1, 10 s + 3 s warm-up per trial. Host load = 1-min max over the cell's trials.
