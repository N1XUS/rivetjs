# SSR-RSS (2026-11-01): peak memory vs Qwik

Goal: rivet-resume / rivet-router peak memory ≤ best Qwik lane at 100 / 1000 / 5000 rows, c1 + c10, CPU/page, p50, TTFB not worse. Outcome: goal met at 1000 / 5000 rows (was already); 100 rows still behind qwik-stable. Landed: node adapter `NodeRequest` (no undici signal-following per request): 100 rows c10 peak −35 MiB (resume) / −32 MiB (router), CPU flat. Output byte-identical.

## Setup
- `apps/ssr-bench/benchmark.py`, Docker 1 CPU / 512 MiB, `--single-threaded-gc --max-semi-space-size=8`, C# gRPC backend, prewarm at max rows × min(10, conc) (protocol unchanged). Peak = container `usage - inactive_file`, 250 ms samples.
- Batches as the official comparison (Qwik OOMs at 5000 rows c10): `c1 r100`, `c10 r100`, `c10 r1000`, … one `benchmark.py` per batch, fresh containers.
- Host: macOS Docker Desktop, another lane running browser benchmarks; load 7–28 (baseline, first A/B), 10–280 (final A/B). Not waited for idle.

## Peak breakdown (rivet-resume 100 rows c10, ~150–175 MiB)
- V8 pages ≈ 118 MB (472 × 256 KiB VMAs): committed heap 70–95 MB (old gen 35 → 80 MB between mark-compacts at ~4 MC/s; new ~16 MB) + pooled pages 30–60 MB (`--memory-pool`, freed after 8 s idle).
- brk malloc ~19 MB; glibc thread arenas 15–35 MB (V8 worker compile zones; Solid similar, Qwik ~3 MB each); misc ~8 MB.
- Idle: anon ~62 MB, V8 13.6 MB; non-V8 mmap ~39 MB vs Qwik ~7 MB (arenas).
- Promotion: every scavenge runs during sweeping (single-threaded GC); `--trace-gc-nvp` ~142 KB promoted / 241 KB survived per scavenge. Heap sampling (`includeObjectsCollectedByMajorGC`), promoted bytes per request: rivet-resume 18.2 KB, router `/page` 16.7, rivet-compiled 7.6; no undici signal 15.8; + harness unpin 8.7. Allocation ~147 KB/request.
- Request lifetime: 84.7 % live across 0 scavenges, 15.3 % across 1, none ≥ 2 (rivet-resume; rivet-compiled 6.6 % across 1).

## Change: `NodeRequest` (libs/router/adapters/node.ts)
`new Request(url, { signal })` (undici) makes its signal follow the init signal through a WeakRef + FinalizationRegistry entry + `addAbortListener`. Registry cells clear only on a full GC → request objects promoted. Microbench (200 scavenges): old gen 55 MB with init signal vs 20 MB without vs 5 MB plain. `NodeRequest extends Request` overrides `signal` with the adapter's disconnect signal; `clone()` pins the same signal. `limitBody` (`server/security.ts`) passes `signal: request.signal` to its copy.

## Screened, not landed
- `--optimize-for-size`: peak 160 → 78 MiB, rps −40 % (CPU).
- `--heap-growing-percent=10`, `--no-memory-pool`, `--no-large-page-pool`: no reduction.
- Semi-space override: the bench sets `--max-semi-space-size=8` for every Node lane; changing it per lane is unfair.
- Harness unpin (`services/content.server.ts`, shared by all lanes): `removeAllListeners()` when the h2 stream closes (its listeners' closure pins the last page's chunks) → promoted 15.8 → 8.7 KB/req, peak not moved in screens. Harness change for every lane → needs a ruling; not in the patch.

## Remaining gap at 100 rows
qwik-stable 87 / 118 MiB vs rivet-resume 93 / 153 (c1 / c10). Set by old-gen limit (live-after-MC ~35 MB incl. floating garbage × growing factor) at ~25× Qwik's request rate, plus page pool and arenas. Next candidates: rate-matched memory comparison; fewer in-flight objects per request (one-shot pages), malloc arena cap (`MALLOC_ARENA_MAX`, an adapter/product default would need a launcher).
