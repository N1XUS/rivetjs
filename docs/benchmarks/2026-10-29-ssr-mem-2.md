# SSR-MEM-2 (2026-10-29): router handler fixed allocation

Goal: cut SSR peak memory (last SSR metric lost, vs Qwik). Outcome: per-request allocation down ~3-6 KB (rivet-router, 100 rows); peak RSS not measurably changed (see below). CPU not worse. Output byte-identical.

## Changes
- `libs/router/server/handler.ts`: `_routeIndexes` matcher (index + params, no `RouteMatch`/URL copy); production module cache per route; lazy `LoaderEvent` dependency tracking; assignment-built render input.
- `libs/router/server/app.ts`: assignment-built `DocumentInput` / render options, `universalOf` cache, sync `head()` when modules are loaded.
- `libs/router/shared/head.ts` `rankMerge`: sorted fast path, lazy Maps.
- `libs/runtime/router.ts` exports `compilePattern`; `libs/runtime/server-router.ts` adds `_routeIndexes`.

Handler microbench (`/page?rows=0`): 12850 → 10658 B/req, 5.75 → 4.34 µs.

## Findings
- Fixed router cost is a long tail of small items; peak RSS is dominated by warmup spike, V8 page pool and promotion of in-flight objects, not live data.
- Dropped (CPU/TTFB/contract cost, data kept in report): larger BodyWriter FLUSH_AT / QUEUE, direct body, `_listRows` array-join.
