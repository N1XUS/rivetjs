# Masonry suite (2026-10-11)

`apps/dom-bench/masonry` (`build.ts` + `run.ts --samples 7`), Chromium (Playwright), cross-origin isolated, fresh page per sample, scenarios interleaved, warm-up discarded. Host: MacBook, AC power, 1-min load 6.2 → 6.5 during the run (bench lock `MASONRY`, maxLoad 8). Raw: `2026-10-11-masonry.json`.

Lanes:
- **rivet** = `@rivetjs/cdk/masonry` at `perf/ssr-beat-razor` (after 66815f2b). `exact` = known ratios with 3 container breakpoints (masked max() CSS); `exact-3` = one fixed column count (plain calc); `justified` = justified rows (`rowHeight` 200, 5 breakpoints: 0 + the then-fixed splits 480 / 768 / 1024 / 1440); `measure` = unknown sizes (`reflowMeasured`: one read phase, one write phase); `virtual` = Virtualizer + `MasonryLayout`, 10k items.
- **vanilla** = hand-written algorithm equivalents, not the libraries: CSS `column-count`, react-masonry-css round-robin columns, masonry.js measure + absolute placement.

Ops (ms, median): `mount` 1000 tiles at 1000 px incl. forced layout; `resize` 1000 → 1300 px (3 → 4 columns) incl. forced layout; `resizeLayouts` = CDP `LayoutCount` of that resize plus the frame after it (observer-driven work); `toggle` = live `getSpan` of item 0 1 → 2 columns (one incremental relayout, `motion={false}`), incl. forced layout; heap after GC.

Server render (node, `libs/cdk/tests/masonry-ssr.test.ts` cost case, median of 15, same lock window): 1000 items columns 9.24 ms, justified 12.61 ms (plain static grid 0.24 ms).

Reading:
- Rivet exact / justified pages are server-placed: on a real page the client mount above is not paid (resume adopts the server HTML; the resumed story asserts 0 DOM mutations at the same width). The mount column measures a client-side render of the whole grid (component + style objects), which the vanilla lanes skip (they write static markup).
- Resize: server-placed layouts reflow by CSS alone — one layout pass, no script. Cost grows with breakpoint count (max() terms per property): exact-3 4.7 ms < exact 6.6 ms < justified 13 ms. Measured mode: 2 layout passes (observer rAF write + forced read), vs 3 for the masonry.js algorithm (reads per item).
- Toggle (item 0 = worst case: everything after it re-places): 8–25 ms incl. style recalc of every moved item; later items re-place less (incremental from the changed index).
- Not a win yet: client mount of 1000 exact items is 3× the static-markup lanes (style objects per item; the grid variables are registered as `@property` by the component on client render); justified resize is 13 ms at 6 breakpoints. Candidate: fewer max() terms per item (merge breakpoints whose terms coincide).

Reading:

- Next candidates: fewer terms per item (share per-row terms through row-level custom properties instead of per-item max()), cap splits by default at a typical page max width.

## Fix round 2 (2026-10-12): toggle profile

Target re-baselined (review 2): justified = "with `maxWidth` ≤ 1400" — resize 9.3 ms is accepted as is; no per-row custom properties (ruling M3). Toggle split with CDP: unminified build (`build.ts --no-minify`), 1 000 items at 1000 px, 20 warm-up toggles, then 40 toggles of item 0 (each: `toggle()` → forced `offsetHeight`), CPU profile at 50 µs + `Performance.getMetrics` deltas, bench lock `MASONRY`. Per toggle, median, ms:

| lane | total | script (`toggle()`) | style recalc | layout | `setProperty` (native CSS parse) | style binding (`_applyStyle`, `unsafeStyle`, `_styleProp/_styleValue`) | style strings (`geometryStyle`, `linear`, `across`, `sameStyle`) | placement (`placeJustifiedRun` / `placeColumns`) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| exact | 11.3 | 6.7 | 4.1 | 0.37 | 3.2 | 1.6 | 1.0 | 0.08 |
| justified | 25.3 | 13.5 | 9.9 | 2.1 | 7.3 | 3.1 | 1.8 | 0.07 |
| justified max | 17.8 | 9.3 | 6.4 | 2.2 | 4.9 | 2.2 | 1.2 | 0.05 |

Items rewritten per toggle (style text differs): item 0 → 1000 / 1000 in every lane, item 500 → 500–509. Average inline style: exact 300 B, justified 682 B, justified max 446 B.

Reading:
- Placement is < 1 % of a toggle. The cost is writing + parsing + recalculating the long `max()` values of every moved item: `setProperty` 28–29 %, recalc 36–39 %, string build 7–9 %.
- Per-item style string cache: unchanged items already keep their style object (no write); every rewritten item has a different `top`, so a "same string → skip" cache skips nothing. Prototype of the broader variant (skip unchanged properties inside a rewritten item, `_applyStyle` keeps the previous value per property): justified 25.6 → 25.3 ms (−1 %), justified max 18.1 → 18.0 (−1 %), exact 11.5 → 10.7 (−7 %). Below the 20 % bar: not implemented.
- `unsafeStyle` (runtime style sanitizer: lower-case + regex over every value) is 1.9 ms of the justified toggle (14 % of script) on 682 B values: a candidate for a runtime fast path (no semantic change), outside the masonry lane. Done 2026-10-12 (STYLE-FAST, `libs/runtime/style.ts`): ASCII values are tested as written by one case-insensitive regex that allows control / space runs inside tokens (same decision as the rule, fuzzed; non-ASCII keeps the rule). Interleaved A/B, 10 samples, load 8–11: justified toggle script 13.04 → 11.67 ms (−10.5 %), justified max 9.43 → 8.45 (−10.4 %), toggle total −4 % / −6 %, exact toggle −10 %; style-heavy update (1000 × 6 properties) script 2.46 → 1.89 ms (−23 %); server `_style` over masonry-like objects 1.01 → 0.52 ms / 1000 (−48 %). A bounded value cache on top: −1.6 / −4.5 % more on masonry script, +21 % on the style-heavy update (Map churn on fresh values) — not landed.
- Remaining lever = term count per item (breakpoints): `maxWidth` 1400 cuts the toggle 30 %, `maxWidth` 768 (2 breakpoints) further.
