## Derived model, server side (lane DERIVED-S, 2026-10-21)

- Base `b3d30103c` + DERIVED-S items 1–3: derived `<For>` rows from one list tape (`_rFor`, ABI 9), `Root` payload `x` copy (V8 JSON fast path), non-JSON loader data through `_rData` (resume table, RV2107). Lanes on `/resume`: `rivet-resume` (serialized, default build) and `rivet-derived` (`vite.derived.config.ts`), one image `rivet-ssr-bench-node:derived-s` built from the lane snapshot.
- Host: macOS arm64, 14 cores, Docker 10 vCPU VM; other lanes (DERIVED-C Chromium probe, LAZY-FLIP / PPR fuzz) and non-Rivet containers running. **Host load (1-min) was 9–37 for the whole run** (max per cell below; R5 ran at 5–7): absolute numbers are inflated against R5 and only the interleaved `rivet-resume` / `rivet-derived` comparison of this run is meaningful. Tuned GC, node generator, 1 CPU / 512 MiB per lane.
- Commands: `RIVET_BENCH_NODE_IMAGE=rivet-ssr-bench-node:derived-s docker compose -p rivet-derived-s -f apps/ssr-bench/compose.yaml --profile variants build rivet-derived`, then `RIVET_BENCH_NODE_IMAGE=rivet-ssr-bench-node:derived-s SSR_BENCH_PROJECT=rivet-derived-s SSR_BENCH_PORT_PREFIX=187 python3.12 apps/ssr-bench/benchmark.py --skip-build --frameworks rivet-resume,rivet-derived --rows 100,1000,5000 --concurrency 1,10 --duration 10 --warmup 3 --repeats 3`.

- `derivedTail` was 3–4× too slow because the router handler's shared empty `byURL` (`x`) is a frozen array, and a frozen array takes the whole `JSON.stringify` off V8's fast path (microbenchmark: 0.26 → 0.07 ms per 94 KB payload). Fix: codegen `x: [...input.byURL]`.
- Open: derived GC self time stays above serialized (224 vs 130 ms) — the per-boundary record objects + the payload copy kept for the tail; not pursued here.
