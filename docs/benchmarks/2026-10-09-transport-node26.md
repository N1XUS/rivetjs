# Fair comparison — 2026-10-09 (Node 26 + lean h2 data client)

Generated by `apps/ssr-bench/fair-report.ts` from the runs listed under Inputs. Every number below is a median over ≥3 interleaved repeats with the trial range as subscript (min–max).

## Methodology

- **SSR** (`apps/ssr-bench`, Docker): every lane 1 CPU / 512 MiB, same gRPC backend (2 CPU), same DTO, strict validation of every row/field (sampled strictly every 32nd response + length checks). Node load generator `loadgen/` v2 (sha `feca615ea273`), 10 s measured after 3 s warmup per trial, 3 repeats with rotating lane order, 10 s unrecorded prewarm per lane (JIT tiering). Closed loop c=1/10/100.
- **GC profiles (B2)**: identical for every Node lane. `tuned` = `--single-threaded-gc --max-semi-space-size=8` (Razor: `DOTNET_gcConcurrent=0 DOTNET_GCgen0size=0x1000000`); `default` = runtime defaults for everyone. Container commands are recorded per run (results.json metadata.provenance.commands).
- **Like-for-like classes (B3/RA3)**: *static* — `rivet-compiled` (Rivet compiled JSX, no resume data) vs Razor and Solid 1 compiled `hydratable:false` + `renderToString`; *resumable/hydratable* — `rivet-resume` (`/resume`: file route + nested layout with state, keyed `<For>`, per-row click handler + reactive attribute + `<Link>`, resume state) vs Solid 1/2 (`hydratable:true`, hydration keys) and Qwik 1/2 (container state). Peers render the same page without handlers, so the resumable comparison is conservative for Rivet. `rivet-router` (router + resume render, no handlers) and `rivet-for` are shown for attribution.
- **Verdicts (B4)**: WIN/LOSE only for a ≥3% median gap with non-overlapping trial ranges; else TIE (`apps/dom-bench/verdict.ts`).
- **Escaping (B5)**: `--strings` variant — every field is text, field 3 of each row (10%) is `<b>"N"</b> & 'é€漢字𝄞'`; the validator compares exact characters after HTML parsing (any valid escaping accepted, raw markup rejected).
- **HTML bytes**: mean successful response body bytes (chunked framing excluded).
- Machine: 2 input file(s); host see results.json metadata.

## Notes (hand-written; appended by `fair-report.ts --notes`)

### What changed in the harness (2026-10-09, every Node lane)

- **F0 — runtime:** `apps/ssr-bench/Dockerfile.node` moved from `node:24.14.1-bookworm-slim` (V8 13.6) to digest-pinned `node:26.11.1-bookworm-slim` (V8 14.6), for the build stage and every Node lane (Rivet, Solid, Qwik, router; Bun / Deno lanes copy the same bundles). Razor stays on .NET 10. The load generator image (`Dockerfile.loadgen`) stays on Node 24 so its source hash and provenance are unchanged.
- **F2 + F3 — data client:** `apps/ssr-bench/services/content.server.ts` no longer uses grpc-js / proto-loader. It is a lean unary gRPC client over `node:http2`:
  - one persistent session (16 MiB receive window), hand-framed `PageRequest`, `grpc-timeout` 15 s;
  - `grpc-status` / trailers-only errors, abort via `signal`;
  - the static `page-decoder.ts` runs once in the stream's close handler, outside any call-state object chain.
  - Same proto, same request contract, same wire bytes from the backend, same strict validation.
  - Same class of client as Razor's Grpc.Net.Client. `server.ts` and the router app both import this one module, so every Node lane gets it.
- **Rejected:** a Rivet-only byte-text representation of decoded strings (PERF-TRANSPORT F1). The harness gives no lane its own data path.
- Findings and prototype: PERF-TRANSPORT (scratchpad). The probe scripts and logs live in the IMPL-TRANSPORT scratchpad.
