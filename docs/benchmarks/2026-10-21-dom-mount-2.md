# DOM mount 2: protocol fix, competitor re-store, allocation profile (lane DOM-MOUNT-2, 2026-10-21)

Follow-up of [`2026-10-20-dom-mount.md`](2026-10-20-dom-mount.md) (5000-row mount LOSE vs Solid = V8 incremental-marking finalization delay after run.ts's forced GC). Base `e14ab639`, macOS arm64 (Apple M4 Pro), Playwright Chromium **153.0.8010.12** headless shell, cross-origin isolated; other agent lanes ran tests on the host (1-minute load noted per run). Raw numbers: [`2026-10-21-dom-mount-2.json`](2026-10-21-dom-mount-2.json).

## Result

- **Protocol `rewarm-2026-10-21`** (run.ts, mount-quick.ts): warm-up mount + dispose → settle → forced GC (heap baseline, unchanged) → **one unforced mount + dispose** → settle → one macrotask → timed mount. No marking cycle inside the timed mount on Rivet / Solid 1.9 / Solid 2 (trace below).
- **Competitors re-stored** (`apps/dom-bench/competitors.json` `dom`, provenance browser / protocol / date / load): React 19.3, Solid 1.9.15, Solid 2.0.0-rc.13, same Chromium build as the Rivet run.
- **Scoreboard**: `dom 1000 mount` and `dom 5000 mount` = **TIE** (were LOSE); every update / heap row WIN; remaining dom LOSE = bundle gzip vs Solid 1.9 (accepted).
- **No allocation diet landed**: Rivet already allocates 38 % less per row than Solid 1.9; byte-slope ablation shows the reachable runtime-owned savings sit inside noise.

## Why the yield alone does not work

- V8 postpones marking finalization ("Delaying GC via stack guard", ≤ 50 ms overshoot) when its *average time to an incremental-marking task* ≤ 50 ms. That average moves only when a marking task runs; a yielded macrotask after the forced GC runs none, so the decision keeps following the page's earlier task history.
- `mount-quick.ts --gc-trace` (V8 `--trace-incremental-marking --trace-gc --expose-gc`, renderer stdout to a file, window = minor `gc()` markers around the timed mount), 5 mounts per cell, load 3–6. Cell = "Delaying" decisions / mark-compacts inside the timed mount:

## Allocation per row (item 3)

CDP `HeapProfiler.startSampling` (64 B interval, objects collected by minor + major GC included) over one timed 5000-row mount under the new protocol, 2 mounts per lane:

| lane | bytes / row (10 fields) |
|---|---|
| Rivet | 5437 |
| Solid 1.9 | 8804 |
| Solid 2 rc | 10721 |

Rivet per field (unminified lane, inlining off for attribution, ≈ 545 B): Field body (node-walk wrappers, handler closure + context) 133, `ArgNode` binding record 96, text-binding string (compiled template literal) 89, `signal` (Source + bound getter + 3-slot property array) 84, `setAttribute` number → string ×2 59, `_on` expandos 20, template root clone 18, props + `Array.from` callback 16, row share (section, `_t` slot, flatten / assign arrays, row binding) ≈ 55. Runtime / reactivity own ≈ 190 B; the rest is browser wrappers and compiler-emitted closures / strings (compiler = Rust, out of scope).

- CPU profile of the same mount (ns / field): `cloneNode` 449, GC (scavenges only now) 445, `insertBefore` 336, `setAttribute` 280, Field body 213, `_bindingEffect1` 62, `_tx` 43; bundle JS frames (adapter + runtime + reactivity, incl. inlined signal / wrapper creation) ≈ 25 % of mount self time.
- Byte slope: `ArgNode` padded with 5 fields (+20 B / field, +3.7 % bytes) → mount +1.4 % (1000) / −2.2 % (5000), load 4.2–5.4 = noise. A diet of the reachable size cannot move mount measurably.
- Signal without own properties (`set` / `update` inherited from a custom prototype of `read`): `Function.prototype.bind` leaves V8's fast path when the target's prototype is not `Function.prototype` — 42 vs 11 ns per signal (Node 26 microbench). Rejected.
- Not re-measured (2026-10-20 rejections): placeholder-free text bindings, `_on` / expando ablations, construction-document cache, shape pins.

## Rulings

- Protocol: yield alone (brief option b) verified ineffective → unforced re-warm cycle after the baseline GC — keeps the forced GC + heap baseline, removes the marking cycle from the timed mount for every non-React lane — cost if wrong: the mount row stops reflecting a cold post-GC heap (real first navigations do start near an empty heap); the old protocol stays available as `mount-quick.ts --rewarm 0 --yield 0`.
- Protocol id in results + `competitors.json`; scoreboard refuses a mount comparison across ids — cost if wrong: a stale store shows n/a instead of a verdict.
- Discarded the round with a load-9.0 trial; stored 3 rounds (load ≤ 7.7) — cost if wrong: 9 instead of 12 trials per lane.
- No allocation diet landed (slope inside noise, signal diet slower) — cost if wrong: ≤ 1–2 % mount left on the table.
- React 5000 trials exceed the 3 GB tree-RSS cap (renderer ≈ 2.8 GB, tree 3.6–4.1 GB summed RSS): ran 4 rounds once for the re-store, no further React 5000 runs — cost if wrong: cap breached for ≈ 30 s per round.
