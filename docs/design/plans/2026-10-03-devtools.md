# DevTools P0 + P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development) to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** P0 (hook, `_debug`, reactivity + DOM façades, hot/DEV events, zero-cost gates, suites re-run under `development`) and P1 (`@rivetjs/devtools`: page agent + prebuilt Rivet UI on `vite serve`, docked iframe + pop-out; Components, Signals, Updates, HMR, Errors panels).

**Architecture:** Instrumentation lives only in modules that production resolution never reaches: `development` export conditions select façades (`libs/reactivity/dev.ts`, `libs/runtime/dev/dom.ts`); `hot.ts` and `dev/on.ts` emit through `DEV` (`#dev`, folds to nothing in production). Façades report to a global hook (`globalThis[Symbol.for("rivet.devtools")]`) created by the page agent (first dev script). The agent keeps weak id maps, walks owners with `_debug`, previews values without invoking user code, draws overlays in a shadow root, and talks the spec's protocol to the UI (prebuilt Rivet app, own realm) over `MessageChannel` (docked iframe) or `BroadcastChannel` (pop-out). `rivet()` (compiler Vite plugin) serves the UI at `/__rivet/devtools/` and injects the agent; the router plugin adds it to its dev scripts.

**Tech stack:** TypeScript (erasable syntax, Node 24 type stripping), Vite 8.3.2, rolldown 1.2.12, esbuild 0.28.2, node:test, Playwright Chromium.

**Spec:** [docs/design/specs/2026-10-03-devtools-design.md](../specs/2026-10-03-devtools-design.md)

## Global constraints

- Production resolution byte-identical: scratchpad gates `runtime-hash-rolldown.mjs` (existing lines identical; new entries allowed), ssr-bench lanes hashes, oracle 227/227, `npm run typecheck`, full `nx run-many -t test`. Run before every commit.
- No edits to `libs/reactivity/index.ts`, `libs/runtime/dom.ts`, `libs/runtime/server.ts` (hot files). `hot.ts` edits only as `DEV && DEV.emit(...)` / `if (DEV) ...` (verified to fold away).
- Façades return the real primitives (identity, `_inspect`, `_trackReads`, resume encoding unchanged); never add observers; level checks at call time.
- Agent never imports app or framework code, never calls getters on user objects, never throws into the page (internal failures → `error.agent`).
- UI never touches the page realm except through the protocol.
- Match surrounding style: dense short doc comments, no prose blocks.

## Decisions (spec vs code; conservative picks)

- **Hook creation:** the page agent creates the hook; façades/`DEV.emit` only use an existing hook (spec: "whichever dev module runs first"). Keeps SSR (dev server), `node --conditions=development`, `devtools: false` pages and development builds without `RIVET_DEVTOOLS=1` fully inert with one rule. Agent is the first module script, so the hook exists before app modules evaluate.
- **`_debug` location:** `libs/reactivity/debug.ts` (subpath `@rivetjs/reactivity/debug`), not `index.ts`: an extra export in `index.ts` changes the `@rivetjs/reactivity` and `hot-reactivity` entry bundles (entries keep all exports). Field coupling moves next to `index.ts`; `tests/debug.test.ts` pins it. Getter → internal node through the getter's own symbol properties (`rivet.signal` / `rivet.computed` descriptions).
- **Hot names (D5):** no `hotId` export (would change the `@rivetjs/runtime/hot` bundle); `hot.register { id, wrapper }` lets the agent name wrappers.
- **Façade events kept minimal for P1:** `sig.create/write`, `node.create/run`, `batch.start/end`, `comp.mount/unmount`, `root.mount/unmount`, `dom.update`. `bindEvent` / `For` / `Async` / `lazyComponent` / `clientOnly` wrappers (D1 event timing, row counts, async states) move to P3 (Async panel).
- **Q11 self-reference imports:** with P2 (only resumed pages need them).
- **Signals without `bindModel` highlight:** its effect reads the model signal internally; highlight covers `bindChild`, `bindAttribute`, `bindRCData`.
- **Stacks:** captured as `Error` objects (formatting deferred) while `hook.stacks` is on: on when the panel is connected, and from page start when the panel was open before a reload (sessionStorage).
- **UI build output:** `libs/devtools/dist/ui` (gitignored like every `dist/`), built by `nx run devtools:build`; `devtools:test` and the router/playground tests that open the panel depend on it. Missing build → `/__rivet/devtools/` answers 503 with the build command.
