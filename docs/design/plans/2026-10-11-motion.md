# @rivetjs/motion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Motion's (motion.dev) DX on Rivet signals as `@rivetjs/motion`:
- `<Motion.div initial animate exit transition variants whileHover whilePress whileFocus whileInView layout>`, `Presence` / `PresenceFor`, scroll / in-view / reduced-motion primitives, typed hybrid `animate`;
- server-rendered `initial` styles, resumed pages animating without hydration;
- 0 B for apps that do not import it.

**Architecture:**
- Engine: `motion/mini` (WAAPI) for every declarative prop. Independent transforms map to CSS `translate` / `scale` / `rotate`. Hybrid `motion` only through `@rivetjs/motion/animate`.
- Feature-carrying props (`layout={layout}`) instead of `LazyMotion`.
- Presence is built on kit `createTransition` (kit gains `useTransitionScope` + `hold`).
- Layout = one FLIP core `@rivetjs/cdk/flip`, extracted from masonry, with pluggable drivers: house `Motion1D` by default, Motion WAAPI via `layoutDriver`.
- Embla physics keeps gestures / drag.

**Tech Stack:** TypeScript (Node 26, vitest node + Chromium browser projects, Playwright via `libs/runtime/tests/resume/harness.ts`), `motion@14.1.0` (MIT, peer `>=14.1.0 <15`), `@rivetjs/reactivity`, `@rivetjs/runtime/dom`, `@rivetjs/kit/transition`, `@rivetjs/cdk/motion`.

**Spec:** [`docs/design/specs/2026-10-11-motion-design.md`](../specs/2026-10-11-motion-design.md) (D1–D17; rulings Q1–Q3 in §9: CSS entrance, no `drag`, overlay springs via a motion token).

**Status:** T1 done (scaffold + bytes, see the T1 commit). T3+ wait for the lead's brief → implement → review loop.
