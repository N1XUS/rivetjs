# Compiled runtime milestone

Rivet now has separate server and DOM JSX/TSX compiler targets. TypeScript authoring uses JSX preserve and `jsxImportSource: "@rivetjs/runtime"`; compilation is required for runtime JSX. Functions are ordinary components, and native markup is hoisted without allocating a native-element VNode graph.

The browser target caches parsed templates per Document/context, clones once, and saves binding destinations. Scalar changes update retained Text nodes or native properties. Owned effects, event listeners, models, component branches and keyed rows dispose together. Keyed `For` preserves row identity on moves and same-key replacement; native `moveBefore` additionally preserves focus where available. Context follows logical owners rather than repeated DOM ancestry searches.

`@rivetjs/reactivity` provides signals, computed getters, effects, batching, cleanup and scoped context. `@rivetjs/runtime/dom` provides mounting, models and structural Provider/For helpers. `@rivetjs/runtime/server` supports escaped synchronous rendering and async ordered streaming, writer backpressure, cancellation and response-owned Provider/For output. Owned server regions are consumed once; recreate them for each response. Model/event expressions retain author order on both targets.

This milestone supports full CSR of the tested JSX subset, including SVG, MathML, foreignObject and table contexts. Dynamic textarea/title text has independent bindings; failed reads immediately release partially constructed components. Static textarea newlines are preserved by direct scalar construction. Unsupported spreads, script/style JSX, raw HTML and structural RCDATA children receive diagnostics. Supported two-way models are text-like input values, checkbox checked and textarea values.

## Effect scheduling
- Writes mark effects; the flush runs them synchronously after the outer `batch` (or the write itself).
- Owners first: a queued effect whose owner effect is also queued/dirty runs after it — the owner's re-run disposes it (no "zombie" child reading values that remove it, e.g. `batch(() => { v.set(null); show.set(false) })` under `{show() ? <p>{v()!.x}</p> : null}`) or leaves it alive to run once with fresh values.
  - Owner walk only while an effect owning children is queued; leaf-only flushes cost what they did.
  - Children created later under an already-queued effect through `runWithOwner` are not ordered.
- Failures: every queued effect still runs; the first error is rethrown, the rest are reported — production: `reportError` per error (else `console.error`); development (`development` condition): one `AggregateError` listing all.
- Event handlers run in a `batch` in CSR (`bindEvent`) as after resume (`dispatch`): two writes in one handler, one effect run.

## Async and demand loading

Both runtime targets now provide explicit `Async`, `lazyComponent` and `clientOnly` helpers. Server boundaries await data in output order and retain request ownership through writer acknowledgments. Server `load` runs when the boundary is constructed (sibling loads start together; request abort is linked when traversal reaches it), so resumable renders record its synchronous signal reads. Browser boundaries cancel obsolete loads, ignore late results and dispose replaced branches. Ordinary Promise children still require an explicit Async boundary.

`@rivetjs/runtime/async` exposes `captureAsyncContext()` for explicit context reads and synchronous owned work after await. Context is never held globally across an await. `@rivetjs/runtime/lazy` exposes `lazyFunction()`; it shares successful module loading, retries failed imports and never shares invocation results. Each wait can be cancelled independently.

For server compilation, supported inline `clientOnly` imports are erased from the server graph. Unsupported indirect forms receive diagnostics. The server renders fallback without invoking browser module code; the DOM target loads the component when mounted. Strict types preserve required component props across lazy helpers.

Independent review verified ordered thenable admission, rejecting siblings, writer acknowledgments, reentrant async replacement/unmount, once-only cleanup and client-only graph erasure. Single-pass escaping and scalar dispatch also passed output-parity and ownership checks. These rendering optimizations have not yet been measured in a rebuilt Docker comparison.

## Error boundaries

- `ErrorBoundary({ fallback: (error, reset) => …, children: () => … })` from `@rivetjs/runtime/dom` (retargeted to `/server`), next to `Async`. Children: plain JSX (`<ErrorBoundary fallback={…}><Page /></ErrorBoundary>`) or a function child — the compiler thunks plain children (and a `children={…}` attribute) of a named `ErrorBoundary` import from `@rivetjs/runtime/dom|server`, like `Provider`; a single function-literal child is kept as is. Namespace access (`rt.ErrorBoundary`) is not thunked: pass a function child.
- Reactivity: `catchError(fn, handler)` — fn's synchronous throw and later effect/computed/cleanup failures of its descendants during a flush go to the nearest handler (a throwing handler forwards up); handled failures no longer reach the `.set()`/`batch` caller; unhandled ones behave as before. `_handleError(error, owner)` (runtime ABI) routes a late error to a captured owner. Cost: one owner walk on the error path only (handler = owner context fields under a private token, no new field); +114 B min in bundles that flush.
- DOM: catches synchronous render errors, binding/effect failures inside (also ones an event handler's write triggers) and `Async` rejections without their own `error` (routed through `_handleError` from the rejection microtask; no boundary → thrown there as before). First error wins until `reset()`, which disposes the fallback and renders children again. Not caught (React model): errors thrown by event handlers themselves, errors of `fallback` itself (→ outer boundary).
- Server: children evaluate inside the boundary; their output renders into a buffer (sink swap; traversal is sequential) and is written once complete. Any failure — sync, a deferred child, an awaited `Async` rejection without `error` — renders the escaped `fallback(error, reset)` in place; none of the failed content reaches the response, siblings render normally, status is unchanged (the router decides). Request abort is never caught. Cost: only content inside a boundary is buffered (one `[CAUGHT]` brand check before the function branch of the renderer; `renderToString` 1000-row microbenchmark unchanged within noise).
- Resume (`renderResumable` / `resumableToString`): a boundary claims its region site (the `<ErrorBoundary>` component site), which is therefore always a region — its captures must be resumable. A failure drops everything the content recorded (handlers, bindings, regions, effects, streamed boundaries). The fallback's `reset` serializes as entry kind `reset` (region id); in the browser it re-creates the region through its DOM symbol, so the DOM boundary renders children there. Inside a `Show`/`Switch` branch the boundary claims the site around the `Show` (reset re-creates the whole `Show`) and that branch is never adopted. No region site (page root, `For` row): `reset` is inert and not resumable.
- Streaming: the content scope is a logical region linked to the boundary region (`a` entry `[region, content, region, 3]`, not listed in `data-stream`). A streamed `Async` inside a boundary that sits directly in its site and fails (load without `error`, `error`/children render failure) writes the boundary's fallback as a segment for the boundary region (`<template data-a=region>` + patch with `[region, content, region, 1]` and every unwritten inner segment retired with status 1); other segments inside are dropped. Deadline/cut-stream continuation (status 2) is unchanged.
- Limits: browser-side failures of resumed bindings/handlers inside a server-rendered boundary (before the region is re-created in the browser) are reported through `rivet:resume-error`, not routed to the boundary.
