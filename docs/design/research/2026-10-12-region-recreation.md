Scope: resume fuzz T31 pins `recreated` (cdk `/region-state-repro` ×3 owned by runtime; cdk autocomplete / grid-list / lightbox / selection-indicator(-groups) / slots / tag-group, ui action-bar grid / avatar-group / data-grid / resume surface / segment indicator / toggle-buttons / tag-group). ## Mechanism

A resumed page runs no component code at load. Each server read of a signal is recorded on its *site* (text, attribute, region, row). On the first change of that signal the browser runs the site's DOM symbol:

- **A. No own region (component re-run).** Reads that are not their own site — a component-root `Show` / `Switch` condition, reads through a projection (`globalDOMProps(props)`), destructured props (P4), site-less calls — attribute to the nearest enclosing region scope (`server-resume.ts` region scopes; safety net in `docs/guides/resumability.md` "site-less call"). The first change re-runs that region's symbol: the whole component is rendered again in the browser (`_insert`), its server nodes are dropped (focus, scroll, resumed bindings and handlers inside go with them), its locals start fresh unless created with `_regionState` (`libs/reactivity/CLAUDE.md`). Pins: autocomplete ListBox, selection-indicator, slots Input, ui avatar-group, resume surface, toggle-buttons, segment indicator.
- **B. For row adoption.** A re-created region's browser `For` adopts the server rows (`dom-adopt.ts`) only while a row's item is identical / equal in data and its read index is unchanged; reads of the row's `row()` / `index()` getters are not resume sites (guide "For inside a region", gotcha "getter-only cell is plain HTML"), so a row whose item changed is re-created even when its key is the same — a client render keeps the keyed row and updates the getter-bound text. `/region-state-repro` is exactly this: `<For each={() => [String(second.count())]} by={() => "row"}>{(key) => <span>{key()}</span>}</For>` — the item goes `"0"` → `"1"`, the key stays `"row"`; CSR keeps `#nested-row`, the resumed page replaces it (the `_regionState` values themselves adopt correctly: `#nested-text` updates in place). Flag-2 rows (own render read signals, RESUME-KEEP-ROWS) are the same family. Pins: `/region-state-repro` ×3, grid-list rows, tag-group tags, lightbox slides, data-grid cells, action-bar grid rows.

## The reverted root region (8c9caaf3 → 61e803bf, RESUME-BUGS 2026-10-09)

`resume.rs scan_root_structural` made a component's returned `<Show>` / `<Switch>` a Region site (`_rBind(id, () => Show({…}), captures)`): the first change re-ran only the Show over its captures. Reverted 2 h later because components rely on their body re-running on a re-creation:

- body-side client setup next to the root Show never ran: cdk SharedElement (`client` flag, enter / exit effects, `onCleanup` snapshot → selection-indicator lost its animation, keyboard / radio / toggle cases timed out), ScrollAreaScrollbar (`_regionState` activation → hover scrollbars never showed, extra ScrollAreaCorner chunk), TabPanel (render-function panels → tabs case timed out);
- the region captured the body's locals, some unserializable: cdk FieldError under RadioGroup failed the render (`capture #0 function is not serializable`), cdk fields-ssr / radio-group / dom-events-forms / widgets / cdk-docs prerender.

Recorded gap (guide): a root region needs an opt-in or a way to keep such body code.

## Candidate designs

| # | Design | Browser cost | Server cost | Clears |
|---|---|---|---|---|
| 1 | **Row getter sites.** Compile `row()` / `index()` reads in a `For` row render as row-scoped sites: the server records them under the row region (per row: item ref already encoded; + one text/attr marker per getter read); the browser `For` adopts a row whose item changed but whose key matched, re-points its item signal and runs only those sites. | runtime: adopt-with-new-item path in `dom-adopt.ts` + row item signal (est. +250–400 B min, `dom-adopt` chunk only, zero-cost for pages without rows); markup: +1 marker per getter read per row | per row: site records for getter reads (≈ text-binding cost: ~1 entry / read) | B: `/region-state-repro` ×3, grid-list, tag-group, lightbox, data-grid, action-bar grid (rows whose cells read only getters); flag-2 rows partly |
| 2 | **Opt-in root region** (`resumeRegion: "root"` component option / `// @rivet-region` pragma, diagnostic when the body has client-only setup or unserializable captures): the reverted 8c9caaf3 lowering, only where the author opts in; body client setup moves to `clientEffect`. | 0 B runtime (existing Region ABI) | one region entry + captures per opted component (≈ a Show region today) | A, per opted component: autocomplete, selection-indicator, avatar-group, toggle-buttons, surface, segment (cdk/ui lanes opt in + move setup) |
| 3 | **Adopting re-run.** The first change re-runs the component's DOM symbol in adopt mode over its server nodes (as `dom-adopt.ts` does for slots / lists / branches today) instead of inserting fresh nodes, with compiler-wrapped `_regionState` for body-local `signal()`s: body code runs (fixes the 8c9caaf3 breakage), nodes / focus / resumed handlers stay, locals continue from server values. | runtime: full-template adopt path (est. +1.5–2.5 KB min in the resume runtime; must stay out of non-resumed bundles); per component re-run CPU = a client render without node creation | `_regionState` records for every body-local signal (≈ +1 state entry each); no new markers (template walk) | A and B (adopted rows keep nodes): every `recreated` pin; also the "follows the re-creation" `missing` pins (slots, tag-group, data-grid) |

Recommendation: 1 first (bounded, runtime-owned, clears the 3 runtime pins + the row family); 3 as the general fix once its byte cost is measured against the zero-cost gate (compiler patch + runtime); 2 only as a stop-gap for a hot component. Measure with resume-bench (first-change latency) and size-report (`dom-adopt` / resume runtime rows).
