# Backend-heavy examples — design (2026-10-12)

- Status: **design only (lane BACKEND-EXAMPLES)**. Implementation waits for the user's "GO". Plan: [`../plans/2026-10-12-backend-examples.md`](../plans/2026-10-12-backend-examples.md).
- User directive (2026-10-12, verbatim): "another gap: no real backend-heavy exampels, like db/grpc/kafka/docker/workers/bg jobs".
- Scope: runnable reference apps (db, cache, queues, event streaming, RPC, realtime, object storage, containers) + the small router helpers they surface + a docs section "Backend recipes". No new heavy lib.

## 1. Gap + what "real" means

### 1.1 Today

- `apps/docs/examples/*` (~46): UI / routing snippets. Server ones (`mode: "server"`: `live-updates`, `login-form`, `guard-login`, `json-endpoint`, `server-load-inline`, `protected-pages`, `optimistic-like`) use in-memory module state (`visitors.server.ts`). Code-only in the docs (docs-kit lists them as not live).
- `templates/starter-server`: `load(…)` + `actions(…)` exports, `serve.js`, two-stage `Dockerfile`. No db, no compose, no worker.
- `apps/docs/content/guides/deploy/docker.md`: single-container image; no services.
- Result: nothing shows Rivet against a database, a broker, a worker process or a second service. Adopters evaluating "can I build my product on this" find no answer; competitors answer it (§2).

### 1.2 Definition of "real" (every example, no exceptions)

| Must have | Rule |
| --- | --- |
| Runnable app | Full Rivet app (`vite.config.ts` + `rivetRouter`, file routes, node adapter `serve.ts`), not a snippet. `npm run example:<name>` brings the stack up and prints the URL. |
| `compose.yaml` | Every external service (db / broker / object store / second service / worker) with `healthcheck`, `depends_on: condition: service_healthy`, `mem_limit`, named volumes, pinned image tags (digest in a comment). Examples with no external service (`sqlite-local`) have no compose. |
| Migrations | Versioned SQL migrations checked in (`drizzle-kit generate` output or plain `migrations/NNNN_*.sql`), applied by a one-shot `migrate` script / compose service, never at app import time. |
| Seed data | `scripts/seed.ts`, deterministic (fixed PRNG seed), sized to make streaming + pagination visible (10k rows where relevant). |
| Tests | `tests/*.test.ts` run with **no Docker and no network**: in-process fakes that run real code (PGlite, `node:sqlite :memory:`, Connect in-memory transport, `ws` on port 0) or thin ports with memory adapters where no in-process engine exists (Kafka, Redis). Plus one e2e (`tests/e2e.test.ts`, Playwright Chromium) against the built node adapter on fakes. |
| `.env.example` | Every variable, documented, safe dev defaults; `.env` gitignored; no secret ever committed; app validates env at startup (§4 G4). |
| README | What it proves, architecture sketch (ASCII), run (stack / fakes), test, deploy notes, "Files to read first", known limits. Embedded in the docs page (§5). |
| Rivet value shown | At least three of: loaders / actions with `*.server.ts` modules, streaming `Async` / `Suspense` for slow queries, live pages (`export const live = true`) or SSE over live data with resumable UI, `@rivetjs/forms` progressive enhancement (works with JS off), endpoints (`routes/api/*.ts`), guards + sessions, `invalidate(key)` / `depends`. Each example names its "one thing it proves". |

## 3. Where examples live (decision)

- **Decision: new top-level `examples/<name>/`** (not `apps/docs/examples/`).
- Why not `apps/docs/examples`:
  - docs examples are pages of the docs app (docs-kit "Example frames"), merged over `templates/starter-*`, built inside the docs build and run by its `test` steps; server-mode ones are already code-only. Backend examples need their own deps (drivers, Connect, ws), own `package.json`, workers, compose, migrations — none of which fit the merge-over-starter model.
  - docs build must not need Docker, must not install drivers, and must stay ≤ 3 GB RSS (1.5 GB today); 10 more apps inside it would cost build time for zero live value (they cannot run in a docs iframe).
- `examples/*` added to root `workspaces` (CI installs once from the root lockfile; versions pinned; dependabot sees them). Each example's `package.json`: `private: true`, `@rivetjs/*` as `"*"` (workspace), drivers pinned exact. Not copied by create-rivet (follow-up F6 decides overlays).
- Native addons banned in default paths (Node 26, no host toolchains): `node:sqlite` not better-sqlite3, `node:crypto` scrypt not argon2, KafkaJS not librdkafka, `aws4fetch` not the AWS SDK. Allowed only inside the example's Docker image if ever needed.
- CI: examples **never** start services. Per example `check` = `rivet sync` + `rivet-check` + `tsc` + client/SSR build + node adapter boot on fakes (`/healthz`, one page, one action) + `test`. Full stack only via `npm run example:<name>` (developer machine with Docker) and an optional manual workflow (`examples-stack.yml`, `workflow_dispatch` + weekly, non-blocking) that runs `compose up` + `smoke` per example on GitHub runners.

## 5. Shared infra

- `examples/_shared/` (not a workspace package; copied, never imported, so each example stays copyable):
  - `compose/` fragments (`postgres.yaml`, `redis.yaml`, `minio.yaml`, `redpanda.yaml`) with healthchecks + `mem_limit`; examples `include:` them (Compose `include`, v2.20+).
  - `wait-for.ts` (TCP / HTTP readiness with timeout, used by `migrate` and `smoke`), `env.ts` template (G4 until the helper lands), `pglite.ts` test helper (apply migrations dir, return drizzle db), `Icon.tsx` (lucide) template.
  - `scripts/examples/sync-shared.ts --check`: copies `_shared` files into examples that declare them (`examples/<name>/shared.json`), CI fails on drift (same pattern as `libs/mcp/ai/sync.ts`).
- `scripts/examples/`:
  - `run.ts <name>` (`npm run example:<name>`): checks Docker, `docker compose -p rivet-ex-<name> up -d --wait`, migrate + seed, build, start node adapter (`serve.ts`), print URL; Ctrl+C → `serve` drain + `compose stop` (volumes kept; `--reset` removes them). Refuses when another `rivet-ex-*` project is running (one stack at a time).
  - `check.ts [<name>…]`: no Docker; `rivet sync`, `rivet-check`, `tsc -p`, `vite build && vite build --ssr`, boot `dist` with `BACKEND=memory` (fakes), GET `/healthz` + `/` + one action POST, JS budget from the manifest, `.env.example` covers every `env` key, no `.env` tracked, compose lint (pinned tags, healthchecks, `mem_limit`, total ≤ 3 GB).
  - `smoke.ts <name>`: against a running stack: page, action, worker round-trip (job done / event projected / RPC answered), SIGTERM drain.
  - `list.ts`: names + metadata (from each `package.json` `rivetExample` field: title, proves, services, budget) → docs + MCP data.
- Nx: projects inferred from `examples/*/package.json` → `example-<name>:check`, `:test`, `:serve` (= `run.ts`, never cached, not in `run-many` defaults via `"tags": ["example"]` + CI excludes `serve`). Root scripts `example:<name>` generated by `list.ts --write` (or one `example` script taking the name; decided in T1).
- RAM / CPU: every compose stack ≤ 3 GB total `mem_limit` (Redpanda capped at 768 MB; Kafka KRaft rejected: ~1 GB+ JVM); one stack at a time (`run.ts` lock); `check` runs examples sequentially, vitest `--maxWorkers=1`, Playwright one browser.
- Secrets: only `.env.example` committed; `scripts/examples/check.ts` greps tracked files for `.env` + high-entropy strings; dev passwords in compose are `rivet-dev` style and named as such.

## 6. Framework gaps surfaced (follow-ups, with "do we need a lib" ruling)

| # | Gap | Today | Proposal | Ruling |
| --- | --- | --- | --- | --- |
| G1 | **Streamed loader data** (`defer`) | Loader data must be serializable now; slow parts need `<Async load>` in the component, which re-runs the query function on the client after navigation and cannot call `*.server.ts` code (stripped from the browser graph). Remix `defer`, SvelteKit streamed promises, Next RSC all stream server data. | Loader may return promises as values (`{ issues, stats: statsPromise }`); the resume encoder writes a pending cell, the renderer streams the resolved value into the `Async`/`Suspense` segment (`_detach` lifecycle already exists), the data endpoint streams NDJSON for client navigations. `<Async of={data.stats}>` reads it. | **Router + runtime change, no lib.** Own spec (`STREAMED-DATA`); E2 lands first with `<Async load>` over an endpoint and switches when G1 ships. Highest-value gap. |
| G2 | **Extra server entries** (workers, relays, CLI tasks) | Only the generated server entry is built; a `worker.ts` importing app `*.server.ts` modules must run separately (`node` type stripping, no Vite aliases / env / `?raw` transforms) and does not share chunks with the server build. | `rivetRouter({ serverEntries: { worker: "src/worker.ts", migrate: "scripts/migrate.ts" } })` → extra Rollup inputs in `vite build --ssr` → `dist/server/worker.js` sharing chunks; dev: `rivet run worker` via Vite's module runner (HMR restart). | **Router build option, no lib.** Small (build inputs + CLI subcommand). Needed by E4, E5, E9, E10. |
| G3 | **App lifecycle hooks** | `start()` / `closeOnSignals` drain HTTP; nothing closes db pools, stops consumers or reports dependency readiness (`/readyz` is "not draining" only). | `start({ ready?: () => boolean \| Promise<boolean>, onClose?: () => Promise<void> })` (`/readyz` 503 until `ready`, `onClose` after drain, before exit, bounded by `grace`); same on `serveUws`; fetch targets ignore. Worker side: tiny `onShutdown(fn)` in the same module as G2's runner. | **Node adapter options, no lib.** E4 proves it. |
| G4 | **Typed server env** | `process.env` reads scattered; nothing fails fast on missing vars; risk of importing env into a browser graph is covered only by `*.server.ts`. | `@rivetjs/router/env`: `defineEnv(schema)` (Standard Schema, like forms) → frozen typed object, validated at first import (startup), errors list every missing / invalid key; browser import = build error (same guard as `server-only`). | **Small router subpath, no lib** (≤ 1 KB, zero-cost when unused). Until then `_shared/env.ts` template. |
| G5 | **WebSocket upgrade route** | `serving.server.on("upgrade")` works but bypasses routing, guards, Host check, `trustProxy`, cookies; `close()` does not end sockets; uWS adapter has native WS unused. | Endpoint export `onUpgrade(event) => WebSocketHandler` (node: `ws`-free minimal RFC 6455 or peer `ws`; uWS native); guards + cookies run first; drain closes sockets with 1001. | **Router feature, own spec later** (decide after E8 measures; may stay "example pattern"). |
| G6 | SSE helper | Each SSE endpoint hand-writes `ReadableStream` + abort cleanup (`live-updates` example: 30 lines, easy to leak timers). | `eventStream(event, (send, close) => cleanup)` in `@rivetjs/router/sse` (retry / id / heartbeat / backpressure) + client `liveSource(url)` signal (lazy, closes on leave). | **Small router subpath, no lib.** Used by E5, E9, E10. |
| G7 | Dev HMR singletons | Vite SSR re-evaluates `db.server.ts` on edit → new pool per edit (connection leak in dev). | Document `globalThis` keyed singleton pattern; optional `devSingleton(key, create, dispose)` in `/server` (dev-only branch, zero bytes prod). | Doc first; helper only if ≥ 3 examples need it (they will: E2, E5, E6). |
| G8 | Per-route body limit / streamed uploads | Global `maxBody`; forms multipart 10 MiB cap; no streaming multipart to a sink. | Route export `maxBody` + `request.body` streaming documented for endpoints. | Router option, small. E7 JS-off path needs it. |
| G9 | `rivet build --target docker` | Template Dockerfile + docs page. | No new target: `create-rivet --deploy docker` overlay adds `compose.yaml` (app + healthcheck) + `.dockerignore` + `serve.ts` with G3 hooks. | **No.** Overlay only (create-rivet / nx `--deploy docker`). |

## 8. Risks

| Risk | Mitigation |
| --- | --- |
| Docs build time / RAM | Examples never built by docs; `::source` reads text only. Gate: docs build peak RSS unchanged ±5 % (measure before / after T17). |
| Root install growth (drivers in workspaces) | Pure-JS deps only; budget: total added `node_modules` ≤ 60 MB, measured in T1 and per example task; heavy optional pieces (Redpanda console, Caddy) are images, not npm deps. |
| CI without services | Fakes run real engines where possible (PGlite, `node:sqlite`, in-memory Connect, `ws`); ports + memory adapters only for Redis / Kafka / S3; optional manual `examples-stack.yml` catches adapter drift weekly. |
| Fake / real drift (PGlite vs Postgres 17, memory bus vs Kafka) | Same migrations on both; PGlite version tracks the compose major; smoke scripts assert the same behaviours the unit tests assert (shared `tests/contract.ts` run against both). |
| Secrets hygiene | `.env.example` only; `check.ts` secret grep; dev credentials obviously fake; README warns before deploy. |
| Driver / image churn (KafkaJS stale, Drizzle 1.0 RC, pg-boss majors, Connect v2) | Exact pins; compose images digest-pinned; dependabot group "examples"; each README "Versions verified" line with date; KafkaJS-shaped API keeps the Confluent swap trivial. |
| Native deps on Node 26 | Banned in default paths (§3). |
| Examples rot vs framework (breaking changes allowed) | Examples are in-repo consumers: `check` in CI → API changes must update them in the same change (root rule "update every in-repo consumer"). |
| Scope creep (10 apps) | Each ≤ 1.5k LOC; shared patterns copied from `_shared` with drift check; order lets the user stop after E1–E5. |
| Security of reference code | E3 reviewed against OWASP session guidance; rate limits + CSRF on by default; no `trustProxy` default; README "not production-hardened" list. |
