# @rivetjs/compiler/rust

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

The `rivet-compiler` crate (Rust 2024, oxc 0.75 pinned) built to `wasm32-unknown-unknown` as a raw module: JSON request in, JSON response out. Output lands at `../rivet_compiler.wasm` (committed, generated).

## Protocol (`src/lib.rs`)

- Exports: `alloc(len) -> ptr`, `dealloc(ptr, len)`, `run(ptr, len) -> ptr` (consumes the request buffer), `result_len()`, `panic_ptr()` / `panic_len()` (UTF-8 message of the last panic, `"<payload> (at file:line:col)"`, written by the hook `run` installs once; the trap itself is `unreachable`), `source_hash_ptr()` / `source_hash_len()` (X2: `RIVET_SOURCE_HASH` set by `build.sh`, empty otherwise). Loader: `../wasm.ts` (`call()`), one instance per process, recreated after a panic.
- Requests (`op`): `compile { source, options }`, `check { source, options }` (options arrive as raw JSON and are parsed per op: a bad option is an RV7001 diagnostic in the op's result shape, P4), `moduleFacts { source, filename, options? }`, `registerTable { id, table }` (i18n), `decodeHtml { text }`, `panic { message }` (loader self-test only). Response `{ ok }` or `{ error }`.
- `compile_json` builds `compile::Options` (defaults: target `server`, filename `module.tsx`, `serverListMounts` true, `domV2` false), runs `server_split` first when `serverExports`, and shapes the JSON (`code`, `diagnostics` (errors, each with `code` from `diagnostics::classify` + `severity`), `warnings?` (T10 fix 2: `Diagnostic.warning` entries, `severity: "warning"`; never suppress `code` — `compile.rs` checks `Diags::has_errors`), `map?`, `css?`/`cssClasses?`, `symbols?`/`scope?`, `serverExports?`/`serverImports?`).
- `check_json`: compiles every requested target with `check: true` (DOM with `dom_v2: true`, as production), merges diagnostics by (message, span) adding `targets`, assigns `RV` codes (`diagnostics::classify`; a warning keeps `severity: "warning"`), converts byte offsets to UTF-16; `sites` from the DOM compile.
- `resume`: `{ module?: string }` / `true` on (`module` defaults to the filename), JS-falsy off, anything else RV7001 (`resume_module`); `styles` validated by `styles_option`. Responses are built by moving values (`handle`'s `ok`, `Value::String(code)`): `json!` deep-copies a `Value` through `to_value`.

Named volumes `rivet-cargo` / `rivet-target` / `rivet-rustup` (env overrides `RIVET_*_VOLUME`, `RIVET_RUST_IMAGE`). No host toolchain needed; `Cargo.lock` is authoritative (`--locked`).

- After a rebuild: `npx vitest run --project compiler`, `node libs/compiler/oracle/check.ts`, `sh scripts/zero-cost/check.sh`, `NX_DAEMON=false npx nx run typescript-plugin:build` (copies the wasm into its dist). Commit the wasm with the Rust change.

## Invariants

- Zero cost: a change must not alter emitted code for sources it does not target — gate: `sh scripts/zero-cost/check.sh` identical before/after, oracle `239/239`. Intended deltas: update baselines (`--update`) and re-record affected corpus cases (`../oracle/CLAUDE.md`).
- Server and DOM compiles run the same resume analysis → symbol ids agree; byte-length-preserving rewrites (server split) keep spans valid for maps and diagnostics.
- `check` output never contains generated code. `compile` diagnostics carry the same `RV` codes as `check` (since H5).
- Resume subtree containment (`src/resume/bounds.rs`, CONTAIN-INDEX 2026-10-11, ported from codex/hybrid-resume-hydration): `Resumed::has_site_within` (server list eligibility) queries a lazy `OnceCell` of non-Props site + ref-cell spans sorted by start with suffix-minimum ends — O(n log n) build on first query, O(log n) per query, same inclusive bounds as the old linear scan (quadratic on big modules). `Resumed` must stay immutable after `analyze` (the cache never invalidates); DOM-only compiles never build it. Output unchanged. Bench: `node libs/compiler/tests/resume-analysis-bench.ts <before-wasm-dir> 12 lists`.
- List mounts (`.map` / keyed `<For>` rows): `width_scan` must count exactly the slots `walk_server` writes — class/style groups (`class`, `class:x`, `style`, `style:x`, via `styling::analyze`) are one slot each unless static; only `attribute()` slots become plan attribute entries (`_styleAttr` is a whole value). A mismatch is RV9001 at build time (regression test `tests/server-list.test.ts`).
- oxc crates pinned `=0.75.0`; `oxc-browserslist` pinned `=2.0.12` (newer breaks `oxc_transformer` 0.75).
