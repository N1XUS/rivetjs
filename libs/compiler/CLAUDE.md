# @rivetjs/compiler

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

JSX/TSX compiler (Rust/oxc → WebAssembly) with its TS API, Vite plugin, image pipeline and parity oracle. Lowers JSX to hoisted HTML + server slots (server target) or template specs + bindings (DOM target); resume = the derived model only (M6 2026-10-22: boundaries + keyed state; the serialized lowering, symbol modules and their codes are gone).

- `dev: true` — unknown prefixed keys warn at runtime (set by `rivet()` on the dev server when a contributor plugin exists).
- `styles: { scope, names, layer }` — css`` blocks → `css` + `cssClasses` in the result.
- `serverExports: true` — route module: exports that are module-scope `const`s initialized by a `@rivetjs/router` wrapper call (`load` `guard` `actions` `entries` `headers` `onRequest` `onGet` … `onOptions`; aliases / namespace members followed; any export name) plus re-exports from server-only modules (kind `?`) are checked and stripped from the DOM target together with code only they use (`rust/src/server_split.rs`; docs/guides/server-code.md). Output `serverExports` (names) + `serverKinds` (kind per name; also in `moduleFacts`). RV3007 (own statement / wrapper not a module-scope `const` initializer / duplicate kind / `export *`), RV3010 (untagged former magic name `serverLoad` … `onOptions`). Spec `docs/design/specs/2026-10-20-server-exports-design.md`.
- `sourcePackages: string[]` — `@rivetjs/*` packages with `"rivet": { "source": true }` whose components are user components (boundaries / keyed state) in resume mode; other `@rivetjs/*` are framework components; non-`@rivetjs` packages are always user components.
- `sourceMap: true` — adds `map`; emitted code must not change (tests/source-map.test.ts runs the whole corpus).

Option validation (P4): malformed options are an RV7001 `Invalid compiler option …` diagnostic, not a thrown `invalid request` — wrong types, `styles` without a string `scope` / bad `names` / non-string `layer`, `resume` not `{ module?, boundaries?, independent?, conditional?, static? }` / boolean (`boundaries` / `independent` / `conditional` / `static`: arrays of component names) (JS-falsy `0` / `""` / `null` / `false` = off), unknown `check` `targets`.

Diagnostics (derived model: RV2103 error / RV2104 warning, above): `compile` returns `{ category: "error", code: "RVnnnn", severity: "error", message, filename, line?, column? }` and empty `code` output when any exist (every compiler error fails the build). Compile warnings (T10 fix 2, `Diags::warn` / `Diagnostic.warning`: RV2104 keyed state in a loop) never suppress code: `compile` returns them under `warnings` (`CompileWarning`, absent when none), `check` with `severity: "warning"`, `vite.ts` `finish` prints each once (`[rivet:compiler] RVnnnn …` via `formatDiagnostic`, `ctx.warn`). Language-service warnings: RV3101. `check` (editor op) returns the same codes + UTF-16 ranges + `targets`, merged across server and DOM compiles, plus resume `sites` (M6: `classes` / `forRows` removed); codes are assigned from the message text in `rust/src/diagnostics.rs` (1xxx syntax/JSX, 2xxx resume, 3xxx imports/helpers/server code, 4xxx i18n, 5xxx styles, 6xxx slots, 9xxx internal). Registry: `codes.json` (add every new code there). Vite errors (DIAG-VERBOSE): `[RVnnnn] file:line:col: message` lines, each followed by `  fix: …` (language-core `explain.json` fix text, `diagnostics-format.ts` `remedyLines`) + `  docs: <url>`; diagnostics after the first carry their own code frame in the message; the RollupError sets `plugin: "vite-plugin-rivet"` (the real name: builds overwrite `plugin` with it), `pluginCode`, `url` (docs), `loc` and `frame` explicitly (Vite's dev `_formatLog` returns early when `pluginCode` is set, so it never adds them; the frame is read from the file on disk — static icons change the transformed text); (RV2010, the plugin-only module-ref build error, retired in M6.) Code table: docs/guides/editor.md.
