# @rivetjs/compiler

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

JSX/TSX compiler (Rust/oxc → WebAssembly) with its TS API, Vite plugin, image pipeline and parity oracle. Lowers JSX to hoisted HTML + server slots (server target) or template specs + bindings (DOM target); resume = the derived model only (M6 2026-10-22: boundaries + keyed state; the serialized lowering, symbol modules and their codes are gone).

## Layout

- `index.ts` — public API types + `compile`/`check`/`moduleFacts` calls; `groupComponents` (chunk grouping: component / group (`ChunkGroup`) / route).
- `facts-fixpoint.ts` — derived model (M2 C1, lane A 2026-10-18; not a package export, `vite.ts` imports it): `boundaryFacts(facts, resolved, roots)` closes `moduleFacts(…, { boundaries: true })` over the module graph — interactivity = change sources (M6-PARITY 6b, user ruling 2026-10-22: props are live when the caller passes a reactive value; literals are static): a boundary has `source` (own handler / client effect / client event / element effect / model (a `ref` is a read: its element reaches a browser reader that is live itself), keyed `signal` / `createStore`, `resource`, `Async` / `Suspense` / `clientOnly` tag, or a read site over module state: browser global, module `let`, import / module const used as a value — `count()`, `store.x`, `rows.map(f)`; helpers called with arguments, namespace helpers `ns.f(x)`, module functions, data literals, context tokens and capitalised names are not state), or `interactive` own read sites AND live data in (`inputs` live: some resolved call site passes a function (`calls[].fn`) or non-data inputs (`calls[].inputs` false: attributes / expression children; element children are their own calls, function children slots) from a `live` caller; no resolved call site and not a route root = live) or a live context (`context` and a `provides` component enclosing a call site (`calls[].around`) / a caller up the call chain is `live`), or renders a boundary; `live` = source ∨ live inputs ∨ live context. Least fixpoint. Tags resolve through local / named / default imports, `exports` / `reexports` / `stars` (`export … from`, `export *`) and `compounds` (`Object.assign(Root, { Part })`: `<Meter>` → root, `<Meter.Output>` → part) — module facts of every module (Rust `facts.rs`); the walk includes plain `.ts` / `.js` app / source-package modules (re-export barrels, `meter/index.ts`) without boundaries; `verdict.because` = `source` / `live-props` / `live-context` / `renders`. Runtime: a live call site still passes getters (`hasLiveProp` / `splitLive` path) — only the static case changed. `conditional` = a boundary whose `because` is not `source` (and no route root): `conditional(file)` → `resume.conditional` → flag 1024 `COND` on its `_rB`; the server keeps such a record only for a live instance (runtime `server-derived.ts` "Conditional boundaries": per instance, server props are the values the caller computed, so the call site's reactivity shows as reads in its own unit — slot content / context values over a signal made outside its subtree — or as a kept boundary below it; a dropped instance keeps its markers and is adopted by a materialised parent as a dependent unit from an empty record, `dom-derived.ts` `claim`). A static `<Meter value={40}>` ships no record, no chunk, no runtime, never adopts; `independent` = interactive + `params: "object"` + no context + every resolved call site in the program data-only (`calls[].data`), or a route root's default export (`roots`); `dependentBecause` names the first reason. Returns `boundaries(file)` / `independent(file)` / `conditional(file)` name lists for the module's `resume: { module, boundaries, independent, conditional }`. Test `tests/facts-fixpoint.test.ts` (hand-built facts, no wasm). Vite wiring (M2 C3, 2026-10-20, `vite.ts` `derivedWalk`): every derived build (client + SSR) walks the resume modules in `buildStart` (`moduleFacts(…, { boundaries: true })`, imports resolved through `this.resolve`) → `boundaryFacts(facts, resolved, routeRoots)` (route roots = `serverExports` modules) and passes each module's `boundaries(id)` / `independent(id)` into both targets' compile options; dev serve uses the module-local closure (no walk).
- `wasm.ts` — synchronous loader: `new WebAssembly.Instance` of `./rivet_compiler.wasm`, `call({ op, ... })` → `{ ok } | { error }`; `hasDerivedModel()` reads the `has_derived_model` export (M2 lane A: the build understands derived `resume` / `moduleFacts` `boundaries`; tests of the model skip without it). One instance per process (tables registered via `registerTable` live in it). Any throw out of `run` is fatal (T8): a Rust panic (`panic = "abort"` → `RuntimeError: unreachable`, message + Rust location via `panic_ptr`/`panic_len`), a V8 stack overflow inside wasm (plain `RangeError`) or a shadow-stack overflow (out-of-bounds trap) throws `CompilerPanic` (`code` RV9001, "…nests too deeply" for the stack cases) and drops the instance; the next call instantiates a fresh one and replays every `registerTable`. `compile`/`check` turn it into an RV9001 diagnostic. An instance whose linear memory grew past `MEMORY_LIMIT` (256 MiB; memory never shrinks) is replaced after the call. Request strings are made well-formed (lone surrogates → U+FFFD, same UTF-16 length). `wasmSourceHash()` reads the embedded source hash (X2), `hasInstance()` is a test hook.
- `vite.ts` — `rivet()` plugin; see "Vite plugin" below.
- `server-only.ts` — SERVER-REACH (spec `docs/design/specs/2026-10-20-server-reach-design.md`; re-exported from `./vite`): `SERVER_ONLY_MARKER`, `SERVER_FILE`, `isServerOnly(patterns, specifier, id?)` (marker / `*.server.*` / patterns), `matchesServerOnly` (patterns only), `declaredServerOnly(plugins)` (`api.rivetServerOnly` of other plugins), `serverOnlyStub(id, chain, names)` (browser stand-in: one Proxy as `default` + every name, throwing `[rivet] <id> is server-only; reached from <chain>…` on any trap; internal names `$$fail` / `$$stub`, names starting `$$` skipped). Build-time only.

## Compile targets and modes (`CompileOptions`)

- `target: "server" | "dom"` (default server). Server: hoisted fragments + ordered slots (`compiledTemplate`); DOM: `template()` specs + binding setup.
- H-holes fact (PPR-T6, `rust/src/holes.rs`): per streamed boundary (`<Async>` / `<Suspense>` from `@rivetjs/runtime*`) whether a stored shell may re-run only its thunks: `<Async>` with `fallback`, no spread, function child; `load` / `children` / `error` capture only data (globals, module symbols, params, bindings inside the thunks, `const`s initialised by data: literals, templates, member reads, object / array literals, operators); no `let` / local function / class / catch / reassigned capture; the component creates no `signal` / `computed` / `createStore` (from `@rivetjs/reactivity*`) on the element's path (nearest enclosing function encloses it); `<Suspense>` never. `moduleFacts(src, file, { holes: true })` → `holes: HoleFacts[] { component, tag, at, line, column, eligible, because }` (absent without the option); the server target with `resume` emits `$hole: 1` on eligible elements (read by `@rivetjs/runtime/server-shell`). ## Vite plugin (`vite.ts`) rules

- `serverOnly` (`RivetOptions`, SERVER-REACH): server-only patterns, published as `api.rivetServerOnly` (the router reads them). Without the router plugin (`routed` false), a client import matching them (patterns only, not `*.server.*`) → `this.error`; with the router, its reach analysis decides.
- ABI handshake (`abi.ts`): first `buildStart` resolves `@rivetjs/runtime/server` from the root and `this.error`s when its package.json `rivet.abi` ≠ `RUNTIME_ABI` (exported from `.`). Build-time only — 0 B in output. Bump `RUNTIME_ABI` + `libs/runtime/package.json` `rivet.abi` together. `@rivetjs/runtime` is a **peer** dependency (the app's runtime is the one compiled code imports; runtime → compiler is only the optional peer of `./testing/register`).
- Environment selection: `options.ssr ?? environment.consumer === "server"` → server target; else DOM. Skips `\0` ids, `node_modules` (unless a source package, or a `FRAMEWORK` package's `.jsx` / `.tsx`: installed packages ship preserved-JSX `.jsx`, `frameworkJsx`), `?raw` / `?url` / `?rivet-chunk`. `config()` always adds `ssr.noExternal: [/^@rivetjs\//]` (Node cannot load an externalized `.jsx`) and `optimizeDeps.exclude` = `RIVET_PACKAGES` (esbuild would compile their JSX as React) — no-ops for workspace-linked packages (test: `tests/vite-installed.test.ts`).
- T7 file selection: `include` / `exclude` (`FilterPattern`, Vite `createFilter` resolved from root) gate every compile; `foreignJsxPragma(source)` (leading comments only: `@jsxImportSource X` ≠ `@rivetjs/runtime`, or classic `@jsx`) → file left to other plugins. Plain `.ts` route modules (endpoints) compile on the browser target only, with `serverExports: true, target: "dom"` (handlers + server imports stripped when a page imports a constant from them); server builds leave them alone. oxc source type per extension (`rust/src/source_type.rs`): `.ts`/`.mts`/`.cts` no JSX, `.js`/`.jsx`/`.mjs`/`.cjs` no TS.
- Editor manifest: `configResolved` writes `.rivet/editor.json` when `resume` is set or the app has a `configFile` (`{ version: 1 }` without resume); unchanged content → mtime bump only (`updateEditorManifest` returns false).
- Resumable module set = `resume.modules` (root-relative) + (`resume.appModules: true`, set by `rivetRouter`) every app `.tsx`/`.jsx` inside the Vite root outside `node_modules` + source-package `.tsx` reached by the build's boundary facts walk (`isResumable` requires `/\.[jt]sx$/`).
- Derived model (the only resume model; M2 C3 2026-10-20, M6 2026-10-22 dropped `resume.model`): both targets compile with `resume: { module, ...verdict }` (the walk's verdicts, `derivedWalk`); client build emits one chunk per module holding boundaries + `\0rivet-derived-entry` (`export { default } from "@rivetjs/runtime/dom-derived"`, chunk `derived-runtime`); no symbol grouping / merge / budget / `resume-entry`; `generateBundle` → `derivedManifest` = `{ hash, runtime, symbols: <module>#<export> → chunk URL (names from the client compile `result.boundaries`), sizes, deps, builtins?, domData? }` (`deps`, DERIVED-C: sorted static import closure of the runtime entry and of every boundary chunk; the server's fetch-ahead `data-fo`), `builtins` (DERIVED-S 2026-10-21: the chunk of `@rivetjs/runtime/resume-builtins`, dev too — `_rData` names it in a `Root` payload with built-in entries; `tests/vite-derived.test.ts` asserts it). Browser environment serves `DERIVED_SWITCHES` + lazy rows switches (`derivedSwitch`). SSR environment: the router's `@rivetjs/runtime/server-resume` import (importer under `libs/router/` / `@rivetjs/router/`) resolves to `\0rivet-derived-server-resume` (`export *` + `renderDerived as renderResumable`, `derivedToString as resumableToString` from `/server-derived`) — router source untouched, serialized servers 0 B. Dependency facts (DERIVED-C4 / C5): in derived builds `resolveId` sends `@rivetjs/reactivity` (and `/store`, server only) of every importer but the runtime's / reactivity's own (`RUNTIME_OWN`) to `@rivetjs/runtime/server-derived-reactivity` / `server-derived-store` (SSR) or `@rivetjs/runtime/derived-reactivity` (browser): plain signals made in `.ts` helpers (cdk `createListData`, collection state) become visible to the derived server's wake lists, so heavy dependents (collection hosts) adopt after their parent (`libs/runtime/CLAUDE.md` "Dependency facts"). `resume.domData` on derived (DERIVED-C5): the browser serves the `dom-data` switch only (`DOM_DATA = true`, read by `dom-derived.ts`), the server `dom-data-derived` (`derivedDom.api` = `server-derived-dom.ts` `_derivedDom`), never `dom-data-resume` / `dom-data-server` (the serialized reader / registry stay out); `domDataIn` → manifest `domData: true`, the derived server then writes tail `d` entries. Dev: manifest `{ model, runtime: dev URL of the entry, symbols: Proxy name → module dev URL }`; `hotUpdate` of a resumable client module = full reload. Ignored under derived: `resume.entry` / `preload` / `chunks` / `merge` / `budget`. Test `tests/vite-derived.test.ts`.
- Module ids: app files root-relative posix; source-package files `<package name>/<path>` (stable across install paths; boundary names and keyed-state keys depend on them).
- Dev: resume mode only when `resume.dev` (router sets it); `api.devResume.manifest()` = `{ runtime, symbols, builtins? }` (boundary name → the dev URL of its module); an edit of a resume module reloads the page, except a css``-only edit (only its sheet updates); with the router (`routed`) the plugin leaves it to `entry.dev.tsx` (resumed page → reload, client-rendered after DevTools inspection → hot replace). App modules resolve `@rivetjs/reactivity` to `@rivetjs/runtime/hot-reactivity` (state-keeping signals); framework packages (`FRAMEWORK` set, outside their `tests/`) never do. `?t=` requests of framework sources answer a re-export facade; framework edits full-reload (E16).
- `staticIcons` (default true): every compile site (facts walk, sheet `load`, `transform`, `hotUpdate`) compiles `prepared(file, source)` = `static-icons.ts` over `.tsx` / `.jsx` (same text on both targets → same boundary names / keys); lucide data via `createRequire(importer)("lucide")` (CJS build, cached per resolved file). `rivetRouter({ staticIcons })` forwards it (unset: the compiler default).
- One option builder (`moduleOptions(filename, source, server, id)`) feeds `transform` and `hotUpdate` (CSS-only edits recompile with the same resume / split / styles options as the transform).
- Compile-option contributors: sibling plugins exposing `api.rivetCompileOptions(server, id?)` (e.g. `@rivetjs/i18n/vite`) are merged into every compile (`dev: serve` added when any exist).

- Route modules (`serverExports.modules`, read live) compile with `serverExports: true` on both targets.
- Dev caches (`sheets`, `clientCode`) are pruned in `watchChange` when a module is deleted / renamed away (T6).
- `bridges` (framework bridges T5, spec §12): `rivet({ bridges: [react(), …] })` → `[bridgeHost, rivetPlugin]` (+ `imagesPlugin`); absent / `[]` → plugin list + resolved config equal to before (test `tests/vite-bridges.test.ts`). `bridgeHost` imports `@rivetjs/bridge/vite` lazily from the app root (`config` hook; optional peer, no hard dependency) and adds each `BridgeEntry`'s framework plugins (`BridgeEntry` (+ `wrappers`, `islands.include`) / `RivetBridgesApi` interfaces here). Files a bridge owns are never compiled by Rivet (transform returns null; an explicit Rivet `include` selecting one → RV2145; one with a value import / re-export / `import()` of `@rivetjs/runtime*` (parsed: `import type`, comments, strings ignored) or the runtime's leading JSX pragma → RV2148 build error); virtual facades (`\0rivet-island:<target>.tsx`) compile through `api.rivetBridges` like app modules (resume mode, `sourcesOf` maps them back; `appModule` / `sourcePackage` / `isResumable` / `moduleId` / `devUrl` guards for `\0` ids, dev URL `@id/__x00__…`); `seeds()` adds `@rivetjs/bridge/root.tsx` to the resume walk. Manifest `islands: { <file | npm spec>#<export> → chunk URL }` (+ `sizes` / `deps` closures; dev manifest: a proxy to dev URLs). Facades the derived walk reaches with no boundary (islands-only pages, M6-CUT) are emitted as chunks too, so their island chunks are built and listed (lean boot loads them; the facade chunk itself stays unused).
- `images` → `[rivetPlugin, imagesPlugin]`; `devtools` (default true) loads `@rivetjs/devtools/server` if installed, dev only.
- Fact resolutions (the boundary facts walk) go through `resolveFact(ctx, spec, importer)`: an in-flight `importer \0 spec` registry that import guards read via exported `_factsResolve(spec, importer)` (router server-only guard). Never mark them with `this.resolve(…, { custom })`: rolldown 1.2.12 keys context-resolve options by `resolveOptionsMap.size` and deletes them after the call, so concurrent resolves reuse a live key and a hook sees another call's `custom` or none (the `fixture-inline` canary failed at random, 2026-10-11; regression `libs/router/tests/inline.test.ts` "concurrent context resolves").

## Gotchas

- Rust edits without rebuilding the wasm change nothing; tests, language-core and the typescript-plugin all load the committed `rivet_compiler.wasm`.
- Serialized-model gotchas (symbol modules, content-stable symbol ids, serializable builtins, data classes, `reconstruct` / `resource()` recipes, live-props-p4 aliases, method shorthands, returned accessors, re-export covering, module references, captured holders, hoisted registrations, boxed `let` cells, narrow member captures, function groups + `.bind`, store literal paths): obsolete since M6 (2026-10-22) — their emission is deleted; the matching `resume.rs` / `resume/*.rs` analysis still runs into scratch (trim = follow-up). History: git log before M6.
- `check` runs both targets with `check: true`, the DOM target as production lowers it (so DOM-only diagnostics such as RV1005 show in the editor); `sites` come from the DOM target (member captures appear as `props.a` with the member expression's span).
- `styles.ts` `scopeHash` and `rust/src/styles.rs::hash` must stay bit-identical (CSS modules vs css`` share names).
- `hotModule` returns `null` (module left to normal propagation) on `function*` defaults, `export … from`, or `as default` in export lists. Arrow defaults (`export default (p) => …`, `async`, single param) are rewritten to `let __rivetDef=` (same width, source maps hold) and wrapped like named components. Anonymous `export default function (…)` → `function __rivetDefault(…)` padded to the same width (T9; columns no longer shift).
- R2 (2026-10-06): `html.rs` `encode_attribute` writes HTML attribute names lowercase (React-style `encType` / `readOnly` / `tabIndex` → `enctype` / …; SVG / MathML keep case) and keeps a non-empty `hidden` keyword (`hidden="until-found"`); `resume.rs` makes a native element's parameterless concise arrow child containing a call (`{() => log().join()}`) a Bind site; since 2026-10-08 a block body with a call too (`{() => { const v = s(); return <b>{v}</b>; }}`, also among lazy children; was frozen after resume). Tests: `attribute-names.test.ts`, `resume-function-children.test.ts`.
- Server hoists (ui-pure-fragments, 2026-10-08): `const __rivetFragmentsN = /*#__PURE__*/ Object.freeze([…])` and `/*#__PURE__*/ _variants(…)` — unused templates of a multi-component module (e.g. `@rivetjs/ui` `dom-tags.tsx`) tree-shake out of server bundles.
- Server builds: a call of the runtime's imported `clientEvent` lowers to `undefined` (`compile.rs` `visit_node`) — the server never attaches it and its `window` / `document` target would throw outside a browser. Derived server modules: `clientEffect(fn, options)` → `clientEffect(void 0, options)` (M6-CUT: the closure and its browser-only imports leave the SSR bundle; the call stays so the server `clientEffect` flags the open boundary's client trigger — lowering it to `undefined` (M6-PARITY) left `clientEffect`-only pages without `data-boot`; ai-eval ticking-clock / persisted-theme / window-size, docs examples effect-title / motion-scroll). Test `tests/server-client-event.test.ts`.
- Spread elements (compile.rs exception, user ruling 2026-10-06): a lone `style={obj}` merges into the spread object (`styling::spread_directive` / `lone_style`; source order, later key wins, one `style` attribute on every target; style checks still run in `styling::analyze`); next to `style:` directives it stays grouped with them. A spread `<textarea>` without children / model gets a server `spreadChildren()` slot after the newline sentinel (`server-spread.ts` turns `value` / `defaultValue` into the content). Test: `tests/spread-style-textarea.test.ts`. A plain `<textarea value={…}>` / `value="lit"` / `defaultValue` renders as content on the server too (round-2 C3, `tests/round2-pending.test.ts`).
- Q1 gaps (G-CMP, 2026-10-06): C15 `class` + `className` on one non-spread element = RV5003 (`styling.rs` `CLASS_TWICE`); C14 style numbers get `px` outside React's unitless list (`styling.rs` `UNITLESS` / `number_value`, twin of runtime `style.ts` `UNITLESS`; `0` and `--custom` as written); SEC3 SMIL `values` split on `;` only (`html.rs`); C5 `compile.rs` `IMPLIED_TBODY` (RV1005 on server and DOM: `implied_tbody_child` rejects the tree, `report_dom` reports it) — statically visible For / Show / `.map` / `?.map` directly in `<table>`, components and `{children}` stay legal; dynamic `defaultValue` / `defaultChecked` / boolean `popover` are not plain v2 attributes (runtime writer). v2 `unquoted` quotes any Unicode whitespace (`label="\xA0"`). Tests: `tests/gap-cmp.test.ts`.
- X2 staleness guard: `rust/build.sh` embeds sha256 of the `sha256sum` manifest of `Cargo.toml`, `Cargo.lock`, `.cargo/config.toml`, `src/**` (sorted) as `source_hash_ptr/len`; `tests/wasm-fresh.test.ts` recomputes it, so any Rust edit without a rebuild fails the compiler suite.
- Compile speed (2026-10-06, CMP, `SCRATCH/cmp/bench.mjs`): cdk 1.7 MB server 0.048 ms/KB, DOM 0.048 (v1 was 0.049), resume 0.06–0.064, check 0.075 (was 0.267). Known superlinear: `compile.rs` `unique` probes (cubic for many lists / templates in one module: 2000 small components 1.3 s server) — patch proposed, needs compile.rs authorization.
- Wasm `call` is synchronous and single-instance per process; `registerTable` state is global to that instance (tests that register tables affect later tests in the same worker — vitest `pool: "forks"`, one worker per file).
