# @rivetjs/compiler

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

JSX/TSX compiler (Rust/oxc → WebAssembly) with its TS API, Vite plugin, image pipeline and parity oracle. Lowers JSX to hoisted HTML + server slots (server target) or template specs + bindings (DOM target); extracts resume symbols.

## Layout

- `index.ts` — public API types + `compile`/`check`/`moduleFacts` calls; `_compileSymbolModule` (symbols → browser ES module, DOM target), `groupComponents` (chunk grouping: component / group (`ChunkGroup`) / route).
- `wasm.ts` — synchronous loader: `new WebAssembly.Instance` of `./rivet_compiler.wasm`, `call({ op, ... })` → `{ ok } | { error }`. One instance per process (tables registered via `registerTable` live in it). Any throw out of `run` is fatal (T8): a Rust panic (`panic = "abort"` → `RuntimeError: unreachable`, message + Rust location via `panic_ptr`/`panic_len`), a V8 stack overflow inside wasm (plain `RangeError`) or a shadow-stack overflow (out-of-bounds trap) throws `CompilerPanic` (`code` RV9001, "…nests too deeply" for the stack cases) and drops the instance; the next call instantiates a fresh one and replays every `registerTable`. `compile`/`check` turn it into an RV9001 diagnostic. An instance whose linear memory grew past `MEMORY_LIMIT` (256 MiB; memory never shrinks) is replaced after the call. Request strings are made well-formed (lone surrogates → U+FFFD, same UTF-16 length). `wasmSourceHash()` reads the embedded source hash (X2), `hasInstance()` is a test hook.
- `vite.ts` — `rivet()` plugin; see "Vite plugin" below.
- `abi.ts` — `RUNTIME_ABI` (8: Function Bridge (`_rMod` from T2; thunk captures, `_rCell`, `_rBound`, `_rGroup`, `_rStorePaths`, `_rClass` in later bridge tasks); 7: IMPL-SPREAD F3 `_pm`; 5: IMPL-SPREAD `_attrs` / `_spread` exclude), `runtimePackage(file)`, `runtimeAbiProblem(pkg)`: compiler ↔ runtime handshake used by `vite.ts` `buildStart`.
- `hot.ts` — `hotModule()`: dev client hot replacement (exported components → `hot()` wrappers via `@rivetjs/runtime/hot`; `@refresh reset` opts out of state keeping). T6: `topLevel(code)` lexes the compiled module (strings, template literals incl. `${}` nesting, comments, regex literals) so only top-level `export ` lines are rewritten; several declarators (`export const A = …, B = 1`) → `null`; `export let` components stay values (live binding). `sourceStamps(source, file, code)` (DIAG-VERBOSE, dev client only, appended by `vite.ts` `finish`): one IIFE registering each column-0 capitalized `function` / `const|let|var` declaration (guarded by `typeof X === "function"`) and its `__rivetHotN` wrapper in `globalThis[Symbol.for("rivet.sources")]` (WeakMap fn → [name, "file:line:col"]) — runtime `dev/where.ts` names components with their declaration site in dev warnings. Dev server: `configureServer` installs `globalThis[Symbol.for("rivet.locate")]` = `appFrames` over an `ssrFixStacktrace`-mapped probe stack (server-side dev warnings from cdk / reactivity name the app frame; the probe alone raises `Error.stackTraceLimit` to 60 — V8's 10 frames end inside ui / cdk / runtime frames; `server.close()` removes the hook when it is still this server's; test `tests/vite-locate.test.ts`).
- `styles.ts` — scoped class naming shared with `rust/src/styles.rs`: FNV-1a 64 over `scope\0local`, `readable` `<local>_<hash5>` / `short` `r<hash6>`; `nameRegistry()` collision check. Also used for `*.module.css` via `css.modules.generateScopedName`.
- `editor.ts` — editor manifest (above).
- `static-icons.ts` — compile-time icons (IMPL-ICON 2026-10-09): `staticIcons(source, filename, loadLucide)` rewrites `<Icon icon={X} …/>` (`Icon` from `@rivetjs/kit/icon`, `X` a named `lucide` import, no children, only constant `size` / `color` / `strokeWidth` / `absoluteStrokeWidth` / `class` / `data-*`, values free of `"&<>{}\` / newlines) to the inline `<svg>` kit `Icon` renders (its `root` order: lucide defaults, then caller attributes in source order; shapes in data key order), keeping the line count. Parser: Vite's `parseSync` (oxc, UTF-16 offsets). Names redeclared anywhere (params, locals, patterns) are left alone; parse errors / no lucide → source unchanged. Byte-identical server output vs the component: `tests/static-icons.test.ts` (every lucide icon × 5 prop sets). Kit `icon.tsx` `root` / defaults change → change this file too.
- `images/` — `?image` / `?jsx` / `?svg` imports, sharp pipeline (raster), svgo (SVG assets + inline `?svg` components, compiled here with `compile()`) (own CLAUDE.md).
- `oracle/` — parity corpus + checker (own CLAUDE.md).
- `spikes/portability/classify.ts` — THROWAWAY spike P1 (`docs/design/research/2026-10-18-backend-agnostic.md` §7): TypeScript-AST classifier of component server renders into portable / sidecar / browser tiers for a portable template IR, per root, with the demoting constructs; `--roots`, `--top`, `--allow` (helper allow-list), `--json`. Node ≥ 24, `typescript` dev dependency; not part of the package or the typecheck project. Delete when the compiler-facts classifier exists.
- `rust/` — the compiler crate (own CLAUDE.md). **Root agent only** edits `rust/**` and builds the wasm (root CLAUDE.md rule; subagents submit patch files) (wave 2 touched compile.rs for component-children lowering and the `_rOn` flags only).
- `rivet_compiler.wasm` — **generated** (committed; `rust/build.sh`, Docker). Copied by `libs/typescript-plugin/build.ts` and located by `libs/language-core/compiler.ts` — keep the path.
- `tests/` — vitest project `compiler` (own CLAUDE.md).

## Compile targets and modes (`CompileOptions`)

- `target: "server" | "dom"` (default server). Server: hoisted fragments + ordered slots (`compiledTemplate`); DOM: `template()` specs + binding setup.
- `resume: { module }` — resume mode: closures that must run in the browser become module-level symbols `<module>#<Component>$<hash>` (content-stable, below); result carries `symbols` + `scope`. Same analysis on both targets → identical ids. Resume mode keeps `.map` list mounts for rows without a resume site (`resume_list_ok` / `Resumed::has_site_within`; a row holding a site keeps the recorder path) — keyed `<For>` list mounts stay off (the resume row hook). FLATTEN-CMP: reads of a structural `<For>` child function's `row()` / `index()` getters (not reassigned) are not sites (`accessors` in `resume.rs`; server rows are constant getters, client adoption re-creates a row on item / read-index change), so getter-only cells are plain slots (no `_rBind` / `_rAttr`); expressions with JSX or other calls keep theirs. `Link` from `@rivetjs/router/client` is a static framework component like `@rivetjs/router/link`. Wave-2 rules: lazy component children are `slot` sites (`__rivetSlot(() => …)` symbol, server `_rFn(id, __rivetSlot(…), captures)`); spread / styled sites capture member reads (`props.a`, `props["x-y"]`) and `@rivetjs/cdk/dom-props` projections (`globalDOMProps(props[, owned])`, `textInputDOMProps`) instead of whole objects (symbol params `props$a` / `props$0` + a prologue rebuilding `props`; other site kinds still capture whole); `onX={c ? f : undefined}` / `c && f` with a side-effect-free test passes `!!c` as `_rOn`'s 5th `present` argument (flags `undefined` when empty); `onXCapture` records `_rOn(…, { capture: 1 })` (the old "Capture-phase handlers are not resumable" diagnostic is gone); a const arrow referring to itself has no self capture (symbol `{ const f = (…); return f; }`); optional member reads (`a?.b`, `a?.[k]`, `a?.b()`) capture the object whole (the guard stays in the read); a component among a user component's lazy children (`<List><For each={items}/></List>`) is its own `region` site — server `__rivetSlot(() => _rBind(id, () => For(…), captures))`, so its rows are adopted instead of the whole `List` re-creating (framework components' children and native-element children keep the existing rules). COND (2026-10-07, `rust/src/compile/lazy_binds.rs`): an expression child containing a call among a user component's lazy children (`<Box>{c() && <p/>}</Box>`, `{c() ? "on" : "off"}`, `{view()}`) is its own `bind` site — server `_rBind(id, () => …, captures[, 1 when it may render JSX])` inside the slot thunk, so it updates after resume (was frozen: the slot thunk ran once); DOM wraps a "maybe nothing" operand (`may_render_jsx` + `dynamic`) in `_scoped(() => …)` on every component, `Show` / `Provider` included (`dom_v2.rs` `lazy_child_v2`; plain calls such as cdk `place(useChildren(…))` stay unwrapped — wrapping them re-ran the slot per read, dom-rows regressions). Open: a non-JSX reactive expression (`{c() ? "a" : "b"}`) directly among `Show` / `Provider` children still freezes on the client (they call the slot once) — wrap it in an element or a function child. SRV-ROWFN (server resume target, `rust/src/compile/server_rows.rs`): an `_rAttr` read is a hoisted `const __rivetReadN = (__rivetCaps) => { const a = __rivetCaps[0], …; return (…); };` (runtime `read(captures)`; stays a thunk when the text holds `__rivet` / `arguments` / `await` / `yield` / `super` / `new.target`); a `return` / concise-body native template whose own `_rOn` / `_rAttr` slots repeat a capture list → `{ const __rivetCaps = [a, b]; return …; }` shared by them (only when no captured binding has a write reference; otherwise the statement text is unchanged); a closed `<For by>` arrow (no enclosing-function locals / `this` / `arguments` / JSX) → hoisted `__rivetByN`. Test: `tests/server-rowfn.test.ts` (differential HTML + state). R-PLAN (IMPL-RESUME 2026-10-09, server resume target, `rust/src/compile/resume_rows.rs`; `serverListMounts` on, no i18n): a `<For>` whose sole child is a concise 1–2 identifier-param arrow returning a native element (no `model:`, the arrow not itself a site) lowers its row once — `children: (row, i) => <template>` (captures shared as above) — and, when every row-template slot is a plain attribute / value (no function, getter prop, resume call, `this` / `arguments` / `await` / `yield` / `super` / `new.target`), `_rId()`, `_rOn(type, id, caps[, flags])` (no `present`) or `_rAttr` with a lifted read, adds `"$rows": [__rivetRowPlanN, __rivetRowTapeM, [env…]]`: `const __rivetRowPlanN = _rRowPlan(fragments, entries, sites)` (list plan entries: `_rAttr` / `_rId` = attribute entries, `_rOn` = null; sites `[slot, 0]` / `[slot, 1, type, id, shape, flags?]` / `[slot, 2, name, id, read, shape, ns?]`, shape = env index / -1 row getter / -2 index getter from the site's captures) and a module-level `function __rivetRowTapeM(tape, base, row, index, env, site)` binding `env` locals by name and writing each slot (`site(k)` for `_rAttr` / `_rId`, null for `_rOn`). Unchanged output: non-JSX operands, static tests, `this` / `super` / `arguments` / `new.target` / `await` / `yield` anywhere (`getter_safe`), JSX attribute / prop values, the server target (no `_cond` import unless used). Resumed pages: `_compileSymbolModule` compiles with the internal option `symbols: true` (`Options::symbols`); a binding symbol `(captures) => () => (cond)` with such a conditional becomes `(captures) => _cond(…)` (`dom_v2.rs` `symbol_cond_v2`), the accessor the resumed region runs — after its activation (first dependency change re-creates as before) it rebuilds only on a branch change. Plain compiles keep `() => cond` arrows. Tests `tests/ternary-memo.test.ts`, runtime `tests/cond-memo-browser.test.ts`.
- Component children: plain JSX children of a component element (elements / fragments / expressions, not text-only, not a single function or bare reference) compile to a branded lazy thunk `__rivetSlot(() => …)` (`_slot` from `@rivetjs/runtime/dom` on the DOM target and in symbol modules — keeps it in the dom chunk — and from `@rivetjs/runtime/slot` on the server) on every target, so `useContext` inside the children sees the component's providers; `Switch` children stay eager (its `Match` markers). Runtime side: `isSlot` / `renderSlot` (`libs/runtime/slot.ts`).
- `serverListMounts` — list-mount plans for `.map` rows and, without resume, keyed `<For>` rows (structural `For` from `@rivetjs/runtime/dom|server`, sole concise-arrow child returning native JSX or a twin: `children` + compiler-private `$list: [plan, each]`; docs/design/server-list-mounts.md).
- `staticCalls` / `variants` / `variant` / `timeZone` (i18n): tables registered per process with `registerTable(id, table)`; server output carries every variant, DOM inlines `variants[variant]`. Unused `staticCalls` must leave output byte-identical (tests/i18n.test.ts).
- `dev: true` — unknown prefixed keys warn at runtime (set by `rivet()` on the dev server when a contributor plugin exists).
- `styles: { scope, names, layer }` — css`` blocks → `css` + `cssClasses` in the result.
- `serverExports: true` — route module: `server[A-Z]…` exports and `onRequest`/`onGet`/… are checked and stripped from the DOM target together with code only they use (`rust/src/server_split.rs`; docs/guides/server-code.md).
- `sourcePackages: string[]` — `@rivetjs/*` packages with `"rivet": { "source": true }` whose components are user components (symbol callbacks / slot props) in resume mode; other `@rivetjs/*` are framework components; non-`@rivetjs` packages are always user components.
- `resolvedImports: { [specifier]: moduleId }` — resume mode: the unit of module reference ids for imports (Function Bridge T3; `rivet()` fills it per module from `ctx.resolve`); absent specifiers fall back to the spelling rule.
- `sourceMap: true` — adds `map`; emitted code must not change (tests/source-map.test.ts runs the whole corpus).

Option validation (P4): malformed options are an RV7001 `Invalid compiler option …` diagnostic, not a thrown `invalid request` — wrong types, `styles` without a string `scope` / bad `names` / non-string `layer`, `resume` not `{ module?: string }` / boolean (JS-falsy `0` / `""` / `null` / `false` = off), unknown `check` `targets`.

Diagnostics: `compile` returns `{ category: "error", code: "RVnnnn", severity: "error", message, filename, line?, column? }` and empty `code` output when any exist (every compiler error fails the build). Compile warnings (T10 fix 2, `Diags::warn` / `Diagnostic.warning`: RV2012 / RV2013 / RV2014 on receivers that may own a `bind`; RV2015 a component's returned accessor that cannot resume) never suppress code: `compile` returns them under `warnings` (`CompileWarning`, absent when none), `check` with `severity: "warning"`, `vite.ts` `finish` prints each once (`[rivet:compiler] RVnnnn …` via `formatDiagnostic`, `ctx.warn`). Language-service warnings: RV2101, RV3101. `check` (editor op) returns the same codes + UTF-16 ranges + `targets`, merged across server and DOM compiles, plus resume `sites` and `classes` (T28: the module-scope classes the resume target registers, `{ name, kind: "data" | "revive" }` from `resume/classes.rs` `ClassReg.revive`; empty without `resume`) — language-core RV2101 trusts them; codes are assigned from the message text in `rust/src/diagnostics.rs` (1xxx syntax/JSX, 2xxx resume, 3xxx imports/helpers/server code, 4xxx i18n, 5xxx styles, 6xxx slots, 9xxx internal). Registry: `codes.json` (add every new code there). Vite errors (DIAG-VERBOSE): `[RVnnnn] file:line:col: message` lines, each followed by `  fix: …` (language-core `explain.json` fix text, `diagnostics-format.ts` `remedyLines`) + `  docs: <url>`; diagnostics after the first carry their own code frame in the message; the RollupError sets `plugin: "vite-plugin-rivet"` (the real name: builds overwrite `plugin` with it), `pluginCode`, `url` (docs), `loc` and `frame` explicitly (Vite's dev `_formatLog` returns early when `pluginCode` is set, so it never adds them; the frame is read from the file on disk — static icons change the transformed text); plugin-only build error RV2010 (one import ref id, two installed copies; `vite.ts`). ## Gotchas

- Rust edits without rebuilding the wasm change nothing; tests, language-core and the typescript-plugin all load the committed `rivet_compiler.wasm`.
- `_compileSymbolModule` (phase d): symbol chunks run on the DOM ABI; the resume runtime adopts server nodes into slots / lists / branches (`libs/runtime/dom-adopt.ts`). Resumed main modules lower the same; resume spread symbols call `_spread(el, read, flags, names)` (flags 1 = content), styled attribute sites `_attrValue` (`resume.rs`).
- Resume symbol ids are content-stable (Function Bridge C2, 2026-10-09, `resume.rs` `content_digest`): `<Component>$<hash>` where the digest = FNV-1a 64 over kind, component, symbol body text, params + capture kinds, imports, as 13 base-36 digits least significant first, and `<hash>` = its shortest prefix of ≥ 3 digits (`HASH_MIN`) that no other digest of the same component shares (C1C2-SLIM 2026-10-09: set rule, colliding ids both extend; was a fixed 6 digits, +5.5% playground state); identical twins in one component `$<hash>_<k>` (source order). An id changes only when that closure's code / captures change (adding a site elsewhere renumbers nothing; was positional `$<n>`); a changed closure gets a new id, so a skewed page fails safe (runtime `dom-resume.ts` `symbol()`). Tests match ids with `\$\w+` / `[0-9a-z]{3,13}` or read them from `symbols`, never a literal positional index. All 51 resume oracle cases re-recorded (id-only) by C2 and again by C1C2-SLIM.
- Captured `const x = new X(…)` (BRIDGE C1, `resume.rs` `SERIALIZABLE_BUILTINS` / `serializable_builtin`): no "class instances are not serializable" diagnostic when `X` is an unshadowed global the encoder serializes (Map, Set, Date, URL, URLSearchParams, RegExp, ArrayBuffer, DataView, typed arrays, Error family); keep the list in sync with `libs/runtime/resume-format.ts` `build`.
- Data classes (Function Bridge C12 / T24, 2026-10-12, `rust/src/resume/classes.rs`): every module-scope class declaration of a resume module that is a data class registers — no instance `#private` element / `accessor` field (D-priv), `extends` only a module-local data class (built-in / package / Node `EventEmitter` bases are ineligible), no resource read while constructing (`window` `document` `navigator` `globalThis` `localStorage` `sessionStorage` `WebSocket` `EventSource` `Worker` `BroadcastChannel` in instance field initializers or the constructor; nested functions and function-valued fields excluded), no class / member decorator and no field arrow reading `super` / `new.target` (review T24 L2 / M1; such an arrow is never lifted). Registered and sound (same module code in the browser): prototype mutation, a reassigned class binding (the symbol reads it live), static blocks, computed keys, static `#private`, TS parameter properties. Not caught at compile time (review T24 L1, as designed): a field from an imported call (`pool = createPool()`) fails at render if its value is not serializable; a module-level `typeof window` conditional (`const w = typeof window … ; class R { win = w; }`) restores the server value (`null`). Server epilogue `_rClass(Cls, "<module>#<Cls>$class")` after the `_rMod` stamps; symbol `<Cls>$class = () => (Cls)` (kind `class`, component = class name, locals / scope `[Cls]`). Instance arrow fields → server `inc = _rFn("<module>#<Cls>$<h>", () => this.c++, [this])` (`resume_node`, `Resumed.class_arrows`), symbol `(__rivetSelf) => () => __rivetSelf.c++` (kind `fn`; `this` rewritten outside nested non-arrow functions; `<h>` = shortest digest prefix unique per class).
