# @rivetjs/kit

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Document head as components (title, meta, links, scripts, JSON-LD, theme script), font + image head preloads, `kit()` Vite plugin, `<Transition>`. Router-only (needs `@rivetjs/router` head sink). Strict nonce CSP, hash CSP, Trusted Types safe.

## Layout

- Flat by decision: every public subpath is one file at the package root (~1.1k lines total). No `<name>/index.ts` folders; keep it flat unless a subpath grows to ≥3 files.
- `google-fonts.ts`: internal, build-time only (Node): `parseGoogleFontId`, `googleFaces`, `resolveGoogleFont` — css2 + gstatic download into the cache, returns the local `?font` id. Imported lazily from `vite.ts` `resolveId`.
- `shared.ts`: internal, target-independent pieces both `index.ts` and `dom.ts` re-export: `HeadLevel`, `KIT_POLICY`, `childText`, builders (`seo`, `openGraph`, `twitterCard`, `canonical` (`trailingSlash` = router `TrailingSlash` via `slashPath`, default the app's `TRAILING_SLASH`), `alternates`, `jsonLd`, `unsafeInlineScript`, `themeScript`), component prop types.
- `tests/head.test.ts`: unit (rank merge, builders, preloads, `parseFontId`); imports `../shared.ts`, `../image.ts`, `../vite.ts` by path.
- `tests/font.test.ts`: `?font` fallback face from a real woff2 (`node_modules/@fontsource-variable/geist`, declared by docs-kit) via plugin hooks; Google Fonts with a mocked `fetch` (css2 URL, cache, offline, subsets).
- `tests/app.test.ts`: fixture e2e (dev + build, Playwright, strict CSP + TT, client nav head; production sheets are inline `<style nonce>` (the fixture's sheets total ≤ 6 KB br): router `inlineStylesheets` "auto").
- `tests/transition.browser.test.tsx`: `<Transition>` in Chromium (vitest browser project).
- `tests/icon.test.ts`: `Icon` server markup vs lucide defaults, props, lucide tree-shaking (esbuild), server bytes vs the old per-shape spread `REFERENCE` for every lucide icon × prop set (incl. a getter prop), client + resume in Chromium via `../../runtime/tests/resume/harness.ts` (icon compiled as `@rivetjs/kit/icon.tsx` in resume mode; `site(src, path)` serves a page resumed at `path` and client-rendered at `path + "csr"`); `/live/` page: every root mode matches the server markup (sorted attributes) and follows live props.
- `tests/fixture/`: Vite + router app; `src/routes/shell.tsx` (PPR-T57) = a shell-cache route (`routeRules` `/shell` `shell: { maxAge }` in `vite.config.ts`) whose hole renders `<Title>` / `<HeadLink>` / `<Script>`: `app.test.ts` checks late links / scripts carry the hit's nonce and the title write is ignored + warned. `tests/fixture/.rivet/` = generated by router codegen (gitignored, excluded in `tsconfig.json`).

## Rules / invariants

- Server and DOM targets keep the same export names and prop types. `index.ts` ↔ `dom.ts` swap happens only via `kit()` `resolveId`; never import `./dom.ts` / `./index.ts` directly from shared code.
- `image.ts` / `font.ts` import `pushHead` from `"@rivetjs/kit"` (self-import, not `./index.ts`) so the plugin can swap targets in browser builds. Keep it.
- Export names + subpaths are load-bearing outside the package — do not rename:
  - Compiler site-less allow-list `libs/compiler/rust/src/resume.rs` `static_framework_component`: `@rivetjs/kit[/…]` `Picture` `Image` `Font` `Head` `Title` `Meta` `HeadLink` `Script` `JsonLd` `ThemeScript` (documented in `docs/guides/resumability.md`). New head component that reads no signals → add to that list too (compiler owner).
  - Router codegen `libs/router/build/codegen.ts:199` imports `HeadLevel`, `applyRouteHead` from `@rivetjs/kit`.
  - `KIT_POLICY = "rivet-script"`: shared with the router's script bootstrap (`document.$rs = { p, l }`); one policy per page, no `'allow-duplicates'`.
- Head components render nothing in place (server: only late post-shell body-valid markup). Resumed pages never run them: zero client JS for head.
- `HeadLink`, not `Link` (router owns `Link`).
- Inline script code only via branded `unsafeInlineScript` / `themeScript` (`inlineScript` from router); plain objects throw.
- JSON-LD = data block: no nonce; DOM side only through TT `createScript`, which accepts JSON only.
- `ThemeScript` is static per props (stable CSP hash); DOM target is a no-op (server script already ran).
- `<Transition>` resumable at zero JS: state in signals/refs, phase machine driven from bindings reading `show`.
- `TransitionScope.hold(promise)` (T9 of the motion plan): a run (enter / leave) settles once the element's CSS transitions AND every promise held during it are done (holds added mid-wait too); ignored while settled (`shown` / `hidden`); an interrupted run drops its holds. Both bindings reading `show` may queue the same run: a repeat (phase already at its `from`) keeps the list. `useTransitionScope()` = the enclosing scope (read in the component body). `@rivetjs/kit/transition` +220 B min / +90 B br (4,305 → 4,525 / 1,652 → 1,742, `Transition` alone, runtime external). T10: holds are kept per direction (`towards(end)`: a hold arriving right after `show` changed, before the run started, lands in the list of the run toward `show`), and each run carries a token (`runs.n`): only the latest run steps the phase / settles (a quick leave → enter → leave left an older chain hijacking the phase); 4,600 / 1,783.
- `overlayPresence: { create?(isOpen) }` (motion fix round 1): an empty registry that `@rivetjs/motion` fills at module evaluation (`element.tsx` `overlayScope` → `{ wrap(render), take() }`); cdk `Modal` calls it optionally, so a bundle without Motion ships only the optional call. `TransitionScope.register?()`: a Motion element with `exit` announces itself (the overlay waits for holds only then). `Scope` context is `/*#__PURE__*/`.
- Social/SEO URLs must be absolute (or `baseUrl`): relative throws.
- UI/icons: never invent SVG paths, never UTF symbols as icons — use lucide via `@rivetjs/kit/icon` (root rule). `Icon` reads no signals: constant props record no resume state (static), dynamic props re-create it in its parent's region.
- Compile-time icons: the compiler's Vite plugin inlines `<Icon icon={LucideImport} …/>` with constant simple props as the `<svg>` this component renders (`libs/compiler/static-icons.ts` mirrors `root` + defaults: change both together; its test compares bytes for every lucide icon).
- `Icon` perf shape (IMPL-ICON 2026-10-09): shapes = `_svgShapes(props.icon)` imported from `@rivetjs/runtime/dom` (the compiler rewrites it to `/server` on the server target; keep it a `.tsx` import) — keyed by array identity, so icon data must not be mutated. Root `mode(props)` picks one of four JSX branches, all byte-identical on the server: FIXED (no getter: locals, no binding), STATIC (only `icon` a getter), LIVE (`title` key or another getter: per-attribute bindings, `<title>` cond), SPREAD (keys beyond own props + `class`, or Proxy props `Symbol.for("rivet.props")`: `{...root(props)}`). A key set is fixed per props object (non-Proxy), so the mode is decided once at creation. Measured (1000 icons, Chromium mount / Node SSR): 6.7 → 3.0 ms (getter `icon`), 2.4 ms (constant), heap 1466 → 247 / 73 KB; SSR 3.0 → 0.71 ms.

## Gotchas

- `dom.ts:189` `interaction` strategy listens to `touchstart`; `docs/guides/kit.md` says touch arrives as pointerdown (gap E15, out of scope).
- `docs/guides/kit.md` describes `document.$rs` as `{ p, a }`; code uses `{ p, l }` (`dom.ts` `Shared`).
- No head sink (no router / no `kit()` and no `head: "components"`) → server components throw with a setup hint.
- Client nav ranking is an approximation: layout components rank below the route head; page-level components win.
- Font `fallback` metrics need optional peers `@capsizecss/unpack` (`^3 || ^4`) + `@capsizecss/metrics`; absent → warning, no fallback face. Use `fromBuffer(await readFile())` only: unpack 4.x moved `fromFile` to `@capsizecss/unpack/fs` (G16). Pinned as kit devDeps (unpack 4.0.1, metrics 4.3.0; hoisted to root `node_modules` so apps resolve it). Typed `?font` import needs `&font` last.
- `google-font:` ids hit the network only on a cold cache (`node_modules/.rivet/fonts`); tests must stub `globalThis.fetch` (see `tests/font.test.ts`), never reach Google.
