# @rivetjs/typescript-plugin

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

TypeScript language service plugin: Rivet compiler diagnostics, quick fixes, resume inlay hints/hover, route-link completion/go-to/hover in every TS-based editor (VS Code, WebStorm, typescript-language-server / vtsls). Thin adapter over `@rivetjs/language-core` — logic belongs there, not here.

## Entry points

- `main` → `dist/index.cjs` (generated by `build.ts`, gitignored). tsserver `require`s it; `module.exports = init`.
- `index.ts` — source; `export default init`, `export interface PluginConfig` (`linkModules`, `inlayHints: "client" | "all" | false`, `typeAware` (RV3101 route-link checks; default on), `compilerWasm`). Hover on a captured variable: "is captured by resumable code (…)" (M6: captures are not serialized).
- `build.ts` — `buildPlugin()`, `distDir`; esbuild CJS bundle (target node18, `typescript` external) + copies `libs/compiler/rivet_compiler.wasm` into `dist/`. Imported by `apps/vscode/build.ts` — keep path + exports.

## Layout

- `index.ts` — `init({ typescript })` → `PluginModule`:
  - `create(info)`: proxies the LanguageService; overrides `getSemanticDiagnostics`, `getCodeFixesAtPosition`, `provideInlayHints`, `getQuickInfoAtPosition`, `getCompletionsAtPosition`, `getDefinitionAndBoundSpan`.
  - Session protocol handlers (once per session): `_rivet:sites` (`{ resume, sites }`), `_rivet:doctor` (`{ findings }`) — consumed by `apps/vscode/extension.ts`.
  - `getExternalFiles`: adds `.rivet/*.d.ts` (route types) of every Vite root (`viteRoot`) of `project.getRootFiles()` — solution / monorepo projects included.
  - `onConfigurationChanged`: merges editor config (VS Code `configurePlugin`) over tsconfig plugin config, drops compiler-candidate memo, `refreshDiagnostics()` on every live (open) project.
  - `_rivet:sites` sites carry `label` (`siteLabel`, same text as the inlay hint) for client-side inlay providers.
  - Context `result` is a lazy getter: completions / definitions / route features never run a compile.
- `tests/fixture.ts` — temp app under `.artifacts/` + in-process LanguageService with the plugin applied; `at(text, name)` marker positions.
- `tests/plugin.test.ts` — in-process feature tests. `tests/plugin-config.test.ts` — config refresh, per-wasm cores, lazy compile, externals from Vite roots. `tests/tsserver.test.ts` — real `ts.server.Session` loading the built bundle (runs `buildPlugin()`).

## Rules / invariants

- Every override is wrapped in `guard(prior, …)`: plugin errors are logged (`rivet: internal error`) and TS's own result returned. Never let a plugin bug break the editor.
- Only active when the project's `jsxImportSource === "@rivetjs/runtime"` and file is a Rivet file (`core.isRivetFile`).
- Diagnostic codes: `RVn` → tsserver number `70000 + n`, source `rivet` (TS doesn't use that range). Fixes keyed by `FIXABLE_CODES` from language-core.
- A manifest with `resumeModules` marks the whole app's JSX modules as resumable, including modules absent from those seeds (D2). `tests/plugin.test.ts` verifies RV2001's exact code, error severity and browser-global range in an unlisted module, plus no diagnostic for the same read in a handler.
- Compiler + core cached per process keyed by wasm path + mtime (`cores`): projects with different `@rivetjs/compiler` installs get their own; a rebuilt wasm reloads. Candidates memoised per project (cleared on config change). Compiler lookup order: `config.compilerWasm` → workspace `@rivetjs/compiler` → bundled `dist/rivet_compiler.wasm`.
- Use the `ts` passed to `init` (host TypeScript); `typescript` stays external in the bundle.
- Bundle must run on editors' bundled Node (node18 target, CJS) — no Node ≥ 24-only APIs in `index.ts` or language-core code it bundles.

## Commands

- Build: `NX_DAEMON=false npx nx run typescript-plugin:build` (= `node libs/typescript-plugin/build.ts`) → `dist/{index.cjs,rivet_compiler.wasm}`. Required for editors using workspace TS (`tsconfig.base.json` `compilerOptions.plugins`); rebuild after language-core or compiler changes.
- Test: `npx vitest run --project typescript-plugin` (builds the bundle itself).
- Typecheck: `npx tsc -p libs/typescript-plugin` (stays TypeScript 5.9 tsc; the repo's other typecheck targets run tsgo via `scripts/tsc.ts`).
- Publishable package: `NX_DAEMON=false npx nx run typescript-plugin:package` → `dist/libs/typescript-plugin` (`.ts` → `.js`, `.tsx` → `.jsx`, `.d.ts`, LICENSE, generated package.json); publish from there — this package.json stays the private workspace manifest (`publishConfig.directory`). Builder + tarball smoke: `scripts/package/` (scripts/CLAUDE.md). `publishConfig.prebuilt: "dist"`: the package is the esbuild `dist/` + manifest (`package` runs `build` first). `engines` `>=18` on purpose: it runs in the editor's tsserver Node, not the app's.

## Gotchas

- Editor shows stale behaviour → plugin not rebuilt, or TS server not restarted ("TypeScript: Restart TS Server").
- Workspace resolves the plugin via `node_modules/@rivetjs/typescript-plugin` (workspace symlink) → `dist/index.cjs`; missing `dist` = plugin silently absent (Doctor reports `plugin`).
- TypeScript 7 (tsgo) loads no JS plugins — use TS 5.x/6.x in the editor (docs/guides/editor.md Limits).
- tsserver.test.ts prints raw `Content-Length:` protocol frames to stdout — normal.
