# @rivetjs/bridge

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Framework bridges (foreign islands): React / Preact / Solid / Vue / Svelte components used as JSX tags in Rivet `.tsx`, server-rendered into the Rivet stream, hydrated by a `client` policy, live props, callbacks through the Function Bridge, resumable Rivet slots. Spec `docs/design/specs/2026-10-11-framework-bridges-design.md` (authority; rulings §11), plan `docs/design/plans/2026-10-11-framework-bridges.md` (lane BRIDGES). Status: T3 server protocol (`_island` server, ids, slots, async, head, errors, policy recording) + T4 client driver (`/client`, `/dom`: policies, live props, hydrate-on-change, callbacks, intent replay, client mount, nesting) + T5 Vite integration (`rivet({ bridges })`: ownership, virtual facades, resume registration, manifest `islands`, dedupe, HMR) done; adapters live in `libs/bridge-<fw>` (`libs/bridge-react`: T6 done). User guide: `apps/docs/content/guides/components/framework-components.md` (update it with any user-facing change here).

## Layout

- `package.json`: `@rivetjs/bridge`, `sideEffects: false`, `rivet.source: true`, `#dev` import (`dev-on.ts` under the `development` condition, else `dev-off.ts`: `DEV`, `devWhere()`); peers `@rivetjs/runtime` / `@rivetjs/reactivity` / `@rivetjs/compiler`, optional `vite` ^8.3.2; `publishConfig.directory` `../../dist/libs/bridge`.
- `index.ts` (`.`): public types — `RivetContent` (Rivet content in a framework slot), `IslandOptions` (`client` / `preload` / `persist` / `fallback`), `IslandProps<P, Node>` (props whose type covers the framework node type `Node` accept `RivetContent`, + options), re-exported `ClientOn` / `ClientPolicy` / `PreloadStrategy`. Adapters' `types` modules build on `IslandProps`.
- `adapter.ts` (`./adapter`): contract types — `SlotMark`, `IslandContext` (`id`, `nonce` = runtime `_renderNonce()` (resumable renders only), lazy `signal`, `slot(name)`), `ServerAdapter` (`render` → `string | IslandRender | PromiseLike`, optional page-level `head(ctx)`), `ClientAdapter`, `IslandModule` (`__rivetIsland?` = island key, dev HMR), `IslandRender` (`{ html, head? }`), `ClientOn` / `ClientPolicy` / `PreloadStrategy`, `islandRecovered(framework, id, error, root?)` (RV2149: `console.error` with the code; dev also `error.island` on the devtools hook), `PolicyOptions` (captured: `id` + policy + object-form options), `IslandDef` (`id`, `c`, `a`, `chunk?` = island chunk URL for `_rPreload`, `head?` = head sink, kit `pushHead`); identity `defineAdapter`.
- `server.tsx` (`./server`): `_island(props, def, load?)` (facade ABI). Splits island props (`client` `preload` `persist` `fallback`: read once, never passed to the framework) from framework props; `children` → slot `default`, content props (`_slot` thunks, compiled JSX = `rivet.template` / `rivet.compiled` brands, arrays of them) → slots by key; the rest = framework props (values; adapters get a snapshot). Renders `adapter.render` → `splitSlots` → `[_markup(part0), content0, _markup(part1), …]` in a root; sync result written in place, a PromiseLike → `Async` (no fallback: awaited in ordered renders, streamed by a streaming `Suspense` above as a segment whose patch holds the island's records); `ctx.signal` created on first read and linked to the boundary's request signal. Head: `adapter.head` once per id scope (per island outside any scope); `IslandRender.head` → `def.head(head)` written before the root (kit decides shell vs late), no sink → dev warning, dropped. Errors (sync throw / rejection): `fallback` prop → static root with the fallback; else `Error("[rivet:bridge] RV2144 <fw> island <id> failed to render: <msg>" + devWhere(), { cause })`, which the nearest `ErrorBoundary` catches. A slot hole missing or written twice in the adapter output (a framework that rewrote the mark) = the same island error path in every build (`fallback`, else RV2144 `slot "<name>" has no hole …` / `has more than one hole`), never silently dropped content. `client="only"`: no render, no adapter page head (the next server-rendered island of that framework gets it), `fallback` in a hydrated root (`when: "load"`).
- `root.tsx`: island root element + hydration effect, compiled for both targets in resume mode — `_staticRoot(id, rf, rc, parts)` (nothing recorded), `_hydratedRoot(id, rf, rc, parts, load, props, options, when)` (root `ref` → `data-r`, one `clientEffect` capturing `load` / root / framework props (a `splitProps` part: forwarding getters stay live) / options, body imports `@rivetjs/bridge/client` lazily and calls `hydrateIsland` through `runWithOwner(getOwner())`; its cleanup stops a driver still loading). Plain functions, not components: parameters are values, so attributes and content are static markup (no resume sites). `data-rf` / `data-rc` dev only.
- `ids.ts`: `_renderIslands()` — island counter (`i0`, `i1`, …) + page-level head set per `withIdScope` scope (WeakMap; router opens one per request, segments continue it); outside any scope a process-wide counter (`_resetIslandIds()` for tests).
- `slots.ts`: `slotMark(name)` (`<rivet-slot [name] style="display:contents"></rivet-slot>`, default unnamed, name attribute-escaped), `splitSlots(html, marks)` → `{ parts, order }` (parts keep the hole tags around the cut; duplicates listed, missing absent).
- `client.ts` (`./client`): the island driver. `hydrateIsland(load, root, props, options)` (resume ABI, run with the island owner: `root.tsx` calls it through `runWithOwner`) → `_drive`: live-props `effect` over `callbacks(owner).snapshot(props)` (first run = the hydration values; later runs = one `adapter.update` per Rivet batch, or, no `options.on`, the start of a hydrate-on-change island: hydrate with the old values, then update); `start()` = `load()` → wait for in-flight nested islands inside the root (`pending` WeakMap) → `adapter.hydrate(root, C, values, slotNodes(root), { id })` (throw → dev warn, clear, `adapter.mount` with the same slot nodes) or `mount` (`only`, client-created: `clear()` the fallback, `replaceChildren`, root back to `display: contents`) → pending update + intent replay; owner cleanup → `unmount` (or never mounts when disposed while loading); chunk failure → static + one `console.error` (dev: id). `intent` → loads `intent.ts` on demand, then its listeners; recorded cold events replayed once after hydration. `slotNodes(root)`: `rivet-slot` holes whose nearest `rivet-island` is `root` → child nodes by name. `Trigger` / `_drive` shared with `dom.tsx`.
- `intent.ts` (`./intent`, internal): the `intent` policy, on demand (driver dynamic import; `root.tsx` prefetches it next to the driver for intent islands). `intent(root, listen, start, queue)`: island-local pointerover dwell (60 ms) / focusin / touchstart start it; the first cold `pointerdown` / `click` on the root are recorded. `redispatch(event)`: a cancelable copy on the original target (coordinates, modifier keys, `button` / `buttons`, `detail`, pointer fields), `preventDefault()` before dispatch + window capture guard (no second default action even when a handler stops propagation); checkbox / radio clicks pre-flipped so handlers read the user's resulting state, restored after.
- `callbacks.ts`: `callbacks(owner).snapshot(props)` + `kill()` (driver cleanup: every wrapper becomes a no-op, dev warns once) — reads every prop key into a plain object; function props → one stable wrapper per key calling the current function in `batch` (Rivet DOM written when the call returns; not `_dispatch`, measured spec §12), a throw → `_handleError(error, owner)` (rethrown to the framework when unhandled); return values pass through.
- `triggers.ts`: `trigger` — policy triggers of client-created islands (`load` / `only` now, `idle` + `timeout`, `interaction` = document pointerdown / keydown, `visible` + `rootMargin` over the fallback's boxes or the root as an empty block, `media:`); out of `client.ts` so the resumed driver chunk has none of it.
- `dom.tsx` (`./dom`): `_island(props, def, load?)` DOM variant (client-created islands: a `Show` branch first rendered in the browser, client navigation, client-rendered apps), untracked: `rivet-island[data-ri="c<n>"]` (dev `data-rc`), slot content (`children` + content props: nodes / `_slot` / arrays) rendered once into owned outputs (`_dom.output`) → `Node[]`, `fallback` rendered in the root until mount, `_drive(…, "mount", slots, clear, trigger)`. No loader → fallback only (dev warning). Dev: `claim(def.id)` reuses a parked root + handle (Rivet HMR re-render keeps the island mounted).
- `hot.ts` (dev-only, no top-level side effects): `track(island)` installs `globalThis.__rivetBridgeDev.replace(key, component)` (island module `import.meta.hot.accept` → swap the component in every live island of that key); `park(island, unmount)` keeps a disposed driver's root + handle for one task, `claim(key)` hands it to the re-created `_island` (else unmounts).
- `ownership.ts`: `ownership({ name, suffixes, pragma?, include?, exclude? })` → `{ owns, specifiers, configure }` for adapters' `BridgeEntry`; `jsxSource(name, source, owns)` (`rivet:<name>:jsx-source`, pre: leading `@jsxImportSource <source>` pragma on owned `.tsx` / `.jsx` without one, line-exact map; React + Preact adapters); `ownerOf(entries, root, file, source)` (two owners → RV2145 naming both), `specifierOwner`, `isPackageName`, `jsxImportSource`.
- `facade.ts`: virtual id constants (`virtual:rivet-bridge/core`, `virtual:rivet-island-def:`, `virtual:rivet-island-client:`, `virtual:rivet-island-pure:`), `exportList(code, star, lang, { wrappers })` (vite `parseAst`; island = capitalised non-ALL_CAPS / `default` export whose value is a function / a class that `extends` something (plain classes = models) or a `WRAPPERS` call (+ entry `wrappers`), followed through bindings (npm bindings by name); objects / schemas / enums are plain; `export default X` / `export { X as Y }` of an exported component = one island (alias; `islands.exclude` of either name makes it a plain re-export); SFCs: `default`), `exportsOf` (memoised walk, cycle-safe), `facadeSource` (identical TSX for both environments: content-hash ids agree), `serverDefs` / `clientDefs` / `islandModule`.
- `vite.ts` (`./vite`): `bridgePlugin(entries)` (`rivet:bridge`, enforce pre) used by the compiler's `rivet({ bridges })` (`bridgeHost` imports it lazily from the app root). `resolveId`: a Rivet importer (not node_modules, not owned) of an owned file / npm specifier → `\0rivet-island:<target>.tsx` (target = file or `npm:<spec>`); `load` facade / defs / island module; `api.rivetBridges` for the compiler (owner, facade, sources, `islandKey`, `islandModule`, `seeds` = `root.tsx`); `config` dedupe + `optimizeDeps.include`; `hotUpdate` (export-list change → island + def + facade modules); `generateBundle`: RV2146 (non-component exports in the client bundle via `renderedExports`) + `[rivet:bridge] <page>: <fw> N KB br` + `[rivet:bridge] unused islands (…): <keys>` (island chunks no Rivet module imports; importer bindings parsed from source). `BridgeEntry.islands.include` forces islands, `exclude` (wins) drops them (names / key patterns); owned-import resolution cached per importer + specifier. Island key = `<root-relative file (incl. `../` outside the app root, never an absolute path) | npm specifier>#<export>`, resume module id `<key>.island`; `manifest.islands` maps keys → chunk URLs (preload + T7b lean records). `persist.ts` (`./persist`): placeholder (T12).
- `lean.ts` (T7b, internal): islands-only lean tail. `offerLean(id, key, on, props, blocked, dev)` (called by `server.tsx` `_island` for every hydrated island, before `_hydratedRoot`) adds the island to the render's collector (`_rLean(create)`, runtime) or records why it needs the full driver (`slot "<name>" holds Rivet content`, `client="intent" (cold-event replay)`, live props without a policy, a getter reading a signal (`_trackReads`; a getter reading none, e.g. `rows.map(…)` / `t("x")`, is sent as its value; caveat: a read inside `untrack(…)` is invisible to `_trackReads`, so such a prop is sent as a constant and never updates the island), a function / non-JSON prop: first reason only). At shell end the runtime calls `Lean.tail(view, deferred)`: lean iff no blocker, no Rivet resumable besides the islands' own `_hydratedRoot` effects, regions and client events (handler / binding elements, texts, other effects, asyncs, links, paths block; `lists` ignored), island effects = accepted islands, and `manifest.islands` maps every key → tail = `<script type="rivet/islands">[[id, url, props, on, prefetch?], …]</script>` (`prefetch` = chunk + `deps`, every policy except `interaction` / `media:`) + `<script>BOOT</script>` (nonce on each); no `<link rel="modulepreload">` tags (LCP fix 2026-10-13: high-priority preloads of the `load` chunks sat on Lighthouse's simulated FCP / LCP path, 2.6–4.6× rivet-full). Else `null` → full tail; dev (`server.tsx` `DEV`): one `console.info("[rivet:bridge] full resume driver for this page: <why>")` per distinct reason (dedupe set capped at 256).

## Rules

- `rivet.source: true` here only: the core's `.tsx` (`server.tsx`, `dom.tsx`) is Rivet code compiled in resume mode with stable ids (`libs/compiler/vite.ts` `sourcePackage`); adapters (`@rivetjs/bridge-<fw>`) never set it, their JSX belongs to the foreign framework.
- Naming: "island" = framework island only. Rivet's chunk-grouping component is `ChunkGroup` (`resume.chunks: "group"`; renamed from `Island` 2026-10-12, spec §11 Q3).
- Zero-cost: every subpath tree-shakeable, `sideEffects: false`; the core never imports an adapter (the generated facade imports exactly one); dev-only attrs / hooks (`data-rf`, `data-rc`, `__rivetBridgeDev`) never in a production entry. `scripts/zero-cost` gates every bridge entry since T4 (`packages-hashes.mjs` lines, `dev-leaks.mjs`: `dev-on.ts` + the driver / DOM `_island` dev warnings); size-report entries land with T16.
- Live props: every framework prop is live (value or getter, forwarded unread to the hydration effect). Exceptions, read once by `_island`: `client` / `preload` (they pick the effect and the preload at render time), `persist` (T12: the parking key of one render), `fallback` (Rivet content, rendered in place).
- Facade shape (T5 generates it; tests use it): `function loadX() { return import("<island chunk>"); }` at module level + `export function X(props) { return <>{_island(props, ISLAND_X, loadX)}</>; }`. The loader resumes by reference (`_rMod`) only as a named module function used inside a JSX-returning component; an inline arrow argument or a member of the module-level `ISLAND_X` object is not resumable (render error "function is not serializable").
- `_island` (server and DOM) runs untracked: the facade's `{_island(…)}` child must record no binding over the props (else a resumed page re-creates the island on the first change: test `state.b` empty + `resume-browser.test.ts`).
- A static island (no `client`, no getter prop) records nothing: a page with only static islands ships no state / loader (test). A getter prop + a loader = idle hydrate-on-change effect (spec §3.6), no chunk preload.
- Islands-only lean client (T7b, spec §3.12): decided per render, exactly — any Rivet resumable other than regions / `intent` client events, slot content, `intent`, live / callback / non-JSON prop or a missing `manifest.islands` entry keeps the full driver. File-router pages (router region + navigation `clientEvent`s, `libs/router/build/codegen.ts`) take the lean tail + a deferred, non-booting state (D-lean): islands hydrate exactly as their `client` policies say, only Rivet's own navigation / resume loader waits for the first link intent / click. Fetch-ahead policy: router document prefetch on (`rivetRouter({ prefetch })` → generated `fetchAhead` → `preload.ahead`) = the runtime + router chunks are modulepreloaded at low priority after `load` + fonts + the first `paint` entry (no entry type → no wait; 1 s cap) + idle (`resume-loader-module.ts` `fetchOnly`; the paint gate keeps them off Lighthouse's FCP / LCP graph, bridges demo `/`) (fetched, never evaluated: test `lean-deferred-browser` counts module evaluations); off = nothing before intent (first client navigation waits for the runtime: apps/bridge-demo Fast 3G 3.2 vs 1.7 s, smoke). Lean and full read the same build manifest (no build flag); `boot.ts` triggers mirror `dom-resume` `when` and `client.ts` recovery — change them together.
- `.ts` modules never import `@rivetjs/runtime/dom` (not server-rewritten); resumable code goes in `.tsx`.
- Installs: framework packages only with the user's permission (one ask per task, name + size). Root has `react` / `react-dom` 19.3.0 (hoisted from `apps/dom-bench`).

## Gotchas

- `@vitejs/plugin-react` 6.x is the Vite 8 line (peer `vite ^8.0.0`; 5.x stops at Vite 7): `@rivetjs/bridge-react` peers `>=6.0.0 <7` (the plan's `>=5 <6` predates Vite 8.3 in the repo). Optional peer: Vite 8's oxc transform compiles React JSX without it (no Fast Refresh) — decided in T6; either way `react()` adds `rivet:react:jsx-source` (leading `@jsxImportSource react` on owned JSX files), since a tsconfig `jsxImportSource` beats Vite's global oxc JSX options.
- Error precedence (deviation from spec §3.9, which puts the boundary first): the island's own `fallback` wins over an enclosing `ErrorBoundary` — the core cannot see whether a boundary is above it (no runtime hook), and the island is the nearer handler. Without `fallback` the RV2144 error reaches the boundary.
- Visible preload of an island chunk (T5 ruling, spec §12): `[chunk, "P", []]`, no element ids. A React-sized closure (≈ 220 KB min) fits the 1 MiB background budget → idle prefetch; past the budget the island's own `visible` trigger still loads it. T7 bench (`docs/benchmarks/2026-10-12-islands.md`): visible / idle first-input-to-paint TIE with Astro in both conditions, kept; the bench's losses are bytes + JS requests before input (resume runtime on an islands-only page, ungrouped chunks) → plan T7b.
- Resume builds emit an island chunk for every island export of an owned module (unused ones too: listed in the build log).
- Rolldown `this.load` in `buildStart` returns no code: export lists parse the source file (`exportsOf`). Facade ids carry no `?env=`: environment-specific code only behind the virtual imports, or server and client symbol ids diverge.
- Fixture HMR / build tests write under the repo-root `.artifacts/bridge-<name>-*` (copied app); `tests/fixtures/app` is excluded from the bridge tsconfig.
- Driver bytes (rolldown min / gzip / br, 2026-10-12, T4 review fixes + T5): `/client` 2,159 / 1,151 / 1,034 B (prod; dev HMR code stripped) (spec §3.6 target ≈ 1 KB br; client-created triggers in `triggers.ts`, intent in `intent.ts` 1,275 / 599 / 501 B).
- `intent` replay records on the island root once the hydration effect started and `intent.ts` loaded: a click before that is not replayed (spec §3.5 named the loader's cold event snapshot; it records only elements with Rivet handlers). Follow-up T-INTENT-COLD in the plan (delegated `data-r` marker on intent roots). Replayed events carry `defaultPrevented === true`.
- Slot content renders lazily during traversal (like any Rivet `children` thunk): element ids inside a slot may be numbered after later siblings; resume does not depend on id order.
- The T1 spike harness (`bytes.mjs` / `cpu.mjs`) is not committed; the island bench (T7, `apps/island-bench`) replaces it.
