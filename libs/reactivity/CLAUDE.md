# @rivetjs/reactivity

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Push-pull signal graph: signals, lazy computeds, effects, owners/disposal, context, batch, untrack, error routing; plus resume/runtime ABI (`_*` exports) the compiler output and `@rivetjs/runtime` rely on. Zero deps.

## Layout

Flat by design: one file per public subpath, dev façade beside it. Not converted to `<name>/index.ts` folders — other packages import these files by path (`libs/runtime/tests/resume/harness.ts`, `libs/runtime/tests/dom.test.ts`, `libs/cdk/tests/browser.ts`, `vitest.config.ts` → `tests/dev-hook.ts`, docs links).

- `index.ts` — whole engine (Owner / Node / ComputedNode / Source classes, track, mark, flush, dispose) + public API + `_*` ABI. Hot file.
- `dev.ts` — development façade: `export *` from index + wrapped `signal`/`computed`/`effect`/`batch`/`createContext`/`useContext`/`_bindingEffect`/`_bindingEffect1` (→ tracked `() => fn(a, b, c)`) reporting to the devtools hook (+ `_dispatch`: `event.defer` before a trusted mouse click, level 2); computed pins, `notify`; AggregateError flush reporting. Dev-only checks at every hook level (0 prod B): unbound `set`/`update` → readable TypeError (shared this-checked methods; prod fails opaquely); effect returning a function → one `console.warn` per effect (ignored, use `onCleanup`); first read of a disposed computed → one `console.warn` (getter wrapper carrying the `rivet.computed` symbol, so `_inspect`/`_trackReads`/`_debug`/resume see the computed). Every dev warning appends `where()` = the `Symbol.for("rivet.locate")` hook's line (runtime `dev/where.ts` component chain in the browser, compiler `vite.ts` app frame on the dev server; "" when absent; DIAG-VERBOSE).
- `track.ts` (`@rivetjs/reactivity/track`, DIET-CODE 2026-10-22) — `_trackReads` + its collector, `_ownedReads(owner)` (M6-CUT: leaf signals every effect / computed owned under `owner` read, through computeds — the derived lazy-list sample root) (`unique`, `collectThis` / `collectKey`, `collect`, `walk`, frozen `EMPTY`). Own module so a client build places it in its callers' chunk (derived runtime `dom-derived.ts` lazy lists, dev tools) instead of the eager reactivity chunk (measured on the serialized model, DIET-CODE: lazy-row apps' eager runtime −1.26 KB min / −0.34..−0.41 KB br; every other entry −18 B (the top-level `Object.freeze([])` call no longer kept). Reaches the engine through `index.ts` ABI exports `_swapObserver` (set the current observer, return the previous), `_keyedRead`, `_COLLECTOR` / `_SOURCE` + type aliases (`_Collector`, `_Node`, `_Source`, `_Selector`, `_KeySource`, `_Getter`, `_Tracked`). Same `./index.ts` instance as the dev façade (`dev.ts` re-exports index), so no development variant. Browser test harness maps the specifier (`libs/runtime/tests/resume/harness.ts` `/track.mjs`).
- `debug.ts` — read-only views; finds internal symbols/prototypes by probing (not exported by index.ts). Field names mirror index.ts.
- `store.ts` — one signal per *read* path, nodes created lazily; immutable data, writes copy containers along the path; `produce` = copy-on-write Proxy drafts (revoked after); `refresh` prunes unobserved nodes of removed keys (+ their cache entries). Reads the signal's internal `observers` via the probed `rivet.signal` symbol (same coupling as debug.ts).
- `store-dev.ts` — façade: `createStore` emits `store.create { store, owner, tree }`.
- `tests/` — vitest suites (`*.test.ts`) + `dev-hook.ts` (`--import` preload: recording hook level 2, stacks on).
- `bench/bench.ts` (vs `@solidjs/signals`), `bench/store.ts` (store vs Solid proxy store).

## Engine model (index.ts)

- Kinds `OWNER 0, COMPUTE 1, EFFECT 2, COLLECTOR 3, SOURCE 4`; states `CLEAN 0, CHECK 1, DIRTY 2`.
- Push: write marks direct observers DIRTY, below a computed CHECK; effect queued on first mark. Pull: CHECK pulls upstream computeds, runs only if one changed; equal recompute stops propagation.
- Deep chains: `mark` is an iterative depth-first walk in observer order (`marking`/`positions` stacks; queue order = recursive order); `checkSources` pulls iteratively (`checking`/`indexes` stacks). Writes / updates through 20k+ computed chains don't grow the stack (Solid 1.9 overflows at ~7.8k, Solid 2 at ~5.7k). Only a lazy *first* read of an unevaluated chain recurses (get → run → fn per level: ~2.4k levels prod, ~1k under dev wrappers); deferred: needs an abort/retry trampoline that user `try/catch` in computeds could swallow.
- Failed computed caches its error (`fail`: `flags` FAILED set, READY cleared, `value` = error, CHECK consumers → DIRTY): reads rethrow it without re-running until a source changes (TC39 / Angular / Preact semantics); recovery always notifies. `equals` is called as a plain function (`this` undefined).
- `run` collects every failure: cleanup errors (reset) + the run's own; an effect rethrows the first, a computed caches it; >1 → `_flush.report(errors)` (also from `dispose` and `catchError` sync failures). One try/catch/finally per run (smaller frame).
- Duplicate links: a read whose source was last seen by a newer (nested) run scans this run's links (`linked`) before linking — no double subscription when a nested computed read the same source in between.
- Writes outside a batch flush synchronously. `batch` defers to the outermost exit (also on failure). Flush = index loop over `queue`; work queued mid-flush runs same pass.
- Owner-first flush: when `nested` (an effect with children queued), the top-most dirty owner effect runs before the child (no zombie children). `topDirty`: ≤ `LONG` (32) ancestors walk directly; deeper chains continue through `verified` (Set of owners with no dirty effect at or above them; valid while `queue.length` is unchanged — only a newly queued effect can dirty a chain; cleared at flush end): O(owners) per wave, not O(queued × depth) (context suite `themed-500` update 2.83 → 1.32 ms; Solid 6.0). Regression tests: `tests/context-frames.test.ts` (a stale `verified` fails them).
- Context frames: every owner has `ctx` = nearest `Frame { token, value, up, owner, memo }` (inherited in the `Owner` constructor; `provide` / `catchError` push one, `owner` = the providing owner). `useContext` walks frames (providers), not owners; a lookup passing `MEMO` (8) frames memoizes token → providing frame (null = default) on the starting frame (`remember`; frames are immutable, so never stale). `handleError` walks frames too (handler runs with `frame.owner` current). Context suite: providers-50 DOM mount 2.68 → 0.58 ms, deep-500 1.55 → 1.24 ms; heap +~0 (one pointer per owner).
- Effect init stack: `initializeEffect` / `_bindingEffect` call `run` in their own frame when already batching (every nested effect) — one / two frames less per nested reactive level: cold deepest nested-component tree 775 → 1064 levels (Solid stable 632; `apps/dom-bench/context` `--max-depth`).
- Infinite-loop guard: >10000 repeat runs of one effect in one flush → error; counts live in a side `Map`, not on nodes.
- Flush failures: first error rethrown; `_flush.report(errors)` sees all (prod: rest → `reportError`/`console.error`; dev: one AggregateError).
- Signal writes inside computed evaluation throw (`computedDepth`). Circular computed → throws.
- Owners: children in doubly linked list, newest first; dispose is iterative and allocation-free (no stack: enter = mark disposed + detach, descend to oldest child via `next`, leave = cleanups, then newer sibling via `prev`, else parent); children before parents, creation order; `first` cleared on leave; cleanup errors collected lazily, first thrown. `reset` (re-run) disposes children oldest→newest via `prev` without arrays. Disposed nodes drop `fn` (shared no-op), keep `value` (disposed computed reads stay stable).
- Effect init runs directly (no `batched` wrapper) when already batching/flushing.
- `catchError`: handler stored in the frame it pushes (`ctx`) with `handleError` as private token; throwing handler forwards upward. Handler runs with the catchError owner current (`getOwner()`, `useContext` work during flushes), untracked. A sync throw disposes what `fn` built first (`reset`). Synchronous only: dev façade warns when `fn` returns a thenable.
- `selector(source, fn?, { keys? })` (Solid `createSelector`, lane IMPL-SELECTION 2026-10-09): `sel(key)` = `fn(key, source())` (default `key === source()`); a tracking reader subscribes to a per-key observer-only `Source` (`value` = its `Selector`, `getter` null) instead of `source`. One owner-free watcher effect (created on the first tracked read, `adopt(null)`) re-reads `source` and marks only keys whose `fn` result changed — the `keys(next, previous)` hint limits the compare (cdk Set selections: symmetric difference), else every subscribed key; with the default `fn` and no `keys` the hint is `pairKeys` (sentinel: `selectorRun` looks up the `next` / `previous` keys directly, no array — Solid parity; krausest select 0.37 → 0.19 ms, the full compare was O(rows)). Every `SWEEP` (16)-th change compares all keys and drops unobserved ones; no key left → the watcher disposes itself (re-created by the next tracked read), so it never outlives its readers by more than 16 changes and can never miss a change while a reader exists. Subscribing is O(1) without a hash insert (lane IMPL-ROWCREATE 2026-10-09): a tracked read reuses the reader's own source at its tracking cursor (re-runs), else `last` (consecutive readers of one key share a source: an option's bindings, every item's `isSelectionEmpty` key 0), else the indexed `subs` head, else appends a fresh `KeySource` (`key`, `same` chain) to `pending` and schedules `fold` (one `setTimeout(0)` task per batch, `unref`ed) that moves live pending sources into `subs` (key → chain; `notifyKey` walks it, drops unobserved ones). A change before the fold also `scanPending`s (plain compare loops: pair keys / small hint inline / larger hint Set / all). Not an idle callback: cdk ListBox first update after mount 0.06 → 0.14 ms (scan) with `requestIdleCallback`; with the timer it stays 0.06 (table 0.14 → 0.16, noise), heap equal (3391 / 3402 KB). `pending` drops unobserved sources when it doubles (`limit`); every SWEEP-th change folds first. Readers leaving release their keys without a selection change (lane PERF-MEM 2026-10-09; 6486a443 had dropped the insert-time sweep, so run / clear cycles kept every key ever read: 5000 `KeySource`s + Map backing = 346 KB after krausest 25's 5 cycles): key sources carry the sentinel `equals` `KEY`; `unsubscribeLast` calls `selector.dropped()` when one loses its last reader (inline observer, or an observers array emptied → collapsed to `null`, so several readers of one key are seen too); that schedules the fold (`foldTask`, same timer, once per batch), which prunes dead chains from `subs` (`dead` flag) and, with no key left, disposes the watcher (as the sweep does). Cost on every other source: one `equals` compare on the last-observer unlink; the call goes through the `Selector` instance (no selector code in bundles without `selector`). krausest 25_run-clear 1.733 → 1.40 MB (Solid 1.31), local_clear 1.391 → 1.334. Tests: "run / clear cycles … bounded", "a key read by several readers is dropped …" (`v8.queryObjects` count of key sources). Measured: node binding+selector read 228 → 109 ns/row (= a plain signal read); krausest kops (sync click, 4× CPU) overhead above vanilla run1k 3.12 → 1.94 ms (Solid 1.73), create10k 30.0 → 21.0 (Solid 21.5) incl. the probe counter below; select unchanged (0.09 / 0.10). Inside a batch a reader evaluated before the flush first `update`s the dirty watcher (sees the new value); a computed cached before the write keeps its value until the flush. Untracked reads and disposed observers read `source` directly; a `_trackReads` collector calls its `key` method (`collectKey`, LAZY-T6): with a `keyed` hook that accepts `(source, kind, key)` (kind 0 = `pairKeys`, 1 = `memberKeys`; source must be a plain signal getter; `keyedRead`) the source is read untracked and NOT added to the collector (server lazy rows record the read per key), else `fn(key, source())` tracked as before (whole-For wake); `walk` follows a key source to the watcher's sources (a computed that read a key reports the real signal to resume). `debug.ts` views of key sources: `ref` = the source, no `getter`. Tests `tests/selector.test.ts`. Consumer: `libs/cdk/selection/keyed.ts` (cdk ListBox 1000 options, change 1 selection: 2.4 → 0.06 ms; GridList 2.7 → 0.04, Tree 89 → 0.28, Table 8.5 → 0.12, Menu 1.7 → 0.04). Tree-shaken when unused (own class + 3 functions; `walk` only reads `.node`).
- `createRoot` attaches to the current owner (disposed with it; server-only exception: a root `_detach`ed by streaming) — differs from Solid's detached roots, documented in `apps/docs/content/start/coming-from-other-frameworks.md`; runtime/cdk rely on it (`dom-derived.ts` adopt owners, `cdk/virtualizer` effects).

## Runtime / resume ABI (`_*` exports — compiler & runtime depend on these)

- `_trackReads(fn, arg?)` (from `@rivetjs/reactivity/track`) — run `fn(arg)` untracked by caller (SRV-ROWFN: `_rAttr` passes the captures array), return `{ value, signals }` (third arg `keyed`: optional `KeyedRead` hook for selector reads, also consulted by `walk` for key sources reached through a computed; LAZY-T6): leaf signals read, through computeds, deduped in first-read order (server-resume region recording). Collector passes through `createRoot` / `runWithOwner` / `_rootIn` (`keepCollector`); a nested `_trackReads` does not forward to the outer one (rejected: S9). Collector = array of signal getters / computed nodes, deduped by `includes` up to 16 then a Set; no computed read → that array is `signals` (no walk); computed → closure-free depth-first source walk; nothing read → shared frozen `EMPTY`. `track()` reaches the collector only through the collector's own `add` (`node.add(source)`; one shared module function `collectThis`, `this` = collector — no closure per `_trackReads` call: resume lane −1.25 MB/req at 1000 rows), never by calling `collect` directly — keeps `collect`/`unique` tree-shaken out of bundles that never call `_trackReads` (−288 min / −73..−80 br per client app, krausest 5817 → 5716 br). `signals` is read-only for callers (server-resume / dev/dom only iterate, `some`, `includes`, `length`, `map`).
- `_inspect(fn)` — classify getter without reading: `{kind:'signal', value, equals}` / `{kind:'computed', equals}` / null.
- `_bindingEffect(fn)` — DOM binding effect; inert leaves (no sources/children/cleanups after init) are disposed immediately unless an owner was handed out (`getOwner`/`computed` getter) during its initialization: `observeOwner` bumps the `observations` counter, a binding compares it before and after its first run (conservative: any hand-out keeps the bindings initializing around it; replaced per-binding probe stacks, node binding create 157 → 104 ns). `_observeBindings()` disables release — called by debug.ts at import only when a devtools hook already exists (`globalThis[Symbol.for("rivet.devtools")]`; the agent and `tests/dev-hook.ts` install it before any reactivity module evaluates); without a hook, importing debug keeps production release behaviour.
- `_bindingEffect1(fn, a, b?, c?)` — closure-free `_bindingEffect` (OPT-D, DOM v2 `_fx1`): compiled templates hoist the binding to a module-level `fn` and pass up to three captures; runs `fn(a, b, c)`. Own class `ArgNode extends Node` (`call`, `a`, `b`, `c`; `fn` = shared `callArg`, which `run` calls as a method — `run` and effect/computed shapes unchanged: an extra `value`/arg slot on every effect measured dispose 2.3 → 4.6 ms per 100k after a forced GC). Same release rule (observation counter) as `_bindingEffect` (body duplicated: no extra frame per nested binding). Heap per signal+binding: Node 408 → 344 B, Chromium 204 → 172 B (1 capture), 297 → 257 B (element + 2 captures, a captures array saves only 4–12 B); fan-out update +~3% (one trampoline call). `_wrapEffects` set → wraps `() => fn(a, b, c)`. Tests: `tests/binding-effect1.test.ts`.
- `_rootIn(parent, fn, holder)` / `_dispose(root)` — list-row roots without closures/result objects.
- `_detach(root)` — unlink `root` from its parent (`unlink` + `parent = null`): the parent's disposal no longer reaches it, its own disposer does; context / catchError frames stay (inherited at creation). No-op on a disposed root (its `unlink` already ran; a second one would reset the parent's `first`). Server streaming only (`@rivetjs/runtime` `server-async.ts` / `server-suspense.ts` streamed roots, `server-resume.ts` ErrorBoundary pins). Dev: `useContext` provider reporting (`dev.ts`, devtools hook level ≥ 1) walks owner parents, so under a detached root it reports `provider: null` while the value is right (frames). Tests `tests/detach.test.ts` (middle / newest child, disposed root).
- `_scoped(fn)` — `fn` as an accessor whose every read runs in a fresh child scope of the creation owner (context lookups see the creation site's providers) while the reader keeps tracking; the previous read's scope is disposed on the next read and with the reader; no owner → `fn` itself. Used by DOM v2 `_scoped` (dynamic fragment children, re-exported by `dom-v2.ts`) and cdk live collection content (`place()`).
- `_observer()` / `_reobserve(observer, fn)` — capture the current observer (opaque) and run `fn` with it as the current observer: re-enter a tracking scope from an untracked component body. Only while that observer runs synchronously. Consumer: cdk collection build pass (`libs/cdk/collections/components.tsx` `tracked`). Separate functions, no hot-path change; tree-shaken when unused (+113 B min / +25 B gzip on the entry bundle only).
- `_hiddenRoot(fn)` — RAC hidden render for the cdk collection build pass (TITLE-JSX 2026-10-29): runs `fn` in a fresh root that inherits the current owner's context frames but is not linked to it (the running computed's next run does not dispose it), still tracked by the current observer, with signal writes allowed (`computedDepth` 0 inside, restored after; outside it computeds stay pure). Returns the root when its subtree holds an effect / computed / cleanup (walk of the owner list), else null; a throw disposes it. Dispose with `_dispose`. Consumer: `libs/cdk/collections/components.tsx` `segment`. Tests `tests/hidden-root.test.ts`.
- `_wrapEffects(wrap | null)` — wrap the function of every effect created afterwards; `server-derived.ts` binds effects created during a resumable render to that request's `AsyncLocalStorage.snapshot()`, so a re-run triggered by another request's write records into its own request (C16). Unset in browsers (one null check in `reactive`).
- `_scheduleFolds(run | null)` — schedule the keyed selectors' index folds (`selector`, `later`) through `run` instead of `setTimeout(fn, 0)` (unref). `server-derived.ts` creates the fold timer in an `AsyncLocalStorage.snapshot()` taken at module load (outside every render): a Node timer keeps the async context it was created in, so a fold scheduled inside a render kept that render's recorder (and every record / computed / row) alive until the timer phase — VIRT-LEAK 2026-10-21, runtime CLAUDE.md "Server memory". `run` must call `fn` in a later task. Unset in browsers (one null check per scheduled fold).
- `_dispatch(owner, handler, target, event, onError?)` — every DOM event handler (v2 `_on`/`_listen`/`_spread`, v1 `bindEvent`, `clientEvent`, resumed `dispatch`): batched under `owner` (dropped once disposed). Deferred click flush: the first `isTrusted` `click` with `pointerType` "mouse" per document (`event.view` in a lazy WeakSet `settled`) whose handlers queued effects, outside a batch/flush → handler + writes synchronous, flush in a MessageChannel task (`hold` / `release`; port unref'd in Node). Same event's later handlers share it (`heldEvent`). Pending flush (`held`, null otherwise) runs first on another event's `_dispatch`, every `batched` entry and every `signalSet` (one null check each — the only cost for pages without handlers). `release` routes the flush failure to `onError` ?? `reportError` ?? `console.error` (owner handlers first, inside `flush`). `_settle()` = run it now (`@rivetjs/runtime/testing` `flush`, `@rivetjs/testing` `act`). Why one-shot: Chrome stalls the frame after the first DOM-changing mouse click of a tab (click→paint headless 45–62 ms sync vs 32 deferred; headed 47 vs 13) but later clicks paint faster sync (16 vs 32 / 6 vs 13); keyboard / touch measured slower deferred. Tests: `tests/dispatch-defer.test.ts`; Chromium: `libs/runtime/tests/click-defer-browser.test.ts`. Details: `docs/guides/resumability.md` "First mouse click".
- `_deferredFlush()` — true while a deferred first-click flush (`release`) runs. `@rivetjs/runtime` dom-v2 `drop` / `swap` read it: the removed old node under the pointer (`:hover`) is hidden (`display:none`) and detached in the next rAF, because Chrome holds the frame ~50 ms after the hovered element is detached on a document's first mouse click. Navigations no longer opt out of the deferral (the old `_flushInEvent` is gone).
- `_bindingOwner()`, `_tracking()`, `_untrack1(fn, arg)`, `_handleError(error, owner)`, `_observeOwner`, `_flush`.
- Consumers: `libs/runtime/dom.ts`, `dom-v2.ts`, `dom-derived.ts`, `server-derived.ts`, `server-cache.ts`, `server-shell.ts`, `dev/dom.ts`, `libs/cdk/collections/components.tsx` (`_observer` / `_reobserve` / `_hiddenRoot` / `_dispose`). Compiler (`libs/compiler/rust/src/resume.rs:977,1191`) treats `signal`/`computed` imported from `@rivetjs/reactivity` as serializable state creators — keep names/import specifier.

## Rules / invariants

- Zero-cost: production bundles of every subpath (+ `runtime/hot-reactivity`) are hash-pinned in `scripts/zero-cost/runtime.txt`. Any byte change in `index.ts` / `store.ts` / `debug.ts` changes hashes → needs intended `--update`.
- Never add exports to `index.ts` for tooling: entry bundles keep all exports. Debug/dev code goes in `debug.ts` / `dev.ts` / `store-dev.ts` (production resolution never reaches façades).
- Façades must stay transparent: same export set as base (`tests/dev-facade.test.ts`), add no observers, no change to laziness or flush order; without a hook nothing is reported (the dev-only misuse checks above still apply).
- `debug.ts` couples to index.ts field names (`sources`, `observers`, `slots`, `kind`, `state`, `flags`, `ctx` frame + its `owner`: a view reports `token`/`context` only when `ctx.owner` is itself…) — `tests/debug.test.ts` pins them; rename both together.
- Perf shape (V8 hidden classes / memory): fields initialized in one constructor order; computed-only fields in `ComputedNode` (effects don't reserve them); `ctx` (frame pointer) on every owner, set in the constructor (one shape for providers and others); single link inline (`Links<T> = T | T[] | null`, smi slot) promoted to arrays on second link; one cleanup stored as function, not array; run/outcome booleans packed in one `flags` smi on `Node` (`RUNNING 1 | FAILED 2 | READY 4`; computeds carry no `failed`/`ready` fields — `debug.ts` reads `flags & 2`); computed getter = `computedRead` bound to its node + own `[COMPUTED]` prop, effect disposer = `disposeThis` bound to the node (bound functions, no closure + context each; OPT-D 2026-10-07: heap per signal→computed→effect 808 → 744 B (Node, no pointer compression), bench.ts create −20% / churn −7% / chain −6%, but `diamond` (reads through `reduce`) +~6% median; lazy first-read depth unchanged 2586); `signal` = bound `read` + shared `set`/`update` (no per-signal closures; keep it at 3 own props (`set`, `update`, `[SIGNAL]`): V8's out-of-object property store holds 3, a 4th grows it — `signal.peek()` was tried and reverted 2026-10-07 for +~15 ns per created signal (1M: 35.6 → 50.5 ms); untracked reads use `untrack(sig)`); computed-only logic (`check`, `exec`, `settle`) unreachable unless `computed` is used (tree-shaken).
- Dependency tracking reuses previous-run links while read order matches (`cursor`); divergence → `cursor = -1`, suffix unlinked. O(1) unlink via slot swap.
- No semantic trades for bundle size (repo-wide decision).

## Gotchas

- Shape pins (lane DEPTH): `adopt` creates one parentless `Owner` + effect `Node` on first use, `computed` one `ComputedNode`, `_bindingEffect1` one `ArgNode` — V8 clears class maps after a full GC with no instance alive and deopts everything that embedded them (context suite DOM themed-500 mount 1.26 → 1.05 ms, dispose 0.095 → 0.02). Keep them; a new hot class needs the same.
- `set`/`update` are `this`-methods: never pass `get.set` unbound (use `(v) => get.set(v)`, as `bench/bench.ts` does).
- Same for app code: `const { set } = count` or `onChange={count.set}` breaks — bind it.
- `untrack` blocks the `_trackReads` collector too; `createRoot` / `runWithOwner` do not (server regions must see reads made while constructing).
- `_bindingEffect` releasing inert leaves means `getOwner()` inside a binding marks it escaped (kept alive) — intended; don't "optimize" away `observeOwner` calls.
- `onCleanup` outside a live owner throws; `onCleanup(nonFunction)` throws TypeError at registration (prod: matches the other misuse guards, which throw in prod; before it failed later at dispose); `runWithOwner` / `_rootIn` with disposed owner throw.
- Store `write`: a function argument is always an updater (types reject raw function values: `StoreUpdate<V>` excludes callables; store one via `() => fn`); writing below a primitive (`"a.b"` over `a: 5`) throws TypeError (null/undefined containers are still created).
- Store: data is immutable — mutating a read value in place notifies nothing; use `write` / `produce`. Nodes exist only for read paths; lookup map is never serialized (rebuilt after resume). Pruning drops only nodes of removed keys with no observer in their subtree (a server write removing a key whose path a binding recorded via `_trackReads` would drop it — collectors are not observers).
