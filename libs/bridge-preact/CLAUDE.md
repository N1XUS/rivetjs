# @rivetjs/bridge-preact

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Preact 10.29+ / 11 adapter for `@rivetjs/bridge` (framework islands). Spec `docs/design/specs/2026-10-11-framework-bridges-design.md`, plan `docs/design/plans/2026-10-11-framework-bridges.md` (T8). Status: T8 done — SSR (sync string, async fallback for suspension), hydrate / mount / live-prop updates / unmount, slots, `preact()` Vite entry, JSX types; coexists with `@rivetjs/bridge-react` in one app. Upstream costs in `libs/bridge/CLAUDE.md` "Upstream costs".

## Rules

- Only documented Preact entry points (`preact`, `preact/hooks`, `preact-render-to-string`) plus one private field: the vnode `useId` mask `__m` (mangled `_mask`, stable across 10.29 and 11; `tree.ts`). A Preact that moved it is caught at runtime (server probe → RV2150, `libs/compiler/codes.json` + `libs/language-core/explain.json`) and in CI (`ssr.test.ts` id assertions, hydrate tests).
- Never imported by `@rivetjs/bridge` core; only generated facades import an adapter.
- No `"rivet": { "source": true }` (same rule as every `@rivetjs/bridge-<fw>` adapter, see `libs/bridge-react/CLAUDE.md`).
- Signals in props (passing a Preact `@preact/signals` signal through an island prop): out of scope for v1; island props are plain values / live Rivet props.
- Hydration mismatch: Preact patches mismatched text in place (no throw, no recoverable-error hook) → no RV2149 for Preact islands. Attributes / props are never patched: hydration does not diff props, and later renders diff the client's previous props against the new ones, so a prop whose value differs between server and client but never changes afterwards keeps the server value in the DOM for good. Keep island render output identical on both sides (same rule as RV2149's fix). A structural mismatch (another element type) goes through Preact's own debug hook (`preact/debug`), not through the bridge.
- `lazy` (`preact/compat`) needs a `Suspense` boundary: a bare root `lazy` rejects in `renderToStringAsync` and is reported as an island SSR error.
- `renderToStringAsync` takes no abort signal: a slow suspending island is not cancelled by the request's signal.
- `stopPropagation` in a Preact handler: listeners sit on the elements themselves, so it stops the native event before island ancestors.
- No island head: Preact has no hoistables, so a `<title>` / `<meta>` inside an island renders inline in the island's HTML (`ssr.test.ts` pins it). Page head = Rivet's (`@rivetjs/kit` head components / route `head`).
- `@preact/preset-vite` aliases (`react` → `preact/compat`) are off: they would capture a React bridge's imports. The preset path is untested until the T16 matrix (the preset is not installed in the workspace): its global `oxc.jsx.importSource` is overridden per file by `jsxSource` in theory only, and its `include` strings resolve against `process.cwd()`, not the Vite root (run Vite from the app root).
- Peer floor 10.29.0 = the version verified (`useId` / `_mask` exist since 10.11): preact 10.29.8 + preact-render-to-string 6.8.0 checked out of tree (ids, SSR, hydrate) and measured in `apps/island-bench` (`rivet-bridge-preact-p10`). CI tests only 11.0.1 until the T16 floor + latest matrix.
- Derived resume model: nothing adapter-specific — `@rivetjs/bridge` routes islands to the lean boot or the enclosing boundary's adopt run (`libs/bridge/CLAUDE.md` "Derived model"); island-bench `RIVET_RESUME_MODEL=derived` builds the Preact lane on it.
