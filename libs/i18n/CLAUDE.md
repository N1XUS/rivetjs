# @rivetjs/i18n

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Compile-time i18n: ICU catalogs → per-key, per-locale table → Rust compiler static-call hook. Static messages ship no catalog, parser or runtime to the browser and create no resume state.

## Entry points

- `.` → `index.ts`: `t()` / `t.in()` marker + `Messages` / `Locales` (augmented by generated `.d.ts`). Never runs: compiler replaces every call; reaching it throws ("t() was not compiled").
- `./vite` → `vite.ts`: `i18n(config & { dts? })` plugin; `api.rivetCompileOptions(server, id)` read by `@rivetjs/compiler/vite` (`libs/compiler/vite.ts`); `api.clientPaths` (`clientPathPattern`: RegExp source of the app paths a client build's locale serves) read by `@rivetjs/router/vite` (wraps `underBase` → cross-locale links load documents); `DEV_LOCALE_PARAM`.
- `./runtime` → `runtime.ts`: `plural`, `select`, `number`, `date`, `pick` — imported only by compiled code for runtime-dependent parts (plural/select/number/date, `t.in`).
- `./resolve` → `resolve.ts`: isomorphic locale resolution (`resolveServer`, `resolveClient`, strategies, `localeCookie`, `cookieName`, `match`, `localeFromPath`). Cookie reads go through `@rivetjs/router` `parseCookies` (router semantics: quotes stripped, invalid percent-encoding kept raw → not a locale → skipped).
- `./router` → `router.ts`: `i18nGuard`, `errorLocale`, `localizeHref`, `delocalizeHref`, `alternates`, `dirOf`, `setLocale`.

## Layout

Flat: one file per module (package convention; keep it — `libs/compiler/tests/i18n.test.ts` deep-imports `../../i18n/catalog.ts` and `../../i18n/runtime.ts`).

- `index.ts` — `t` marker + typing (`Key`, `Args`, `Result` (string | `Content` when the message has tag params), `PrefixKey` / `Pattern` (`` t(`nav.${id}`) `` overload), `Translate`). Type-only import of `Content` from `@rivetjs/runtime/jsx-runtime`.
- `icu.ts` — ICU MessageFormat → compact IR (`Part`, `Variant`), `paramsOf`, `I18nError`. Build-time only (`@formatjs/icu-messageformat-parser`).
- `catalog.ts` — `I18nConfig`, `loadCatalogs`, `flatten` (nested → dotted keys), `fallbackChain`, `buildTable` (`Table` = key → `Variant[]` indexed by `config.locales`).
- `types.ts` — `declarations(table, locales)`: text of the generated `.d.ts`; tag params `(children: Content) => Content` (+ `import type { Content }` when any), native tags (`NATIVE_TAGS` = compile.rs `MESSAGE_TAGS`) optional.
- `vite.ts` — plugin (catalog load, `registerTable`, dts write, per-locale client build, dev locale query, HMR, DevTools JSON). Client environments resolve `@rivetjs/i18n` to `\0rivet-i18n-client:<locale>` (`t` re-exported, `export const locale = () => "<l>"`): build = `RIVET_LOCALE`, dev = importer's `?rivet-locale`, else default locale.
- `index.ts` — `t` (compiled away) + `locale()`: server = `_requestLocale()` (`@rivetjs/router/route-context`, `ServerData.locale` = rendered locale, first locale when none settled); throws outside a render (loaders / actions: `event.locals.locale`). Test `tests/vite.test.ts` (`locale()`).
- `runtime.ts` — message runtime (Intl instances cached per locale + options).
- `resolve.ts`, `router.ts` — see entry points.
- `tests/` — vitest project `i18n` (`libs/i18n/tests/*.test.ts`, root `vitest.config.ts`).
  - `fixture/` — single-page app (`rivet({ resume })`) for `vite.test.ts` builds.
  - `fixture-app/` — file-routed `[[lang]]` app (`rivetRouter`, `i18n.config.ts`) for `browser.test.ts` (Chromium via playwright) and the app-base test.
  - `.base-app-*/` — temp copies of `fixture-app/` made by `vite.test.ts` ("router in a locale's client build…"), removed by `onTestFinished`; gitignored (`tests/.gitignore`).

## Generated files

- `<root>/src/rivet-i18n.d.ts` (`dts` option): written by the plugin on config resolve + catalog edit, header `// Generated by @rivetjs/i18n. Do not edit.`; rewritten only when text changes. Fixture copies are gitignored (root `.gitignore`, `fixture-app/.gitignore`) and excluded in `tsconfig.json`.
- `fixture*/.rivet/`, `fixture*/dist/`: router/build output, gitignored.

## Rules / invariants

- Plugin order: `i18n()` before `rivet()` / `rivetRouter()` (`enforce: "pre"`).
- `config.locales` order = compiler variant index (table, `variant`, manifests, `pick`). Don't reorder casually.
- Server build + dev SSR: every locale as a variant (`staticCalls` + `variants`). Client build: exactly one locale (`RIVET_LOCALE`, required; output `<outDir>/<locale>/`, base `<base><locale>/`).
- Static-call hook: `{ id: "rivet-i18n", module: "@rivetjs/i18n", export: "t", prefixLookup: true }`. Compiler side: `libs/compiler/rust/src/i18n.rs` (knows no ICU, only the IR); DOM v2 lowering of messages `libs/compiler/rust/src/compile/dom_v2_i18n.rs` (translated client modules lower v2 unless resumed).
- IR field names (`t a n d p s tag c cases f ord`) are a contract with `i18n.rs` (serde untagged, disjoint names) — change both together.
- Static messages must never import `./runtime`. Untranslated apps: compiler output byte-identical; variant checks behind a module flag (see `docs/guides/i18n.md` Cost).
- Params: object literal only, evaluated once in source order. ICU: `other` required, plural `offset` rejected.
- Missing key: default locale always error; others per `missing` (`error` default; dev forces `warn` unless set). Plugin messages start `[rivet:i18n]`; missing-key warnings add `  fix: add "<key>" to the <locale> catalog (<file>) …`, ICU warnings a fix line (DIAG-VERBOSE; docs `guides/i18n/translating-text.md`).
- SSR/resume pages never resolve locale on the client (`<html lang>`); `resolveClient` is CSR / static root redirect only.
- No runtime catalogs, no in-place locale switch (switch = navigation).

## Gotchas

- `browser.test.ts` and the app-base test both touch `fixture-app/.rivet/` — that's why the app-base test works on a `.base-app-*` copy.
- Node without full ICU formats numbers/dates in English (plugin warns at config resolve).
- Server `t()` outside JSX is a per-locale value: `String()` throws; use `t.in(locale, …)`. Resolved for you in children, attributes (runtime `Picture` alt / title too), route `head` and kit head components (router `translateHead`).
- Images (`?image`) under per-locale client builds: `libs/compiler/images/plugin.ts` strips `<locale>/` from the base and writes files once into the locale outDir's parent (C1).
- Message tags in attributes / `t.in` → diagnostic `RV4004`.
- Modules importing `t`: server list-mount plans and direct regions off.
- Dev: non-default locale pages load `entry.dev.tsx?rivet-locale=<l>`; app modules (under Vite root, not node_modules) inherit the query (`resolveId`).
- Dev: `api.devPaths` (every locale's `clientPathPattern`, null for `prefix: "never"` / one locale) lets the router's dev `underBase` refuse cross-locale paths, so a language switch loads a document as in a build. Error pages of unmatched URLs take the URL prefix's locale in dev and in builds (`createApp` `errorLocals` segment fallback; fixture `_404.tsx`).
