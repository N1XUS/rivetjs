## Invariants / gotchas
- Built collection (`collectionOf`, object-literal `build = { content, createCollection }`); parts render from `node.render(node)`; `CollectionBranch` gets `{ key }` (never the node instance: resumable capture); renderer via `(custom ?? DefaultCollectionRenderer)`.
- Children inside providers are bindings: `{provide(Ctx, v, () => rp.children())}` (Column, Cell, ResizableTableContainer) — a JSX `<Provider>` child is not reactive / not provided.
- Native table elements; hidden description divs are siblings after `<table>` (a div inside a table is foster-parented).
- Row / Cell hover + own focus are delegated (HOTPATH 2026-10-09): `onPointerOver` → `hoverStateOver`, `onFocusIn` starts with `focusStateIn` (target === element, one native blur while focused); no native focus / blur / pointerenter / pointerleave per row or cell; the user's `onPointerEnter` / `onPointerLeave` bind only when given. Table ×1000 rows: listeners 28032 → 8032, mount 115 → 104 ms, dispose 16.7 → 13.2 ms, heap −7%. Remaining per-element natives: cell keydown capture, row dragstart / pointercancel.
- Row / Cell resume state (CELL-DIET 2026-10-19): each instance builds ONE plain data object (`RowData` / `CellData`: key, view accessor, options, user hover callbacks, its signals, static `class` / `style` / `children` or the live views); every handler / binding captures only it and calls module functions (`rowOn` / `cellOn`, `rowAttrs` / `cellAttrs` = the whole own attribute set in one spread after `{...dom}`, `rowSyncPressed`). The state computed, render-prop values, `renderProps` accessors, interaction options and the row focus-within ring (`focusRingFocus` / `focusRingBlur` over `withinFocused` / `withinVisible`) derive per object (`rowOf` / `cellOf`, module `WeakMap`): eagerly in the component body (`initRow` / `initCell`, component owner), lazily on a resumed page under NO owner (`untrack(() => runWithOwner(null, …))` — built under a binding effect, the memoized computed would be disposed on its re-run and stay stale). Row provider values: one `checkboxSlots` for CheckboxContext + CheckboxFieldContext, module constants for the default slot / drag / non-treegrid ButtonContext, closures capture `r`; `CollectionBranch` parent = `r` (only `key` read). No closure, computed or `{}` per instance in the state unless a consumer captures it (a selection checkbox / indicator, a render prop function reading the values). ui `table-virtualization` (1000 rows × 3 cells): 145 → 39 table entries / row, state 5.19 → 2.70 MB raw, 460 → 168 KB br. Remaining per row: 35 handler entries (`e`, ~1.2 KB raw, 8 per cell), 5 bindings, 14 signals, 4 data objects, 4 `dom` (`data-slot`) objects. Keep new per-instance closures off these objects (derive them in `deriveRow` / `deriveCell`).
- Column header focusMode "child": focusing a resizable header moves focus to the resizer input on the next frame (RA useGridCell rAF).
- Build pass tracks nested reads (`collections/components.tsx` re-entry): `<TableBody items={sig}>`, `<Collection items={columns}>` in Row / TableHeader, controlled widths through column items rebuild the collection. Rows / header cells render through `renderNodeAt`: unchanged rows keep their DOM; `TableColumnNode.liveProps` (`width`, `defaultWidth`, `minWidth`, `maxWidth`: read live by the resize state) keep the header (and its dragged resizer) when only widths change.
- Focus after a removed row (`index.tsx` reset effect): `resetGridFocusedKey` picks the replacement key, then a microtask focuses its element when the grid was focused or the last focusout-to-nowhere target left the DOM (Chromium fires focusout on removal; jsdom / React detached-node events do not).
- Virtualized (`<CollectionVirtualizer layout={TableLayout}>`, COLLECTION-VIRT 2026-10-19): renderer `isVirtualized` → div grid (`role=grid` / `rowgroup` / `row` / `columnheader` / `rowheader` / `gridcell` divs, RAC), body + header rows through `CollectionRoot` / `CollectionBranch` of `../virtualizer/collection-renderer.tsx`, `aria-rowcount` / `aria-colcount` / `aria-rowindex`; Table.Content element = scroller (`scrollRef`, scroll forwarded). Column resizing inside the Virtualizer not covered.
- Gaps: no DnD, placeholders render nothing. Resumed selection checkboxes (the old docs lane D3 gap "select-all dead, row checkbox toggles once by mouse") work: CDK-RESUME-BUGS 2026-10-19 could not reproduce it at 671410c4 or 28f317fc (story `/table`, cdk-docs `table-basic`, ui-docs `table-selection` / `table-custom-cells`, cold + warm, in an iframe too); pinned by `tests-components/table.test.ts` selection tests. A keyboard / programmatic focus on the select-all checkbox with no focused key moves focus to the first row (RA useGridCell + useSelectableCollection, focus visible).
- Ids: only body row header cells get ids (`<table>-<row>-<col>`); other cells have none.
- Live props (P5): Table / TableHeader / Column / ColumnResizer / TableBody / Row / Cell `class` / `style` / `children` render props read live (`renderProps(…, props)` when a prop is live, untracked); header + rows kept on a live class change (`collections` `ownProps`); Row `isDisabled` live (node props forward unread; locked by the LIVE-SWEEP round 2 test)
