## Rules / invariants
- naming (wave 2): RA `useX` → `xProps(props)` returning RA's result object with RA keys; call idiom `const press = pressProps(o)` then `{...press.pressProps}` / `press.isPressed()` (destructuring `const { pressProps } = pressProps(…)` is a TDZ error); state hooks → `createX`; attach-style → `watchX`. Old `use*` names removed (no shims)
- hooks return `xxxProps` bags of inline arrows calling exported `xxxHandler(state, e)` functions -> handlers are R2 resumable symbols; state = plain JSON object + signal
- conditional handlers: separate object literals / `Object.assign` (R2 wraps object-literal function values, not conditional expressions) (`focus.tsx:98`, `keyboard.tsx:67`)
- mutable module state lives in ONE object (resume-extracted symbols import module bindings read-only) (`hover.tsx:37`, `focus-visible.tsx:30`)
- nothing at import time; browser listeners added inside handlers / client effects
- `isDisabled` etc. are `MaybeAccessor`, read at event time via `read()`
- `mergeProps` (merge-props.tsx, RA rules): later wins, `undefined` never overrides; `on[A-Z]*` chained earlier-first (`chain2`); `class`/`className`/`UNSAFE_className` joined (accessor-aware: an accessor on either side yields an accessor); `id` via `mergeIds`; `ref` via `mergeRefs`; aria id lists NOT joined (RA). Live props (P5): any source with an own getter → runtime `mergeProps(...sources, combined)` (getters forwarded unread, last defined wins per read); `combined` = keys with ≥2 holders: live handlers chain at call time (`liveChain`), live classes join in an accessor `(renderProps?) => string` (`liveClass`; render-prop class functions get the render props), data handlers / classes / `id` / `ref` folded once (identity props). Resume-compiled module -> chained handlers / merged refs are resumable symbols when the inputs are
- Delegated dispatch (IMPL-INTERACT 2026-10-09): hook bags carry only bubbling (runtime-delegated) handlers — press keydown / click / pointerdown / pointerup / mousedown, hover pointerover, focus focusin. Mid-interaction events bind per interaction: `Press.track` bits (`PRESS_TRACK_DRAG` dragstart, `PRESS_TRACK_EXIT` pointerenter / pointerleave; `pressProps` sets both, the element adapter `elementPress` DRAG only — button / link / toggle had no RA enter / leave press handlers on the element; Table rows wire `elementPointerEnter` / `elementPointerLeave` explicitly) → `pressPointerDown` `addGlobal`s them on currentTarget, `removeAllGlobals` drops them. No pass-through props → `pressProps` returns the handler bag itself (no mergeProps copy).
- `pressProps` adds `data-rv-pressable=""` to `pressProps`; reads `PressResponderContext`. Resumability deviations (press.tsx header): `lastClick` guard (a replayed cold keydown older than the last click starts nothing); on native activatable elements (`<button>`, `<input type=button|submit|reset|checkbox|radio|image>`) a keyboard press ends at the native `click`, not keyup, and blur cancels it; `pressClick` ends such a press (pressup skipped); after a pointerup, RA's 80 ms "no click → cancel / synthesize" timer re-arms (≤ `PENDING_CLICK_MAX` 10 s) while the document saw a click (`timeStamp`) that `pressClick` has not (`lastClick` older): the resume loader holds a click behind an earlier cold event (cdk carousel: cold root `focusin`) — cancelling dropped the press. Edge: a click stopped before the pressable's handler (descendant `stopPropagation` after an unstopped pointerdown) keeps `data-pressed` up to 10 s (upstream: 80 ms)
- interact-outside / FocusScope ignore `[data-rv-top-layer]` targets
- Static-path prop bags (LIVE-FAST 2026-10-09): every copy / merge / element spread walks every key, set or not, so big RA bags pay for their unset entries. Build a context / input bag once without them (`definedProps`, `mergeDefined`: TextField input bag ~45 → ~15 keys, toggle input bag), merge into bags you own instead of copying (`mergeInto` after `liveOmit` / `globalDOMProps`). Effect: unset keys of a context bag no longer reserve their position, so an own prop the part sets (`placeholder` on a ui `Input`) lands after the bag's keys (attribute order only). A private-field brand (`#plain in bag`) to skip `hasLive` scans was measured and dropped: V8's clone fast path skips objects with a private field and adding one can turn a >16-key bag into a dictionary-mode object; a WeakSet costs ~0.4 µs per `add` in Chromium.
- package-wide rules: [../CLAUDE.md](../CLAUDE.md)
- Resume loader modality (CDK-PINS 2026-10-12): `setupGlobalFocusEvents` adopts `window.__rvIM` (last input recorded by the runtime resume loader before any cdk code ran: `"keyboard"`, `"virtual"`, or a pointer type `"mouse"` / `"pen"` / `"touch"`) when the modality is still unknown; absent / unknown values keep `null` (`:focus-visible` fallback in `syncModalityFromFocus`). Set by the resume loader (contract: `libs/runtime/CLAUDE.md` "Loader cold mousedown", `docs/guides/resumability.md` "Cold press"; `"virtual"` is accepted but reserved — the loader never writes it); test `tests/focus-visible-loader.browser.test.tsx`.

## Gotchas
- `keyboardProps` with `shortcuts`: `onKeyDown`/`onKeyUp` get the native event, not `RivetKeyboardEvent` -> `continuePropagation()` TypeError (`keyboard.tsx:49`, `keyboard.tsx:60`)
- resumed pages: delegated dispatch runs only the innermost handler per type -> `continuePropagation()` reaches native ancestor listeners, not other resumed handlers (`keyboard.tsx` header)
- delegated resumed `wheel` listeners are passive -> `preventDefault` no-op until a client listener binds (`scroll-wheel.tsx` header)
- link: first press lost after another component resumed (link + `press.tsx`)
- `Pressable` / `Focusable` children: a spread never sets `ref` → render function must pass `ref={p.ref}`
- `tests/interactions-browser.test.ts` holds only the press smoke test; hover/move/outside stories not driven by any test
