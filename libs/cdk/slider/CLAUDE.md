## Rules / invariants
- State: plain signals + JSON + free functions. React refs → `state.refs` (plain object, mutated): `values`, `draggings`, `editables`, plus behaviour's `data` (RA `sliderData`: label id, describedby, details), `track` (track drag index / position / pointer), `thumbs[i]` (thumb drag position / pointer).
- `value`: two-way `Signal<number | number[]>` or fixed plain value; snapped on read (`sliderValues`). `onChange` / `onChangeEnd` get a number when `value` / `defaultValue` was a number (`scalar`).
- `SliderState.value` may be an accessor only in transient views (color slider `sliderView`). `SliderState.format` (optional): label override for derived states (RA ColorSliderState) — `getFormattedValue(state)` without a value and `getThumbValueLabel` return it.
- Thumb input ids = `${refs.data.id}-${index}`; handlers find inputs by id (resumed page: no element refs needed). Window up-listeners live in a browser WeakMap.
- Resumability: the parts bind behaviour handlers from inline arrows in object literals (never assign `bag.onX = …` after creation, never an arrow inside `c ? () => … : x`: neither is R2-wrapped); handlers capture `aria` = merged props minus children / class / style / ref / slot (PROPS-CAPTURE); `moveProps` (`../interactions/move.tsx`) on track and thumb; no code runs before the first interaction (story `tests-components` `/slider`).
- Consumers: `../color/slider-state.tsx`, color components (C5) import `../slider/behaviour.tsx` and the parts; `@rivetjs/ui/slider` (HeroUI port) wraps the parts (inherits free drag + snap).

## Free drag + animated snap (deliberate deviation, user decision 2026-10-08)
- `snap?: "release" | "drag"` (stately `SliderProps`, so `Slider` / `createSliderState` / behaviour all take it), default `"release"`. `"drag"` = upstream RA/RAC (snap during drag).
- `"release"`: pointer drags (thumb `sliderThumbMove`, track `onDownTrack` + `sliderTrackMove`) call `setThumbDragPercent(state, i, percent)` after `setThumbPercent`: `state.dragPercents` (signal, null = not free; always null on the server → SSR stepped) holds the free 0–1 position, clamped to the track and to the neighbours' values. Value / aria / output / form value / `onChange` unchanged (stepped, onChange per stepped change).
- Positioning reads `getThumbPositionPercent(state, i)` (free ?? `getThumbPercent`): `sliderThumbProps` thumb style, `SliderFill`; track drag start uses it too (track press → drag continues from the press point).
- Release: `setThumbDragging(i, false)` → `releaseThumbPosition` clears the free position; when it differed from the step, not `prefers-reduced-motion: reduce` and `requestAnimationFrame` exists (else jump), `state.snappings[i]` = true and a `@rivetjs/cdk/motion` `Motion1D` (embla duration 25 / friction 0.68, user decision 2026-10-08: no CSS transitions) animates `state.dragPercents[i]` from the free position to the step each frame; `onSettle` → `endThumbSnap` (stop, free position null, snapping false). No inline `transition`, no CSS var. `data-snapping` on thumb + fill, `isSnapping()` thumb render prop. Motions in a module WeakMap keyed by `state.refs` (not JSON). A second release while snapping (thumb move end + global pointerup both call `setThumbDragging(false)`) retargets the running motion; a new drag (`setThumbDragPercent`) or a non-drag `setThumbValue` cancels it.
- Keyboard / programmatic changes never set a free position. Color sliders (`../color/slider-state.tsx`) inherit it: `ColorSliderProps.snap` passes through (default `"release"`); `sliderView` spreads the stored `dragPercents` / `snappings` / `refs` (the snap-motion WeakMap key), `colorSliderThumbStyle` positions with `getThumbPositionPercent`, `ColorThumb` gets `isSnapping` (`data-snapping`).

## Gotchas / deviations
- Thumb `<input>` carries `data-rk` (arrows, PageUp/PageDown, Home/End; none when disabled): a cold keydown on a resumed page is held instead of moving the native range input by its own page size (`tests/slider.browser.test.tsx` data-rk case)
- `numberFormatter` (Intl.NumberFormat instance) → `locale` + `formatOptions` (`../number` `NumberFormatter`, cached); locale / direction from `useLocale()`.
- No-change detection compares values element-wise (upstream: `replaceIndex` identity + `Object.is`); write base = current values.
- useSliderThumb's "focus the input when it becomes the focused thumb" effect runs where the track press sets the focused thumb.
- Label slot: RA re-renders with `label: false` when no `<Label>` renders; here the group's `aria-labelledby` follows the slot (accessor). SliderThumb: its label id (`<thumb id>-label`) goes into LabelContext as a slot id (`SlotId`, `rendered` starts false; a `<Label>` consuming it marks it rendered); the input's `aria-labelledby` is an accessor that names the thumb label only while rendered (else slider label + own `aria-labelledby`: no dangling id, no dev a11y warning). The thumb children are built (`const content`) before the input JSX so the server writes the input after its Label rendered (SSR markup right). Tests: `tests/fields-ssr.test.ts` (SSR), `tests/slider.browser.test.tsx` "labels thumb inputs only by labels that render".
- The range input's `change` (`onInput`) resets the DOM value to the snapped value (React controlled input).
- `render` (RAC DOMRenderProps): `if (render) return render(attrs, renderProps)` before the compiled element; reactive attrs are accessors, handlers inline arrows; tests `tests/render-forms.browser.test.tsx`; on Slider, SliderOutput, SliderTrack, SliderThumb (hidden input in `children`), SliderFill
- `children` functions run in a binding: read values with `untrack(() => sliderValues(state))`, or every change re-creates the thumbs.
- `SliderOutput` / `SliderTrack` / `SliderFill` props declare `id` explicitly (global DOM props omit it).
- live props (P5): `Slider` runs `liveOptions(merged, ["isDisabled"], ["value"])`, body in `slider()` under `untrack`; state: `value` may be a controlled accessor (`writable: false`, changes via `onChange`), `isDisabled` may be an accessor (`state.disabled`; read `isSliderDisabled(state)` — setters / handlers / track click use it); `data-disabled` goes through the spread bags (`disabledAttrs`: accessor when live, value when static); `SliderThumb` own `isDisabled` live (`liveAt`; `isSliderThumbDisabled(opts, state)`; a live one keeps the thumb editable + its handlers and they check the current value; input `tabIndex` / `disabled` / `data-rk` become returned-arrow accessors); Output / Track / Fill: `readOnce` + `liveOmit`, class / children from a live view. Live `minValue` / `maxValue` / `step` / `orientation` / `formatOptions` (LIVE-SWEEP round 2 state refactor): in `LIVE_KEYS` (gated by `hasLive`); `createSliderState` keeps the creation numbers + `state.live` accessors (`SliderLive`), numbers resolved on read through `sliderMin` / `sliderMax` / `sliderStep` / `sliderPageSize` / `sliderOrientation` / `sliderFormatOptions` (`state.ts`: clamping, percent, rounding, formatter, increments; key handlers read them untracked); thumb input `min` / `max` / `step` / `aria-orientation` and group / track / fill `data-orientation` / styles follow (returned arrows `orientationAttr` / `stepAttr`, `data-orientation={sliderOrientation(state)}` in the spread thunk); a changed range restricts the shown value (no `onChange`). Static path: one `state.live?.x` check per reader call (no new bindings). Read once (JSDoc "Read once at mount"): `SliderFill offset` / own `style` of Thumb / Fill, `defaultValue`, `id`, `name`, handlers. Gap: a track click may still move a thumb whose own live `isDisabled` turned true (editability registered at creation). Tests `tests/live-props.browser.test.tsx`, story `tests-components/live-props.test.ts`
