# libs/cdk/tests-components
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Component tests for `@rivetjs/cdk`: resumed story app (production build + node adapter + Chromium) plus pure state/behaviour suites.

## Runner
- vitest project `cdk-components` (root `vitest.config.ts`): `libs/cdk/tests-components/*.test.ts`, `fileParallelism: false` — suites share one production build + Chromium, one file at a time.

## Harness
- `global-setup.ts` — the project's vitest `globalSetup`: one `buildApp()` per run, `provide("cdkStoriesDist", dist)` (CI-TIME 2026-10-21: files run in separate forks, so the per-process build ran once per file, ~50 builds per run).
- `harness.ts` — `stories({ preload? })` (`preload: { lean }`, default `{ lean: true }` since M6-CUT: no fetch-ahead `data-fo`, whose `modulepreload` requests after `load` made every request-based "no library code before interaction" / "chunk loads on press" check fail and whose chunks later evaluate with no request; files whose checks are "preloaded when visible" / "first press needs no further chunk" opt back in with `stories({ preload: {} })`: carousel, sidebar, scroll-area, dates-calendar, widgets): skips the build when `inject("cdkStoriesDist")` is its `dist`, else builds once per process (`app/serve.ts` `buildApp`; `dom-data.test.ts` with its own `STORIES_DIST`, the fuzz project), `start({dist, port: 0, preload})` node adapter, one headless Chromium; `watch(page)` (script requests + page errors) and page helpers; `markDeferred(page)` (before `goto`) + `scriptsBeforeDeferred(page)`: script paths requested before the first idle callback / post-parse `modulepreload` (the resume loader warms chunks from ~150 ms by design) — "nothing loads by itself" checks use it instead of a fixed wait, which raced the warm-up (`date-picker.test.ts` SSR markup). Chunk checks never match file names (route chunks are named after route files, merged shared chunks `rivet-merge-…`): `chunksOf(symbolIdRegex)` = paths of the chunks holding matching symbols (`.vite/rivet-resume.json` `symbols`; boundary names `<module>#<Component>` (end with `$`, no hash since M6-CUT), cdk modules `@rivetjs/cdk/<path>`), `closureOf(chunks)` (+ manifest `deps`), `codeOf(regex)` = those chunks + the shared chunks only they import (not in the runtime / router App closure), `among(scripts, chunks)` (a `.deps.js` list counts as its chunk), `scriptsOf(scripts, regex)`, `hinted(page)` = the chunk paths the page hints before any input (`data-preload` plan + fetch-ahead `data-fo` + on a `data-boot` page the runtime and the chunks of its client-trigger boundaries (tail flags & 224), plus their `deps` closure; "no X code before interaction" checks subtract these — under route chunks one chunk holds every component of the page: `dates-calendar`, `selection-indicator`); `libraryScripts(seen)` = `among(seen.scripts, codeOf(/^@rivetjs\/cdk\//))` (in route mode the story route's own chunk holds cdk symbols too). Masking caveat: page code the merge budget puts into the router App's closure counts as always-loaded.

## Rules / invariants
- State/behaviour suites (calendar-*, date-picker-state) use Jest globals from `@rivetjs/testing/jest`.
- Story routes are resumed pages: follow ../CLAUDE.md resumability rules (inline-arrow callbacks; plain children are lazy slots, function children for render props).
- New component story: add `app/src/routes/<name>.tsx` + `<name>.test.ts` using `stories()`.
