# libs/cdk/masonry

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

`@rivetjs/cdk/masonry`: Rivet-authored `Masonry` (Pinterest-style columns) + `Bento` (span tiles). No upstream: React Aria / RAC / Angular CDK have no masonry; interaction follows RA GridList semantics, virtualized mode reuses the react-stately `WaterfallLayout` port. User request 2026-10-11 (MASONRY lane, Bento added the same day). Spec `docs/design/specs/2026-10-11-masonry-design.md`. `@rivetjs/ui/masonry` = the HeroUI-styled version.

## Rule (user ruling 2026-10-11)

- Sizes known → the server lays out, in ALL modes (columns, justified, Bento): ratio / `width`+`height` (`?image` descriptors) / `getItemHeight`. Server emits every breakpoint; the client re-places from the same pure functions. Unknown sizes → client measurement; mixed list → server lays out the known prefix (`data-layout="mixed"`: grid `padding-top` = prefix extent + gap, suffix CSS columns then measured under it).

## API

- Data-driven (no `Masonry.Item` JSX parts: ratios / spans are needed before render): `items` (array / accessor / Signal), `children(item, state)` render function (`state` = `{ key, index(), isSelected(), isDisabled() }`), `getKey`.
- Shared: `columns` (number \| `{minWidth: n}` map), `minItemWidth` + `maxColumns` (auto columns), `gap` (number \| `[x, y]`), `maxWidth` (root `max-width`; bounds the last breakpoint range: justified / mixed terms exact up to it, fewer justified splits), `selectionMode` / `selectionBehavior` (`toggle` default / `replace`), `selectedKeys` (value / Signal / accessor) / `defaultSelectedKeys` / `onSelectionChange`, `disabledKeys` (live), `disallowEmptySelection`, `onAction`, `onLoadMore` + `isLoading` (live) + `renderLoader`, `renderEmptyState`, `semantics` (`grid` default \| `list`), `id` / `aria-*` (on the grid element), `class` / `style` (root), `gridClass`, `itemClass` (string \| `(state) => string`), `loaderClass`, `emptyClass`.
- Masonry: `getAspectRatio` (default `aspectRatio` / `width`÷`height`), `getItemHeight` (fixed px, text cards), `getSpan` (columns; justified = width weight; default `span`) — the three may return accessor / Signal = live item control (incremental relayout + FLIP); `extraItemHeight`, `layout` (`auto`: exact / mixed / measure; `exact`, `measure`, `justified`), `fit="both"` (column ends stretched, flush bottom), justified `rowHeight` (Responsive, default 240; keys + `justifiedSplits(rowHeightTolerance, maxWidth)` split breakpoints so rows stay within the tolerance), `rowHeightTolerance`, `minRowHeight` / `maxRowHeight`, `lastRow`, `referenceWidth`, `virtualize` + `height` + `initialSize`.
- Shared (new): `gap` Responsive (`{0: 8, 768: [16, 24]}`; keys split breakpoints, `--rv-gx` active column gap), `motion` (`false` \| `{duration, friction}`), `handleRef` (`MasonryHandle`: `relayout()`, `scrollToItem(key)`, `getPosition(key)`; DOM functions `masonryRelayout` / `masonryScrollTo` / `masonryPosition` in behaviour.ts). `masonrySizes({columns, gap, span, inset, maxWidth})` = img `sizes` for a srcset (container-relative; `span` may be a map / a live span's value).
- Bento: `getColSpan` / `getRowSpan` (number \| breakpoint map; default `colSpan` / `rowSpan` fields), `columns` default 4, `rowHeight` (px default 160 \| `{ aspectRatio }` \| `"auto"`), `pack` (`dense` default \| `skyline`).
- Live (review fix 2026-10-12, every layout prop unless structural): Masonry `items`, `columns`, `minItemWidth`, `maxColumns`, `gap`, `maxWidth`, `rowHeight`, `rowHeightTolerance`, `minRowHeight` / `maxRowHeight`, `lastRow`, `fit`, `extraItemHeight`, `referenceWidth`, `motion`; Bento `items`, `columns`, `minItemWidth`, `maxColumns`, `gap`, `rowHeight` (px / aspect), `pack`, `maxWidth`, `motion`; `selectedKeys`, `disabledKeys`, `isLoading`; accessor results of `getAspectRatio` / `getItemHeight` / `getSpan`. Read once at mount (JSDoc says why): `layout` (structural: server-placed vs measured DOM + observers), `virtualize` (+ the virtual layout options), `semantics`, `selectionBehavior`, readers (`getKey`, `getAspectRatio`, `getItemHeight`, `getSpan`, `getColSpan` / `getRowSpan`), Bento `rowHeight="auto"` switch. Config changes re-place every breakpoint (style objects reused where boxes are equal); kind (exact / mixed / measure / justified) stays the mount decision.

## Invariants

- DOM: root `div.rv-Masonry` / `.rv-Bento` (`container-type: inline-size`, `data-rv-masonry`, `data-layout` = `exact` \| `measure` \| `virtual` \| `dense` \| `skyline` \| `auto`, `preload="visible"`) > grid (`role=grid` / `list`, `data-rv-grid`, `tabindex=0` until focus is inside) > keyed `For` rows (`role=row` > `role=gridcell`, or `listitem`; `data-rv-item`, `data-key`, `data-key-type`, `tabindex=-1`, `aria-selected`, `data-selected`, `aria-disabled`, `aria-rowindex` / `aria-colindex` for single-breakpoint Bento) > sentinel (`data-load-more`) > loader (`.rv-Masonry-loader`, `data-loading`).
- No `<style>` element (CSP; Rivet JSX rejects inline style content): breakpoints are inline "masked max()" CSS. Per breakpoint b: mask `--rv-m<b>` = 0 inside its container range else 1e9px (`clamp(0px, (100cqw − min + 0.01px) * 1e9, 1e9px)` edges), `--rv-w<b>` = column width − mask, `--rv-mw` = max of the masked widths; every item top / inset / height = `max()` over breakpoints of linear terms in `var(--rv-w<b>)`; constant-only terms subtract the mask. Single breakpoint = plain calc. `100cqw` resolves against the root (container). Exact placement = layout.ts rects to < 0.6 px at every width (`masonry.browser.test.tsx`).
- Greedy comparisons happen at a deterministic reference width per breakpoint (middle of its range, ≥ 320; `referenceWidth` override): server and client agree, no reflow; at other widths the picture scales (column assignment fixed per breakpoint).
- Exact + Bento (px / aspect rows) = absolute positioning from server CSS: zero JS, zero CLS, nothing boots. Style objects are frozen (runtime writes one `cssText`), and `registerGridProperties(n)` (client render) / `masonry.css` (`@rivetjs/cdk/masonry.css`, `@property` for 12 breakpoints) register the grid variables as inherited `<length>`s: unregistered, every item re-parses the clamp() token streams (measured 1k items: mount layout 33 → 11 ms, resize 28 → 5 ms). Bento `rowHeight="auto"` = native CSS grid (`repeat(auto-fill, minmax(calc(var(--rv-mw) - 0.01px), 1fr))`, `grid-auto-flow: row dense`, spans resolved at the smallest breakpoint, clamped to the min column count).
- Measured mode: first paint = CSS columns (`column-width: calc(var(--rv-mw) - 0.01px)`: exactly n columns at the final width; items `width: var(--rv-mw)`, border-box), then ONE `clientEffect` per grid element (boots by design; does not re-run per items change) runs `watchMeasured`: ResizeObserver on the root (content width from `contentBoxSize`) + every item (`borderBoxSize` heights), MutationObserver on the grid (added items: `position: absolute` + `visibility: hidden` until placed, observed; removed: unobserved + relayout); changes coalesce into one rAF = pure `placeMasonry` + write phase (`transform`, grid height; RTL mirrored, grid gets `data-measured`). Zero layout reads while watching (test spies `getBoundingClientRect` / `offsetHeight`); `reflowMeasured` = imperative pass (one read phase, then writes). Bug fixed 2026-10-11: appended items (load more) stayed in the flow under the placed cards (the effect re-ran before `For` inserted them and observed only the old items).
- Virtualized: `Virtualizer` + `MasonryLayout` (entries are the virtualizer items, `getKey` = entry key: O(1)), `aria-rowcount` = item count; the Virtualizer renders its first window at `initialSize` and starts its engine on the first scroll / focus, so one `clientEffect` dispatches a synthetic `scroll` when the scroller size differs (column widths need the real width; the engine then follows resizes); keys outside the window navigate through layout rects (`focusKey` scrolls `:scope > .rv-Virtualizer` / `[data-rv-scroller]`, retries a frame later).
- Interaction = RA GridList: one tab stop; arrows by visual position (`nearest`: vertical = nearest edge then widest overlap; horizontal = WaterfallLayout `deltaX − overlapY`, centre-distance fallback); PageUp / PageDown by viewport; Home / End; Space toggles, Enter = action (else select), Shift extends from the anchor (geometric range), Ctrl/Cmd+A (multiple), Escape clears (unless `disallowEmptySelection`); toggle + `onAction`: click runs the action while nothing is selected; replace: selection follows focus, double click / Enter = action. Disabled keys skipped.
- Resumable: handlers are inline arrows on the grid over a `ctx` literal of locals (PROPS-CAPTURE); anchor / focus in signals; no effect in exact / Bento modes (story `/masonry`: no `data-boot`).

- Placement computed: per breakpoint `placeColumns` with CHECKPOINT=32 snapshots / `placeJustifiedRun` row plans, re-placed from the first changed input (same config); unchanged items keep their frozen style object (`sameBoxes` against the previous geometry, per-row `computed`) → zero DOM writes to them. FLIP: First from the previous geometry (one grid rect read + `animatingBoxes`), play in a microtask after the flush.
- Rows (H1 fix 2026-10-12): keyed `For` over keys; each row reads its item / index through per-row computeds keyed by `key` (`keepItem` / `keepIndex` equality) → a new `items` array re-renders only rows whose item object changed (load more keeps item nodes, images and focus). Resumed page: the first items change re-creates the rows (resume adoption keeps a row whose own render read signals only while those hold their server values, runtime RESUME-KEEP-ROWS; masonry rows read `entries()` — the items — through their per-row computeds, so the items change itself invalidates them) — client-rendered grids keep them.
- Unknown sizes (M6): `auto` / `exact` → measured (mixed / measure; `exact` warns in dev); an item without size added after mount to an exact grid = square + dev warning (the kind is the mount decision). Justified: items without a ratio (and the items behind them, prefix rule) wait in a provisional row below the placed prefix (fix round 2): hidden 1:1 placeholders `pendingSlot(j)` (`top: var(--rv-pt)`, `width: var(--rv-pr)`, `inset-inline-start: j · var(--rv-pa)`; past `PENDING_SLOTS` = 24 at `calc(100% + 1px)`), grid vars `--rv-pt/pr/pa` + `overflow-x: clip` + height `calc(var(--rv-pt) + var(--rv-pr))` while pending (content below does not jump, clipped lazy images stay unloaded); `watchRatios` measures them (img natural ratio / box), the row packs once known. Ratios: a `Map` + `ratioVersion` signal (O(1) per measure). Never a silent square / zero-height box at mount.
- Resume captures: local consts referenced unconditionally (an arrow or a const referenced only inside a conditional expression is not wrapped → "function is not serializable"); captures are read at creation, so a const used by a computed must be declared before it. Exact / justified pages serialize no measured-mode styles (resumed page: MutationObserver count 0 at the same width, `tests-components/masonry.test.ts`).

## Gaps

- No typeahead, no drag reorder, no sections; virtualized + unknown sizes navigate rendered items only; Bento aria indices only with a single breakpoint; layout kind read once at mount; measured, virtualized and justified-with-unknown-ratio grids boot one client effect each; the cdk component imports the Virtualizer, `justified.ts` and `flip.ts` statically (L7: a lazy import would add a chunk request on the first interaction; masonry chunk 87 KB min dom, size-report `cdk-example:masonry-expand` first click 17 requests / 58.8 KB br); SSR 1k items ≈ 2× a plain keyed `For` with the same bindings (per-item style strings + render prop); resumed rows are re-created on the first items change (see Invariants); `motion.duration` well above the default (e.g. 60) settles very slowly on Motion1D.
