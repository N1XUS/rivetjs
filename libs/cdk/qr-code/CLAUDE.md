# @rivetjs/cdk/qr-code
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

QR Code encoder = port of Project Nayuki's "QR Code generator library" (TypeScript version `typescript-javascript/qrcodegen.ts`, MIT, © Project Nayuki; `NOTICE`) + Rivet-authored geometry / SVG path builders. Pure functions, no DOM, no state: identical output on server and client (RV2103-safe). Consumer: `@rivetjs/ui/qr-code` (QRCODE 2026-10-28).

## Entry points
- `@rivetjs/cdk/qr-code` → `index.tsx` (re-exports; package `./*` wildcard):
  - `encode.ts` (port): `encodeQr(text, { ecc = "M", minVersion = 1, maxVersion = 40, mask = -1, boostEcc = true })` → `QrMatrix` `{ version, size, ecc, mask, modules, functions }` (row-major `Uint8Array`s, `1` = dark / function module; (x, y) = `[y * size + x]`); `encodeQrSegments(segs, options)`; segments `makeSegments` (single mode: numeric / alphanumeric / UTF-8 byte, as upstream; no ECI / kanji / mixed-mode optimisation), `makeNumeric`, `makeAlphanumeric`, `makeBytes`; internals exported for tests / decoders: `buildMatrix`, `addEccAndInterleave`, `blockLayout`, `numDataCodewords`, `numRawDataModules`, `alignmentPositions`, `formatBits`, `versionBits`, `maskBit`, `penaltyScore`, `drawFunctionPatterns`, `rsDivisor` / `rsRemainder` / `rsMultiply`. Too long → `RangeError("Data too long")`.
  - `shapes.ts` (Rivet): `moduleRole(version, x, y)` (finder / separator / timing / alignment / format / version / dark / data), `finderOrigins`, `isFinderModule`, `centerRect(size, ratio)` (centred, same parity as `size`), `excavate(qr, rect, { keepAlignment = true })` (copy; clears data modules, alignment only opt-in; never finder / separator / timing / format / version / dark), `placeholderQr(version = 2)` (real function patterns, seeded xorshift data, format modules light → not decodable), `qrPaths({ size, modules }, shape)` → `{ body, eyes }`.
- Shapes: `square` = horizontal runs as relative rects (`M x y h n v1 h-n z m dx dy …`); `rounded` = one rect per run with corners rounded (r 0.5) where both edge neighbours are light + concave fillets in light modules whose two edge neighbours and diagonal are dark (all clockwise, nonzero union, no seams); `dots` = `body` is a STROKE path of zero-length segments (`M x.5 y.5h0 m dx dy h0 …`, ≈ 8 B per module; draw with `stroke-linecap: round`, width < 1), `eyes` = 7 × 7 ring (r 2) − 5 × 5 hole (r 1) + 3 × 3 centre (r 1) for `fill-rule: evenodd`. `body` excludes the finder patterns in every shape; `eyes` = finders only.

## Tests
- `tests/qr-code.test.ts` (`cdk`): ISO vectors (format words Annex C, version words Annex D, alignment table Annex E for v1–40, total codewords, byte capacities L/M/Q/H v1–10 + v40, block structure samples, HELLO WORLD 1-M RS codewords), function map = ISO layout for v1–40, capacity boundaries v1–40 × 4 levels (n fits, n + 1 throws), boost, auto mask = argmin penalty, round trips through `tests/qr-decode.ts` (every mask × level, v1–40 at capacity, numeric / alphanumeric count ranges, injected errors corrected), excavation invariants, ECC H + 22 % logo decodes, placeholder not decodable, path builder contracts.
- `tests/qr-decode.ts`: test-only independent decoder (own GF(256) tables, BCH check by minimum distance, ISO alignment table + function map, zigzag, de-interleave, Berlekamp–Massey + Chien + Forney correction, numeric / alphanumeric / byte parsing). Only `blockLayout` comes from the encoder (pinned against ISO in the tests).
- `tests/qr-code.browser.test.tsx` (`cdk-browser`, Chromium): `isPointInFill` / `isPointInStroke` at every module centre of each shape = encoder modules, decodes (plain + excavated).

## Gotchas
- No QR decoder / encoder exists in node_modules (no jsqr / zxing / qrcode): correctness evidence is the ISO vectors + the independent decoder above.
- `ecc` is the MINIMUM level with `boostEcc` (upstream default): `encodeQr("rivet")` is 1-H.
