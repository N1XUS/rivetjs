# @rivetjs/cdk
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Headless, accessible, resumable UI toolkit: 1:1 ports of React Aria / React Stately / React Aria Components (RAC), `@internationalized/date` and Angular CDK, on Rivet signals + SSR resume. Source package (`"rivet": { "source": true }`): `.tsx` is compiled by the app build; one subpath per module, unused module = 0 B (no barrel).

## Layout
- `<name>/index.tsx` component (RAC port) · `<name>/behaviour.ts` attribute bags + handlers for custom markup (react-aria hook port) · `state/<name>.ts` serializable state (react-stately port). Every module folder has its own `CLAUDE.md` (purpose, upstream, parts/props, tests, gaps).
- Foundations are grouped folders: `a11y/`, `announcer/`, `bidi/`, `focus/`, `i18n/`, `interactions/`, `keys/`, `platform/`, `utils/`, `overlay/` (React Aria), `overlay-service/` (Angular CDK), `portal/`, `collections/`, `selection/`, `state/`, `clipboard/`, `coercion/`, `layout/`, `observers/`, `date/`, `number/`, `color/`, `slider/`, `scrolling/`, `virtualizer/`, `motion/` (embla motion core, reusable).
- Root files only: `package.json`, `project.json`, `tsconfig.json`, `NOTICE` (third-party licences + list of ported files; update it when adding ported files), `theme.css`, `tailwind.css`, this file. `.artifacts/` is gitignored scratch (screenshots).
- Tests: `tests/` (vitest project `cdk`: unit, node DOM, Chromium harnesses, `tests/date/` upstream suite), `tests-components/` (project `cdk-components`: story app `tests-components/app` built for production, resumed in Chromium), `tests-fuzz/` (project `cdk-resume-fuzz`, `@rivetjs/testing/fuzz`: every story route resumed vs CSR, own `STORIES_DIST` `dist-fuzz`; known findings + owners in `tests-fuzz/pins.ts`). See `tests/CLAUDE.md`, `tests-components/CLAUDE.md`.
- Generated: `state/date-intl.ts`, `*/intl.ts` (locale strings from react-aria intl JSON) — header says "Generated; do not edit".

## Rules / invariants
- Faithful ports (user rule): port upstream 1:1 — same behaviour, options, events, edge cases; only framework plumbing adapts (DI / NgZone / RxJS → factories + minimal emitter; React hooks → signals + handler functions). Port the upstream test suite alongside. Full upstream component set, no simplified reinterpretations. Where Angular CDK and react-aria share a widget name: ONE `@rivetjs/cdk/<name>` module covering the union (no `ng-`/`primitives` duplicates).
- File header convention: first lines `// Ported from <upstream package> (<files>), <licence>, © <owner>.` then `Rivet:` / `Deviation:` / `Changes:` bullets. Add the file to `NOTICE`.
- Headless styling: default class `rv-<Name>[-part]` only when `class` / `<part>Class` is omitted; state through ARIA attributes + `data-*` (`data-disabled`, `data-selected`, `data-focused`, `data-focus-visible`, `data-pressed`, `data-placement`, `data-orientation`, `data-entering` / `data-exiting`, …). Behaviour-critical styles (visually hidden, underlay `position:fixed;inset:0`, z-index, arrow, `touch-action`) are inline / CSSOM, never keyed on a class — overriding a class must not break behaviour. No base stylesheet; `theme.css` is looks only. Class literals in cdk sources are `rv-*` (or Angular CDK `cdk-*`) only — never Tailwind utilities (`libs/ui/tests/no-raw-utilities.test.ts`).
- Icons: never invent SVG paths, never use UTF symbols (✓ × ▾ → ★ …) as icons — use an icon library (lucide) (root CLAUDE.md rule).
- Props: every component accepts `GlobalDOMAttributes` (`utils/dom-props.ts`) and forwards them to its root via `globalDOMProps(props, OWNED)`; `OWNED` lists the global events the component handles itself (user handler is chained from the component's own). Parts get `<part>Props` objects / `<part>Class` props. In spread elements (`{...dom}`) read every prop into locals BEFORE the JSX: an element with a spread resumes as one binding over all attributes, and reading `props` there captures the whole props object (children included).
- Resumability (docs/guides/resumability.md, docs/guides/aria.md): callback props = inline arrows or local functions (module-level / imported functions are not serializable — wrap in a local const); plain JSX children are lazy (compiler slot, `renderSlot` / `isSlot` from `@rivetjs/runtime/slot`: evaluated where the parent renders them, so providers / closed overlays see them); function children for render props (`({ close }) => …`) and item renderers (`(item) => …`, told apart with `!isSlot(c)`); pass signals for two-way values (a value read from a signal is a live prop: migrated parts update in place, see Live props below); state lives in `state/*` factories (plain signals + free functions) so it serializes; composite widgets set `data-rk` (`keys` `navigationKeys`) so cold keys never scroll; context tokens = plain `createContext(v)`.
- First-interaction latency (2026-10-08): click / key / focus handlers plan their chunks `intent` (unless another use of the chunk is visible), and so do their dependency chunks (bindings reading signals the handler reaches) — a cold click without pointer dwell then waits for every missing chunk plus its static-import waterfall (slow network: ~1 s for the sidebar). A component whose state is read by many bindings puts a literal `preload="visible"` directive on its root element (sidebar wrapper, carousel root + viewport, scroll-area activators): handler + dependency chunks fetched and evaluated when visible, nothing runs, no `data-boot`. Measure with `tests-components/cold-latency.ts` (slow profile = 150 ms RTT, 1.6 Mbps, 4x CPU). Not on `render` paths (directive is JSX-literal).
- Idle boot (UI-COLD 2026-10-08): nothing may register a load / idle `fx` on a closed or untouched component (any `fx` sets `data-boot`): server slot ids record no check effect (`slots/`; field owners probe their parts first: `probeSlots` + `slotIdRef(id, false)`, server only — field children render twice on the server: keep them pure), exit-animation effects live inside the open overlay (`popover/`, `modal/`), `prop:` bindings only when the prop is given (`checkbox/` `indeterminate`). - Resume: standalone Modal with `isOpen` signal opens on a resumed page (`tests-components/overlays.test.ts` "standalone controlled Modal"); standalone Popover / Tooltip with `isOpen` + `onOpenChange` open on a resumed page (`tests-components/overlays.test.ts`, `tooltip.test.ts`); `on*Capture` not resumable; conditional `onX={c ? f : undefined}` still records a handler entry; local arrow `const filtered = () => …` passed as `items={filtered}` goes stale after resume (use `computed`); `clientEffect(() => bp.connect())` "function is not serializable" (`layout/index.ts`).
- Server ids (CDK-PINS review 7, 2026-10-12): `idSignal` / `mergeIds` (`utils/id.ts`) register per render id scope on the server (`#server` `scopedIdUpdaters`): `rv` ids restart per request, so a process-wide registry crossed concurrent requests (request B's TextField id merge changed request A's `for` / `id`). A `mergeIds` after an `await` outside the render's id scope sees only the process-wide `rvs` registry. The nearest `_idScope()` wins: a `renderCache` fragment's own scope separates its Input from an outer field's id (gap, `utils/CLAUDE.md`).
- Resume build graph: the client build walks `.tsx` imports of resume modules only — a `.tsx` module reached only through a `.ts` barrel (`@rivetjs/cdk/color` → `color/field-state.tsx`) has no symbol chunks ("Resume manifest has no chunk for …"); a component that stores a closure of such a module imports the `.tsx` file directly (`color-field/index.tsx`, `number-field/index.tsx`). Closures in `.ts` modules are never resumable (a `.ts` wrapper around a user callback = "function is not serializable").
- Parts inside a collection build pass (ComboBox / Select `collectionOf` over the whole children tree): RAC hides Text / Label / Input / Button / Header there (`createHideableComponent`); until those parts check `isHidden()`, a `<Text slot="errorMessage">` in a ComboBox inside a Dialog throws "Invalid slot" (build pass sees the outer TextContext). Not ported: FocusRing component, useHasTabbableChild, cdkMonitor*Focus directives, CdkConnectedOverlay / CdkOverlayOrigin.
- `keys`: `"Ctrl+s"` silently becomes `"s"` (`Ctrl` is not a modifier alias); `bidi`: `useDirection()` throws in SSR; `data-*` state values: RAC-port components use `"true"` (`dataBool`), older ones may still write `""`.
- One div overlay layer: Angular `OverlayContainer` is a `data-rivet-portal` host moved after later portals on attach (`bringToFront`); no native top layer (`usePopover` / `withPopoverLocation` removed).
- Single implementations (B3 dedupe, 2026-10-06): press = `interactions/press.tsx` (`button/press.ts` is a per-element adapter over its exported handlers); modality = `interactions/focus-visible.tsx` (`noteModality(e)` for resumed handlers; `_adapters`, `selection/dom-utils.ts` re-export); router / `openLink` / `linkState` = `utils/links.tsx` (`link/router.ts` re-exports; `Router` is plain data `{ isNative, navigate?, useHref? }` so handlers can capture it — RA's `router.open` / `router.useHref` are `routerOpen` / `routerHref`); `mergeProps` / `chain` / `mergeRefs` = `interactions/merge-props.tsx` (RA rules; `utils/index.ts` re-exports; no `merge` alias); platform probes = `platform/` (server `undefined`), DOM helpers = `utils/dom.ts`, `runAfterTransition` = `utils/index.ts` (`interactions/utils.ts` re-exports); outside-ness = `interactions/interact-outside.tsx` `isValidOutsideEvent` (`overlay/index.ts` `interactOutside` uses it); shared types (`Key`, `Selection`, `SelectionMode` incl. `"none"`, `Orientation`, `Direction`, …) = `collections/types.ts` (re-exported by `_adapters`, `collections/index.ts`, `bidi`, `i18n`, `scrolling/state.ts`, `virtualizer/types.ts`; `state/select.ts` `SelectionMode` = `Exclude<…, "none">`; `keys/` `Orientation` incl. `"both"` is a different concept); numeric keys = `data-key-type="number"` everywhere (`collections/dom.ts` `keyAttrs` / `domKey`).
