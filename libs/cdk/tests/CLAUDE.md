## Harnesses
- `harness.ts` `libraryImports(page)`: library resource entries no `<link rel="modulepreload">` names (Chromium reports fetch-ahead `data-fo` preloads with initiator `script`) + `(derived runtime started)` when `document.$rdp` exists (M6-CUT).
- `harness.ts` — story app `tests/app`: production build (client + server via `app/serve.ts` `buildApp`) into `app/dist`, node adapter (`@rivetjs/router/node` `start`, port 0), one headless Chromium per file. Cross-process lock dir `app/.stories-lock` (pid file, stale-pid cleanup) held until `close()` — files share `dist/`. Every story-app suite (`smoke`, `interactions-browser`, `scrolling-browser`, `virtualizer-browser`, `resume`, `transition-resume`) MUST use it: `buildApp()` deletes and rebuilds `dist/`, so an unlocked build under a running suite makes its pages time out. Helpers: `stories()`, `watch(page)` (script requests + page errors), `componentRan(page)` (resumability: no component ran), `libraryScripts(seen, extra?)` (scrolling/virtualizer/drag-drop/dnd/behaviour chunks), `focused`, `errors`, `text`, `activeId`.
- `browser.ts` — plain `node:http` server rooted at the repo root, strips TS types (`stripTypeScriptTypes`), import map `@rivetjs/reactivity`, `@rivetjs/runtime/dom`, `@rivetjs/runtime/slot`, `@rivetjs/cdk/` -> `/libs/cdk/` + `scopes` generated from every `libs/*/package.json` `imports` field (`packageImportScopes()`: `#dev` -> `/libs/runtime/dev/off.ts` under `/libs/runtime/`; conditions `browser` > `default`, never `development`; `#x/*` -> `#x/` prefix) so package-private specifiers cannot drift (extension-less `/libs/cdk/<subpath>` resolved through `resolve-subpath.ts`; `.ts` only, `.tsx` targets are not served); `harness().page(body?, {css, viewport})`. Pages import by repo path: `import("/libs/cdk/overlay/position.ts")`. Used by `angular-overlay.test.ts`.
- `browser/harness.ts` — Vite dev server rooted at `libs/cdk` (`rivet()` compiler plugin, client TSX, no HMR) + one Chromium; `blank({colorScheme, viewport, reducedMotion})` opens `browser/index.html` with clipboard permissions. Tests import by root path inside `page.evaluate`: `await import("/observers/index.ts")`.
- `browser/deps.ts` — re-exports bare specifiers (`mount`, `signal`, `computed`, `effect`, `batch`, `untrack`, `useContext`, `createContext`) for `page.evaluate`: `await import("/tests/browser/deps.ts")`.
- `server.ts` — `serverModule(name, source?)`: compiles a cdk `.tsx` (and its `.tsx` imports) for the server in resume mode (`@rivetjs/compiler` `compile`, `sourcePackages: ["@rivetjs/cdk"]` like an app build, throws on diagnostics; `importModule`, `renderHtml` helpers), resolves the runtime specifiers in its `runtime` list (`server-resume`, `server`, `style`, `slot`, `resume-format`, `props`, reactivity — add new compiler imports there), resolves `#dev` (package `imports`) here under the run's conditions (dev-off in `cdk`, dev-on in `cdk-dev`; the temp dir has no package scope — DIAG-VERBOSE fix 1 put `#dev` in `checkbox/behaviour.tsx`), maps `#server` to its own server build of `collections/server-on.tsx` (one `slotProbing` / `_probeTree` instance with the compiled graph: a natively loaded copy would import another `components.tsx`), compiles `@rivetjs/kit/transition` for the server too (cdk Modal renders its `TransitionScopeProvider`; natively the loader builds the `.tsx` for the DOM), rewrites relative / `@rivetjs/cdk/x` imports to files (subpaths through `resolve-subpath.ts`, dir -> index), writes the module to a per-process temp dir (`rivet-cdk-server-*`, removed on exit) and returns its file URL once the module and every module it reaches are written — import cycles are allowed (`collections/components.tsx` → `#server` → `server-on.tsx` → `./components.tsx`, SMALL-FIXES 2026-10-21): each module's file is allocated before its build, importers never await a dependency's build (that deadlocked: the cdk node suite stuck at `live-flags-ssr`, 0 % CPU, no test timeout — CI-RED-2 2026-10-21) — never a data URL: nesting each dep's data URL in its importer re-embeds the whole subtree per level (date-picker hit 12 MB/URL, > 4 GB run; bound asserted in `render-server.test.ts`); render with `resumableToString`. Used by `modal.test.ts`.
- `resolve-subpath.ts` — `resolveCdkSubpath("overlay-ref")` -> `overlay-service/overlay-ref.ts` from `package.json` `exports` (exact keys, then `*` patterns); used by `server.ts` and `browser.ts` so harnesses follow the real export map.
- `dom.ts` — happy-dom `Window` as global DOM at import; Angular `@angular/cdk/testing` event helpers `createMouseEvent`, `createTouchEvent`, `createKeyboardEvent`, ...
- `install-dom.ts` — `installDom(url?)` (call before importing modules under test; returns `{window, reset()}`), `mockLayout(element, rect/scroll sizes)` (happy-dom has no layout).
- `bundle.ts` — `bundle(entry)`: esbuild IIFE of TS source (imports relative to `tests/`), exports on `window.cdk`; for engines needing real layout without the story app.

## Gotchas
- `angular-overlay.test.ts`: `t.content()` is a `DomPortal` of an element in a holder OUTSIDE the document (a DomPortal needs a parent and moves the element back there on detach; upstream attaches a fresh component portal — content in the document only while attached). Positions apply on the next animation frame after `attach` (Angular `afterNextRender`): `await t.render()` wherever upstream runs `detectChanges` / `tick` before reading styles. Expectations follow the upstream `@angular/cdk/overlay` `*.spec.ts`, e.g. rtl `start` → `flex-start` + `margin-right` (the host has `dir=rtl`).
- `angular-overlay.test.ts` 10→61 failures meant the `browser.ts` import map lacked a package `imports` specifier (`#dev`): scopes are generated from package.json now — a new `#x` import needs no harness change.
- Open overlay at test end: its FocusScope restores focus one frame after unmount; the by-id target (`current()`, resumed regions) is resolved at unmount since 2026-10-09, so the next test's trigger with the same id (`rvc0-trigger`) no longer gets focused (`focus-scope-restore.browser.test.tsx`). `select.browser.test.tsx` `afterEach` still waits a frame after `cleanup()` (harmless).
- `harness.ts` lock: killed run leaves `app/.stories-lock`; removed automatically only when the recorded pid is dead.
