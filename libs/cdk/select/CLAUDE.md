# @rivetjs/cdk/select
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Select (RAC `Select` + `SelectValue`, composing Label / Button / Popover / ListBox): trigger shows the value or a placeholder, listbox in a popover of the div overlay layer, hidden native `<select>` carries the form value (posts before JS). Single or multiple.

## Entry points
- `@rivetjs/cdk/select` -> `index.tsx`: `Select` (dispatch: no `items` and no `state` → RAC parts form `SelectParts` (`select-parts.tsx`); else the items preset), `SelectProps` (preset), `SelectPartsProps` / `SelectPartsRenderProps` (parts form, accessor render props; RAC `SelectProps` / `SelectRenderProps`), `SelectRenderProps`, `SelectValueSnapshot` (deprecated `renderValue` props), `SelectValue` / `SelectValueProps` / `SelectValueRenderProps` (accessors) / `SelectContext` (`SelectContextValue`: `placeholder`, `renderItem`) / `SelectStateContext` / `SelectValueContext` / `selectedText` (from `select-value.tsx`), `HiddenSelect`, `HiddenSelectProps`, `AriaHiddenSelectProps`; re-exports `createSelectState`, `setSelectValue`, `selectValue`, `selectedKeys`, `selectedItems`, `selectedItemsOf`, `openSelect`, `toggleSelect`, `removeSelected`, `clearSelection`, `toggleSelected`; types `Item`, `Key`, `Selection`, `CollectionEntry`, `SelectionMode`, `SelectState`, `ValueType`, `ChangeValueType`, `ItemRenderProps` (option slot props, defined in `select-value.tsx`)
- `@rivetjs/cdk/select/parts` -> `parts.tsx` (explicit package.json entry, UI-COLD 2026-10-08): parts-only `Select` (= `SelectParts`, no items preset: the preset's popover-overlay / kit transition / header / text-field graph stays out of the trigger chunk closures), `SelectValue`, the contexts, `selectedText`, state + value helpers, types; used by `@rivetjs/ui` select / cell-select / inline-select / autocomplete
- `@rivetjs/cdk/select/behaviour` -> `behaviour.tsx` (explicit package.json entry; .tsx so the `selectProps` accessor closures resume): `selectProps(props, state)` (RA `useSelect` bags, same keys: `labelProps`, `triggerProps`, `valueProps`, `menuProps`, `descriptionProps`, `errorMessageProps`, `hiddenSelectProps`, + `ids`; ids / ARIA only, reactive values as accessors), part ids (`triggerId`, `labelId`, `valueId`, `listId`, `popoverId`, `hiddenId`), `TRIGGER_KEYS`, `syncListSelection(state, selection, keys?)`, `selectListChange` (list `onSelectionChange`), `selectListBlur` (ListBox `onBlur`), value helpers `removeSelected` / `clearSelection` / `toggleSelected` (Rivet extras over `setValue`: `onChange` + commit validation against the hidden field), `SelectCallbacks`, trigger handlers (`selectTriggerKeyDown`/`KeyUp`/`PointerDown`/`MouseDown`/`Click`/`Focus`/`Blur`), `selectLabelClick`, `selectFocusWithin`, `selectOpen(state, focusStrategy, toggle?)`, `commitSelect`, `syncHiddenField`, `hiddenSelectChange`/`Invalid`/`Reset`, `isValueKey`
- state: `@rivetjs/cdk/state/select` (`createSelectState`, `selectCollection`, `canOpen`, …; `items` optional: no items = empty data collection, no throw; parts form: `collection` accessor (built collection) → `selectEntries` maps its nodes to `BuiltItem`s (`value` = item object of a dynamic ListBox, `content` = the ListBoxItem children; `WeakMap` cache per collection))

## Layout
- `select-parts.tsx` - RAC parts form (`<Select><Label/><Button><SelectValue/></Button><Text slot="description"/><FieldError/><Popover><ListBox>…</ListBox></Popover></Select>`): `SelectParts` (`isHidden()` → null, `contextProps(SelectContext)`, collection = `collectionOf(build.content)` over the children, function children called with static accessors) → `SelectPartsInner`: `createSelectState({ collection })`, value-controlled list selection (as the preset), Provider values SelectContext `{placeholder}`, SelectStateContext, SelectValueContext `{id}`, LabelContext (`elementType: "span"`, `createSlot` ref, click focuses trigger), ButtonContext (trigger ids / ARIA accessors, `data-rk`, `isPressed` = open, `preventFocusOnPress`, useMenuTrigger `onPressStart` / `onPress` = `selectTriggerPressStart` / `selectTriggerPress`, useSelect keyboard / focus handlers), OverlayTriggerStateContext, PopoverContext (`trigger: "Select"`, `triggerRef`, `scrollRef`, `placement: "bottom start"`, `clearContexts: [LabelContext, ButtonContext, TextContext]`), ListBoxContext (= preset `menuProps`), ListStateContext, TextContext (description / errorMessage slot ids), FieldErrorContext; server: `probeSlots(values, children)` (`#server`) before the trigger renders (inside another field's probe the Select returns `null`), no-Label ids (`hasLabel()` false: trigger labelled by the value alone, menu unlabelled) are computed directly, not by a second `selectProps` call (its `labelProps` logged the dev "no visible label" warning for every Select, 2026-10-12; `tests/label-warning.test.ts`); trigger `aria-describedby` = `slotIdRef(id, false)` (only rendered Description / FieldError, COMBOBOX-DEV 2026-10-08); root `<div preload="visible">` (or `render(attrs, renderProps)`: a directive in the user spread is ignored, so that path passes `<HiddenSelect preloadVisible>`, whose `<select>` carries the directive) + `HiddenSelect`; the directive (UI-COLD 2026-10-08) fetches the root handlers' dependency chunks (popover Show / exit state, SelectValue, HiddenSelect, indicator bindings) when visible: slow first click 361 → ~120 ms (they were 6–9 requests after the input, over Chrome's 6-connection limit); root `onKeyDownCapture` = `selectTriggerKeyDownCapture` (Space continuing a typeahead never reaches the Button's press); `autoFocus` focuses the trigger in a `clientEffect` (Button only sets the attribute)
- `index.tsx` - root `<div>` > label `<span data-slot="label">` + trigger `<button>` (> `<span class="rv-SelectValue">` + `indicator`) + description + `FieldError` + `<span data-rv-overlay-anchor>` > `PopoverOverlay` > `Provider` (`ListStateContext` + `ListBoxContext`) > B5 `ListBox` + `HiddenSelect`; collection = `collectionOf(<ListBox items children={option}>)` (`selectOption`: item → `ListBoxItem` (+ `Text slot="label"/"description"`), section → `ListBoxSection` + `Header` + `Collection`)
- `select-value.tsx` - RAC `SelectValue` + `SelectContext` / `SelectStateContext` / `SelectValueContext` (ids `rv-select`, `rv-select-state`, `rv-select-value`); content in a `Show` region (placeholder text <-> elements resumes); multiple: `Intl.ListFormat` parts, items in `<span data-slot="value-item">`; the preset trigger renders it inside a `Provider` (`renderValue` adapted through `valueSnapshot`)
- `behaviour.tsx` - useSelect + useMenuTrigger(type "listbox") handler bodies (imports leaf modules only: `../_adapters/type-select.ts`, `../interactions/focus-visible.tsx`, `../platform`, `../utils`, `../selection/dom-utils.ts`; not the `_adapters/interactions.ts` / `selection.ts` barrels: every trigger handler chunk statically pulls this module's closure before input) (+ parts form: `selectTriggerPressStart` / `selectTriggerPress` (useMenuTrigger press callbacks), `selectTriggerKeyDownCapture`); closed trigger uses data items (`selectCollection`); the open ListBox runs its own handlers (`../listbox/behaviour.tsx`), the select hooks in via `onSelectionChange` / `onBlur`
- `hidden-select.tsx` - hidden `<select>` (<= 300 items) else hidden `<input>`s (only with `name`); container = `span` (RAC: `div`; visually hidden + `position: fixed`) so a Select can sit in phrasing content such as a `<p>` (`@rivetjs/ui/inline-select`; a `<div>` start tag closes the paragraph in the HTML parser)

- `../state/select.ts` (value / open / focus / validation, region state; value = `controllable(value | selectedKey, default, onChange)` 3-arg form → `state.control`, plain controlled value or Signal; writes via `setControlledValue`); listbox selection = `createMultipleSelectionState` (`../selection/state.ts`) forced `controlled: true` (signal written only by `syncListSelection`) + a `ListState` object literal over the built collection

## Rules / invariants
- Root data attrs: `data-focused`, `data-focus-visible`, `data-open`, `data-disabled`, `data-invalid`, `data-required` (boolean `|| undefined`); trigger `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls` (only open), `data-pressed` while open, `data-rk={TRIGGER_KEYS}`; value span `data-placeholder`
- Ids from base `id` (generated when omitted): `<id>-trigger`, `<id>-trigger-label`, `<id>-value`, `<id>-listbox`, `<id>-popover`, `<id>-hidden`; trigger labelled by value + label (useSelect)
- Classes: `class` `rv-Select`, `triggerClass` `rv-Select-trigger`, `valueClass` `rv-SelectValue`, `labelClass` `rv-Label`, `descriptionClass` `rv-Text`, `popoverClass` `rv-Select-popover`, `listClass` `rv-ListBox`, `optionClass` `rv-ListBoxItem`, `sectionClass` `rv-ListBoxSection`, `headerClass` `rv-Header` (RAC part defaults); empty state = ListBox `renderEmptyState` (`div[role=option]`, no class); popover `data-trigger="Select"`, width via `--trigger-width` (theme.css)
- Part props: root takes global DOM props; `triggerProps` (OWNED `onPointerDown`, `onMouseDown`, `onClick`), `valueProps`, `popoverProps`, `listBoxProps` (spread into `ListBoxContext`: the ListBox's OWNED handlers run first); user handler runs after the select's
- Field callbacks `onFocus` / `onBlur` / `onFocusChange` / `onKeyDown` / `onKeyUp` via `SelectCallbacks` (trigger; listbox: `onBlur` / `onFocusChange` only, useSelect `menuProps.onBlur`)
- Popover lives in its own binding site (overlay anchor span): read its props into locals first (`index.tsx:236-244`); popover content is a function child; closed = renders nothing
- Listbox (ListBoxContext = useSelect `menuProps`): `autoFocus` accessor (`focusStrategy || true`), `shouldSelectOnPressUp`, `shouldFocusOnHover`, `linkBehavior: "selection"`, `escapeKeyBehavior: "none"`; selection: `disallowEmptySelection` for single, `allowDuplicateSelectionEvents` (re-select closes)
- Capture patterns (resume): closures in bags are inline arrows in object literals (`selection.onSelectionChange`, `listBoxContext.onBlur` / `autoFocus`); a closure must not reference the object it is created in (`listKeys` is its own const, else "Cannot access before initialization" on the server); a conditional or const arrow capturing content is NOT compiled into a closure (`renderEmptyState` goes in a conditional spread `...(empty != null ? { renderEmptyState: (v) => … } : {})`); no computed holding JSX content in captured state (collection built on use, cached per instance in a module `WeakMap` keyed by `listKeys`: `selectListCollection`); props destructured into locals before any binding (label, description, classes, autoComplete, transition)
- Popover content provides the list contexts with synchronous `provide(...)` + `ListBox({})` (a JSX `<Provider>` child is a lazy slot); the build pass clears `ListStateContext` / `ListBoxContext` (it runs where first read: inside the popover's providers)
- `shouldCloseOnSelect` defaults to single mode (`state/select.ts:116`); `canOpen`: empty collection opens only with `allowsEmptyCollection`
- `validationBehavior` default "native" (or enclosing `<Form>`'s); state default "aria"
- Pointer: mouse / pen open on pointerdown (focus trigger first), touch toggles on click, virtual click opens on "first"; keyboard Enter / Space / ArrowDown open "first", ArrowUp "last"; ArrowLeft / ArrowRight change value while closed (single); typeahead on closed trigger (single only)
- Hidden select: `aria-hidden`, `data-react-aria-prevent-focus`, `tabIndex=-1`; `change` / `input` set the value (autofill); `invalid` focuses the trigger; form reset restores `defaultValue`
- live props (P5): parts form (`SelectParts`) and preset run `liveOptions(props, ["isDisabled", "isInvalid", "isRequired", "placeholder", "aria-describedby"], ["value", "selectedKey"])` (controlled value = accessor via `controllable`; bodies under `untrack`); select state keeps a live `isDisabled` (`state.disabled`, read `isSelectDisabled(state)` in handlers / bindings; bags / ButtonContext / HiddenSelect get `selectDisabled(state)` = returned-arrow accessor when live, `selectDisabledAttr(state)` for render bags); parts root class / style / children from a live view. Live `isRequired` (LIVE-SWEEP 2026-10-11): `state.required` accessor (read `isSelectRequired(state)`; `selectRequiredAttr(state)` for render bags), root `data-required`, HiddenSelect `required`; live `placeholder`: SelectContext carries the accessor, SelectValue's `Show` fallback is a branch returning the text accessor (`placeholderBranch`: a text binding, static path unchanged). Read once: `name`, `form`, `selectionMode`, `disabledKeys`, `shouldCloseOnSelect`, `allowsEmptyCollection`, `aria-label` / `aria-labelledby`, `autoFocus`, `autoComplete`, `id`. HiddenSelect `disabled` is now a binding (one per Select). Tests `tests/live-props.browser.test.tsx`, story `tests-components/live-props.test.ts`

## Gotchas
- Listbox selection = its own signal, re-synced from the value (`syncListSelection`) by an `effect` created in the popover content (tracks the value while open) and after each pick; a derived signal from a `.ts` module would not serialize
- Commit after a pick needs the hidden field's document: from `rootRef` (`ref()` on the root `<div>`), never the `document` global (server build rejects it in .tsx)
- Listbox focusout while open with `relatedTarget` null / inside the popover is not a blur (one `onFocus` / `onBlur` pair per focus; `data-focused` stays while open)
- Tab / Shift+Tab in the open listbox stay inside the modal popover (`tests-components/select.test.ts`)
- Preset (with `items`) still monolithic outside the listbox (`renderValue`, `indicator`, `*Class`, `*Props` bags, `state` prop); parts form = RAC (2026-10-08, `tests/select.browser.test.tsx` = RAC Select.test.js port); the preset keeps the boolean `SelectRenderProps` name (docs), parts use `SelectPartsRenderProps` until the preset goes
- Parts form: SelectValue renders the selected item's ListBoxItem children (function children called with every state off), `selectedItem()` / `selectedItems()` = the item objects of a dynamic ListBox (`null` for static items); `<Popover>` children render inside the collection build pass (a computed): a component there that writes a signal (`ref()` signal binding) throws "Signal writes are not allowed during computed evaluation" — use callback refs (`tests/popover.browser.test.tsx` nested popover)
- JSX `indicator` not serializable (`index.tsx:219`, rendered `index.tsx:332`)
- Preload closure (PRELOAD-GROUP 2026-10-12, ui `select-default` frame): the root `preload="visible"` pulls ~420 KB raw / 150 KB br; with the compiler's shared chunk merging (`resume.merge`) 126 → 80 requests, 150 → 140 KB br before input (Chromium example check). Popover / overlay code is only ~1.2 KB of it as a separate root: `select-parts.tsx` imports the popover / overlay / focus modules statically, so cutting open-only code (~26 KB raw: overlay + popover) needs a lazy import of the popover part, not preload tuning.
- `onKeyDown` / `onKeyUp` only fire on the trigger (and listbox via callbacks), not root
- Trigger runs on `../_adapters/` (`collections.ts` ListKeyboardDelegate / typeahead, `selection.ts`, `interactions.ts`, `intl.ts`) - see `../_adapters/CLAUDE.md`
- Requested (gaps.md, user): chips inside the field (Group + TagGroup) and searchable Select (Autocomplete + SearchField in the popover) — possible with the parts form now (not demoed in cdk-docs yet); done: multiple stays open after a pick (`shouldCloseOnSelect` default), selected items rendered outside (`selectedItems` / `selectedItemsOf` + `removeSelected`, story `chips`)
- `data-*` value style: root / listbox / options `dataBool` (`"true"`), trigger `data-pressed="true"`, SelectValue `data-placeholder="true"`
