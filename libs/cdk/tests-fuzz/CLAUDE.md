# libs/cdk/tests-fuzz — resume fuzz over the cdk story app (Function Bridge T31)

- `resume-fuzz.test.ts`: vitest project `cdk-resume-fuzz` (node, Chromium via playwright, `fileParallelism: false`). Builds/serves the story app from `../tests-components` (`harness.ts` `stories`) with `STORIES_DIST=dist-fuzz` (own dist: never races `cdk-components`). One test per route of `../tests-components/app/src/routes/` + one `test.fails` per open pin.
- Driver + normaliser: `@rivetjs/testing/fuzz` (`libs/testing/fuzz/`, see `libs/testing/CLAUDE.md`); guide: `docs/guides/resumability.md` "Fuzz".
- `pins.ts`: known findings `{ route, kind, match, step?, owner, note, design? }`; `match` (substring / RegExp) is tested against the finding's `diff` only — the differing tokens (`line N <tag#id>: resumed only [...] / csr only [...]`), for a structural difference `resumed: <line>\ncsr: <line>`, the replaced nodes, the error — never context lines; `step` = 1-based step (0 = load). Keep matches narrow (a token with its value, not a bare attribute name). Open pin = `test.fails` (fixing the finding fails the suite: delete the pin). `design: true` = accepted or non-deterministic difference, filtered only (a finding that does not reproduce on every run must be `design`, else CI flakes; 3-run rule: 3 reruns of the route with identical findings before a `test.fails` pin, 1–2 of 3 = narrow `design` pin with the rate in its note — guide `docs/guides/resumability.md` "Fuzz"). A new finding fails its route test with the repro log: fix it, or pin it with an owner (triage table: spec `docs/design/specs/2026-10-09-function-bridge-design.md` §8.5).
- Run: `RIVET_FUZZ_LOG=1 RIVET_FUZZ_OUT=/path/results.jsonl npx vitest run --project cdk-resume-fuzz --maxWorkers=1`. Scope: `RIVET_FUZZ_ROUTES=tabs,/^\/visual\//` (substrings or /regex/), `RIVET_FUZZ_SHARD=1/3`, `RIVET_FUZZ_STEPS=40`. Never run both fuzz projects (or another Chromium suite) at once. CI: job `resume-fuzz` (app × 3 shards).
- Derived model: `RIVET_RESUME_MODEL=derived RIVET_FUZZ_SHARD=1/3 npx vitest run --project cdk-resume-fuzz --maxWorkers=1` (`RIVET_FUZZ_SHELL` is ignored: the shell cache rejects derived documents, `/shell-loader` is fuzzed as a plain render) (knob in `../tests-components/app/vite.config.ts`; the test file then defaults `STORIES_DIST` to `dist-fuzz-derived` and uses `pins-derived.ts`, never `pins.ts`). `pins-derived.ts` (M2-R5 2026-10-20, one run of 3 shards, union with the pre-fix runs): route + kind pins, empty match, all `design: true`, grouped by root cause (`PRESS` cold press, `RECREATE` adopt mismatch → browser render, `MOUNT` mount effects); 64 routes, 1,793 steps, 8 routes without findings (2 drive 0 steps). Narrow or delete a group's pins as its gap closes. DERIVED-C (2026-10-21; cold press port + cold hover, UNKEYED adopt, unrecorded build pass; 66 routes, 1,852 steps per run): 118 → 67 pins — 59 kept (PRESS 21, RECREATE 24, MOUNT 14; pins that passed in both full runs after the fixes deleted: PRESS 8, RECREATE 32, MOUNT 19) + `ADOPTED` (`/tag-group` mismatch: its page root adopts now, browser-created collection parts number `useId`s after the adopted ones) + `BASE` (`/deferred-loader`, `/dom-data`: red at base `dcc93d7ac` too; `/shell-loader` + `/shell-replay` added at intake: the same deferred hole, the shell cache rejects derived documents). Findings per run (before → after): recreated 25 → 5, PRESS mismatch 58 → 36; MOUNT top 3 = the serialized model's documented deviations (`aria-labelledby` without a server createSlotId check, 21 lines on 5 routes; measured layout styles of carousel / masonry / table; TabPanel `tabindex=0`, RA useHasTabbableChild) — same pins as `pins.ts`, not derived-specific.
- Lazy rows + DOM-DATA (LAZY-FLIP 2026-10-21): `RIVET_LAZY_ROWS=on RIVET_LAZY_ROWS_HARNESS=1 RIVET_DOM_DATA=1 RIVET_FUZZ_SHARD=1/3 npx vitest run --project cdk-resume-fuzz --maxWorkers=1` (the router's harness flag turns `resume.lazyRows` on, the app config's `RIVET_DOM_DATA=1` knob `resume.domData`; the test file then defaults `STORIES_DIST` to `dist-fuzz-flip` and uses `pins-flip.ts`). `pins-flip.ts` = `pins.ts` minus the pins these builds fix (`/scheduler` resume-error, `/tabs` `num-tabpanel-2` mismatch, `/selection-indicator-groups` recreated: 3/3 "Expect test to fail") plus flip-only findings (3/3 flip, 0/3 default, all from lazy rows: domData-only shows none): `/selection-indicator-groups` mismatch (the deselected lazy row materialises after the change, so its SelectionIndicator never snapshots the server element; the new one enters instead of sliding) and `/select-autofocus` design pin (autofocus fires before the loader is parsed; loader follow-up).
- Story routes added to `tests-components/app` are fuzzed automatically: pin or fix their findings in the same change.
