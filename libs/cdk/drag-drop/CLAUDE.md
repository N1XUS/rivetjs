# libs/cdk/drag-drop
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Angular CDK drag-drop: 1:1 engine port (DragRef, DropListRef, registry, sort strategies, preview) + Rivet components replacing the directives (`cdkDrag` → `<Drag>`, …), resumable. React Aria dnd engine (`/aria`, RA drag button on `DragHandle`) = later phase.

## Entry points
- `@rivetjs/cdk/drag-drop` → `index.tsx` (resolves through the package `./*` → `*/index.tsx` pattern): re-exports `cdk-index.tsx`.
- `@rivetjs/cdk/drag-drop/cdk` → `cdk-index.tsx`; `@rivetjs/cdk/drag-drop/utils` → `drag-utils.ts` (server-safe array helpers) — explicit `exports` entries pending (lead).
- Barrels must be `.tsx`: the resume build follows re-exports only through `.tsx` modules (a `.ts` barrel drops the component symbols from the client manifest → "Resume manifest has no chunk for …").
- Surface: `Drag`, `DropList`, `DropListGroup`, `DragHandle`, `DragPreview`, `DragPlaceholder` (+ `*Props`); `DragInstance`, `DropListInstance`, `DropListGroupInstance`, `DragHandleInstance`; `dragInstance(el)`, `dropListInstance(el)` (Angular `@ViewChild(CdkDrag)`); `DragDropConfigContext` / `DragDropConfig` (`CDK_DRAG_CONFIG`); event types (`DragStart`, `DragDrop`, …); `dragDrop` service object; `createDragRef` / `DragRef`, `createDropListRef` / `DropListRef`, `dragDropRegistry`, `SingleAxisSortStrategy`, `MixedSortStrategy`; `moveItemInArray`, `transferArrayItem`, `copyArrayItem`.

## Layout
- Engine (upstream files): `drag-ref.ts`, `drop-list-ref.ts`, `drag-drop-registry.ts`, `preview-ref.ts`, `drag-utils.ts`, `drag-drop.ts` (service), `drag-events.ts`, `sorting/*`, `dom/*` (+ local copies `coerce.ts`, `shadow-dom.ts`, `fake-event.ts`; Rivet `mount-content.ts`, `layout-shift.ts`, `inherited-text.ts`).
- Directive instances (`directives/`): `drag.ts` (`DragInstance` = CdkDrag), `drop-list.ts` (`DropListInstance`), `drop-list-group.ts`, `drag-handle.ts`, `config.ts`, `assertions.ts`, `registry.ts` (Rivet: attribute names, element → instance WeakMaps, wake protocol, DOM lookups).
- Components (`*.tsx`): `drag.tsx`, `drop-list.tsx`, `drop-list-group.tsx`, `drag-handle.tsx`, `drag-preview.tsx`, `drag-placeholder.tsx`; `lazy-refs.ts` = their handlers + lookups. `drop-list.tsx` does NOT import `lazy-refs.ts` (BIG-UI 2026-10-27): its handlers call `registry.ts` `listHost.event` / `listHost.destroyed`, which `lazy-refs.ts` sets when it evaluates. Everything that needs a list's instance (an item's press / wake via `drag.tsx`, `dropListInstance`, a connected list's engine) imports `lazy-refs.ts` statically, so the hook is set by then; a press in a list no item ever meets creates nothing. A page whose lists never hold a `<Drag>` (the scheduler's external-drop hit area without external items, a list not rendered) ships no engine (~19 KB gz).
- Tests (in `../tests`, `../tests-components`): `drag-utils`, `drag-drop-registry`, `drag-drop-service` (project `cdk`); `standalone-drag`, `drop-list-single-axis`, `drop-list-mixed` `.browser.test.tsx` (Chromium, `drag-test-utils.tsx`, `drop-list-shared*.tsx`, `drop-list-fixtures.tsx`); `tests-components/drag-drop-resume.test.ts` (story `/drag-drop`).

## Rules / invariants
- Engine stays 1:1 with upstream; deviations only in headers (no DI / NgZone / Renderer2; `Emitter` for Subjects; rAF loop; resets `<style>` on first drag; `ElementRef` → `{nativeElement}`).
- Deviation (KANBAN-DND 2026-10-08, user bug "another column list not smooth shift"): upstream moves the placeholder between connected lists with a plain DOM insert, so the receiving list's items (and the source list's, once the placeholder leaves) jump; only in-list sorting animates. `DropListRef.enter` / `exit` FLIP the non-dragged items instead (`dom/layout-shift.ts`): rects read before the change (`enter`: after `beforeStarted` synced the items, before the sort strategy measures), then in a microtask (after the whole pointer move) each moved item plays an additive Web Animation (`composite: "add"`, id `rv-drop-list-shift`) back to zero, so sort transforms + their CSS transitions keep working on top and inline styles never see it. Timing = the item's computed `transform` transition after the change, else before it (the source loses `cdk-drop-list-dragging` on exit); no transform transition → upstream jump (upstream specs unaffected: fixtures have none). `start` / `enter` cancel running shifts before measuring. Tests: "layout shift between connected lists" in `drop-list-single-axis.browser.test.tsx`.
- Deviation (2026-10-08, user bug "kanban dragged item - missing paddings"): `drag-drop-registry.ts` `loadResets` inserts the resets `<style>` FIRST in `<head>`, so `@layer cdk-resets` is the lowest-priority layer. Appended (upstream), it was declared after an app's layers (Tailwind v4) and its `padding: 0` / `background: none` / `border: none` beat the preview clone's `p-*` / `bg-*` / `border` utilities. Unlayered app CSS wins either way. Test: "layered styles win over the preview resets" in `drop-list-single-axis.browser.test.tsx`.
- Deviation (2026-10-09, user bug "kanban - dragged item has different font sizes"): a `global` preview (in `<body>`) inherited the body's text styles, so a card in a `text-sm` board showed its plain text at 16px next to its unchanged `text-xs` parts. `DragRef` passes the dragged element's parent to `PreviewRef.attach(parent, inheritFrom)` (global only; `parent` / element containers keep their own inheritance); `dom/inherited-text.ts` `carryInheritedText` copies its computed inherited text properties (color, font family / size / style / weight / variant-numeric / feature-settings, line height, letter / word spacing, text-align / -transform, white-space) onto the preview as `--rv-drag-<property>` custom properties, and the resets layer sets `<property>: var(--rv-drag-<property>, inherit)` (`INHERITED_TEXT_RESETS`): lowest priority, so the element's classes and app `.cdk-drag-preview` rules still win. Unitless line heights stay factors (Typed OM `computedStyleMap`). Custom properties / other inherited styles still come from `<body>`. Tests: "global preview typography" in `drop-list-single-axis.browser.test.tsx`.
- Lazy instances: nothing runs before the first press. A `<Drag>` / `<DropList>` element's own `mousedown` / `touchstart` / `dragstart` handler creates its instance from the props it captured (`dragHostEvent` / `dropListHostEvent`); other lists / API lookups wake an element with a non-bubbling `CustomEvent("dragstart", {detail: WAKE})` so its own handler runs. Handles, groups and templates are DOM-derived (`data-rv-drag-handle`, `data-rv-drop-list-group`, `<template data-rv-drag-preview|placeholder>`): they ship no code.
- Cold press: the loader replays it after the chunks load; `_pointerDownFromHost(event, age)` keeps the original timing (drag-start delay) and ends the sequence on the next move when the press was released meanwhile (instead of a loader `pointerup` timestamp: 0 loader bytes). Replayed = handled after its dispatch ended (`eventPhase` NONE) or more than `REPLAYED_AFTER` (50 ms) late (`lazy-refs.ts` `dragHostEvent`): age alone missed fast replays (route / merged chunks preloaded: replay ~15 ms after the press), so a press whose `mouseup` the loader never held (no resumed handler) kept its sequence and the next move dragged an element the replayed click had removed (`null.insertBefore` in `_startDragSequence`; ui-docs `showcase-kanban` build, KANBAN-BUILD 2026-10-19); test "fast cold-press replay" in `drop-list-single-axis.browser.test.tsx`. A press handled after its dispatch ended (`eventPhase` NONE: the replay, also on a resumed page whose runtime started late) clears the text selection its default action started before the registry's `selectstart` listener existed (user bug 2026-10-09: the first kanban drag selected a neighbouring card's title; Playwright real input, warm or cold; later drags were fine); test "replayed press text selection" in `drop-list-single-axis.browser.test.tsx`.
- Lazy instance lifetime (ARM-FIX 2026-10-19): `DragSetup.element` = the `<Drag>`'s `ref()` (captured by its handlers, so each server `<Drag>` ships one `{s}` → `{r, z}` ref entry); `dragHostEvent` calls `DragInstance._releaseWith(ref)`: an owned effect destroys the instance (Angular `ngOnDestroy`) once the ref stops holding the element — client unmount (`bindRef` cleanup) or, on a resumed page, the death of the server element's region (the row a `For` drops: the runtime resets the revived ref). Before, a resumed row's lazily created instance stayed in the registry (`_dragInstances` + the document `touchmove` listener), its list's `_unsortedItems` (until the next `_collectItems`) and its sync effects. A ref already reset when the handler runs (region dead before a replayed press) on a detached element: destroyed at once, the press ignored. Tests "resumed row removal" in `drop-list-single-axis.browser.test.tsx`. `<DropList>` instances have no such hook yet (a resumed list dropped keeps its instance: gap).
- `preload = "visible"` on `drag.tsx` / `drop-list.tsx`: first drag after preload is synchronous.
- Server markup: `cdk-drag` / `cdk-drop-list` / `cdk-drag-handle` + `rv-*` default classes, `data-disabled`, `data-orientation`, `freeDragPosition` transform (`getTransform`), handle native-interaction styles = `nativeDragInteractionStyles(false)` (`dom/styling.ts`, shared with `toggleNativeDragInteractions`). Upstream sets no touch-action on a drag root at rest, so neither do we. Host attributes (UI-PORT-C): `Drag` / `DragHandle` / `DropList` / `DropListGroup` forward `hostDOMProps` (global DOM props + every `aria-*` + `role`, live values update) — upstream directives keep whatever the template writes on the host element (no upstream spec; `tests/drag-host-attributes.browser.test.tsx`). `<Drag>` owns `style` (`OWNED` in `drag.tsx`, not forwarded by `hostDOMProps`): merged with `style:transform` — a spread `style` would duplicate the attribute on the server and overwrite the transform in the browser (compiler gap: spread + `style:prop`, scratchpad compile-rs-patches/MATRIX-1.md).
- Client-only work keys on `globalThis.document` (bare browser globals are RV2001 in server-rendered `.tsx`), never on `getOwner()` (set during server renders too) nor on the `ref()` shape (the serialized server ref's `id` is gone since M6-CUT). `drag.tsx`, `drag-preview.tsx` / `drag-placeholder.tsx` (server: content inside the `<template>`; browser: `mountTemplateContent` replaces the template fragment's server content, then mounts).
- Function-valued inputs (`constrainPosition`, `enterPredicate`, `sortPredicate`) are plain functions (not accessors); other inputs take a value or an accessor/signal. Upstream-writable instance fields (`sortingDisabled`, `enterPredicate`, `sortPredicate`, `autoScrollDisabled`, `autoScrollStep`) have setters (`_assigned` override).

## Gotchas
- Nested lazy `<Drag>` (instance created by its delegated pointerdown): the outer DragRef's native root listener runs before that delegated handler under DOM v2 (spec P4), so `DragRef._beforeRootPointerDown` (set by `directives/drag.ts`) creates the nearest uncreated nested drag on the composed path first and hands it the event (`_pointerDownFromHost`); a stopped event skips the outer drag (Angular: inner drag's handler stops propagation first). Multitouch nested drag spy ×2 under v2 (V2-FIX R4)
- `dom/mount-content.ts` (`.ts`, not server-rewritten) imports real `@rivetjs/runtime/dom` into the server bundle: fine today (no import-time DOM work), `mount` is only called in the DOM branch. Keep it that way or switch to a dynamic import.
- Resumed pages: an alternate root (`rootElementSelector`) only starts a drag after the `<Drag>` element itself was pressed (client renders watch the root with a document capture listener, `watchRoot`); a drag disabled at render keeps its server-rendered handles' `touch-action: none` until its instance exists (client renders sync them, `syncHandleInteractions`); a `<DragHandle>` enabled while its drag is disabled re-applies the native-interaction styles.
- A keyed `<For>` as `<DropList>` children reorders the same rows after a drop on a resumed page (drag-drop-resume "a drop reorders the For rows…", a plain `test` since the runtime fix; the file header still mentions `test.fails`).
- `<DragHandle>` costs one `data-r` (element ref) per handle on the server.
- Chromium synthetic `new MouseEvent(..., {clientY})` reports `pageY` without the page scroll: drag tests on scrolled pages must use real input (Playwright mouse) or unscrolled fixtures.
- Test env: `drag-test-utils.tsx` sets `body { margin: 8px }` (Karma default the upstream expectations include).
- `dom/coerce.ts`, `dom/shadow-dom.ts`, `dom/fake-event.ts` duplicate `coercion/`, `platform/`, `a11y/focus-monitor.ts` helpers — dedupe later.
- `virtualizer/types.ts` keeps its own drop-target types (React Aria dnd phase).
