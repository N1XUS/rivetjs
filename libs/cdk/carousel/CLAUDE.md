## Parts / props
- `Carousel`: embla options as props (`ENGINE_KEYS`: align, axis, direction (default = locale), loop, slidesToScroll, containScroll, dragFree, dragThreshold, duration, startIndex, skipSnaps, inViewThreshold, watch*, breakpoints, active) + `autoplay`, `autoScroll`, `plugins: () => EmblaPluginType[]`, `slideCount`, `tabs`, `onApi`, `onSelect`, `onSettle`, aria label props. Root: `role="region"`, `aria-roledescription="carousel"`, `data-orientation` / `data-loop` / `data-draggable` / `data-dragging` / `data-playing` / `data-ready`, `data-rk` arrows, keydown + focusin.
- `CarouselViewport`: embla root, inline `overflow:hidden` + `touch-action` (pan-y / pan-x pinch-zoom), pointerdown / mousedown / touchstart chained before the user's; `ref` merged with the parts ref.
- `CarouselContainer`: embla container, inline `display:flex` (column for `axis="y"`); `items` / `by` / function child via `For` + slide-index context, or static children (render-order index); `aria-live` off while rotating, else polite; server `startIndex` offset as CSS `translate` (see Gotchas).
- `CarouselSlide`: `role="group"` (`tabpanel` with `tabs`, labelled by its tab), `aria-roledescription="slide"`, label `"N of M"` once the count is known, `data-index` / `data-snapped` / `data-in-view`, inline `flex: 0 0 var(--rv-carousel-slide-size, 100%)` + `min-width/height:0`.
- `CarouselPrevious` / `CarouselNext`: cdk `Button`, labels "Previous slide" / "Next slide", `aria-controls` viewport, `isDisabled` accessor default `!canScrollPrev/Next`.
- `CarouselRotationControl`: cdk `Button`, label from `isRotating` ("Stop / Start automatic slide show"), `data-rotating`.
- `CarouselDots` (`role="tablist"`, label "Choose slide to display", APG automatic activation, Home/End, loop wrap) / `CarouselDot` (`role="tab"`, `aria-selected`, roving tabindex, `aria-controls` = snap's slides, label "Slide n", `data-selected`).
- Render props (accessors): selectedIndex, snapCount, canScrollPrev/Next, isPlaying, isRotating, isDragging, orientation, state; slide + index/isSnapped/isInView; dot + index/isSelected. `render` (RAC DOMRenderProps) on every native-element part.
- `class` props typed `ClassNameOrFunction<…>` (not `RenderProps<…>["class"]`: exactOptionalPropertyTypes in consumers' `.d.ts`).

## Resume / zero cost
- No engine before interaction: handlers call `ensureCarousel` synchronously. Cold first `mousedown` / `touchstart` (replayed, `eventPhase` 0, after embla's own listener would have missed it) → `carouselDragStart` → `DragHandler.pointerDownEvent`; mouse safeguard dispatches a synthetic `mouseup` if the button is already up on the first move.
- First-input latency (2026-10-08): root + viewport divs carry `preload="visible"` (literal directive; not on the `render` path): their handler chunks + dependency chunks (bindings reading the carousel state, incl. slots `renderProps` / `renderValues`) are fetched + evaluated when visible, nothing runs (engine still starts in the first handler). Slow network (`../tests-components/cold-latency.ts`, 150 ms RTT, 4x CPU) p50 click lost (3/3) → 75 ms, key 166 → 33, tap 200 → 37, drag ~515 → 215 (gesture time).
- Cold press fix (2026-10-08, `../interactions/press.tsx`): the Next button's chunks were in, the root's `focusin` chunk was not → the press ran at pointerdown, the loader held the click behind the cold focusin replay and RA's 80 ms "pointerup without click" fallback cancelled the press; the press now waits (≤ 10 s) for a click the document saw but its handler has not. Test: `../tests-components/carousel.test.ts` "held behind a loading chunk" (route-gated root chunk; fails without the fix).
- `clientEffect(carouselEffect, { when: "visible" })` is recorded only on client renders (`typeof document !== "undefined"`), with rotation, or with `plugins` / `onApi` (2026-10-08: embla inits plugins + API listeners on mount, so Fade / AutoHeight / tweens style the slides before the first interaction; documented preload).
- Rotation plugins: dynamic `import()` on first use (`loadRotationModules`) — 0 B for carousels without them. The runtime still adds `modulepreload` links for those dynamic chunks once the behaviour chunk loads (fetch only; runtime policy).
- `@rivetjs/cdk/motion` is its own subpath; carousel-free apps import nothing of either.

## Deliberate deviations / additions
- `DragHandler.pointerDownEvent(evt)` (Rivet addition): the stored `downIfAllowed` listener, so a replayed cold pointer down can start a drag.
- Motion split into `../motion` (math identical; carousel engine wraps it).
- APG rotation defaults for Autoplay / AutoScroll: `stopOnMouseEnter: true`, `stopOnInteraction: false`, `stopOnFocusIn: false`, `rootNode` = the `Carousel` root (hover over slides + controls); keyboard focus (`:focus-visible`) / rotation control stop rotation by `reInit` without the plugins (`isRotationStopped`, so `mouseleave` cannot restart); `isRotationStopped` starts true when every rotation plugin has `playOnInit: false`.
- Reduced motion (embla has none): `behaviour.tsx` `reduceMotion` sets the scroll body duration to 0 on `select` / `pointerUp` / `scroll` while `matchMedia("(prefers-reduced-motion: reduce)")` matches (read per event = live), no pointer is down and AutoScroll is not playing → prev / next / dots / keys / autoplay / drag release / edge bounce land on the next frame; dragging still follows the pointer.
- ClassNames plugin → headless `data-*` on the parts (plugin still exported for custom markup).
- `carouselKeyDown` ignores `defaultPrevented` on replayed events (`eventPhase` 0): the loader `preventDefault`s held `data-rk` keys.

## Gotchas
- A translated container is its slides' `offsetParent` (Chrome) and embla measures `offsetLeft`: the server offset uses the CSS `translate` property (not `transform`), `startCarousel` clears it before `EmblaCarousel()`, and the container style drops it once `isReady`.
- Static children: "N of M" labels / `startIndex` offset / button states at SSR need `slideCount` (or `items`); otherwise they appear when the engine starts. SSR offset is exact only for uniform slides without gaps.
- Engine on a resumed page started by a handler is not destroyed when its region is disposed (no clientEffect cleanup) — only the client-render / rotation path has one.
- First Tab focus into a slide before init: SlideFocus emulated (`scrollTo(snap, true)` + `scrollLeft = 0`).
- Touch cold replay has no release safeguard (mouse only).
- Inactive engine (`active: false`, also per `breakpoints`): embla sets `plugins()` only in `activate`, so it returns `undefined` — `sync` / `stopRotation` / `startRotation` read `api.plugins() ?? {}`.
- Resumed page + DOM plugins that add classes (ClassNames): fixed in the runtime 2026-10-08 — the server records the slides' rendered string class (` =class` spread token), so the resumed `_spread`'s first run (first signal change after the engine starts, `sync`) leaves an unchanged class alone and `is-snapped` set at init stays (`libs/runtime/tests/resume-spread-class-browser.test.ts`). A class that does change is rewritten, as on client renders. Inline styles (Fade / tweens) survive (per-property diff). The class-names examples dim with plain `.slide:not(.is-snapped)` and assert slide 0's `is-snapped` at load.
- `behaviour.tsx` reads `globalThis.document` (bare `document` in a server-rendered `.tsx` = compiler RV2001).
