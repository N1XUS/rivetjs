# @rivetjs/cdk/slots
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

THE RAC slot / context / render-prop contract (port of RAC `utils.tsx`). Every RAC part reads its context with `contextProps`; containers provide part props with `<Provider values>`.

## Entry points
- `@rivetjs/cdk/slots` -> `index.tsx`

- `DOMRenderProps` / `DOMRenderFunction` re-exported from `../utils/render.ts` (RAC `utils` exports them)

## API (contract — other lanes build on these exact signatures; RAC `useX` → Rivet names per cdk naming convention: `useContextProps`→`contextProps`, `useSlottedContext`→`slottedContext`, `useRenderProps`→`renderProps`, `useSlot`→`createSlot`, RA `useSlotId`→`createSlotId`)
- `DEFAULT_SLOT` (string `"__rv_default_slot"`, not a Symbol: must serialize)
- types: `ContextValue<T, E>` (= `SlottedContextValue<WithRef<T, E>>`, `id` may also be a `SlotId`: props + `ref`, or `{ slots: { [name | DEFAULT_SLOT]: props } }`), `SlottedContextValue<T>`, `WithRef<T, E>`, `SlotProps { slot?: string | null }`, `RefValue<E>` (`ref()` | callback | `{ current }`), `ProviderValue<T> = [Context<T>, T]`, `StyleProps`, `DOMProps`, `HTMLProps<"tag">` (native attrs minus children/ref/slot/class/style), `StyleObject`, `ClassNameOrFunction<T>`, `StyleOrFunction<T>`, `StyleRenderProps<T>`, `ChildrenOrFunction<T>`, `RenderProps<T>`, `RenderPropsHookOptions<T>`, `RenderPropsHookRetVal`, `RACValidation`, `SlotId`
- `<Provider values={[[HeadingContext, {...}], [ButtonContext, { slots: { close: {...} } }]]}>children</Provider>` — nested runtime `Provider`s, outermost first
- `slottedContext(context, slot?)` → value for slot; `slot === null` → `null`; slotted value without that slot → throws `Invalid slot "x". Valid slot names are …` / `A slot prop is required. …`
- `contextProps(props, props.ref, Context)` → `[mergedProps (no ref), ref]`: own props win (`mergeProps`: handlers chain context-first, classes join, ids merge); `style` objects merge, style functions compose (RAC); ref: one side → that ref; both → fresh `ref()` + `clientEffect` copying the element to both (merged callback refs are not resumable). Static path: one rest copy of the context (merged into in place: `mergeCopy(…, true)`, no second getter scan), own props read without a copy unless they hold `ref`. Live props (P5): own or context getters → `liveContextProps`: `splitProps` parts without `ref` (forwarding unread) merged by the cdk `mergeProps` live path; slot / merged ids replaced by their plain id (read once); `style` on both sides → a composed style function read at render-prop time
- `mergeRefValues(a, b)` — the ref merge above (RA `mergeRefs` / `useSyncRef` for Rivet refs)
- `renderProps({ class, style, children, values, defaultClassName, defaultStyle, defaultChildren })` → `{ class(): string | undefined, style(): StyleObject | undefined, children(): Content }`; `const rp = renderProps(…)`, read INSIDE bindings: `class={rp.class()}`, `style={rp.style()}`, `{rp.children()}`. `values` = render props object of ACCESSORS (`{ isHovered: () => boolean }`); user fns get `{ ...values, defaultClassName | defaultStyle | defaultChildren }`. `renderProps(options, from?)`: `from` (a `liveView(props, ["class", "style", "children"])`, or `LiveRenderProps` = one view per key `[classView, styleView, childrenView]`, live props P5) supplies class / style / children read inside the accessors; without it the options' values are used (static path: DIET-STATE 2, 2026-10-22, `classOf` / `styleOf` / `childrenOf` return one `{ fn: () => … }.fn` per value shape, and only a FUNCTION class / style / children captures `values` — a string class, a style object or plain children resume with the resolved value and no render-props bag; cdk story pages −18.9 KB br state, `/calendar` 30,720 → 26,568). `renderPropsOf(props, { values, defaultClassName, … }, keys?)` = `renderProps({ ...props, … })` for a part's own props: live → class / style / children through one `splitProps` view per key (`liveRenderProps(props, keys?)` → `[classView, styleView, childrenView]`, a left-out key = empty view: on a resumed page each accessor captures only its key — a `children` function capturing a class instance, a calendar cell's `date`, no longer fails the class / style binding; RESUME-BUGS 2026-10-09, ui-docs calendar-with-indicators; LIVEVIEW: every cdk part), static → the values (`keys`: only those). Call it directly as the `rp` initializer (no `untrack(() => …)`, no inline arrow in the options): a function in the initializer makes the compiler capture `rp` whole in spread sites (member captures `rp.class` / `rp.style` otherwise). `contextProps` live style compose (both sides set) reads one-key `style` views, never the whole own / context props
- `composeRenderProps(value, wrap)` → `(renderProps) => wrap(resolved, renderProps)`
- `createSlot(initialState = true)` → `[Ref<Element>, hasSlot()]`: put the ref on the slotted element (via its context value); `hasSlot()` = ref set (RAC useSlot: set on mount, reset on unmount), or `initialState` on the server; `hasSlot` is resumable (bindings may capture it)
- `createSlotId(id?, deps?)` → `SlotId { id, rendered: Signal<boolean | string> }` (`rendered` is the part's own id string when it rendered with an `id` prop ≠ the slot id — RA mergeIds: `slotIdRef` returns that id, so a Dialog's `aria-labelledby` follows `<Heading slot="title" id="x">`; `syncRendered` / `probeSlot` use it too) (RA `useSlotId(depArray)`; plain data + signal: serializable). Client: `rendered` starts `true` (first client render keeps the id, whatever the order of consumer and part); a `clientEffect` after mount (one microtask later, after DOM updates) sets it to `!!document.getElementById(id)` and re-runs when signals read by `deps` change. Server (UI-COLD 2026-10-08): no check effect (any `fx` sets `data-boot` = idle runtime boot): `rendered` starts `false`, `markRendered` sets it (no server cleanup) so the serialized flag says whether the part is in the HTML; only a part of an id created with `deps` records its unmount cleanup (`clientEffect`, boots). `slotIdRef(slotId, expected = true)`: on the server an unrendered id is kept while `expected` (part may render later in the tree: RA server HTML); FieldError ids pass the validity (`slotIdRef(errorId, isInvalid())`: RAC FieldError renders only while invalid). Deviation: a server id whose part never rendered (no `deps`) stays in the owner's attribute until that binding re-runs (validity change, part mounting); a client check that finds such an id strips the token from `aria-describedby` / `aria-labelledby` (`syncRendered`). Server probe (COMBOBOX-DEV 2026-10-08): an owner whose attributes are written before its parts (ComboBox input, Select trigger, TextField / SearchField / NumberField input, CheckboxGroup / CheckboxField, RadioGroup / RadioField, DateField, DatePicker, ColorField, ListBoxItem, MenuItem, alert Dialog — UIID 2026-10-12) runs `probeSlots(contexts, () => children)` (`collections/server-on.tsx` via the cdk `#server` import; browsers resolve a no-op) first; hideable parts (`Text`, `ComboBoxValue`, `Keyboard`) call `probeSlot(props, context)` in the probe (`slotProbing`) and mark their slot id, so the owner reads `slotIdRef(id, false)` and the resumed page never carries a dangling IDREF. A `when: "interaction"` check was tried and dropped: it loaded the owners' chunks mid-typing (lost DateField keys). Fast path: a part consuming the SlotId as its context `id` (`[TextContext, { slots: { description: { id: slotId } } }]`) through `contextProps` sets `rendered` true on mount, false on unmount. Owner reads `slotIdRef(slotId)` (`rendered() ? id : undefined`) inside the aria-labelledby / -describedby binding. `deps` must be resumable: a signal / computed / local const fn, NOT an inline arrow argument ("function is not serializable"). `isSlotId(v)`
- `removeDataAttributes(props)`; re-exports `createContext`, `useContext`, `Context`, `resumableContext`
- part contexts (own folders): `HeadingContext` (`rv-heading`), `TextContext` (`rv-text`), `HeaderContext` (`rv-header`), `SeparatorContext` (`rv-separator`), `KeyboardContext` (`rv-keyboard`), `InputContext` (`rv-input`), `TextAreaContext` (`rv-text-area`), `LabelContext` (`rv-label`, in `label/`); `FocusableContext` (`rv-focusable`, `focus/focusable.tsx`); `PressResponderContext` (`rv-press-responder`, `interactions/press.tsx`)

## Rules / invariants
- `AccessorProps<T, Except>`: props type whose non-`on*` values may be accessors (Input / TextArea props: `"aria-invalid": () => invalid()`); `markRendered` writes skip no-ops and defer (microtask) when made during a computed evaluation (build pass)
- context tokens: `resumableContext(createContext<ContextValue<P, E>>({}, { id: "rv-<name>" }))`; values serializable (plain data, signals, `ref()`, R2 functions = inline arrows / local consts)
- prop names: `class` (RAC `className`); render props are accessors (component runs once; only bindings re-run)
- context values may be ACCESSORS (state-dependent props: `"aria-invalid": () => invalid()`, `children: () => title()`): `contextProps` passes them through untouched; Heading / Text / Header / Label / Keyboard render `children` with `renderSlot` (function child = reactive content in a child binding); Input / TextArea read `disabled` / `aria-invalid` with `read()` inside bindings; other accessor attributes are spread as-is (spread resolves function values of non-`on*` keys)
- spread parts: destructure `children` / `class` / `slot` before JSX; `slot={slot ?? undefined}` (null → absent)
- Deviations: no `data-rac`; no `render` prop / `dom` proxy; `createSlot` / `SlotId` instead of layout effects
- `createSlot` server value (CDK-PINS 2026-10-12): `initialState`, or `true` once `markSlotRendered(ref)` ran for its ref earlier in the render (Label marks its context ref) — RAC useSlot's ref callback turns a `false` initial state (`aria-label` given) true when the part renders; a part rendering after the owner's attributes keeps the initial value. `markSlotRendered` is exported for cdk parts (only `label/` calls it) but `@internal`: not public API, not in cdk-docs.

## Gotchas
- closures this module returns / assigns that bindings may capture MUST be object-literal function values (`const o = { fn: () => … }; return o.fn`): R2 rewrites only those (and inline JSX / handler arrows); an arrow in an array literal, a plain local const, or `obj.x = () => …` → server 500 "capture #N function is not serializable" (`createSlot` hasSlot, `contextProps` style merge, `composeRenderProps`; tests: story `/slots` HasSlot / MergedStyle)
- resumed page: a server-rendered slot element removed by `Show` keeps its `ref()` value (runtime gap, lane R ref-reset fix queued) → `hasSlot` stays true there
- a JSX value stored in a const and inserted later (`const content = <P>…<Show/>…</P>; return <div>{content}</div>`) loses the `Show` region on resumed pages (toggling does nothing) — render inline
- element spread rejects `style` ("Unsafe attribute name", runtime `dom.ts` bindAttribute / `dom-v2.ts` UNSAFE_NAME): parts destructure `style` and bind `style={…}` explicitly; never leave `style` in a spread object
- a spread never sets `ref`: render-function children of `Pressable` / `Focusable` pass `ref={p.ref}` explicitly
- `contextProps` with both refs boots a `clientEffect` (runtime at idle on resumed pages) — prefer one ref
- `Dynamic` (non-compiled tags: Text/Label/Separator custom `elementType`) drops event handlers on the server (not resumable)
- `MergedId` (`createMergedId(id?)`, `isMergedId`, `mergedIdOf`): RA mergeIds for an id a parent generates and a child may override. Context `id` = MergedId → `contextProps` sets `ctxProps.id = merged.id` and writes a non-empty own id into `merged.current` (parent reads `current()` for aria-controls etc.)
