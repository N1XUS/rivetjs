## Rules / invariants
- Layout runs on integers only: days = day numbers, event times = wall minutes (`day * 1440 + minute`) on the wall clock of the scheduler `timeZone`. Events are normalized once (`normalizeEvent` reads the dates; nothing downstream touches a date object). Segment / lane / cluster order and keys are malva's (`${id}:r${startIndex}`, `${id}:c${dayIndex}`).
- `DateValueString` bodies are proleptic Gregorian ISO (`[u-ca=…]` only names the calendar to parse back into), so strings are read with one regex and no calendar code; non-Gregorian instances go through `toCalendar(v, gregorian)`. Write-back: string in → string out (same shape + annotation), instance in → same class / calendar / zone; `allDay` decides date-only vs timed for a date `like`; DST gap → `"compatible"`.
- Unparsable dates → `normalizeEvent` returns `null` (malva: Invalid Date propagates); the event is not shown, `schedulerNormalizedEvents` warns once per event object in dev (`tests/scheduler-dev.test.ts`).

- State = strings / numbers / plain objects only (keyed state ships as data); the state never wraps options in accessors or computeds: the `.tsx` components pass inline arrows and memoize the derived functions.
- `onVisibleRangeChange` fires from the state mutation functions only when the day bounds move (before / after compare through `controlledValue`), never on init and never for writes the caller makes to its own `date` / `view`; each fire announces `rangeChanged`.
- Read once: `renderHeader`, `renderSlotMenu`, `renderEventMenu`, `canMove`, `canResize`, `onEventMove`, `onEventResize`, `onVisibleRangeChange`, `onRangeSelect`, `onExternalDrop`, `onEventAction`, `onEventDoubleClick`, `onEventContextMenu`, `onEventDelete`, `onSlotAction`, `onSlotDoubleClick`, `onSlotContextMenu`, `dropGroup`, `onEventsChange`, `onViewChange`, `onDateChange`, `onMoreAction`, `defaultEvents`, `defaultView`, `defaultDate`, `renderEvent`, `stateRef`, `id`. ## Adapter mapping (malva `MlvDateAdapter` → integers)
`addCalendarDays` / `shiftDays` → `day + n`; `startOfDay` → `dayOf(wall) * 1440`; `compareDate` / `compareDateTime` / `sameDate` → integer compare; `addMinutes` / `withTime` / `minutesOfDay` / `differenceInMinutes` / `getHours` / `getMinutes` → minute arithmetic; `getDayOfWeek` → `dayOfWeek`; `getMonth` / `getYear` / `createDate` / `addCalendarMonths` → `civilFromDay` / `dayFromCivil` (month range edges only); `today` / `now` → `todayDay` / `nowWall`; labels → `formatDay` / `formatWall`.

## Deviations
- Wall-clock arithmetic: a moved timed event keeps its wall-clock duration (malva: elapsed minutes); the two differ only across a DST shift inside the event. `isLaneEvent` was already wall-clock in malva.
- `SchedulerEvent`: `tone` → `color` (`info` → `accent`), `color` → `cssColor`, `draggable` / `resizable` → `isDraggable` / `isResizable`.
- Drag ghost id suffix `__rv-ghost` (malva `__mlv-ghost`).
- Naming: `isReadOnly` (malva `editable`), `allowsRangeSelection` (`selectable`), density `compact | default | comfortable` (spec §0 ruling).
- `+N more` panel = cdk `Popover` (malva `MlvPopupService`); its `onMoreAction` payload = the hidden events (malva implementation; its type doc said all events).
- Time grid: the all-day band never collapses (malva; spec "month + all-day cap" ruled out in T4: no all-day overflow UI exists upstream); no server `data-scroll-to` (the effect derives its target from the state); a roving stop is a day number + minutes, kept while the day stays visible and the slot rendered.
- Drag engine (T5 ruling, spec §12 R1): cdk `DragRef` instead of SortableJS, pinned root + own clone (a cdk drop container would move the chip into `<body>`: unsafe under `For` rows); the `+N more` panel is not a drop list (hidden during the gesture so the grid under it is the target; closes after) and its chips have no resize handles; no root `user-select` toggle (month grid + sheet carry inline `user-select: none` always; the cdk registry blocks `selectstart` while dragging). Kind conversions (spec "Written-back dates"): all-day → timed writes date-times; timed → all-day keeps the input class / string shape at midnight (`…T00:00:00`, `allDay: true`); zoned stays zoned.
- Pass `timeZone` on SSR pages for local time: without it the server lays out in UTC and the resumed page keeps UTC (`state.zone`); malva runs client-side in the local zone.
- `onVisibleRangeChange` not emitted on init (malva emits the initial range): the initial range belongs to the route loader.
