# @rivetjs/cdk/data-grid
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Rivet-authored (not a port): headless, data-driven grid. Feature set inspired by HeroUI Pro's public DataGrid docs (https://heroui.pro/docs/react/components/data-grid: prop / column / section names only); independent implementation — no Pro source, styles, class strings, demos or bundles were viewed or copied (clean room, user request 2026-10-08). Keyboard / focus / selection / sorting semantics follow React Aria's table (`../table`, the faithful RAC port, stays the composable sibling).

## Entry points
- `@rivetjs/cdk/data-grid` -> `index.tsx` (package.json `./*`): `DataGrid<T>`, `DataGridProps`, `DataGridColumn` (+ `header` string | fn({ sortDirection: accessor }), `cell(item, column)`, `headerClass`, `cellClass`), `DataGridHeaderInfo`, `DataGridStrings` / `defaultDataGridStrings`, `DataGridCheckboxState`, `SELECT_COLUMN` / `DRAG_COLUMN` (utility column ids `__rv_select` / `__rv_drag`), `DataGridReorderEvent`, `DragState`, `SelectionBehavior`, + everything of `state.ts`.

## Layout
- `state.ts` — pure, DOM-free: `dataGridRows` pipeline (filter keeping ancestors → stable per-level sort → flatten expanded (`"all"` too) → paginate, page clamped; rows `{ key, item, depth, parentKey, hasChildren, posInSet, setSize, index }`), `compareValues` (nulls last, numbers, dates, booleans, `Intl.Collator` numeric) / `collatorFor` / `columnComparator` / `sortItems` / `nextSortDescriptor`, selection helpers (`toggleKeySelection`, `rangeSelection`, `replaceSelection`, `selectAllState`, `selectionSize`, `isKeySelected`; `"all"` minus disabled), layout (`columnCssWidths` px / % / fr → calc, `tableWidthPx`, `pinnedOffsets` + edge, `clampColumnWidth` min 40), `virtualWindow` / `scrollTopFor`, `reorderItems`, `expandableKeys` / `toggleExpandedKey`.
- `behaviour.ts` — every handler delegated on the `<table>` over a plain `DataGridContext` (no per-row closures): `gridClick` (resizer guard, select-all, header sort, expand, checkbox, interactive content ignored, Shift range, row action vs toggle / replace, mod key), `gridDoubleClick`, `gridFocusIn` / `gridFocusOut` (one tab stop: the table is `tabIndex=0` until focus is inside), `gridKeyDown` (keyboard drag mode → resizer keys → drag handle → editable inputs (only Escape returns to the cell) → header keys → row / cell navigation, treegrid expand / collapse / parent, Home / End / Ctrl, PageUp / Down, Shift extend, replace-mode selection follows focus, Space, Enter, Ctrl+A, Escape, typeahead), `gridPointerDown` (column resize + pointer row drag with auto-scroll + indicator), `gridScroll` (virtual window + root `data-scrolled-start` / `-end`), keyboard drag (slots before each row + after the last, `../announcer/live-announcer.ts` messages).
- `index.tsx` — the component: props split into locals (`splitProps` live keys: data, columns, disabledKeys, pageSize, page, isLoadingMore, filter, treeColumn), `controllable` selection / sort / expanded, computeds (columns + utility columns, pipeline, window, spacers, pins, widths, table style), markup (root div `preload="visible"` → scroll div → table → colgroup / thead / tbody (spacers, keyed `For`, empty row, load-more sentinel via `../utils/load-more-sentinel.tsx`) → drop indicator; footer after the scroll div).

## Rules / invariants
- Rows: `For each={windowKeys} by={(k) => k}` (primitive keys) + per-row `row = computed(rowByKey().get(key) ?? goneRow(key), { equals: keepRow })` and `item = computed(row().item)`: a resumed page adopts every server row on the first change (item identity = the key; DataGridRow objects are new per pipeline run), sorting moves rows, cell content re-runs only when the row's item object changes. `goneRow` (index -1) covers a row whose key left the window before `For` disposed it (a resumed row computed may run without `keepRow`); custom `cell` content renders nothing for it.
- Per-column static cell data (`cellMeta` computed: id, pinned, edge, style, class, tree flag) are plain locals in `cellShell` (four literal `td` shapes: gridcell / rowheader × styled / unstyled; row headers are `<td role="rowheader">` as React Aria's Cell — a `th` brought UA centring / bold and missed the vendored `td:first-child` / `td:last-child` corner radii): one `setAttr` per attribute, no binding effect per cell. Pinned offsets are CSS variables `--rv-dg-pin-<i>` on the table (one binding); the pinned edge depends on column order only.
- Resumability: closures never capture `props` (it holds JSX `footer` / `loadMoreContent`: "rendered content is not serializable"); module-level functions are referenced inside arrows, never held in captured locals (`defaultRowId`, `defaultResizeLabel`, strings are plain); render-prop accessors (`renderSortIndicator(direction)`, `header(headerInfo)`, `renderCheckbox(rowCheckbox | selectAllCheckbox)`, `renderExpandIcon(rowExpanded)`) are local consts over plain locals — inline arrows as call arguments there are NOT registered ("capture #0 function is not serializable" when a caller's binding reads them; `tests/data-grid-ssr.test.ts` "render props" case).
- Behaviour-critical styles inline: `table-layout: fixed`, `border-collapse: separate` + `border-spacing: 0` (default spacing shifted virtual rows), sticky header / pinned cells, virtual row heights + spacer rows, resizer `touch-action: none`, scroll container overflow / height + `--rv-dg-header-height` (the `headingHeight` px: `@rivetjs/ui`'s frame mask rounds the body below the sticky header with it). Looks = `rv-DataGrid*` classes (every part has a `*Class` prop) + `data-*` state (`"true"` / absent).
- `id` / `aria-label*` land on the `<table>` (the grid element); other DOM props on the root.
- Controlled `sortDescriptor` ⇒ `sortMode="manual"` (data arrives sorted) unless `sortMode="client"`.
- Cells are `tabIndex=-1` (RA: a click focuses the cell); a focus applies via querySelector + microtask / rAF retry; virtual mode scrolls the row into view first (`scrollTopFor`).
- Perf (apps/dom-bench/data-grid, 2026-10-08, Chromium, cpu ×1, median of 3; baseline = RAC `@rivetjs/cdk/table`): 1k rows mount 57–64 ms vs 232–267, sort 25–27 vs 90–99, filter 7–8 vs 39–43, select-all 1.0–1.4 vs 31–36, heap 8–9 MB vs 54; 10k virtual mount 17–20 ms, sort 4.6–5.3, select-all 0.2, scroll step p50 0.8–0.9 ms / p95 1.3–1.6, 60 fps, 0 long frames, ~25 rows in the DOM; 10k plain 377–429 ms vs 2037–2257.

## Not supported (vs HeroUI Pro's public API)
- `dragAndDropHooks` (React Aria DnD between collections; cdk has no RA DnD port) — `onReorder` covers in-grid reordering.
- Function `header` gets `sortDirection` as an accessor, not a value.
