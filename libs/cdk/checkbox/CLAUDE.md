# @rivetjs/cdk/checkbox
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

RAC Checkbox family: `CheckboxGroup`, `CheckboxField` + `CheckboxButton`, `Checkbox` (deprecated in RAC, kept); visually hidden native `<input type=checkbox>` inside a `<label>`; RA form validation.

## Entry points
- `@rivetjs/cdk/checkbox` -> `index.tsx`: `CheckboxGroup`, `CheckboxField`, `CheckboxButton`, `Checkbox`; contexts `CheckboxContext` (rv-checkbox), `CheckboxFieldContext` (rv-checkbox-field), `CheckboxGroupContext` (rv-checkbox-group), `CheckboxGroupStateContext` (rv-checkbox-group-state); `*Props`, `*RenderProps`, type `CheckboxGroupState`
- `@rivetjs/cdk/checkbox/behaviour` -> `behaviour.tsx` (explicit package.json entry; closures → .tsx): `toggleProps`, `checkboxProps`, `checkboxGroupProps`, `checkboxGroupItemProps`, handlers `toggleLabelPress` / `toggleChange` / `toggleFocus` / `toggleInvalid`, `syncGroupValidity`, `mergeInputRefs`, types `AriaToggleProps`, `AriaCheckboxProps`, `AriaCheckboxGroupProps`, `AriaCheckboxGroupItemProps`, `ToggleAria`, `CheckboxGroupAria`, `ToggleContext`, `ItemValidation`
- `@rivetjs/cdk/state/checkbox-group` -> `state/checkbox-group.ts` (RS useCheckboxGroupState: `createCheckboxGroupState`, `isRequiredNow`, `isSelected`, `isGroupInvalid`, `setValue`, `addValue`, `removeValue`, `toggleValue`, `setInvalid`; optional mutable `data` = RA checkboxGroupData)
- toggle state: `@rivetjs/cdk/state/toggle` (`createToggleState`; `isSelected` plain / Signal / accessor; `selected()`, `isDisabled?` accessor)

## Layout
- `index.tsx` components; group composes `<Label>` (span), `<Checkbox value>` children, `<Text slot="description">`, `<FieldError>` via contexts
- `behaviour.tsx` RA useToggle / useCheckbox / useCheckboxGroup / useCheckboxGroupItem; reused by `switch/`
- input focus: delegated `onFocusIn` (target === input → `toggleFocus`); press via `pressProps` (enter / leave / dragstart bound only during a press); input props merged in one `mergeProps` pass (RA nests `mergeProps(pressProps, focusableProps)`: same result). 2 native listeners per checkbox left (`change`, `invalid`)
- tests: `tests/checkbox.browser.test.tsx` (RAC Checkbox.test.js, 53), `tests/checkbox-group.browser.test.tsx` (RAC CheckboxGroup.test.js, 32), `tests/checkbox-group-behaviour.browser.test.tsx` (RA useCheckboxGroup.test.tsx, 12), `tests/checkbox-group-state.test.ts` (RS, 21); stories `tests-components/checkbox.test.ts` (route `checkbox.tsx`), `dom-events-forms`, `widgets` "form fields" + `axe` (route `forms.tsx`)
- docs examples: `apps/cdk-docs/examples/checkbox-*/`, `checkbox-group-*/` (RAC parts: `CheckboxField` + `CheckboxButton` with a drawn box, `Label` / `Text` / `FieldError`; tests click `label:has(#id)`)

## Rules / invariants
- input hidden by inline `visuallyHidden` span; style the `<label>` (`rv-Checkbox` / `rv-CheckboxButton`) via `data-selected`, `data-indeterminate`, `data-pressed`, `data-hovered`, `data-focused`, `data-focus-visible`, `data-disabled`, `data-readonly`, `data-invalid`, `data-required`; group root `rv-CheckboxGroup` `role=group`
- render props are accessors; `isSelected` / `isIndeterminate` / `isDisabled` accept accessors; `indeterminate` bound with `prop:indeterminate` only when `isIndeterminate` is given and not `false` (`CheckboxButton`: a `prop:` binding compiles to a load-time client effect, which booted every page with a checkbox button)
- label `onClick` preventDefault + press toggles (RA); `toggleLabelPress` sets `input.checked` before commit (binding not flushed yet)
- validation: own `validationBehavior` else Form's else native; group item validity per item behaviour (`syncGroupValidity(group, input, item.behavior)`); description / error slot ids per RA useSlotId (`slotIdRef(id, false)`; CheckboxGroup + CheckboxField (server: a slot probe, `probeSlots(values, children)`, runs first, so the attribute names only the parts that render — UIID 2026-10-12; the FieldError id is kept while invalid, `slotIdRef(errorId, isInvalid())`: RAC FieldError renders only then; inside another field's probe the owner returns `null`; before, the description id was kept by expectation and stayed a dangling IDREF on resumed pages: dev `aria-idref`); a lone Checkbox names none); `data-rv-error` for cold submit
- closures: inline arrows in object literals only (no method shorthand, no post-hoc assignment, no conditional closures); destructure props first
- input refs: `mergeInputRefs` = synchronous callback ref (mergeRefValues is async)
- `toggleProps` input bag = `mergeDefined(literal, pressProps, focusableProps)` (LIVE-FAST 2026-10-09: literal merged into in place, unset keys dropped on the static path; same attributes and order); Checkbox / Switch roots merge into their fresh `globalDOMProps` bag (`mergeInto`)
- live props (P5): `CheckboxField` / `Checkbox` run `liveOptions(merged, LIVE_KEYS, ["isSelected"])` at the boundary (isDisabled / isReadOnly / isInvalid / isIndeterminate / aria keys → accessors; `toggleProps` reads `isReadOnly` / `aria-describedby` with `read`, toggle state keeps a live `isReadOnly` accessor: `isToggleReadOnly`); rest destructures → `liveOmit`, `removeDataAttributes` → `liveWithoutData`, option spreads → runtime `mergeProps`; render props from a live view. Read once (JSDoc "Read once at mount"): `name`, `value` (a group's item key), `form`, `id`, labeling combos (`isRequired` is live: LIVE-REST). Test `tests/live-props.browser.test.tsx`. `CheckboxGroup` controlled `value={v()}` stays live (`liveOptions(merged, [], ["value"])` → `controllable` accessor; options copied untracked so a resumed group is not re-created on a value change; its `isDisabled` / `isReadOnly` still re-create — gap)
- live props (P5), resume: `Checkbox` renders its button by a direct call (`untrack(() => CheckboxButton(button))`), not `<CheckboxButton {...button} />`: on a resumed page a component spread of a live (forwarding) props object re-created the region when the button read a forwarded key (`class`) in a binding (runtime gap, story `tests-components/live-props.test.ts`)
- Live props (P5): CheckboxGroup body untracked (`checkboxGroup`); `liveOptions(merged, [isDisabled, isReadOnly, isRequired, isInvalid], [value])` → state keeps accessors (`disabled` / `readOnly` / `requiredNow`, read `isCheckboxGroupDisabled` / `ReadOnly` / `Required`; writes blocked at event time); root `data-disabled` / `data-readonly` / `data-required` only in the spread bag (`flagAttr`: returned-arrow accessor when live; a plain JSX attribute after a spread takes the key from the spread); items: `checkboxGroupItemProps` `itemFlag` / `groupRequired` (static path = the creation values), group `aria-disabled` live. CheckboxField / Checkbox / CheckboxButton: `isRequired` live too (`LIVE_KEYS`; `data-required` + input `required` / `aria-required` via `toggleProps` `requiredAttr`). Tests `tests/live-controlled.browser.test.tsx` ("live flags"), `tests/live-flags-ssr.test.ts`, story `/live-props` `#lf-checks*`

## Gotchas
- story tests must click the `<label>` (`label:has(#id)`): the input is visually hidden (Playwright refuses it)
- resumed `/forms` page: a truly cold Space on `#terms` toggles (widgets "form fields" passes); a Space pressed right while the runtime boots / chunks load (after the idle slot effect) is flaky: the input's `click` arrives `defaultPrevented` (label `onClick` preventDefault without the input's stopPropagation?) and the box reverts (K1 probe 2/3 runs); open
- resumed page, label click: after a first label click (input spread activated) a Space on the input was swallowed — runtime takeover order (the label's delegated onClick preventDefault ran before the input's own stopPropagation), fixed in `libs/runtime/dom-resume.ts` `dispatch` (runtime-bugs K3-rt-1; example switch-events). Still open: the very first label click while the runtime / chunks load double-toggles (loader C8 replays the label-activated input click; proposal in scratchpad runtime-bugs.md [G-PAR/K-rt-1])
- `render` (RAC DOMRenderProps): `if (render) return render(attrs, renderProps)` before the compiled element; reactive attrs are accessors, handlers inline arrows; tests `tests/render-forms.browser.test.tsx`; CheckboxGroup / CheckboxField `<div>`, CheckboxButton / Checkbox `<label>` (hidden input inside `children`)
- in a group, native `required` = the item's own `isRequired` ?? the group's `isRequiredNow` (RA `props.isRequired ?? state.isRequired`; `checkboxGroupItemProps`); test `tests/fields-ssr.test.ts`, docs `checkbox-group-validation`
