# @rivetjs/cdk/sidebar
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Headless port of the shadcn/ui Sidebar (release `shadcn@4.21.4`, MIT): behaviour + API of `apps/v4/registry/new-york-v4/ui/sidebar.tsx` (React Aria base `bases/aria/ui/sidebar.tsx` for the parts: Button / Link / Tooltip / Sheet), `hooks/use-mobile.ts`. Styled HeroUI version: `@rivetjs/ui/sidebar`.

## Extensions (feature set inspired by HeroUI Pro's public docs; independent implementation)
User decision 2026-10-08: keep the shadcn API + names, add features. Defaults of the shadcn parts unchanged (`collapsible` offcanvas, markup identical when the new props are unset — no extra attributes / providers).
- Provider: `toggleShortcut` (string `mod+b` default; modifiers `mod` (Cmd or Ctrl) / `cmd` `meta` / `ctrl` / `shift` / `alt`, `+` joined, `mod++` = plus key; `false` / `null` off; parsed at event time from `state.shortcut`; Shift / Alt exact, key vs `event.key` lower-case or `event.code` `Key*` / `Digit*`), `reduceMotion` (wrapper + sheet + overlay `data-reduce-motion="true"`; theme CSS drops transitions; sheet swipe / pages jump), `closeMobileOnAction` (default false = shadcn: a link press keeps the sheet open; `@rivetjs/ui` provider defaults it to true), `side` / `variant` / `collapsible` defaults for the `Sidebar`s inside (own props win; AppLayout lane request), `navigate` + `useHref` (cdk `RouterProvider` value for the subtree; default native links = `@rivetjs/router` document-level interception, document load when no route matches). All plain data.
- Options context `SidebarMenuOptionsContext` (`{ closeMobileOnAction?, reduceMotion? }`): provided by `SidebarGroup closeMobileOnAction` / `SidebarMenu closeMobileOnAction | reduceMotion` only when set; resolution item → menu → group → provider. `SidebarMenu reduceMotion` writes `data-reduce-motion` "true"/"false" (CSS honours only "true"; `SidebarPages` honours both).
- Tree menu (APG disclosure navigation, not `role=tree`: links + buttons in lists, Tab moves, Enter / Space toggles): `SidebarMenuItem` / `SidebarMenuSubItem` with `expandable` or `defaultExpanded` / `isExpanded` / `onExpandedChange` (+ `isDisabled`) = cdk `Disclosure` rendered as the `li` (`data-expanded`, `data-expandable="true"`; its `render` prop is ignored). `SidebarMenuTrigger` = SidebarMenuButton `slot="trigger"` (Disclosure ButtonContext → `aria-expanded` / `aria-controls`; never closes the sheet). `SidebarMenuIndicator` = `span[aria-hidden]` (children = icon; CSS rotates 90° under `[aria-expanded=true]`). The item's `SidebarMenuSub` renders inside `DisclosurePanel` (`div.rv-SidebarMenuSub-panel[data-slot=sidebar-menu-sub-panel]`, animated `--disclosure-panel-height`, `hidden="until-found"` collapsed) and resets the item context so plain nested subs stay plain. Shadcn's manual `<Disclosure render=li>` pattern keeps working (context false).
- Guide lines: `SidebarMenu showGuideLines` (true default → no attribute; `"hover"` / `false` → `data-guide-lines="hover" | "none"`) = the sub menu's start border (theme CSS).
- Menu buttons: `isCurrent` (value / accessor → `aria-current="page"`, `data-active` unless `isActive` given), `forceReload` (`data-rivet-reload` + native `RouterContext` around the Link), external `http(s)://` hrefs → `target="_blank" rel="noopener noreferrer"` unless `target` given, `closeMobileOnAction` (onPress chained after the user's; closes only when the sheet is open). Same on `SidebarMenuSubButton`. The `data-active` / `aria-current` accessors are built in the component body, not in a helper: a closure returned by a module helper is not a registered symbol ("Cannot resume … renderLink: capture #0 function is not serializable" on resumed pages).
- `SidebarMenuActions` (`div[role=group]`, `data-show-on-hover`): several `SidebarMenuAction`s at the item end (theme: absolute group, actions static).
- `Sidebar backdrop` "blur" (default) | "opaque" | "transparent" → overlay `data-backdrop` (theme / ui CSS).
- `SidebarPages` (`value` / `defaultValue` / `onValueChange` / `reduceMotion`; default = first `SidebarPage` rendered, `first` region signal) > `SidebarPage value` (`role=group`, `data-value`, `data-active`; inactive: `hidden` + `inert` + `aria-hidden`). Inline `display:grid; overflow:hidden` on the container, `grid-area:1/1` on pages (behaviour-critical). No load work: the page `hidden` binding schedules one microtask transition per container: DOM order gives the direction (RTL flips), one `Motion1D` slides enter + leave (`translateX`), done within 0.5 px of the target (embla's settle tail is invisible), leaving page hidden at the end; reduced motion / zero width → instant. Focus inside the leaving page → first focusable of the entering page. `theme.css` / ui `sidebar.css` set the page `display` only on `:not([hidden])` (a class `display` would override the UA `[hidden]` and show the inactive page). `useSidebarPages()` → `activeValue()`, `setActiveValue(v)`, `activeIndex()`, `order()` (DOM order; empty on the server).

## Rules / invariants
- State = `controllable(open, defaultOpen ?? true, onOpenChange)` (`open`: value / two-way Signal / accessor); `openMobile`, `isMobile` signals.
- Cold at load (2026-10-08, nothing boots the runtime on a resumed page): no load effect. `isMobile` false on server; re-read by `toggleSidebar` (first) and by `clientEvent("media:(max-width: 767px)", …, { preload: "interaction", standalone: false })` (literal required: RV1103; attached when the runtime starts; `standalone: false` and the window `keydown` shortcut likewise — TOAST-ACTIVE 2026-10-26: the derived server keeps a standalone `clientEvent`'s idle trigger, which would boot every sidebar page). Tooltip `isDisabled` and `useSidebar().isMobile()` read the viewport at call time (`sidebarViewportIsMobile()`). Before the first toggle the mobile / desktop split is CSS: desktop root (`[data-state]`) `display: none` below 768 px (`theme.css`, ui `sidebar.css`; upstream `hidden md:block`). Shortcut Cmd/Ctrl+B: delegated `onKeyDown` on the wrapper (works cold while focus is inside the wrapper; user `onKeyDown` runs first) + window `keydown` clientEvent `preload: "interaction"` (body focus, once the runtime runs); `sidebarShortcutKeyDown` handles an event once (WeakSet). Measured (story apps, before → after): `data-boot` true → false; scripts before interaction cdk 91 → 69 (desktop) / 85 → 45 (500 px), ui 91 → 86 / 88 → 81 (rest = visible-preload of handler chunks, not a boot).
- First-click latency (2026-10-08, cold lane): the wrapper div carries `preload="visible"` (resume directive, literal; not on the `render` path — add it to your element there). It plans the wrapper keydown handler's chunks AND its dependency chunks (every binding reading the sidebar state: Sidebar, provider, the app's `onOpenChange` / `onPress` chunk) as visible: fetched + evaluated when visible, nothing runs (no `data-boot`). Without it a menu-button click (its TooltipTrigger `isDisabled` captures the sidebar state) waited for ~25 intent-only chunks (the whole `sidebar.js` graph: modal / dialog / sheet-motion …). `libs/cdk/tests-components/cold-latency.ts`, slow (150 ms RTT, 1.6 Mbps, 4x CPU) p50 before → after: click 1091 → 59 ms, hover+click 423 → 36 (pre-c0c6cf9b: 59 / 25); scripts before input 69 → 93 (pre-c0c6cf9b 91, booted).
- Attributes as upstream: wrapper `data-slot="sidebar-wrapper"` + `--sidebar-width` / `--sidebar-width-icon` vars; root `data-state` expanded|collapsed, `data-collapsible` (`""` when expanded, else the mode), `data-variant`, `data-side`, `data-slot="sidebar"`; parts `data-slot` + `data-sidebar`; MenuButton `data-size`, `data-variant` (default / outline), `data-active`; mobile sheet `data-mobile="true"`.
- Desktop markup: root > gap (`rv-Sidebar-gap`) + container (`{...rest}`, `class`, `rv-Sidebar-container`) > inner. `collapsible="none"` = one div. Mobile: `Show` swaps the gap/container for `ModalOverlay` > `Modal` (`rv-Sidebar-sheet`, `--sidebar-width: var(--sidebar-width-mobile, 18rem)`) > `Dialog` with visually hidden title "Sidebar" + description (upstream SheetHeader).
- `asChild` → `render` prop (RAC DOMRenderProps) on every part; MenuButton / MenuSubButton = cdk `Link` when `href`, else `Button` (aria base). MenuButton `tooltip` (string | TooltipProps) → `TooltipTrigger delay={0} isDisabled={() => open || isMobile}` (tooltip `isDisabled` accepts an accessor since this port).
- Collapsible groups / menus: cdk Disclosure (`<SidebarGroupLabel render={(p) => <Button slot="trigger" {...(p as {})} />}>`); see docs.
- Looks: `theme.css` `rv-Sidebar*` rules (collapse widths, offcanvas slide, variants, rail, sheet slide; every `rv-Sidebar*` element `box-sizing: border-box` = Tailwind preflight, upstream sizes assume it; collapsed icon-mode buttons carry `[data-sidebar]` to beat the `[data-size]` heights = upstream `size-8!`). Without a stylesheet the state flips but nothing moves (upstream is all Tailwind classes too).

## Deviations
- `data-active` / `data-show-on-hover`: `"true"` or absent (cdk `dataBool`), upstream writes `"false"`.
- MenuAction `data-show-on-hover`, MenuButton `data-variant`: attributes instead of upstream Tailwind classes (headless).
- On mobile the desktop root (`data-slot="sidebar"` with data-state) stays in the DOM (empty); the sheet is portaled to the overlay layer, so `--sidebar-width-mobile` must be set on `Sidebar`'s `style` (or `:root`), not only on the provider.
- `SidebarTrigger` children: rendered (headless: the icon), then the visually hidden "Toggle Sidebar" label always (shadcn ignores children, renders icon + `sr-only`); an icon child never leaves the trigger unnamed.
- Mobile sheet focus: the dialog itself on open (React Aria `Dialog`; Radix focuses the first tabbable), back to the trigger on close (Radix: body when the trigger is gone).
- `SidebarMenuSkeleton` width: `signal(random 50–90%)` (upstream `useState`; M2-R5 2026-10-20, was a plain `Math.random()` per render = RV2103 under the derived model and a new width on client re-creation): the server's pick ships (keyed state under derived, the style binding's captured signal under serialized).

## Gotchas
- Cold-page gap: Cmd/Ctrl+B with focus on `<body>` before any interaction does nothing (no element on the event path carries a handler; the window listener attaches when the runtime starts). Upstream's window listener always catches it.
- On a cold mobile page the desktop gap / container stay in the DOM (CSS-hidden) until the first toggle swaps them for the sheet.
- Provider: a closure referencing `rp` must be declared after `rp` (the compiler captures eagerly: TDZ "Cannot access 'rp' before initialization" at SSR).
- vitest browser iframe < 768px → tests stub `innerWidth` (`setWidth(1024)`).

- ID-RESUME (2026-10-27): Generated mobile-dialog title and description ids use the shared `resumedId()` keyed-signal helper. The resume record retains the server id when parts adopt independently. Existing explicit-id fallback and ARIA behaviour are unchanged.

- COLD-CAPTURE (2026-10-29): `SidebarResizeHandle` carries internal `data-rv-capture=""`, so the inline resume loader captures a held primary pointerdown before handler code arrives. The complete cold gesture stays on the handle through physical release; adopted handlers replay the moves and clear drag state. Production UI regressions hold every script request through a full mouse / touch drag and require the rendered width and both callbacks to agree.
