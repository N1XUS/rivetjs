# @rivetjs/mcp
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Rivet MCP server (Model Context Protocol, stdio) for AI assistants: offline docs search, docs pages, component reference, compiler + language-service checks of a snippet, diagnostic explanations. Dev tooling: no runtime package imports it (not in `scripts/zero-cost`). Official SDK `@modelcontextprotocol/sdk` 1.32.1 + `zod` 3.25.76 (exact pins).

## Entry points
- `.` → `index.ts`: `createRivetServer`, `findDoc`, `findComponents`, `componentMarkdown`, data (`buildData`, `loadData`, `writeData`, `dataFile`, `dataProblems`, `SITES`), search (`createSearchIndex`, `tokens`), checks (`checkCode`, `formatCheck`, `rivetCompiler`).
- bin `rivet-mcp` → `cli.ts` (`npx @rivetjs/mcp`; `--help`, `--version`): `createRivetServer({ cwd })` on `StdioServerTransport`; stdout = protocol, logs on stderr. Run from the app dir: `check_code` uses the app's compiler wasm (`workspaceCompilerWasm(cwd)`, else this package's) and resolves `@rivetjs/*` types from there.

## Tools (`server.ts`)
- `search_docs(query, site?: docs|cdk|ui, kind?: page|api|example, limit?)` → ranked doc ids + description + best line. `search.ts`: BM25 (title ×4, description + headings ×2, body), identifiers split (`createAsyncList` → async, list), all-terms bonus, title = query ×3, pages ×1.15.
- `get_doc(path)`: doc id `<site>:<href>` (`ui:/components/select/`), a path (several sites → list of ids), a docs URL (origin → site via `data.origins`) or its `.md` form.
- `list_components(package?: ui|cdk|kit)`; `get_component(name, package?, examples? = 3)`: import line, summary, docs + API doc ids, every API symbol of the entry (signatures, members table), example sources from the entry's docs page. Name match: entry, `ui/select`, component name, kebab of it, else a symbol name; order ui → kit → cdk.
- `check_code(code, filename? = src/routes/index.tsx, resume? = true for .tsx/.jsx)` (`check.ts`): compiler `check` (both targets, resume module = filename) → language-core `analyzeFile` over a one-file TS program (in-memory source, real `node_modules` from `cwd`: RV3101 / RV1017 type-aware checks + `TSnnnn` errors); `@rivetjs/*` unresolvable (TS2307 / TS2875) → TS errors dropped + note. Each RV diagnostic: line / column, excerpt, `fix` (language-core `explainCode`), quick fixes (`codeFixes` + `applyEdits` → whole fixed source).
- `explain_diagnostic(code | "all")` → language-core `explanationMarkdown` (registry title / severity / docs + messages, fix, quick fix, Avoid / Prefer).
- Server `instructions`: the core Rivet rules + "check_code every file".

## Data (`data.ts`)
- `McpData { digest, origins, docs: McpDoc[] (id, site, kind page|api|example, href, title, description, section, tags, markdown), components: McpComponent[] (name, package, entry, summary, doc?, api, symbols, examples) }`.
- `buildData(repo)`: `@rivetjs/docs-kit/tools/llms` `loadLlmsSource` + `llmsFrom` per site (`SITES` = docs / cdk / ui → `apps/docs`, `apps/cdk-docs`, `apps/ui-docs`) with a `link` that writes doc ids (sibling-site URLs mapped back by origin), so the documents ARE the llms.txt documents (sync by construction). Components: every API entry of `@rivetjs/{ui,cdk,kit}/*` (first site wins); docs page = a page importing the entry (`components/<last>` of its own package first); examples = `::example` ids of that page. docs-kit is imported by path (devDependency; never loaded by the published server).
- `loadData()`: workspace (module under `<repo>/libs/mcp`) → `buildData` in memory once per process (≈ 4 s, never stale); published package → `data/rivet.json` written by `bundle.ts` (package hook `publishConfig.bundle`). `data/` is gitignored.
- Ruling 2026-10-08: data not checked in (≈ 27 MB, churns with every docs edit); `node libs/mcp/build-data.ts --check` (CI `gates`) = `dataProblems` (every llms doc of every site present, counts equal, component doc / api / example ids resolve) + two builds same digest + an existing `data/rivet.json` not stale. Measured: 2232 docs, 289 components, 27.4 MB, 6–7 s, 0.9 GB RSS.

## Layout
- `cli.ts`, `server.ts`, `data.ts`, `search.ts`, `check.ts`, `index.ts`, `build-data.ts` (`[--out file] [--check]`), `bundle.ts`.
- `ai/`: one source for the starters' AGENTS.md / CLAUDE.md / skills / Cursor / Copilot files, public installable `skills/` bundles and the Claude Code plugin — see [ai/CLAUDE.md](ai/CLAUDE.md). Includes `rivet-ui-design` with five references for visual foundations, structure/layouts, composition, interactions and Rivet implementation; MCP is optional for that skill. `plugin/` + `.claude-plugin/marketplace.json`: generated by `ai/sync.ts` (never edit).
- `tests/server.test.ts` (vitest project `mcp`): in-memory transport (`InMemoryTransport`) on real data: six tools listed, data ⇔ llms outputs, search, get_doc forms, components (ui / cdk / kit), check_code (RV1009 + fix + quick fix; clean counter), explain_diagnostic. `tests/ai.test.ts`: AI instruction files in sync.

## Commands
- Test: `NODE_OPTIONS=--max-old-space-size=2048 npx vitest run --project mcp --maxWorkers=1`. Typecheck: `node scripts/tsc.ts -p libs/mcp` (tsgo; nx `mcp:typecheck`).
- Data: `node libs/mcp/build-data.ts [--check]`. Run from source: `node libs/mcp/cli.ts`. Package: `NX_DAEMON=false npx nx run mcp:package` → `dist/libs/mcp` (incl. `data/rivet.json`).
- User docs: `apps/docs/content/guides/tooling/ai.md` (Claude Code / Cursor / VS Code config).

## Gotchas
- Doc links inside the data are doc ids; links in the web llms outputs are URLs on `site.origin` — same documents, different `link`.
- Explanations live in `libs/language-core/explain.json` (one per `libs/compiler/codes.json` code, tested); a new RV code needs an entry there. The same entries render the docs pages `/errors/RVxxxx` (committed `apps/docs/content/errors/`, docs-kit `tools/errors.ts`): docs search / `get_doc` serve them as ordinary pages of the llms outputs.
- In `scripts/package/smoke.ts` `PACKAGES` since 2026-10-09 (packed with ~31 MB `data/`, installed offline, `.` imported under Node + `tsc`; +6 s, peak RSS 1.2 GB vs 0.9 GB without). Not in `create-e2e.ts` (no starter depends on it). The stdio bin was smoke-tested by hand 2026-10-08 from a packed copy.
