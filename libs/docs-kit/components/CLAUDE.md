# @rivetjs/docs-kit/components
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Docs UI components (Rivet TSX), used by generated content routes and the shared routes. Read site data from `virtual:docs/*`.

## Layout
- `SiteFrame.tsx`: `SiteFrame({ path, links?, children })` = the app layout's frame (on `site.leanPages` paths: search bar without the `/` hint and `aria-keyshortcuts`; page-owned visible effects still run; no client triggers of its own: highlighting / shortcuts are `page-script.ts`'s): skip link (`#content`), sticky `header.top-bar` (`MobileMenu` button < 900px, logo (`span.top-brand-mark`, CSS background: no image request) + name, version pill, `nav.top-sections` = `TopLinks` (areas + API / Examples, active `aria-current="true"` + soft gradient underline), search field (`bar`) / icon (`icon`, < 900px), `ThemeMenu`, GitHub text link), `div.frame-body` = `SideNav` of the current area (none for `/api/`, `/examples/`, home) + `<main id="content">` + footer (Docs = areas / Reference / `links` columns / Project). Exports `TopLinks`, `FooterColumn`, `FooterLink`. Frame URLs (`frameIdOf`) render children only (no chrome). Imports `../fonts.ts` (docs `@font-face` + fallback faces as a SiteFrame CSS chunk).
- `SideNav.tsx`: `SideNav({ sections, area, path, label? })`: one nav per area, no drill-down: each section a `div.side-part` (uppercase `p.side-title` when the area has several sections or the section is named unlike the area), each group a native `details.side-group > summary.side-summary` (ChevronRight rotates; collapsible without JS) over `ul.side-list`. Open when it holds the current page (`data-current`) or the area has ≤ 4 groups. Items: `aria-current="page"`, or `"true"` on a child page of the item (`NavItem.children`; same style: CSS keys on `[aria-current]`) (accent text, soft tint + gradient bar), New/Updated tag, "Planned" badge only. Static markup, no JS.
- `nav.ts`: pure nav helpers (server + browser): `ROUTE_ITEMS`, `topItems(areas)`, `holds(item, href)` (the item's page or one of its `children`; every lookup below uses it), `sectionOf`, `areaOf(sections, path)`, `sideModel(sections, areas, area, path)` → `SidePart[]` (`OPEN_ALL` = 4), `breadcrumbOf(sections, areas, path)` (area → section → group).
- `browser.ts`: browser-only helpers (a `.ts` module: not server-rewritten, may touch `document` / `localStorage`; RV2001 forbids that in `.tsx` outside handlers): TOC scroll-spy `spy()` + `spyState`, theme `currentPref` / `applyPref`, `currentPath`.
- `ThemeMenu.tsx` (RT-DIET2 DOCS-CHROME 2026-10-26): static `button.theme-button[data-chrome]` only (cdk trigger markup, `aria-haspopup`, `data-menu-placement`; exports `themeIcons`) — no boundary. `theme-menu-open.tsx`: `ThemeMenuLive` = cdk `MenuTrigger` + `Popover` + single-select `Menu` (System / Light / Dark, lucide Monitor / Sun / Moon + Check; selection synced from `currentPref()` on open, `applyPref` writes `data-theme(-pref)` + `localStorage.theme`); `liveThemeMenu(button)` mounts it in the static button's place (page script: pointerover / focusin, not during a press; focus handed over); `openThemeMenu(button, event)` = an activation that came first, replayed on the live button (`chrome-press.ts` `replayPress`: pointer sequence when `detail` > 0, else virtual click; ArrowDown / ArrowUp keydown).
- Warm chrome press (ZERO ABI-SPLIT 2026-10-27): the `theme-menu-open` / `mobile-menu-open` chunks and their static imports carry the V8 eager-compile hint (`vite.ts` `docsChunks`), so the code the press runs compiles while the module loads on hover; they import only the derived component ABI (no adopt runtime). Glossary, 4× CPU, 600 ms hover then click: INP 56–64 → 32 ms, menu shown 48–58 → 25–28 ms, JS before the click 81.3 → 70.1 KB; cold click shown 85–94 → 64–73 ms (78.4 → 67.2 KB); drawer 71 → 59.7 KB.
- `MobileMenu.tsx`: static `button.menu-button[data-chrome]` (RT-DIET2). `mobile-menu-open.tsx`: `MobileMenuLive` = cdk `DialogTrigger` + `ModalOverlay isDismissable` + `Modal` + `Dialog` (focus trap, Escape, outside press, scroll lock, focus restore); content = render function (created on open): close button + `ul.drawer-sections` (top-bar items) + `SideNav` of the current area; `liveMobileMenu` / `openMobileMenu` as the theme menu's.
- `DocPage.tsx`: content page body inside `SiteFrame`: `.docs-grid` = article (header panel: breadcrumb, edit icon link, h1, lead, status; inline `<details>` TOC under 1280px; planned callout; prose; related; prev/next with `data-rivet-prefetch="prerender"`; edit / report links) + `Toc` column (sticky, scroll-spy = `page-script.ts` window scroll → `browser.ts` `spy` (was a `clientEvent` → IDLE trigger, booted the runtime), `aria-current="true"` on the active entry, back-to-top). Props: `PageInfo`.
- `Example.tsx`: `<Example id example={…}>` (generated pages pass `ExampleData` from their own `virtual:docs/examples?ids=…` module — ZERO Z9; hand-written routes from their loader; no browser lookup of the whole manifest): code tabs (plain `span.line` markup, coloured at build by `tools/highlight-pages.ts`; dev / client renders: by the shared lazy highlighter chunk), "Server HTML" tab (`<pre data-src>`: the frame page fetched same-origin and formatted client-side, `format-html.ts`), same-origin iframe `framePath(id)` (no sandbox; `height` = `ExampleData.height`, `data-auto-height` when `auto`: sized by `frame-theme.ts` `PARENT_FRAME_HEIGHT`), `<p class="what-loaded" data-measure>` (filled by the build's checks, hidden while empty), code-only note with the reason (`ExampleData.codeOnly`).
- `frame.tsx`: frame pages of examples: `frameEntries(sub)` (prerender entries), `loadFrame(event)` (frame route `load(…)`: loads the example's wrapper module + stylesheet URLs — once per example per production server, memoised promise (ZERO Z7: −4 KB heap / request on docs frames; dev reloads each request for hot updates; a rejected load is forgotten) — runs the page's own `load(…)`), `frameHead(input)` (example head + its stylesheet links), `FramePageView` (page in its layouts; browser fallback `lazyComponent`), `FrameRoot` (region root without the router), types `FrameProps` / `FrameComponent` / `FramePage` / `FrameModule`.
- `frame-page.tsx` (server): `framePageOf(input)`: the page factory of a frame URL (no router `<App>`, no router contexts); wired by `vite.ts` `docsFrames` into `.rivet/entry.server.tsx`.
- `frame-dev-mount.tsx` (dev server, browser): the client-render fallback of a frame page (the router's `.rivet/dev-mount.tsx` for docs pages): fetches the route data, loads the frame module, mounts `FrameRoot`. `vite.ts` `frameDevEntry` points `.rivet/entry.dev.tsx` here on frame URLs, so a frame's browser graph never reaches the docs layout / nav / `.rivet/app.tsx`.
- `page-script.ts` (ZERO Z13, 2026-10-25; STATIC-ZERO-3 2026-10-27: on a `.search-page-form` page with `?q=` it opens the search dialog with the query at once (was the search route's load-time client effect), and benchmark plots' keyboard — document keydown (arrows / Home / End / Escape) / focusin (`:focus-visible` plot) / focusout → `bench-keys.ts` (static import), also replayed from the stub queue; site chrome RT-DIET2 2026-10-26: theme menu / drawer warm + mount on pointerover / focusin, static-button activations, search button click, code copy — outside `data-lean` too; DOCS-ZERO 2026-10-27: imported on first intent by `document.ts` `PAGE_STUB`, named listeners + `replay(window.__rvDocs)` of the events the stub queued, then `__rvDocs = null`; test `apps/docs/tests/search.test.ts` "page script"; CSS-only scroll-spy rejected: `scroll-target-group` / `:target-current` is Chromium 140+ only, sets no `aria-current` and picks its own reading line (a second highlight beside the JS one), `:target` follows clicks not scrolling — the spy stays JS, loaded on the first scroll): docs page script — ONE plain module script on every docs page (not frames), no resume runtime / boundary: Toc scroll-spy (`spy`), and off `<html data-lean>` (`site.leanPages`): `/` + Ctrl/Cmd+K → search dialog (document keydown, capture), dialog warm-up (lone Ctrl / Meta, pointerover / focusin on `.search-button`), idle `watchCode()` + MutationObserver for added `CODE_SELECTOR` blocks (client navigations). ## Rules / invariants
- Resumability: content pages ship no JS; interactive bits load on use (`preload="intent"`, dynamic imports). No code strings in resume state (CopyButton reads the DOM).
- Resumed handlers are delegated from `document`: use `event.target`, not `currentTarget`.
- Inline arrows inside `x.find(fn) ?? fallback` in a component body become resumable closures and break render: hoist to module scope (`StarterButton.tsx`).
- Links use `data-rivet-reload` (full page loads between docs pages); keep `data-rivet-prefetch` attributes when restyling.
- Browser globals (`document`, `localStorage`, `location`) only inside handlers or in `browser.ts`; mutable module state in objects (`spyState`): resumed handler chunks import bindings read-only.
- Overlays: cdk div overlay layer only (never native `<dialog>` / popover); frame z-indexes stay below it (`--z-nav` / `--z-bar`).
- Icons: lucide only, through `@rivetjs/kit/icon` (`<Icon icon={Sun} size={20} class? />`, server + client); no invented SVG paths, no UTF symbols as icons.

## Gotchas
- `BenchChart` data: marks are placed by the server (CSS vars of their axis share); the table + `data-say` are the client contract of `bench-keys.ts`. Never put chart specs in captured closures (resume state).
- Generated routes import these by path (`@rivetjs/docs-kit/components/<Name>.tsx`, see `../tools/content/generate.ts`): keep file names.
- cdk `Button` (ThemeMenu / MobileMenu triggers) carries hover (`pointerenter`) handlers → the preload planner would schedule its chunks as `visible` (~39 modules prefetched after load). Both docs apps set the preload rule `{ match: "@rivetjs/cdk/", strategy: "intent" }` in `vite.config.ts` (JS on idle 70 → 42 KB br); keep it in any new site.
- Site chrome without boundaries (RT-DIET2 DOCS-CHROME 2026-10-26): ThemeMenu / MobileMenu / SearchButton / CopyButton are plain markup; with the router's client router off and nothing else live, the server ships no tail / loader / runtime (`server-derived.ts` `inertOnly`). Docs glossary JS before input 126.7 KB br / 61 files → 1.8 KB br / 1 file (page script); HTML 16.2 → 13.3 KB br. First theme / drawer press: the live cdk trigger (≈ 75–80 KB br: DOM runtime + cdk menu / dialog) loads on pointer / focus intent; 4× CPU INP warm 72 ms (main 56–64), cold 24 ms (main 128). Keep new chrome off boundaries: one boundary that listens brings the tail + runtime back to every page.
