# @rivetjs/docs-kit/components
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Docs UI components (Rivet TSX), used by generated content routes and the shared routes. Read site data from `virtual:docs/*`.

## Layout
- `SiteFrame.tsx`: `SiteFrame({ path, links?, children })` = the app layout's frame (on `site.leanPages` paths: search bar without the `/` hint and `aria-keyshortcuts`; page-owned visible effects still run; no client triggers of its own: highlighting / shortcuts are `page-script.ts`'s): skip link (`#content`), sticky `header.top-bar` (`MobileMenu` button < 900px, logo (`span.top-brand-mark`, CSS background: no image request) + name, version pill, `nav.top-sections` = `TopLinks` (areas + API / Examples, active `aria-current="true"` + soft gradient underline), search field (`bar`) / icon (`icon`, < 900px), `ThemeMenu`, GitHub text link), `div.frame-body` = `SideNav` of the current area (none for `/api/`, `/examples/`, home) + `<main id="content">` + footer (Docs = areas / Reference / `links` columns / Project). Exports `TopLinks`, `FooterColumn`, `FooterLink`. Frame URLs (`frameIdOf`) render children only (no chrome).
- `SideNav.tsx`: `SideNav({ sections, area, path, label? })`: one nav per area, no drill-down: each section a `div.side-part` (uppercase `p.side-title` when the area has several sections or the section is named unlike the area), each group a native `details.side-group > summary.side-summary` (ChevronRight rotates; collapsible without JS) over `ul.side-list`. Open when it holds the current page (`data-current`) or the area has ≤ 4 groups. Items: `aria-current="page"`, or `"true"` on a child page of the item (`NavItem.children`; same style: CSS keys on `[aria-current]`) (accent text, soft tint + gradient bar), New/Updated tag, "Planned" badge only. Static markup, no JS.
- `nav.ts`: pure nav helpers (server + browser): `ROUTE_ITEMS`, `topItems(areas)`, `holds(item, href)` (the item's page or one of its `children`; every lookup below uses it), `sectionOf`, `areaOf(sections, path)`, `sideModel(sections, areas, area, path)` → `SidePart[]` (`OPEN_ALL` = 4), `breadcrumbOf(sections, areas, path)` (area → section → group).
- `browser.ts`: browser-only helpers (a `.ts` module: not server-rewritten, may touch `document` / `localStorage`; RV2001 forbids that in `.tsx` outside handlers): TOC scroll-spy `spy()` + `spyState`, theme `currentPref` / `applyPref`, `currentPath`.
- `ThemeMenu.tsx`: cdk `MenuTrigger` + `Popover` + single-select `Menu` (System / Light / Dark, lucide Monitor / Sun / Moon + Check); selection synced from `currentPref()` on open, `applyPref` writes `data-theme(-pref)` + `localStorage.theme`.
- `MobileMenu.tsx`: bar button → cdk `DialogTrigger` + `ModalOverlay isDismissable` + `Modal` + `Dialog` (focus trap, Escape, outside press, scroll lock, focus restore); content = render function (created on open): close button + `ul.drawer-sections` (top-bar items) + `SideNav` of the current area.
- `DocPage.tsx`: content page body inside `SiteFrame`: `.docs-grid` = article (header panel: breadcrumb, edit icon link, h1, lead, status; inline `<details>` TOC under 1280px; planned callout; prose; related; prev/next with `data-rivet-prefetch="prerender"`; edit / report links) + `Toc` column (sticky, scroll-spy = `page-script.ts` window scroll → `browser.ts` `spy` (was a `clientEvent` → IDLE trigger, booted the runtime), `aria-current="true"` on the active entry, back-to-top). Props: `PageInfo`.
- `Example.tsx`: `<Example id example={…}>` (generated pages pass `ExampleData` from their own `virtual:docs/examples?ids=…` module — ZERO Z9; hand-written routes from their loader; no browser lookup of the whole manifest): code tabs (plain text, coloured in the browser by the shared lazy highlighter chunk), "Server HTML" tab (`<pre data-src>`: the frame page fetched same-origin and formatted client-side, `format-html.ts`), same-origin iframe `framePath(id)` (no sandbox; `height` = `ExampleData.height`, `data-auto-height` when `auto`: sized by `frame-theme.ts` `PARENT_FRAME_HEIGHT`), `<p class="what-loaded" data-measure>` (filled by the build's checks, hidden while empty), code-only note with the reason (`ExampleData.codeOnly`).
- `frame.tsx`: frame pages of examples: `frameEntries(sub)` (prerender entries), `loadFrame(event)` (frame route `load(…)`: loads the example's wrapper module + stylesheet URLs — once per example per production server, memoised promise (ZERO Z7: −4 KB heap / request on docs frames; dev reloads each request for hot updates; a rejected load is forgotten) — runs the page's own `load(…)`), `frameHead(input)` (example head + its stylesheet links), `FramePageView` (page in its layouts; browser fallback `lazyComponent`), `FrameRoot` (region root without the router), types `FrameProps` / `FrameComponent` / `FramePage` / `FrameModule`.
- `frame-page.tsx` (server): `framePageOf(input)`: the page factory of a frame URL (no router `<App>`, no router contexts); wired by `vite.ts` `docsFrames` into `.rivet/entry.server.tsx`.
- `frame-dev-mount.tsx` (dev server, browser): the client-render fallback of a frame page (the router's `.rivet/dev-mount.tsx` for docs pages): fetches the route data, loads the frame module, mounts `FrameRoot`. `vite.ts` `frameDevEntry` points `.rivet/entry.dev.tsx` here on frame URLs, so a frame's browser graph never reaches the docs layout / nav / `.rivet/app.tsx`.
- `page-script.ts` (ZERO Z13, 2026-10-25): docs page script — ONE plain module script `document.ts` links on every docs page (not frames), no resume runtime / boundary: Toc scroll-spy (`spy`), and off `<html data-lean>` (`site.leanPages`): `/` + Ctrl/Cmd+K → search dialog (document keydown, capture), dialog warm-up (lone Ctrl / Meta, pointerover / focusin on `.search-button`), idle `watchCode()` + MutationObserver for added `CODE_SELECTOR` blocks (client navigations). Replaced three client triggers that booted the resume runtime at idle on every page (SiteFrame `watchCodeAtIdle` clientEffect in `code-watch.tsx` (deleted), SearchButton document `clientEvent`s, Toc scroll `clientEvent`): docs pages with `data-boot` 998 → 3; `/learn/resuming/` idle 5.7 → 2.4 MB heap, script 6.6 → 3.5 ms. `highlight-browser.ts` (`watchCode(root | blocks)`, `CODE_SELECTOR`; started by `page-script.ts`), `highlighter.ts` (one shared lazy chunk: Shiki core + JS regex engine + github-light/dark; grammar chunks on demand; colours plain `<pre data-lang>` blocks in place, fills `data-src` blocks first), `highlight-classes.ts` (themes, `LANGS`, token classes shared with the build's `highlight.css`): pages ship plain code (markdown fences and example code), coloured in the browser; fragments are coloured at build (`loadTokenizer(langs)` → sync tokenizer, same `Token` classes as `highlightPre`; `data-hl` blocks are skipped).
- `format-html.ts`: `formatHTML(html)`: "Server HTML" tab text (frame theme script stripped).
- `ApiCard.tsx`: `::api` card; takes `card: ApiCardData` (name, kind, entry, href, summary, first signature, resolved `runs` label) inlined by content generation — never looks symbols up, because `virtual:docs/api` is empty in the browser and the page renders there on client navigation (2026-10-20: `ApiCard: unknown symbol` threw after a search-result click, URL changed but the page did not). `Inline.tsx`: doc-comment text with `code` spans.
- `CodeBlock.tsx`: `CopyButton` = icon button (lucide Copy / Check, `data-copied` 1.5 s, aria-label "Copied") in the code header (`.code-panel` example panes float it top-right); copies the first visible `<pre>` of its `.code-block` / `.code-panel` (open tab, source of a compiled block); `preload="intent"`, reads code from DOM.
- `SearchButton.tsx`: `SearchButton({ variant: "bar" | "icon", shortcuts? = true })`: link to `/search/`; with JS opens `../search/dialog.tsx` (cdk modal overlay primitives); `bar` = field look with `kbd` "/"; `icon` = narrow top bar. Only the click handler is the component's; shortcuts `/` + Ctrl/Cmd+K and the dialog warm-up are `page-script.ts` document listeners (ZERO Z13: client triggers booted the runtime at idle). `shortcuts={false}` (SiteFrame on `site.leanPages`): no `kbd` / `aria-keyshortcuts` (the page script skips lean pages).
- `StarterButton.tsx`: plain form POST of a starter to StackBlitz (no JS).
- `BenchChart.tsx`: `BenchChart({ chart, compact? })` = benchmark figure (`::chart{id}` / `::chart{id compact}` in content; the apps/docs home uses source-derived HTML proof summaries with links to these full charts): plain title + small "Lower / Higher is better" note, legend, `.bench-plot` canvas (height from `rowLayout` at 720 / 519 px as `--bench-h` / `--bench-h-narrow`: no layout shift), visually hidden `<table>` (screen readers, no-JS fallback, and the canvas's data source: `tr[data-group|data-label|data-value|data-min|data-max|data-rivet|data-note]`), caption (machine, date, method, report link; `compact` drops method). `stat` kind: HTML big-number card (accent ratio + `lead`, `claim`, the two values), no canvas. Client: `clientEffect(() => mountChart(root()!), { when: "visible" })` (captures only the ref: no chart data in resume state).
- `BenchProof.tsx`: `BenchProof({ metrics, name? })` = segmented control (radio inputs `name`, no JS, `:has()` shows the panel) over one panel per `ProofMetric` (`data-verdict`): headline (`text-wrap: balance`), subline, `ol` of thin rounded bars (`--p` = value / max, `--i` = stagger index, Rivet bold + accent), value at the bar end, one provenance line. Bars grow once on view: `clientEffect(() => reveal(root()!), { when: "visible" })` → `bench-proof.ts` sets `data-in` (CSS transition 400 ms, 40 ms stagger; only under `(scripting: enabled)` + no reduced motion, so no-JS shows full bars). `BenchGrid({ grid })` = `ProofGrid` table: framework columns (Rivet tinted), metric rows (unit in the label, sticky first column on narrow screens), best cell bold (`bestCell`), "—" = not measured, one sources line.
- `HeroGlow.tsx` + `hero-glow.ts`: decorative hero glow (`aria-hidden`): server = element whose `::before` is the static CSS glow (app CSS); at idle (`clientEffect … { when: "idle" }`, ~1.3 KB br chunk) `mountGlow` draws 4 drifting / breathing / squashing radial blobs (`blobAt`, ~20–40 s periods) on a 1/8-resolution canvas at 24 fps (timer + rAF, no per-vsync wake), sets `data-live` (CSS cross-fades static → canvas), pauses off screen (IntersectionObserver) and in hidden tabs, one static frame under reduced motion; re-reads `--glow-colors` / `--glow-points` / `--glow-composite` on theme change. `createGlowLoop(draw, clock, { reduced, fps })` = the DOM-free loop (tests: `../tests/hero-glow.test.ts`). Measured ~0.7 % main-thread time at 1440 (headless Chromium, CDP TaskDuration), 0 % off screen / reduced.
- `chart-model.ts`: pure (server + browser): spec types `BenchChartSpec` (`bar` | `range` | `stat`, `ChartGroup`, `ChartPoint` (`rivet` flag = accent colour), `StatChartSpec` (`lead`, `claim`), `ChartCaption`), `niceStep` / `niceAxis` / `linear` / `formatValue` / `formatTick` (one cached `Intl.NumberFormat` per digit count, never `toLocaleString` per value: it built a formatter per call, 80 % of `/about/benchmarks/` server render; lane X7) / `sorted` (best first, stable) / `extent` / `rowLayout` (labels left ≥ 520 px, above bars below) / `hitRow` / `advantage` / `easeOut`, `LAYOUT` constants; homepage shapes `ProofMetric` (tab, headline, subline, verdict, points, source line) and `ProofGrid` (columns, rows with `null` cells, notes, sources) + `bestCell`. Tests: `../tests/chart-model.test.ts`.
- `chart-canvas.ts`: browser renderer (.ts, not server-rewritten): `readChart(figure)` (spec back from the markup), `mountChart(figure)` → cleanup. devicePixelRatio (≤ 3) canvas, ResizeObserver redraw, IntersectionObserver (30%) starts a 720 ms ease-out staggered entrance (none under `prefers-reduced-motion`), MutationObserver on `<html data-theme>` + `document.fonts.ready` re-resolve colours / fonts and redraw; flat bars (3 px end radius), quiet solid grid, value labels at the mark end, whiskers for min–max, median dots on range charts; pointer hover + keyboard (arrows / Home / End / Escape on the focusable `.bench-plot`) → tooltip `.bench-tip` + polite live region. Colours: `--chart-*` tokens resolved through a probe `<span>` inside the figure (any CSS colour syntax works); text in the figure font.
- `bench-chart.css`: chart, proof (`.bench-proof*`) and grid (`.bench-grid*`) styles + `--chart-*` tokens on `.bench-tokens` (the root class of BenchChart / BenchProof / BenchGrid; light; `[data-theme=dark] .bench-tokens` dark; `--chart-peer-soft` = thin proof bars). Rivet = one indigo accent `--chart-rivet` (`--chart-rivet-end` equal; set it to another colour for a soft two-stop ramp), peers = neutral greys; mark colours are literals, text maps onto theme semantic tokens with fallbacks (`var(--fg-soft, var(--fg-2))`, …) so a new identity restyles them; contrast: `../tests/bench-chart.test.ts` (marks incl. `--chart-peer-soft` ≥ 3:1, text ≥ 4.5:1 on `--chart-surface`, both themes); own `.bench-sr` visually-hidden class. Not in theme.css / site.css: apps import it (`@import "@rivetjs/docs-kit/components/bench-chart.css"`).
- `StatusBadge.tsx`. Theme pre-paint script: `../document.ts`.
- `types.ts`: shared shapes of generated data (`NavData` (sections with `area` + groups), `NavAreas` (`{ id, title, href }[]`), `NavItem` (+ `tag?`), `PageIndexEntry`, `PageInfo`, `ExampleData`, `ExampleFile`, `ExampleMeasure`, `Status`).

## Rules / invariants
- Resumability: content pages ship no JS; interactive bits load on use (`preload="intent"`, dynamic imports). No code strings in resume state (CopyButton reads the DOM).
- Resumed handlers are delegated from `document`: use `event.target`, not `currentTarget`.
- Inline arrows inside `x.find(fn) ?? fallback` in a component body become resumable closures and break render: hoist to module scope (`StarterButton.tsx`).
- Links use `data-rivet-reload` (full page loads between docs pages); keep `data-rivet-prefetch` attributes when restyling.
- Browser globals (`document`, `localStorage`, `location`) only inside handlers or in `browser.ts`; mutable module state in objects (`spyState`): resumed handler chunks import bindings read-only.
- Overlays: cdk div overlay layer only (never native `<dialog>` / popover); frame z-indexes stay below it (`--z-nav` / `--z-bar`).
- Icons: lucide only, through `@rivetjs/kit/icon` (`<Icon icon={Sun} size={20} class? />`, server + client); no invented SVG paths, no UTF symbols as icons.

## Gotchas
- `BenchChart` data: the canvas reads the server table, so table markup + `data-*` attributes are the client contract (`chart-canvas.ts` `readChart`); change both together. Never put chart specs in captured closures (resume state).
- Generated routes import these by path (`@rivetjs/docs-kit/components/<Name>.tsx`, see `../tools/content/generate.ts`): keep file names.
- cdk `Button` (ThemeMenu / MobileMenu triggers) carries hover (`pointerenter`) handlers → the preload planner would schedule its chunks as `visible` (~39 modules prefetched after load). Both docs apps set the preload rule `{ match: "@rivetjs/cdk/", strategy: "intent" }` in `vite.config.ts` (JS on idle 70 → 42 KB br); keep it in any new site.
