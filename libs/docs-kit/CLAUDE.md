# @rivetjs/docs-kit
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Private docs-site engine: Markdown content → Rivet routes, examples as pages of the docs app itself (frame routes, Chromium checks), API reference (TypeDoc), Pagefind search, prerender, link check. Sites: `apps/docs`, `apps/cdk-docs`, `apps/ui-docs`.

## Entry points
- `package.json` `exports: { "./*": "./*" }` → every file is importable by its path (`@rivetjs/docs-kit/tools/content/generate.ts`). Source package (`rivet.source: true`), no build step.
- **Every file path is public API**: apps, their tests, generated routes and `scripts/size-report.mjs` import files directly. Never move/rename a file without grepping the repo (`grep -rn "docs-kit/<path>"`).
- `cli.ts`: `node libs/docs-kit/cli.ts <command> <app root> [options]`, dispatches to `tools/*`:
  - `build [--no-checks] [--no-search] [--no-cache] [--dist dir]` → `tools/build.ts`: ONE Vite build (docs pages + example frame pages, shared chunks; in child processes, `tools/vite-build.ts`: client, then server bundle; the docs plugin's `config` hook generates example frames + data and content routes in the client child) → prerender → build-time highlighting (`tools/highlight-pages.ts`: every plain `<pre data-lang>` block of a docs page coloured with the browser highlighter's tokens + classes and marked `data-hl`; logs `highlight: N code blocks coloured in P pages (x plain, y left for the browser)`; apps/docs 979 blocks / 220 pages ≈ +2.3 s, cdk-docs 3836 / 762 ≈ +7 s) → host files + AI outputs (`tools/llms/`) → example checks in Chromium against `dist/client` (measures written into the pages) → critical CSS per page (`tools/critical-css.ts`; after the measures, so their markup counts) → the site's compression dictionary (`writeDictionaries`, `_rivet/dict/`; `serve` answers `dcz` with it) → Pagefind → link check. Out: `dist/client`, `dist/server`; `--dist` = another output dir (keep it inside the app, e.g. `<app>/.artifacts/…`: the server bundle resolves externals from node_modules above it). Logs `site phases: vite …, prerender …, checks …, critical …, search …, links …` + `content: N pages, M examples (L live)` + `done in N s (…, peak … MB)` + peak tree RSS vs budget (`tools/memory.ts`, `DOCS_KIT_MAX_RSS_MB`, default 3072: above it the build fails). `--no-checks`: "What loaded" paragraphs stay empty; `--no-cache`: re-check every example.
  - `check-examples <id…> [--dist dir]` → `tools/check-examples.ts` `checkExamplesOnly`: production check of a few examples without the site: one Vite build (child processes, `tools/vite-build.ts`) restricted to those frame pages (`vite.ts` frames-only transforms under env `DOCS_KIT_FRAMES_ONLY`: `.rivet/routes.ts` keeps the frame routes, `.rivet/app.tsx` page imports other than frames reject, the frames index keeps the ids), prerender, their Chromium checks (no cache read / written; quarantine applies). Out: `<app>/.artifacts/check-examples/`. Measured 2026-10-08: cdk-docs 8 ids 32 s / 2.05 GB peak tree RSS (full build ~6–8 min); ui-docs 34 ids ~40 s / 2.8 GB. Run through the shared CPU gate when lanes run in parallel.
  - `examples` → `tools/examples.ts` `examplesCommand`: regenerate the example frames + data, list code-only examples with the reason. Nothing is built.
  - `api [--missing]` → `tools/api.ts`: TypeDoc over `api.config.ts` → `src/generated/api.json` (committed). `--missing`: symbols without summary.
  - `prepare` → `tools/prepare.ts`: example frames + data, content routes (incl. the error pages of a site with `errorPages`), router `.rivet/` (for typecheck without build).
  - `errors [--check]` → `tools/errors.ts` `errorsCommand`: regenerate `content/errors/*.md` (diagnostic code pages from `libs/compiler/codes.json` + `libs/language-core/explain.json`, site `errorPages: true`); `--check` = no writes, fails on stale / missing / orphan pages (CI `gates`). prepare / build / dev regenerate them too.
  - `check-content [--strict]` → `tools/check-content.ts`: validate content, no writes; `--strict` fails on `TODO-CONTENT` and on markdown links to `localhost` / `127.0.0.1`. Cross-site links: `[x](site:<name>/<path>)` resolves at build time against site config `sites` (name → origin; env-overridable, dev defaults = local ports, production sets the `*_DOCS_ORIGIN` env vars; canonical URLs use `origin` the same way). Never hard-code sibling-site URLs.
  - `check-snippets` → `tools/check-snippets.ts`: every ts/tsx/js/jsx fence of `content/**.md` parses (excerpt forms accepted: sibling markup, `…`, object members, call items, one JSX element per statement); importing fences are typechecked with the app's tsconfig under `.artifacts/snippets/`, failing only on import drift (missing `@rivetjs/*` module/export: TS2305/2307/2459/2460/2614/2724); fence meta `check` = full typecheck, `nocheck` = skipped. CI `gates` job.
  - `llms [--out dir] [--check] [--dist dir]` → `tools/llms/generate.ts`: AI outputs (`llms.txt`, `llms-full.txt`, `<page>.md`, `api/<entry>.md`, `examples/<id>.md`; llmstxt.org) from committed sources, written into `<app>/dist/client` (also by every `build`, after prerender); `--check` = no writes, every page has Markdown, same-site `.md` links resolve, two generations byte-identical (CI `gates`); `--dist` also compares a built site. Not checked in (ruling in [tools/llms/CLAUDE.md](tools/llms/CLAUDE.md)).
  - `serve [--no-watch] [--port n] [--dist dir] [--dev]` → `tools/serve.ts`: built `dist/client` on the site origin port (`site.config.ts` `origin`, overridable), through the router node adapter (zstd / brotli / gzip by `Accept-Encoding`; `/assets/` precompressed next to the file on first request); default: watch + incremental rebuild (see "serve rebuilds"); `--no-watch`: serve dist as is. `--dev`: the docs app's Vite dev server only (`vite.config.ts` port, `--port` overrides): docs pages AND example frames compile on demand with HMR; nothing else is built or started.

## App contract (what a site root holds)
- `site.config.ts` → `export const site: DocsSite` (`tools/app.ts`); bundled into pages. `errorPages?: true`: diagnostic code pages `content/errors/` (`tools/errors.ts`, committed, regenerated by prepare / build). `criticalCss?: { extraSelectors?: string[] }`: selectors of DOM the site adds in the browser before the full stylesheets load (their rules are inlined; see "Critical CSS"). `leanPages?: string[]` (paths, e.g. `["/"]`): disables generic idle code highlighting, search shortcut setup and router fetch-ahead (`preload.lean`); code samples must be coloured at build. Page-owned visible effects still run, so leanPages is not a zero-script guarantee (the apps/docs home is zero-script because its hero motion is CSS, STATIC-ZERO-3).
- `api.config.ts` (optional) → `entries: ApiEntryConfig[]`, `packages: ApiPackage[]`; build/server only.
- `content/**.md` + `content/_nav.ts` (`export const areas: NavArea[]` (top-bar sections; an area with `href` is a route area — a hand-written `src/routes` page such as ui-docs `/themes/`, no sections, a known link target for check-content) + `export const nav: NavSection[]` (each with `area`; a page entry may carry `children`: routed, not listed in the side nav), types in `tools/nav.ts`); optional `content/_<name>.md` fragments → `src/generated/fragments/<name>.tsx` (home page blocks; code coloured at build, `data-hl`).
- `content/_charts.ts` (optional) → `export const charts: Record<string, BenchChartSpec>` (`components/chart-model.ts`), referenced by `::chart{id}`; optional `proof: ProofMetric[]` / `proofGrid: ProofGrid` for a homepage `BenchProof` / `BenchGrid`; app styles import `components/bench-chart.css`. Its other data exports are written as literals to `src/generated/charts.ts` (typed by the source module): hand-written pages import those, not `_charts.ts`, whose report imports would land in the client chunk (apps/docs home: 175 KB JSON).
- `examples/<id>/example.ts` + example sources (`src/routes/**`, `src/components/**`, `src/styles.css`, …): modules of the docs app itself; `_`-prefixed folders are shared files. `examples/_quarantine.json` (optional, `tools/example-checks.ts` `QUARANTINE`): `{ "<id>": { "step", "reason" } }` = known check failures, reported as quarantined (not hidden), not failing the build.
- Shared example assets (`tools/examples.ts` `SHARED_ASSETS`): a relative import of `examples/<id>/src/assets/<path>` the example does not have resolves to `examples/_assets/<path>` (`vite.ts` `docsFrames`). `?image` / `?jsx` imports need `rivetRouter({ images: true })` in the app (ui-docs).
- `vite.config.ts` with `docsSite()`; `templates/` at repo root = starter templates (`::starter`, StarterButton; `starter-static/src/styles.css` = stylesheet of examples without their own).
- Generated, gitignored: `src/routes/(docs)/`, `src/routes/{search.tsx,examples/,api/}` (kit route copies), `src/generated/*` except committed `src/generated/api.json` (incl. `examples.json`, `example-frames.tsx`, `example-frames/<id>.tsx`, `example-css/<hash>.css`); `.artifacts/example-checks.json` (check cache).

## Example `Step` schema (`define.ts`, runner `tools/example-checks.ts` `run()`)
Input steps (first one starts the "after first interaction" measure):
- `{ click: sel }`, `{ dblclick: sel }`, `{ rightclick: sel }` (fires `contextmenu`), `{ contextmenu: sel }` (right click that fails unless the trusted `contextmenu` default ended prevented — a custom context menu; catches a cold one the resume loader did not hold, `data-cm`, COLD-CTXMENU 2026-10-27), `{ hover: sel }` (pointer/mouse enter/over)
- `{ longpress: sel | [sel, ms] }`: mouse down on the element centre, hold `ms` (default 700), mouse up (press-and-hold, item morph)
- `{ wheel: [sel, deltaY] }`: hover then wheel; `{ drag: [from, to] }`: Playwright `dragAndDrop` (pointer drags + HTML DnD)
- `{ tap: sel }`: CDP touch at element centre (touchstart/touchend, `pointerType: "touch"`, click); no `hasTouch` context needed
- `{ fill: [sel, value] }`, `{ press: [sel, key] }` (focus + key), `{ key: key }` (on current focus; Playwright key names)
Assertion steps (wait ≤ 5 s): `expect` (text contains), `attr` (`null` = absent), `name` (accessible name), `described` (aria-describedby text), `focused`, `matches`, `absent`.
- New step kind: add to `Step` (define.ts), `INPUT_STEPS` if it acts on the page, a branch in `run()`, a case in `tests/steps.test.ts`, this list.

## serve rebuilds (`tools/watch.ts` → `tools/rebuild.ts` → `tools/serve.ts`)
- Watches (fs.watch recursive, 300 ms debounce, bursts coalesced, changes during a rebuild queue for the next; editor / atomic-write temps ignored: hidden files, `x~`, `#x`, `x.tmp`, `x.tmp.<pid>.<hash>`, `x.<pid>.<ts>.tmp`, `___jb_tmp___` / `___jb_old___`, `.crswap`, vim `4913` — `watch.ts` `EDITOR_TEMP`): app `content/`, `examples/`, `src/` (hand-written; generated routes/`src/generated/*` ignored except `api.json` / `examples.ts` written by another process), `api.config.ts`, `site.config.ts`, `vite.config.ts`, `tsconfig.json`, `package.json`; repo `templates/`, `libs/` (minus tests, `*.md`, node_modules, dist, `compiler/{rust,oracle}`).
- `classify(files) → Plan`: `content/**` → regenerate content + affected pages; `examples/<id>/**` (existing example) → regenerate examples + its pages (`usedOn`, `/examples/<id>/`, its frame pages); new / removed / `_`-shared example files, `templates/` → content + full site; `api.config.ts` → TypeDoc + full site; app `src/`/config → full site; `libs/**` → full site when in the site graph (`.artifacts/site-graph.json`), tooling (`libs/compiler/`, `docs-kit/tools/`, `router/{build,adapters}/`, `*/vite.ts`) or no graph yet.
- Rebuild runs in a fresh child process (current tool sources, no module state; exits when `serve` disappears, IPC `disconnect`), stages into `dist/.next/` (example checks through their cache: only changed frame pages open Chromium); `serve` swaps staged `client`/`server` in by renames while requests are held (`serveSwappable.swap`: in-flight finish, new wait) → never a half-written or mixed build. Failure: stale build keeps serving, error + output tail printed, plan retried with the next change.
- Incremental prerender (`tools/incremental.ts`): every page embeds the full route-chunk list, so pages whose route files changed are rendered; the rest are copied from the served build with asset names rewritten (old → new via the two Vite manifests, CSP meta recomputed). Falls back to a full prerender when a canary page (home + one more) rendered fresh differs from its rewritten copy, or a reference is missing. Shared generated files (nav.ts, pages.ts = titles, terms, highlight.css, starters, kit route copies) → full prerender. The canary's fresh render is highlighted (`highlightHTML`) before the compare: copies already carry build colours. Search index reused on incremental (body-only edits are not re-indexed until a full rebuild), rebuilt otherwise. Generated files written by a failed attempt are kept in `.artifacts/serve-pending.json` until a swap succeeds.
- Startup: sources newer than `dist/.serve-stamp.json` (else `dist/client/index.html` mtime) → serve stale + rebuild in the background; no dist → build first (503 + auto-reload until ready).
- One log line per rebuild: what was rebuilt, duration, changed files.
- `--dev`: no rebuild loop — the Vite dev server serves docs pages and example frames on demand (HMR); the content plugin regenerates content / example files on change. Measured ui-docs (868 examples): ready in 2–4 s, first frame ~4 s cold (its Tailwind group), next frames ~0.1 s.

## Rules / invariants
- Prose ships no JS: Markdown → static JSX; no raw HTML in content (build error).
- Unknown references are build errors: glossary terms, example ids, API symbols, starters, internal links, nav orphans/duplicates.
- Page paths equal ignoring letter case are build errors (router `prerender`): macOS/Windows/case-insensitive hosts keep one file. API names that differ only in case (`codeInfo` / `CodeInfo`) get distinct URLs from `tools/api.ts` `assignHrefs` (`CodeInfo-interface`, `jsonLd-2`; 2026-10-07: docs 13 + cdk-docs 59 pages renamed, docs static build writes all 821 pages, was 807 with 13 lost).
- Examples run as pages of the docs app's production build (same origin, frame routes); console errors fail the build (unless quarantined).
- Site links are full loads (`data-rivet-reload`); prev/next links also carry `data-rivet-prefetch="prerender"` (router document prefetch; the app enables it with `rivetRouter({ prefetch: "document" })`, which covers the other reload links). Keep both attributes when restyling links.
- Icons: never invent SVG paths, never UTF symbols as icons; use lucide (`lucide` dep) via `@rivetjs/kit/icon` `Icon` (see root CLAUDE.md).
- Interactive frame pieces use `@rivetjs/cdk` (dep): theme menu = `MenuTrigger`/`Menu`/`Popover`, mobile drawer and search = `ModalOverlay`/`Modal`/`Dialog` on the cdk div overlay layer (never native `<dialog>`/popover). Apps load cdk chunks on intent: `rivetRouter({ resume: { preload: { rules: [{ match: "@rivetjs/cdk/", strategy: "intent" }] } } })` (JS on idle 70 → 42 KB br). Animations respect `prefers-reduced-motion`.

## Gotchas
- Incremental prerender falls back to full on every rebuild while server ids come from the runtime's process-wide `createId` counter (`rv…` differs per render order: canary `rvacy` vs `rv2`); fix proposed to the runtime/router lane 2026-10-08 (per-request `withIdScope` in router `stream()` + render-cache probe scope). No docs-kit change needed once ids are per-request.
- Example check measures (`requestsBefore` / `After`) are timing sensitive (idle-time prefetches vs the first interaction). Quiet detector (2026-10-09, PERF-LIBS F8), 250 ui-docs examples on one build: 6 pages 29 s vs old waits 3 pages 97 s (3.3×) / strict 1 page 337 s; two 6-page runs identical (250/250); vs strict 248/250 — the 2 diffs (`calendar-basic`, `card-with-form`) count more "after" scripts, and the old waits vary there run to run (25 vs 14, 48 vs 33: `networkidle` undercounts); peak tree RSS at 6 pages 1.5 GB (ui-docs, 250) / 2.0 GB (cdk-docs, all 567: 125 s, same 6 stale-build failures as strict mode). Do not floor the wait in Node time or trust Playwright request events alone: the loader defers its first preloads 150 ms (`calm`, timers due < 300 ms page time) and appends `fetchPriority=low` links whose requests start later — both measured 0 "before" scripts on 2–4 of 60 pages at 6 pages. The cache keeps a measure until the frame page changes; content-hash keys (F8 "Further (a)") evaluated 2026-10-09: two builds 50 min apart reused 0 / 886 either way (shared runtime chunks + the global CSS change on most commits) — not implemented. App-wide preload rules (`resume.preload.rules`, cdk on intent for the docs chrome) apply to frames too and make them LIGHTER, not heavier (measured 2026-10-08, scripts / KB br before interaction, rules on → off: aria-menu 0 / 0 → 51 / 71.9, calendar-limits 50 / 76.5 → 53 / 79.3, listbox-sections 61 / 72.6 → 61 / 72.8); the remaining pre-interaction weight is the planner's automatic `visible` preload for handlers on ≥ 3 list rows + shared-build chunk granularity (lucide icon / box / context chunks), not the docs app. Quarantined check failures blamed on the rules were runtime / cdk bugs exposed by intent-time loading (fixed 2026-10-08).
- Dev search (`tools/dev-search.ts`): built lazily on the first `/pagefind/` request by rendering every prerenderable page through the running dev server (apps/docs ~820 pages ≈ 3 s; cdk-docs ~3200 pages ≈ 16 s cold, its 38 MB `src/generated/examples.ts` transform needs > 3 GB heap). A source change only marks it stale: the next `/pagefind/` request gets the stale index and starts one rebuild, which re-renders only changed route modules' pages (rest = cached HTML) unless a shared file changed. Edits under `libs/` (outside the app root) do not mark it stale.
- Tools hold module state (`tools/app.ts` current app): one app per process; `loadApp(root)` first.
- One watching `serve` per app: it renames `dist/client` on swap, which breaks another (old, index-mode) server process serving the same dist.
