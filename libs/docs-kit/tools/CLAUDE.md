# @rivetjs/docs-kit/tools
> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Node-side build tools behind `cli.ts`. Each command module exports `<name>Command(root, args)` plus a programmatic function.

## Layout
- `app.ts`: `loadApp(root)` / `app()`; `DocsSite` (incl. `leanPages`: loader-only pages, see ../CLAUDE.md App contract), `ApiEntryConfig`, `ApiPackage`, `DocsApiConfig`, `RunsOn` types. Cached per root; `templates` = `<repo>/templates`, repo = `root/../..`.
- `build.ts`: `buildDocs(root, { checks?, search?, dist?, cache?, log? })` (`buildSite`, then logs counts, phase totals + peak tree RSS, `memory.ts`; content + example generation happens in the Vite client child's `config` hook); `buildSite(root, { dist, search?: boolean | "reuse", incremental?: { previous, pages }, checks?: boolean | { cache }, log? })` (one Vite client + server build into `<dist>` through `vite-build.ts`, records site graph, prerender full or incremental, critical CSS (`critical-css.ts`), host files + AI outputs (`llms/`), example checks + measures, search, link check); host files (`_headers`, `speculation-rules.json`, Cloudflare Pages format).
- `examples.ts`: examples as modules of the docs app (see ../CLAUDE.md "Example frames"): `generateExamples(root, { lenient? }) → { examples, written }`, `examplesCommand(root)`, `framePlan(config, files, sources)` (live pages + layout chains, or `codeOnly` reason), `groupCSS(text, members, fromGenerated)`, `exportNames(source)`, `shownFile(path, source)` / `focusRegion` (plain text + marks / focus), `exampleIds`, `loadExample`, `usage(root)` (pages embedding each example), constants `EXAMPLES_JSON`, `FRAMES_INDEX`, `FRAMES_DIR`, `CSS_DIR`, `SHARED_ASSETS`.
- `api.ts`: `buildApi(root)` TypeDoc → normalized `ApiModel` (`ApiSymbol`, `ApiMember`, `ApiParam`); `tsconfig.api.json` = TypeDoc's tsconfig. `assignHrefs(model)` (end of `normalize`): page URLs unique ignoring letter case — entry `/api/<entry>/`; symbol `<entry href><name>/`, on a case clash `<name>-<kind>/` (kind unique among the clashing names) else `<name>-<n>/`; claim order: entries, then per case-folded name values (function, class, variable, enum, namespace) before types (interface, type), then code point; same key (merged declarations) = one page. Deterministic, order-independent. Links always use `symbol.href` / `entry.href`, never `entry.href + name`.
- `prepare.ts`: `prepare(root)`: example frames + data, content routes, router `.rivet/`.
- `check-content.ts`: dry-run `generateContent`; `--strict` also fails on `ContentResult.localLinks` (hard-coded localhost links; use `site:<name>/<path>`, see `content/markdown.ts` `siteHref`/`isLocalUrl`; test `tests/site-links.test.ts`).
- `check-snippets.ts`: `checkSnippets(root)` → `{ snippets, failures }`; `extractSnippets(md, file)` (remark, same parser as the pipeline), `syntaxErrors(snippet)` (`ts.transpileModule` diagnostics, `EXCERPT_FORMS` fallbacks), `typeErrors(root, snippets)` (one `ts.createProgram` over `<root>/.artifacts/snippets/snippet-N.<lang>` with the app tsconfig options + its `.d.ts` includes; `DRIFT` codes unless meta `check`). Failures carry the Markdown line.
- `check-links.ts`: `checkLinks(dist)`: hrefs/srcs/anchors (example iframes are frame pages of the same build; frame pages: assets only, element hrefs other than `<link>` are demo placeholders), StarterButton StackBlitz form actions skipped.
- `search.ts`: `buildSearch(client)`: Pagefind over `**/index.html`, only `data-pagefind-body`; writes `client/pagefind/`. `SEARCH_INDEX` = index options shared with dev.
- `dev-search.ts`: dev-server search, same index as the build, in memory. `docsDevSearch()` Vite plugin (in `docsSite()`, `apply: "serve"`): `/pagefind/*` middleware ahead of Vite's, watcher on the app root (minus node_modules/dist/.artifacts/.rivet) → `invalidate(file)`. `devSearchIndex(source, { log? }) → { handle, invalidate(file?), build, close }`: lazy build on first request (requests wait); `invalidate` only marks the index stale (+ records the file; none = all) — the next `/pagefind/` request starts one background rebuild (coalesced: never two at once) and is answered from the stale index; a change during a build marks it stale again; failed build → previous index kept, next build re-renders all. Pagefind `createIndex(SEARCH_INDEX)` → `addHTMLFile` per page → `getFiles()` kept in a Map (latest + previous build's files, so a loaded `pagefind-entry.json` still finds its chunks); builds serialized per process (`pagefind.close()` ends the shared backend); build error → 500 text/plain with the reason; 0 pages = error. `devServerPages(server, { concurrency? = 8, outDir? = ".rivet" })`: enumerates pages like `@rivetjs/router/static` `prerender` (ssrLoadModule `entry.server.tsx` routes, static + `serverEntries()`, `prerender` flag) and fetches them from the listening dev server; URL recorded as `/a/` (build form); non-200 pages skipped with a warning. Keeps each page's HTML (docs ≈ 35 MB, cdk-docs ≈ 150 MB): a rebuild re-renders only pages of changed route modules + new pages (`changedRoutes(changed, root, ids, routesDir?)`: `<routesDir>/<route id>.tsx` → that route; page Markdown `content/**/[^_]*.md` → nothing (its generated route module changes too); anything else, e.g. `src/generated/*`, layouts, components, `_nav.ts`, fragments → all). Measured apps/docs: route-module edit 2.3 → 0.2 s dev-server CPU (Pagefind's own process ≈ 1 s either way); `search: re-rendered N of M pages` logged per rebuild.
- `serve.ts`: `serveCommand` (`--dev` = the app's Vite dev server only; else watch loop, startup staleness, swaps; `--dist <dir>` build dir override), `serveSwappable(dir, port)` (fs-lookup server whose `swap(fn)` holds requests while `fn` renames dirs), `replaceDir(target, staged, trash)`, `serveStatic(dir, port)` (index-mode: files indexed at startup, `--no-watch`), `seconds` / `time` / `list` log helpers. Both servers are the router node adapter with `compress: true` (M5 E2 2026-10-18): pages (the folder → index.html handler) go out as zstd when accepted (brotli / gzip otherwise), `/assets/` files are precompressed once at the best quality and written next to the file (`.zst` / `.br` / `.gz`; a swapped-in build has new hashed names, so stale siblings go with the old dir). Test `tests/serve-encoding.test.ts`.
- `watch.ts`: `classify(files, { root, repo, graphs, exists? }) → Plan` (`changed`, `content`, `api`, `examples` = edited existing examples, `site`), `ignored`, `mergePlans`, `hasWork`, `watchSources(root, repo, fn, { debounce? })` (fs.watch + debounce), `watchedDirs(root, repo)`, `changedSince(root, repo, ms)`.
- `rebuild.ts`: `rebuild(root, plan, { dist })` (child side: api → examples + content → site into `dist/.next/`; an example edit re-renders its pages incrementally), `runRebuild(root, plan, options)` (forks itself, captures output; the child exits on IPC `disconnect`), `RebuildOptions`, `pagesOf(written)`, `STAGING`, `PENDING`.
- `incremental.ts`: `prerenderPartial({ dist, previous, pages, origin })`, `renameMap`, `rewritePage` (HTML: `restoreLinks` first — copies are compared and inlined again as prerendered), `stableKey`, `assetRefs`.
- `critical-css.ts`: `inlineCriticalPages(client, { files?, added?, extraSelectors? }) → { pages, bytes, skipped }` (build: every `sitePages(client)` file, i.e. `*.html` minus assets / pagefind / example frames; `added(html)` = class names scripts add early, build passes the highlighter token classes on pages with `data-lang`; `extraSelectors` = the site's `criticalCss.extraSelectors`, on top of `CLIENT_SELECTORS`; `skipped` = pages left as they are with `criticalSkip` reasons, logged), `inlineCritical(html, sheet, added?, extra?)` (subset → `pruneCustomProperties`), `criticalSkip(html)`, `CLIENT_SELECTORS` / `selectorNames`, `DEFER_ACTIVATOR`, `restoreLinks(html)`, `parseSheet` / `criticalCSS` / `presence` / `selectorNeeds` / `pruneCustomProperties(css, html?)` (always-kept `@property` and `--x` declarations of nameless rules (`:root` / `*` / `::backdrop`) go unless a kept rule / statement / the page `var()`-references them, followed to a fixpoint; identical nameless rules under the same block chain (Tailwind properties fallbacks of several sheets) deduped only when every declaration of each property has one value; own CSS splitter on minified output: no CSS parser dependency; nested style rules kept whole). See ../CLAUDE.md "Critical CSS".
- `graph.ts`: `graphPlugin(repo, set)` (Vite plugin: module ids + plugins' `addWatchFile` files (e.g. Tailwind `@import`ed CSS) → repo-relative), `readGraph` / `writeGraph`, `siteGraphFile`.
- `memory.ts`: peak RSS of the build process tree, printed and checked against `DOCS_KIT_MAX_RSS_MB` (default 3072).
- `example-checks.ts`: optional `DOCS_KIT_CHROMIUM_PATH` selects a build-only Chromium executable (Cloudflare rootless bundle); otherwise Playwright defaults. `checkExamples(root, client, examples, { cache?, log? })` (Chromium over `dist/client`, `CHECK_CONCURRENCY` (default 6), `CHECK_STRICT` (env `DOCS_KIT_CHECK_STRICT=1`: old waits, 1 page), quiet detector `quiet`, cache `CHECK_CACHE` (`FORMAT` 2 / 2-strict), quarantine `QUARANTINE`, all failures reported together; `only` = check just these ids, `persist: false` = leave the cache file alone), `run()` step runner (exported for tests), `found()` failure context, `measureHTML`, `writeMeasures(client, measures)`.
- `vite-build.ts`: `viteBuild(root, { dist, graph?, env? })`: the docs app's Vite build in two child processes, client then server bundle (`node tools/vite-build.ts <root> <json>`, stdio inherited, `--max-old-space-size=VITE_HEAP_MB` (1536; env `DOCS_KIT_VITE_HEAP_MB`)); the server child gets env `GENERATED_ENV` (`DOCS_KIT_GENERATED`: `content/plugin.ts` skips regeneration) and adds its modules to the site graph the client child wrote (`graph: true`). Children exit when done, so rolldown's native memory is gone before prerender / Chromium (measurements: ../CLAUDE.md "Memory").
- `check-examples.ts`: `checkExamplesOnly(root, ids, { dist?, log? })` / `checkExamplesCommand(root, args)` (`cli.ts check-examples`), `CHECK_EXAMPLES_DIST`; passes `vite.ts` `FRAMES_ONLY_ENV` to its `viteBuild` children (helpers `onlyFrameRoutes` / `onlyFramePages` / `onlyFrames`, each failing on an unexpected generated shape).
- `lock.ts`: `withLock(dir, fn, { timeout?, stale? })` (rename-in lock dir with owner pid; dead/stale owners broken), `writeAtomic(file, text)`.
- `nav.ts`: `NavArea` / `NavSection` / `NavGroup` / `NavPage` / `NavTag` types for `content/_nav.ts` (`areas` = top-bar sections → `nav` sections (side-nav parts, `area` = area id) → groups (collapsible) → pages). `NavPage` = content path or `{ path, tag: "new" | "updated" }`; `navPath` / `navTag` helpers.
- `content/`: Markdown pipeline, see [content/CLAUDE.md](content/CLAUDE.md).
- `llms/`: AI outputs (`llms.txt`, `llms-full.txt`, per-page Markdown) + the page data of `@rivetjs/mcp`, see [llms/CLAUDE.md](llms/CLAUDE.md).

## Rules / invariants
- Example measure: scripts requested before first input step (after the page is quiet (`quiet`), idle / visible prefetches count as "before"; strict mode: `networkidle` + 300 ms) vs after (quiet again; strict: `networkidle`); a navigation ends the "after" window.
- Example frame pages exist at `/examples/<id>/frame/` (+ sub-paths); code-only examples (`ExampleData.codeOnly`) have none and are not checked.
- `api.json` is committed: its diff = public API change. `_`-prefixed and `@internal` exports excluded.
- Generated files carry `// Generated by @rivetjs/docs-kit… Do not edit.` headers.

## Gotchas
- `incremental.ts` deep-imports `../../router/adapters/build.ts` (`loadBuild`) and router `shared/{data,slash}.ts`: keep in sync with the static adapter's page/data layout.
- Module-level state (`app.ts` current app): call `loadApp` before helpers.
- Step timeouts are 5 s; `key` acts on current focus without a selector wait.
