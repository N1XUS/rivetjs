## Invariants

- `composeTwRenderProps`: `cls` may return `string | undefined` (cdk `ClassNameOrFunction` shape, so `FieldError` passes its `class` prop through untyped-cast-free); two non-function inputs → a string (upstream via RAC `composeRenderProps` always returns a function; cdk `class` takes both, same classes). A function input → `(v) => cx(tw(v), cls(v))`; `v` = cdk's render-props object unchanged (accessors, e.g. `v.isSelected()`).
- `dom` is a module namespace (upstream: runtime `Proxy` over every intrinsic tag). Tags = those HeroUI components use (`abbr button circle div fieldset h3 header kbd legend li nav p section span svg tbody thead ul`); add a tag (named export in `dom-tags.tsx`) when a ported component needs one. Namespace member access tree-shakes: `@rivetjs/ui/card` [dom] keeps only `div` / `h3` / `p` (was all 18 with the old object map). Server bundles still keep every tag's hoisted `Object.freeze([...])` fragment array (compiler emits it without `/*#__PURE__*/`; root patch `ui-pure-fragments`).
- `dom.*` bodies spread `{...props}` as a plain object (no destructuring, no wrapper call): the element `_spread` reads every key inside its effect, so live getter props (`class={slots.base(…)}` from a part, `<dom.div class={c()}>`) and accessors (`class={() => c()}`, spread rule: a function value is an accessor) both update in place. `{...{ render: undefined }}` after it keeps `render` off the element (default path). `ref` is not an explicit attribute: it rides in the spread (`_spread` binds it on client-created elements, `tests/dom.test.tsx` ref test); the server does not record it, so on a resumed page a `dom.*` ref is empty (parts that need their element on resume render a plain element with an explicit `ref`, e.g. `scroll-shadow`).
- `DOMProps<E>` accepts accessors: every attribute of `JSX.IntrinsicElements[E]` may also be `() => value` (`AccessorAttrs`; `ref`, `children`, `render`, `on*` unchanged), so `<dom.div class={() => cls()} />` needs no cast. Tag bodies cast the spread back (`{...(props as JSX.IntrinsicElements["div"])}`): the runtime spread binds accessors, JSX spread typing does not know. Type test `../../tests/dom.types.tsx`.
- `render` prop: every tag starts `if (props.render) return rendered(props);` BEFORE the unchanged compiled element (no JSX fallback callback: it breaks resume, cdk render rule 1). `rendered` (module-private, not a `dom` member) calls `render(propsWithoutRender, undefined)`: lazy JSX `children` resolve once (`renderSlot`), a user function `children` passes as is (a wrapper arrow is not serializable: the resumed spread site would be lost). Props type `DOMRenderedProps` (loose, no cast for `{...props}` on another tag; `tests/dom.types.tsx`). Development: a `ref()` signal still empty one microtask after `render` returned warns with the upstream message (`#dev`, `DEV` from `dev-on.ts`; production bundles drop check + message, `tests/dev-warning.test.ts` bundles with rolldown + runs happy-dom with/without `--conditions=development`; text registered in `scripts/zero-cost/dev-leaks.mjs` `DEV_MESSAGES`). Never cdk's runtime `isDev()`.
- Resume (verified, `../../tests-components/resume.test.ts`): the server-resume spread site captures `props` whole (`_rSpread(id, () => ({ ...props, … }), [props], tag)`), `children` included. Captures serialize only when the spread read signals (an accessor prop reading a signal, `class={() => c()}`); JSX `children` then serialize as a slot symbol (`{f: "<route>#…$n"}`, R2 JSX-returning function prop), so no compiler change is needed. Former runtime bug (spread update re-ran that `children` slot when another key changed) fixed in runtime commit "fix(runtime): spread re-inserts children only when `children` changes"; `../../tests/dom.test.tsx`, `../../tests-components/resume.test.ts` assert child node identity. `ref` inside the spread is NOT resumed (no `_rRef` for a spread key): resumed `dom.*` refs stay empty (runtime gap, reported to the runtime lane). Server-resume and DOM-resume compiles of `dom.tsx` report no diagnostics (a compile under a non-TSX filename does: RV1000 parse errors).
- `dom.tsx` / `dom-tags.tsx` must stay `.tsx` (server-rewritten; `.ts` modules are not). Resume symbol ids: `@rivetjs/ui/src/utils/dom-tags.tsx#<tag>$<n>`.
