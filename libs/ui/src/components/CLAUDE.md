## Port pattern (every component)

- File header: `// Ported from HeroUI v3.2.6 packages/react/src/components/<name>/<file> (Apache-2.0, © 2025 NextUI Inc.; modified).` + `Rivet:` deviation list.
- Keep upstream section banners, names, prop order, `data-slot` values; `className` → `class`; `"use client"` dropped.
- `*Variants` from `../../../styles/src/components/<name>/index.ts` (vendored `@heroui/styles`; per-component path keeps the module graph small — the styles barrel would tree-shake too, `sideEffects: ["*.css"]`).
- Context: upstream type + default, `createContext<XContext>({})` + `<Provider token value>` (`@rivetjs/runtime/dom`, so the part must be `.tsx`). Values: data (`{ variant }`; spec §2), never accessors or tv slot functions (module-level constants like upstream `DEFAULT_SURFACE_CONTEXT` too). Live props: fields are getters over the props (`{ get variant() { return local.variant ?? "default"; } }`, `card` / `surface` / `chip`): readers see data, the encoder reads the value. `React.useMemo` → that object. Parts read the context in the class expression (`slotsOf(context)?.x`), not in the body.
- Context carrying tv slots upstream (`{ slots }`) → `{ <variant props> }`; NEVER slots in context. Root + parts read slots from a module-level memo, `undefined` when the context is the `{}` default (= upstream `slots?.x`):
  - one variant prop: `const SLOTS: Partial<Record<V, Slots>> = {}; const slotsFor = (variant: V) => (SLOTS[variant] ??= xVariants({ variant }));`
  - several: `Record<string, Slots>` keyed by the template string `${size}|${variant}|${color}` → `(SLOTS[key] ??= xVariants({ size, variant, color }))`; key on the defaulted values so it is total.
  - Safe: tv slot functions are pure (same props → same string; tailwind-merge only runs on a `class` / `className` override, `styles/src/utils/tv.ts`). Measured (Card, warm, 6 slot calls): per-part `xVariants()` 0.62 µs, upstream 1× 0.13 µs, memo 0.03 µs.
- Rivet JSX is eager: an element built before `<Provider>` (upstream `const content = <…/>`) renders outside it → `const content = () => <…/>`, called inside the provider. DOM target only (server `Provider` always calls a children thunk), so SSR tests do not catch it: every provider-wrapping part needs a DOM test reading the context.
- Elements via `dom.<tag>` (`import { dom } from "../../utils/dom.tsx"`, a namespace: only used tags are bundled): forwards `ref`, ignores + dev-warns `render`.
- Live props (spec `docs/design/specs/2026-10-07-live-props-design.md`): never destructure `props` (snapshots the getters); `const [local, rest] = splitLive(props as XRootDivProps, ["children", "class", "variant"])` (`../utils/live.tsx`), classes computed in the JSX attribute (`class={slotsFor(variant()).base({ class: local.class })}`: the `dom.*` spread binds it). cdk parts keep live getters live (P5): forward a live prop as a member expression (`value={local.value}`); a cdk prop the ui part derives (`class` from `variant` / `size`, context values) becomes a render-prop function / getter only when `hasLiveProp(props, keys)` (static path passes plain data → the cdk static copy path; `button.tsx`). Migrated: `surface`, `card`, `chip`, `button` (Plan 2 Task 23), `progress-bar` / `progress-circle` / `meter` (Task 19: cdk value props forwarded as getters since P5, class via `renderClass`), the other wave-1 dirs (`badge`, `alert`, `kbd`, `spinner`, `skeleton`, `avatar` + vendor primitive, `link`, `close-button`, `typography`, `label`, `separator`, `header`, `description`, `error-message`, `field-error`, `empty-state`): parts read the context through `slotsOf(context)` in the class binding (no `useSlots()` destructure); cdk parts (`Label`, `Text`, `Header`, `Separator`, `Link`, `Button`, `FieldError`) take `const classOf = () => …; const cls = hasLiveProp(local, STYLE_PROPS) ? (values) => renderClass(classOf(), values) : classOf();` (cdk binds a function class; inline in the body so the compiler registers it: resumable, `../../CLAUDE.md` Gotchas). Element-picking props (`orientation`, `type`, `level`, `size` of Paragraph) stay read once. Measured (happy-dom, 1000 mounts, median): Card + Header + Title 30.1 → 22.4 ms, Button 21.4 → 20.8 ms (noise).
- Generic `<E extends keyof JSX.IntrinsicElements = "…">` roots: keep the generic; props `XRootProps<E> & JSX.IntrinsicElements[E]` (no `Omit` of the generic indexed type: TS2590 at JSX sites passing a function-valued attribute, seen with `ref`, `onClick`; `../../CLAUDE.md` Known diffs); body destructures `props as XRootDivProps` (default-element type, exported from `<name>.tsx`; per part `X<Part><Tag>Props`, e.g. `CardTitleH3Props`).
- Conditional element children: before TERNARY-MEMO (compiler `cond_v2` + runtime `_cond`) a JSX ternary / `&&` child re-ran on ANY read inside its test and re-created its element — a CSS enter animation replayed on every unrelated change (input-otp slot value per keystroke, stepper check per step change; fixed 2026-10-08 with `<Show>`, kept). Now the compiler memoizes the condition: a branch is rebuilt only when the rendered branch changes; a read inside the JSX operand's own expressions binds in its own effects. `<Show when>` stays the explicit form (resume branch slots, function children). Regression: `tests-components/reanimate.test.ts`.
- `index.ts` type `X = { Props; RootProps; … }`: React `ComponentProps<typeof XRoot>` → the default-element type (`XRootDivProps`); never `Parameters<typeof XRoot>[0]` on a generic root (resolves `E` to its whole constraint). Non-generic parts may use `Parameters<…>[0]`.
