# @rivetjs/ui

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Rivet UI: styled compound components (`Card`, `Card.Header`, …) over `@rivetjs/cdk` + the forked style base (`styles/`, from `@heroui/styles`) + Tailwind v4. Derived from HeroUI v3.2.6 (`heroui-inc/heroui` @ `73000ea`, Apache-2.0, © 2025 NextUI Inc.; provenance pin `UPSTREAM`, no tracking): similar look and API, improved (identity spec `docs/design/specs/2026-10-11-ui-identity-design.md`).

## Entry points (`package.json` exports)

- `.` → `index.ts`: barrel (re-exports only; prefer subpaths) = upstream `packages/react/src/index.ts` sections: every ported component + `dom` / `DOMRenderProps` / `DOMRenderFunction` / `DOMProps` (`src/utils/dom.tsx`) + `tv` / `cn` / `type VariantProps` (`tailwind-variants`, as upstream). Compose helpers stay internal (upstream: `utils/index.ts` only, not re-exported by the root). Subpath value exports that are not components reach the barrel too (same binding, e.g. `masonrySizes` from `./masonry`). Exact name list pinned in `tests/package.test.ts`.
- `./<name>` → `src/components/<name>/index.ts` per HeroUI component dir (`./surface`, `./card` in Plan 1, field primitives in Plan 2 wave 1, `./progress-bar` / `./progress-circle` / `./meter` in Task 19; target: all 86). `tests/package.test.ts` enforces the mapping both ways (export → dir, and each `src/components/<dir>/` → `./<dir>` export + `index.ts` line) and that every subpath value export reaches the barrel as the same binding (guards ambiguous `export *` drops).
- `./theme` → `src/theme/index.ts`: framework-free theme derivation (port of HeroUI's theme builder algorithm) — `deriveTheme(params)` (accent lightness / chroma / hue + gray chroma `base` → authored tokens, light + dark), `themeVariables(params, mode)` (every variable for an inline `style`: radius + tokens + derived formulas; `motion: { overlays: "spring" | "<visualDuration> <bounce>" }` adds the cdk motion token `--rv-motion-spring`, `OVERLAY_SPRING` = `0.3 0.2`, also in `themeCss`), `themeCss(params)` (copy-paste snippet), `derivedFormulas`, presets (`THEME_PRESETS`, `RIVET_PRESET`, `CLASSIC_PRESET` (id `classic`, label "Classic": the upstream default accent; was `HEROUI_PRESET` until 2026-10-12, DEBRAND), look presets `BRUTALIST_PRESET` / `GLASS_PRESET` / `MAUVE_PRESET` (2026-10-12: whole-look swaps through `overrides` incl. shape tokens `--border-width` / `--field-border-width` / `--surface-shadow` / `--overlay-shadow` / `--field-shadow` / `--surface-backdrop`; Rivet contrast fixes re-tinted per hue (`contrastFixes`); audited in `tests/theme.test.ts`, Glass also composited on the background), `matchPreset`, `resolveParams`, `RIVET_BRAND`), OKLCH / OKLab / sRGB math + CSS `color-mix(in oklab)` (`color.ts`, matches Chromium), WCAG + APCA audit (`auditContrast`, `auditVariables`, `CONTRAST_PAIRS` (31: text 4.5:1 + Lc 60 on every surface level / field / soft fills, focus / accent / chart series 3:1 + Lc 30; `CHART_PALETTE` per mode = chart.css), `apcaContrast` (APCA-W3 0.1.9 Lc, `color.ts`); identity T6 2026-10-12). `RIVET_PRESET.overrides` may also override a derived formula (dark soft foregrounds): `themeVariables` applies tokens after `derivedFormulas`. rivet.css adds tinted shadows (light) + 8 % white hairline `--surface-shadow` / `--overlay-shadow` (dark) from `scripts/gen-themes.ts`. Not a component: exempt in `tests/package.test.ts`.
- `./styles` → `styles/index.css` (`style` condition, **Rivet theme**): tokens, base, utilities, variants, `out/theme.css` (theme variables in use); NO component rules (since the CSS split, identity T4 2026-10-12). `./styles/*` → raw files under `styles/` (`styles/themes/scoped.css` = the Rivet theme under `[data-ui-theme="rivet"]`, for a Rivet-themed island on a page with other variables: docs home, ui-docs stage; portaled overlays keep the scope through `src/utils/portal-theme.ts` (cdk `portalHooks.place` stamps the trigger subtree's `data-ui-theme` / `data-ui-preset` / `data-theme` / `.dark` on the moved `[data-rivet-portal]` host, UI-THEME-PORTAL 2026-10-20); `styles/themes/presets.css` = every `THEME_PRESETS` entry under `[data-ui-preset="<id>"]` (light + dark, shape tokens reset per block: a swap is one attribute change; ui-docs `theme-swap` example, ~171 KB raw / 7.5 KB gzip, opt-in); `styles/out/base.css` = `index.css` compiled, `styles/out/all.css` = base + every component: plain-CSS entries for apps without Tailwind / a bundler).
- Per-component CSS: each `styles/src/components/<name>/<name>.styles.ts` (the tv file every component module imports) imports `../../../out/<name>.css` — the CSS graph is the JS import graph, a page pays for the components it imports (4 crumbs < 600 B that never render without their parent live in its file: `FOLDS` in `scripts/build-css.ts`, TW-151); the router merges a route's sheets into one (`libs/router/build/route-css.ts`). `out/` is generated + committed: `node libs/ui/scripts/build-css.ts` (`--check`; `tests/styles-split.test.ts` fails when stale). All files share layer `components`: cross-file overrides win by specificity as in the old single bundle; equal-specificity ties between files are banned by `styles-split.test.ts` (fix: `:where()` exclusion in the earlier file, TW-117 / TW-120, or the later file's tv module imports the earlier stylesheet first, TW-121; a slot class rendered on another component's root, e.g. `<CloseButton class="modal__close-trigger">`, is listed in the test's `COMPOSED` so its ties with the root's file are checked too).

- `./scheduler` → typed data-driven `Scheduler` on the CDK scheduler; `schedulerVariants` + `SchedulerProps<T>` / `SchedulerClassNames` / CDK type helpers. `variant` default / secondary, `density` compact / default / comfortable (auto month lanes 3 / 4 / 5), functional tv slots including portals, localized Button/ButtonGroup/Segment toolbar; `toolbar=false` hides only the default header. Story `/scheduler`, focused server/live/style and production-browser suites. Lane start-resize consumes the logical preview shift; generated-style contracts and real production LTR/RTL month/week pointer tests pin the opposite end, commit and restore Escape. Test traces/screenshots use `.artifacts/ui-components/scheduler`.

## Known diffs

- `dom.*` `render`: the render function gets `DOMRenderedProps` (`Record<string, any>`; upstream `JSX.IntrinsicElements[E]`) so `<section {...props} />` needs no cast (element-typed handlers do not unify across tags); second argument is `undefined` (as upstream). Dev check wording = upstream ("Ref was not connected to DOM element returned by custom `render` function…"); it only runs for a `ref()` signal (callback refs cannot be probed) and only in the browser.
- Resumed pages: a `ref` inside a spread (`dom.*` props, a `render` spread) is not recorded by the server, so it stays empty on a resumed page (runtime gap; parts that need their element on resume use a plain element with an explicit `ref`, `scroll-shadow`).
- `composeTwRenderProps(string, string)` returns a string (upstream: a function); same classes.
- Generic roots: upstream `props: XRootProps<E> & Omit<JSX.IntrinsicElements[E], keyof XRootProps<E>>`; here `XRootProps<E> & JSX.IntrinsicElements[E]` (intersection, no `Omit`): an `Omit` of the generic indexed type is TS2590 (union too complex) at JSX sites passing a function-valued attribute (seen with `ref`, `onClick`) over Rivet's intrinsic map. Type-only (overlapping `class` / `children` narrow to ours); signature stays generic, `<XRoot<"span">>` works.
- `dom` (exported from the root barrel, as upstream) is the namespace of the tags HeroUI uses (+ `section`), not a Proxy over every tag: upstream `dom.<anyTag>` works, here `dom.<otherTag>` (e.g. `dom.article`, `dom.a`) is a type error and `undefined`.
- Hooks that were React hooks are plain functions (`useCSSVariable`, `src/hooks/`, not in the barrel until Task 24); `useIsHydrated` / `useMounted` / `useIsSSR` are not ported (no hydration pass).
- Root exports not ported yet: the hooks (`useIsHydrated`, `useListData`, `useMeasuredHeight`, `useMounted`, `useOverlayState`, `useSafeLayoutEffect`, `useIsomorphicLayoutEffect`, `useMediaQuery`, `useTheme`; Plan 2 infra lane, `useIsHydrated` / `useMounted` per the translation table), the `rac` re-exports (Plan 2 infra lane) and the 84 other component dirs (Plan 2 lanes).
- `description` / `error-message`: upstream `useHasTextSlot` / `FieldSlotsGate` (gates the part inside TagGroup / Select / ComboBox / Autocomplete until the collection root's visible pass provides the `TextContext` slots; outside a gate always rendered) is not ported: cdk `Text` returns `null` itself in a collection build pass (`isHiddenPart`), so the part is always renderable and the visible DOM is the same (one part, linked ids: `tests/field-slots-gate.test.tsx` with a cdk `TagGroup`); no `FieldSlotsGate` export.
- Field primitives (`separator`, `header`, `label`, `description`, `error-message`, `field-error`) are not generic over the element (as upstream: RAC wrappers); prop types are the cdk part props (+ variants). `FieldError` children / `class` functions receive cdk render props as accessors (`({ isInvalid }) => isInvalid()`), not snapshots.
- `card`: `SurfaceContext` is always provided; for `transparent` its `variant` getter returns the outer surface's (upstream provides none) — readers see the same value, and a live `variant` switching to / from `transparent` keeps the nodes. Context values (`card`, `surface`, `chip`) have getter fields over the live props (readers see data; resume encodes the values read).
- `progress-bar` / `progress-circle` / `meter`: context `{ color, size, state }` instead of `{ slots, state }`; `state` = the cdk render props, accessors (`state.percentage()`), not React snapshot values (a custom part reading the context calls them). Root props are the cdk `ProgressBarProps` / `MeterProps` (value props also accept accessors, a cdk superset). `Output`'s default text (`children ?? state.valueText`) only when no children are given (Rivet children are slots). SVG stroke attributes are written with their SVG names (`stroke-width`, `stroke-dasharray`, `stroke-dashoffset`, `stroke-linecap`; React renames camelCase, Rivet does not): same DOM attributes; `dom.circle` types them (`SVGStrokeAttrs`). Fill `style` is the Rivet style object (`width: 60%`, serialized as `width: 60%;`).
- Attribute order on the element differs from React DOM output (`data-slot` before `class`): same attributes.
- `spinner`: upstream's inline gradient `<svg>` (two hand-authored arc paths + `linearGradient`s) → lucide `LoaderCircle` via `@rivetjs/kit/icon` (icon rule). Visual diff: stroked arc without the gradient fade; same `data-slot="spinner-icon"`, `viewBox`, spin animation (CSS on `.spinner`). `lucide` is a peer dependency of `@rivetjs/ui` now (optional peer of kit).
- `kbd`: `kbd.constants.ts` (⌘ ⇧ ⌃ ⌥ …) is verbatim upstream text, not icons (icon rule does not apply: they are the key labels users read). Context value `{ variant: null }` marks "inside a Kbd without variant".

A literal string / number is wrapped in `*Label` as upstream; `{expr}` children resolve inside a child accessor (`src/utils/with-label.tsx`) and a string / number result is wrapped, anything else renders as is. An `Image` outside a `Root` renders with a status of its own (upstream throws). Upstream `Avatar` reads `AvatarGroupContext` only on cloned (`AVATAR_GROUP_CHILD: true`) children; Rivet: every Avatar under an `AvatarGroup` reads it unless `{ [AVATAR_GROUP_CHILD]: false }` (no clone).

## Gotchas

- Server field slot probe (cdk `probeSlots`, `@rivetjs/cdk/slot-probe`): a field runs its children once more on the server before its input renders, so field children must stay pure. Label / Input / TextArea / FieldError / InputGroup.Input return `null`, Description returns the bare cdk `Text` (slot + id), InputGroup returns its children while `slotProbing` is on (no class composition: the probe stays cheap). Browser builds resolve `slotProbing` to the constant `false`: the checks fold away (app bundles 0 B; the size report / zero-cost `[dom]` lines keep cdk external, so they show the import + check, ~+70 B per part).
- cdk overlays (Popover / Dropdown / Tooltip / Modal / Select / DatePicker …) render a `display: contents` `span[data-rv-overlay-anchor]` next to their trigger (the overlay's resume region); React portals render nothing in place. Vendored CSS that counts siblings (`:first-child` / `:last-child` / `+`) breaks when a trigger sits in a group → patch to `:nth-child(1 of .x)` / `~` (done: button-group, avatar-group; TWEAKS.md). Audited 2026-10-08: every built ui-docs + cdk-docs example, anchor present vs removed, computed styles of siblings — no other difference. Author CSS (Tailwind `first:` / `last:` / `space-x-*` / `divide-*`) in apps has the same hazard.
- `nx run ui:test` = `node scripts/vitest-seq.ts`: `ui` then `ui-components` (story app build once per run + Chromium), both `--maxWorkers=2`; both run even when `ui` fails (status 1 if either fails). CI: 3 shards (`nx run ui:test --shard=i/3`, files balanced by measured seconds in `scripts/ci/test-weights.json`; `visual` + `a11y` are the heavy ones).
- Live props (P1/P2 landed): `<Card variant={variant()}>` / `<Button variant>` / `<Chip color>` / `<Surface variant>` update classes + context readers in place on client-created trees (`tests/live-props.test.tsx`). Resumed pages: the first change still re-creates the component region (spec P3 resume recipes not landed: `tests-components/card.test.ts` `test.fails` "first change keeps the server-rendered root"); every later change updates in place (card / wave1 / resume suites assert node identity). Every wave-1 component reads props live (`tests/live-props-wave1.test.tsx`; exceptions in the Translation rules row). Context values reach re-created child regions (`tests-components/resume.test.ts`).
- Resume chunks follow `.ts` barrels of source packages (`barrelLeaves`, `libs/compiler/vite.ts`): `import { dom } from "@rivetjs/ui"` resumes `dom.*` symbols (story app route imports it that way).
- Former runtime bug: a `_spread` update re-ran the `children` slot when another key changed (`dom.*` children re-created) — fixed in runtime commit "fix(runtime): spread re-inserts children only when `children` changes"; `tests/dom.test.tsx` + `tests-components/resume.test.ts` assert node identity.
- Story app: component modules outside `src/routes` imported by a route resume via rivetRouter's `resume.appModules` (default true); no `resume.modules` list (`tests-components/app/vite.config.ts`).
- Conditional element children: before TERNARY-MEMO (compiler `cond_v2` + runtime `_cond`) a JSX ternary / `&&` child re-ran on ANY read inside its test and re-created its element — a CSS enter animation replayed on every unrelated change (input-otp slot value per keystroke, stepper check per step change; fixed 2026-10-08 with `<Show>`, kept). Now the compiler memoizes the condition: a branch is rebuilt only when the rendered branch changes; a read inside the JSX operand's own expressions binds in its own effects. `<Show when>` stays the explicit form (resume branch slots, function children). Regression: `tests-components/reanimate.test.ts`.
- Rivet JSX builds nodes eagerly (React JSX = descriptions): an element hoisted into a `const` before a `<Provider>` renders outside it. Hoist a function (`const content = () => <…/>`) and call it inside the provider (`card.tsx` root). DOM target only (server `Provider` always calls a children thunk): SSR tests pass with the bug, so every provider-wrapping part needs a DOM test.

- Resumable functions handed to cdk parts (live accessors / class functions): a cdk handler or binding that closes over them serializes them on resume (live-props P3: server props are getters, so the live paths run on the server too). Only compiler-registered functions serialize: inline arrows in a `.tsx` component body (a `const` initializer holding a function is registered with its captures; a const arrow used as a value too: `button.tsx` `isDisabled`; an inline arrow passed as a call argument), functions returned from a `.tsx` helper (`accessorIfLive`), not closures built in a `.ts` module or from an unregistered argument (the removed `cdkClass(live, () => …)`: "Cannot resume …: capture #n function is not serializable"). Class pattern: `const classOf = () => …; const cls = live ? (values) => renderClass(classOf(), values) : classOf();`. Context getter objects: a `const` initializer, also inside a conditional (`live ? { get x() {…} } : {…}`: `button-group.tsx`; registered since live-props-p4).
