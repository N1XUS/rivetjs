## Rules

- Zero-cost: every subpath independently tree-shakeable. `scripts/zero-cost/packages-hashes.mjs` gates every `@rivetjs/motion*` entry (`[dom]` / `[server]` lines; `motion` stays external there, so the hashes cover own code) and `dev-leaks.mjs` scans them; upstream bytes are tracked by the size-report docs-example apps `example:motion-{basics,gestures,presence,layout,scroll}` (`scripts/size-report.mjs` `EXAMPLES`). Package: `node scripts/package/build.ts libs/motion` (`.jsx` for `.tsx`, `.d.ts`, LICENSE + NOTICE, `peerDependencies.motion` kept); `scripts/package/smoke.ts` has `motion` in `PACKAGES` + `PEERS`.
- Rulings 2026-10-11 (spec §9): entrance = CSS, no JS, LCP-valid; no `drag` in v1; overlay springs opt-in via a motion token.
- CSS-only call sites compile away (MOTION-CSS, user ruling 2026-10-27 "0 JS for a CSS entrance"): in derived builds `@rivetjs/compiler` (`static-motion.ts`) rewrites a `<Motion.<tag>>` written in place with constant `initial` / `animate` / `transition` / `reducedMotion` and no other Motion prop, at a call site the call-site proof shows no `MotionConfig` / variant parent / kit transition scope above, into the plain `<tag style={…} data-mve="…">` + an import of its rule (`rivet-motion-entrance:<hash>.css`, route CSS). Before: a resumed boundary enclosing it ran the Motion element inline (element + tags + kit transition ≈ 33.9 KB raw / 11.7 KB br before input). Keep `staticMotion` equal to `motionElement`'s server path (`tests/static.server.test.ts`) when either changes; dev keeps the component.
- Entrance form: `@keyframes` + `animation … backwards` (the inline final state beats `@starting-style`; no forwards fill, which would override later inline values from JS animations / gestures). Head sink (server): one `Head.styles` entry per hash per page (`@rivetjs/router` component head, nonce). Sink closed (streamed boundary after the shell) or absent: `data-mvv` + inline `--rv-mve-*` for `entrance.css` (two-frame opacity / translate / scale / rotate only; other entrances render the final state + dev warning). Client render: one constructable sheet (`adoptedStyleSheets`, CSP-neutral; light DOM only).
- Read once (documented exception to live props): `as`, `initial` (the entrance is the mount), which gesture groups exist, `whileInView` presence. Live: `animate`, `variants`, `custom`, `transition`, `style`, `reducedMotion`, callbacks, every forwarded attribute.
- No `initial` (or `initial={false}`) = no entrance: the element renders `animate` (Motion SSR semantics).
- Live `animate`: binding `data-mv-t` (never written); runs `animateTo` only when the element is connected and in the browser, so creation / server runs record nothing. Inline style = user `style` + the element's motion state (`motionState`, untracked), so a live `style` change re-applies current motion values, never stale ones.
- `reducedActive` keeps one `MediaQueryList` (re-made when `matchMedia` is replaced); `finished` is lazy (built on read or for `onComplete`).
- `engine.animateTo` / `setNow` first `takeOver` a CSS entrance (commit running values inline, drop `data-mve` / `data-mvv`), then seed unknown keys from inline / computed style, so a resumed page animates from what the server rendered.
- Reduced motion = Motion's semantics: transform / layout properties jump, opacity / colors still animate; `"user"` under `prefers-reduced-motion`, `"always"` regardless, `"never"` off (CSS and JS paths).
- Springs (D4b, fix round 1 2026-10-12): Motion's `spring` value only (`{ type: spring }`), entrances included (its `applyToOptions` → CSS `linear()`; the ported spring math is gone); string `"spring"` throws in entrances (`SPRING` message names the import), dev error in `animateTo` (prod: set final values).
- Gestures (T6): handler groups (hover: `whileHover` / `onHoverStart` / `onHoverEnd`; press: `whilePress` / `onPress*`; focus: `whileFocus`, also bound with press for blur) are bound only when present at creation (read once), so a Motion element without gestures binds no handler: hovering it loads nothing on a resumed page. One handler `on = (e) => gesture(e, layers)` over the element's own props (`motionElement` local). Hover ignores `pointerType: "touch"`; press = primary button (window `pointerup` / `pointercancel` while held) or Enter / Space on the element itself (no automatic `tabindex`: make it focusable); `whileFocus` only when the element itself matches `:focus-visible`. Gesture state lives in a per-element WeakMap (transient: nothing to resume). Bytes: `Motion.div` 8,138 → 9,244 B br (+1.1 KB, target 0.6 KB — over; trim pass in T15).
- Variants (T7): a child without its own `animate` / `initial` follows the parent's variant _labels_ (own or inherited; plain targets do not propagate, as Motion); `inherit={false}` opts out. Scope = `VariantContext` provided only by elements with labels; children read it in the body. Orchestration = `delayChildren` (seconds or `stagger(…)`) + `staggerChildren` of the parent's merged transition for its current target.
  - CSS entrances: one rule for all children: `animation-delay: calc(var(--rv-mvi,0)*<each>ms + <start>ms)`, the child carries `--rv-mvi: <creation index>`; `delayChildren: stagger(…)` is probed as linear (`fn(0)`, `fn(1)`), so `from: "last" / "center"` / eased staggers are approximated on entrances (documented limitation). Custom-property form: the delay is baked per child.
  - Live re-targets (parent label change): children's bindings queue per parent scope (`enqueue`) and start in one microtask sorted by document position (DOM order, also after a reorder) with `childDelay(i, n)`.
