# @rivetjs/runtime

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Target runtimes the compiler emits calls into: server rendering (string / writer / streaming), client DOM (one ABI: templates, delegated events, `_insert` value slots), resumability (server boundary recorder → `rivet/boundaries` tail → inline loader → `dom-derived` adopt runs), JSX types, dev façades. Deps: `@rivetjs/reactivity`; `@rivetjs/compiler` is an optional peer (testing register only).

## Rules / invariants

- **Zero cost**: production bundle of every subpath is hash-pinned in `scripts/zero-cost/runtime.txt` (`runtime-hashes.mjs`: rolldown, minified, `production` condition; unbracketed = the files as written (non-resume builds), `[derived]` = a resume build (the adopt run switches `DERIVED` + `LAZY_ROWS` on), `[dom-data]` = `resume.domData: true`). Any byte change in a shipped file changes a hash → intended deltas only, `sh scripts/zero-cost/check.sh --update`. Dev-only code lives behind `#dev` / `development` condition files; `DEV` must stay a `false` constant in production.
- **Pay-per-use modules**: Suspense (`dom-suspense.ts`, `server-suspense.ts`), `resource` (`dom-resource.ts`, `server-resource.ts`; nothing at import), spreads (`server-spread.ts`, `dom-v2-spread.ts`), the derived recorder (`server-derived.ts`, `_setDerived`) install themselves on import; `sideEffects: false` drops them when unused. Don't add top-level side effects elsewhere; don't add exports to entry files for tooling (entry bundles keep all exports).
- **Compiler ABI** (`package.json` `"rivet": { "abi": N }`): the compiler-emitted helper contract this runtime implements; `@rivetjs/compiler` `RUNTIME_ABI` (`libs/compiler/abi.ts`) must equal it and its Vite plugin fails builds/dev start on a mismatch. Bump both together on any semantic change of a compiler-called helper, marker/template/resume format (test: `libs/compiler/tests/abi.test.ts`). ABI 3 (2026-10-08): `_cond`; ABI 4 (2026-10-09): `_tx` (sole text child on a template placeholder Text); ABI 5 (2026-10-09, IMPL-SPREAD): `_attrs`, `_spread` 5th argument `exclude`. ABI 6 (2026-10-09, IMPL-RESUME): `_rRowPlan` + `For` `$rows` (server resume row plans), router `_linkHref` (compile-time bare server `<Link>`). ABI 7 (2026-10-09, IMPL-SPREAD F3): `_pm`. ABI 8 (2026-10-09, Function Bridge T2, plan `docs/design/plans/2026-10-09-function-bridge.md`): `_rMod`; later bridge tasks add thunk captures, `_rCell`, `_rBound`, `_rGroup`, `_rStorePaths`, `_rClass` under the same number. ABI 9 (2026-10-21, DERIVED-S): `_rFor`. ABI 10 (2026-10-23, STATIC-ZERO T3): `_rHandler` / `_rHandlers`.
- **Untampered built-ins required**: ordinary intrinsics are assumed (`_list` compares `Array.prototype.map`, records are never thenable); no polyfill tolerance.
- **No component runs in the browser on load** (`__componentRuns` stays unset in Playwright tests before the first interaction); a boundary runs once, over its server nodes (adopt run), when its first event / wake / trigger arrives — or renders in the browser when its markup differs.
- `ref` inside `{...spread}` is applied like an explicit `ref={…}` attribute (`_spread` binds it once, on the first run, under the spread's owner so a `ref()` resets only on unmount; never written as an attribute). `ref` binds on the spread's FIRST run only (a thunk that gains or changes `ref` later is ignored, as explicit `ref=` is once). Pairing an explicit `ref=` (after the spread) with a spread that also carries `ref`: one bind (compiler `ref: undefined`, live-props-p4). Test `tests/spread-ref.test.ts`. The compiler appends `ref: undefined` to the spread object when an explicit `ref` follows the last spread (patch `live-props-p4`: explicit wins, one bind); an explicit `ref` BEFORE a spread still binds next to the spread's. Tests `tests/resume-p4-browser.test.ts` gap 3.

- **Resume compiled output byte-identical** for non-resume modules; ssr-bench pages compile unchanged (hash gate `lanes.txt`).
