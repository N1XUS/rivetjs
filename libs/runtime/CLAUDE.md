# @rivetjs/runtime

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Target runtimes the compiler emits calls into: server rendering (string / writer / streaming), client DOM (one ABI: templates, delegated events, `_insert` value slots), resumability (server recorder → state table → inline loader → client resume runtime), JSX types, dev façades. Deps: `@rivetjs/reactivity`; `@rivetjs/compiler` is an optional peer (testing register only).

## Rules / invariants

- **Zero cost**: production bundle of every subpath is hash-pinned in `scripts/zero-cost/runtime.txt` (`runtime-hashes.mjs`: rolldown, minified, `production` condition). Any byte change in a shipped file changes a hash → intended deltas only, `sh scripts/zero-cost/check.sh --update`. Dev-only code lives behind `#dev` / `development` condition files; `DEV` must stay a `false` constant in production.
- **Pay-per-use modules**: Suspense (`dom-suspense.ts`, `server-suspense.ts`), spreads (`server-spread.ts`, `dom-v2-spread.ts`), the derived recorder (`server-derived.ts`, `_setDerived`) install themselves on import; `sideEffects: false` drops them when unused. Don't add top-level side effects elsewhere; don't add exports to entry files for tooling (entry bundles keep all exports).
- **Compiler ABI** (`package.json` `"rivet": { "abi": N }`): the compiler-emitted helper contract this runtime implements; `@rivetjs/compiler` `RUNTIME_ABI` (`libs/compiler/abi.ts`) must equal it and its Vite plugin fails builds/dev start on a mismatch. Bump both together on any semantic change of a compiler-called helper, marker/template/resume format (test: `libs/compiler/tests/abi.test.ts`). ABI 3 (2026-10-08): `_cond`; ABI 4 (2026-10-09): `_tx` (sole text child on a template placeholder Text); ABI 5 (2026-10-09, IMPL-SPREAD): `_attrs`, `_spread` 5th argument `exclude`. - **Untampered built-ins required**: ordinary intrinsics are assumed (`_list` compares `Array.prototype.map`, records are never thenable); no polyfill tolerance.
- **No component runs in the browser on a resumed page** (`__componentRuns` stays unset in Playwright tests); a region is re-created, never resumed.
- Cold events replay in dispatch order (one promise chain; a hot event waits while cold ones are pending) — `resume-cold-order.test.ts` holds the keydown chunk behind the input chunk. ## Gotchas / open bugs

- `on*Capture` handlers resume through the runtime (`_rOn(type, id, captures, { capture: 1 })` — explicit attributes and spread `onXCapture` → entry key `type!`, loader dispatches capture entries outermost-first). Delegated capture handlers see `eventPhase` 1 like every delegated handler.
- `_rOn(…, flags, present)`: `present === false` records nothing; the compiler passes `!!c` for `onX={c ? f : undefined}` / `c && f` when `c` is an identifier / member chain / `!x` (anything else still records).
- Deploy skew (Function Bridge C2, 2026-10-09): symbol ids are content hashes (compiler `resume.rs` `content_digest`), so an id present in a chunk is the same closure. `dom-resume.ts` `symbol()`: a loaded chunk without the export (registry table entry, `__rivet(id)`, or the export by name → not a function) never runs another function — it calls the loader's `fail` (`document.$r.f`) with `Error & { skew: id }` (cancelable `rivet:resume-error`, then the guarded reload) and throws it; `report` skips errors carrying `skew` when the loader is present (no second event / console error). 0 loader bytes. Corpus `skew-renumbered` / `skew-changed` (`tests/function-bridge-corpus-browser.test.ts`).
- Late captures (Function Bridge T5, 2026-10-11, `server-resume.ts` `capturesOf`): `_rFn(id, fn, captures | () => captures)` — a thunk is called once, at the recipe's first encode, and replaced by its result in `FnMeta.captures`; every encode-side `fns` meta read goes through `capturesOf`. Render-time records (spread `onX` handlers, `_rChild` / spread `children` `_rBind` sites) store `siteCaptures(meta, recorder)`: the array, or a `() => capturesOf(meta)` thunk + `recorder.late`; `encodeRecords` runs `settleLate(recorder)` first (texts / regions / element handlers / bindings → arrays), `sameCaptures` never packs a row holding one. Streamed segments: `viewOf` gives each view an own `late: false`; Suspense `prepare` carries the flag with the records it moves out of the shell; a segment settles at its render's end inside the segment's `fail` path (a throwing thunk → that segment fails / continues in the browser, the stream goes on; ErrorBoundary fallback views likewise). Thunk-free pages: no thunk, no settle pass. Thunk errors → `TypeError("Cannot resume <id>: captures <message | String(thrown)>", { cause })`. `_rProps` / `_rMod` / forward metas keep plain arrays. `resolveContent` reads the `_rSpread` recorder from module-level `contentRecorder`, restored after `resolveSpreadContent` (no render's recorder retained). Test `tests/bridge-late.test.ts` (incl. a Suspense nested in a Suspense segment: late captures encode in the inner segment).
- Recipe consts by value (Q5, Function Bridge T18, 2026-10-12, `server-resume.ts` `special`): a non-function `_rFn` value (not `MODULE`, live, `fw` or getter object) encodes by `plain(value)` when everything in it encodes (functions = References) — the browser does not re-run its initializer — else `{f: id, a: captures}`; a recipe id whose `plain` failed once is in `recipeOnly` (process-wide, one failed attempt per id). `_rGroup` adds its id to `recipeOnly` (members encode `{i: [members, k]}`: the array by value would contain them). Replaces the old signals-only rule (`holdsSignal`, removed). Tests `tests/bridge-recipe-value.test.ts`; corpus `recipe-side-effect` passes.
- Capture error messages (Q6, Function Bridge T19, 2026-10-12, `server-resume.ts` `captureError`, used by `refsOf` / row `refs` / `packRun`): dev `Cannot resume <id>: capture `<name>` <error>` from `ResumeManifest.captures` (dev manifests only: the compiler dev server; user-facing names, `o.a` for a member-narrowed capture — T19 fix 1), `#<i>` without names; prod `Cannot resume <id>: <error>` (no index). Tests `tests/bridge-names.test.ts`.
- Streamed boundary lifetime (SEGMENT-SUSPENSE 2026-10-11 + fixes 1–2): a streaming `Async` (`server-async.ts`) and a claimed `Suspense` (`server-suspense.ts`, its root owner) call reactivity `_detach` on their root right after `stream.defer` / `claim.defer` returns (a throwing Async fallback leaves the root attached to its parent; a throwing Suspense fallback disposes the root before rethrowing — `renderResumable` has no owner around the page): the render holding them (shell or segment) disposes its scoped records at its end — an awaited `Async` (e.g. the content of an outer Suspense's segment), a `Provider` — and that disposal used to cascade into the streamed root (`AbortError` from `live`, the segment always continued in the browser, status 2). The stream alone disposes it (`release` → `settle`, after its segment and every nested one are out; `abandon` at the end). - Awaited Async content (2026-10-08, overlay leak): `server-async.ts` `Async` asks `_onAsyncContent` (installed by `server-resume.ts`) at construction for an `enter` wrapper and renders `children` / `error` through it (non-streamed only); the wrapper sets `recorder.region` to a `held` logical scope (`id: null`, `async: true`) under the constructing read's region, so the content's records (bindings, regions, effects, refs) encode with that region as parent — the Router's route content is a child of the Router region, and the browser's re-creation of it disposes the page (cdk overlay portal + `inert` + scroll lock no longer leak on non-live revalidation / client navigation / back). `held` acts as the page root elsewhere: `_onForRow` (no row markers), `rowOf` / planner `keyOf` stop at it, `_onClientOnly` mounts nothing on it, `_onAsync` / `_onSuspense` never claim it (`async`) — HTML unchanged. `/server` 0 B (hook folded away without server-resume), `/server-resume` +24 B min.
