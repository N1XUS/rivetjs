# @rivetjs/runtime — resume area

> **Keep this file current:** ALWAYS update this file in the same change whenever the resume code changes (ABI, tail format, loader, pipeline, gotchas).

Server renders; the browser runs nothing on load and runs a boundary (an interactive component) once, over its server nodes, when it is first needed. Files: `server-derived.ts` (boundary recorder + tail), `server-resume.ts` (façade), `resume-format.ts` (values codec + tail types), `resume-loader-derived.ts` → `build-loader.ts` → generated `resume-loader-derived.min.ts` (inline loader), `dom-derived.ts` (client runtime, subpath `dom-derived-runtime`; compiled modules import the ABI from `dom-derived-abi.ts` = subpath `dom-derived`, ZERO ABI-SPLIT), `dom-adopt.ts` / `dom-adopt-run.ts` (adopt run), `derived.ts` / `lazy-rows.ts` (build-time switches), `dom-data-derived.ts` + `server-derived-dom.ts` (DOM data, `resume.domData`). User docs: `apps/docs/content/learn/resuming.md`; spec `docs/design/specs/2026-10-18-structural-resume-design.md`.

## Pipeline (derived model: M2 lane R 2026-10-20; the only model since M6-CUT 2026-10-22)

- Server: `derivedToString` / `renderDerived` (`server-derived.ts`) = the derived render + manifest / nonce → `<script type="rivet/boundaries" data-rt [data-events] [data-boot] [data-g] [data-fo]>{v, b, w?, m?, k?}</script>`; `data-fo` (DERIVED-C) = runtime + `m` chunk URLs + their static closures (manifest `deps`)<script nonce>DERIVED_LOADER</script>`. `m` = boundary name → chunk URL (`manifest.symbols[name]`), `k` = id → keydown keys held while cold (`_rB` `keys`: the compiler passes none, so compiled pages ship no `k`; widgets list their keys in `data-rk`). Record flags add `LOAD` 32 / `IDLE` 64 / `VISIBLE` 128 (triggers; any → `data-boot`).
- Loader (`resume-loader-derived.ts`, 1,636 B br since COLD-CTXMENU (`data-cm` hold); 1,631 since SLIDER-KEY (`data-rk` hold); 1,583 since ZERO ONDEMAND (fetch-ahead timing, intent list, hover dwell; 1,344 after STATESPACE `data-nc`); 1,160 after DERIVED-C (fetch-ahead + cold press); 1,043 after M2-R5 `data-g`; was 1,023 ≤ 1,024): no table, no `find`. Fetch-ahead: per `data-fw` (absent = first idle period after `load`, `load`, `intent` = none; none under Save-Data / 2G), one low-priority `modulepreload` per `data-fo` URL; on the first intent the whole list at high priority (fetched, never evaluated: the first click evaluates modules already in the map — `/resume` 1000 rows: 0 scripts on the click instead of 8). An event of a `data-events` type (default `click input change submit keydown pointerdown pointerup pointercancel mousedown mouseup focusin focusout`) inside a boundary → `rt.on(event)` (true = everything around the target materialised now, the event runs natively) else held (click defaults / submit / invalid / a `contextmenu` inside the nearest `data-cm` (the browser's own menu canceled; cdk MenuTrigger `trigger="contextMenu"`) / keys of the target's nearest `data-rk` — a text field without its own stops the lookup — or of `k`) as `[event, composedPath(), replay, [value, checked, activeElement]]` → `rt.cold` (or `api.q` before boot). Intent (pointerdown / focusin / touchstart / keydown inside a boundary, or a mouse / pen pointer resting 80 ms) boots and `rt.w(target)` loads the chunk; held hover events boot on `idle` / `load` pages; on `intent` pages they never boot and are pruned once the pointer left. Not in the loader (budget): the sessionStorage-less reload fallback, `files` in the snapshot, `mousewheel` passive.
- Runtime (`dom-derived.ts`, default export): unit = one boundary (or one lazy row). Adopt run = `dom-adopt.ts` probe / align / adopt (as `_adoptRow`) over the unit's server range, with holes: child `_b` (claims the child's range or `data-b` element; record name must match), `<For>` (claims `n` row groups, rows lazy). Text / comment runs pair positionally when equal in length (comment data ignored: content markers line up with template `<!>` markers), else are replaced by probe copies (the unmarked fragment / empty-sole-text cases land here). Element mismatch → client render of the unit (dev: `DEV.adopt` warns once per boundary name with the first difference).
- Materialisation order: dependent children with their parent; independent children on their own event / trigger / wake; wake sources (record `w`) before their readers; a For row on an event inside it, on a write to a keyed signal its rows read outside a row writer (two detached sample rows: first + last), or through the client `_for` (first change of the items; `_adoption.rows` hands it the lazy rows). DERIVED-C: a list adopts O(1) (keep token; a sole list is not scanned until needed); a keyed signal read only through hoisted `_fx1` writers whose captures every row supplies reruns those writers over the lazy rows (no row runs).
- Async replacement (CX-ASYNC2): awaited and streamed holes share `lazyNodes` with lazy For ranges. The enclosing slot takes its snapshot on the first replacement read, including a segment that arrived after adoption; insertion unwraps the memoized snapshot once to a plain array before reconciliation removes nodes, avoiding repeated Proxy reads (CX-LAZYSNAP). The keep token remains a live range. Regression: `tests/derived-async-replace-browser.test.ts`.
- First list reconciliation (CX-VFOCUS): row adoption can add boundary anchors around retained server elements. The slot snapshots the live row range when reconciliation first reads it, including when a helper returns the For beside an insertion anchor. Snapshotting during alignment omitted those anchors and made reconciliation detach retained focused elements. Once captured, the snapshot stays fixed during DOM mutations; subsequent updates use `_for`'s existing live-range tracking. Regression: `tests/derived-rows-focus-browser.test.ts`.
- Measured (`tests/derived-adopt-browser.test.ts`, Chromium, `rt.m(1)` = adopt the page root incl. Header): 10 rows 2.7 ms, 1000 rows 4.8 ms (eager rows: 11.8 ms); no row function runs. DERIVED-C (ssr-bench `/resume`, `spikes/derived/probe.ts`): numbers in `docs/benchmarks/2026-10-21-derived-c.md`.
- Router (M2-R5, 2026-10-20): the page root is the router's generated `Root` (independent, props = route payload). A standalone boundary's component may export `ready(props)`: called once before its standalone adopt run (and on intent), awaited (`Rec.ready`). Document click listeners: server `_rListen(selector)` → tail `g: [[id, selector]]` + loader `data-g`: an event outside every boundary whose target is inside a match is held for that boundary; `listeners(event)` materialises it before `around`, then the replay reaches its document `clientEvent` (router link interception).
- Adopt cost (M2-R5, DERIVED-C): delegated controls of a unit = the form controls among its alignment's live elements (`controlsOf`; was `controlsIn`, a querySelectorAll over the whole range); `opener` incremental; a probe run pairs with a longer server run by kind (no node moves); a list whose first materialised row's unit met no hole and no keyed state adopts later rows through `_adoptRow` with one shared `RowPlanCache` (`Lazy.plain`). A child `_b` whose hole the probe discarded (reached no probe node: a cdk collection build pass renders items for their context registration only, M2-R5) runs inline in a re-probe and the adopt run (`Unit.inline` by `_b` index; nested `_b` inside run inline too), else the registration was skipped, the list probed empty and the unit fell back to a browser render (`/links` breadcrumbs). DERIVED-C: build passes (`_rUnrecorded`) run outside every unit (`_setUnrecorded`: `cur = null`), so a cached `computed` first read in a probe builds the real collection.
- Cold press + hover (DERIVED-C): cold-press replay (`queued` / `replay` / `record` / `late` / `hide` in `dom-derived.ts`: focus-back, UNDO-FOCUS walk, COLD-FOCUS hide, up / click retarget, listeners a replay attaches); the first mouse / pen event after an adopt dispatches `pointerenter` / `mouseenter` along its path. UNKEYED records adopt (non-data signals start from the browser init).
- Gaps: a held event whose target left with a client-rendered unit is dropped; one chunk import per boundary name (route chunks: same URL, one module).

## Gotchas / open bugs

- Not yet on the derived model (plan M6, lane M6-PARITY): framework islands beyond the lean boot, `Suspense` whose content waits for a load the server could not ship (a resource value the resume table cannot encode or without the router `Root`'s table decoder, a resource made outside a boundary, a streamed Suspense past the deadline: renders in the browser), per-component preload strategies / `ChunkGroup`.
- Injected markup: HTML inserted from user content (sanitizers such as DOMPurify keep `data-*` by default) must strip `data-b` / `data-rk` / `data-cm`, else an injected element can claim a boundary's id.
- Adding an import to `dom.ts` / `dom-derived.ts`: list it in `tests/resume/harness.ts` `sources` and `tests/dom.test.ts`, or browser suites 404.
