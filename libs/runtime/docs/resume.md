# @rivetjs/runtime — resume area

> **Keep this file current:** ALWAYS update this file in the same change whenever the resume code changes (ABI, state format, loader, pipeline, gotchas).

Server renders once; the browser never re-runs a component. Files: `server-resume.ts` (recorder), `resume-format.ts` (table + types), `resume-loader.ts` / `resume-stream.ts` (inline scripts) → `build-loader.ts` → generated `resume-loader.min.ts`, `dom-resume.ts` (client runtime). Full semantics table: `../../../docs/guides/resumability.md`.

## Pipeline

1. **Compiler** (`libs/compiler/rust/src/resume.rs`) rewrites resume-mode modules: every site (handler, text/attr/child binding, effect, client event, computed, R2 function) becomes a symbol `<module>#<Component>$<hash>` (content-stable: a hash of its own code + captures, twins `_<k>`) exported from the DOM chunk and a `_r*` call on the server.
2. **Recorder** (`server-resume.ts`): `renderResumable(factory, writer, { manifest, nonce, stream })` / `resumableToString`. One `Recorder` per render in `AsyncLocalStorage` (`store`); `_r*` without a recorder degrade to plain output. `_rOn` (`flags.capture` → key `type!`; `present === false` → nothing) / `_rAttr` / `_rModel` / `_rRef` record on the pending element, `_rId` closes it (`data-r="<n>"`); `_rBind` runs the read under `_trackReads` → plain value (no signals), text `<!--rN-->…<!--/-->`, or region `<!--rN[-->…<!--]-->` (structural / `region` flag / client-only mount / streamed Async). `_rFn` / `_rComputed` register symbol + captures on the function (`_rFn`: a private-field stamp, `Recipe`; non-extensible functions fall back to a WeakMap; first registration per render wins, so `props.fn ?? default` keeps the creation site's recipe; a function reused across renders re-registers); `_rEffect` / `_rClientEvent` record for the browser. `tailOf` appends the state script only when `recorder.used`. `_rUnrecorded(fn)` (`resume-format.ts`, installed by `server-resume` through `_setUnrecorded`) runs `fn` outside the recorder (`store.exit`): every `_r*` call inside degrades to plain output and records nothing — for passes that render content only to inspect and discard it (cdk collection build pass), so wrapper elements / conditionals inside it leave no dead region entries; browser / non-resumable renders: `fn()`. Live props (LIVE-PROPS P3, 2026-10-08): a component call with dynamic props passes `_rProps(id, { get x() {…} }, captures[, 1])` — the props object is encoded as its recipe `{f: id, a}` (symbol = the call's JSX attributes compiled for the browser through `_propsOf`; flag 1 = the server's lazy children slot is the last capture), never by value (unserializable captures → by value, cached per id in `unportable`); `@rivetjs/runtime/props` helpers report forwarded getters through `_onForward` (`fns` meta `fw`: key → sources), so `splitProps` / `mergeProps` / `_spreadProps` / `_restProps` outputs encode as `{k:"props", a: [key, value | {k:"m", a:[key, …sources]}, …]}`; member captures go through `_rMember(object, key)` (a getter of a live / forwarded object → forward box, read unread). Encoder `special` gets `refs(values)` (journaled; undefined on failure). Client: `dom-resume` decodes `k:"m"` → a forward box (`Symbol.for("rivet.forward")`), `k:"props"` → an object whose boxes are getters over the sources (last defined value wins; own copy, so the runtime chunk does not import `props.ts`); a forward source whose getter reads no signal (`_trackReads` at encode) is written as `{ [key]: value }` (`undefined` → source dropped; unencodable value → source kept), so a handler capturing a static forwarded prop does not reach — and preload — the parent's props recipe chunk (IMPL-EAGER 2026-10-09: starter-ui no longer loads ui ButtonRoot + tailwind-merge before interaction, `tests/resume-forward-const-browser.test.ts`); symbol prologues of member captures call `props.ts` `_members` (same rule). Result: the component's own bindings record the signals behind `props.x`, the enclosing region records nothing, and the first change updates server nodes in place (`tests/resume-live-props-browser.test.ts`, ui `card.test.ts`). Still re-created: components destructuring props (P4), projection captures (`globalDOMProps(props)` reads every getter), native attributes / text reading `props.x` without a call (no site).
3. **Encoding** (`encodeRecords` → `encodeState`): one interned table `t` shared by shell and every streamed patch (`t0` = first new index); `createEncoder({ special })` handles signals (`{s,q}`), refs (`{r}`), contexts (`{x}`), computeds/functions (`{c}`/`{f}` + `a` captures; `a` may be empty: a module reference `_rMod(() => value, id[, 1])` — Function Bridge T2 / T3; thunk resolved at the first encode (TDZ retried), only referable values: non-reactive functions, static plain data — encodes `{f: id, a: []}`, wire `{f: [sym]}`, wherever a render reaches the stamped function / object), custom kinds (`{k,a}`: router, const, `ctx` — a `resumableContext` token held as a value (Popover `clearContexts`): `{k:"ctx", a:[id]}`, the browser gets the registered token (`_placeholderContext`, SELECT-STATE 2026-10-12; was a plain `{defaultValue, id}` copy, so the popover cleared nothing after a resume), `store` — a store marked by `_rStorePaths` (Function Bridge T12) whose server reads were by path: `{k:"store", a:[root signal, nodes]}` (dev: `+ kept paths` → `DEV.resumeStore` warns on a read of an unshipped path), the root and node signals encoded with values pruned to the union of every mark's literal paths ∪ server-read paths (`prunedSignals` while the entry encodes; new containers, the data is never written), dom-resume rebuilds `{ ...nodes, v }`; unmarked / whole-read stores, and stores encoded while streamed segments are pending, stay plain objects; `cell` — a `_rCell` `let` cell: `{k:"cell", a:[value]}` at its first encode, interned; later server writes stay on the server, dev warns (Q2); decoder: a plain `{ v }` created before its value decodes, so a function in it may capture the cell; a cell reached while a function / computed / custom entry decodes gets `v` when the outermost one is done — any cycle through a cell decodes from any end; a cell whose value fails becomes an accessor that retries on read and throws until it decodes — failures stay with the cell's readers; a failed decode rolls back its whole frame — the entry and every entry first decoded inside it (`log` / `top`, out-of-line `undo`), queued cells of the failed entry dropped (and any queued cell rolled back meanwhile skipped by `drain`), dom-resume arms only decoder-queued signals the decoder still holds (the check sits in the `get` drain, not `arm`: identified context signals `{x}` are never decoder-held and always arm; the drain (`settle`) also runs after a row const and after a failed cell's accessor decodes — decoder hook `settle`) — so a retry rebuilds the subgraph and nothing memoized captures a discarded half-built object), refuses class instances / foreign functions / Promise / WeakMap with a type name (dev: value path via `DEV.at`). Uniform `For` rows → one `RowTemplate` + `CompactRows` (expanded by the loader; row consts refs ≤ -10 into `state.k`). `planPreload` picks per-chunk strategy (`eager > idle > visible > intent > interaction`, app rules from `manifest.preload` win) → `data-preload`, `state.x` (never on intent), `state.g` (sibling groups), `state.l` (lazy imports).
4. **State script**: `<script type="rivet/state" data-region="0" data-events="click keydown …" [data-boot] [data-stream] [data-preload]>{v,h,rt,c,s,l?,x?,g?,t,e,m,b,fx,ce,a?,w?}</script>` + `<script [nonce]>LOADER | LOADER_KEYS</script>` (+ `STREAM` when `a`; `<script [nonce]>ROWS</script>` before the state script when `w`, `EXPAND` when `rx` (compact row templates), `REPEAT` when `rr` (repeated entries, below)). Emitted as `compiledTemplate(TAILS[i], [head, nonce(, nonce)])`: the per-request state script is a plain `template([…])` (one string write), the loader / stream text lives in four hoisted frozen fragment sets (keys × stream) with `nonce` as an attribute slot, so byte writers encode the loader once per process. Markers likewise use hoisted `REGION` / `TEXT` fragments around an integer id slot (`writeInteger`), and `_rId` passes the id as a number; output bytes unchanged. Entry shapes: `resume-format.ts` (`HandlerEntry`, `BindingEntry` 13 positions — region `[11]` `_regionState` locals, `[12]` enclosing identified providers `[tokenId, valueRef, …]`, on the wire the table index of that array when shared (`shareProviders`) — `ModelEntry`, `EffectEntry`, `ClientEventEntry`, `AsyncEntry`, `PreloadEntry`). A region entry's chunk list (`[5]`) covers everything its activation decodes: captures, row items, branch values, locals, providers. Branches (`[8]`, or `[10]` after rows): server `_onBranch` gives every Show/Switch the site's read creates directly a slot (`Scope.shows`; `nest` > 0 while a branch renders in the site scope or `readChildren` calls function children — the browser creates those Shows in nested owners), adoptable ones go to `Scope.adopts` with their slot; `_rBind` nulls every key when the read touched a signal outside `Scope.inner` (Show conditions / contents, `For each` accessors via `_onForEach`). One adoptable branch → the single spec (pre-2026-10-08 bytes), ≥ 2 → array. Repeated sibling bindings (≥ 3 instances of one component's text / attribute bindings) travel as one `"+"` entry with a `PackedBindings` template (`[8]`; `g: 1` = each row in its own row region, shifted with its nodes), expanded by `dom-resume` before registering; entries name symbols by page index (wire symbols rule below).
5. **Loader** (`resume-loader.ts`, inline stub, budget below; scheduling, the `later` queue, idle evaluation and the lazy router's fetch-only `data-fo` hints (after `load`, the web fonts, the first paint entry and an idle slice) live in the loader module `resume-loader-module.ts`, `data-ld`; the cold chain in `dom-resume` `cold`): capture listeners for every `data-events` type + `pointerover`/`pointerout`/`focusin`/`touchstart`/`pointerdown`/`keydown`/`scroll`. Intent (60 ms dwell, focus, touch) → `modulepreload` runtime + handler chunks + `extra` (chunks of bindings the handler can update) + lazy imports (`later` queue, ≤2 in flight, `fetchpriority=low`, paused 150 ms after scroll, off on Save-Data/2G). `pointerdown`/`keydown` → evaluate. Event with loaded chunks → `rt.dispatch` synchronously; cold → `preventDefault` for `a[href]` click / `submit` (`requestSubmit(submitter)` replay, re-dispatch stopped at window capture) / a plain click whose activation target is a checkbox, radio, `<summary>` or a form's submit / image / reset control (C8: replayed as a copy of the user's click, `new event.constructor(type, event)` dispatched on the target — not `el.click()`, a virtual click to cdk focus-visible —, the loader skips that one click — `skip` consumed once, so the replayed toggle's `input` / `change` still dispatch), load, dispatch, replay (in a microtask, after `show` restored the live form state) unless prevented. Events a replayed handler dispatches synchronously (`focus()`, a link's synthetic click) run nested, like on a live page, not queued behind the remaining cold events. The state script is `document.currentScript.previousElementSibling` (U2: never a document query — an injected earlier `rivet/state` script would name the runtime URL the nonce'd loader imports); `data-r` values that are not digits are skipped (SEC1: `constructor` / `__proto__` are no table keys). Chunk failure → one cache-busted retry, `rivet:resume-error`, reload (≤1 per URL / 10 s). `data-boot` → runtime at idle. Exposes `document.$r` hooks for the stream add-on (`x`: the state script). Stream add-on: `$rA(id)` takes its patch / template by position (`currentScript` ← `script[data-patch]` ← `template[data-a=id]`), never by query (U2).
6. **Runtime** (`dom-resume.ts` `createResume({ contexts })`): `start(state, doc, api)` pairs markers at idle (char-code scan), registers bindings as stubs per signal ref; `arm` effect activates a binding on the first *change* of a dep (sync when chunk loaded). Text → `bindText` (upgrades in place to a `bindChild` range on the first non-primitive value); attribute → `bindAttribute`; `#` region → mark dead, dispose owners inside, re-create via symbol (`_region` hands slot i of the region's branches (`BranchesSpec`: one `{w, k, s?, v?}` or an array, `s` = direct Shows without a branch before it) to the i-th `_show` / `_switch` the read creates directly, rows to the first `For`, `_adoptState` feeds `_regionState` values, `[12]` providers re-provided through `resumableContext` tokens, refocus by id). Cold events replay in dispatch order: the loader chains every cold event (`chain`, `cold` count) and a hot event waits while cold ones are pending. `load` / `idle` `clientEvent` listeners queue in `eager` (attached at idle, or by the first `dispatch` before its handler, so a document / window event that handler dispatches is heard). A `ref()` element entry `{r, z}` names its region: `arm` registers an `onCleanup` under that region's owner resetting the signal (`untrack(s) === el`) when the region dies. `dispatch(event, el, id, type, replaying, entry?)` never throws (C7: drain / `show` / model sync failures report as `rivet:resume-error` with symbol `model:<id>`, so the cold chain is not poisoned) and runs the handler (`entry`: resolved by the loader at event time, so a spread takeover meanwhile cannot orphan a cold event) in `batch` under the root owner with `currentTarget = el`; model entries sync the signal then `bindModel`. `patch(delta)` merges streamed segments; `dead(region)` tells the stream add-on to drop a segment. Dev only: `dispose()`.

## Event delegation (loader)

- Listeners are document-level **capture** listeners; `passive` only for `touch*` / `wheel` / `mousewheel` / `scroll` (so mousedown / input / dragstart handlers can cancel).
- `find` walks `event.composedPath()`: capture entries (`type!`) of every ancestor outermost first, then **bubbling** handlers (or models) of that type innermost first; `rt.dispatch` runs them in that order with the entry resolved at event time and stops at `cancelBubble`. **Non-bubbling** events (`focus`, `blur`, `pointerenter`, `mouseleave`, `scroll`, `load`…) take the bubbling handler of `event.target` only (capture entries of ancestors still run).
- Intent lookup (`type === undefined`) stops at the nearest element with any handler.
- `pointerover` + `pointerdown` + `keydown` on one target share one lookup (`memo`).
- Cold `keydown` inside `[data-rk="ArrowDown Space …"]` (`LOADER_KEYS` variant only, picked when the recorder saw a `keydown` handler): listed keys are `preventDefault`ed while the chunk loads; keydown handlers that only appear in later streamed segments get no hold.
- Cold replay state: the loader snapshots the target's `[value, checked, files]` at dispatch and passes it as `dispatch(…, live)`; `dom-resume` `show` swaps it in while that event's handlers / flushed bindings run, then restores the live state in a microtask (unless changed meanwhile). Later events' defaults (typed text, toggles, a second file pick) never leak into an earlier replay, and stale re-applied bindings never overwrite them.
- Cold `invalid` (native validation stopping a submit) is not cancelled by the loader (byte budget): the native bubble may show once before a resumed `onInvalidCapture` handler runs (forms `onInvalid`).
- A handler installed by a spread (`@type` binding) is taken over by the spread binding on activation; during that event's dispatch it binds after it (`dom-resume.ts:230`). Bubbling order across a takeover (K3-rt-1): the loader's document capture walk still finds the element's delegated ancestors; `dispatch` defers such an ancestor's bubbling handler to a one-shot listener on the outermost taken-over element below it (`dom.ts` `_takeover` hook: `add` marks per element, `defer`; installed by a resumed `spreadAttributes`, so only apps with resumed spreads ship it), so it runs after the element's own listener and not at all once that stopped propagation (`tests/resume-takeover-order-browser.test.ts`).

Before: 2,329 B; lane STRUCT-PREFETCH +93 B: deps modules (`data-deps`; an urgent hint of a symbol chunk / the runtime imports `<chunk>.deps.js`, written by the compiler plugin, and hints its static import closure — zero bytes before intent, imports never warmed alone, only before the runtime started and not over HTTP/1.1 (`nextHopProtocol`)); lane PRELOAD-VISIBLE: background `P` entries (planner budget) also queued at idle −1 B; +4 B: `v` preloads wait for a non-zero visible area (`intersectionRatio`, not `isIntersecting`), so clipped visually-hidden controls do not prefetch at load; lane RESUME-ROWS-2 +17 B: `find` / visible preloads fall back to the rows add-on `$rw` for path-addressed row elements; lane REG +27 B: a replayed non-link click default is stopped in the loader's capture listener, so no listener sees it twice; lane CDK-LEFT +3 B: events dispatched from microtasks a replayed handler queued also run nested; lane MATRIX +18 B: events dispatched by a replayed handler run nested, a scheduled preload of the runtime URL also starts it (MATRIX-rt-1); gap round G-APP: Z1 lazy router +24 B, cold label hold rt-1 +2 B; round-2 lane SEC raised the budget from 2,048 B: state-script binding U2 + digit ids SEC1 +5 B, cold click-default hold C8 +85 B; earlier: shipped 2,042 B, 2026-10-06 H3: cold-event chain + `live` snapshot `[value, checked, files]` (RESUME-PINS: + focused element) +17 B, `expand` slice-and-patch; a cold-`invalid` `preventDefault` measured +27 B → over budget, not shipped), `LOADER_KEYS` − `LOADER` in (0, 96] B (48 B), `STREAM` ≤ 1,024 B (712 B; RESUME-STATE-DIET +3 B: the patch as `$rx`'s third argument); must equal `build-loader.ts` output (stale → test fails; run `node libs/runtime/build-loader.ts`); must not contain `</script` or `<!--`.
- Every byte ships inline per page: prefer reusing an existing local over a new helper, short property names on state (`c s l x g t e m b fx ce a k`), no `class`, no async/await, esbuild `es2020`. `RIVET_KEYS` define cuts the cold-key branch for pages without keydown handlers (`build-loader.ts` finds the `else if(…=="keydown"){…}` branch textually: keep that shape).
- Type annotations are free (Function#toString of type-stripped source, normalized by esbuild).

## Rules

- Region = creation, not resumption: everything resumed inside is disposed first; row regions of a keyed list belong to the enclosing region (`For` adopts them). A component among a user component's lazy children is its own region (nested `_rBind` reads are isolated by `_trackReads`, so the enclosing component's read records no signals and stays plain): `<List><For each={items}/></List>` re-creates the `For` alone.
- Markers: end markers carry no id; nesting pairs them. HTML minifiers / proxies that strip comments break resume (`drift` hint).
- Marker ids: a start marker whose id continues the stride of the two start markers written before it (text or region, in write order) is written without it — `<!--r-->` / `<!--r[-->` (badge page: HTML br −25%). Writer side (`server.ts` `markOut`, per render): slot 0 of a compiled record over the `template.ts` `_markFragments` arrays (`TEXT` / `REGION` chain, `BOUNDARY` keeps its id for the stream add-on, the `MARK_RESET` record writes nothing); a reset forgets the stride (the next two ids are written) after a streamed boundary (its fallback is replaced before the browser reads markers), after a non-empty raw `template()` fragment (cached HTML may carry markers of its own) and at `_rReset()` (compiler, end of `<textarea>` / `<title>` / `<noscript>` / `<template>` / … content: markers there are no comment nodes); a failed ErrorBoundary and a raw slab attempt that wrote nothing restore it. Reader side (`dom-resume.ts` `markers()`, walks the whole document incl. `<head>`): id-less start = previous start + its step; `patch` keeps the ids a scan read for the rescan (a re-created region removed the starts they continued). Tests: `tests/resume-marks.test.ts`, `tests/resume-marks-browser.test.ts`.
- Table repeats (wire only): `server-resume.ts` `compactTable` writes a `c` / `f` / `k` entry (shapes `{f|c, a, q?}`, `{k, a}`) that equals an earlier full entry of the same symbol / kind (the first or the latest, from the chunk's `t0`) with its references past that entry moved by the distance as `{y: base}`; `resume-format.ts` `repeated` rebuilds it in the decoder. Repeated component instances' props recipes (`{f, a: [signal, own value]}`) become a constant. The server keeps the full table (preload planning, packing); only `state.t` / patch `t` carry `{y}`. Tests: `tests/resume-repeat.test.ts`.
- Relocated entries (wire only, RESUME-STATE-DIET 2026-10-19): collections (a cdk Table's rows and cells, `.map` list items) record the same handlers, bindings, recipes and props objects per element, differing only in captures that sit at other table indexes — most not "past the base" (`{y}`) but in two or three ranges (shared page values, the row's own signals, the cell's captures). A **relocation** (`resume-format` `Relocation`) maps them: `floor, delta` pairs, floors ascending, a ref takes the delta of the last floor ≤ it, refs below the first floor stay. Three wire forms, each against the latest entry of the same shape in the segment (so row k repeats row k − 1 with small, regular maps):
  - Table `{R: [back, floor − index, delta, …]}` (`compactTable`, `EntryRecord.R`): a plain recipe (compact `c` / `f` / `k` list past the head + numeric `q` relocated; same symbol / kind, arity, `v`) or an `o` / `{w, o}` object (same key list; value refs relocated) — written when not longer than its compact / shaped form; floors are relative to the entry's own index, so a row's forms repeat byte for byte (brotli). Never a `{y}` base nor a `w` shape base (both read their base's wire entry in full). The repeat add-on rewrites each `{R}` in place, in index order (its base, earlier in the segment, is already rewritten; a `{y}` base is resolved first), into the base's wire form — the table decoder never sees `R`, so `resume-format` / `dom-resume` carry no relocation code (a lazy decoder variant measured +747 B min / ~+230 B br on every resumed page's runtime).
  - Handlers `e[id] = [back, floor, delta, …]` (`RepeatedHandlers`): the handler map of element `id − back` (same types in order, symbols, chunk lists), capture refs relocated. Plain bindings (7 slots: no region data) `[-1 − back, node Δ, region Δ (when ≠ node Δ: odd length), floor, delta, …]` (`RepeatedBinding`, recognized by [0] < −1): the binding `back` entries earlier, node / region moved, refs [3] + signals [4] relocated. Server `repeatEntries` (after `wireSymbols`; shape key = types / symbols / ref counts / chunk lists; estimated bytes, no stringify) writes them only when, with the table's `{R}` savings (`tableSavedBytes`), the segment saves more than the repeat add-on (`REPEAT.length`, 0 once the page shipped it: `Recorder.repeatAddon`, `Stream.addon`) — else `compactTable` runs again without `{R}`; flag `rr`. The add-on (`resume-repeat.ts`, before the state script / the first patch that needs it) decodes them in `$rx` before any reader: loader parse (`$rx(state, state.b)`) and the stream add-on's merge (`$rx(s, x.b, x)`: the patch's handlers, already merged into `s.e`, are replaced in both). Readers of a raw state (tools, tests) use `handlersOf(e, id)`.
  - Measured (ui-docs `table-virtualization`, 1000-row cdk Table, 145k table entries): state 5,192,867 → 3,203,153 B raw (−38%), 456,961 → 183,418 B brotli (−60%); `t` 3.45 → 2.90 MB (br 312.6 → 137.6 KB), `e` 1.27 MB → 78 KB (br 74.6 → 11.0 KB), `b` 469 → 219 KB (br 67.7 → 30.5 KB); page brotli 484,662 → 210,645 B; loader `parse()` (JSON.parse + `$rx`, Node) 28–33 → ~31 ms (JSON.parse ~19 ms on the smaller text + `$rx` ~12 ms rewriting 51,830 `{R}` entries; the lazy decoder variant was ~20 ms); whole-table decode unchanged (~35 ms). A shared table of chunk lists (handler [2] / [3], binding [5]) was measured and dropped: with the repeats it saves < 1% raw and costs brotli (`[0,1,2]` repeated compresses better than an index). Tests: `tests/resume-repeat-entries.test.ts`.
- Bound functions + function groups (Function Bridge T9 + fix 1, 2026-10-12; compiler emission C8 / C9: T10, `libs/compiler/rust/src/resume/groups.rs` + `.bind` rewrite): `_rBound(fn, self, args)` returns `fn.bind(self, ...args)` and, while recording, encodes `{k:"bind", a:[fn, self, ...args]}` (dom-resume custom `bind` binds again; bound-of-bound nests). A function with its own `bind`, or a `bind` returning a primitive, is left unrecorded. `_rGroup(id, members, captures)` registers one instance of a group symbol (mutually recursive locals): the members array is one plain recipe `{f: id, a: captures}` (its factory returns the array; compacted and `{y}`-repeated like any recipe) and each member function encodes as `{i: [group ref, k]}` (the decoder's array-element entry: `parent[k]`, a missing member throws "Invalid resume table entry"). One factory call per instance, identity per instance (two instances never share members), rollback for free (a rolled-back frame deletes the group entry like any recipe). Reach walkers (`reachEntry`, `reachStack`, `reachesNone`, `reachableSymbols`) follow an `i` entry to its parent, so a handler capturing a member needs the group symbol's chunk. Both kinds are installed by the first `_rBound` / `_rGroup` call (`fnSpecial` chain): `special` makes one optional call otherwise. Limit: a bound `this` / argument reaching the bound function back (`o.h = f.bind(o)`) is a capture cycle — decoding throws "Cyclic reference" unless a `let` cell breaks it, as for any function entry. Tests `tests/bridge-shapes.test.ts`, `tests/bridge-bind-browser.test.ts`.
- Recipe consts by value (Function Bridge T18, Q5): a non-function `_rFn` value encodes by `plain` when it can (its initializer does not run again in the browser), else its recipe. It is a snapshot at its first encode (the shell flush, or the first segment that references it): later mutations and the late captures (T5 thunks) of functions inside it are read then, not at a later segment's end. A symbol id whose value failed `plain` once stays recipe-only for the process (`recipeOnly`, also every `_rGroup` id). The browser gets data, not a re-run: a factory that registered something client-side by running there no longer does.
- Data class instances (Function Bridge T23 + fix 1): `_rClass(Cls, id)` registers a class (compiler C12 / T24 emits it at module load for every module-scope data class of a resume module; class-field arrows `_rFn(id, arrow, [this])`); an instance of a registered class is `{cls: <class symbol>, a: [own enumerable string-keyed fields]}`. The browser restores it without running the constructor, in the on-demand `resume-builtins` chunk (pages without classes ship no class decoder; the class comes from the `fn` hook): `Object.create(Cls.prototype)` is memoized first, then the fields are defined as own data properties — two-phase like `{k:"cell"}`, so a class-field arrow capturing `this` decodes in either order. Refused (error names the class): an unregistered subclass of a registered class, a class extending a built-in (Map, Date, Error, EventTarget, …), an own `__proto__` field. Own state that does not resume as it is — symbol keys, non-enumerable fields, accessors, read-only fields, frozen / sealed instances — fails in dev; production drops symbol / non-enumerable keys and restores accessors / read-only fields as plain writable data. True `#private` fields are not restorable (D-priv).
- Resource holders (Function Bridge T25): an instance with `[serialize]()` (beats the data fields) of a class with `static [revive]`, or of a class registered with `registerClass(cls, { id, serialize?, revive })` (package classes: no class symbol, `cls` is the registered id — a string without `#`), is `{cls, a: [data], rv: 1}`. The browser decodes the data first (instances in it complete), then memoizes `Cls[revive](data)` / the registered `revive(data)`, on first decode; a cycle through its data throws. `[serialize]` without a reviver is `RV2102: <Class> has [serialize] but no static [revive]` at encode. The registry (`Symbol.for("rivet.classes")`) must be filled on both sides: the module calling `registerClass` is imported by the server code and the resume entry.
- Encode cost (IMPL-ENCODE 2026-10-09, output byte-identical): reach walks are a recursive walk memoised per table entry (`reachEntry`; a cycle through plain data taints the walk and the root is walked again by the one-stack `reachStack`; chunk lists cached per reach); `compactTable` compares precomputed per-entry ref arrays (`repeats` stays monomorphic: entry-shape polymorphism deopt-looped it in Maglev); `stateJSON` stringifies the table in 256-entry slices (one `JSON.stringify` over ~600+ mixed-shape entries measured 3× slower than slices); encoder `special` gets one `plain(value)` per encoder (no closure per object). ui showcases in-process resume SSR 1.09–1.15× faster (dashboard 2.38 → 2.11 ms median). Test `tests/resume-reach.test.ts`.
- Wire symbols / shapes (IMPL-STATE-SIZE 2026-10-09, wire only; the server table keeps ids): `encodeRecords` → `wireSymbols` gives each segment's new symbols the next page indexes, grouped by module (`symbolList`), and every handler / binding / effect / clientEvent entry (row templates, packed bindings) and table `f` / `c` names its symbol by index. `s` = `[chunk, id, …]`: a number sets the chunk of the ids after it; an id is `module#Local`, `#Local` (same module as the previous id) or `$a$b…` (one id per `$suffix`, each = the previous id's module + component: ids are grouped by module, then component); patches append (stream add-on). Spread binding names (`...names`) and region provider token ids ([12]) are table string refs (numbers). `compactTable` also writes `{f | c | k: [symbol | kind, ...refs], q?}` (decoder `full`) and `{w: base, o | p: values}` for an object whose key list equals an earlier `o` / `p` entry's in the segment. Client: `dom-resume` `named` / `symbol` decode `s` lazily (index → id + chunk), `unpack` reads table names back, providers read token strings. ui showcases (dashboard / mail / chat / settings): state 57.2 / 62.5 / 29.9 / 67.5 → 30.9 / 35.2 / 17.3 / 38.2 KB (1.73–1.85×), gzip −8 to −12%.
- Table refs: `-1` hole, `-2` row item, `-3` row index (template), ≤ -10 row consts (`state.k`), else table index. Patches stay index-aligned (`t0`).
- Signals revive on first use; comparator `q` armed after the decoder's initial write; `q: false` = always notify.
- Captured computeds (`{c}`): the entry lists the `resumableContext` providers (non-default values) that enclosed the creation as its last capture, flag `v: 1` (`[token id, value, …]`, outermost first, one shared list entry per context frame; values that do not encode are left out); `dom-resume` creates the computed under an owner providing them (one per list, under the root), so `useContext` while it evaluates — a cdk collection build pass running item bodies — reads the server's values (RESUME-CTX 2026-10-09; before: the resume root's defaults). Not for recipe consts (`{f}`: same captures, and their provider values would join the state, +3–7% on ui showcases) nor bindings / handlers / clientEffects (they run under their region owner / the root: a context read inside the expression itself sees the default — read it in the body).
- Contexts: only `createContext(d, { id })` values pass. Unregistered token → `{x}` reference supplied by `createResume({ contexts })` (client-side values such as the router); `resumableContext`-registered token → the value is encoded structurally (must be serializable), so no client table is needed. Signal values provided as identified contexts arm bindings.
- Framework islands (bridge ABI): `_rPreload(url, strategy, ids?)` plans an island chunk like a symbol of that chunk (manifest-known URLs only; dev warns on unknown); `when("visible")` on an inline `display: contents` island root observes its element descendants through nested contents wrappers (≤ 48; none: idle). `_markup(html)` (`./server-markup`) writes the framework's HTML verbatim.
- `renderResumable` without `stream` = same contract as `renderToWriter`; `resumableToString` never streams.

## Row functions (LAZY-ROWS ABI, compiler T2 2026-10-19; runtime T4 pending)

- Spec `docs/design/specs/2026-10-19-lazy-collection-rows-design.md` §3.3. Compiler emits, server resume target, per lazy-eligible keyed `For` (verdict `libs/compiler/rust/src/resume/rows.rs`): `children: _rFn(rowId, row, caps)` (row function registered like any Slot / Fn site; browser symbol `kind: "slot"` for a JSX row, `"fn"` otherwise, compiled by `_compileSymbolModule`) and compiler-private prop `"$lazy": [flags]` / `[flags, "key.path"]`.
- `flags`: 1 = row reads its index parameter; 2 = `by` is a function with a recipe (`by: _rFn(byId, by, caps)`).
- `key` (present iff `by` is a key-path arrow): `by(item)` = item value at the dotted path, `""` = item itself; server keying still calls the authored `by`.
- Ineligible Fors: no `$lazy`, no row `_rFn`, unchanged bytes. `$rows` (R-PLAN) may sit next to `$lazy`.
- Runtime today: `For` ignores `$lazy`; `_rFn` on `children` only registers the row function (rows render eagerly + stay recorded). T4: server `R` record reads `$lazy` and stops recording row entries; browser renders rows from the row symbol. T5 hook: adopt-mode DOM lowering of the row symbol in `_compileSymbolModule` (not started).

## Gotchas / open bugs

- Explicit `onXCapture={…}` attributes compile to `_rOn(…, { capture: 1 })` (entry key `type!`), like spread `onXCapture`; the old "Capture-phase handlers are not resumable" diagnostic is gone (wave 2).
- `_rOn` `present` arg: the compiler passes `!!c` for `onX={c ? f : undefined}` / `c && f` when `c` is an identifier / member chain / `!x`; other tests still record a handler (chunk prefetch for nothing).
- Cyclic `{s}`/`{c}`/`{f}` entries throw at decode (plain object/array cycles are fine); dev encode throws first (`assertAcyclic`).
- Region re-creation runs under the resume root: only providers of `resumableContext`-registered tokens are re-provided (entry `[12]`); other `Provider`s are lost. A token no loaded client module registered yet is provided through a placeholder (`_placeholderContext`) that the later `resumableContext(token)` call adopts and returns — register tokens as `export const T = resumableContext(createContext(…, { id }))`, never keep the raw token.
- Kept reading rows (RESUME-KEEP-ROWS 2026-10-12): a row whose own render read signals (row flag 2 / compact `w`: no site inside the row binds them) used to be re-created on the region's first run. The server now lists those signals per region at entry `[13]` (`RowReads`, deduplicated over the site's rows; `[12]` padded with `null`, unencodable → omitted); dom-resume `unchanged` checks each still holds its server value (a never-decoded signal was never written) and passes `_region` a `changed` check. `takeRows` marks such rows -3 (kept; rows that also read their index stay -2); the For's effect reads `changed()` and on its first true turns every -3 row into -2, so the pass re-creates exactly those rows. First items change after resume: the reading rows stay (fixture 1,000 rows: list update 8.9 → 4.5 ms, frame 18.6 → 6.0 ms). Rows reading the list signal itself (cdk masonry via `entries()`) still re-create on an items change.
- Spread element → one all-attribute binding + resume state (captures: member reads / `globalDOMProps(props)` projections); DOM v2 lowers it through `_spread`. Binding name tokens: ` #c` (the object itself read signals: the client replaces the content on the first run), ` #r` (a symbol function `children` rendered as its own `_rBind` site: the client never writes the content from the spread), ` @type` per spread handler, ` =<class>` (the rendered string class, spaces as newlines: the client's first run leaves an equal class untouched, so classes client code added since stay; other keys still compare against a sentinel and are rewritten with the same value).
- Module-level / imported functions used by name in a component (prop, local const, object / array / call argument) resume by reference (`_rMod`, Function Bridge T2 / T3); "function is not serializable" stays for functions no resume module uses by name (reached only through other values: module-level objects, hooks, library results — build those with `reconstruct(() => …)`).
- Shell handler dependency prefetch ignores bindings streamed later.
- Resumed `onClick` may run before a capture `useInteractOutside` listener (order).
- Injected markup: server output never repeats a `data-r` id; HTML inserted from user content (sanitizers such as DOMPurify keep `data-*` by default) must strip `data-r` / `data-rk`, else an injected element with a real id receives that id's handlers (with server captures) and possibly its bindings. The element Map keeps the first element per id in document order (dev: `DEV.resumeDuplicate` warns once per id).
- Path-addressed rows (RESUME-ROWS-2): planned `For` rows whose template `server-resume-paths.ts` `rowPaths` accepts, whose content slots held primitives and whose list drops ≥ 768 ids (`pathMin`; the rows add-on is ~700 B br) carry no `data-r`. Element k of the row with id N has id N + 1 + k. State `w: [[first row id, stride, rows, ["tag:i.j", …], anchor?]]` (patches append, `resume-stream` merges `w`): row k's id = first + k × stride; its root is the element right before its end marker `<!--]-->` in row regions (the start marker may move: `<p>` auto-close, `<tbody>` fostering), or — anchor 1, rows outside row regions whose first id element is the root — the root keeping `data-r` = row + 1; `i.j` = element child indexes below the root, the tag checked (mismatch → no element; the binding falls back as for a missing id). Rejected templates (implied end tags, nested `a` / `button` / `form`, table parts outside a `tr` root, raw text / RCDATA elements, `select`, SVG beyond plain shapes, `/>` on HTML elements, several roots) keep their ids. Readers: loader `find` → `d.$rw(node)` (climbs to the row root, rebuilds the chain), visible preloads → `d.$rw(id, observer)` at idle; the rows add-on (`resume-rows.ts`, `ROWS`, inline before the state script, or before the first streamed `<template>` whose patch has `w`) scans the markers itself until the runtime starts, then asks `ResumeInstance.q`; `dom-resume` `build()` adds the `w` elements to the element map, `pathIds` maps them back (cold key retarget). Bytes (brotli): resume-bench document 13,024 → 9,854 B; ssr-bench `/resume` 1000 rows 29,160 → 28,269 B.
- Element lookups: one lazy `[data-r]` Map per activation burst (reset with `comments` on `patch()`), `querySelector` fallback for disconnected / unknown ids. Resumed attribute / spread bindings' first run keeps live form state while the value equals the server `default*` (`_keepLive`, installed by `start`, pay-per-use in `dom.ts`).
- Dev only: `resume.region` events + re-creation `console.info` (component, cause: first change of signal #n, ErrorBoundary reset, mount trigger, late patch, continuation, speculative idle), drift hints for missing markers, chunk-failure warnings (`DEV.resumeChunks`); 0 prod bytes.
- Preload planner (`server-resume.ts` `planPreload`): automatic `visible` only for list rows (≥ `LIST` = 3 rows of one `For` list per symbol — region rows via their row scope, region-less rows via `ElementRecord.list` tagged in `_onForRow`) or non-intent events, and only for chunks ≤ `VISIBLE_MAX` (8,192 B minified own size); `INTENT` includes `pointerdown` / `mousedown` / `touchstart` / `focus` / `focusin` / `invalid`. N instances of one component (9 calendars, 3 date segments × pickers) stay intent (`tests/server-resume.test.ts` "preload plan: …"). Rules / element directives still override.
