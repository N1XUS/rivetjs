# @rivetjs/bridge-vue

Keep this file current with API and layout changes. Vue 3.5 islands (framework bridge design §3, plan T10).

- `server.ts`: async `createSSRApp` + `vue/server-renderer.renderToString`. Fresh app per island, public `app.config.idPrefix = ctx.id`; async setup resolves to completion. Captures synchronous/async errors even when Vue handles them, then rejects for the bridge fallback. Teleports to `head` become kit-compatible head entries via `@rivetjs/bridge/head`; other teleport targets reject (a teleport cannot escape the island DOM boundary).
- `client.ts`: `createSSRApp().mount` hydrates; `createApp().mount` mounts; one `shallowReactive` snapshot per app. Updates delete absent keys and assign the full new snapshot, preserving local component state. Public Suspense readiness keeps synchronous apps synchronous and awaits actual async initialization (including mounted effects); initialization rejection and native-head cursor validation failure unmount the app exactly once before rethrowing (sync and async paths). Unmount uses `app.unmount`. Hydration warnings report RV2149 through public `warnHandler` in Vue development builds; production Vue repairs mismatches without a public recovery callback.
- `options.ts`: `VueAdapterOptions.setup(app)` customises every app before SSR/mount. Install a fresh Pinia/i18n instance per call when isolation is required. Both `/server` and `/client` export `createAdapter({ setup })` for programmatic integration.
- `slot.ts`: native Vue slot functions, names unchanged (including kebab-case). Static `<rivet-slot [name] style="display:contents" innerHTML="">` holes match the core protocol exactly. Vue never reconciles the Rivet-owned children. Mount/update hooks adopt the original Node objects; no HTML parse/copy. Adapters never import each other.
- `vite.ts`: `vue({ include, exclude, plugin, setup, islands })`. `.vue` files owned by default. Optional `@vitejs/plugin-vue` peer is composed unless `plugin: false` (app must supply it then). Scoped CSS uses its standard Vite CSS pipeline. `setup` is a module specifier exporting the default setup(app) function; relative paths resolve against the Vite app root. Two virtual adapter modules import it symmetrically; no process-wide setup singleton. Dedupes Vue runtime modules.
- `types.ts`: import once to augment Rivet's foreign component registry. Vue constructors/defineComponent/SFC public `$props` map to island options; functional VNode components are accepted, Rivet components retain their types. Vue's JSX global namespace stays disabled.
- Peers: Vue `>=3.5.0 <4`, optional plugin-vue `>=6 <7` (Vite 8 line). Exact dev pins Vue/server-renderer 3.5.43 and plugin-vue 6.0.10. Server uses `vue/server-renderer` so the renderer always matches the Vue peer.
- Tests: `vitest run --project bridge-vue --project bridge-vue-browser --maxWorkers=1`; typecheck `node scripts/tsc.ts -p libs/bridge-vue`. SFC production build verifies setup, scoped CSS and static-island stylesheet collection, including a dynamically imported native async SFC child. The fixture uses `kit()` and the real router head sink, proving generated adapter definitions forward native head metadata automatically. Chromium checks CSS with JavaScript disabled, then holds all island JS, captures parser-created head nodes and verifies their identities after hydration plus independent live/static head contents. Browser suites cover original nodes, updates/deletions, local state, callbacks, slots, IDs, nested islands, disposal and every client policy. SSR head teleports use the shared native-head contract, retaining exact teleport target anchors and a server-only nonenumerable render callback. Client hydration uses `withNativeHead`; the root Suspense scope keeps async setup inside the owning head range until ready. Fresh mounts discard a stale failed SSR range through the shared helper. The shared helper owns the pinned/guarded Vue 3.5 private `_lpa` target cursor; all app/render/slot logic uses public Vue APIs. Native SSR `context.modules` is returned as `cssModules` so Vite `moduleCss` supplies scoped CSS for dynamically imported async SFC children without linking unrelated native views. Heavy Vite/browser runs coordinate with the root resource slot; Node 26.5.1, V8 2GB, process tree <=3GB, maxWorkers=1.
- Public Vue API references: https://vuejs.org/api/ssr.html and https://vuejs.org/api/application.html.

- Production SFC fixture minifies both client and SSR builds, including serialized native-head lifecycle code, and verifies scoped CSS without JavaScript plus parser-created head node identity through hydration.
