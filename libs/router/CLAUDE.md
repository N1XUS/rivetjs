# @rivetjs/router

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

File-based routing for Rivet apps: route scan + codegen (`.rivet/`), Vite plugin, web-standard request handler (guards, loaders, actions, endpoints, CSRF), resumable SSR, client router (data endpoint, persisted layouts, prefetch, transitions), deploy adapters (node / fetch / static / csr + platform targets vercel / netlify / cloudflare / bun / deno). Built on `@rivetjs/runtime/router` (pattern matching, `Router` region).

## Layout

Convention (decided): folder per subsystem, flat files inside; subpaths point at files (not `<name>/index.ts`). Keep it — many paths are referenced from outside (see Gotchas).

- `build/` — build-time Node code: route scan, codegen, Vite plugin, dev errors, route CSS, migrate codemod, `lazy-rows.ts` (env-only `RIVET_LAZY_ROWS=swap` measurement harness, never shipped; `lazyRowsBuild`: `resume.lazyRows` forced on / off for the lazy-rows tools' `on` / `off` builds) → [build/CLAUDE.md](build/CLAUDE.md)
- `server/` — request handler, CSRF/body limit, server-export normalization, page render, app assembly → [server/CLAUDE.md](server/CLAUDE.md)
- `client/` — browser router, layouts, navigation API, params/search, leave guards, transitions → [client/CLAUDE.md](client/CLAUDE.md)
- `adapters/` — node / fetch / static / csr, platform targets (vercel / netlify / cloudflare / bun / deno: runtimes + `target-build.ts` + `pack.ts`), build loading → [adapters/CLAUDE.md](adapters/CLAUDE.md)
- `shared/` — code both sides import: wire contract, head, errors, redirects, base path, CSP → [shared/CLAUDE.md](shared/CLAUDE.md)
- `cli/rivet.ts` — CLI over `build/sync.ts` + `build/migrate.ts` (migrate imported lazily)
- `index.ts` — public route-module API + all route typing machinery (`PageProps`, `DataOf` serializability check). `Leaf`/`Serializable` mirror the resume encoder (`runtime/resume-format.ts`): primitives (no symbol), Date, URL, URLSearchParams, RegExp, Map, Set, typed arrays / ArrayBuffer / DataView, Error family, arrays, plain objects; rejects functions, symbols, classes with methods. Change both together: `tests/data-of-samples.ts` pins each sample's type verdict, `tests/data-of.test.ts` compares it with the encoder (known gaps: methodless class instances and Error subclasses type-check, encoder throws).
- `tests/` — vitest project `router` (`tests/*.test.ts` only). Fixtures `tests/fixture*/` = small Vite apps; their `.rivet/` is generated (gitignored, excluded in `tsconfig.json`).
  - `fixture` (app/server/static/devtools e2e; also used by `libs/devtools/tests`), `fixture-base` (base path), `-csr`, `-depends` (`invalidate(key)`), `-dev`, `-fetch`, `-groups` (nested path-less groups `(site)/careers/(jobs)/<slug>`, static mode + transitions), `-inline` (server-code canary), `-nav`, `-nav-api`, `-nested` (layouts), `-live-nested` (live page under a nested layout level: `live-nested.test.ts` search-only navigations in place), `-prefetch` (static mode, `prefetch: "document"`, every link kind incl. an unknown `/legacy/`), `-documents` (node, document links: dynamic page, shadowed endpoint `items/export.ts`, `api/ping.ts`, `public/legacy.html`, unknown path; document routes `report.tsx` (`*.server.ts`) / `secret.tsx` (declared `virtual:fixture-secret` behind a helper); `broken.tsx` throws in the browser), `-reach` (`server-reach.test.ts`: RV3011 component chains, `reach: "warn"`, layout reach, marker page, stand-in Proxy, build reject / warn build, dev overlay + terminal once), `-deploy` (deploy targets: `about.tsx` `prerender = true`, `public/robots.txt`; built with inline configs by `deploy.test.ts`), `-slash` (`trailingSlash: "always"`), `-static`, `-transitions`.
  - `[browser]` e2e tests (Playwright Chromium + Vite build): app, base, `document-links` (unmatched paths / endpoints load documents, no data request; page routes navigate; document routes `report` / `secret` ship no page code; a throwing client render and back to a document route load the document), depends, dev-errors, dev-resume, groups (dev + static-build client navigation across route groups), inline, nav-api, navigation, nested, `prefetch` (Speculation Rules + fallback incl. cacheability probe per `cache-control`, hash CSP; Chromium never activates prerenders under CDP: `PrerenderingDisabledByDevTools`), static, trailing-slash, transitions. Unit: routes, codegen, `live` (live pages: scan flag, codegen wiring, `_serveLive` in place / concurrency; e2e in `libs/forms/tests/drawer.test.ts` + `live-nested`), server, security, actions, node, `encoding` (node adapter content encodings: `negotiate` zstd / br / gzip + opt-out, dynamic one-call / streamed / direct bodies as zstd, immutable files precompressed + written next to the file, mutable in memory, existing siblings served as they are, stale siblings (older than the source) ignored + overwritten, concurrent first requests compress once, `compress: { zstd: false } | { precompress: false } | false`, unwritable dir), `idle-memory` (controller on fake timers + adapter opt-out), `prefetch-unit` (selectors, rules, eagerness, shell wrapper, codegen/usage, hash CSP, `whenActivated`, min freshness), migrate, `sync` (`rivet sync` CLI + API), `endpoint-split` (client build: page importing a constant from a `.ts` endpoint drops its handlers + server imports), `hardening` (handler/render round-2 fixes), `node-hardening` (targets, Host, keep-alive drain, ranges, validators), `deploy` (platform layouts vs documented contracts + entries run with synthetic requests / Bun), `*-types` (checked by `tsc`).

## Rules / invariants

- Seeded locals: `app(request, { ...context, locals })` seeds `event.locals` per request (caller-only, shallow copy, route-cache bypass; recipe `apps/docs/content/recipes/render-with-data-from-another-server.md`); a config-level `AppConfig.locals(request)` hook is a possible follow-up, not built.
- Pay-per-use: features ship only when the app uses them (`routerUsage` detects `useSearchParams`, `navigate`/`invalidate`, `useParams`, `<Link active>`, `prefetch="document|prerender"`; `transitions`, `announce`, kit head are options). A disabled feature must add zero bytes and leave generated output byte-identical. Wire fields (`deps`, `keep`, `byURL`, `head`) are omitted when empty.
- Resumability: `rivetRouter` sets `resume.appModules` (default true; `resume: { appModules: false }` opts out): every app `.tsx` module reachable from a route/the generated App compiles in resume mode, so `resume.modules` is only an extra seed (e.g. components never imported statically). Before 2026-10-08 an unlisted component module outside `src/routes` was silently non-resumable (request-time `Resume manifest has no chunk`, dead handlers). Test `resume-app-modules` (+ `fixture-resume-app`). Generated `.rivet/app.tsx` + route components compile in resume mode (server/static modes). Client exports must be no-op / server-safe outside a browser. Preload background budget / lean pages: adapter / `createApp` option `preload: { background, lean }` (`server/CLAUDE.md`, `adapters/CLAUDE.md`; planner in `docs/guides/resumability.md`). `<Link>` renders a plain `<a>` and resumes with no component code.
- Server reach (SERVER-REACH, spec `docs/design/specs/2026-10-20-server-reach-design.md`): `build/reach.ts` scans every page / layout / error page's browser graph before the build; a page reaching a server-only module (marker, `*.server.*`, `rivetRouter({ serverOnly })`, plugin `api.rivetServerOnly`) through its own module / non-component helpers = document route (links load documents, page code out of the client build); through a component, or from a layout / error page = RV3011 (`serverOnly: { reach: "warn" }`: warning + document route); dev reports it on page load (overlay + terminal). Client `recover`: an uncaught error during a client navigation loads the URL's document (once per URL / 10 s).
- Server code never reaches the browser: `*.server.*` and `@rivetjs/router/server-only` imports from browser graphs fail the build unless only document routes reach them (stand-in Proxy that throws) (`build/vite.ts` `resolveId`; `node:*` imports are not checked — Vite's own browser externalization applies); in-file `server*`/`on*` exports are stripped by the compiler (`serverExports` option). Details: [docs/guides/server-code.md](../../docs/guides/server-code.md).
- Security order per request (handler): CSRF check → body limit → `onRequest(…)`/`on<Method>` → guards → `headers` → action → loaders → render. OPTIONS (preflight): no CSRF/body limit, `onRequest(…)` then `onOptions(…)`, else 204 + `Allow`. See [server/CLAUDE.md](server/CLAUDE.md).
- Node adapter compression (default on, M5 E2 2026-10-18): zstd when accepted (level 1 for bodies ≥ 256 KiB, 3 below; streams too), brotli q4, gzip 6; immutable client files precompressed once at the best quality (zstd 19 / br q11 / gzip 9) on their first request and written next to the file (`.zst` / `.br` / `.gz`); `compress: { zstd?, precompress? } | false` — see [adapters/CLAUDE.md](adapters/CLAUDE.md), measured in `docs/design/research/2026-10-18-floor-first.md` §9.
- Node adapter `idleMemory` (default on, Node only): after traffic, one tiny cppgc allocation (`new vm.Script("")`) once idle so V8's memory reducer can shrink the heap (V8 treats a zero embedder allocation rate as "high") — see [adapters/CLAUDE.md](adapters/CLAUDE.md), [V8 draft](../../docs/design/research/2026-10-07-v8-memory-reducer-embedder-rate.md).
- Node adapter trusts no `X-Forwarded-*` header unless `trustProxy` (hop count / predicate, rightmost-first) — see [adapters/CLAUDE.md](adapters/CLAUDE.md).
- Web-standard only in `server/`, `shared/`, `adapters/{fetch,assemble,vercel-edge,netlify,cloudflare}.ts` (edge runtimes); Node APIs only in `build/`, `adapters/{node,idle-memory,build,static,target-build,pack,vercel,uws}.ts` (`uws.ts` = experimental uWebSockets.js transport, no subpath); `adapters/{bun,deno,files,server-target}.ts` use only `node:fs` / `node:path` / `node:url` (implemented by Bun and Deno).
- Document links: a same-origin link whose path matches no page route of the client table (generated `modules`) is never intercepted, data-fetched or chunk-prefetched — see [client/CLAUDE.md](client/CLAUDE.md). `reload` / `data-rivet-reload` keep forcing documents for page routes.
- Document prefetch (`rivetRouter({ prefetch, prefetchEagerness, prefetchPaths })`, `<Link prefetch="document" | "prerender">`): Speculation Rules (eagerness default `moderate`) + inline intent fallback (first prefetch per tab session is a `no-store` cacheability probe; uncacheable HTML → off, `sessionStorage["rivet:prefetch"]`) in every page's head via the generated entry's document wrapper; only navigations that load a document (client-routed apps: links whose path matches no route + reload / external links; routes RegExp from codegen `routePathRegExp`, left out with `prefetchPaths: false` → reload / external links only — the docs sites; endpoint links only when marked reload). Spec: [docs/guides/routing.md](../../docs/guides/routing.md#file-routes-document-prefetch). Fallback source `client/prefetch-fallback.ts` → `node libs/router/build/prefetch-script.ts` → `shared/prefetch-fallback.min.ts` (generated; `prefetch-unit.test.ts` fails when stale).
- `trailingSlash` (`ignore` default | `never` | `always`): build-time constant `TRAILING_SLASH` in `shared/slash.ts`, rewritten by the Vite plugin only when set → unset apps byte-identical. Handler 308s, `<Link>`/`navigate()` canonical hrefs, static layout.
- Route CSS (production): a page links at most two stylesheets, the app entry's first, then ONE route sheet: a route whose module closure has several CSS files (per-component `@rivetjs/ui` CSS) gets a merged `assets/route-<hash>.css` (files joined in order, repeated top-level `@property` / `@keyframes` / `@layer` statements dropped, same list → same asset); under route chunks (the default) a route's own components already share one chunk, so its sheet is usually that chunk's single Vite asset (`assets/routes-<hash>.css`, chunk `_routes`) and the merge only runs when the closure still has several files; compiler resume-chunk CSS stays per route (`build/route-css.ts` `mergeRouteCSS`, `tests/route-css.test.ts`; size-report `cssSheets` / `css` per route). Dev links each file.
- Inline stylesheets (production, `rivetRouter({ inlineStylesheets: "auto" | { maxTotalBrotli } | "always" | "never" })`, default `"auto"`, Astro model decided per page on compressed bytes, coordinator ruling 2026-10-12): `auto` inlines ALL of a page's listed sheets (global + route) when their brotli total ≤ 6144 B (`MAX_TOTAL_BROTLI`; playground Tailwind 13.8 KB raw / ~3.5 KB br → no stylesheet request, Fast 3G DCL −0.6 s), else each sheet ≤ Vite `build.assetsInlineLimit` (4096 raw). Build lists candidates with `css` / `bytes` / `br` (q11) in `.vite/rivet-inline-css.json` (`InlineStyleManifest`) → `AppConfig.inlineStyles` → per page `server/inline-styles.ts` `inlineStylesFor` (cached per stylesheet list) → `DocumentInput.inlineStyles` (URL → CSS); `headTags(head, input)` writes them as `<style nonce>` in the link's place. Relative `url()` / `@import` keep a sheet linked. CSP: `strictCSP` / `hashCSP` add the nonce / style hashes to an app-set `style-src(-elem)` (not to one with `'unsafe-inline'`). Shells mapping `styles` by hand (docs-kit, router test fixtures) link everything.
- Route rules (`rivetRouter({ routeRules })` JSON → generated entry `routeRules` export; `createApp` / `start` / fetch `create({ routeRules })` replace them; ROUTE-CACHE 2026-10-12, spec `docs/design/specs/2026-10-12-route-cache.md`): Nitro-style patterns (`/a`, `*` segment, trailing `/**`, below `base`; all matching merge, less literal chars first: headers by name, most specific `cache` wins) → `headers` on every response of the path, `cache` / `swr` / `isr` → in-process page store (`server/route-cache.ts`, loaded by `createApp` via dynamic import only when rules exist; dev = headers only). Stored: GET 200 `text/html` pages without `set-cookie` / `private` / `no-store` / `Vary: *` (`Vary: cookie` only with rule `varies`), without a reported render failure, canonical path encodings only; requests without `Cookie` (unless `cookies: true`: fill renders anonymous, no cookie / authorization) / `Authorization` / `_rivet`; a hit runs no guards / loaders. Key = origin + decoded path + query + `varies` + learned response-Vary names; `isr` needs `routeCache.origin` (node `start` / fetch pass `origin`). Validators + 304, `s-maxage` / `stale-while-revalidate` (`isr`: `s-maxage=0, must-revalidate` unless `cdn`), `x-rivet-cache: HIT|MISS|STALE`; stored bodies lose the request nonce and get a hash CSP of the nonce'd elements only (`shared/csp-hash.ts` `noncedSources`). Keys of client-chosen input (query, `varies` / learned header value, any key without a fixed origin) stored on their 2nd miss; fills drop `address` + per-visitor proxy headers (`x-forwarded-*`, `cf-*`, …); `cookies: true` + `Vary: cookie` never stored. `revalidate()` voids matching in-flight fills (per fill, path / tag), relayed to every node `start({ workers })` worker; refresh 404/410/3xx/`Set-Cookie` drops, other failures back off. Node adapter serves fresh hits before building a `Request` (`ROUTE_CACHE` lookup on the handler, headers merged + zstd 19 / br q11 / gzip 9 once per page). Editorial N=1000 article: see `server/CLAUDE.md`.
- Early hints (`createApp` / `start` / fetch `create({ earlyHints })`, EARLY-HINTS 2026-10-12, default off, production only): build-asset stylesheet / font preloads (+ `links`, `runtime`; head preconnects never learned) per route → node `103 Early Hints` before guards + `Link` header on pages; `server/early-hints.ts` loaded only when set — see `server/CLAUDE.md`, `adapters/CLAUDE.md`.
- Generated files start with `// Generated by @rivetjs/router from the routes directory. Do not edit.` (`build/codegen.ts` `HEADER`). Never hand-edit `.rivet/`.
- Behaviour is spec'd in `docs/guides/routing.md` / `docs/guides/server-code.md`; update them with behaviour changes.

## Gotchas

- CI parity (CI-RED-2 2026-10-21): the `[browser]` suites' unscripted hover prefetches on CI (`base` "/app/", `navigation` "/", `nested` "/?_rivet_keep=/", `depends`) came from Linux headless Chromium's virtual cursor over the fixtures' first link at (0, 0) — guarded for every suite by `@rivetjs/testing` `node-env.ts` (headless cursor guard); `codegen` defines an `ErrorEvent` stand-in on Node 24 (no global there; CI's Node); `document-links` waits for the `pageerror`s of the document route and of the broken render (they can arrive after the document load); `encoding` unwritable-dir waits until the fire-and-forget temp is gone.
- Files imported by path from outside — moving them breaks others:
  - `server/handler.ts`: `libs/forms/tests/{server,autosave,wizard,csrf}.test.ts`.
  - `tests/fixture/`: `libs/devtools/tests/{e2e,e2e-perf,e2e-resume,names}.test.ts`.
  - `tests/fixture-nav-api`, `tests/fixture-nested`: `scripts/size-report.mjs`.
  - `client/{index,link,navigation,search,transitions}.ts(x)`, `server/index.ts`, `adapters/{node,static,csr}.ts`, `build/vite.ts`: `apps/docs/api.config.ts` (API docs generator).
  - `shared/base.ts`: resolved by absolute path in `build/vite.ts` (`BASE_MODULE`).
- `client/route-context.ts` must stay free of `.tsx` imports: Node loads it in tests and the generated server entry imports `ServerData` from `/client`.
- e2e tests rebuild their fixture's `dist/` + `.rivet/`; edit fixture `src/`, never their generated output.
- Playwright Chromium launches pass `args: ["--use-mock-keychain", "--password-store=basic"]` (macOS "Chromium Safe Storage" keychain prompt otherwise); keep it on new launches.
- Route server exports are wrapper calls from `@rivetjs/router` (`shared/server-exports.ts`: `load` `guard` `actions` `entries` `headers` `onRequest` `onGet` … `onOptions`; any export name, tag `Symbol.for("rivet.server")` = kind), the same in page / layout modules, sibling `*.server.ts` and `.ts` endpoints; `prerender` / `csrf` / `live` stay plain named data exports. No magic names: untagged `serverLoad`… / `onGet`… (and sibling `load` / `GET`…) are errors (compiler RV3010, editor, `server/module.ts` at runtime). Codemod: `rivet migrate server-exports`. Spec `docs/design/specs/2026-10-20-server-exports-design.md`.
- Deferred loaders (PPR-T01, 2026-10-21): `load(fn, { defer: true })` → `loader[Symbol.for("rivet.defer")]`; type `Deferred<T>` (exported with `LoadOptions`); document requests render without awaiting them (per-request thenable handle, auto `stream: {}`), data requests await them; `setHeader(s)` / cookie writes throw. Handler half in `server/deferred.ts` (dynamic import). Details `docs/guides/routing.md` "File routes: deferred loaders"; user docs `apps/docs/content/guides/routing/loading-data.md#deferred-loaders`. A deferred `redirect()` becomes a client redirect (`location.replace` script at the document's end, PPR-T23).
- Shell cache (PPR-T23, 2026-10-21): route rule `shell: true | { maxAge, swr, tags, varies, query }` → stored shell prefix (cut after the root state tail) + live holes (deferred loaders under `<Async fallback>`); guards run on hits; H-holes (PPR-T6: no shell render when every hole is compiler-marked, `x-rivet-cache: SHELL-HIT`) else H-replay (`SHELL-HIT-REPLAY`) with byte compare + reload-once fallback, every 64th hit a full VERIFY replay; `RIVET_SHELL_HOLES=0` = replay only; an entry whose hole writes a signal an enclosing component provides through context stays replay-only (PPR-T57 frame watch); hole head components write late links / scripts with the hit's nonce, title / meta ignored; fills track request reads (allow-list) and store only request-independent shells; dev = probe (`x-rivet-cache: SHELL-BYPASS <reason>`). `server/shell-cache.ts` (dynamic import with `route-cache.ts`); details `docs/guides/routing.md` "File routes: shell cache"; user docs `headers-and-caching.md#partial-prerendering-shell-cache`.

## Known gaps

- Client navigation has no route-CSS ordering: lazy chunks' CSS is appended by Vite's preload helper in load order, not the SSR order (`build/route-css.ts`), so equal-specificity cross-file overrides can lose after a client nav (ui select popover width, worked around by chained selectors in 77cc0729). Fix sketch: router inserts route stylesheet links in SSR order on client nav — [research note](../../docs/design/research/2026-10-12-client-nav-css-order.md).
