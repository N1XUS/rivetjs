# @rivetjs/router — build (`/vite`, `/routes`)

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Build-time Node code: scan `src/routes/**` → route table → generate `.rivet/` → compile with `rivet()` (resume mode for server/static) → Vite build inputs + dev server. Never shipped to browsers.

## Entry points

- `@rivetjs/router/vite` → `vite.ts`: `rivetRouter(options)` (returns `Plugin[]`: router plugin, `rivet()` compiler plugin(s), deploy-target entry plugin when `adapter` is set — `../adapters/target-build.ts`), `routerUsage(root)`, `generateRoutes`, `RivetRouterOptions`.
- `@rivetjs/router/routes` → `routes.ts`: `routeTable(files, exports)`, `scanRoutes(dir)`, `_serverExportsOf`, `RouteTable`/`RouteEntry`/`RouteModule`.

## Layout

- `routes.ts` — file name → pattern/layout/special-page rules; route order; conflict errors.
- `codegen.ts` — `generate(table, options)` → `{ files, resumeModules }`; pure string templates. Server loaders in `routes.ts` / `AppRoute.server` / `layouts` return normalized `ServerModule`s: sibling `once(async () => serverExports(await import(spec), "<routesDir>/<file>", true))`, in-file `serverExports(own, file)`, both `mergeServer(…)` (imports `serverExports` / `mergeServer` only when used). Route types: `ModuleData<typeof import(…)>` / `ModuleActions` (exports found by tag) for in-file and sibling modules alike.
- `reach.ts` — SERVER-REACH (spec `docs/design/specs/2026-10-20-server-reach-design.md`): `analyzeReach(options)` → `{ documents, problems, documentOnly, targets, names, chains }`. Browser graph of every page / layout / special page: Vite `config.createResolver()` (client conditions), edges from `compile(src, { target: "dom", serverExports })` (`.tsx` / `.jsx` / route modules) or `transformWithOxc` (`.ts`) + `parseSync` static / literal dynamic imports, mtime cache; node_modules, `?query`, `\0` ids not followed; unresolvable virtual ids matched by specifier. Page reach through its own module / non-component helpers (or a marker import) → document route; through a component (`.tsx` / `.jsx` ≠ page) → RV3011 (`RV_REACH`; `reach: "warn"` → warning + document route); layouts / special pages → always RV3011. Message: `[rivet:router] RV3011 <chain " → "> (server-only), rendered by <≤ 5 route paths + "and N more"> (client-navigated page route[s])` + `fix:` / `docs:` lines. Display paths root-relative, else `<package>/<path>`. `serverOnlyOption(option)` normalizes `string[] | { modules, reach }`. Tests `tests/server-reach.test.ts`, `tests/document-links.test.ts`.
- `vite.ts` — plugin: options, `routerUsage` feature scan, `.rivet/` sync, `resolveId` server-only guard, reach analysis (`configResolved` → `analyze()` sets `codegen.documents`; `buildStart` warns / errors with `pluginCode: "RV3011"`; dev: re-analysis when a route / source file changed, `devReach(url)` logs each problem once and hands the matched route's problems to `devHandler` → overlay), `transform` rewrites `server/shell-build.ts` `SHELL_BUILD` (undefined) to `() => import(<abs path of server/shell-cache.ts>)` when a `routeRules` entry has a truthy `shell` (shell cache bundled only then, PPR-T23), document-page stub `\0rivet-document-page:<page>` (client builds: `.rivet/app.tsx`'s import of a document page → a component that throws), stand-in `\0rivet-server-only:<key>` (`serverOnlyStub` with the export names the graph saw: rolldown has no `syntheticNamedExports`), build inputs, dev middleware + watcher, route CSS asset, i18n base rewrite.
- `dev-errors.ts` — `vite serve` only: overlay reporting (`overlayOf(server, { message, stack, plugin }, nonce)`; `devHandler(handler, server, table, reach?)`: reach errors of a GET HTML page request → hint comment + overlay injected into a < 400 response), dev error page, route list on unmatched URLs, `rivet:client-error` (sent by the generated dev entry / `app.tsx` `_devError`: `codegen.ts` `DEV_DESCRIBE` turns a non-Error value or an `ErrorEvent` without `error` into a message + reporting-site stack, `tests/codegen.test.ts`; in `app.tsx` the helpers are module-local `const _devDescribe` / `_devBenign`, only `_devError` is exported, so production builds drop them — ZERO Z5, −0.65 KB raw per App chunk). The benign `ResizeObserver loop completed with undelivered notifications.` / `ResizeObserver loop limit exceeded` notices are filtered (generated `DEV_BENIGN`: dev entry `send` + `_devError` drop them and log once at `console.debug`; `listenClientErrors` drops them too for older clients): no overlay, no error log. Escaping: `@rivetjs/runtime/escape` (`escapeText` for content, `escapeAttribute` for attributes); inline-script JSON via `escapeJSON` (`<`, U+2028, U+2029). `lateFailures`: a failure reported while the body streamed (document closed with its failure marker, or an errored body) appends the hint comment + overlay + reload script.
- Dev middleware never rejects (connect does not await; an unhandled rejection kills the dev server): router middleware catch guards `ssrFixStacktrace`; node listener catch guards a throwing `onError`; `@rivetjs/devtools/server` `uiMiddleware` answers 400 for malformed `%`.
- `route-css.ts` — per-route stylesheet lists (`.vite/rivet-route-css.json` in build, module graph in dev). Build: `bundleRouteCSS(…, appEntries)` — CSS of the app's own inputs (`build.rollupOptions.input`, router `styles` by default) is global; the compiler's entries (derived boundary modules, e.g. `src/routes/index.tsx`) are not (their CSS = a page's / component's, per route; before RED-DOCS a boundary route page's CSS was linked as a 3rd global sheet); `mergeRouteCSS(bundle, css, base, prefix = "route")` joins a route's several sheets into one `assets/<prefix>-<hash>.css` (re-exported from `@rivetjs/router/vite`; docs-kit frames use prefix `frame`) (`dedupeTopLevel`: repeated `@property` / `@keyframes` / `@layer` statements once) → 2 sheets per page (global + route). `inlineCSS` (`rivetRouter({ inlineStylesheets })`, Astro `build.inlineStylesheets` model, default `"auto"`): the `InlineStyleManifest` (`server/inline-styles.ts`: `mode`, `maxTotalBrotli` (default `MAX_TOTAL_BROTLI` 6144 or `{ maxTotalBrotli }`), `limit` = `build.assetsInlineLimit` (number, else 4096), `sheets` URL → `{ css, bytes, br }` (brotli q11)) of every client CSS asset + merged route sheet that could go inline (`"always"`: all; `auto`: br ≤ `maxTotalBrotli` or bytes ≤ `limit`; `"never"`: none), markers stripped, skipping relative `url()` / `@import` references (`RELATIVE_REFERENCE`) → `.vite/rivet-inline-css.json` (`INLINE_CSS`; written only when non-empty). The server picks per page. Server / static modes only (csr shell links). Dev unchanged. Tests: `tests/route-css.test.ts`.
- `sync.ts` — `sync({ root, configFile, mode })` → `{ root, configFile, manifest }`: Vite `resolveConfig(…, "build")` so the router `config` hook + compiler `configResolved` regenerate `.rivet/` (incl. `editor.json`) without serving / building; CLI `rivet sync`.
- `prefetch-script.ts` — `node libs/router/build/prefetch-script.ts` regenerates `../shared/prefetch-fallback.min.ts` from `../client/prefetch-fallback.ts` (esbuild minify of `fn.toString()`); `minifiedFallback()` used by the staleness test.
- `migrate.ts` — `rivet migrate server-exports [--routes dir] [--dry-run]` codemod (2026-10-20 wrapper calls): phase 1 language-service renames project-wide (old name → default `loader` / `access` / `forms` / `paths` / `responseHeaders` / `middleware` / `GET`…; taken → `<name>Export`), phase 2 parser rewrites: `export const x = init` → `export const NEW = wrapper(init)` (`let` → `const`, `: T` → `satisfies T`), function declarations → arrows (function expression when `this` / `arguments` / `super` / generator / type parameters), `export { a as old }` → `export const NEW = wrapper(a)`, wrapper import added / merged (aliased `rivetLoad` … on a local collision; inserted after the last import's line, trailing comment kept). In-file magic names everywhere under the routes dir; sibling names (`load`, `GET` …) only in `*.server.*`. Skipped + reported: re-exports of old names, multi-declarator statements. `migrateSource` (one module, docs snippets), `migrateTexts`, `writeMigration`; CLI in `../cli/rivet.ts`.
- `head-strip.ts` — `unexportHead(code)` (EXT-A 2026-10-22): `vite.ts` plugin `vite-plugin-rivet-router-head` (`enforce: "post"`, `apply: "build"` — M6-CUT: on the dev server the compiler hot wrapper lists `head` among the exports before this post transform, so stripping it made every edit an export change (invalidate → reload, state lost; router `app.test` dev HMR, `dev-resume`, devtools e2e) —, last in `rivetRouter()`'s list; browser environment of server / static apps, route modules = `serverExports.modules`) blanks the `export` of `export const head = …` (one declarator) / `export function head` / an `export { x as head }` specifier at the same byte length (`map: null`): the bundler drops `head` and code only it uses (route head CSS / meta never reach the browser; server merges them, client navigation gets the data endpoint's `head`). Kept when module code reads `head`; csr keeps the export (`_csrHead`). Test `tests/head-strip.test.ts`.

## Route file rules (`routes.ts`)

- Pages `*.tsx|jsx`; `index` = folder URL. Segments: `[id]` param, `[[lang]]` optional (expands to 2 entries, same id), `[...rest]` splat (last only), `(group)` path-less.
- Special: `_layout`, `_404`, `_error` (nearest by folder). Other `_x` names / `_` folders ignored. Only `_layout` may have a server module.
- Server module: sibling `x.server.ts` or in-file server exports (wrapper calls `load(…)` … `onGet(…)`, or `prerender` → `inline: true`). Same wrapper rule for both; the scan reads KINDS (`moduleFacts(…).serverKinds`: `load`, `onGet`, …, `?` for a re-export from a server-only module), not names.
- Live pages: `export const live = true` in a page module (`routes.ts` `LIVE` regex, checked before the server-export prefilter; `_serverExportsOf` reports it as the kind `live`, which `isInline` ignores) → `RouteEntry.live`. Layout / special-page flags ignored. Dev watcher: `inFile` also holds `live:<page>`, toggling the flag regenerates. Codegen only when a live page exists AND `navigate` (forms ⇒ navigate) and mode ≠ csr: `LIVE` page indices, `const live = _live(source)` (declared before the listeners; single-level apps — no nested levels — `_live(source, router)`, top Router `_liveRouter(router, live)`, click / popstate / `rivet:go` handlers call `_armLive(router, live[, nest, NEST])` first: search-only navigations of the shown live page refresh in place; nested levels: `arm()` → `_sync(router, nest, NEST, (from, url) => _liveLevels(router, live, nest, NEST, from, url))`, the arrow inline — a stored `_liveLevels` closure is an unserializable capture of the resumed `arm`), `rivet:go` → `_serveLive(router, live[, nest, NEST])` (replaces `_serve`), route render hoists `const data = LIVE.includes(row[2]) ? _livePage(…) : result.data[depth]` + `<Page data={data}>` (static prop). Otherwise byte-identical (`tests/live.test.ts`). Spec `docs/design/specs/2026-10-08-partial-render-design.md`.
- Endpoints: plain `x.ts` (e.g. `api/ping.ts`) exporting a request handler (`export const GET = onGet(…)`: kind `onRequest|onGet|onPost|onPut|onPatch|onDelete|onOptions`, or `?`) → endpoint-only route (`page: false`). Plain `.ts` without handlers = helper, no route. `x.ts` + `x.server.ts` for one base → error.
- Ignored: dotfiles, `*.test.*`/`*.spec.*`, `*.d.ts`.
- Order: static < param < splat per segment; first match wins. Two files with one shape → "Route conflict" error. Duplicate param names → error.
- Route id = file path without extension (`blog/[slug]`); layout id = `/` + folder (`/`, `/shop`) at runtime, file path (`shop/_layout`) in types.

## Generated output (`.rivet/`, all marked `// Generated by @rivetjs/router … Do not edit.`)

- server/static: `app.tsx` (App + layout table, resumable), `routes.ts`, `entry.server.tsx` (`GeneratedEntry`), `entry.dev.tsx` (a JS hot update while resumed → `location.reload()`; `rivet:devtools-inspect` → dispose + client render, then hot replace), `dev-mount.tsx`, `routes.d.ts` (type augmentation); no resume entry (M6-CUT: the derived runtime is the compiler plugin's `\0rivet-derived-entry`).
- csr: `app.tsx`, `entry.client.tsx`, `routes.d.ts`. csr `app.tsx` imports layouts as namespaces (`import * as LayoutN$`, component = `.default`) and lists them per route in `HEADS` (route index → layout namespaces, outermost first); route loads end with `_csrHead(data, HEADS[row[0]], page, match[, rankMerge])` (kit: `rankMerge` from `@rivetjs/router/head`): the route head applies in the browser (title; merged head for `applyRouteHead`). Server / static output unchanged.
- `editor.json` written by `@rivetjs/compiler/editor` (`updateEditorManifest`; unchanged → mtime bump = staleness clock).
- `routeModules()` (compiled with `serverExports`) = pages + layouts + plain `.ts` endpoint modules (not `*.server.*`): a page importing a constant from an endpoint gets the endpoint's handlers stripped in the browser build (T7).
- Generated code imports only public subpaths (`@rivetjs/router/client|server|navigation|search|transitions|prefetch`, `@rivetjs/runtime/*`, `@rivetjs/kit`) — internals are `_`-prefixed exports of `/client`.

## Rules / invariants

- `routerUsage(root, { exclude })` walks sources only: directories matching `OUTPUT` (dot, `node_modules`, `dist`, `dist-*`/`dist.*`/`dist_*`) and `exclude` (plugin passes `build.outDir` + `.rivet` outDir) are never entered; ENOENT/EISDIR on read = skip (sibling builds rewrite their `dist-<lane>` concurrently). Test: `tests/router-usage.test.ts`.
- Pay-per-use: `routerUsage` (text scan of sources in files importing `@rivetjs/router`; `forms` = `@rivetjs/forms` anywhere or `Form` in a file importing `@rivetjs/ui` ⇒ `forms` + `navigate`; codegen `forms` → `_brand(_go)` first in every router handler, `client/CLAUDE.md` "Router brand") decides `searchParams` / `navigate` / `params` / `activeLinks` (`<Link … active`) / `prefetch` (`prefetch="document|prerender"`, also `data-rivet-prefetch=`, `prefetch={"…"}`) codegen. Off ⇒ nothing generated for it (byte-identical output). Options override detection.
- `resolveId`: browser graph importing a server-only module (`isServerOnly(patterns, id)`: marker, `*.server.*`, `serverOnly` patterns + plugin-declared) from an importer only document-only graphs reach → stand-in; otherwise → `this.error({ message, id: importer, plugin: "vite-plugin-rivet-router" })` (the real plugin name: builds overwrite `plugin` with it anyway); message = `[rivet:router] <id> is server-only and cannot be imported by browser code (imported from <importer>)` + `fix:` / `docs:` lines (DIAG-VERBOSE; quoted in docs `guides/security/server-only-code.md`, `best-practices/secrets-in-server-files.md`; test `tests/codegen.test.ts`). Skipped for SSR and compiler fact resolutions (`_factsResolve(id, importer)` from `@rivetjs/compiler/vite`, an in-flight registry — not `resolveOptions.custom`, which rolldown 1.2.12 loses under concurrent context resolves).
- `routeRules` (`rivetRouter`): checked at config time (`compileRules` from `server/route-cache.ts` + JSON-data check: finite numbers, strings, booleans, plain objects / arrays; `isr: true` for no expiry), carried on the `codegen` object → `entry.server.tsx` `export const routeRules = <JSON>;` (only when non-empty: unset apps byte-identical). Test `tests/route-cache.test.ts`.
- Codegen output is ordinary TSX so the compiler treats it like app code; change templates, not generated files. `tests/codegen.test.ts` pins template shapes; `tests/generated-types.test.ts` type-checks output under `strict`.
- `routes.ts` wraps every server-module loader and `universal[id]` in a generated `once()`: builds memoise the import promise (rejections retried); `import.meta.env.DEV` returns the loader itself (each dev request re-imports, so edits are never pinned). Hence `/// <reference types="vite/client" />` in `routes.ts`.
- Dev middleware, `mode: "static"`: `GET|HEAD <page>/_data.json` (the client's static data URL, `dataURL(url, "static")`) is rewritten (`staticData`) to `<page in trailingSlash form>?_rivet=data` + `accept: application/json` before the listener, as `prerender` renders it — dev has no prerendered files, so before this every client navigation 404'd into `_404` (`tests/groups.test.ts`). Dev also answers pages a build would not prerender (dynamic without `entries`).
- Dev middleware: one `createApp` + listener per `entry.server.tsx` namespace (WeakMap; Vite returns a new namespace after invalidation). `devResume.manifest` is a getter (dev manifest grows as modules compile).
- `dev-mount.tsx` fetches route data with `accept: application/json` only (the old `x-rivet-data` header was never read).
- Dev regenerations serialize (`regenerations` chain); route table regenerates only when in-file server exports appear/disappear; `*.server.ts` edits send `rivet:data` (data refetch + remount).
- `prefetch` (`true` / `"document"` / `"prerender"`; validated in `rivetRouter`; option name = `RouterUsage` key): `entry.server.tsx` imports the shell and exports `document = documentPrefetch(shell, { default?, routed?, routes?, eagerness? })` (`routed` + `routes` = `routePathRegExp(every route pattern incl. base)` unless single-route mode; `prefetchPaths: false` drops `routes` (validated boolean, on the `codegen` object); `eagerness` only when `prefetchEagerness` is set and not `moderate`) instead of re-exporting it; `app.tsx` unchanged. Unset/false ⇒ byte-identical entry. `prefetchEagerness` validated in `rivetRouter`, carried on the `codegen` object (also when `prefetch` is detected, not set).
- `clientRouter` (opt-in, default `false` in every mode; csr always routed — EXT-A 2026-10-22, was `mode !== "static"`): codegen option. Every App router clientEvent (click / pointerover / focusin / pointerdown / popstate / `rivet:go`) carries `standalone: false` in both settings (csr: none) — TOAST-ACTIVE 2026-10-26: the derived server keeps a `clientEvent`'s trigger, a standalone router listener would boot the router at idle (Z1 says first link click / intent); `true` keeps pages resumable through the App's non-weak record. With `false` they alone (with the routes region's router-location-only binding, runtime `onlyLocations`) do not make a page resumable → inert static pages ship zero JS and links load documents; interactive pages still route in place (STATIC-ZERO-JS 2026-10-12). Derived model: `false` also emits `if (import.meta.env.SSR) _rWeak();` at the top of the generated `Root` and `App` (ZERO Z3, `generate` `weak`): weak records alone ship no tail / loader / runtime (`libs/runtime/derived-eager.ts`, `server-derived.ts` `weakOnly`); `tests/groups.test.ts` "client router off" builds fixture-groups without it (no script, every click a document; prerender prunes all chunks).
- `preload: { background }`: validated in `rivetRouter` (non-negative bytes); codegen adds `export const preloadBackground = N` to `entry.server.tsx` only when set (`createApp` default; adapter `preload` options override). Dev manifests carry no sizes (dev chunks are whole transformed source files, no bundle graph; sizes would also flip the 8 KB automatic-`visible` cutoff), so dev keeps `visible` chunks viewport-only.
- `trailingSlash` (`never`/`always`): validated in `rivetRouter`; codegen adds `export const trailingSlash` to `entry.server.tsx` (absent by default); `transform` rewrites `shared/slash.ts`'s constant (`SLASH_MODULE`) in client + server builds (dev too); `ssr.noExternal` gets `@rivetjs/router` so the server bundle carries the rewritten copy.
- `app.tsx` route tables (RA1/RA2/Z4): module-level `PATHS<level>` + route columns (route id, depth, page index, enter, failure; Z5b: a column is inlined as a literal when constant, as `n` when it equals the row index, else `R<level>_<c>: number[]` — no row literal per route; `NEST.routes` = `PATHS.map(path => [path, CHAINS[i]])`, one shared array per distinct layout chain; routes-500 App 60.4 → 44.6 kB min) + `PAGES` (data-driven `() => import()` table; `page(i)` memoizes one `lazyComponent` per page, Z5); App passes `routes = { paths, route(n) }` (`RouteTable`, `@rivetjs/runtime/router`) so paths compile once per process and only the matched route is defined. One shared `fail<j>` per distinct `_error` chain and one `enter<k>` per persisted layout level (layout + nested `Router`), picked by row index — the App chunk no longer grows a closure per route (routes-500 App chunk 544 → 94 kB min). `modules` maps paths to `preloadPage(page(i), PAGES[i])` (one shared load per page module, retried after a failure — no `import()` per server request); route `load` = `_take` (nested) `?? _ssrLevel(work, ok, failed, land) ??` the browser chain (`Promise.all([routeData, loadPage])…then(loaded, failed).then(_landed)`): on the server `_ssrLevel` applies the handler's `ServerData` through the same steps synchronously (no promise hops, no page import; not in csr mode). Capture order of the route-table closures follows first use (`nest` before `router`); click / intent handlers pass it (`interceptClick(event, router, modules)`, `routableAnchor(event, modules)`) so links no page matches load documents. Endpoints the server matches before a later overlapping dynamic page pattern (`overlaps`) become `[path, _endpoint]` rows spliced in at their table position (`shadowed`; none ⇒ byte-identical `const modules`). `routePathRegExp(patterns)`: trie RegExp source of all route paths over `pathname.slice(1)` for document prefetch (`tests/codegen.test.ts`). Nested layouts / `_404` stay static imports (lazy layouts need level-load preloading; unmatched 404s render synchronously).
- Single-route mode (Z1): one static page route, server/static mode, no `navigate`/`searchParams`/`activeLinks`/nested layouts → no click / intent / popstate client events (no eager router chunk; template `minimal`: eager JS 0 B). Links are plain full loads there.
- Lazy router (Z1): multi-route App listeners (click / pointerover / focusin / popstate / `rivet:go`) are `clientEvent(…, { preload: "intent" })` → page idles with 0 B eager JS; inline loader boots the App chunk on first link intent/click. Nested-layout `_sync` and active-link marking run via `(arm(), …)` → `_arm(router, …effects)` (client/index.ts; once per router) instead of idle `clientEffect`s. Link intent boots the router (derived loader: intent fetches the Root boundary chunk, a held click replays); the intent handler also `arm()`s. First click (routes-10, Slow 4G + 4× CPU, 5 runs p50): cold click 262 ms (645 before the fetch-only modulepreload hints) / hover+click 87 ms vs eager 229 / 82 ms. Landing: idle-executed JS 126.6/45.0 → 85.7/30.5 KB min/br per page (it still boots for its own idle effects).
- Stopped link clicks (RESUME-PINS 2026-10-12; derived M6-CUT 2026-10-22): non-csr Apps add `clientEvent(document, "click", (event) => _onStopped(event, () => interceptClick(…)), { capture: true, preload: "intent", match: "a" })` after the bubbling one. A link's own handler whose `stopPropagation` hides the click from the bubbling router listener (cdk / ui Link press; resume fuzz T31 cdk `/links` `#current`, `/sidebar` `#home`; ui `/visual/card` `href="#"`): `_onStopped` (`@rivetjs/router/client`) routes it now when already stopped (a cold click's replay runs the handlers before this listener, `late`), else wraps the event's `stopPropagation` / `stopImmediatePropagation` and routes once a later handler stops it (live clicks: the derived runtime's delegated listener runs a link's handlers at the document bubble phase, after this capture listener; test `tests/stopped-links.test.ts` warm + cold). Clicks never stopped skip it; csr Apps have no resumed handlers.
- ROUTER-LAZY (2026-10-12): the App's document listeners carry clientEvent `match` — click / pointerover / focusin `"a"` (pointerover / focusin `"a,form"` with live pages: hovering a form warms the live page's data readers — the measured live-form win, kept by ruling 2026-10-12), live pointerdown `"form"` — so a first click / hover outside links (a signal handler's button, plain text) neither runs them nor loads the App chunk; popstate / `rivet:go` unfiltered. Docs (`fold-nogroup` vs this, CDP coverage, 3 runs): `/` copy-button click 20 scripts 149,710 / 48,514 B br → 10 / 77,377 / 29,205 (no resume-App / `_layout` / SiteFrame); `/learn/resuming/` hover over text 11 scripts 129,515 / 40,126 → 1 / 24,432 / 8,836.
- `vite.ts` server builds (`ssr === true`, plain and adapter targets): `build.minify = config.build?.minify ?? true` (EXT-B 2026-10-22: Vite's SSR default is off; fixture-recipe server 422.6 → 198.6 KB raw, 128.9 → 76.3 KB gz; `--minify false` / config wins).
- `vite.ts` `preloadDeps` (`build.modulePreload.resolveDependencies`, unless user sets `modulePreload`): drops dynamic-import deps already in the host chunk's static closure (routes-500 App chunk 93.9 → 76.7 kB min).
- `vite.ts` forwards `devtools`, `css`, `images`, `staticIcons`, `comptime` and `locales` (only when set: unset = the compiler default; `locales` unset = the `i18n()` plugin's, else whole locale tables) to `rivet()`. `bridges` (framework bridges, `rivet({ bridges })`): non-empty → `rivet()` returns the framework plugins + bridge host before the compiler, found by name (`vite-plugin-rivet`); csr mode throws (islands are server-rendered); test `tests/bridges-option.test.ts`.

## Gotchas

- `vite.ts` `transform` rewrites `shared/base.ts` for i18n client builds with a regex on `import.meta.env?.BASE_URL`; changing that expression in `shared/base.ts` breaks the build (it errors loudly).
- i18n client builds also wrap `underBase` (`export function underBase(` must stay; errors loudly) with the i18n api's `clientPaths` RegExp: other locales' URLs are not client-routable (links/`navigate()`/redirects load the document; switch = navigation). Without it a held link click (Z1) switched locale in place with the wrong build's messages.
- i18n dev server (`serve`, client transform only): `underBase` also requires the target path's locale (first match of the i18n api's `devPaths`, one pattern per locale) to equal the page's, read once at module load (`location.pathname`); SSR copy untouched. Same effect as the build wrap: a cross-locale link loads its document (dev used to client-navigate with the old locale's module graph). Test: `libs/i18n/tests/browser.test.ts` "a link to another locale loads its document".
- `mode: "csr"` + `adapter` → throws; csr rejects `.server.ts`.
- `routerUsage` does not scan published deps: set `rivetRouter({ navigate, params, searchParams })` when only a package uses them.
- Custom `resume.entry` must provide `[Navigation, navigation]` itself when `transitions` is on.
