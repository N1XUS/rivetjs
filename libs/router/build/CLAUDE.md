# @rivetjs/router — build (`/vite`, `/routes`)

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Build-time Node code: scan `src/routes/**` → route table → generate `.rivet/` → compile with `rivet()` (resume mode for server/static) → Vite build inputs + dev server. Never shipped to browsers.

## Entry points

- `@rivetjs/router/vite` → `vite.ts`: `rivetRouter(options)` (returns `Plugin[]`: router plugin, `rivet()` compiler plugin(s), deploy-target entry plugin when `adapter` is set — `../adapters/target-build.ts`), `routerUsage(root)`, `generateRoutes`, `RivetRouterOptions`.
- `@rivetjs/router/routes` → `routes.ts`: `routeTable(files, exports)`, `scanRoutes(dir)`, `_serverExportsOf`, `RouteTable`/`RouteEntry`/`RouteModule`.

## Layout

- `routes.ts` — file name → pattern/layout/special-page rules; route order; conflict errors.
- `codegen.ts` — `generate(table, options)` → `{ files, resumeModules }`; pure string templates.
- `vite.ts` — plugin: options, `routerUsage` feature scan, `.rivet/` sync, `resolveId` server-only guard, build inputs, dev middleware + watcher, route CSS asset, i18n base rewrite.
- `dev-errors.ts` — `vite serve` only: overlay reporting, dev error page, route list on unmatched URLs, `rivet:client-error` (sent by the generated dev entry / `app.tsx` `_devError`: `codegen.ts` `DEV_DESCRIBE` turns a non-Error value or an `ErrorEvent` without `error` into a message + reporting-site stack, `tests/codegen.test.ts`). The benign `ResizeObserver loop completed with undelivered notifications.` / `ResizeObserver loop limit exceeded` notices are filtered (generated `DEV_BENIGN`: dev entry `send` + `_devError` drop them and log once at `console.debug`; `listenClientErrors` drops them too for older clients): no overlay, no error log. Escaping: `@rivetjs/runtime/escape` (`escapeText` for content, `escapeAttribute` for attributes); inline-script JSON via `escapeJSON` (`<`, U+2028, U+2029). `symbolNote` adds the component + the capture's source location for a recorder error naming a symbol: ``capture `name` `` (dev manifest names as written, `o.a` for member captures, Function Bridge T19 + fix 1; `tests/dev-errors.test.ts` `unserializable-member` route) or `capture #n`. `lateFailures`: a failure reported while the body streamed (document closed with its failure marker, or an errored body) appends the hint comment + overlay + reload script.
- Dev middleware never rejects (connect does not await; an unhandled rejection kills the dev server): router middleware catch guards `ssrFixStacktrace`; node listener catch guards a throwing `onError`; `@rivetjs/devtools/server` `uiMiddleware` answers 400 for malformed `%`.
- `route-css.ts` — per-route stylesheet lists (`.vite/rivet-route-css.json` in build, module graph in dev). Build: app entries' CSS is global; resume chunk entries (`\0rivet-resume-chunk:`) are not (their CSS = a component's, per route); `mergeRouteCSS(bundle, css, base, prefix = "route")` joins a route's several sheets into one `assets/<prefix>-<hash>.css` (re-exported from `@rivetjs/router/vite`; docs-kit frames use prefix `frame`) (`dedupeTopLevel`: repeated `@property` / `@keyframes` / `@layer` statements once) → 2 sheets per page (global + route). `inlineCSS` (`rivetRouter({ inlineStylesheets })`, Astro `build.inlineStylesheets` model, default `"auto"`): the `InlineStyleManifest` (`server/inline-styles.ts`: `mode`, `maxTotalBrotli` (default `MAX_TOTAL_BROTLI` 6144 or `{ maxTotalBrotli }`), `limit` = `build.assetsInlineLimit` (number, else 4096), `sheets` URL → `{ css, bytes, br }` (brotli q11)) of every client CSS asset + merged route sheet that could go inline (`"always"`: all; `auto`: br ≤ `maxTotalBrotli` or bytes ≤ `limit`; `"never"`: none), markers stripped, skipping relative `url()` / `@import` references (`RELATIVE_REFERENCE`) → `.vite/rivet-inline-css.json` (`INLINE_CSS`; written only when non-empty). The server picks per page. Server / static modes only (csr shell links). Dev unchanged. Tests: `tests/route-css.test.ts`.
- `sync.ts` — `sync({ root, configFile, mode })` → `{ root, configFile, manifest }`: Vite `resolveConfig(…, "build")` so the router `config` hook + compiler `configResolved` regenerate `.rivet/` (incl. `editor.json`) without serving / building; CLI `rivet sync`.
- `prefetch-script.ts` — `node libs/router/build/prefetch-script.ts` regenerates `../shared/prefetch-fallback.min.ts` from `../client/prefetch-fallback.ts` (esbuild minify of `fn.toString()`); `minifiedFallback()` used by the staleness test.
- `migrate.ts` — `rivet migrate server-exports` codemod (TypeScript language service renames); CLI in `../cli/rivet.ts`.
- `lazy-rows.ts` — lazy collection rows T1 measurement harness (spec `docs/design/specs/2026-10-19-lazy-collection-rows-design.md` R2, never shipped): `lazyRowsHarness(entry)` (in `rivetRouter()`'s plugin list; inert unless `lazyRowsMode` = `swap`) prepends `import { _lazyRowsSwap } from "<runtime>/server-lazy-rows.ts"; _lazyRowsSwap();` to the generated `entry.server.tsx` (SSR transform only; a call, not a bare import: the runtime is `sideEffects: false`). `lazyRowsMode(command, env)`: env `RIVET_LAZY_ROWS` (`LAZY_ROWS_ENV`; build value `swap`; `on` / `off` = runtime server lazy row records (LAZY-ROWS T4, read at render) → null, no build change; others throw) applies in `vite serve`, or in a build whose env also has `RIVET_LAZY_ROWS_HARNESS=1` (`LAZY_ROWS_HARNESS_ENV`, set by docs-kit `buildFrames` for its children); a plain production build warns and ignores it. No `rivetRouter` / `rivet.config` option on purpose. `lazyRowsModule()` = the runtime file path (no package export). `lazyRowsBuild(env)` (LAZY-T5B): `RIVET_LAZY_ROWS=on` + `RIVET_LAZY_ROWS_HARNESS=1` → `rivetRouter` adds `resume.lazyRows: true` (the lazy-rows tools build app configs they do not own; apps opt in with `rivetRouter({ resume: { lazyRows: true } })`, passed through to the compiler plugin). Test `tests/lazy-rows.test.ts`.

## Route file rules (`routes.ts`)

- Pages `*.tsx|jsx`; `index` = folder URL. Segments: `[id]` param, `[[lang]]` optional (expands to 2 entries, same id), `[...rest]` splat (last only), `(group)` path-less.
- Special: `_layout`, `_404`, `_error` (nearest by folder). Other `_x` names / `_` folders ignored. Only `_layout` may have a server module.
- Server module: sibling `x.server.ts` (legacy names ok) or in-file exports (`serverLoad`…, `on*`, `prerender` → `inline: true`).
- Live pages: `export const live = true` in a page module (`routes.ts` `LIVE` regex, checked before the server-export prefilter; `_serverExportsOf` reports it as the name `live`, which `isInline` ignores) → `RouteEntry.live`. Layout / special-page flags ignored. Dev watcher: `inFile` also holds `live:<page>`, toggling the flag regenerates. Codegen only when a live page exists AND `navigate` (forms ⇒ navigate) and mode ≠ csr: `LIVE` page indices, `const live = _live(source)` (declared before the listeners; single-level apps — no nested levels — `_live(source, router)`, top Router `_liveRouter(router, live)`, click / popstate / `rivet:go` handlers call `_armLive(router, live[, nest, NEST])` first: search-only navigations of the shown live page refresh in place; nested levels: `arm()` → `_sync(router, nest, NEST, (from, url) => _liveLevels(router, live, nest, NEST, from, url))`, the arrow inline — a stored `_liveLevels` closure is an unserializable capture of the resumed `arm`), `rivet:go` → `_serveLive(router, live[, nest, NEST])` (replaces `_serve`), intent handler + `pointerdown` clientEvent call `_liveIntent(event, live[, nest])`, route render hoists `const data = LIVE.includes(row[2]) ? _livePage(…) : result.data[depth]` + `<Page data={data}>` (static prop). Otherwise byte-identical (`tests/live.test.ts`). Spec `docs/design/specs/2026-10-08-partial-render-design.md`.
- Endpoints: plain `x.ts` (e.g. `api/ping.ts`) exporting `onRequest|onGet|onPost|onPut|onPatch|onDelete` → endpoint-only route (`page: false`). Plain `.ts` without handlers = helper, no route. `x.ts` + `x.server.ts` for one base → error.
- Ignored: dotfiles, `*.test.*`/`*.spec.*`, `*.d.ts`.
- Order: static < param < splat per segment; first match wins. Two files with one shape → "Route conflict" error. Duplicate param names → error.
- Route id = file path without extension (`blog/[slug]`); layout id = `/` + folder (`/`, `/shop`) at runtime, file path (`shop/_layout`) in types.

## Generated output (`.rivet/`, all marked `// Generated by @rivetjs/router … Do not edit.`)

- server/static: `app.tsx` (App + layout table, resumable), `routes.ts`, `entry.server.tsx` (`GeneratedEntry`), `entry.dev.tsx`, `dev-mount.tsx`, `routes.d.ts` (type augmentation), `entry.resume.ts` (only when contexts needed: navigation / search).
- csr: `app.tsx`, `entry.client.tsx`, `routes.d.ts`.
- `editor.json` written by `@rivetjs/compiler/editor` (`updateEditorManifest`; unchanged → mtime bump = staleness clock).
- `routeModules()` (compiled with `serverExports`) = pages + layouts + plain `.ts` endpoint modules (not `*.server.*`): a page importing a constant from an endpoint gets the endpoint's handlers stripped in the browser build (T7).
- Generated code imports only public subpaths (`@rivetjs/router/client|server|navigation|search|transitions|prefetch`, `@rivetjs/runtime/*`, `@rivetjs/kit`) — internals are `_`-prefixed exports of `/client`.

## Rules / invariants

- `routerUsage(root, { exclude })` walks sources only: directories matching `OUTPUT` (dot, `node_modules`, `dist`, `dist-*`/`dist.*`/`dist_*`) and `exclude` (plugin passes `build.outDir` + `.rivet` outDir) are never entered; ENOENT/EISDIR on read = skip (sibling builds rewrite their `dist-<lane>` concurrently). Test: `tests/router-usage.test.ts`.
- Pay-per-use: `routerUsage` (text scan of sources in files importing `@rivetjs/router`; `forms` = `@rivetjs/forms` anywhere or `Form` in a file importing `@rivetjs/ui` ⇒ `forms` + `navigate`; codegen `forms` → `_brand(_go)` first in every router handler, `client/CLAUDE.md` "Router brand") decides `searchParams` / `navigate` / `params` / `activeLinks` (`<Link … active`) / `prefetch` (`prefetch="document|prerender"`, also `data-rivet-prefetch=`, `prefetch={"…"}`) codegen. Off ⇒ nothing generated for it (byte-identical output). Options override detection.
- `resolveId`: browser graph importing `*.server.*` or `@rivetjs/router/server-only` → `this.error({ message, id: importer, plugin: "vite-plugin-rivet-router" })` (the real plugin name: builds overwrite `plugin` with it anyway); message = `[rivet:router] <id> is server-only and cannot be imported by browser code (imported from <importer>)` + `fix:` / `docs:` lines (DIAG-VERBOSE; quoted in docs `guides/security/server-only-code.md`, `best-practices/secrets-in-server-files.md`; test `tests/codegen.test.ts`). Skipped for SSR and compiler fact resolutions (`_factsResolve(id, importer)` from `@rivetjs/compiler/vite`, an in-flight registry — not `resolveOptions.custom`, which rolldown 1.2.12 loses under concurrent context resolves).
- `routeRules` (`rivetRouter`): checked at config time (`compileRules` from `server/route-cache.ts` + JSON-data check: finite numbers, strings, booleans, plain objects / arrays; `isr: true` for no expiry), carried on the `codegen` object → `entry.server.tsx` `export const routeRules = <JSON>;` (only when non-empty: unset apps byte-identical). Test `tests/route-cache.test.ts`.
- Codegen output is ordinary TSX so the compiler treats it like app code; change templates, not generated files. `tests/codegen.test.ts` pins template shapes; `tests/generated-types.test.ts` type-checks output under `strict`.
- `routes.ts` wraps every server-module loader and `universal[id]` in a generated `once()`: builds memoise the import promise (rejections retried); `import.meta.env.DEV` returns the loader itself (each dev request re-imports, so edits are never pinned). Hence `/// <reference types="vite/client" />` in `routes.ts`.
- Dev middleware, `mode: "static"`: `GET|HEAD <page>/_data.json` (the client's static data URL, `dataURL(url, "static")`) is rewritten (`staticData`) to `<page in trailingSlash form>?_rivet=data` + `accept: application/json` before the listener, as `prerender` renders it — dev has no prerendered files, so before this every client navigation 404'd into `_404` (`tests/groups.test.ts`). Dev also answers pages a build would not prerender (dynamic without `entries`).
- Dev middleware: one `createApp` + listener per `entry.server.tsx` namespace (WeakMap; Vite returns a new namespace after invalidation). `devResume.manifest` is a getter (dev manifest grows as modules compile).
- `dev-mount.tsx` fetches route data with `accept: application/json` only (the old `x-rivet-data` header was never read).
- Dev regenerations serialize (`regenerations` chain); route table regenerates only when in-file server exports appear/disappear; `*.server.ts` edits send `rivet:data` (data refetch + remount).
- `prefetch` (`true` / `"document"` / `"prerender"`; validated in `rivetRouter`; option name = `RouterUsage` key): `entry.server.tsx` imports the shell and exports `document = documentPrefetch(shell, { default?, routed?, routes?, eagerness? })` (`routed` + `routes` = `routePathRegExp(every route pattern incl. base)` unless single-route mode; `prefetchPaths: false` drops `routes` (validated boolean, on the `codegen` object); `eagerness` only when `prefetchEagerness` is set and not `moderate`) instead of re-exporting it; `app.tsx` unchanged. Unset/false ⇒ byte-identical entry. `prefetchEagerness` validated in `rivetRouter`, carried on the `codegen` object (also when `prefetch` is detected, not set).
- `clientRouter` (default `mode !== "static"`): codegen option; `false` adds `standalone: false` to every App router clientEvent (click / pointerover / focusin / pointerdown / popstate / `rivet:go`), so they alone (with the routes region's router-location-only binding, runtime `onlyLocations`) do not make a page resumable → inert static pages ship zero JS and links load documents; interactive pages still route in place (STATIC-ZERO-JS 2026-10-12).
- `preload: { background }`: validated in `rivetRouter` (non-negative bytes); codegen adds `export const preloadBackground = N` to `entry.server.tsx` only when set (`createApp` default; adapter `preload` options override). Dev manifests carry no sizes (dev chunks are whole transformed source files, no bundle graph; sizes would also flip the 8 KB automatic-`visible` cutoff), so dev keeps `visible` chunks viewport-only.
- `trailingSlash` (`never`/`always`): validated in `rivetRouter`; codegen adds `export const trailingSlash` to `entry.server.tsx` (absent by default); `transform` rewrites `shared/slash.ts`'s constant (`SLASH_MODULE`) in client + server builds (dev too); `ssr.noExternal` gets `@rivetjs/router` so the server bundle carries the rewritten copy.
- `app.tsx` route tables (RA1/RA2/Z4): module-level `PATHS<level>` + `ROUTES<level>` rows `[route id, depth, page index, enter, failure]` + `PAGES` (data-driven `() => import()` table; `page(i)` memoizes one `lazyComponent` per page, Z5); App passes `routes = { paths, route(n) }` (`RouteTable`, `@rivetjs/runtime/router`) so paths compile once per process and only the matched route is defined. One shared `fail<j>` per distinct `_error` chain and one `enter<k>` per persisted layout level (layout + nested `Router`), picked by row index — the App chunk no longer grows a closure per route (routes-500 App chunk 544 → 94 kB min). `modules` maps paths to `preloadPage(page(i), PAGES[i])` (one shared load per page module, retried after a failure — no `import()` per server request); route `load` = `_take` (nested) `?? _ssrLevel(work, ok, failed, land) ??` the browser chain (`Promise.all([routeData, loadPage])…then(loaded, failed).then(_landed)`): on the server `_ssrLevel` applies the handler's `ServerData` through the same steps synchronously (no promise hops, no page import; not in csr mode). Capture order of the route-table closures follows first use (`nest` before `router`); click / intent handlers pass it (`interceptClick(event, router, modules)`, `routableAnchor(event, modules)`) so links no page matches load documents. Endpoints the server matches before a later overlapping dynamic page pattern (`overlaps`) become `[path, _endpoint]` rows spliced in at their table position (`shadowed`; none ⇒ byte-identical `const modules`). `routePathRegExp(patterns)`: trie RegExp source of all route paths over `pathname.slice(1)` for document prefetch (`tests/codegen.test.ts`). Nested layouts / `_404` stay static imports (lazy layouts need level-load preloading; unmatched 404s render synchronously).
- Single-route mode (Z1): one static page route, server/static mode, no `navigate`/`searchParams`/`activeLinks`/nested layouts → no click / intent / popstate client events (no eager router chunk; template `minimal`: eager JS 0 B). Links are plain full loads there.
- Lazy router (Z1): multi-route App listeners (click / pointerover / focusin / popstate / `rivet:go`) are `clientEvent(…, { preload: "intent" })` → page idles with 0 B eager JS; inline loader boots the App chunk on first link intent/click. Nested-layout `_sync` and active-link marking run via `(arm(), …)` → `_arm(router, …effects)` (client/index.ts; once per router) instead of idle `clientEffect`s. Dev client-render fallback deletes `$r.p().n`. Link intent boots the router (loader + `dom-resume` intent replay); the intent handler also `arm()`s. First click (routes-10, Slow 4G + 4× CPU, 5 runs p50): cold click 262 ms (645 before the fetch-only modulepreload hints) / hover+click 87 ms vs eager 229 / 82 ms. Landing: idle-executed JS 126.6/45.0 → 85.7/30.5 KB min/br per page (it still boots for its own idle effects).
- Stopped link clicks (RESUME-PINS 2026-10-12): non-csr Apps add `clientEvent(document, "click", (event) => event.cancelBubble && interceptClick(…), { capture: true, preload: "intent", match: "a" })` after the bubbling one: on a resumed page the loader's document capture listener runs a link's own handlers first and a press handler's `stopPropagation` (cdk / ui Link) never let the click reach the bubbling router listener (resume fuzz T31 cdk `/links` `#current`, `/sidebar` `#home`: no `tabindex=-1` target focus; ui `/visual/card` `href="#"` scrolled to the top and lost the hover). Clicks not stopped skip it (`cancelBubble` false); csr Apps have no resumed handlers.
- ROUTER-LAZY (2026-10-12): the App's document listeners carry clientEvent `match` — click / pointerover / focusin `"a"` (pointerover / focusin `"a,form"` with live pages: hovering a form warms the live page's data readers — the measured live-form win, kept by ruling 2026-10-12), live pointerdown `"form"` — so a first click / hover outside links (a signal handler's button, plain text) neither runs them nor loads the App chunk; popstate / `rivet:go` unfiltered. Docs (`fold-nogroup` vs this, CDP coverage, 3 runs): `/` copy-button click 20 scripts 149,710 / 48,514 B br → 10 / 77,377 / 29,205 (no resume-App / `_layout` / SiteFrame); `/learn/resuming/` hover over text 11 scripts 129,515 / 40,126 → 1 / 24,432 / 8,836.
- `vite.ts` `preloadDeps` (`build.modulePreload.resolveDependencies`, unless user sets `modulePreload`): drops dynamic-import deps already in the host chunk's static closure (routes-500 App chunk 93.9 → 76.7 kB min).
- `vite.ts` forwards `devtools`, `css`, `images` and `staticIcons` (only when set: unset = the compiler default, on) to `rivet()`. `bridges` (framework bridges, `rivet({ bridges })`): non-empty → `rivet()` returns the framework plugins + bridge host before the compiler, found by name (`vite-plugin-rivet`); csr mode throws (islands are server-rendered); test `tests/bridges-option.test.ts`.
- `fetchAhead` (bridge D-lean, 2026-10-12): codegen adds `export const fetchAhead = true` to `entry.server.tsx` when document prefetch is on (`document` + `prefetch`); `createApp` passes it as `preload.ahead` (islands-only lean pages keep the runtime fetch-ahead; test `tests/preload-option.test.ts`).
- `vite.ts` passes `resume.lazyOwned: [.rivet/app.tsx]` to `rivet()` (route chunks preloaded by the App's own dynamic imports are not inlined into `state.l`).
- Everything dev-only stays behind `serve` / `import.meta.hot` so builds carry none of it.

## Gotchas

- `vite.ts` `transform` rewrites `shared/base.ts` for i18n client builds with a regex on `import.meta.env?.BASE_URL`; changing that expression in `shared/base.ts` breaks the build (it errors loudly).
- i18n client builds also wrap `underBase` (`export function underBase(` must stay; errors loudly) with the i18n api's `clientPaths` RegExp: other locales' URLs are not client-routable (links/`navigate()`/redirects load the document; switch = navigation). Without it a held link click (Z1) switched locale in place with the wrong build's messages.
- i18n dev server (`serve`, client transform only): `underBase` also requires the target path's locale (first match of the i18n api's `devPaths`, one pattern per locale) to equal the page's, read once at module load (`location.pathname`); SSR copy untouched. Same effect as the build wrap: a cross-locale link loads its document (dev used to client-navigate with the old locale's module graph). Test: `libs/i18n/tests/browser.test.ts` "a link to another locale loads its document".
- `mode: "csr"` + `adapter` → throws; csr rejects `.server.ts`.
- `routerUsage` does not scan published deps: set `rivetRouter({ navigate, params, searchParams })` when only a package uses them.
- Custom `resume.entry` must provide `[Navigation, navigation]` itself when `transitions` is on.
