# @rivetjs/router/server

> **Keep this file current:** ALWAYS update this CLAUDE.md in the same change whenever code in this directory changes (APIs, layout, commands, invariants, gotchas).

Web-standard request pipeline: route match → CSRF → request handlers → guards → actions → parallel loaders → streamed resumable render; plus the JSON data endpoint client navigation uses and endpoint routes (`routes/api/*.ts`). No Node APIs here (fetch/edge adapters run it).

## Entry points

`@rivetjs/router/server` → `index.ts` re-exports:
- `handler.ts` (all): `createHandler(AppOptions)` → `AppHandler` (`AppHandlerContext`), `RequestEvent`, `Cookies`, `ServerModule`, `AppRoute`, `RenderInput`, `ErrorInput`, `ErrorInfo`/`ErrorPhase`, `encodeData`, `DATA_PARAM`, `BodyLimit`.
- `app.ts`: `createApp(AppConfig)` (generated entry + document + manifest → handler), `mergeHeads`, `GeneratedEntry`, `PageInput`. CSP: default / `{ trustedTypes }` → `nonceCSP` (sync); `{ directives }` → `import("./strict-csp.ts")` at createApp (validates once; bad directives = rejected promise at startup, unhandled → process fails; requests before it settles await it in `respond`, later ones are sync). ~3 ms cold, once. `preload: { background }` (number, or `(url) => number | undefined` per request) → `renderDocument` → `renderResumable` `preload` (background prefetch byte budget of `visible` chunks, runtime default 1 MiB; docs-kit frames pass `0` via `framePreload`) + `lean` (boolean or `(url) => boolean | undefined`: empty schedule, no fetch-ahead `<link rel=modulepreload>` of a lazy router's chunks; docs-kit `site.leanPages` via `pagePreload`) + `ahead` (boolean; default the entry's `fetchAhead` = document prefetch on: islands-only lean pages of bridge apps keep the runtime fetch-ahead, D-lean; `resume.chunks: "route"` builds (manifest `fetchAhead`): every page also fetches its own handler chunks ahead, never evaluated; ignored with `lean`); unset → the entry's `preloadBackground` (`rivetRouter({ preload })`, codegen export) → runtime default; test `tests/preload-option.test.ts`.
- `strict-csp.ts`: `strictCSP(nonce, { trustedTypes, directives })` (sync, imports `shared/csp-directives.ts` statically). Own module, re-exported by `index.ts` only: **`app.ts` must not import it statically** (rolldown `INEFFECTIVE_DYNAMIC_IMPORT` → merge code back in the server entry, +673 B gz). Tests import it from `../server/strict-csp.ts`.
- `render.ts`: `renderPage` (always a `Response`), `renderDocument` (`Response | Promise<Response>`; what `createApp` uses), `failureMarker`, `headTags`, `DocumentShell`/`DocumentInput`/`DocumentParts` (`DocumentInput.inlineStyles`: the page's subset of `AppConfig.inlineStyles` (URL → CSS), `headTags(head, input)` writes them; shells mapping `styles` by hand link everything).
- `inline-styles.ts`: `InlineStyleManifest` (`.vite/rivet-inline-css.json`) + `inlineStylesFor(manifest)` → `(styles) => URL → CSS | undefined` per page: `always` all listed; `auto` all listed when their `br` total ≤ `maxTotalBrotli`, else each with `bytes` ≤ `limit`; cached per joined list. No Node APIs (sizes precomputed at build).
- `module.ts`: `serverExports`, `mergeServer`, `loadServer`.
- `early-hints.ts` (type `EarlyHintsOptions` re-exported by `index.ts`; module loaded by `createApp` via dynamic import only with `earlyHints`, `respond` waits for it like `directives`): `EARLY_HINTS` (`Symbol.for("rivet.earlyHints")`, the node adapter's per-request `HintWriter` on the Request), `isAsset(url, base)` (`<base>/assets/`), `styleLinks(urls, inline, base)` (linked, non-inlined build-asset sheets → `rel=preload; as=style`), `headLinks(head, base)` (build-asset font preloads only — preconnects / other head links may be per-visitor loader data and would reach every later visitor, EH-MC review MED-1; header-unsafe URLs dropped). Only build assets are preloaded: Chromium reuses an early-hint preload only when cacheable — a revalidated `/site.css` was fetched twice, FCP 224 → 324 ms (EARLY-HINTS bench, fast loader). `createApp({ earlyHints: true | { runtime, links } })` (not in dev): per route id `hints` memo (styles + `routeStyles` + learned head links + `links` + runtime `modulepreload`), learned from each render's merged head (`learn`, invalidates the memo on change); `Link` header on page responses (unless set); handler hook writes them as 103 when the request carries a writer (page GET / HEAD; route-cache hits and detached fills carry none). Tests `tests/early-hints.test.ts`.
- `route-cache.ts` (subpath `@rivetjs/router/route-cache`; types re-exported by `index.ts`): `withRouteRules(handler, rules, csp, base, { maxBytes, maxEntries, origin })` → handler + `[ROUTE_CACHE]` lookup `(method, origin, pathname, search, header)` (`Symbol.for("rivet.routeCache")`, node fast path), `compileRules(rules, origin?)` (validation `TypeError`s incl. `isr` without a fixed origin, `varies` naming cookie / authorization, `cdn`; pathname memo bounded 2048), `normalPath` (decoded match path + canonical flag), `revalidate({ path, tag })` (process-wide registry of stores, WeakRefs; voids each store's matching in-flight fills: `store.filling` `{ path, tags, void }`, same path / tag predicate; then calls `globalThis[Symbol.for("rivet.revalidate.broadcast")]` if set — node `adapters/cluster.ts` relays it to the other workers, which call the `Symbol.for("rivet.revalidate.local")` drop this module registers at load), `notModified`, `RENDER_FAILED`. Store: Map + CLOCK bit, 32 MiB / 5000 default, `page.size` = body + key + headers + `charge`d adapter copies, page > maxBytes/4 never stored; doorkeeper (`secondMiss`: keys with a query string, a non-empty `varies` / learned header value, or any key without a fixed `origin` are stored on their 2nd miss; Set cleared at 10k); single flight (`flights`: waiters get the page or render themselves when uncacheable); stale hit → one background `fill` unless backing off (`page.retry`; refresh 404/410/3xx/`Set-Cookie` deletes, else `failures` doubling 1 s → 5 min). Key = origin + decoded path + query + `varies` + `cache.learned` (response-Vary names, per rule). `fill` renders a detached `new Request(url, { headers })` without `VISITOR` headers (`cookie`, `authorization`, `forwarded`, `x-forwarded-*`, `x-real-ip`, `true-client-ip`, `x-client-ip`, `cf-*`, `fastly-client-ip`; unless in `varies`) and with a context without `address` (a client going away does not abort it), refuses `Vary: *` / credential Vary without `varies` or with `cookies: true` (then a credentialed visitor gets `handler(request)` — their own render — and the key goes into `personal` for `PERSONAL_MS` 10 s: requests of it render once, as themselves, with no fill first; bounded 10k), reads the body from the `DIRECT_BODY` sink (one copy; stream fallback), and — when the response policy equals the app's `csp(nonce)` and `hash` is set (default / `CSPOptions` apps) — hashes only the nonce'd elements on the latin1 view (`shared/csp-hash.ts` `noncedSources` + `hashPolicy`, digests over byte ranges) and cuts the nonce attributes out by byte range; nonce elsewhere → not stored (warn once per path); a policy trusting the nonce that is not converted → not stored. Not stored either: `RENDER_FAILED` on the detached request (app.ts render `onError`), a matching `revalidate()` since start. Answers carry `DIRECT_BODY` (`bytesResponse`). The MISS response keeps its own nonce + policy with the stored page's weak ETag (SHA-1); uncached answers keep the response's own `cache-control`. Web-standard only. Tests `tests/route-cache.test.ts`; `tests/route-cache-csp.test.ts` (Chromium; Firefox when installed, skipped in CI): stored hash + `'self'` policy runs the loader's `import()` chain, console clean; injected inline script blocked on MISS + HIT, parser-inserted same-origin `<script src>` runs on HIT only (`'self'` delta); pins that `import()` is blocked and `createElement("script")` allowed under `hashes + 'strict-dynamic'` (why no `'strict-dynamic'`; WebKit allows both).

## Layout

- `handler.ts` — the pipeline (one closure per request), cookies (`HttpOnly; Secure; SameSite=Lax` defaults; header parsed on first access), `privateCache` when a cookie is set, digests for hidden 5xx (`_digest`, internal export for `app.ts`), data/keep/deps wire. Absent handlers/guards are skipped without `await` (each costs microtasks).
  - `serializeCookie` validates (TypeError): name token, `path` (`/…`, no `;`/CTL), `domain` (host name), finite `maxAge`, valid `expires`, `sameSite` value, `none` ⇒ `secure`, `__Secure-`/`__Host-` (secure; `__Host-`: path `/`, no domain), name + encoded value ≤ 4096.
  - `merge(response)`: raw `Response` from `onRequest(…)`/`on<Method>`/guard/action/endpoint gets event `set-cookie` appended, other event headers only where it lacks them, `privateCache` when a cookie was set; immutable headers → copied `new Response(body, response)`.
  - `early()` (data/enhanced JSON): `Location` passing `unsafeTarget` and relative or `http(s):` → `{ redirect }`; else `{ reload: true }`.
  - Actions: `Object.hasOwn(actions, name)` + function check (no `Object.prototype` members).
  - Data requests: `url.searchParams` only when `url.search` contains `_rivet`; router params stripped textually (`withoutRivet`, `shared/data.ts`) so loaders see the query bytes the page URL had.
  - Dev only: a layout loader rejecting with 401/403/redirect logs a one-time hint per layout id (`accessHint`): loaders are skipped for kept layouts → auth belongs in `guard(…)`.
- `security.ts` — `crossSite()` (CSRF) and `limitBody()` (413).
- `deferred.ts` — deferred loaders (`load(fn, { defer: true })`, PPR-T01): `deferredHandle(promise, dev)` (frozen `{}` + non-enumerable `then`; dev Proxy throws `DeferredDataError` on field reads), `startDeferred(run)` (rejection pre-caught), `lateEvent(event)` (header / cookie writes throw). Loaded by `handler.ts` via `import("./deferred.ts")` only when a matched module's `load[DEFER]` is set (module-level `deferredModule` memo); document requests start deferred loaders in the loaders' `Promise.all` turn, assign handles after it, `RenderInput.deferred: true` → `app.ts` `PageInput.deferred` → `stream: {}` when `config.stream` is unset. Data requests await them. Tests `tests/deferred{,-types,-app}.test.ts` (`fixture-deferred`).
- `shell-cache.ts` — route rule `shell` (partial prerendering, PPR-T23 = spec T2 + T3; `docs/guides/routing.md` "File routes: shell cache"): `createShells(host: ShellHost) → ShellServe` (called by `withRouteRules` when `createApp` passes the module), `shellCut(text)` (byte offset after the root state tail). Per request a `Run` (`ShellRequest`, put on the request under `Symbol.for("rivet.shell")`) answers `begin()` with a hit / fill `ShellPhase` or undefined; fills track request reads (allow-list Proxies over the event, `TrackedParams`, deferred-handle gate), hold bytes to the cut and store `ShellEntry` (bare prefix + nonce slots + `h` + shell loader data by reference) in the route rules' `Store`; hits (`Composer`) send the prefix with the live nonce at once, replay the page and forward the rest after the holes script; mismatch → evict + sticky + reload script. Replay (PPR-T3B): muted by default — `ShellBody` (`BodyWriter` subclass, `render.ts` option `body`) compares the shell's bytes in place against the prefix (nothing handed off) and `@rivetjs/runtime/server-shell` `shellHook` (option `shell`) skips the root state encode, thawing the fill's numbering (`entry.seal`, sealed at the fill's first patch; `entry.tail` = where the root tail starts, counted by the fill's `ShellBody`) for the patches; every 64th hit (`VERIFY`) and unsealed entries replay in full (whole prefix compared, PPR-T23). H-holes (PPR-T6): a fill whose `shellHook` retained its holes stores `entry.holes` (else `holesWhy`); muted hits of such entries (not VERIFY, not test `{ replay: true }`, not `RIVET_SHELL_HOLES=0`) answer `x-rivet-cache: SHELL-HIT` / `SHELL-STALE` (replayed hits: `…-REPLAY`) and render `render.ts` option `holes` = `shellHoles(entry.holes)` instead of the app (no layouts / page / document); `ShellPhase.handle(promise, dev, index)` — on a hit fills `slots[index]` (the retained handles resolve the hit's promise via `shellSlots()`), on a fill returns a handle reading `shellSlots()?.[index] ?? own` (own slot `STALE` once the fill's stream ends). Charge: +1 kB per hole + 64 B per seal table entry. Test hook `Symbol.for("rivet.shellTest")` `{ holes: n }` / `{ full: true }`. Dev: probe only (`SHELL-BYPASS <reason>`). Imported only by `app.ts` (dynamic, with `route-cache.ts`) when a rule has `shell` through `shell-build.ts` `SHELL_BUILD` (undefined; rewritten by `build/vite.ts` to an `import()` of this file when the build's `routeRules` name `shell` — never import `shell-cache.ts` by value elsewhere, rolldown would emit its chunk into every app): other apps' bundles have no shell chunk (zero-cost); runtime-only shell rules → `createApp` TypeError. Tests `tests/shell-cache.test.ts`, `tests/shell-app.test.ts` (`fixture-shell`).
- `module.ts` — `serverExports(module, file, server?)`: one pass over the module's export names, reads the wrapper tag (`Symbol.for("rivet.server")`, `shared/server-exports.ts`) → `ServerModule` key = kind (`load` `guard` `actions` `entries` `headers` `onRequest` `on<Method>`), plus `prerender` / `csrf` by name; cached per module object (WeakMap). Errors (thrown at the first request that loads the module, file named): two exports of one kind (`a` and `b` are both `load(…)`); an untagged export with a former magic name (`serverLoad` … `onOptions`; with `server` = raw-loaded `*.server.ts` / `.ts` endpoint also the former sibling names `load` `guard` `actions` `entries` `headers` `GET` … `DELETE`) with the wrapper fix in the message. `mergeServer(inline, sibling, files)` cached per (inline, sibling) pair (hot edits = new objects = new merge); one kind in both → error. `loadServer(load)` = `load?.()`: generated loaders (`build/codegen.ts`) already return normalized `ServerModule`s.
- `app.ts` — `routeRules` (config, else `entry.routeRules`; dev: headers + `shell` keys (probe)) → `import("./route-cache.ts")` (+ `import("./shell-cache.ts")` when a rule has `shell`) at createApp (malformed rules reject at startup, unhandled; requests before it settles wait), returned handler delegates and exposes `ROUTE_CACHE` through a getter once loaded; render `onError` sets `Symbol.for("rivet.renderFailed")` on the request (route cache: error-fallback pages not stored). `renderCache` (`RenderCache`) → `import("@rivetjs/runtime/server-cache")` at createApp; `render` runs `renderDocument` inside `withRenderCache({ cache, variant, nonce, signal, resumable: manifest present })` (render-cache hook H1). Without either: no import, same code path. Head rank merge (defaults −1, layouts, page, kit components), CSP header, i18n variant/manifest by `locals.locale`, dev pages (`data-rivet-dev`, embedded data, `devResume` modes), route styles.
- `body.ts` — direct page bodies: `BodySink` (`write(view, done)` / `end` / `error`), `DIRECT_BODY` (`Symbol.for("rivet.body")`, own property of every `renderPage` / `renderDocument` Response: `(sink) => boolean`). Web-standard (no Node types); the node adapter attaches, everything else reads `body`.
- `render.ts` — internal options `body(enqueued)` (a `BodyWriter` subclass instead of `BodyWriter`; `BodyWriter` exported for it) and `shell` (runtime `ShellHook`, passed to `renderResumable`): shell routes only (`shell-cache.ts` via `ShellPhase.render`, spread by `app.ts`). `renderResumable` / `renderToWriter` into a `ReadableStream` (derived model builds, M2 C3 2026-10-20: the compiler Vite plugin resolves this file's `@rivetjs/runtime/server-resume` import to a module whose `renderResumable` is `renderDerived` — no router code for it; outside Vite a derived manifest renders as serialized) (high-water mark 0) or a direct sink, with back-pressure. Consumers (A, 2026-10-07): none yet → handed-off chunks park (≤ `QUEUE` 64 KiB, then the renderer waits — unread bodies still stop there); stream read (`pull` = a read waits) → parked chunks enqueued, later ones straight to the waiting read; `attach(sink)` (`DIRECT_BODY`, false once read / cancelled) → parked + later slab views go to the sink, slabs pooled (process-wide, 32 × 64 KiB) and reused once the sink released every view (stream views are never reused). `close` / `fail` / `cancel` replace direct `controller` calls (a consumer arriving after the end still gets the parked bytes + close / error). Router resume lane 1000 rows (in-process e2e, server + client + gRPC in one process): CPU 6.55 → 5.9–6.1 ms/req, peak RSS 280 → 262 MiB, HTML identical. Also: kit head hold; dev `discardState`; `epilogue()` (string written after the body, before `around.end`: deferred-redirect client redirect, `app.ts`). Non-hold renders get a **byte writer** `BodyWriter` (module-level class over runtime `SlabWriter`, the core shared with `NodeStreamWriter`: `writeText` / `writeBytes` / `writeInteger` / raw-slab `claim(n)` / `bytes` / `offset` / `commit(end)` come from it; `write` here: Node / Bun: slabs are `Buffer`s (`Buffer.allocUnsafeSlow`, feature-detected `utf8Write`) and `write` is one native `utf8Write`, so the runtime's `putText` / raw-row long strings take the native encoder too (ssr-bench text grid `strings=2`, rivet-router lane Docker c=1: CPU 3.59 → 3.23 ms/page, p50 3.94 → 3.57 ms; `putText` was 24% of CPU on `Uint8Array` slabs); other hosts: strings ≤ 64 chars copied as ASCII by hand, else `encodeInto`, into a 64 KiB `Uint8Array` slab; pooled for direct sinks): scalar-only compiled records and list rows are written in place (`rawTemplate` / `rawRow`) (router lane 1000 rows: 2.44–2.48 → 2.17–2.25 ms CPU/page in-process, G-RES; `tests/render.test.ts` raw-slab case); views of the slab are handed off at 16 KiB (`FLUSH_AT`, bytes), on every write while the consumer is behind, or in a microtask (renderer paused on pending content → shell flushed at once); a small synchronous page = one chunk. Fullness is cached (`full`: QUEUE bytes parked or a direct sink's wait — `threshold` 0 then, so every write flushes and returns the shared wait —, cleared by `pull` / sink drain → `ready()`; `cancel` makes the next hand-off throw) — `desiredSize` per write was ~3% CPU. Hold renders (kit head) keep the byte path too: the held writer exposes `writeBytes` / `writeInteger` / `writeText` (escaped on hold; items buffered as strings / `Uint8Array`s, replayed in order on release; `tests/render.test.ts`). P1: router lane allocations −42%/request, peak RSS (local, unbounded heap) ~430–1400 → ~350–440 MiB. Only real waits are `await`ed in the render driver (a bare `await` would let the flush microtask split the page).
  - Direct-sink waits (LAZY-FLIP 2026-10-21): every wait a sink returns gets a rejection handler (`gone` → `cancel()`: the next hand-off throws, the render ends) — in `flush` (mode 2) and in `attach`. Before, the scheduled flush (`later`) and the attach-time `.then` dropped it: a client that stopped reading and left while a page waited on the node adapter's backpressure (256 KiB buffered) rejected that wait unhandled, and Node exits on an unhandled rejection. Test: `tests/node.test.ts` "a client gone while a streamed page waits on backpressure".
  - Retention (IMPL-ALLOC 2026-10-09): the body `ReadableStream` (`bodyStream(out)`) and the `DIRECT_BODY` hook (`directBody(out)`) are built at module level and close over the writer only; the writer's `enqueued` callback is swapped for a no-op when the render ends. Node keeps a Response's web stream and its source reachable through scavenges until the next mark-compact (unread or read): built inside `stream()`, the source closures shared its V8 context (factory, page data, recorder) and every request's render graph was promoted (in-process `/resume` 1000 rows: 133 → 3 KB/request old-space growth, mark-compacts 1.27 → 0.03 per 100 requests under a 128 MB heap, CPU 1.51 → 1.24 ms; Docker c1 2.45 → 2.04 ms CPU/page, HTML identical). Never let anything a Response reaches close over the render's scope; `tests/render.test.ts` checks a finished render's unread Response retains none of it (full GC + WeakRef).
  - Ids: the render call (`renderResumable` / `renderToWriter`, not `factory` — the renderer visits what it returns, and pending `Async` content later, under that owner) runs inside `withIdScope("rv", …)`: every page render counts `createId` from `rv0` (reproducible HTML / ETags; docs-kit incremental prerender canaries match). Concurrent / streamed renders each own their counter (owner context, not ALS). Ids made outside the render (loaders, module level) are `rvs…` (`@rivetjs/runtime/id`). Tests `tests/render-ids.test.ts`.
  - U7 (failures): `renderDocument` hands out the `Response` only once the renderer really waits (pending content; two `Promise.race([render, TICK])` probes so an already-settled rejection — `renderCore` returns `Promise.reject` for sync traversal errors, +1 tick with `stream` — still counts as "before") and bytes are queued, or the render ended. Before that a failure throws/rejects → handler `phase: "render"` → `settle()` → `_error` page, 500 + digest. A synchronous page answers synchronously (no extra promise); a big page that hit back-pressure answers at once (consumer must read). After it: `onError` (app: `report` with digest, `phase: "render"`, route) → document ends cleanly: `failureMarker(nonce, digest)` (`<script nonce>` dispatching `rivet:resume-error` `{ phase: "render", digest, error }`) + shell `end` (no `around.end`); hold not released yet / consumer cancelled → errored body. Bench (handler micro, in-process, body drained): 5 rows 35.4–37.1 → 33.5–34.2 µs, 200 rows 568 → 557 µs, async page 38.1–41.4 (eager) vs 38.5–39.6 µs.

## Request order (handler.ts — keep)

1. Match (`compileRoutes` from `@rivetjs/runtime/router/server`: the bucketed server matcher, same first-match result as the linear browser one); none → 404 (inside root layout when its guard passes, HTML GET only). `trailingSlash` set (build constant `TRAILING_SLASH`): page GET/HEAD in the other form → 308 to `slashPath` (query kept; data requests `{ redirect }` via `early`); endpoints/other methods untouched.
2. Method not in GET/POST/PUT/PATCH/DELETE/OPTIONS (HEAD = GET) → 405.
3. Unsafe method (not GET/OPTIONS): **CSRF** (`crossSite`) unless route module `csrf === false` → 403; then `limitBody`. Then a malformed action name (bad `%` encoding) → 400.
4. Page route, non-GET, no `?/action`, no own `on<Method>` → 405 with `Allow`.
5. Per module outer → inner: `onRequest(…)`, then `on<Method>` (endpoint route's own `on<Method>` excluded here). `Response` ends; `HttpError` throws. OPTIONS: `onRequest(…)` then `onOptions(…)` per module (route's own module included, page or endpoint); none answered → 204 + `Allow` (route's methods + OPTIONS); no guards/loaders. Compiler `server_split.rs` `HANDLERS` strips `onOptions(…)` from browser builds (canary: `fixture-inline`).
6. Early hints: `AppOptions.earlyHints(route, request)` for HTML page GET / HEAD (no data request, no action) — the 103 moment, before the slow part.
   Then guards outer → inner; first non-void (`Response`/`HttpError`) ends.
7. `headers()` of every module. Then shell rules (`request[Symbol.for("rivet.shell")]`, page GET without action, not a data request): `begin(route, event, headers)` → hit (stored loader data, prefix goes out now) / fill (tracked events) / undefined.
8. Endpoint route: own `on<Method>` must return a `Response`; none → 405 with `Allow`.
9. Action `POST ?/name` (name ends at `&`): result / `fail()` → status; default redirect → 303. Enhanced (`accept: application/json`) → JSON; + `x-rivet-revalidate` and status < 400 → loaders rerun, single-flight `{ action, data, head?, deps? }`; a `redirect()` (returned or thrown) back to the page's own path without query / fragment (`backHere`) → `{ redirect, status, data, head?, deps? }` (PRG single flight, loaders on the query-less URL; other targets: `{ redirect, status }` only). Answers are `ActionAnswer` / `DataAnswer` (`shared/data.ts`; `json()` is typed to them). No custom form header: forms send only `accept` (+ `x-rivet-revalidate`); the form id is the `_form` field. Cookies: `shared/cookie.ts` `parseCookies`.
10. Loaders in parallel (skipping kept layouts from `_rivet_keep`, `keepable`; shell hit: non-deferred loaders skipped); layouts reading `event.url`/`request` reported as `byURL`. A deferred loader's `redirect()` → `RenderInput.moved` (client redirect at the document's end).
11. `?_rivet=data` → JSON `{ data, status, head?, keep?, byURL?, deps? }` (`private, no-store`); else render (`no-cache` default).

## Endpoints + CSRF rules

- Endpoint = plain `routes/api/x.ts` exporting request handler calls (`export const GET = onGet(…)`, `onPost(…)` / `onPut(…)` / `onPatch(…)` / `onDelete(…)` / `onOptions(…)` / `onRequest(…)`; any export name) (or `x.server.ts` without a page). Must return `Response`; non-Response → 500 `"<id>: onGet must return a Response"` (the kind).
- CSRF applies to every non-GET request, page and endpoint alike, before any handler: `Origin` present → must equal URL origin; else `Sec-Fetch-Site` → must be `same-origin`; else form content types (`x-www-form-urlencoded`, `multipart/form-data`, `text/plain`) → 403 outside dev. JSON without either header passes (non-browser clients).
- Opt-out only per route module: `export const csrf = false` (webhooks). Layout `csrf` is ignored.
- Origin = request URL origin: behind TLS proxies the adapter must set it (`origin` / `trustProxy`), or every action 403s.
- Body limit: default 1 MiB, multipart 10 MiB; `Content-Length` first, then streamed count → 413.

## Rules / invariants

- Seeded locals (SEEDED-LOCALS 2026-10-20): `AppHandlerContext.locals` → `locals = seed ? { ...seed } : {}` at request start (shallow copy, caller's object never written; no seed = the old `{}`, no extra allocation); everything that sees `event.locals` / `ErrorInput.locals` / `RenderInput.locals` (app.ts i18n locale + error locale) sees it; never encoded (HTML / state / data answers carry loader data only); `route-cache.ts` `wrapped` bypasses the store (no read, no fill) when `context.locals` is set, rule headers kept. Tests `tests/seeded-locals.test.ts`.
- Redirects: absolute targets must match request origin unless `redirect(url, { external: true })` (else 500). Data/enhanced requests get `{ redirect, status }` JSON, never a 3xx.
- 5xx messages hidden outside dev: `Internal Server Error (digest <id>)`; `onError(error, request, { digest, phase, route })`. 4xx `HttpError` messages are exposed.
- `RenderInput.byURL` is always present on page renders (shared frozen `[]` when empty): the client treats its presence as "server render" (`client/layouts.ts` `at`). Never drop it.
- Wire fields omitted when empty (byte-identical responses when a feature is unused). Data encoded with the resume table (`encodeData`: Date/Map/Set/BigInt/cycles); a table holding built-in entries (RegExp / URLSearchParams / binary / errors) also gets `x` = `AppOptions.builtins()` (the resume manifest's `builtins` chunk URL, `app.ts`), loaded by the client before decoding.
- `RequestEvent`: `route.id` (`null` unmatched), `isDataRequest`, `setHeader`/`setHeaders` (`set-cookie` → TypeError), `cookies.getAll()`. `parent()` deferred.
- `trailingSlash` has no `AppOptions` field: the handler reads `TRAILING_SLASH` (rewritten in the app's server bundle by `build/vite.ts`); a plain `createHandler` outside Vite ignores. Tests: `tests/trailing-slash.test.ts` (per-policy copy of `server/` + `shared/`).
- `RequestEvent.depends()` records only inside loaders (per-loader event view: `LoaderEvent` class, getters read through to the request's event, `depends` a getter returning this loader's recorder so destructuring works, layouts note `url` / `request` reads; replaced `Object.create(event, descriptors)`, ~0.6 µs + garbage per loader); no-op elsewhere. Assigning a `RequestEvent` member on a loader's view throws (getters only); other properties are its own.
- Kept layout loaders don't run, but their `onRequest(…)`/`on<Method>`/guards/`headers` always do (security).
- `ServerModule` keys are kinds (wrapper names); no legacy names (`GET`… removed 2026-10-20). Old apps: `rivet migrate server-exports`.

## Gotchas

- `handler.ts` is imported by path from `libs/forms/tests/*.test.ts`: don't move/rename it.
- Exporting both `load` and `load(…)` in one sibling, or one export in both page and sibling → error at first request (`module.ts`).
- Request handlers run before guards: auth checks inside `onRequest(…)`/`on<Method>` are the handler's job.
