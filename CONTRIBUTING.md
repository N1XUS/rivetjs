# Contributing

## Setup

- Node ≥ 24, npm; Docker (compiler wasm rebuilds, `apps/ssr-bench`); Python 3.12 only for the SSR benchmark.
- `npm ci`, then `npm run build`.
- Editor: the workspace TypeScript (`.vscode/settings.json`) and the `@rivetjs/typescript-plugin` give Rivet diagnostics.

## Before you open a PR

`node scripts/gates/run.ts` runs every check below that your changes need (changed files vs `HEAD`, or `--base <ref>`; `--all` for everything; `--list` prints the plan) and prints one table; known reds and measurement noise are listed separately. The steps one by one:

1. `npm run typecheck` (TypeScript 7 native `tsgo` through `scripts/tsc.ts`; `RIVET_TSC=tsc npm run typecheck` runs TypeScript 5.9 instead)
2. `npm test` (or `npx vitest run --project <name>` for one suite; names in `vitest.config.ts`)
3. `npm run zero-cost` — must print `runtime + lanes: identical` and `N/N corpus cases match`. Update baselines only for intended size/output changes and say so in the PR.
4. `npm run size-report -- --check` when runtime, router, compiler or kit bytes can change.
5. Format: `npm run format:check` (prettier, pinned in `package.json`, options in `.prettierrc.json`) checks the files you changed that were formatted at the merge base with `origin/main`; `npm run format` (or `npx prettier --write <files>`) fixes them. Files that were not formatted before are left alone.
6. Docs: `node libs/docs-kit/cli.ts check-content apps/docs --strict` and `node libs/docs-kit/cli.ts check-snippets apps/docs` (same for `apps/cdk-docs`) after content changes; code fences that are pseudo-code take the `nocheck` meta (```` ```ts nocheck ````), self-contained ones can opt into a full typecheck with `check`.
7. Update the nearest `CLAUDE.md` (and `docs/guides/*` when behaviour changes) in the same commit.

CI (`.github/workflows/ci.yml`) runs all of these plus `gen-events --check`, `compiler:parity` and the cdk docs build. The nx `test` targets run as parallel shards listed in `scripts/ci/test-shards.json`; a new project with a `test` target must be added to one (`node scripts/ci/check-test-shards.ts` fails otherwise).

## Packaging and release checks

Needed when you change package manifests, `exports`, templates, create-rivet or the release scripts:

- `NX_DAEMON=false npx nx run-many -t package` builds every lib into `dist/libs/<lib>`; `node scripts/package/smoke.ts` installs the tarballs into a strict consumer; `node scripts/package/create-e2e.ts` scaffolds, checks the AI files against `libs/mcp/ai/sync.ts`, builds, checks (`npm run check`) and serves every starter from the tarballs (offline).
- `node scripts/release/release.ts patch` is a dry run of the release (nothing is published, tagged or committed). Real npm publishes happen only in `.github/workflows/release.yml`.
- `node scripts/release/local-e2e.ts` runs the real publish path against a local registry: it starts Verdaccio (a root devDependency; config and storage in `scripts/release/verdaccio/`, storage gitignored), publishes every package to it, then runs `npm create rivet@latest` for each starter, installs, builds, type-checks, serves and fetches the page. Every npm call it makes uses its own npm userconfig and cache under that storage folder (`--userconfig`, `NPM_CONFIG_USERCONFIG`, `--@rivetjs:registry`, proxy settings dropped); it refuses to publish when a repo-root `.npmrc` or a global npmrc exists or npm would resolve a registry that is not local. `~/.npmrc` is never read or written. `node scripts/release/verdaccio.ts start | stop | status` runs the registry by itself (port 4873). Publishing to any registry that is not on localhost is refused.

## Rules

- Public API (`package.json` `exports` subpaths) stays stable; every subpath is independently tree-shakeable (untouched features cost 0 bytes).
- Performance changes come with measurements (`apps/ssr-bench`, `apps/dom-bench`, size report).
- `libs/cdk` modules are faithful ports of react-aria / react-stately / react-aria-components / Angular CDK with their upstream tests and license headers (`libs/cdk/NOTICE`).
- No invented SVG icons and no Unicode glyphs as icons; use lucide.
- Compiler Rust code builds in Docker (`libs/compiler/rust/build.sh`); do not add host-toolchain requirements.
- Generated files (`Generated by … Do not edit.`) are regenerated, never edited.

## Commits

Conventional subject (`feat(router): …`, `fix(cdk): …`, `docs: …`, `perf(runtime): …`), body explains why and lists intended baseline deltas.
